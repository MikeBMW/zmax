# 标定诊断测量 · 主参数 M —— 配置/标定/诊断 三合一接口 (ASAM-MCD 类比)

> 2026-10-09 · 设计：静静 · 画布节点 `n_calib_mani`
> **节点已改名**：「🧮 流形引擎标定 · 主参数 M」 → **「🧮 标定诊断测量 · 主参数 M (状态空间结构参数 · 等效惯量)」**
> 改名 + 配置挂载由 `tools/ss_node_sync.py` 落地（只动这一个节点，`flows.save_canvas` 自动备份，除本节点外指纹逐位不变）。
> 该节点现在是 **配置中心 ←→ 状态空间工程 的唯一收口口**：`params.cfg_entries` 挂全部配置文件指针，
> `params.cfg_snapshot` 挂当前配置状态快照，`params.{measure_view,calib_view,diagnose_view,task_layer}` 是三视图 + 任务层摘要。
> 现状：已有单标量 M 的读/写/两臂对比（`library.py::node_ss_calib_mani`，接线 in1←sscalib.out3、
> in2←sslat.out3；out1→ss_mani_eng.in6、out2→ssmani_c.in3、out3→ssmani_exp.in6）。
> 本文把它从「一个标量」升级成**整个工程的整车配置接口**（配置 / 标定 / 诊断 三件事收口在这一个节点）。

## 0. 结论先行（一句话架构）

**M 节点 = 描述文件（MCD-2MC/A2L）+ 测量标定通道（MCD-1MC/XCP）+ 远程控制面（MCD-3MC）三件套在画布上的收口节点。**
参数与能力的真源是文件（`feature.dbc` + `config/calib/*`），节点只做三件事：
① 按 feature 组合**派生**参数集（配置）→ ② 在真机上做**受约束的扫描与目标函数寻优**（标定）
→ ③ 拿在役真值和 feature 断言做**同源判定与报告**（诊断）。
所有结果写一条状态通道（`_SS_STATE["calib_mani"]` + `reports/mcd/*.jsonl`），旁路实时可视化节点以
**区块**形式消费它（同「上网通道」区块的既有做法），远程由 `n_hil` → 8795 控制。

## 1. ASAM-MCD ↔ Z-MAX 映射（这是本设计的骨架）

| ASAM-MCD | 原义 | Z-MAX 对应物 | 真源/落点 |
|---|---|---|---|
| **MCD-1 MC**（通信协议 XCP/CCP） | 工具↔ECU 的物理/逻辑链路与协议 | **测量标定通道**：只读遥测帧（旁路 `bypass_sensor_source.py`）+ 在役位姿真值 `zmax_data/rokae_sdk/tcp_out/latest.json`（50Hz）+ DDS 遥测（`zmax-dds-*`）+ 写入走 8793 `/ctl/*` 收口链（白名单→授权→限流→FIFO→执行器→安全闸） | 不新建通道，复用既有 |
| **MCD-2 MC**（数据描述 A2L） | 描述 ECU 里可测/可标/可诊断的量 | **描述文件 `config/mcd/zmax_mcd.json`**：MEASUREMENT / CHARACTERISTIC / COMPU_METHOD / GROUPS 四段，从 `feature.dbc` + `config/calib/*` 生成 | 本文 §2、§3 |
| **MCD-3 MC**（远程控制） | 远程读/写/启停标定系统 | **远程控制面**：8795 `/hil/term/mcd*`（读描述/读值/写 M/启停扫描/取报告），上游是画布 `n_hil`（🙋 HIL 人机在环）与 ECS relay | 本文 §6 |
| **MCD-1 POD**（可插拔设备即插即用） | 硬件适配器 + PSS 标准化 | **第三方模型接入**：`feature.dbc` 的 `BU_` 节点 + `CM_` 能力组合（按声明接入，不改平台代码） | `docs/feature_dbc_spec.md` |
| **MCD-2 D / ODX**（诊断数据库） | 诊断服务与故障码 | **诊断段**：feature 断言（`verification_layer.FEATURES`，57 条自动/手动）+ 参数健康 + 一致性；故障码 = 稳定 ID（`MCD-E01…`） | 本文 §5.3、§7.3 |
| **MDF**（采集数据存储） | 测量数据落盘格式 | **扫描记录** `reports/mcd/scan_M_<ts>.jsonl`（每点一行：M/指标/帧号/时间戳） | 本文 §9 |

对齐点（别丢）：ASAM 的核心不是协议，而是**「量先被描述，工具才能互操作」**。
Z-MAX 现在缺的正是这份描述——M 的物理意义散落在 `manifold_M_spec()`、节点 `params`、`zmax_manifold.json`
和画布说明里，没有一份机器可读的描述，所以**别的工具（旁路窗口/远程页/诊断脚本）读不到同一个 M**。
本设计第一步就是把这份描述补上。

## 2. 数据模型：三张表（A2L 概念的等价物）

### 2.1 MEASUREMENT（测量量 · 只读，能看不能改）
每条 = {id, 中文名, 单位, 真源路径, 读取方式, 正常判据, 归属层}
覆盖：
- 状态类：43D obs 分段（hand/peg/hole/触觉）、SU(2) 统一状态、残差、contact_p
- 位姿类：tcp(6) / joint(6) / 关节速度范数 / 力(6) / 夹爪，真源 `latest.json`（**帧龄是第一判据**）
- 性能类：D_INSERT 终到误差、节拍、力峰、否决率、η(CJ/J)、V_p
- 健康类：各源文件 mtime 帧龄、Publisher count、端口探活码

### 2.2 CHARACTERISTIC（标定量 · 可写，五级分类 —— 这是「科学整合」的关键）

| 级 | 含义 | 写权限 | 例 | 允许的标定方式 |
|---|---|---|---|---|
| **G0 结构参数** | 由流形结构导出，**非自由拟合** | 只读+授权写 | **M（等效惯量尺度）**、latent_dim、manifold_type | 单标量现场标定；**禁止**当自由参数调 |
| **G1 安全参数** | 硬红线，有守卫兜底 | 只读，写需现场一次性授权 | saturate ±0.6、veto_th、max_step、力阈值 ≤2N、抬升限位、collision_detection | 只能"证明不违反"后收紧，不允许放宽 |
| **G2 性能参数** | 有目标函数，可扫 | 授权写（走 mcd 通道） | 速度系数、前馈增益、夹爪时序、τ | 扫描 + 目标函数寻优 |
| **G3 场景参数** | 现场示教/几何 | 现场写（零运动录点） | 示教点、安全点、plane_z、z7、TCP offset | 只能"读当前真值落盘" |
| **G4 模型权重** | 不可标，只版本 | 只读 | `model.safetensors` / LoRA / ckpt | 版本比对，不标 |

每条 CHARACTERISTIC 的元数据（强制字段，缺一不可）：
`{id, 级, 单位+换算, 范围+夹取策略, 默认值, 真源文件与键, 影响面(哪些节点/层读它), 判据(好/坏阈值), 写权限, 关联 feature}`

> 为什么要五级：把"M 能调多少"和"安全阈值能调多少"分开，是**避免标定变成改红线**的唯一办法。
> G1 的写口永远不在这条链上——M 节点只**读** G1 做约束，写 G1 仍走现场授权。

### 2.3 COMPU_METHOD（换算 · 单位与量纲，全部有实测依据）
| 量 | 换算 | 证据 |
|---|---|---|
| 腿速 | 名义 `0.0935×speed`，**实际 ≈ 名义÷10** | 实测 14mm/s 名义走 37.2s/50mm ⇒ 1.34mm/s；要 ~10mm/s 给 speed≈1000 |
| D405 深度 | 单位 0.1mm（raw 4013 = 401mm） | 实测 |
| 时钟 | 容器 `t` 比宿主早 8h（NTP 回拨），**只用文件龄不用 t** | 已知历史现象 |
| 帧龄阈值 | >2s 拒用（录点）；动作三查 6 帧极差 >1e-4m 判"还在动" | 录点三道闸 |

## 3. feature list 的组合 → 参数集（科学整合的落点）

### 3.1 feature.dbc 扩一个关键字 `PA_`（能力 ↔ 参数 的显式绑定）
现有 `BO_` 只声明能力与 SG_ 信号，没有说"这条能力暴露哪些可配置参数"。补：

```
// 能力参数绑定: 参数ID 级 范围 默认 权限 单位
BO_ C2 精细对位: CFG/OUT C
 PA_ P_FINE_TOL  G2 [0.02,2.0] 0.10  auth  mm"允许偏差 (工位±2 → 视觉±0.1 → 力控±0.02)"
 PA_ P_FORCE_MAX G1 [0,2.0]    2.00  field N "插拔力上限 (红线, 只允许收紧)"
BO_ D2 运动规律建模: OUT D
 PA_ P_M         G0 [0,8]      1.00  auth  -  "主参数 M (等效惯量尺度; 非自由拟合)"
```

### 3.2 组合 → 参数集 的派生（配置的第一步）
`CM_ <模型节点>: <能力ID…>` 已经存在（如 `JOB_MODEL: A1 A2 A4 B1…`）。派生算法：

1. 取选定节点的 `CM_` 能力集合 → 并集所有 `PA_` ⇒ **参数候选集**
2. 按级过滤权限：`field` 级（G3）只有现场能写；`auth` 级要授权；`G0/G1` 强制二次确认
3. **冲突检测**（必须报，不能静默取一个）：同一参数被两条能力以不同范围/默认要求 ⇒ 高亮冲突，取**交集**，交集为空则拒配
4. 缺 G0/G1 参数 ⇒ 拒配（不允许"没标定就跑"）
5. 产出 `run_cfg`（参数取值）+ `param_ready`（每参数就绪度：有真源/在范围/未陈旧）

### 3.3 能力档位（`sscap` 的 L2/L3/L4/L5）与参数的关系
每个档位声明"必须还能干的事"（`engineering/levels.py`）。参数集按档位收敛：
`L2 档 ⇒ 只需 G1+G3`；`L3 ⇒ +G2 视觉/DiT 相关`；`L4 ⇒ +G0（M 必标）+ 世界模型相关`；`L5 ⇒ 只读，不改任何在役参数`。
⇒ **换档 = 换参数子集**，这正是老倪说的"整车配置"。

## 4. 节点 I/O 契约（现有接线一条不动，只加口）

**现状（保持）**
```
in1 ← sscalib.out3   (标定层单一真源 → M 注册口)
in2 ← sslat.out3     (潜空间几何 → 曲率/维度尺度)
out1 → ss_mani_eng.in6   (M → 流形引擎主核)
out2 → ssmani_c.in3      (M → 接触流形势能惯性尺度)
out3 → ssmani_exp.in6    (M → 流形梯度流/动量)
```

**扩展（新增口，不改上面任何一条）**
```
in3 ← ssfeat.out1        (Feature 组合/参数候选 → 配置输入)
in4 ← ssmani_p.out1      (性能流形 V_p/η → 标定目标函数与诊断指标)
in5 ← n_hil.out2         (HIL 远程指令 → 配置/标定/诊断 触发)   ← 上游
out4 → ssfeat.in3        (参数就绪度/配置矩阵 → 功能清单核对)   ← 前向 6000<16666 ✓
out5 → (状态通道) 不画线，写 _SS_STATE + reports/mcd/*        ← 与旁路可视化的数据面
```

**⚠ 为什么与「旁路实时可视化」不走画布线**：`ssbypv` 在可视化行**最左端**（x=700），M 节点在 L4 行
（x=6000）⇒ 连线只能是**反向**（6000 → 700），按画布铁律（`f.x+f.w ≤ t.x`）会被断言拦下，
且反向线会立刻把交叉数拉高。所以交互走**两条真通道**（都不需要反向线）：

1. **数据面（主）**：M 节点把扫描/诊断结果写 `_SS_STATE["calib_mani"]` + `reports/mcd/scan_M_*.jsonl`；
   `SSBypassView` 新增区块「🧮 标定 · 主参数 M」读它（与既有「🛰 上网通道」区块同款实现，`net_channel_status_line()` 是现成范式），
   曲线直接复用 `CurveWidget`；区块里放一个「▶ 扫描 M」按钮 → `POST 8795 /hil/term/mcd` → 真触发。
2. **画布线（可选，老倪要"看得见"时再加）**：在**可视化行右端**（x≈20666）新增一个轻节点
   「🧮 M 标定台 · 曲线」，线 `n_calib_mani.out1 → 该节点.in1`（前向 6340 ≤ 20666 ✓），
   该节点双击就打开同一个面板。**不要**为了连线去挪 ssbypv 或任何既有节点。

## 5. UI 设计（对标 INCA / CANape，一套窗口四页签）

窗口 `tools/gui/mcd_panel.py`（`MCDPanel(QWidget)`），由节点**双击**挂载（复用 `sourceview`/对话框挂载机制）。

```
┌ 流形引擎标定 · 主参数 M ────────────────────────────── [只读旁路] [授权: 无/剩 Xs] ──┐
│ 左：三层树                      │ 右：四页签                                   │
│ ① 域  配置/标定/诊断            │ ┌配置┬标定┬诊断┬组合┐                       │
│ ② 能力  A移动 B感知 C作业 …     │ │                                            │
│ ③ 参数  每条带 级徽章 G0..G4    │ │                                            │
│   M ●G0  1.00  auth            │ │                                            │
│   P_FORCE_MAX ●G1 2.00 field   │ │                                            │
├────────────────────────────────┴──────────────────────────────────────────────┤
│ 状态栏: 帧龄 0.03s · 源 latest.json · 档位 L4 · M=1.00(inertia=off) · 零回归 ✅ │
└───────────────────────────────────────────────────────────────────────────────┘
```

### 5.1 配置页
- 表：`参数 | 级 | 当前值 | 单位 | 范围 | 真源 | 影响节点 | 写权限 | 状态灯`
- 顶栏：**M 大数值 + 滑杆（0~8，越界夹取并显红）**、`inertia` 开关、`⟲ 零回归`（一键回 default/false）
- 每行右键：`看源码`（走 `_EXTERNAL_LOC`）、`看真源文件`、`回滚到 prev`
- 底部：`就绪度 N/M 项`、`冲突 K 处`（点击跳到冲突行）

### 5.2 标定页（核心）
- 目标函数（可编辑权重，默认同源指标）：
  `J = w1·D_INSERT(终到误差 mm) + w2·(1/η 归一) + w3·节拍(s) + w4·力峰(N) + w5·否决率`
- 扫描：`起点/终点/步数`（默认 0.25→4.0 / 16 点）、`每点重复 n 次`、`随机化顺序`（防顺序效应）
- 实时曲线：M → J / ‖v‖动量 / Δx / η（**复用 `CurveWidget`**，与旁路同一控件）
- 结果：**推荐 M\* = argmin J**、`敏感性 S=∂J/∂M`、`可辨识判定`（|S| < 噪声带 ⇒ 明确报"M 本场不可辨识"）
- `应用`（走授权闸，三段：读写前备份 → 写 → 回读核验） / `只留记录不应用`
- 约束（硬）：扫描中不得放宽 G1；每点必须通过**同一套**合法性（帧龄<2s、非全 0、6 帧极差<1e-4m）

### 5.3 诊断页
- **断言跑分**：`verification_layer.FEATURES` 57 条（自动/手动）汇总一屏，按域分组，红/黄/绿
- **参数健康**：越界 / 真源陈旧（帧龄）/ 漂移（与上次扫描比）/ 一致性（calib 描述 vs 在役读值）
- **链路段**：8795 / 8793 / 位姿真值 / Orin / 工控机 的探活码 + 帧龄（会照实报"环境缺失"而不是"服务故障"）
- **故障码**：稳定 ID（`MCD-E01 位姿真值陈旧` / `MCD-E02 参数越界` / `MCD-E03 组合冲突` / `MCD-E04 断言失败` …）
- `导出诊断报告` → `reports/mcd/diag_<ts>.json` + `.md`（同一份数据的两种形态）

### 5.4 组合页
- 矩阵：行 = feature 能力（`BO_` 全量），列 = 模型节点（`CM_`）；勾选即改组合
- 实时显示：**派生参数集**（并集）、**冲突高亮**、**缺就绪项**、**档位要求**（L2/L3/L4 是否满足）
- `应用组合` → 写 `run_cfg` + 生成 `param_ready`；`差量预览`（改前/改后逐参数 diff）

### 5.5 与旁路可视化的 UI 交互
- 旁路窗口新增区块「🧮 标定 · 主参数 M」：显示 `M / inertia / 上次扫描 M* / J(M*) / 帧龄`，一个「▶ 扫描 M」按钮
- 两侧共用：`CurveWidget`、状态文件、同一个"只读旁路"徽章 ⇒ **一份数据两处看，不存在第二份真相**

## 7. 三件事的流程与判据

### 7.1 配置（Configure）
`选组合 → 派生参数集 → 冲突/范围/就绪校验 → 落 run_cfg + 描述 → 记版本`
判据：`冲突=0` 且 `G0/G1 就绪=100%`；否则拒配并列出缺项。

### 7.2 标定（Calibrate）
`选参数(默认 M) → 定目标函数 → 合法性预检 → 扫描(随机顺序, 每点多采) → 记录 → 推荐+敏感性 → [应用]`
应用三段（缺一不可）：① 备份 `prev` 到 `zmax_manifold.json.bak_<ts>` ② `write_manifold_M()`（只改 `manifold_engine` 键，**不整表 sync**）③ 回读 `manifold_M()` 逐位一致 + 跑一次 `zero_regression` 断言分支。

### 7.3 诊断（Diagnose）
`取在役真值 → 断言跑分 → 参数健康 → 链路探活 → 分级 → 报告 + 通知`
判据分级：`OK`（全绿）/`WARN`（参数陈旧或指标接近阈值）/`FAIL`（断言失败或参数越界）——**不许把"跑过了"写成"通过"**。

## 8. 与状态空间工程的科学整合（不是加个面板，是加一层约束）

1. **稳定性先于性能**：M 是二阶演化 `v ← v + (F/M)·dt; p ← exp_p(v·dt)` 的尺度。
   标定必须满足 **Lyapunov 单调性**：沿轨迹 `ΔV = V(p_{k+1}) − V(p_k) < 0`，
   且步长 `‖v·dt‖ ≤ max_step`、谱半径 `<1`。⇒ 可行域不是滑杆给的，是**算出来的**：
   `M ∈ [M_min, M_max] ∩ {M : ΔV<0 且 谱半径<1}`；超出即"不可标定"，不是"标定失败"。
2. **指标同源（零新造指标）**：`D_INSERT≤4mm`(F-A02)、`η`(energy_manifold)、`V_p`(ssmani_p)、
   节拍 `≤6s`、力峰 `≤1N`(F-A10)、否决率 —— 全部取自 `io_trace`/`energy_manifold`/`manifold_layer`，
   **不在面板里另算一套**（同一份数据的第二份真相 = 下一轮被戳穿的地方）。
3. **可辨识性先验**：标定前先算有限差分敏感性 `S=∂J/∂M`；`|S|` 落在噪声带内 ⇒ 报
   "本场 M 不可辨识（换数据段/换指标再试）"，**不报一个假的 M\***。
4. **零回归是默认态**：`inertia=false` 或 `M=default` ⇒ 引擎行为与旧一阶过阻尼**逐位相同**。
   面板上常显"零回归 ✅/❌"，切 M 后立即重算这一条。
5. **能力↔参数↔层 三者可回溯**：每个参数带 `关联 feature` 与 `归属层`；改一个参数，
   能回答"动了哪些能力、哪一层、对哪些断言有影响"（配置页的"影响面"列就是干这个的）。
6. **对称与等效性检查**：SU(2) 统一状态下，M 的改动**不得破坏群约束**（`ssobs` 那条 `群约束` 输入）。

## 11. 红线与回滚

4. **不破坏画布**：加线必须前向、逐条比对既有连线；删/挪节点一律不做（挪节点是交叉变多的主因）。

6. **诚实口径**：M 不可辨识就报不可辨识；断言没跑就写"未跑"；环境缺失（网卡/相机不在位）报环境缺失，不报服务故障。
