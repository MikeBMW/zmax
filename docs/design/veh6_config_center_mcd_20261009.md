## 0. 结论先行

**VEH.6 = 一张「参数表 + 三个视角列」，不是十二个页面。**

```
        ┌ 配置域 (4 行) ┐        ┌ MCD 三轴 (3 列) ────────────────┐
        模型配置 Model            ① 测量 Measurement  看得见 (只读/真源/帧龄)
        工程配置 Project          ② 标定 Calibration  改得动 (权限/编辑器/扫描)
        功能配置 Feature          ③ 诊断 Diagnosis    判得了 (判据/故障码/差异)
        性能配置 Performance
        横切: 入口带(工程文件/模态) · 远程带(8795 HIL/权限) · 交付带(描述文件/全表/Excel/差异)
```
- **参数是行的唯一实体**（A2L 的 CHARACTERISTIC 在 UI 上的投影）；域是分组，轴是**同一个参数的三种操作**。
- **真源永远是文件**（`config/calib/*.json` / `feature.dbc` / 在役权重 / `flows/*.json`）——
  VEH.6 是**编辑面**，不是第二份真相。任何一行都能回答「真源在哪个文件哪个键」。
- 现状缺口（实测）：现有配置中心只覆盖**模型超参**（9 个分组 + 标准参数总表），
  **工程/功能/性能三个域一个都没有**；MCD 描述本次已补（24 条参数 / 4 域 / 就绪 10/24）。

## 1. 定位与分工

| 页 | 管什么 | 一句话 |
|---|---|---|
| **VEH.5** Simulink 模式 | **结构**：节点、接线、拓扑、单步/运行 | 「系统长什么样」 |
| **VEH.6** 配置中心（本页） | **参数**：能力组合、几何、权重版本、性能目标、安全红线 | 「系统按什么跑」 |
| VEH.9 评估分析 | 结果：指标、稳定性、报告 | 「跑得怎么样」 |

三者关系：**VEH.6 是入口，VEH.5 是现场，VEH.9 是结论**。
交叉跳转：VEH.6 任一参数行双击/右键 → 「在 VEH.5 看它的节点」（按 `affects` 里的节点 id 定位并高亮）。

**现状盘点（`studio.py:8634–9350`，约 700 行）**
```
现有 9 组: 架构模式 / UI风格 / 基础配置 / VLM骨干 / Action Head / 世界模型 /
           预处理后处理 / 优化器调度器 / 配置预览 (+ Lerobot 标准参数总表 + 导出 Excel)
覆盖域:   只有「模型配置」一个 (Sys-11 / Sys-11+12 两种模态)
```
⇒ 本设计的动作是**扩域**（补 工程/功能/性能）+ **换骨架**（从「一组控件一张卡」换成「统一参数表 + 三轴列」），
**不改** VEH.5 画布，**不改** 在役标定值。

## 2. 四个配置域的内容（每一域都按 MCD 三轴说清）

### 2.1 模型配置（Model）— 现有基础，改造为三轴
| 轴 | 内容 | 真源 / 落点 |
|---|---|---|
| 测量 | 在役权重（L2 `models/yolo_peg_live.pt` 软链 · L3 SmolVLA LoRA · L4 INTACT）、模型加载状态、单帧延迟、显存 | 权重目录 + 运行日志 |
| 标定 | 架构模态（Sys-11 / Sys-11+12）、`cfg_spec` 六类标准参数（🏗架构/📷视觉/🎮动作/⚙️训练/📊数据/🚀部署，3 模型逐行） + Sys-11/12 具体超参（chunk/obs steps/head hidden/layers/dropout/inference steps/世界模型） | `studio.py::ConfigModule` → 训练 yaml |
| 诊断 | 权重可加载性、退化检测（成功率/接触分离度）、LoRA 是否已 merge（**未 merge = 零动作伪装**）、参数量/版本一致性 | 评审结论 + 断言 |

硬规则：**权重只版本比对，不在这页标定**（G4）。训练超参属 G2（可扫），但"改完必须重训"要在行内标出。

### 2.2 工程配置（Project）— 全新增，9 条实测参数
`camera.K` · `camera.dist` · `T_base_cam` · `plane_z` · `depth_scale` · `cell_geometry.points` ·
`robot.dof` · `tool_payload.mass_kg` · `control_tcp.offset_xyz_m`
| 轴 | 内容 |
|---|---|
| 测量 | 逐个显示**真源 + 当前值 + 缺口原因**（例：`T_base_cam` 未标定「需零运动人工拖动 10+ 位姿采」） |
| 标定 | 现场零运动示教入口（`ss_geom_calib.py --record peg_head|goal|aoi`、板手眼 `board_handeye_solve.py`）+ 写权限（`field`） |
| 诊断 | **实测缺口**：`T_base_cam` / `plane_z` / `cell_geometry.points` 三项未标定 ⇒ 直接判 `MCD-E02/E01`；TCP 一致性（`verdict=刚体一致`，std≤2mm、姿态≤1°） |

这一域是**精度链的起点**，诊断页必须一眼给出"缺哪一项、缺了会导致什么"。

### 2.3 功能配置（Feature）— 从 `feature.dbc` 派生
**实测现况**：节点 5 · 能力 30 条（A4 B5 C6 D3 E3 F3 G4 H2）· 组合 5 个（JOB 26 / GUIDE 6 / SCHED 5 / PERCEPT 5 / THIRD_PARTY 0）
· 档位契约 L2 7 / L3 4 / L4 6 / L5 5 条"必须还能干的事" · 诊断断言 57 条（自动 47；L2 38 / L3 8 / L4 11）
| 轴 | 内容 |
|---|---|
| 测量 | 能力**覆盖矩阵**：30 能力 × 5 节点（`CM_`）勾选态 + 每条能力是否有实现节点（`match_node` 非 None） |
| 标定 | 勾选组合 → 派生参数集 → **冲突检测**（同参数被两条能力要求不同 ⇒ 取交集，空则拒配）；档位 L2/L3/L4/L5 一键切换 |
| 诊断 | 档位契约核验（`levels.check()`：该档节点全有逻辑 key，缺口=0）+ 断言跑分 + **未接入能力点名**（`THIRD_PARTY` 组合为 0 = 还没接第三方） |

> 这一域把老倪的「feature 组合 → 不同功能」直接做成**矩阵勾选**：功能不是写死的，是配置出来的。

### 2.4 性能配置（Performance）— 主参数 M 与红线同框，但权限分离
| 轴 | 内容 |
|---|---|
| 测量 | 指标真值：`D_INSERT` 实测 · 节拍 · 力峰 · 否决率 · `η`(CJ/J) · `V_p` · 动量 ‖v‖ |
| 标定 | **主参数 M（G0，非自由拟合）** + `inertia`（G2）+ 目标函数与权重 + M 扫描/寻优 + 敏感性 S 与可辨识判定 |
| 诊断 | 阈值判定（`D_INSERT<4mm`、节拍≤6s、力峰≤1N、接触分离度>0.3）+ 越界/漂移/回归（零回归：`inertia=false` 或 M=default ⇒ 逐位同旧一阶过阻尼） |

**红线与性能同框但权限分离**：`safety.saturate`(0.6) / `safety.veto_th` 属 **G1，只读**，
显示在表里但**没有编辑控件**——诊断列只报"是否被违反"。这样"能调的"和"不许调的"在同一屏一眼分清。

## 3. 参数行的统一字段（科学整合的核心）

每一行（= 一条 CHARACTERISTIC）固定 14 列，缺列不允许入库：

```
id | 中文名 | 域 | 级(G0..G4) | 真源(文件#键) | 当前值 | 单位/换算 | 范围 | 默认 |
影响面(节点/层) | 判据 | 权限 | 关联feature | 状态灯
```
- **影响面** 是"改这个参数会动到什么"的答案：节点 id 列表（用于跳 VEH.5）+ 归属层（L2/L3/L4/L5）。
- **判据** 是可执行的一句话（不是形容词）：如 `帧龄<2s`、`std≤2mm 且姿态偏差≤1°`、`ΔV<0 且谱半径<1`。
- **权限** 四档：`readonly`（G1/G0 部分，只读）· `field`（现场零运动写）· `auth`（需真动授权）· `version`（只版本比对）。
- **状态灯** 三色：绿=真源在且判据过 / 黄=真源在但判据临界或陈旧 / 红=缺真源或判据不过（红行必须带原因）。

## 5. 与状态空间工程的整合

1. **参数 → 节点/层**：`affects` 由 `_EXTERNAL_LOC`（源码映射）+ `levels.band_map()`（档位行带）**自动生成**，
   不手写；改一个参数能回答"动了哪些节点、哪一层、对哪些断言有影响"。
2. **档位收敛**：L2 只用 G1+G3；L3 +G2（视觉/DiT）；L4 +G0（M 必标）；L5 只读。
   VEH.6 的域树按当前档位置灰/置亮，**换档 = 换可用参数子集**——即"整车配置"的技术含义。
3. **可行域逐层收窄**：四个域的编辑顺序建议 工程（设备事实）→ 模型（能力来源）→ 功能（打开哪些能力）→ 性能（数值）；
   UI 用一行提示语引导，并且**上游未就绪时下游行标黄**（例：`plane_z` 未标定 ⇒ 性能域的 3D 相关指标标黄）。
4. **改完必须能证明**：任何 `auth` 写入走「备份 prev → 只改自己那一节 → 回读核验」三段；
   写 `calib.json` 时**只改本域键**，禁止 `sync_calib(write=True)` 整表重合并（会把其他在役域刷成"当前源"）。

## 7. 权限与安全（这一页最容易出事，先立规矩）

1. **G1 红线（saturate/veto_th/力阈值/限位）永不给编辑控件**——只读展示 + 诊断列报"是否被违反"。
2. `auth` 写入 = 真动授权窗口内才可写；授权来源只有 8793；过期即灰。
3. **只改本节**：写哪个域就读-改-写那个键，禁止整表合并。
4. **写后必回读**：`manifold_M()` / `calib()` 读回逐位比对，不一致即判失败并自动回滚 prev。
5. **GUI 冻结纪律**：老倪在场演示/准备重启控制台时冻结 `tools/gui/*.py` 写操作；
   改完必须说清"要重启控制台才生效"。
6. **诚实口径**：源停更标失效（不许显示成"当前"）；参数未就绪标红并给原因；环境缺失（网卡/相机不在位）报环境缺失。

## 10. 红线

- 真源唯一：VEH.6 不新增任何"配置真相"，一律指向文件；描述文件由生成器产出，不手改。
- 不写标定值：本次生成器**只读**（不调 `sync_calib(write=True)`，不碰 `calib.json` 在役读值）。
- G1 红线无编辑口；`auth` 写入需授权 + 三段（备份/只改本节/回读）。
- 不改 VEH.5 画布、不改在役权重、不动 GUI 冻结期内的 `tools/gui/*.py`。
- 未跑就说未跑：缺口/未接入一律点名，不写成"已支持"。
