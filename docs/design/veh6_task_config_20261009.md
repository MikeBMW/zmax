## 0. 什么叫"任务配置"，为什么它是主要工程配置

```
能力(feature.dbc 31 条) → 工序配方(8 段 25 条, 全集) → 【任务配置：段的子集 + 参数覆盖】 → 工单(一次执行) → 单件记录
```
- **配方**是全集：取件/插拔/分拣…所有段都列着；
- **任务**是"这台设备在这个工位干哪件活"：**选哪些段 + 覆盖哪些参数 + 怎么触发/循环**；
- **工单**是任务的一次执行（`1 盘 = 1 工单，1 件 = 1 条记录`）。

⇒ 所以"上下料的任务配置"= 一条可复用的作业定义，不写代码、不重训模型。
**换产品只改任务，不动机器人与模型** —— 这就是"主要工程配置"的含义。

## 1. 任务配置字段（缺一不许进真源）

| 字段 | 含义 | 上下料实测值（`TASK-02-HANDLE`） |
|---|---|---|
| task_id / name | 任务标识 | `TASK-02-HANDLE` · 料盘/治具上下料搬运 |
| recipe_type | 配方类型 | 上下料搬运 |
| scene_ref / site | 场景与站点 | `SCN-02-HANDLE` · `SITE-A.ST11` |
| **applies_segments** | 适用配方段 | 6/8：0 料源 · 1 取件 · 2 姿态 · 3 对接 · 6 分拣 · 7 节拍 |
| **excluded_segments** | 不适用段 | 4 放置/插入 · 5 拔出（搬运不插拔 — 这就是"任务=子集"） |
| steps | 步骤序列 | 取盘 → 配送 → 精密对接 → 检测 |
| **variants** | 物料粒度 | L1 料盘级(缓存架 600×400×1800) · L2 治具级(200×200×15) · L3 单颗级(18×9×4) |
| **overrides** | 参数覆盖 | `pick.close_force=3.0` · `pick.lift_h=30` · `pick.retry=2` · `cyc.dual_arm=协作` |
| trigger / loop | 触发与循环 | 料盘到位信号 / 手动 · 整盘连续(12 件/盘)，满盘→空盘切换 |
| targets | 验收判据 | 配送准时率 ≥99.5% |
| orders_rule | 工单规则 | 1 盘 = 1 工单；1 件 = 1 条记录 |
| binding_hint | 组配建议 | 逐层选型(L2/L3/L4) + 站点；真机域模型需站点几何齐 |
| safety | 安全 | 继承站点 Sys-0（急停/力阈值 Fz>5N/关节限位±3rad/光幕）— **任务不可覆盖** |

## 4. 操作（重启后怎么用）

```
1. 重启控制台 → 配置中心 → 首屏「📋 任务配置」
2. 选一条任务（如 TASK-02-HANDLE）→ 看适用段/粒度/覆盖/判据
3. 点【✅ 生成工单】→ 落 config/orders/BS_SCN-02-HANDLE.json
4. 点【🔍 全链校验】→ 7 项结果 + 共同根因
命令行等价（随时可跑，不依赖 GUI）:
   python3 tools/config_center.py tasks
   python3 tools/config_center.py task TASK-02-HANDLE
   python3 tools/config_center.py order --task TASK-02-HANDLE
   python3 tools/config_center.py check
```
