# 机器人产线的"配置单"：Build Sheet 怎么配（以「上下料工序」为例）

> 2026-10-09 · 设计：静静 · 配套实测：`tools/build_sheet.py` → `config/orders/BS_*.json`（5 个工单真跑）
> 前置：`docs/design/veh6_config_center_mcd_20261009.md`（VEH.6 配置中心）· `docs/design/model_zoo_config_matching_20261009.md`（模型×工程配置匹配）

---

## 0. 一句话

汽车总装那张纸 = **单车身份 + 装配指令 + 零件清单**；
机器人产线的对应物 = **工单身份 + 工序配方 + 物料清单**，再加一节汽车有但表上不写的：**安全（Sys-0）**。

配置不是"选模型"，是**四层组合 + 一条逐件校验链**：

```
L1 站点配置 config/calib/*     现场事实(坐标系/相机/TCP/机器人/安全)  ← 永远最高, 只读
L2 工序配方 工序模板(RECIPE)    工艺定型(取件→扫码→对位→插拔→分拣→回位) 参数化
L3 工件变体 scenes_5jobs.json  每种物料的尺寸/朝向/穴位/来料姿态
L4 工单实例 本次 BS_*.json      一批 N 件: 逐件 ID + 选项包 + 参数覆盖
优先级: 安全(G1) > 站点几何(G3) > 工单覆盖(G2) > 变体 > 配方默认
```

## 1. 字段对照（汽车 → 机器人）

| 汽车 Build Sheet | 机器人产线对应物 | 我们系统里的真源 |
|---|---|---|
| VIN 车架号 / 订单号 | **工单号 + 工件码 + 场景ID** | `BS_<场景>.json#identity.order_no` / 扫码 |
| 车型 / 车身形式 | **机器人型号 + 上装形态** | 珞石 Z700 + R MPV（固定式/移动式 A4） |
| 动力总成 / 变速箱 | **末端工具 + DOF/负载/TCP** | `calib#tool_payload` / `control_tcp` |
| 颜色 / 内饰 / 选装包 | **工件变体 + 选项包** | `scenes.objects[]` + 选项（扫码/AOI/EEPROM/分拣/老化） |
| 零件清单 BOM | **来料盒(20穴)/治具(4定位孔)/料盘(12槽)** | `scenes.objects[]`（实测尺寸与穴位） |
| 装配指令 / 工艺提示 | **工序配方**（逐步骤：位姿/力/插入深度/判据/超时/重试） | `RECIPE`（25 条参数）+ `scenes.steps[]` |
| 扭矩 / 加注参数 | **力阈值 / 插入深度 / 夹持力 / 节拍** | 实测判据（`orin-grasp-place-workflow.md`） |
| 质量追溯 / 条码 | **单件记录 + 判据快照 + `binding_id`** | 追溯节（`trace`） |
| （表上不写）安全 | **Sys-0：急停 / 力阈值 / 关节限位 / 光幕** | 站点级，**任何工单不得覆盖** |

## 2. 上下料工序怎么配（核心：8 段配方 / 25 条参数）

每条参数都必须带 **真源 · 判据 · 级 · 权限**（缺一项不许进配方）：

| 段 | 关键参数 | 判据（可执行） | 级 | 权限 |
|---|---|---|---|---|
| **0 料源与来料** | 盒/盘 ID · 第 0 穴位坐标 · 穴间距 · 来料朝向 · 空满检测 | 穴距与实测 3 穴位反算误差≤0.5mm；金手指面朝上 | G3/G2 | field |
| **1 取件** | 工具选择 · **夹爪闭合力 1~5N** · 提升高度 · 重试 | **`grasp_normal_force ≥ 5N` 判抓取成功**；连续>2 次失败报错停机 | G1/G2 | auth |
| **2 姿态准备** | 是否翻转 180° · 目标朝上面 | 翻转后目标面朝上（能力 C4） | G2/G3 | auth |
| **3 识别与对接** | 视觉定位 · **工位对接公差 ±10mm** · 扫码工位坐标 | 对接偏差≤10mm 否则不作业（能力 A2） | G1/G2 | readonly |
| **4 放置/插入** | **插入深度 35mm** · 力控频率/上限 · 插入重试 | **`end_pose.x > 0.750` 判到位**；力峰≤5N；二次尝试仍不到位→NG | G1 | auth |
| **5 拔出/取回** | 等待测试结果(HMI) · 拔出/夹持力 | 收到测试结果才拔出；不超夹持力上限且工件无位移 | G1/G2 | auth |
| **6 分拣与回位** | Pass/Fail 料盘 · 分拣规则 | 12 穴位不越界·满盘切换；`ng_place_count` 轮换不重位 | G2/G3 | field |
| **7 节拍与循环** | 单件节拍目标 · 双臂协同模式 · 循环守卫 | 达标率≥目标值；模式与工序匹配且无干涉；`pick_place_loop_done` 正常 | G2 | auth |

**上下料的三个粒度（这是它的特点，其它工序没有）**：
```
L1 料盘级  整盘搬运    330×330mm · 12 槽 · 缓存架第 3 层 → 对接台
L2 治具级  治具上下料  200×200mm · 4 定位孔 (精度<0.1mm)
L3 单颗级  单颗物料    18×9×4mm · 光模块单颗 (在治具内)
```
粒度必须写进变体配置：**同一台机器人三个粒度都要能干**，差的是夹具与判据，不是程序重写。

## 3. 防错校验链（Poka-yoke）—— 配置单存在的理由

逐件、7 步，**任一不匹配 = 停线报警，不允许"跳过校验先干"**：

```
① 扫工件码 → ② 查工单 → ③ 选程序(配方+变体) → ④ 校验资源(工具/料位/机器人)
                                   → ⑤ 参数下发 → ⑥ 安全自检(Sys-0 四项) → ⑦ 记录(判据快照+binding_id)
```
汽车产线靠 IPS-I 电子标签/手持终端做的就是这个；机器人侧的等价物是**扫码 + 工单查表 + 参数回读**。

## 4. 实测产物（`python3 tools/build_sheet.py` 真跑）

```
工序配方: 8 段 / 25 条参数 · 安全节 4 · 防错链 7 步
站点工程配置: 就位 6/9 · 缺 T_base_cam, plane_z, cell_geometry.points

工单号                   场景                            BOM 步骤 参数  就绪
BS-SCN-01-FW-0001      FW Loading + EEPROM 写/读校验       7   9  25  站点 6/9
BS-SCN-02-HANDLE-0002  料盘/治具上下料搬运（← 上下料）       3   4  25  站点 6/9
BS-SCN-03-BI-0003      BI老化箱模块插拔                    1   7  25  站点 6/9
BS-SCN-04-THERMAL-0004 热海柜体电口+光口插拔                 1   8  25  站点 6/9
BS-SCN-05-ATS-0005     ATS/线外检测插接                    1   9  25  站点 6/9
```
上下料那张单（`BS_SCN-02-HANDLE.json`）实测内容：
```
identity : BS-SCN-02-HANDLE-0002 · 目标=配送准时率 ≥99.5% · 珞石 Z700
variant  : 缓存架(多层) · 对接台 · 料盘(12槽 L1) · 治具(4定位孔 L2) · 单颗物料 18×9×4 (L3)
bom      : 对接台 400×400×850 · 料盘 330×330×20 · 治具 200×200×15
process  : 取盘 → 配送(差速转向90°+视觉定位销) → 精密对接(4孔 <0.1mm) → 检测(2D/3D/金线显微/分级)
readiness: 25 参数 · 站点 6/9 · blocked_by_site = [src.pitch, sort.pass_tray]
```

**结论（同一根因）**：全部 5 个工单被**同一处**阻塞 —— 站点几何 `T_base_cam / plane_z / cell_geometry` 未标定。
上下料是**坐标驱动**工序：几何没标定 ⇒ 穴位坐标与工位坐标都不可信 ⇒ 单子发不下去。
这和上一份「模型×工程配置」矩阵的结论**完全同源**（唯一受阻=真机域），说明瓶颈不在模型，在**现场几何**。

## 5. 落点（接到已建的 VEH.6 / 画布，不另建体系）

1. **真源升级**：`flows/scenes_5jobs.json`（5 场景，含对象坐标/穴位/步骤/性能目标）→ 扩成
   **工序配方 + 工件变体**真源；工单实例由 `tools/build_sheet.py` 生成（生成物，不手改）。
2. **能力已在库里，不需要新能力**：`feature.dbc` 现有
   `A1 自主导航流转`（场景字段写着"上下料搬运"）· `A2 工位精准对接 ±10mm` · `C4 灵活翻转取放` ·
   `C5 双臂协同`（场景字段写着"上下料批量取放"）—— **上下料是"配置"问题，不是"能力缺失"问题**。
3. **工艺判据已有实测来源**：`docs/orin-grasp-place-workflow.md`（抓取力判据/插入深度/重试策略/容差/Sys-0）。
4. **VEH.6 加第五个配置域「工序·工单」**，MCD 三轴同样适用：
   测量 = 当前工单/料位/节拍/抓取成功率；标定 = 配方参数 + 穴位示教；诊断 = 防错链结果 + 追溯查询。
5. **状态空间画布**：加一条工序链节点（料源→取件→翻转→对接→插拔→分拣→回位），参数挂在节点上，双击进 VEH.6 对应行。
6. **追溯闭环**：一份工单 = 一次 `binding_id`（工件变体 + 站点 + 档位 + 覆盖）⇒ 单件记录可精确还原"当时哪套配置"。

## 7. 红线

- **Sys-0 安全参数永不被工单覆盖**（急停/力阈值/关节限位/光幕）——它不在配方里，在站点里。
- **防错链不许跳过**：任一校验不过 ⇒ 停线，不允许"先干再说"。
- G1（夹持力/插入深度/重试上限/对接公差）只读展示 + 需授权写；写后必回读。
- 工单是**生成物**：真源是 场景 + 配方 + 站点配置；改工单要改真源再重生成，不手改 JSON。
- 诚实口径：选项包（`options.selected`）目前按 `scene_type` **推定**，字段带 `_derived` 标注 ——
  未与产线工艺卡对齐前，不许当"产线已确认"用。
