# l2_daemon.py 怎么 debug · 断点放哪里

📚 2026-10-18 老倪：「l2_daemon.py 我怎么 debug，断点放在哪里？」

先记住三条铁律：

```
① 线上实例（FIFO 执行器）**不下断点** —— 进程一停，臂还按上一条命令在动，8793 的回执窗口还会超时
② 断点只放在"计划层"（算目标/分段/守卫）或 dry 实例里；这两处永不下发
③ 调试实例必须带 ZMAX_L2_DEBUG_DRY=1：收到的任何命令强制 dry，断点停住也不会让臂动
```

---

## 1. 一张图看懂它怎么跑（当前行号）

```
main() 2143
 └─ 2170  while True: reg = maybe_reload(reg)
     └─ 2170  with open(FIFO) as f:  for line in f:        ← 阻塞在这里等命令
         ├─ 2176  spec = json.loads(line)                   ★断点A: 看命令长什么样
         ├─ 2186  手动回点位限速 (manual_point → MANUAL_SPEED_UNITS)
         ├─ 2199  ZMAX_L2_DEBUG_DRY ⇒ spec["dry"]=True
         └─ 2203  dispatch(reg, spec, chan)                 ★断点B: 进执行分支
              ├─ 1376 dispatch()  技能类型分流 (http / gripper / steps / rel / rot / j6)
              ├─ 229  build_move()      相对位移、绝对点 → 目标位姿      ★断点C
              ├─ 794  plan_stage()      多阶段: 算一段目标/Δ/守卫         ★断点D
              ├─ 1154 run_stages()      逐段: plan_stage → 闸 → 下发 → 等到位
              │    ├─ 1218 天花板闸 (taught_z_ceiling)                   ★断点E
              │    ├─ 1234 dry 分支 (DRY-RUN 后 return)
              │    └─ 1973 _send_via_sdk() → 1981 _T.exec_call(call)                ★断点F: 最终字节
              ├─ 1719 _auth_guard()     授权闸                          ★断点G
              ├─ 1847 _fast_block()     VL 快层遮挡/糊化反射             ★断点H
              └─ 971  wait_arrive()     真值等到位                       ★断点I
```

`_send_via_sdk` → `tools/rokae/l2_transport_sdk.py::exec_call()` → SDK 代理容器。

## 2. 三种调试姿势（按安全度排序，日常用 ①）

### ① 计划层：离线调试台（零风险，最常用）

不动 FIFO、不下发，把「命令 → 目标/分段/守卫」整段跑出来，断点随便放：

```bash
cd /home/ubuntu/zmax
./gui-venv311/bin/python tools/l2_debug_offline.py L2.lift --d_mm 50
./gui-venv311/bin/python tools/l2_debug_offline.py L2.forward --d_mm 10
./gui-venv311/bin/python tools/l2_debug_offline.py L2.rot_a_pos --deg 5
./gui-venv311/bin/python tools/l2_debug_offline.py L2.goto_space1 --speed 32 --manual
./gui-venv311/bin/python tools/l2_debug_offline.py L2.slot1 --speed 32 --json
./gui-venv311/bin/python tools/l2_debug_offline.py L2.lift --d_mm 50 --pose 0.60,-0.05,0.40   # 换起点试
```

实测（刚跑的三条）：

```
L2.lift  d_mm=50   起点 (0.6575, 0.0081, 0.3600) → 目标 (0.6575, 0.0081, 0.4100)  Δ=+50.0mm ↑上升(+Z)
L2.forward d_mm=10 起点 → (0.6675, 0.0081, 0.3600)  Δ=+10.0mm →前进(+X)
L2.goto_space1     段 1/3 (0.6575,0.0081,0.3618) · 段 2/3 (0.6575,-0.1236,0.3618) · 段 3/3 同段2
```

在这个脚本里下断点的位置（`tools/l2_daemon.py` 的**同一条代码**被 import 进来执行）：

```
229  build_move       看 cur/curq、atomic 技能口偏置、点位查表
794  plan_stage       看 st(阶段定义)、c(当前点)、返回 pl["pos"]/["dz"]/["speed"]
```

### ② dry 实例：全链路验证通过但不下发

```bash
cd /home/ubuntu/zmax
# 用独立的 FIFO + 独立的锁：不会抢线上管道，也不会把线上实例 SIGTERM 掉
mkfifo /tmp/l2_dbg.fifo 2>/dev/null
ZMAX_L2_FIFO=/tmp/l2_dbg.fifo ZMAX_L2_LOCK=/tmp/l2_dbg.lock \
ZMAX_L2_DEBUG_DRY=1 ZMAX_L2_FORCE_J=1 \
./gui-venv311/bin/python -m debugpy --listen 5678 tools/l2_daemon.py

# 另一个终端喂命令（会被强制 dry）
echo '{"skill":"L2.goto_space1","speed":32,"manual_point":1}' > /tmp/l2_dbg.fifo
```

注意：

```
· 它会执行 main() 的前置检查（等直连链路 / 建通道），日志同样打到 zmax_data/l2_daemon_stdout.log
· keepalive 每 5 分钟看"有没有 l2_daemon.py 在跑" —— 调试实例在跑它就不拉起线上实例，
  所以**调试期间线上执行器是停的**；要恢复：kill 调试实例，5 分钟内 keepalive 会自动起线上
· 想彻底不受干扰：crontab 里临时注释 keepalive 那行，调完恢复
```

### ③ 线上实例：不加断点，只看证据

线上不能 attach（没带 debugpy 启动），用这三个替代：

```bash
tail -f zmax_data/l2_daemon_stdout.log          # 执行器原始日志（受理/SDK 腿下发/到位）
curl -s 'http://127.0.0.1:8793/ctl/log?n=30'    # 页面同源回执
py-spy dump --pid $(pgrep -f 'l2_daemon[.]py')  # 阻塞时看栈（只读，不暂停进程）
```

`py-spy` 不打断执行，最适合"它好像阻塞了"这类问题。

## 3. 断点表（照抄即可）

| 断点 | 位置 | 条件（condition） | 看什么 |
|---|---|---|---|
| A 命令解析 | `l2_daemon.py:2176` 之后 | `'"L2.lift"' in line` | `line` 原始 JSON、`spec` 字段 |
| B 分支入口 | `l2_daemon.py:2203` | `spec.get("skill")=="L2.goto_space1"` | `spec`、`reg["skills"]` 命中项 |
| C 目标计算 | `l2_daemon.py:229` 函数内 | `sk.get("id")=="L2.lift"` | `cur`、`curq`、返回值 `(xyz, quat)` |
| D 单段计划 | `l2_daemon.py:794` 函数内 | `st.get("name")` 含要查的段 | `st`、`c`、`pl["pos"]`、`pl["err"]` |
| E 天花板闸 | `l2_daemon.py:1218` | — | `_ceil`、`pl["pos"][2]` |
| F 最终下发 | `l2_daemon.py:1981` | `"move_line" in call` | `call`（完整 ros2/SDK 载荷）、`_INTENT` |
| G 授权闸 | `l2_daemon.py:1719` | `kind=="运动"` | `CA.epoch()`、`_CUR`、拒绝原因 |
| H 快层闸 | `l2_daemon.py:1847` | `not fresh` | `f`(遮挡/糊化指标)、`fage`、`err` |
| I 等到位 | `l2_daemon.py:971` | `tol_mm` 相关 | `target`、实测 `cur`、残差、`timeout_s` |

VSCode 里设断点更快的方式：`Ctrl+Shift+F` 搜 `def plan_stage` / `_send_via_sdk`，右键行号
「Add Conditional Breakpoint」，把上表条件粘进去。

## 4. VSCode launch.json（两套，照抄）

```jsonc
{
  "version": "0.2.0",
  "configurations": [
    {
      // ① 调试计划层（推荐日常用）：直接跑离线调试台，参数自己填
      "name": "l2_daemon · 计划层(离线)",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/tools/l2_debug_offline.py",
      "args": ["L2.goto_space1", "--speed", "32", "--manual"],
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}"
    },
    {
      // ② 调试执行层（dry 实例，独立 FIFO/锁）
      "name": "l2_daemon · dry 实例",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/tools/l2_daemon.py",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}",
      "env": {
        "ZMAX_L2_FIFO": "/tmp/l2_dbg.fifo",
        "ZMAX_L2_LOCK": "/tmp/l2_dbg.lock",
        "ZMAX_L2_DEBUG_DRY": "1",
        "ZMAX_L2_FORCE_J": "1"
      }
    }
  ]
}
```

要断点停在**收到命令的那一刻**，用 ② 并在 `2176` 行下条件断点；要断在**算目标**那一刻，用 ①
并在 `229`/`794` 下断点，改完直接重跑，不用重启任何服务。

## 5. 变量速查（断点里看这几个就够）

```
spec   命令字典: {"skill","d_mm"/"deg","speed","dry","manual_point","allow_climb_mm","auth_epoch"}
sk     技能定义: {"id","ros","steps":[...],"guard":{...},"param":{...}}
st     steps 里的一段: {"name","point","note","rel","keep_z","climb_limit_mm", ...}
pl     plan_stage 的结果: {"pos":[x,y,z],"quat":[...],"dx","dy","dz","dir","lin","speed","call"}
cur/curq  真值位姿 (m) / 四元数 —— 断点里打印 ["%.4f"%v for v in cur]
pts    点位库 (space1~7 / slot1~7 / taught_points)
```

## 6. 常见坑

```
· 两个实例抢同一条 FIFO: 命令被某个实例吃掉，界面显示"已下发"臂不动 (2026-10-01 实况)
  ⇒ 调试实例一律 ZMAX_L2_FIFO=/tmp/... + ZMAX_L2_LOCK=/tmp/...
· 新实例会"抢班"：main() 的 _single_instance 会 SIGTERM 老实例 —— 所以锁必须分开
· 断点停在运动过程中：进程冻结，臂继续走完上一条 ⇒ 只有 dry 时才允许下断点
· keepalive 5 分钟一次：调试实例在跑就不会起线上实例；调试结束后 kill 掉等它自动拉起
· 日志只看得到 log() 的：VSCode 调试控制台里 stdout 同样会打印，不必再 tail
```
