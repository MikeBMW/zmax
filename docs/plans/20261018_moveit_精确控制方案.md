## 0. 一句话结论

MoveIt **可以直接用来精确控制这台臂** —— 它的模型口径本来就是对的（实测 3mm / 3.7° 常值偏置，
可标定掉），之前那句「FK 与真机差 259mm」是**拿法兰(tool0)去比夹爪尖**造成的假警报（tool1 的
offset 正好 259.8mm）。

真正的精度不来自 MoveIt，来自三件事：**口径统一 + 关节轨迹分段执行 + 到位真值闭环**。
MoveIt 提供的是「可达 / 不撞 / 关节限位内 / 路径平滑」的规划能力。

## 1. 实测地基（今天用一整天的 50Hz 真值算的，零风险）

URDF：`zmax_data/rokae_sdk/urdf/xms5_r800_w4g3b4c.urdf`
真值：`zmax_data/rokae_sdk/tcp_out/tcp_direct_20261018.jsonl`（50Hz，jpos + tcp + quat）

| 口径 | 位置误差 | 姿态误差 | 判定 |
|---|---|---|---|
| FK(**tool0** 法兰) vs 真机 TCP | **259.2 mm** | — | 差的就是工具长度（URDF `joint_tool1` z=0.2587） |

## 2. 精度链分解（每一环怎么收）

| # | 误差源 | 现状 | 处理 |
|---|---|---|---|
| ① | 模型口径 tool0/tool1 | 259mm 假警报 | **改用 tool1 作为 planning tip link**，plan 的目标直接与真机 TCP 可比 |
| ② | 常值偏置 | 3.0mm / 3.66° | 用 ≥200 组静态样本最小二乘拟合 tool1 的 `xyz + rpy` 修正（离线算，写回 URDF 副本，不动原文件） |
| ③ | 关节零位 | 未发现（误差不随位形变） | 若②后仍 >1mm，再拟合 6 个 joint offset（非线性最小二乘，Levenberg-Marquardt） |
| ④ | 规划起点漂移 | plan 用 50Hz tap 的 jpos | **只在静止时规划**：`|v|<0.2mm/s` + jpos 极差 `<1e-4` 连续 6 帧 |
| ⑤ | 轨迹执行精度 | SDK 只有单点 `move-abs` | MoveIt 的 129 点抽稀成 ≤2°/段，逐段 `move-abs`（关节目标），段间核对 |
| ⑥ | 控制器到位误差 | 实测到位残差 0.0mm（控制器自报） | 用**真值**核对（不是自报），阈值 1mm / 0.5°，超差停止 |
| ⑦ | 时间同步 | plan 与执行有时差 | 静止规划 + 段间闭合，感知不到漂移 |

**注意**：MoveIt 不会让绝对精度变好。它管「怎么走合法」；「走到哪」由 ②③⑥ 决定。

## 4. 执行设计（关键细节）

1. **规划请求**：`tip_link=tool1`、`goal=tool1 位姿`（=真机 TCP，同一 base_link）。
   现在 `moveit_plan_req.py` 里 compare 用的是 tool0 的 FK ⇒ 判定函数要改（这也是 259mm 的来源）。
2. **轨迹抽稀**：MoveIt 129 点 → 按「关节最大步长 ≤2°」或「TCP 位移 ≤5mm」二者取严，预计 15~40 段。
   理由：SDK 只有单点 `move-abs`，段太长会丢中间的安全闸；太短会磨时间。
3. **每段过闸**（与现在完全同一套，不新开通道）：`guard_box` 包络 · `z_floor` · 安全区天花板 ·
   VL 快层裁决 · 抬升闸（按段判，>100mm 要 `allow_climb_mm`）。
4. **段间核对**：每段到位后用 `tcp_out/latest.json` 真值比对，偏差 >1mm 或 >0.5° ⇒ 立刻停止、
   不续发剩余段、写台账（含段号/目标/实测/残差）。
5. **失败回退**：任一段被控制器拒（`rc=6` 奇异 / `50102` / `50113`）⇒ 整条 MoveIt 轨迹作废，
   用现有固定分段规则重算（legacy），并把这次失败记成「该目标不适合 MoveIt 路径」的证据。
6. **首段试探**：真机第一次跑 MoveIt 轨迹时，第一段限 2mm / 0.5°（`speed=16` 即 1.5mm/s），
   确认方向对再加长。

## 5. 精度闭环（把 3mm 压到 ≤1mm）

```
① 到点 → 读真值 tcp_real
② err = tcp_goal - tcp_real
③ |err| ≤ 0.5mm 且 ≤0.2°  ⇒ 完成
   |err| ≤ 3mm                ⇒ 目标补偿一次: goal' = goal + err, 重发最后 1~2 段 (最多 1 次)
   |err| > 3mm                ⇒ 停, 报「口径/标定异常」, 不硬凑
```
理由：控制器重复精度远好于绝对精度，一次补偿就能吃掉常值偏差；两次以上会开始震荡。
