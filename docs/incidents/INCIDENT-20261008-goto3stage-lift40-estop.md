## 根因（我的责任）
我把回点配方从"一条斜线"改成三段单轴时（为避开 50102 奇异点），把**横移高度**定成
**目标点 z + 40mm**（`LIFT_MARGIN_MM = 40`）。而 space7 只比当时高 66mm ⇒
阶段1 变成 **+106.5mm**（66 必须 + 40 无谓）。**在"目标只高一点点"的场景里，多出来的 40mm 就是纯多余的上升**，
现场看到的就是"臂原地往上窜"。

更深一层：**老倪今天对"可见的自动上升"已被惊到三次**（08:47 撞净空 / 10:22 MoveJ 乱摆 / 这一次）⇒
任何**非必要**的抬升都会触发他按停。

## 修法（已落地）
1. **余量最小化**：`LIFT_MARGIN_MM 40 → 5`，且阶段1 用 `dz_mm=5` + `adapt_margin_mm=5` ⇒
   横移高度 = `max(当前 z, 目标点 z) + 5mm`（公式 `max(cur+dz, point+margin)`）。
   本例复查：`max(0.2576, 0.3241)+0.005 = 0.3291` ⇒ 抬升 **+71.5mm**（只比"必须的 66mm"多 5mm），
   横移后下落 5mm 到位。
2. **说明义务**：凡是自动流程里会出现**明显抬升**的步骤，事先要能说清"为什么要抬、抬多少"——
   本次是"目标点本身就比臂高 66mm"，抬升无法避免；但不该多抬 40mm。
3. 天花板闸（0.3885）与"被拒就停、不改走 MoveJ"两条保持有效 —— 本次没有触发（是人为按停）。
