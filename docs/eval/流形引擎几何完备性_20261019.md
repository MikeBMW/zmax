## 一、改了什么

原引擎有两个几何缺口。两条都加了开关，**默认关 ⇒ 与旧版逐位相同**（判据 ①② 已证）。

### ① `su2_tangent` —— 补上 SU(2) 的切空间投影（`ZMAX_MANIFOLD_SU2_TANGENT=1`）

```python
# MetricCalculator.tangent_gradient 原代码只处理 sphere:
if self.type == "sphere":
    g = g - p * np.dot(g, p) / max(np.dot(p, p), 1e-12)
```
旧版 **su2 分支完全没有投影**，而 SU(2) 的单位四元数点同构于 S³，切空间同样是 `⟨v,p⟩=0`。
后果：∇Φ 一直带法向分量，这部分下降在下一拍被 `project()` 吃回去 —— 白做功。

**实测法向泄漏 = 70.5%**（随机四元数对，判据 ④）。也就是说旧版 su2 有七成的下降方向在做无用功。

### ② `phi_metric` —— 势函数用度规距离 + 近/远混合（`ZMAX_MANIFOLD_PHI_METRIC=1`）

旧默认 `Φ = ½‖q − goal‖²`（欧氏），度规只在 `distance()` 里生效，梯度流仍被欧氏驱动。
新实现 `Φ = ½·d_M(q,goal)²`，但**必须混合欧氏保障** —— 原因见第三节。

```
c = |⟨p̂, ĝ⟩|
c ≥ 0.35  → 纯度规势 ½d²       (方向最准)
c ≤ 0.10  → 纯欧氏势 ½‖q−g‖²   (度规势此处有驻点)
中间      → smoothstep 过渡
```

## 三、度规势被证伪 —— 这是本轮最有价值的负结果

我原以为「势函数换成度规距离」会更好（`ab_manifold_subspace.py` 的子空间扫描支持这个方向）。
**用引擎真身跑 A/B，结论相反。**

### 3.1 先是纯度规势：k=150 时 cos 从 0.8036 崩到 0.2800

`tools/diag_metric_phi.py` 逐点量 Φ 的梯度（c = ⟨p̂,ĝ⟩）：

| c | θ(deg) | 欧氏势 cos / ‖∇Φ‖ | 度规势 cos / ‖∇Φ‖ |
|---|---|---|---|
| 0.999 | 2.6 | 0.9997 / 0.0447 | **1.0000** / 0.0447 |
| 0.900 | 25.8 | 0.9747 / 0.4472 | **1.0000** / 0.4510 |
| 0.500 | 60.0 | 0.8660 / 1.0000 | **1.0000** / 1.0470 |
| 0.100 | 84.3 | 0.7416 / 1.3420 | **1.0000** / 1.4710 |
| 0.001 | 89.9 | 0.7075 / 1.4140 | **1.0000** / 1.5700 |
| **0.000** | **90.0** | 0.7071 / 1.4140 | **0.4404 / 5.86e-05** ← 驻点 |

**度规势在 c ∈ [0.001, 0.999] 上方向全程完美（1.0000），欧氏势只有 0.707~0.9997。**
但在 **c→0 处塌陷**：`‖∇Φ‖` 掉到 5.9e-05，方向由数值噪声决定。

真因：Fubini–Study 距离用 `arccos|⟨p,q⟩|`，**绝对值在 0 处有尖点**；而 `project()` 的
`bounded_rotvec(v, gain=2.0)` 把远距离状态映射到接近 π 的旋转 ⇒ 真实轨迹 k=150 时大量点
正好落在驻点邻域 ⇒ 梯度塌陷 ⇒ cos 崩到 0.28。

### 3.2 混合势救回一部分，但仍不如基线

| k | 纯度规势 | 混合势 | 基线 A | 切投影 C |
|---|---|---|---|---|
| 5 | 1.0000 | 1.0000 | 0.9965 | **1.0000** |
| 30 | 0.9000 | 0.9284 | 0.9707 | **1.0000** |
| 150 | 0.2800 | 0.4090 | **0.8036** | **1.0000** |

混合把 k=150 从 0.28 拉到 0.41，**仍低于基线的 0.80**。

### 3.3 为什么度规势注定不如「欧氏势 + 切投影」

数学上有一条恒等式：**欧氏势 `Φ = ½‖p−g‖²` 的切空间梯度，精确等于球面上的测地方向。**

```
∇(½‖p−g‖²) = p − g
切向投影:  (p−g) − p⟨p−g, p⟩ = p − g + p(1−⟨p,g⟩) = p(1−c) − g  ∝  −(g − c·p)
而 g − c·p 正是 p 指向 g 的测地方向
```

所以「欧氏势 + 切投影」已经是**方向意义上的最优解**，度规势在这一点上没有任何提升空间。
度规的真实价值只能在**别的指标**上体现（步长/路径长度/能耗/精度），不在「朝不朝目标」上——
这也解释了为什么 `ab_manifold_subspace.py` 的子空间扫描能测出度规差异（它比的是
`∇Φ ↔ 真实位移` 在**各维度加权后**的一致性），而引擎级的「朝目标」指标测不出来。

教训: **布尔开关必须核验所有构造点** (__init__ / load / 副本拷贝), 否则"接了"只是心理安慰。
