# 原子技能「目标输出口」+ 技能驱动仿真 — 落地与判据（v5.50.739 · 2026-10-16）

> 老倪原话：「现在仿真，是通过原子任务输出的么？@xspace 那这些原子任务都有输出么？最终的 moveit 是怎么选择实际的原子任务动作的」
> → 「要动，补上，按照你的建议执行」

## 一、查清的事实（改之前）

| 环节 | 真实情况 |
|---|---|
| 仿真 | **不是**原子任务驱动。`src/lerobot/engine/` 对 `atomic_skills`/`SK01`/`.clamp(` **0 引用**；u 来自前馈加速器 → `decide`（融合+阶段包络/闸）→ 安全限幅 → 执行器 → 仿真器 |
| 原子技能类 | `atomic_skills.py` 有 SK01-08（insert）/ SK07=放入（tray），每个只有 `clamp()`（削动作）+ `phys()/phys_model()`（物理上限）——**没有目标输出、没有轨迹** |
| 真机 L2 技能库 | `data/skills/l2_atomic/registry.json` **97 条**，其中**只有 29 条有动作阶段**；其余是单步/回点/AOI 接口 |
| 通道 | DDS `skill_sk01..08` 8 条 + `ss_live/skill_phys.json`；13 段里 5 段（拔出/AOI转移/AOI检测/回程/放下）无技能类 → 登记为待接，不假装有 |
| MoveIt | **不选动作**。plan-only 容器 `zmax-moveit`（`allow_trajectory_execution=False`），只做 `/compute_ik` + `/plan_kinematic_path`(RRTConnect)；起点=真机关节角，目标由外部给（`taught_points.json` 点名 / `--goal-xyz` / `POST /station/plan`）；输出 `live_plan.jsonl` → DDS `ss_plan`，**只用于看** |
| 真机执行 | `tools/l2_daemon.py`（grep `moveit` = **0 次**）：`build_move(技能 spec + 点位)` → 两条腿 `ros`（产线 ssh→Orin `/move_line`）/ `sdk`（本机直连），下发前过 8793 `ctl_auth` 授权闸 |

**结论**：三环各走各的 —— 仿真靠加速器、真机靠点位、MoveIt 只规划不动。缺的是**技能执行口**（技能类不会输出目标/动作）。

## 二、补上了什么

### 1. 技能类新增目标输出口（唯一依据只此一处）
`src/lerobot/policies/left_right/state_space/skills/atomic_skills.py`：

```python
SK01Approach.TARGET = {"ref": "peg",          "off_key": "hover_h"}     # 接近: 抓握点上方 90mm
SK02Align.TARGET    = {"ref": "peg",          "off_key": "hover_h"}     # 对位: 上方 50mm
SK03Descend.TARGET  = {"ref": "peg",          "off_key": "descend_h"}   # 下降: 贴抓握点
SK04Grasp.TARGET    = {"ref": "peg",          "off_key": None}          # 抓取: 原地
SK05Lift.TARGET     = {"ref": "peg_xy_table", "off_key": "lift_h"}      # 抬起: 提到台面之上
SK06Transfer.TARGET = {"ref": "hole_mouth",   "off_key": "hover"}       # 转移: 孔口上方 20mm
SK07Insert.TARGET   = {"ref": "hole",         "off_key": None}          # 插入: 孔底
SK08Complete.TARGET = {"ref": "hole",         "off_key": None}          # 完成: 保持
SK07Place.TARGET    = {"ref": "point",        "off_key": None}          # 摆盘: 点位库摆放点
AtomicSkill.next_target(ctx=…, points=…, spec=…)   # 🎯 目标位姿 (两种上下文)
AtomicSkill.command(ctx, x, k, v_cap)              # 🎯 期望速度 u = k·(target−x)
```

- **两种上下文，同一份规则**：仿真给几何 `ctx{peg, head_off, table_z, hole_mouth, hole}`；真机给点位库 `points{slot1/insert_pose/…} + spec["point"]` → 点位 + 本段偏置。
- 解不出 → **返回 None**（调用方显示"未生成"），**不编 0 目标**；未知段（拔出/AOI…）→ None。

### 2. 仿真改成从技能口取目标
`src/lerobot/engine/sim.py`：
- `_stage_target()` → `SK0x.next_target(ctx=self._geom_ctx())`，取不到才走同源保障公式
- `STAGE_APPROACH_H / ALIGN / DESCEND / LIFT` 四个常量改为**从技能类 params 取**（不再是第二份数字）
- 新增 `ZMAX_SKILL_FF=1`：u_ff 由 `SK0x.command()` 产出（技能**自己输出动作**），加速器退为对照/探针；`ZMAX_SKILL_K` 调增益

### 3. 真机侧 opt-in
`tools/l2_daemon.py::build_move()`：技能声明 `"atomic": "SK0x"` 才走技能口（位置 = 点位 + 偏置，姿态仍走既定规则）；**97 条在役技能都没有该字段 ⇒ 行为逐位不变**。

## 七、三项未完成的收尾（2026-10-18）

### ① 真物理路接技能驱动 → **实测 FAIL，默认关**（诚实结论）
`ZMAX_SKILL_FF=1` 在 metaworld（`RealStateSpaceSim`, seed104, 500 步）上：

| 臂 | done | 拍 | 插深 | 横向偏差 |
|---|---|---|---|---|
| A 现状（解析伺服 + 反馈） | ✅ | 348 | **64.3 mm** | **2.5 mm** |
| C 技能驱动 k=6 | ❌ | 500（上限） | 41.9 mm | 18.9 mm |
| C 技能驱动 k=10 | ❌ | 500（上限） | 34.4 mm | 14.3 mm |

**根因**：技能驱动是"到名义目标就停"的纯 P 控制（实测 `reached=True, u=0`，err 1.88mm），
而插孔要的是**接触后自适应**：横向量 18.9mm 说明在孔口外就判定到位。真物理路的阶段目标本身带现场策略，
把 u_ff 覆盖成纯 P 等于把这些策略丢掉。⇒ **真物理路不开技能驱动**（解析引擎快 2× 的结论不外推到这里）。
