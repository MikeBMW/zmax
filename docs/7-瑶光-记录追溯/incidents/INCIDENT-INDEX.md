## INC-20261020-02 SDK 力控插入把力打到 83.6N（2026-10-20 18:40~18:48 控时）

🔴 **现场红线（老倪 18:50）: 插入力不能大于 30N。** 代码里预先固定 `FZ_HARD_N=30` / 停手阈值 `FZ_TRIP_N=25`
（`tools/rokae/insert_sdk_fc.py` 顶部），命令行给更大的值也只按 25N 停手，运动中每 20ms 判一次。
推论: **位置模式小步蹭孔这条路彻底不能用** —— 0.5mm 步进对刚性孔口面就是 40~80N，天然违反红线；
能用30N以内的只有"力控给力 + 位移由力控推出来"的路径。

现象：口径"顶在孔口面上没进去"。几何已对齐示教口（Δy 0.00 / Δz 0.00）后仍只推进 2.2mm 就顶住。

力序列（`zmax_data/rokae_sdk/logs/insert_search_*.csv`）：

| 时间 | 做法 | 力 |
|---|---|---|
| 18:43:36 | 位置推进 speed=30（实测 13.6mm/s，不是文档说的 3mm/s） | 20ms 内 -3.6→-27.4N |
| 18:44:01 | MoveL + SDK Lissajous(6/4) | 峰值 19.6N，位移 0.43mm |
| 18:46:58~18:47:15 | 位置模式 0.5mm/步 蹭孔 | 8.6 → 22.6 → 41.0 → 63.9 → **83.6N** |
| 18:47:37 | 力控 6N + SDK Lissajous（K_lat=1000） | 峰值 18.6N，前进 0.56mm |
| 18:48:03 | 对齐后纯轴向推进 speed=3 | 前进 2.23mm 后 4.2N 触发停，峰值 18.5N |

- 根因①：**0.5mm 的位置步进对刚性孔口面 = 几十牛**。位置模式没有力限制，力超阈是我在"这一步走完之后"才看到的，退让已经晚了。
- 根因②：`fcStart` 后立刻读力是未收敛值（同姿态三次 -0.15/+0.15/-16.06N），拿它当零点判据全错；已改成连续两次差<1N 才采用。
- 根因③：被中止的 MoveL 会在**下一次会话**继续执行（实测自己前移 4.68mm）；收尾已加 `moveReset()`。
- 疑似后果：臂相机实时检测框 `box2d=[600.7,451.8,633.9,480.0]`（锁定值原本 `[316.9,0,350.1,57.4]`）⇒ 模块相对相机位移 285×450px，量级 ~10cm ⇒ **模块可能在那几次顶压中滑出夹爪原位**。等现场目检。
- 工具：`tools/rokae/insert_sdk_fc.py`（probe/zero/step/insert/advance/search），走 `bash tools/rokae_sdk_run.sh --script ...`；力-位移 CSV 与 JSON 证据全在 `zmax_data/rokae_sdk/logs/`。


## INC-20261020-03 · 力控一起就触发 41451 下电, 改"位置推+被动看门狗"
- 时戳: 2026-10-20 19:02~19:12 (控时), 连续 5 次
- 现象: 模块顶在孔口硬接触状态下, `fcStart` / `setLissajousOverlay` / `moveStart` 任一步都报
  `ec=-17 motor power state unsupported operation`, 控制器 `powerState=off`,
  报警 `41451 力控模式触发保护: Cart Velocity OverLimit`。K_z 给 0 / 2000 / 20000 都一样。
- 根因: 不是刚度、不是姿态(tool Z 已调水平 -0.000° 复现同样问题); 是硬接触下力控回路给不出合法速度。
- 对策(已验证): `insert_sdk_fc.py --mode push` —— 位置模式 MoveL 慢推(0.45~1.9mm/s),
  力控全程不启动, `getEndTorque` 只做被动看门狗(每 20ms 比 ΔFz, 30N 停手, 硬红线 40N, 侧向 6N 停)。
  之后 3 发(推 10mm / 退 5mm)全部正常, 无下电。
- 红线: 老倪 19:1x 现场改口径 **最大插入力 40N**(18:50 为 30N); 侧向须控制, 不得划伤模块侧面。
- 数据: `zmax_data/reports/insert_session_20261020_1918.json`

## INC-20261020-04 · 力停手 ≠ 力消失: 楔紧后六维力自涨到 179N; 快指令在孔口楔死
- 时戳: 2026-10-20 19:48~19:51 (控时)
- 现象1: 快速插拔(speed 15 ≈6.8mm/s)在孔口段被楔住 —— 退 60mm 只动 2.73mm 就 力矩 Δ11.04Nm/轴向 Δ35.8N 停;
         随后慢退 3mm 也只动 0.93mm 就 ΔFz 30.9N 停。
- 现象2(最危险): `axial_stop` 之后脚本 `stop()` 只保持位置, 模块楔在孔里伺服一直顶着,
         六维力 **|F| 35N → 119.8N → 178.8N(fx -165.9N, |T| 54.8Nm)** 自己往上走, 不会回落。
         用 `move-rel --dx -3 --speed 3` 回退 3mm 后立刻掉到 **12.6N**(|T| 0.4Nm)。
- 现象3: 一次 kill -9 打断运动中会话 ⇒ 控制器里残留 MoveL 队列在新会话 moveStart 时继续跑,
         实测臂一次自走 **150mm**(0.80294 → 0.65198)。之前已知此坑, 但 kill 比 stop 更容易触发。
- 对策(已实现):
  1. `insert_sdk_fc.py` 增加 `unload_after_stop()`: 任何 force/axial/lateral/torque_stop 之后自动沿轴退 1.5mm 卸力再报数;
  2. 会话开头强制 `stop() → moveReset() → 0.25s 内位移 >0.05mm 则拒发新指令`(预静止闸);
  3. 断会话用 `sdk_ctl.py stop`(规划停), **不用 kill -9**;
  4. 孔口段(socket mouth)必须 ≤1mm/s + 小摆幅李萨如; 快接近段只能停在孔口**之前**≈60mm,
     因为 seat 点距孔口约 50mm, `--approach-mm 15` 会让"快段"一直冲到孔口里。
- 数据: zmax_data/rokae_sdk/logs/insert_fc_lissa_*、insert_fc_seat_*、push_*.csv; sdk_ctl_stop_*.json
