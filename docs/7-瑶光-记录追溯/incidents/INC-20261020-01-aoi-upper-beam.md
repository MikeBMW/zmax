## 为什么工具没拦住

1. `precheck_move.py → arm_polylines()` 返回的是**数学线段**（无半径），距离 55.5mm > 20mm 门槛 ⇒ PASS。
2. 同一脚本对 `dx=0/−100/+100` 三个目标报同一个数值 ⇒ 它对"起手姿态已侵入"无能为力。
3. **手臂相机**根本不在围栏表（`/api/fence` 只有 3 个 box + 3 条线）⇒ 相机永远算不到。
4. 我自己用欧拉角推法兰位置，y 差 251mm，导致给出"法兰距横梁 300+mm 安全"的错判——真实只差 40mm。

## 修复

- `tools/precheck_move.py`：每段扣本体半径（r95/95/90/78/78/62/58），**净余量 < 20mm 直接 FAIL**。同姿态复算：`PASS 145.6` → `最小 38.8mm + 夹爪包络 8.1mm FAIL`。
- 新增 `tools/fk_link_check.py`：读 URDF + `latest.json` 真实关节角做正解，逐级报 link 原点、扣半径后的净间隙、侵入标记。**以后判"肘/腕会不会碰"只认它。**
- 规则固化：tool0 一律读 `agent_heartbeat.json → pose.flange`，禁止手推 R·t。

## 未闭环

- 连杆本体半径 58~95mm 仍是估算值，需要实际外壳尺寸标定；否则 precheck 与 fk_link_check 会给出 38.8mm vs −22.5mm 的分歧。
- 手臂相机（随臂 D405）未建模：需镜头相对法兰的偏移 + 本体包络尺寸，才能建成第 4 个 box 围栏。
- `L2.goto_safe1` 技能包络不含 x≈278 一带（会报「目标出已验证包络」）。
