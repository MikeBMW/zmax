**工程**：状态空间工程 · 主工程　**画布**：状态空间架构 v5.4 三级能力: 🏆专家=世界模型技术(流形导航/潜空间) · 🚀高级=端到端模仿学习(VLM+Flow-Matching) · 🔧基础=分段式小模型(YOLO/前馈MLP/原子技能)（94 节点 / 214 连线）

## 一、项目概述

### 1.1 目标
把状态空间工程中**每个功能的清单项叠加其配置参数**，固化为可独立开发、可配置、可验证的**元任务**；
在 2026-10 ~ 2027-12 内完成全部元任务的开发、接入与验收，并保证工程数据一致性。

### 1.2 元任务定义
> **元任务 = 一个功能（FN-SYSx-N）+ 该功能的全部配置参数 + 依赖 + 验证方法 + 归属层**

数据唯一依据（全部实读，不人工编造）：

| 唯一依据 | 路径 | 内容 |
|---|---|---|
| 功能元数据 | `data/database/zmax/config_meta.json` | 77 个功能的字段/范围/单位/默认值/依赖/验证 |
| 参数注册表 | `sources/config/mcd/param_registry.json` | 每个参数的当前值/默认/min/max/单位/档位 |
| 任务配置 | `sources/config/tasks/tasks.json` | 8 个任务的工序/参数覆盖/触发循环 |
| 任务绑定 | `sources/config/ss_task_binding.json` | 任务 × 节点 × 配方段 绑定 |
| 画布工程 | `src/lerobot/engineering/flows/state_space_obs.json` | 89 节点 / 184 连线 |

### 1.3 工程基线（实测）

```
画布节点 94 = model 64 + row_bg 15 + hardware 7 + system 3 + condition 2 + data 2 + mode_switch 1
功能 77 / 元数据完整 66 (85%) / 不完整 11
参数 2298 条（含通用标定基线 + 功能专属）
任务节点集：TASK-06-TRAY=53 · TASK-01-FW=53 · TASK-02-HANDLE=44 · TASK-03-BI=53 · TASK-04-THERMAL=53 · TASK-05-ATS=53 · TASK-07-AOI=33 · TASK-08-AL1=37
```

**关键结论（决定元任务模型）**：全部 8 个任务的启用节点都是同一 53 节点集的**子集**，
无任何任务专属节点 ⇒ **元任务（功能）为全工程共用，任务之间只差配置**（`overrides` 参数覆盖 + `applies_segments` 配方段 + `run_cfg` 执行开关），
与工程口径“一个状态空间工程承载全部任务；任务 = 配方段子集 + 参数覆盖”完全一致。

## 四、开发排期（2026-10 → 2027-12）

### 4.1 排期原则
1. **摆盘（TASK-06-TRAY）、插拔（TASK-01-FW）优先**：这两个任务启用的节点集覆盖全部 7 个任务的所有节点，
   因此把**支撑它们所需的全部元任务**压在**前 9 个月**（2026-10 ~ 2027-06）完成；
2. **层序推进**：L2（感知/控制/执行/安全底座）→ L3（长程规划）→ L4/L5（自主决策）→ PLAT（平台支撑）；
3. **复杂度优先启动**：参数多、依赖多的元任务先开工（迭代周期长）；
4. **依赖不越级**：被依赖的元任务先于依赖者完成；
5. **明年年底（2027-12）全部 77 个元任务收口**。
