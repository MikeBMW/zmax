## 三、背景技术

### 3.1 现场现状（工程记录）

在与本申请相关的工序上，现场实际遇到的情形如下（均为工程记录，非假设）：

1. 3.1 接口形态不匹配：仿真/规划器输出的是连续速度向量 v ∈ ℝ³（mm/s），可持续变化；而工业生产用机械臂控制器出于安全考虑，通常只开放白名单离散技能（如 forward / backward / left / right / lift / lower），每次只接受单轴、定长、限速的位移指令。
2. 3.2 直接映射的三类风险：- 超速：把仿真速度直接当作指令速度下发，超出安全速度上限； - 超程：单次下发长距离，一旦中途出现碰撞或定位偏差，损失不可控； - 不可中止：一次长动作在队列中执行，中途无法按现场判断立即停止。
3. 3.3 授权与安全闸门不可绕过：真机动作必须经过既有授权流程（人工确认授权窗口）、白名单校验、限流与执行器安全裁决。若跟随模块自建通道或自行授权，等于绕开全部安全机制。
4. 3.4 指令与实际不符无法察觉：下发 5mm 与实测位移 5mm 之间可能因碰撞、未使能、急停、控制器限幅而不一致。若不核对真值，跟随会在"以为在走"的状态下持续累积误差。

### 3.2 结构性原因

上述 4 条并非孤立现象，而是同一个结构缺口在不同场合的表现：在**工程可信层/动作层**这一环上，缺少一个统一的、可被下游直接消费的约定 —— 各环节按自己的理解处理同一件事，因此结果既无法互相校验，也无法在改动后被追溯。

本发明不新增工序，而是在这一环上补上这个约定，并让它可以被逐项核对。

## 六、有益效果

1. 1. 接口不匹配问题被消解：连续速度流可安全驱动只支持离散技能的工业控制器。
2. 2. 三重风险同时受控：超速（限速常量）、超程（单步定长）、不可中止（逐步下发 + 使能开关）。
3. 3. 不绕安全体系：跟随复用既有授权与闸门，不新建特权通道。
4. 4. 误差不累积：每步真值核对，碰撞/未使能/急停立刻暴露，而非走完一段才发现。
5. 5. 可预演：现场可先看"会发什么"再决定是否执行。

## 八、具体实施方式

### 8.1 实施例

1) 6.1 实施例环境：规划器输出 v_cmd（mm/s，已限幅 ≤10），真机为工业机械臂控制器，仅开放白名单技能。跟随模块 tools/bridge_follow.py。
2) 6.2 参数与判据：单步 STEP_MAX_MM（单段行程上限，硬编码） 限速 SPEED_CAP_MMS = 10.0 mm/s（硬编码，现场口径「不超过 10mm/s」） 单步真值偏差上限 ERR_MAX = 2 mm 最大步数上限 = 可配置，默认 20 实际平均速度 = 5mm / 单步耗时 ≤ 5 mm/s
3) 6.3 执行序列：读 v_cmd → 取主轴（如 +X）→ 映射技能（forward） → 下发 {forward, 5mm, 10mm/s, arm:true} → 立即读真机 TCP，期望位移 5mm → 实测偏差 0.4mm ≤ 2mm ⇒ 继续下一步 → 若中途实测偏差 3.1mm > 2mm ⇒ 停手并记录
4) 6.4 安全红线（落地实现）：- 绝不自行授权，只读授权状态； - 每步经过既有闸门，不绕； - 单步 5mm / 10mm/s 硬编码，改动须改代码常量； - 桥接关闭或授权失效，立即停止。
