## 1. 发明名称

一种长耗时感知任务与短周期控制回路的异步快照解耦方法及系统

## 2. 技术领域

本发明属于具身智能与机器人实时控制技术领域，具体涉及一种在同一控制系统中，将耗时尺度相差 1~2 个数量级的感知任务（视觉检测、质量判决、大模型推理）与高频控制回路（10Hz~1kHz）解耦的方法，使感知结果以"最新快照 + 可观测时效"的形式被控制回路消费。

## 3. 背景技术

**3.1 耗时量级失配**
精密装配工位的视觉检测（含多路旁路、缺陷判定、YOLO 推理）实测单次耗时 **1.3~3.0 秒**；而动作控制回路要求 **10Hz（100ms/拍）**。同步执行意味着每拍阻塞 1.3~3.0s，控制频率被压到 0.3~0.8Hz，动作完全失去连续性。

**3.2 简单降频不可行**
降低检测频率会导致缺陷漏检；提高控制周期则违反机械臂安全节拍要求。二者无法用单一周期统一。

**3.3 结果"过期"无法识别**
异步化之后，若下游不知道"这条检测结果是多少秒之前拍的"，就会把陈旧判决当作当前状态使用。尤其在装配过程中（工件位置每拍都在变），1.5s 前的检测结果可能对应完全不同的位姿。

**3.4 未就绪状态被误判为异常**
异步首拍必然无结果。若把"尚未有结果"与"检测失败"混为一谈，会导致启动瞬间误报警或误停机。

## 4. 发明内容

### 4.1 核心思想

**控制回路只读快照，不等待计算。** 把长耗时任务移入独立工作线程按固定周期执行，控制节点每拍以**常数时间**读取最新一份结果快照，并同时取得该快照的**帧龄（age）与序号（seq）**，由下游依据帧龄决定信任程度。

一句话：**算的归算，控的归控；用的时候看它多旧。**

### 4.2 步骤 1 · 工作线程与固定周期

为长耗时任务建立常驻工作线程，按 `interval` 周期循环执行完整流程：

    while alive:
        if now - last_start < interval: sleep(短)
        result = do_full_work()        # 可耗时 1~3s
        snapshot = {result, ts, seq+=1, ok, err}
        store(snapshot)                # 原子替换

周期应大于单次耗时，避免任务堆积；若单次超周期则自然降频，但**不阻塞控制回路**。

### 4.3 步骤 2 · 原子快照与只读消费

控制节点每拍仅执行：

    snap = read_latest()               # O(1)，不复制大对象
    age_s = now - snap.ts
    if snap.seq == last_seq: 沿用上次; 否则视为新结果

写侧以**整体替换**方式发布快照（而非逐字段写入），读侧永远读到自洽的一版，避免读到"半更新"的中间态。

### 4.4 步骤 3 · 时效可观测（帧龄）

快照必须携带 `ts`，并由消费侧计算 `age_s`。**帧龄必须进入下游输出**，使：

- 上层可视化可标注"该数值拍于 X 秒前"；
- 判决类逻辑可设置**过期阈值**：`age_s > T_stale` ⇒ 视为"无有效判决"，不据此做出不可逆动作（例如不据此放行、也不据此硬否决）。

> 关键设计取舍：过期**不等于**失败。过期只能导致"降级为不裁决"，不能导致"判为不合格"——否则陈旧数据会误拦产线。

### 4.5 步骤 4 · 首拍未就绪与失败分离

快照状态区分三态：

| 状态 | 含义 | 下游行为 |
|---|---|---|
| `absent` | 尚无快照（首拍） | 不裁决、不报警 |
| `ok` | 有结果且在有效期内 | 正常裁决 |
| `err` | 有过结果但最近一次执行失败 | 按失败策略降级，并保留 `age_s` |

### 4.6 步骤 5 · 非阻塞失败的旁路降级

长耗时任务内部常含多路外部调用（远端服务、模型推理）。任一路不可用时：

- **不得阻塞**主流程等待超时；
- 记录该路为 `unavailable` 并启用**冷却期**（避免每拍重试造成雪崩）；
- 其余路正常出结果，输出中如实标注哪一路缺失，**不以默认值冒充**。

### 4.7 步骤 6 · 耗时验收口径

必须实测并报出两个数：

- 工作线程单次完整耗时 `T_work`；
- 控制节点单拍耗时 `T_node`（应 ≤ 常数，与 `T_work` 无关）。

判据：`T_node << 控制周期`，且 `T_node` 不随 `T_work` 增长。

## 5. 权利要求书

1. 一种长耗时感知与短周期控制的解耦方法，其特征在于：将耗时任务置于独立工作线程按固定周期执行，并以**整体替换**方式发布结果快照；控制节点每拍以常数时间读取最新快照而不等待计算，且快照携带时间戳与递增序号。

2. 根据权利要求 1 所述方法，其特征在于：消费侧计算并输出所述快照的**帧龄**（当前时间与快照时间戳之差），并依据帧龄阈值决定是否采信该结果。

3. 根据权利要求 2 所述方法，其特征在于：帧龄超过阈值时判定为"无有效判决"，执行**不裁决**（既不据此放行也不据此否决），而非判定为失败。

4. 根据权利要求 1 所述方法，其特征在于：快照状态区分为"尚无结果 / 有结果 / 最近一次执行失败"三态，首拍"尚无结果"不触发报警。

5. 根据权利要求 1 所述方法，其特征在于：所述耗时任务内含多路外部调用时，任一路不可用即标记为不可用并进入**冷却期**，其余路继续出结果，且输出中标注缺失的路别。

6. 根据权利要求 1 所述方法，其特征在于：控制节点单拍耗时与工作线程单次耗时**解耦**，前者不随后者增长。

7. 一种长耗时感知与短周期控制解耦系统，包括存储器与处理器，所述处理器执行程序时实现权利要求 1-6 任一项所述的方法。

## 6. 具体实施方式

### 6.1 实施例环境

光模块装配工位质量检测节点（`ss_aoi.py`）。检测内容：表面缺陷判定 + 多路旁路（远端 AOI 服务两路 + 本地 YOLO 一路）+ 取像健康度体检。

### 6.2 解耦前后实测

| 方案 | 控制节点单拍耗时 | 说明 |
|---|---|---|
| 同步执行 | **2,537.8 ms/拍** | 控制频率被压至 0.39Hz，动作不连续；若按 10Hz 计，250 拍才完成一秒的动作 |
| 异步 worker + 快照 | **1.4 ms/拍** | 降低约 **1,800 倍**，与检测耗时无关 |

工作线程周期 2.0s；实测帧龄 `age_s = 1.68s`，在输出中如实标注。

### 6.3 旁路降级实测

产线远端服务不可达时：

    remote = unavailable（冷却 60s）
    gold_remote = unavailable
    gold_yolo = None
    其余路正常：verdict=gaps_washed, pass=false, 缺陷数=76, sig_n=8

输出如实标注三路缺失，耗时不受影响，不拖节拍。

### 6.4 时效的正确用法（实测反例）

若将"帧龄过大"直接判为不合格，会在检测空窗期误拦产线。本发明要求过期只降级为"不裁决"：

    取像不健康 / 过期 / 无判决  →  不拦（放行名义动作）
    取像健康 且 pass=false      →  硬否决
    取像健康 且 pass=true       →  放行

该四态裁决已实测六个工况全部正确，且断开该链路时行为零回归。

## 7. 有益效果

1. **控制回路不再被感知拖死**：单拍耗时从秒级降到毫秒级（实测 2,537.8ms → 1.4ms）。
2. **时效可审计**：帧龄进入输出，上层可标注"数据拍于何时"，不再有"看着像实时其实是旧值"的隐患。
3. **不误拦产线**：过期只降级不否决，避免陈旧数据造成停线。
4. **失败可区分**：首拍未就绪、执行失败、结果过期三态分离，排查有据。
5. **多路旁路不雪崩**：冷却期 + 独立降级，单路故障不影响整体节拍。

## 8. 与状态空间工程体系的关系

状态空间工程的实时性前提是**每一层都按自己的时间尺度运行，只在收口处对齐**：
L4 流形与 L3 动作头按控制周期走；L2 检测、L5 规划按慢周期走；二者通过"带帧龄的快照"耦合。

本专利是这一分层时间解耦在节点级的具体实现，与 ZMP-2026-014（视觉质量门的四态裁决）配套：**014 决定"怎么判"，016 决定"什么时候的判决才可用"。**
