## 三、改了什么 + 根因

1. `tools/ss_task_bind.py` — 新增 `ss_mode`（由任务工艺机械推出）；**修真 bug**：段→节点映射里
   `抬起/转移/完成` 原来只挂在「5 拔出/取回」段 ⇒ 摆盘任务（不含该段）反而把取放链必需的
   SK05/SK06/SK08 关掉了。现：抬起/转移 归「1 取件」、完成 归「4 放置/插入」、段 5 只留拔取。
   六档位也随 mode 变（摆盘不再勾「插拔+AOI 全链」）。
2. `state_space/cognition.py` — `TRAY_MODE`：同一八阶段状态机，第 7 段语义由配置决定
   （转移段在 tray 模式下水平到位即进「放入」，不走孔口/插入）。
3. `state_space/skills/atomic_skills.py` — 新增 `SK07Place` + `skills_for_mode(mode)`。
4. `tools/sim_scene_def.py` — **tray 盘真源几何修复**：凹槽开口只有 10~15mm，而光模块宽 20mm
   ⇒ 件物理上放不进去（实测只能骑在隔板棱上：落座高 +3.6mm、单边偏 2.5mm）。节距 30→38mm、
   隔板厚 10→5mm（开口 28mm，单边留 4mm）。3D 视图与仿真同源，自动跟。
5. `tools/gen_tray_place_video.py`（新）— 摆盘 episode：状态空间六层源码直驱 metaworld，
   真空吸附按 TASK-06-TRAY 真机工艺建模为**工具坐标 TCP**（吸嘴尖 = 手位 −75mm；两指夹爪指垫
   30mm 高探进 24mm 深盘必撞壁，实测卡在盘壁顶面 z=0.038）。
6. `tools/gen_tray_place_scene.py`（新）— 摆盘场景 XML 生成器，真源 = `sim_scene_def._tray_layout()`。
7. `tools/ss_task_runner.py`（新）— 配置驱动入口（上表）。
8. 视频机位 — `env.render()` 用构造时锁死的 corner2 斜视，件落进深盘后只剩 ~9px（等于看不清）→
   换 MuJoCo 原生近俯视 960×720（件 ~950px/颗；末帧盘内 3 颗金色像素实测 2846，判据帧可核）。

## 四、级联修复（都是实测撞出来的）

- `pin_module` 只设 qpos 不清 qvel ⇒ 自由关节速度累积（每步 −9.81×ctrl_dt），件越掉越深
  （钉 0.35 读到 0.343）⇒ 抬起目标追活件时**飞车**。修：清 qvel。
- 抬起/转移目标原来跟随**活件**位置 ⇒ 目标自我抬升飞车。修：吸附时刻锚定（`top0`）。
- 释放时机 6mm → 1.5mm（6mm 就放，件落下横向漂 2.2mm 撞隔板）。
- `TrayEnv.reset_model/evaluate_state` 覆写：摆盘场景没有「带孔盒」，父类要读 box 的 site（KeyError）。

## 五、未关项（诚实列出）

1. **夹爪打不开**：本机相机近黑（USB mean 5.0 / 内置 5.3，uniform=1.00 lap=0）⇒ 快层 VL 安全闸
   fail-closed 拒发 `L2.grip_open`（5 次点击执行器全收到、每次被闸拦，原文留痕）。两条路：现场把
   相机弄出画面（哨兵 `tools/gripper_open_sentinel.py` 会自动发一次开爪）/ 用户说「关闸」临时停闸。
   我**不擅自关安全闸**。
2. 金手指 AOI「整板原图」现象待确认（后端每条链都出图：10082 `/picture?kind=origin` = 2448×2048
   真图；8791/8793 `/aoi_gold_raw.mjpg` = 1400×1171 整板缩图，与上游逐位一致）——待确认是「点了完全
   不出图」还是「切过去又跳回判据图」。
3. 真机链路依赖产线 USB 网卡在位（Orin 192.168.23.66 / 工控机 192.168.23.50 / AOI 10082·10083）；
   网卡不在位时不可达，且**拒发动作**（按纪律）。
4. 仿真判据只证明「状态空间自驱 + 物理落座」；真机重复定位精度需现场实测（未实测不填数）。
