# 内存 OOM / 死机事故复盘 — 2026-10-18

## 一、结论（一句话）

**吃内存的是 `tools/gui/studio.py` 控制台 GUI**（PyQt + 调试器拉起），不是 Pylance。
单实例跑 8h53m 涨到 **20.2GB RSS + 8.5GB swap**；清掉之后当天又被 **F5 启动 7 次**，
VSCode 窗口期间崩溃 3 次留下孤儿实例继续泄漏 ⇒ 内存与 swap 双双耗尽 ⇒ 系统卡死。

## 二、时间线（有日志证据）

| 时间 | 事件 | 证据 |
|---|---|---|
| 10-16 17:58 | 开机 | `last -x` |
| 10-18 08:30 前 | 某 studio.py 实例已跑 8h53m，RSS **20.2GB** + swap **8.5GB**，available 仅 **475MB**、swap 满 | `ps aux --sort=-rss`、`free -m` |
| 08:33 | 手动清理：SIGTERM 该实例 + 停两个 Restarting 崩溃容器 + drop_caches + swapoff/swapon | `kernel: Adding 8388604k swap on /swapfile`(08:33:35) |
| 08:35 | available **12 990MB**、swap **0**；在役守护（engine/sam3/tdrive/hil）全存活 | `free -m` |
| **08:52 / 09:40 / 10:28 / 11:17 / 12:00 / 12:10 / 12:14** | **又启动 studio.py 7 次**（VSCode F5 / 重启调试） | `~/.config/Code/logs/*/.../ms-python.debugpy/*.log`: `DAP Server launched` |
| 11:16 / 12:00 / 12:10 | VSCode 窗口崩溃重启 3 次（每次可能留下孤儿 studio.py） | VSCode `logs/20261018T111652`、`T120005`、`T121026` |
| 12:14 之后 | **应用层日志空白**（系统 thrash，写不出日志） | `journalctl -b -1 --since 11:50` 仅关机流程 |
| 12:26:36 → 12:26:48 | 干净 poweroff（swap deactivate → final target → Journal stopped） | `journalctl -b -1` |

**关键判定**：内核 **没有** `Out of memory` / `Killed process` 记录，`systemd-oomd` 也无杀进程动作
（累计 49.1s CPU 但无 action 日志）⇒ 不是被 OOM killer 干净杀掉的，而是 **swap 满 + 内存满 → 全局回收式 thrash**
→ 所有进程（含日志）停摆 → 表现为"死机"，最后是人为 poweroff。

## 三、根因

1. **studio.py 单实例无限增长**：8h53m / 20.2GB ≈ 2.3GB/h（启动即刻 1.8GB+，PyQt + torch/CUDA 基线大）。
   代码层具体泄漏点**未定位**（`QTextEdit` 追加 0 处、无 `setMaximumBlockCount` 需求；`_src_cache` 是单元素），不猜。
2. **多实例叠加**：一天 7 次 F5 启动，3 次 VSCode 窗口崩溃 → 旧实例脱离调试器成孤儿（`ppid=1`）继续涨。
3. **没有上限保护**：单进程 RSS 无 cgroup 限制、无看门狗 ⇒ 一路涨到把整机拖死。

## 四、已加防护

`zmax-studio-mem-guard.timer`（systemd，每 2 分钟，`tools/studio_mem_guard.py --enforce`）：

| 规则 | 动作 |
|---|---|
| 单实例 RSS ≥ **8GB** | SIGTERM + 记 `zmax_data/ops/studio_mem_guard.jsonl` |
| 孤儿实例（`ppid=1`）且 ≥ **2GB** | SIGTERM（叠加泄漏的来源） |
| 全部实例合计 ≥ **12GB** | 先杀最大的那个 |

- 只做只读判断 + 精准 SIGTERM，**不碰**引擎 / 采样 / 总线 / 桥。
- 阈值由 `STUDIO_MAX_GB` / `STUDIO_ORPHAN_GB` / `STUDIO_TOTAL_GB` 覆盖。
- 手动查看现状：`python3 tools/studio_mem_guard.py --status`
- 安装脚本：`tools/install_studio_mem_guard.sh`（幂等）

首次运行实测：`studio 看门狗: 2 实例 合计1.89GB 最大1.87GB · 正常`。

## 五、还欠的

1. **泄漏点没定位** —— 需要让一个实例跑 30~60 分钟并周期性抓 `tracemalloc` / `objgraph` 快照对比，
   或按页统计（`/proc/<pid>/smaps_rollup` 的 Private_Dirty）判断是 Qt 图像缓冲还是 Python 对象堆。
2. 若确认是显示层缓存（相机帧/曲线点），在上限处加环形缓冲就能根治；此事要动 GUI，属于"改码攒批"范围。
3. 复查 `VSCode 窗口崩溃` 本身的原因（3 次/2 小时异常），它才是孤儿实例的源头。
