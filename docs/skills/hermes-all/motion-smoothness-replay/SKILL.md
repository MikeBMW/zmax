# 让闭环执行的动作平顺 (S 曲线由规划节点发出 + 时间回放)

适用于「闭环控制跑得准, 但动作一段一段顿、段首/换段时抽一下、肉眼看着不如回放流畅」这类问题。

核心口径: **轨迹要由规划/L2 节点实际发出, 执行端只按时间采样 + 小增益纠偏** ——
不是在执行端里写死一串点, 也不是靠调 P 环增益糊。参照物是**时间参数化回放** (每帧位移恒定)。

## When to Use

- 用户说「动作不连续 / 一顿一顿 / 段首抽一下 / 不如回放流畅」或要求「像 UPH 回放一样平顺」
- 给闭环执行链加轨迹平滑 (S 曲线 / 时间参数化 / 速度包络) 并由规划节点发出
- 已经改了速率/增益但肉眼仍觉得顿, 需要先用指标定位到底是跳支、量化台阶还是段间硬切
- 要同时保「动作连续」和「件节拍(UPH)」, 需要判断段表/规划链里有没有靠瞬移白拿的时间（见「节拍与平顺同时要时的铁律」）
- Don't use for: 纯轨迹规划验证 (不真动), 或真机安全闸/授权流程 (见对应真机技能)。

## Procedure

1. **先量化, 别先改**。按 20~30Hz 连续采 `truth.tcp<side>` 或关节真值 ≥40s, 算四个指标 (见「验收口径」)。
   这一步决定是「跳支」「量化台阶」还是「段间硬切」, 三条路修法完全不同。
2. **在规划节点里加 S 曲线发生器** (五次多项式, C2, 首末速 0):
   ```
   L = |p1-p0|
   T = max(1.875*L/v_cap, sqrt(5.7735*L/a_max))    # 峰速 1.875L/T, 峰加速 5.7735L/T²
   返回 {T, dt, n, pts[], vel[], v_peak, a_peak, src='<节点名>.smooth_traj'}
   ```
   `v_cap` 取段标定真源 (如 `zmax_skill_physics.json` 的 `skills.<stage>.v`), `a_max` 起步 2.0 m/s²。
   返回里带 `src` = 节点名, 日志/取证能对账「这条轨迹谁发的」。
3. **执行端改成按时间回放** (不是每拍重算速度):
   - 每 `dt` (20ms) 等时到达 → 读真值 → 到 tol 就 break (真值判据, 不看指令)
   - `cmd = pt + clip(K*(pt - tcp), ±corr)` (K 0.15~0.35, corr 4~6mm) 补 PD 静差
   - 单拍位移限 `v_cap*dt*1.5`, 超了沿方向截断 (绝不跳)
   - IK 带 `seed`(上一条指令, **跨步保留**) + `rate`; 失败升档 rate 重试一次; 仍失败就保持上一条指令
   - S 曲线走完后加**收尾逼近相位**: 20ms 小步 (每拍 ≤4mm), 时限 3s 上下
4. **保留回退开关** (`XXX_REPLAY=0` 走老链), 改完当场跑一轮并复测四个指标。
5. **段间过渡最后做** (corner blending: 段末 15% 混入下一段方向)。先保证段内平顺, 再动段间。

## Pitfalls

1. **一发式 IK 是最大的一跳**: 任何「把臂搬到某处」的调用 (停机位/让出视野/回 home) 若只给 `side/x/y/z`
   而不带 `seed`/`rate`, 会落进 IK 的另一个解 ⇒ 单帧真值跳几百 mm, 之后 PD 花 7~8 拍追回。
   规则: 所有运动入口走同一条回放; 真需要一步到位时至少给 seed+rate。
2. **改函数返回值契约会引爆调用方重试**: 平滑化一个 `park_clear`-类函数时丢了 `{"ok": True}`,
   调用方 `r.get("ok")` 抛异常 → 进重试循环 12 次, 每次重新摆场 ⇒ 与闭环控制环**抢同一个臂**
   (表现: 某一步永远差 190mm, 采样里出现 118mm/37ms 的假高速)。
   规则: 动一个「调用方判 ok 的函数」前后, 回读所有调用点的判据字段, 保持返回形状。
3. **控制环必须单飞**: `/run` 类接口可被叠加触发, 两条控制环同时下发会互相把臂拽走。
   规则: 模块级非阻塞锁 (`threading.Lock().acquire(blocking=False)`), 已在跑就记一行日志并忽略本次请求。
   诊断特征: 同一步到位值随机变大 (190mm) + 速度序列里冒出不可能的尖峰。
4. **`/reset` 是场景瞬移不是运动**: 一次 reset 就是双臂瞬间回 home (实测一帧 660mm)。每轮都 reset ⇒
   视频开头必抽一下。规则: 默认只在进程首轮 reset, 需要每轮确定性时再开 `RESET_EACH=1`。
5. **rate 限太死会原地卡死**: `rate=3°/20ms` 对 40~50mm 级误差解不出来 ⇒ 解被限幅后判不可达 ⇒ 那一拍被跳过,
   永远差 47~57mm。规则: 不可达时升档 (8~14°) 重试一次, 别在同一 rate 上死循环。
6. **S 曲线走完不代表到位**: PD 滞后/静差会让结束时还差 40~50mm。必须有收尾逼近相位 (小步 + 短时限),
   否则「平顺」换来「到不了」。
7. **峰值速度超标先怀疑执行器**: 指令峰速 350mm/s 而真值跑到 1.2m/s 时, 先在轨迹层反复调 `rate` 是白费 ——
   那是位置执行器 PD 过冲 (`kp/kv` 过大)。分层判据: 轨迹层看「Δ 的包络是不是钟形」, 执行器层看「实际峰速 vs v_cap」。
8. **真值采样间隔会骗人**: 用 `Δ/Δt` 算速度前先看 dt 分布; 采样被阻塞时 dt 变大, 会算出上万 mm/s 的假速度,
   误判成「跳变」。规则: 速度统计只用 dt 中位数附近的样本, 并同时报 Δ 的绝对值分布。

## 节拍与平顺同时要时的铁律 (状态空间 / AR 规划链实测)

1. **段间缺口不是「小抖动」, 是瞬移**: 逐段比 `dist(上一段.b, 本段.a)`。实测 392 段/圈里 10 处缺口
   (最大 564mm), 段表没给过渡时间 ⇒ 视图里单帧瞬移、看着像不可执行的动作。诊断命令口径:
   取两份相邻 `ar_cmd` 快照, 对每次段切换算 b→a 距离, 输出 min/p50/p90/max 与 >60mm 的处数
   (健康值: 绝大多段 = 0mm, 只有跨件/换位处 >200mm)。
2. **瞬移会让节拍数字变好看**: 缺口不补时间 ⇒ 每圈白拿 10+ 秒 ⇒ 报出来的 UPH 是假的
   (实测 307.6 是瞬移口径, 补 travel 后真值 300.5, v_cap=700mm/s 全包时物理下限只有 279)。
   规则: 报节拍必须同时报 `acc`(物理最短一圈) 与 `wall`(实测墙钟), 两者差 >1s 就是有段没按速度走。
3. **归一到目标节拍只许放慢, 不许加速**: `scale = acc/tt` 会为了凑 300UPH 把每段速度拉超上限 ⇒
   改成 `scale = min(1.0, acc/tt)`, acc 已超目标就跑物理下限并如实报 UPH < 300, 不许反向硬凑。
4. **跨件/换位的过渡时间要显式预算**: `t_eff = max(t*k, dist/v_cap) + gap/v_travel`,
   `v_travel` 单独给 (实测 1800mm/s ⇒ 每圈 +8.3s), 并在交付里写清「若接真机执行, 此上限必须按机器实测重设」。
5. **S 曲线要逐样本验证, 不要看曲线像不像**: 规划节点同时发 `u`(已平滑) 与 `u_ratio`(线性比例),
   取一批样本比 `|u - smoothstep(u_ratio)| < 0.01` —— 实测 118/118 才算真生效。
   只发 u 不发 u_ratio 时无法自证, 一律按没生效处理。
6. **采样去重按文件 mtime, 不按 `seq`**: ar_cmd 类文件里的 `seq` 是**段号/元任务序号**, 不是发布计数;
   按 seq 去重会把 6Hz 的更新算成 2.4Hz, 进而把「平顺度变差」误判成事实。

## 验收口径

| 指标 | 定义 | 目标 |
|---|---|---|
| 大跳 | 单采样位移 >100mm 的次数 | 0 |
| 单点最大位移 | max Δ (mm) | ≤ v_cap × 采样间隔 |
| 台阶 | 前一采样 <0.2mm 且本采样 >2mm 的次数 | 趋势下降 |
| 速度包络 | Δ/Δt 序列 | 钟形 (加速-恒速-减速), 不是恒定台阶 |
| 精度不许掉 | 到位步数 / 总步数, 每步 reached_mm | 与改前同级或更好 |

一次真实改造的实测 (双臂 6 步闭环, 同一采样脚本): 大跳 4→0 · 单点最大 660→44mm · 台阶 110→57 ·
6/6 到位且总时长 29.6s→22.9s。**平顺与精度不冲突**, 冲突出在段首/收尾没做过渡, 不在 S 曲线本身。
