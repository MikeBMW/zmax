# 技术协议 → 逐步工艺卡（一页 N 张）

## 1. 抽取顺序（按协议章节走一遍，不要边读边编）

| 协议条目 | 抽出去处 |
|---|---|
| 工艺流程表（典型 §2.2） | **卡数 = 步骤数**；每步原文一句作为「动作分解」的骨架 |
| 技术指标表（典型 §2.1） | 每个工站的组成 → 技术细节；节拍/UPH/OEE/缓存容量 → 参数表 |
| 交互信号（典型 §2.3） | OK/NG/完成/启动 的方向 + 「设计评审确认」项 |
| 功能单元清单（典型 §1.3.3） | 场景里画哪些机构；没列的不画 |
| 来料与载具（典型 §1.4） | 1 PCS/载具、夹具/定位/磁吸/浮动量 → 载具画法与细节条 |
| 硬件配置（仪表型号×数量） | 仪表架上的台数、技术细节里的型号串 |
| 洁净/ESD/产品安全/数据管理 | 各卡各补一条细节，别集中成一张“杂项卡” |

步骤里带子项（如「7.1 OK 仓 / 7.2 NG 仓」）时：同一张卡里画两条通道，**不单独占卡**；协议自己分步的缓存仓（如 OK 仓 2、OK 仓 1）各占一卡，跟着协议走。

每张卡还要记一份「本卡引用的条款号集合」（如 `2.2-4 / 2.1 FC 工站 / 6.1.2.2 / 3.2-5`），写进卡尾来源条 —— 交付时逐条对账就靠它。

## 2. 卡片数据模型（JS）

```js
const CARDS=[{ n:'4', title:'MPO&FC 拔帽 · 端检 · 清洗', stage:'检测工站 ①',
  scene:scene4,                                  // (view,t) => void
  cam:{tgt:[-0.78,0,1.05],yaw:-1.05,pitch:0.33,dist:1.00},  // 仅初值, 之后由 fit() 覆盖
  act:'自动<b>拔除端面帽盖</b> → <b>端检 16 PCS / MPO 1 PCS</b> → <b>端面清洗</b>',
  det:[ /* 4~5 条: 组成/型号/顺序/接法/再判规则 */ ],
  kv:[['处理量','FC 16 PCS / MPO 1 PCS'],['单接头基准','对焦 2 s + 测试 2 s']],
  tags:['拔帽模组','端检仪 ×4','清洗机 ×3'] }];
const FOCUS={4:[[-1.04,-0.40,0.76],[-0.52,0.28,1.52]], /* …每卡一份 */};
```

- `act` 里用 `<b>` 标机构名，用户扫一眼就知道这步动的是谁。
- `title` 里写**裸 `&`**（`MPO&FC 拔帽&端检`），不要写 `&amp;`：同一个字符串既喂 `innerHTML`（卡头）又喂 `textContent`（顶部导航），实体写法在导航里会原样显示成 `&amp;`。
- `kv` 只放能对账的数（节拍/容量/信号方向/数量），散文留给 `det`。
- `FOCUS[n]` 必须包住**动作的极值位置**（拔帽抬起高度、顶升上死点、NG 横移终点），否则动画会跑出窗口。

## 3. 场景互斥原则（分步才有意义）

每卡只画本步涉及的 2~4 个机构 + 必要上下文（流线一段、载具、仪表架暗色），**不要每张卡都放整机缩略图** —— 那等于把大场景切碎，用户看不出“这一步到底动哪里”。

上下文画法：机架/仪表架用最暗档（`#1b242e`/`#33465a`），主体用亮色（青 `#2ee6c8`、琥珀 `#ffb340`、红 `#ff5a68`），靠明度差而不是靠加标注来分主次。

## 4. 迁移/对比卡（默认不做）

**只有用户明确说「怎么从专机迁移到机器人」「方案对比」时才加这一张**；协议里没有机器人的，工艺卡就只到协议的最后一步。
用户没要而自己加一张，等于在客户文档里塞自拟方案 —— 实测会被要求整份重写（「不要按你假设的机器人写」）。

真要做对比，三段都要有依据、缺一段就不算讲清：

1. **替代关系**：逐项对应到协议已列的机构（流线 → 导轨、工站 X/Y 轴 + 顶升 → 多轴臂）；协议没列的臂型/轴数/力控阈值一律不写。
2. **保留**：哪些仪表/工站原位不动（这是方案能成立的前提）。
3. **代价与前提**：串行化后取放时间进 CT，节拍要按协议 CT 重算；兜底建议标「建议」，不写成协议要求。

迁移卡用同一套卡片结构，只是 `stage` 写「方案对比 · 可选」，别混进 1..N 的编号里。

## 5. 诚实标注与溯源审计

- 三维是「按模块关系的 1:1 比例示意, 非施工图」——页脚写明，并说明拿到 LAYOUT 图或实测工位坐标后替换 `FOCUS`/工站 x 表。
- 协议未定项（测试板卡供电、显示器接口、品牌型号、整机功率）→ 照原样标「设计评审确认」「待定」「【待确认】」，不要在图上给一个像真的数。
- 交付前两道审计，缺一道都别发：
  1. **逐字溯源**：把每张卡的「动作分解」打印出来与协议工艺流程表原文逐句比对（从 docx 回读，不是从自己代码里读）；不一致就是改写或补动作了。
  2. **自拟术语扫尾**：全量文本 grep 禁用词表 —— 力控/扭矩阈值、缺陷类型枚举（划痕/污点/凹坑）、IL、节拍解耦、先进先出、缓存满停送、换型只改程序、机器人/第七轴（协议没写时）。命中的逐个删。
  协议自己用的词可以留（如 2.1 洁净设计里就有「洁净型机器人」），只留这种原文命中的。
