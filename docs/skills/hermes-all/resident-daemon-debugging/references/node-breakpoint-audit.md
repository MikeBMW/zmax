# 逐节点断点审计 (全量、可复跑)

目的: 回答"画布上每个节点的代码, 右键打开之后断点能不能停"。单个节点手工试断点只能采样,
用户要的是"每个节点都验证过", 这条链路必须脚本化, 否则永远在补洞。

## 一条主循环

```
枚举节点 → 判定可绑定 → 真跑一拍并记录执行行 → 把"打开位置"校准到真执行到的 return → 再跑一遍
```

每轮都落盘报告 (`reports/node_breakpoints.json`), 下一次只跑"没 PASS 的"。

## ① 枚举: 用实现审计工具, 不要手抄

节点名/语义 key/注册函数/声明文件四元组只承认工具给的:
`tools/ss_node_impl_audit.py --json --write` → `reports/node_impl_audit.json`
(带 `impl_miss` / `shared_keys` / 规则交叉校验; 声明文件可能不等于运行文件)。

## ② 可绑定: 以加载台账为准, 不靠猜名字

`modload.SPEC_LOADED` 里记的是走了 spec 兜底的文件 —— 这些文件的断点**一定**绑不上。
其余只要进了 `sys.modules` 就是正常 import, pydevd 看得到。

判据不要写成"模块名必须以 lerobot. 开头": 顶层 `import yolo_state_aligner`、`import ss_bypass_view`
同样是正常 import, 按前缀判会造出一批假失败。

## ③ 真跑一拍 + 用 sys.settrace 记执行行

tracer 只对关心的文件返回自己, 否则返回 None (否则整进程逐行回调, 十秒变一分钟)。
记录 `(文件 → 执行过的行号集合)` 与 `(文件 → 进入过的函数名集合)`, 这就是"这段代码真跑了没"的硬证据。

单拍跑不到实现文件的节点, **再喂一份合成输入跑第二遍**: 大量包装函数是 `if not in1: return` 早退,
第一遍没进到实现 ≠ 实现没接上。报告里单列 `NEED-INPUT`, 不要算成失败。

**先确认你验的是用户实际用的那条执行路径**: 同一套节点 id 可能同时挂在两套引擎上 —— 一套是
registry (节点名 → 注册函数) 的**真实实现**, 一套是生成出来的桩模块 (`PURE=False` 时只做端口直通)。
拿桩的那套去 trace, 只会看到 `compute → _passthrough`, 于是把“这个文件从没被 import”误判成缺陷。
判据: 桩/直通路的 trace 里**没有**任何实现文件的函数名; 真实现路会有。
所以取样前先问自己“用户按的那个按钮走哪个入口”, 并在报告里写明口径。

同理, `prj.step(only=[id])` 单独跑一个节点时, 很多节点因上游无值直接早退甚至根本不装配 ⇒
`模块=None / 入口=N` 通篇出现是**方法问题不是产品问题**。正确顺序: 先整链跑一遍并全局 trace,
再对整链没进到的节点逐个补跑。

## ④ 判定分类 (别把不同病混成一个数字)

| 判定 | 含义 | 下一步 |
|---|---|---|
| PASS | 打开位置的文件正常 import + 真执行 + 打开那个函数里的 return 真命中 | 完成 |
| NEED-INPUT | 文件可绑、这一拍因缺输入/参数早退 | 用真实数据流复跑, 不是代码问题 |
| FAIL-NOTRUN | 可绑但真跑两遍都没进这个文件 | 包装函数没调实现 → 是真缺陷 |
| FAIL-NORET | 文件进了执行, 但那个函数的 return 一条都没走到 | 落点错(指到 class/def 头)或该分支要特定输入 |
| SUBPROC | 实现是另起子进程跑的脚本 | GUI 进程里天然不会停; 要断点就单独 F5 跑那个脚本 |
| SKIP | 会触发真实副作用(训练/渲染/推流) | 只做静态核对, 并在报告里写明没真跑 |

## ⑤ 校准"右键打开"的落点

`tools/fix_node_source_loc.py` (dry 先看) → `--apply`。它挑**真被执行过且带 return** 的函数,
把映射行号改成该函数第一条 return。挑选要排除私有辅助 (`_brk` / `_debug` / `_xxx`), 否则会把落点
指到调试钩子上。

改完立刻现取一次判据 (同进程, 不是读文件):

```python
sourceview.get_node_location(key)  # 返回的行号必须落在某函数的 return 语句上
```

## ⑥ 收尾

- 报告落盘 + 终端打汇总 (`PASS / NEED-INPUT / FAIL-* / SUBPROC / SKIP` 各自数量与 id 清单)。
- 交付时只报"多少节点已验证"和"还剩哪几类", 不报"我看了 80 个节点"。
- 全量跑一次约 1~2 分钟; 跑前必须 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`, 否则每个加载模型的节点
  都会卡在网络超时上, 看起来像"审计不结束"。
