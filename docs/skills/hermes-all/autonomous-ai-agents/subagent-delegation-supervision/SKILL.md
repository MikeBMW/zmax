# 派活给子代理：契约先行 · 常驻进程脱离 · 父会话验产物

## When to Use
- 一件活足够大或足够独立（写新服务、改 GUI、跑训练、做发布），准备用 `delegate_task` 推进。
- 收到子代理的交付报告，要决定能不能算完成。
- 要同时改两头（服务端 + 消费端、生产者 + 渲染方）。

子代理的价值是**独立上下文 + 并行**；代价是它**不知道你的对话**，而且它的交付是**自述**。
本技能就是把这两件事处理干净。

## 一、派活前：把契约定死（并行不打架的唯一前提）
先由**父会话**写下不可协商的接口，再派两个子代理各做一头，谁都不许改：
- 端点/路径 + **完整 JSON 契约（逐字段名、类型、枚举值）**；新增字段只许"**只增不改**"。
- 真源文件绝对路径、产物目录、venv、**已有可复用工具**（明写"不要重做，直接用"）。
- **同一个文件/端口只能有一个写者**：另一个只读或只"加"不改；并明写
  「**不要回滚别人的改动，冲突就合并**」（实测两个子代理同时往同一个 HTTP 服务加只读路由，
  一方若"回滚到干净状态"就会把另一方的路由删掉）。
- 🔴 **"先派一个、完事再派一个"同样会撞车**: 前一个子代理**可能还活着**(长跑 / 在等)，你再派第二个时它仍在改同一个文件
  ⇒ 两边互相覆盖、还互相杀对方的进程（实测两个子代理轮流重起同一个警报服务，各自把对方的实例杀掉、落下不同的参数值，
  最后两份报告都写"已落定"）。派第二个之前先 `delegate_task(action='list')` 看还有没有活着的，
  有就 `steer` 把它**从该文件上摘出去**（"立即停止对该文件的任何编辑与进程操作"）再派。
- 子代理在报告里问"**请指定唯一 owner**" = 这条规矩已经先被你违反了：那一刻不要选一个，
  而是**当场冻结其余写者**（steer 掉），以**一个已核实的现值**作为唯一真源，让其余人只读、只报结论。
- **提交权收归父会话**: 多个子代理并行时, 契约里明写"**不许 `git commit`/`git push`**, 改动留在工作区, 由我统一提交";
  并给每个子代理**写死它自己的路径清单**(明写"只 `add` 这些路径, **绝不 `git add -A`/`git add <目录>`**") ——
  同一棵树里可能有兄弟正在新建文件, 一条 `-A` 就把别人的半成品带进你的提交。子代理们并发 commit 还会争同一个 index。
- 红线清单：不许碰的系统/盘符、不许用的命令（如 `pkill -f`）、改前必须备份的文件、大文件不入库。
- 需要重启才生效的东西（服务/GUI）要写清"**改完你重启，并粘回归输出**"。

## 二、每份任务里必须带的东西（子代理无法自己推断）
- **验收命令 + 必须交什么证据**，并把交付字段定死：改了哪些文件（绝对路径+行号）·
  关键数字（前/后）· 证据原文（命令 + 输出）· 要不要重启 · **`incomplete`（没做到/降级的如实列）**。
  ⚠️ 不强制 `incomplete` 字段，它会把"本应做"写成"已完成"，你拿到的就是一份漂亮但假的报告。
- **要 `output_schema` 就给合法 JSON Schema**: 字段写成 `{"type":"string"}` —— 写 `{"字段":"string"}` 这种简写会被
  metaschema 拒掉, 而且**整批 `delegate_task` 一起 dispatch 失败**(一个 schema 错 ⇒ 同批几个任务全没派出去, 白等一轮)。
  不想写就不传 `output_schema`(它是可选的), 用"报告必须含 …"的字段清单替代。
- **领域口径要逐条写进 context**：本项目的例子 —— 概念提示词必须英文且一次一个、
  真训练判据（`nvidia-smi` 列出 PID + 利用率 + 步数推进）、梯度闸判据、venv 硬规、
  不许把"跑了 3 步冒烟"说成"训好了"、不许编数据。它猜错的方式和你不一样，而且**它不会告诉你它猜了**。
- **让它先读既有事实再动手**：给文件路径 + 既有工具名 + "用工程自带的审计工具判，不要自己写探针"。
  自写探针很容易因字段名猜错而报假阳性/假阴性（实测：自写脚本报"节点入度=0 是孤岛"，
  而工程自带的 `canvas_node_audit` 报孤立=0、线其实有 4 条 ⇒ 差点"为改而改"）。
- 🔴 **有"人在现场等"的活必须写时间盒，否则它会一直"先读懂再动手"**: 实测一个"立刻去让机械臂动"的子代理
  花了五分钟通读执行器源码、**一次指令都没发**，而现场的人连着追问了好几遍。
  契约里明写：①"**不要为了更好的计划再读一轮代码**；已确认的条件(授权/位姿/接口)列给它，不许复查"
  ②"**N 分钟内发出第一步**，并**每完成一步报一行**（段号/回执/位姿）" ③"开始前只准打印一次计划"。
  这样父会话才能随时回答现场"动到哪了"。反之，一个"只读代码、从不动作"的子代理产出是零风险、也零进展。
- 派"去执行一个现场动作"的活时，**父会话事后要能自己数出它到底发没发**（自述不算）：直接管日志里
  的下发行 —— "只有我发的和你发的，它一条没发"这种核对比读它的报告快得多。

## 三、🔴 子代理起的常驻进程会随它退出而死
子代理用**普通后台方式**起的 GUI/服务，在子代理进程结束时会**被一起回收**。
- 现象：报告里写"已重启控制台，PID xxx，实测在轮询"，而它一交付，用户那边就是"打不开/没反应"。
- 派活时就要求：常驻进程**必须脱离** —— `setsid nohup <cmd> </dev/null >log 2>&1 &`。
- 父会话用 terminal 起长活时同理：`background=true`（必要时 `persist_on_release=true`），
  不要用裸 `&`（会随调用方生命周期被回收，且前台命令里的 `&` 会被安全扫描直接拦）。
- **交付后父会话必须重验所有长驻服务**：进程在不在 · 端口在不在 · 发一次真请求。
  不在就自己用脱离方式重起 —— 这一步是交付的一部分，不是"子代理没做好"的事后补救。

## 四、🔴 子代理的交付是自述，不是事实
对外副作用（公网 URL、上传、写盘产物、重启的服务）**父会话自己验**：
```bash
curl -sI <URL>                      # 状态码 / 类型 / 长度
curl -s <URL> | md5sum              # 与本地产物 md5 逐位比
pdfinfo <产物> ; pdftotext <产物> - | grep <页脚断言>   # 用独立引擎复算它自报的数字
python -c 'json.load(...)'          # 契约字段真的在
```
- 它报的"节点 89/89 · 连线 182/182"这类自查数，要能在产物里**自证**（页脚/字段/退出码），抽出来比对。
- 🔴 **它声称"加了去抖 / 加了下限 / 加了冷却"这类机制时，验的不是"文件改了"，而是"判定那一行真引用了这个符号"**:
  实测子代理报"已按 3 帧去抖改好"，而那个常量只在文件里**声明**、判定行**零引用**（`grep -n <符号>` = 1 处声明、0 处使用）
  ⇒ 现场仍然单帧毛刺就触发。**安全机制类的自述是风险最高的一类**，必须数引用次数，不能在结论里写一句"已实现"。
- 🔴 **"全绿"只覆盖它在契约里被点名的那条路径 —— 派发式接口要自己把每一种都各跑一遍**: 交接里若有个按类型分派的表
  (`NORM[kind](…)` / `if kind == …` / 插件注册表 / 适配器字典), 子代理只测了契约里举例的那一种 verb+kind,
  另一种因为**共用签名少一个可选参数**而直接抛 TypeError、整条 add/update 全挂, 而它的报告依旧是"验收通过"。
  两条处置: ①派活时把"必须跑的**路径矩阵**"(每种 kind × add/update/rm)写进验收清单;
  ②收到报告后父会话按矩阵自己重跑, **尤其跑它报告里没提到的那些 —— 没提就是没跑**。
  同理, "命令成功"要读结构化结果里的 `ok`/`written` 等字段, **不能只看退出码**: 干跑(dry-run)同样是 exit 0,
  `written=False` 才是真相。
- **它报"已推送"时比 SHA, 不比日志**: `git log -1 --oneline` 与 `git ls-remote origin <branch>` 的 SHA 逐位相同才算推上去;
  它报"两端 sha256/镜像一致"就自己 `sha256sum` 两边复算。
- **它说"曾误写明文又改掉了"时, 查提交内容本身**: `git show <sha>:<file>` 取出提交里的那份扫一遍(只报命中数量, 不打印值) ——
  工作区干净 ≠ 历史干净, 而历史可能已经推到公开远端(公开仓库里的旧密钥等于已泄露, 收口只是止血, 正解是换掉)。
- 它诚实写下的 `unknown` / `incomplete` 是要**保留**的行为，不要逼它给数（宁缺毋编 —— 用户会逐个检查那张表）。

## 五、父会话的收尾清单
1. 所有长驻服务重验（进程 / 端口 / 真请求）。
2. 所有对外产物重验（状态码 / md5 / 页数或字段 / 独立性）。
3. 冲突检查：`git status` 看有无别的 agent 的未提交改动；提交只 `add` 自己的文件。
4. 把结论并回主线，**明确下一步归谁**（父会话 or 某条角色线）。

## 六、视觉/图像类交付: 靠"可判定的判据 + 让它自己看图"收敛

- **目标物的形状要写成可判定的判据, 不能只给形容词**。用户口径未定时(如"只保留本体"这种句子),
  先把它量出来、或画成候选图让用户指认, **再**派活 —— 否则子代理会在错前提上迭代, 每版都被否。
  实测: 契约里只写"只保留那条带", 子代理连交两版都把同带里的"满宽横条"当本体留着, 用户只能反复说
  "那一大块还是没切掉"; 补一句形状描述(像钢琴键一样的竖条)后一次实现到位。
- **纠偏要给"它自己的产出数字"**, 不是重述需求: 例如"你草稿保留区的边缘强度只有 1.2~2.4, 目标是 ≥3.5,
  说明缩放把纹理磨平了, 重做"。它对着数字能改, 对着形容词只会再交一版。
- **要求它出图后自己看一遍**: 子代理有 `vision_analyze`(把图载入它自己的上下文) ⇒ 契约里明写
  "出图后必须自检: 画面里是否只剩 X、其余全黑/是否符合验收形状; 不对就自己重做, 不许交"。自检不过的不进交付。
- **让它只写独立新模块, 现役程序由父会话整合**: 明写"不要改任何现役文件", 产物 = 新模块 + 前后对比图 +
  指标表; 父会话验过再走官方部署路径。它跑偏也碰不到产线。
- **交付必须带可复算指标**(均值 / 黑底占比 / 倾角 / 边缘强度 / 削顶占比…), 父会话按指标复算一次再转给用户。

## 七、派"改现役大文件"的活：禁改产线 + 基线数字当门槛 + 父会话留最后一步

当父会话上下文快见底、而活要"通读几千行现役程序 + 反复标定 + 复放验证"时，正确做法是把**实现整段交给一个子代理**，
父会话只保留**验收 + 上线**。契约里必须写死三件事：
- **禁止清单（写进 goal，与验收并列）**："不要部署、不要 git commit、不要碰现役目录，只在本地副本上改" ⇒
  子代理跑偏也碰不到产线，对外动作只由父会话做。
- **基线数字（改前实测）直接当验收门槛**："要求 X 在帧序列上稳定（改前是 …）、Y **逐位相同**（`np.array_equal`）" ⇒
  没有对照它只能自证"我改了"，而不是"改对了"。同时给它**已有的复放装置路径**（明写"照抄别重写"）。
  要求它报"没过的项 + 失败数字"，明写"不要粉饰"。
- **父会话保留并必须做**：① 自己把复放**再跑一遍**（不认自述）② 通过才走官方部署路径 ③ 上线后再实测一组现场数字。
  子代理的自述永远不是上线依据（见第四节的验收命令清单）。
- **"指标大幅改善" ≠ 过验收**: 门槛要定在**主判据**(与目检真值一致且恒定), 不是中间量。
  实测: 平场+自适应把逐根宽度从 11~692px 收到 21~23px、节距从 63~756 收到 71~78、13/13 帧全出图,
  但**根数 20~23 仍不恒定**、众数稳定在 22 vs 目检真值 19 ⇒ 判**没过、不部署**, 并把残留当下一轮起点记下来。
  ⇒ 派活前先在契约里**分开写清"主判据 / 中间量"**, 否则子代理会拿中间量的收敛当完成, 你也会被一串漂亮数字说服。
- **改动后冒出的报错, 先用原版复现一次再定性**: 用改动前的版本能复现同一条报错 ⇒ 是**改前就有的旧问题**
  (常被上层 `try/except` 吞掉, 只在真跑时才露头), 不算本次引入; 复现不了才是新引入。
  省这一步就会把旧账记到本次改动头上(或把新引入的回归当成旧问题放过去)。

### 7.1 🔴 交付物"一旦执行就能动真东西"时: 先读源码确认默认安全, 再试拒绝路径
脚本/服务能动真机(机器人、生产服务、线上写入口)时, 子代理报的 "默认 dry-run、需 --go、未授权会拒"
**不能当事实用** —— 错一步就是真动作。父会话要自己过三道(全程零副作用):
1. **读源码确认默认分支**: 找到 `__main__`/入口里真正决定"发不发"的那一行(如
   `if args.go and not args.dry_run: run_go(...)`), 确认默认落不到那一支; 不能只信报告或 `--help`。
  只有确认了默认安全, 才敢跑它自带的 dry-run —— 否则连"演练"都可能真发。
2. **跑一次拒绝路径**: 故意不带授权/门禁地执行那条真发分支, 要看到**可读的拒绝文案 + 非零退出**
   (实测 `🛑 拒绝执行: 未授权…` + exit 2), 而不是等控制器报错。
   注意管道会把退出码换掉: `... | tail` 后 `$?` 是 tail 的 —— 要拿退出码就别接管道, 或单独再跑一次。
3. **自己把"计划"跑一遍并拿数字**: 它报的段数/每段量/校验项, 自己跑一遍取其原始输出; 它报的"几项全过"
   要能在输出里逐条对上。
另外: 动真机的活交给子代理时, **真发那一步留给父会话、而且要现场人在场且拿到授权** ——
契约里明写"不许真发", 让它只交可审阅的计划 + dry-run 输出。

### 6.1 要接进现役大文件（单实例 GUI/页面）的活：整批派成"只读工具"，整合权留在父会话

当父会话要改的是**一个几千行的现役单文件**（控制台/页面），并行子代理去改它 = 必冲突（见第一节唯一写者）。
可用的形状：**整批子代理只产出独立新工具（只读 + `--json`），父会话一个人把它们接进现役文件**。
契约里写死四条：
1. **产物形态**：`工具 --json`（结构化，供程序读）+ 默认人能读的表；**只读、不写盘、不起常驻进程、不动现役文件**。
   工具直接输出界面要的那几个字断（类别/名称/绝对路径/大小+human/文件数/最新 mtime/来源），父会话只写十几行挂载。
2. 🔴 **数据根目录逐个写死，并要它把"我扫了哪些根"写进交付**：子代理会按生态惯例猜路径
   （HF 缓存在 `~/.cache/huggingface/hub`、数据集在 `data/`），而本项目的数据在独立数据盘（非标准路径）
   ⇒ 它扫的是空目录、报的"0 条"是**假阴性**，你会据此以为"本来就没数据"。
   契约给**绝对路径清单** + 明写"**先列目录确认真实存在再统计**"。
3. ✅ **要它贴"真跑一次的原始输出 + 条数 + 耗时**（不是"已实现"），父会话拿**同一条命令自己复跑**比数字。
4. 🔴 **它报的实时/现场值要用另一条独立通道复读**：它报"GPU 11% / 604MiB"，你自己跑一次 `nvidia-smi` 对数（本次两边一致才算过）；
   它报的目录/条数类事实，按第三节核对根目录与文件名是否真存在。**子代理很可能为了让数据"看起来完整"而把空目录也计入**，
   凡它报的"含真产物的目录 N 个"都要你亲眼点开一个看。
它交付的工具里如果有**"验证它自己是否工作"的钩子**（如自动跑一次合成负载看采集链路会不会动），保留它——
这是下一轮排查的第一个开关。

## 反面清单
- 别为"看起来在推进"重复派同一件活 —— 先读上一个交付报告/产物清单，确认哪些已完成。
- 别在子代理还在改同一批文件时自己上手改（会各写一半）；先 `stop` 或用 `steer` 追加需求。
- 别用"猜的中转接口"给另一个 agent 发消息（实测猜的两个路径都 404）：
  能靠 `@某人` 的群提及转达就靠它，并**把要点写全**（它只看得到你写的那几行）。
- 别把子代理的自述当验收结论直接转给用户 —— 你转述的每一句都会被当成"我验过了"。
