# 检测调用契约: 通道序 / 同类多框 / 面积闸

给 L2 感知喂"非相机来源"的帧 (mujoco 渲染、截图、网络图) 时, 绝大多数"链通了但 0 框 / 框很小 / 定位偏 100mm+"出在下面三处。

## 1. 通道序: cv2.imdecode 出来是 BGR, detect() 里可能再转一次

两头必须对齐, 否则等于通道互换 (金/青反转), 同一帧置信度能差 3 倍 (实测 0.955 → 0.31)。

- `YoloPerception.detect(img, ...)` 若文档写 "img: RGB" 且内部 `cv2.cvtColor(img, RGB2BGR)` 后再 predict, 那么传入 BGR 帧就会二次转换。
- 从 `cv2.imdecode` / `cv2.imread` 拿到的帧是 BGR ⇒ 走 `detect(img, already_bgr=True)` 这类显式开关 (没有就加, 别默默传错)。
- 判定口径: 同一帧 BGR 直喂 vs RGB 双转各跑一次, 比 conf 与框面积, 正确一路 conf 明显高且框贴合目标。不要靠"看起来能检出"下结论。
- 权重训练域决定推理域: 在 `cv2.imread` 图像上训的权重, 推理端同样要 BGR 口径, 两者必须同源。

## 2. 同类多框被折叠: dict 只留最后一个

`detect()` 返回 `{cls: {...}}`, 一类只能放一个框。若写法是 `out[cls] = box` (无比较), 低分碎框会覆盖高分正框 —— 实测 0.898 的工件框被 0.055 的 ~20px 碎框顶掉, 下游拿到错位小框, 3D 定位偏 150mm。

- 修法: `out[cls]` 仅在 `conf` 更高时替换; 另加 `detect_all()` 返回 list, 由调用方决定挑哪个。
- 只要可能多实例 (一排工件/多托盘), 必须走 `detect_all`, 不要把 `detect()` 的 dict 当全部结果。

## 3. 类别闸 + 面积闸 + 可见性闸

落盘或下游使用前过闸, 不合格就如实报"本帧未定位":

- 类别名匹配 (别把别的金黄色零件当目标)。
- 最小面积 (960×720 场景实测取 600px², 正框约 4000px²)。
- conf 下限 (AR 域权重正框 0.4~0.96, 碎框误检常在 0.05~0.3)。
- 场景侧可见性闸: 渲染服务给的像素真值 (如 `gold_px>300`) 为 0 时画面里根本没目标, 模型给框只能是误检 —— 先修视野/停机位, 再谈模型。

失败要写可核对字段 (`n=? best=None reason=面积不足`), 页面显示"未检出", 不要拿碎框充当定位结果。
