## 症状 → 判据
- 现象：目标点比当前高，下发后**一动不动**；失败行 `rc=6 · CHECK · 残差 = 满位移`。
- 区分「控制器拒」与「自家闸拦」：失败行含 `保护停=🛑 扫掠越界急停: ['z'] 轴出包络(实测 [...])` ⇒ **自家扫掠盒闸**，不是控制器/授权/网络。
- 决定性实验：**残差 0.000mm 的原地纯姿态旋转（只转 −16°）也被同样拦停** ⇒ 与可达性无关，是盒子 z 顶被收口。
- 收口链：`box.z[1] = min(包络顶, 安全区天花板)`，天花板 = `taught_z_ceiling()` = **max(空间点z) + 50mm**（动态读点库）。

## 按设计的更新法
1. 备份点库 `zmax_data/backups/space_points_<ts>.json`。
2. **记一个新空间点**（零运动，即当前 TCP 真值，多次采样并报极差）⇒ 天花板自动抬到 `max(z)+50mm`。本次记 space8（z=0.6302，6 采样极差 0.8µm）⇒ 0.5666 → **0.6802** ≥ 点1 的 0.6415，扫掠盒顶 = min(0.6987, 0.6802)。
3. 口径自检：空间点 `quat → rpy` 回读必须与真值逐位一致（本次 `[-0.990,17.099,177.384]°` ✓）。
4. 授权留档：用户原话写进提交信息 + 快照 README。
