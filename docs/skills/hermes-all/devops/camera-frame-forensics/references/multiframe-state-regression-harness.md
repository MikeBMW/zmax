# 多帧有状态画面管道的改造: 跨帧状态隔离 + 零回退回归台

适用: 判据/渲染器/检测器带**跨帧记忆**(投票窗、最后一张好图、自适应阈值缓存…)时, 改它之前与之后。
三条验收目标: ① 参考视角**逐像素零差异** ② 目标视角按真值收敛 ③ 任何"救回"都不许静默顶错图。

## 1. 先清点跨帧全局状态 (只盯正要看的那一处必然漏)

```bash
grep -nE "^_[A-Za-z0-9_]+ *= *[\[\{]|^_[A-Za-z0-9_]+ *= *deque|remember|_CACHE|_MEM|threading.Lock" <程序>
```

清单里每一项都回答: 它语义上是**每视角/每工件**的, 还是**全局共用**的? 共用而该分的 ⇒ 按键隔离。
实测教训: 先找到"认领窗"并以为修好了, 漏了"最后一张好图"缓存 —— 而后者才是现场现象的正解。

## 2. 键(key)的两条硬要求

1. **成功与失败两侧都算得出**: 失败路径手里常常只剩裁剪块 ⇒ 用**裁剪块形状**粗桶(宽 64px / 高 16px 量级),
   别用只有成功路径才知道的节距/行带/格子数。
2. **同视角恒定**: 拿真帧序列量同一视角整段序列里键的取值分布, 出现跨桶就是不合格。

⚠️ **标量分桶的取整边界**: 桶宽要显著大于该标量在同视角内的抖动量, 且别让"中位值 ÷ 桶宽"落在 .5 附近
(实测: 节距 72.0~73.2、桶宽 16 ⇒ 商 4.5 ⇒ 相邻帧分落两桶 ⇒ 投票窗被劈成两半, 一个稳定的量变成乱跳)。
**验不稳就退回单桶(=不隔离)** —— 宁可不隔离, 也不许为隔离制造新抖动。公式看着没问题, 实测才露馅。

## 3. 回归台: 必须"序列 + 预热", 不能单帧

- **把在役程序当模块 import**: 厂商 SDK / detector / cropper 用 `sys.meta_path` 上一个 finder 发桩 ModuleSpec,
  再把 `_Dummy` 类塞进模块命名空间(模块级会实例化相机/模型, 直接 import 会真开设备)。
- **冻结真帧到磁盘**再跑: 每轮重新抓帧会让不同批次的数字不可比(实测两批一批 16/18、一批全 19, 差点误判)。
- **N 轮 × 全序列, 第 1 轮当预热**, 只统计稳态轮 —— 投票类判据的首帧结果与稳态是两回事, 单帧比对会给出"已修好/没修好"的假结论。
- 断言三层: **计数序列** · **关键 meta**(行带/周期性/倾角) · **逐帧像素差**(差异像素数与分布区域)。
- ⚠️ **回归台自己的判据也会错**: 出现过探针报"像素全等 ❌"而直接比对是 `0/298800` 差异(探针 bug)。
  **拿直接比对复核探针**, 别让探针的结论替代证据。
- ⚠️ **异常必须暴露**: 重试门/兜底路径会把异常吞掉换路出结果 ⇒ 表面"通过"。探针里记 `attempt` 与 `err` 并打印出来。

## 4. 关掉一个未证安全的改动: 留开关, 不要删

留**代码 + 布尔开关(默认 False) + 实测依据的注释**。删掉会让下一次重新踩同一个坑。
尤其"补一根/外延"这类启发式: 必须在**参考视角(已验收那个)的整段序列**上验证不触发 —— 只在目标视角上验不够
(实测它在参考视角预热期也触发, 多认一根并连带改了倾角, 使参考视角头 3 帧像素差 49%)。
相关阈值也挡不住这类误触发(边缘周期结构的相关可达 0.6+, 与真目标不可分)。**凭空造一个比漏认更危险。**
