# 判据图/成品图的口径取证 — 先用像素统计把投诉量化, 再改渲染

适用: 用户对着一张**人看的成品图**(AOI 判据图、面板里的图)提意见 —— 「歪斜」「太亮了/过曝」
「右侧有一块东西不是产品」「只要保留 X, 其余全黑」「多带了背景」。要改的是**人看的那张图的渲染口径**, 不是相机坏了。

## 铁律 1: 形容词必须先落成数字, 再动手
用户给的永远是形容词。实现前先跑一份行/列剖面, 否则改完还是被否 ——
逐行(逐列): 均值 · 亮(>=200)占比 · 饱和(>=250)占比 · **边缘强度**(相邻像素灰度差绝对值均值):
```python
for y in range(0, H, 20):  ...   # 行剖面 -> 定位本体 / 过曝带 / 背景
for x in range(0, W, 100): ...   # 列剖面 -> 定位本体左右端与「非本体块」
```
实测把形容词变成的数字: 太亮 = 饱和 19% + 纯白底(>=254) 14.9% · 歪斜 = 质心线斜率 217 px/1000 ·
「右侧那块不是产品」= x≈2000-2200 均值 94 · 亮(>=200) 0% · 边缘强度 0.7。
这套数字既是**交付证据**也是**改后的对照基线**; 汇报直接给数字, 不给"已修复"。

## 铁律 2: 分区/排除按「纹理」, 不按「亮度/饱和」
边缘强度是唯一干净的判据。实测分界: 产品本体(离散焊盘/结构) 水平 4.4~7.2 · 垂直 2.6~4.3;
邻料/夹具/灰暗块(完全平坦) 0.66~0.88 —— 分离约 6 倍。
- **端界 = 「高频纹理消失处」**: 边缘强度 < 阈值(留 3 倍余量)且**持续 ≥N 列** ⇒ 整段不要; 再用「亮像素占比 <10%」交叉校验。
- 🔴 **只按饱和/亮度裁列的旧逻辑永远裁不掉平坦灰块**: 平坦灰块饱和率往往只有 5~8% ⇒ 一直在画面里, 用户会连报两轮。
- **过曝帧上亮度/饱和无法区分本体与背景**(本体自己就打满 255) ⇒ 以**行方向的高频结构**为主判据, 亮度只当辅证。
- 分离判据必须**数据驱动**(逐行/逐列的 run 结构), 不写死坐标 —— 换产品/换光位后写死的坐标必错。

## 铁律 3: 区分「过曝是相机削顶」还是「显示太亮」
- 相机侧削顶(像素到 255)后, **软件压暗只让画面变暗、救不回细节**; 判据 = 饱和(>=250) 占比
  (实测现场帧全图 17.1%、产品区内 48~64% 已削顶)。
- 改**相机曝光/增益**会改模型输入分布 ⇒ 属红线(见铁律 4), 必须配一次**同口径复验**(模型 OK/NG 判决不变)才准动。
  ⇒ 「只改显示」与「改相机」是两件事: 默认只改显示, 改相机要先说清代价并等用户点头。
- 黑底本身就是最大一笔降亮: 旧口径用**白底填充**旋转后的空白区, 实测占 15% 像素 ⇒ 用户观感"太亮"。

## 铁律 4: 人看的图 与 模型吃的图 必须分家
- 改渲染只改**人看的那张**; 模型输入那条路(模板法规整裁剪 / letterbox / 定尺派生图)一字不动。
  两者都要落盘 + 进台账(如 `/last_result` 同时报 `topview`(人看) 与 `model_input`(模型吃)), 追溯不断。
- 验证"模型输入没变"的硬手段: 桩 detector **记录它被喂了哪个文件/字节**, 不是看尺寸对不对。

## 铁律 5: 产物交付前先把「真值几何」量清楚
- 本体位置不许靠猜: 先量出它的行范围 / 左右端 / 厚度, 再写判据与容差。
- 量倾角只许在**本体核心行**上拟合上边缘/质心线(离散结构会把整块 ROI 拟合带偏);
  **两法互校**(直线拟合角 vs 掩膜 minAreaRect 角, 差 >1.5° 就判失败)比单法可靠。
- 历史样本可能换过机型/光位(有的样本大半是暗的) ⇒ **别用历史样本定判据**; 拿现场真帧
  (`?kind=origin` 这类**内存帧, 零副作用、不触发拍照**的口)当基准。

## 铁律 6: 「只保留 X, 其余全黑」是歧义句 —— 形状先确认, 再实现
用户说「只保留本体」时, 本体那个带里**往往同时躺着两种东西**: 产品本体(一排离散竖条/焊盘, 像钢琴键)
和一条**满宽亮带**(横条: 端面/护罩/反光边), 后者**不属于本体、必须剔除**。句子里没说形状 ⇒
直接实现必然返工(实测连错两版: 每版都把满宽横条当本体留着, 用户只能说"右侧一大块还是没切掉")。

**形状判据(数据驱动, 不写死坐标) —— 看列方向的周期性, 不看亮度**:
- 逐 50 行窗口(步长 10)算列剖面 `cf` = 该窗口内每列亮像素(≥200)占比; 亮列 = cf≥0.45,
  相邻亮列合并(缝≤3px), 段宽<4px 丢弃;
- **按键行** = 亮列段数 ≥6 且 **中位间距 25~140px** 且 **间距抖动(中位绝对偏差) < 0.25×间距** (实测命中 y640..840);
- **满宽横条** = 该行跨条宽的亮占比 **≥0.85** ⇒ 整行丢弃(实测 0.94~0.95)。注意上一条本身就把横条段判失败
  (只 1 个亮段) ⇒ 两道判据互相兜底, 这才是"横条不靠坐标写死"的落点;
- **竖条(本体)** = 各命中窗口列剖面取均值的 cfmean≥0.40, 合并缝≤4px, 段宽≥4px (实测 26 根 · 间距 70px · 线宽 29px);
- 掩膜 = (按键行 × 按键列) 内的像素, 其余置 0 ⇒ 实测黑底 61.3% · 均值 75.8(原帧 115) · 输出 1400x203;
- 先旋正再成品: 本体带上边缘最小二乘拟合(实测 -0.20°) → `warpAffine` + `borderValue=(0,0,0)` + `INTER_NEAREST`;
  裁到内容 bbox+20px 边距后**只缩不放**, 禁大倍数纵向拉伸(否则离散竖条糊成一片)。

**渲染后必须复量纹理**: 保留区的水平边缘强度要 ≥3.5(真帧 4.4~7.2)。掉到 2 以下 = 缩放/插值把纹理磨平了
(实测某版掉到 1.2~2.4, 用户看到的还是"一大块平的东西") —— 这种图不许交付。

**形状不明时的正确动作 = 画候选图让他指认**(比再实现一版快得多): 用 cv2 在**现场真帧**上把候选带
(A/B/C)、边界线、切点画出来并标注实测值 → 推到用户看得见的渠道 → 让他一句话定。
实测一句「跟钢琴按键一样, 一个小竖线」就把三轮返工收敛成一次实现; 纯靠数值猜语义会继续错。

**测量/推送的具体命令**(本机环境):
- 量测一律用 `gui-venv311/bin/python`(**系统 `python3` 没有 cv2**); 工作帧用 `?kind=origin` 内存帧(零副作用)。
- 推图给用户: `gui-venv311/bin/python tools/aoi_feishu_push.py --file <png> --text "<指标>"`
  (`--file` 可直推本机任意图); 一张图一条消息, 说明文字另发一条。
- 最省事的交付形态 = **左=现役 / 右=新版** 并排对照图, 图上直接印指标(均值 · 黑底占比 · 饱和占比);
  他说"改好了么/没变化/判据图呢"= **图还没送到他眼前**, 先把图推过去再解释。

## 上线与交付顺序
1. 新口径先写成**独立模块**, 离线对现场真原图跑通, 出**前后对比图 + 指标表**(尺寸/饱和占比/黑底占比/残余倾角/边缘强度)。
2. 上线只走官方部署器(哈希核对 + 失败自动回滚), **只在产线端口**, 绝不用测试口。
3. 交付 = **把前后对比图推到用户看得见的渠道让他目检**(他按画面判), 不是文字描述;
   离线过了也要等他说顺眼再上产线。
4. 上线后自己再抓一张现役成品图与离线结果比一次(同口径), 新数字写进台账。
