# 力控插入(peg-in-hole) —— 通道先证、插入只走力控、进度用真值算

## When to Use
现场说「你正在插入口 / 这个位置你自己记住 / 向前自己插入 / 调用力控算法」, 或任何要把末端工件压进孔的动作。
和「点位转移」不是一类事: 转移靠位姿到位就够, **插入的最后一跳靠力, 且目标点天然在围栏盒里面**。
（本机运动下发/授权的完整细节在用户自有技能 `real-arm-motion-control`; 本文只管插入这一类。）

## 🔴 力红线（高于一切配方）

- **上限以现场当次口头口径为准, 并落成代码常量**: 同一现场会改口（例: 先 30N, 后改为 **40N**）⇒
  改口径时同时改 `FZ_HARD_N`（红线）/ `FZ_TRIP_N`（实际停手, 留 5~6N 余量）、改台账、改记忆, 三处一起;
  `--watchdog-n/--stop-n` 传更大的值也必须被压回 `FZ_TRIP_N`。**不要沿用上一次会话的数值**。
- 判力必须**运动中每 20ms 一次**, 超阈立刻 `stop` + `moveReset`。"等这一步走完再看力"实测就是把力顶到 83.6N 的机理。
- **不做位置步进蹭孔**: 0.5mm 一步顶在刚性孔口面就是 40~80N（实测 8.6→22.6→41.0→63.9→83.6N）, 天然违反红线。
- 红线以内**实测唯一稳定通路 = 位置模式慢推 + 只读力做被动看门狗**（§5）; 力控模式只在自由段成立,
  工件一顶到孔口/止口就必然被控制器保护下电。
- 侧向力是独立红线（"别划伤工件侧面"）: 侧向合力/力矩都要单独设阈值, 不能只盯轴向。
- 超限事件入台账 `docs/INCIDENT-INDEX.md`（力序列/机理/处置）, 不要只在对话里说。

## 流程(按这个顺序做, 每一步都有判据)

### 1. 现场说「记住这个位置」= 落库, 不是脑内记
```
<项目>/gui-venv311/bin/python tools/record_point_sdk.py --record <新点名> --desc "<现场原话场景>"
```
- 零运动、不需真动授权，但**臂必须停稳**(工具自带三道闸: 帧龄/位置范数/极差)。
- 录完**回读**逐位值，并算出它与已有点位的关系一并报给现场
  (例: "离已示教的插入点 54.2mm, 姿态差 0.99°")。这句话的意图是“以后能回到这里/拿它当基准”。

### 2. 算清几何再谈动作(只读, 零风险)
- 当前 TCP、目标插入点、工具 Z 轴在基座系的方向: 由 quat 算 R，取第 3 列。
- 插入深度 = |插入点 − 口点| ，方向 = 工具 Z。两者必须**同向**(夹角小)。
- 口点与插入点的**姿态差**决定能不能纯平移: >2° 就要当心(边转边插会别针)。
- 报给现场的口径: 深度多少 mm、沿哪个轴、姿态差几度 —— 这三个数到位才谈下发。
- **工具 Z 必须校平到水平**（插孔基本水平）: `Rz=[2(xz+yw), 2(yz−xw), 1−2(x²+y²)]`, `angle=asin(Rz_z)`;
  |angle|>2° 先绕 `Rz×Rz_des` 做最小旋转校平（位置不动）再推。不校平就推 = 轴向顶在孔口面,
  加多大力都只出 0.4mm 位移 + 十几牛尖峰（实测轴差 4.46° 时 advance 8s 只前进 0.41mm、力峰 16.7N）。
  欧拉角约定先用当前 quat 自算 ZYX rpy 与控制器 `pose` 返回的 rpy 对齐再下发; 验收看**动后工具 Z 夹角**
  （实测校平后 `[+1.0000,+0.0080,−0.0000]`、位置漂移 0.003mm）。
- 校平判据是"行程上的漂移 ≤ 孔径余量", 不是追到 0.00°: 现场说"目视已经平行、不必绝对水平"时,
  按 quat 真值报残余角度和它在实际行程上造成的侧偏量（几度 × 几十 mm = 几百 μm~几 mm）, 由现场决定是否再校;
  目视只能做粗判, 不能替代 quat 真值。

### 3. 🔴 先证“力控服务在图里”，再谈授权/录点/派发
```
ssh <边端> 'source /opt/ros/humble/setup.bash; export ROS_DOMAIN_ID=0; ros2 service list | grep -Ei "lissajous|insertion"'
```
- **0 条先排 CLI 卡死**: `ros2 daemon stop` 再列。`ros2 node list` 抛 `xmlrpc` 异常 = 守护进程卡死,
  会**假报“图上什么都没有”**(实测同一台机器重列后立刻出现 44 个服务)。
- 仍 0 条 = 驱动/运动栈没起 ⇒ 现场起驱动再谈, 不要派发。
- ⚠️ **TCP 真值新鲜 ≠ 服务在**: 位姿常走 SDK 直连(不经 ROS)，臂“活着”和服务“在图上”是**两个探针**。
- 派发后若回执是 `… · 没拿到 success 字段 · 尾部: waiting for service to become available...` 且 TCP 位移
  `0.00mm` ⇒ 就是服务不在图上，**不是服务慢、不是设备拒动**。立刻停手，别重发第二条。
- 顺序固定: **探服务 → 录点 → 授权 → 派发**。授权窗(300~900s)烧在一条注定没人接的派发上 = 现场白等。

### 4. ��栏预检 FAIL 在插入类任务里是**预期**的
`precheck_move.py --to <插入点>` 常报
`连杆6 侵入<设备> 106.2mm · 夹爪包络 72.9mm · 到目标直线 71.7mm` ——
因为**插孔本来就在那个围栏盒里**。
- 这个签名**不是**“路径不安全”的新信息，而是“最后这一段在盒内”的必然结果。
- ⇒ 既不能硬闯(盲推一条深几十 mm 的直线没有任何力保护)，也不能因此把任务推回去；
  正确做法是**把这一段全部交给力控**(见 §5)，并用围栏原文当“为什么不盲推”的证据讲给现场。

### 5. 插入 = 位置慢推 + 被动力看门狗（力控模式在接触态不可用）
一发 = 力控搜索/压入(搜索盒 ±10mm，以**当前位姿**为盒原点，力沿工具 Z)。驱动侧配方口径(产线状态机):
`6N 沿工具Z`(第二次补 8N) · `K=[6000,6000,0,300,300,100]` · `vmax=[0.1,0.1,0.01,5,5,5]` · 盒 ±10mm / 8s。
⚠️ **硬接触状态下力控模式一律不可用**: 工件顶在孔口/止口时, `fcStart` / `setLissajousOverlay` / `moveStart`
任一步都会触发 `41451 力控模式触发保护, 控制器下电: Cart Velocity OverLimit`（连续 5 次复现;
`K_z` 给 0 / 2000 / 20000 结果一样, 工具 Z 校平到 −0.000° 也照样复现）;
之后所有力控接口报 `ec=-17 motor power state unsupported operation`。**那不是你停的, 是控制器下电** ——
先读 `state` 的 `powerState`, 别以为是脚本坏了; 上电复位只能现场做。
⇒ 插入段**不要进力控模式**: 位置模式 MoveL 慢推（0.45~1.9mm/s）, `getEndTorque` 只做被动看门狗,
六轴阈值（轴向/侧向/力矩）运动中每 20ms 判一次。已验证可连续推 40mm 且全程不下电。
具体配方/参数/判据表见 `references/position-push-insertion.md`。
⚠️ **非力控模式下力含重力偏置**: `getEndTorque` 不扣负载, 静止 |F| 就有 24N 级自载;
一切判据都用 **Δ(相对静止基线)**, 汇报时写"绝对值 X N(含自重 Y N)/ 净接触 Z N", 否则现场会以为已经超红线。
⚠️ **力矩同理, 而且漂得更凶**: 静止 |T| 随姿态在 0.7~9Nm 级变化（自载 × 0.2~0.3m 力臂）,
所以“力矩 > N Nm 就停”这种**绝对阈值在这台臂上没有物理意义**; 力矩看门狗必须写成 `max(|Δtx|,|Δty|,|Δtz|)`,
基线在每发运动前用当前姿态重取（同一个口、同一天, 姿态一变力矩就能差 8Nm）。
- 每发**前后各读一次 TCP 真值**，算 Δ 与累计；一发位移 **<0.5mm** ⇒ 判“到底/挡住”，停。
- 累计超上限(按实际孔深设, 别写死) ⇒ 停。
- 服务回执 `success=False` ⇒ 中止，**绝不重发**(重发=在未知接触状态下叠加力)。
- 全程**不发夹爪指令**: 松开是独立一步, 别让"插入"顺手把工件掉了。
- 每发推进前先确认**件还在爪里**: AR 页面锁定框 `box2d` 与实时框相差几十~几百像素 ⇒ 件在夹爪里滑了/歪了,
  此时“找孔/加压”全无意义（实测几十牛顶压后模块框从 (317,0) 掉到 (600,452)）, 先让人重新夹正再谈。
- 一发位移 **<1mm** 且力已升到阈值 ⇒ 判"顶在孔口面上", **不是"快进去了"**, 不许续力; 位移偏 <1mm 一律按顶面处理。
- **侧向持续 + 力矩单调上涨 = 轴没对齐, 不是孔太紧**: 侧向一直 7~9N、力矩从 1.3→3.0Nm 随行程涨,
  而轴向只有 10N ⇒ 工具轴/孔轴残余角度在长行程上累积成侧偏（5.7° / 40mm ≈ 4mm）。此时续推只会磨一侧壁,
  先退出来、校平轴再推; **工件已在孔内时禁止原地转姿态**（绕 TCP 转 5.7° 会把末端扫动 10mm 级）。

### 5b. 🔴 三条硬教训: stop 不等于卸力 · 快段必须在孔口之前结束 · 打断会话不能 kill

- **`stop()` 只保持位置, 不卸力**: 工件楔在孔里时伺服一直顶着, 六维力会**自己往上爬**
  （实测 35N → 119.8N → **178.8N**/|T| 54.8Nm, 期间臂是 idle 静止的）。
  ⇒ 任何 force/axial/lateral/torque_stop 之后**必须自动沿轴退 1.5~3mm 再报数**（`unload_after_stop()`）;
  卸力后 |F| 会立刻回到自由段基准（实测 179N → 12.6N 只用 3mm）。
  **汇报里要区分“峰值 |F|”和“卸力后 |F|”**, 否则现场会以为臂还在顶。
- **快速接近段必须在孔口之前就结束**: seat 点距孔口约 50mm, `--approach-mm 15` 意味着“快段”会
  直接冲进孔口 —— 实测 speed 15(≈6.8mm/s) 在孔口 1mm 内就顶出 35.8N/11Nm, 把工件楔死。
  ⇒ 快段只用到孔口前 ~60mm, 孔口段一律 **≤1mm/s**; 快到孔口却不减速 = 用位移换力, 必楔。
- **打断运动会话用 `sdk_ctl.py stop`(规划停), 不要 `kill -9`**: 被 kill 的会话在控制器里留下
  MoveL 队列, **下一次会话 `moveStart` 会接着把它跑完**（实测臂自走 150mm, 0.80294→0.65198）。
  ⇒ 会话开头强制 `stop() → moveReset() → 0.25s 内位移 >0.05mm 立即拒发新指令`（预静止闸）。
- **李萨如摆幅要跟着偏差量级选**: 尖端差 1~2mm 时 ±0.2mm 摆幅只能推 1.2mm 就顶 30N,
  ±1.2mm 摆幅能推 3.2mm（但侧向涨到 17.6N）。⇒ 先大摆幅找孔, 进入后**收小摆幅**防划侧壁;
  若各档摆幅都卡在同一个力位, 说明不是摆幅问题, 而是**工件在爪里已经歪了**, 先让人重新夹正。

### 6. 验收与取证(不许用“已下发”当插入成功)
- 硬证据三件套: 起点 TCP → 每一发的 Δ 表 → 终点 TCP + 累计前进 mm。
- 落盘 JSON(起终点/每发耗时/Δ/回执)到 `zmax_data/reports/insert_force_<时间>.json`。
- 汇报必须给**逐发位移表**，而不是“已插入”；位移为 0 却报成功是事故级谎报。

### 7. 到底判定 → 存点位 → 同口一步直插
- **到底的硬签名是“力卸载”**: 顶到 56.1N 后只松 0.49mm, |F| 立刻回到自由段静载基准(24.1N) ⇒ 前端是硬止口;
  反之"松一点力仍大" = 摩擦/楔紧, 不是到底。**只靠位移量判到底会过头**（实测多推 3.2mm 才开始抬力矩）。
- 判到底后先松到无残余压力, 再 `record_point_sdk.py --record 插入到位_<口>` 存点（回读 6 帧极差）;
  台账里同时记: 顶上时 |F|/|T| 峰值、松开后的 |F|、自由段静载基准、深度（从哪个基准点算）。
- 同口复现用一步直插模式: 目标点(位置+quat) → 快走到 `点 − 沿轴 approach_mm` → 低速直插 → **到点误差 <0.35mm 判 reached**;
  全程被动看门狗（轴向 30N 停 / 红线压回、侧向 10N、力矩 3.5Nm）。
- **已经在接近点更深处就别再后退去“接近”**: 反向行程会拉卡扣/止口, 实测力矩 3.59Nm 直接停 ⇒ 跳过接近段只走插入段。
- 入止口后**拔出来是独立一步**, 判据只能用 Δ: 真正的保持力签名 = 退出段**侧向 Δ 单调涨**（实测 0.5→5.5→11.4→12.8→13.9N）+ 轴向 Δ 峰 25N。
- 🔴 **力矩绝对值不能当“楔紧/卡扣”证据**: 长力臂姿态下同一台臂的 `ty` 会在 −0.7 ~ −9.1Nm 之间漂,
  那**只是自载重力力矩**（自载约 24N × 力臂约 0.3m）; 把它当接触力会得出完全相反的结论（我据此误判过一次“有卡扣保持力”）。
  力矩只看 Δ(相对**同姿态**静止基线), 每发推进前重取一次基线。
- 退出别硬拔: 先按现场许可把阈值一次性放开（实测 侧向 20N / 力矩 8Nm）, **沿轴直退 3mm、不加任何横动**（横动才划侧壁）,
  判据 = 退完 |F| 回到自由段静载基准（实测 15.1N vs 基准 15.2N）= 已从止口解出; 一次走完, 不要半步来回磨。
- 现场要“看着力插入”时, 把六维力接到信号分析窗口（管道见 `references/force-control-api-map.md` 只读侧）。
  ⚠️ 波形“总是断开”先查总线节流, 不要怀疑信号源: `ar_aoi_bus.py watch` 的 sleep 下限写死 0.5s、
  且每轮 `take(timeout=0.30)` 阻塞 ⇒ 总线上限只有 2Hz（实测 0.5Hz）; 窗口按 20Hz 轮询文件 ⇒ 必然断成点。
  修法: sleep 下限 0.05s + 慢源(DDS)降频 1s 抓一次并用缓存 + 二次起超时 0.02s + 原子写 tmp 文件名按 pid 唯一。
  修完实测 6.3Hz（间隔中位 166ms）波形连续。

## 已知阻塞路径(遇到别再试第二遍)
- 力控服务不在图上 → 只剩两条路: ①现场起驱动，②用 SDK 原语自己实现插入(见 `references/force-control-api-map.md`)。
  走 ② 时**不要进力控模式**(硬接触必然 41451 下电), 按 §5 的位置推 + 被动看门狗做;
  已验证到"插到底 → 存到底点位 → 一步直插复现"这条链路。
- **运动会话同一时刻只能有一条, 只读采样可以并存**: 实测 10Hz 力采样器 + 位姿真值采样器 + 一次位置推同时跑,
  `n_err=0`、真值不断。会踩的不是会话数, 而是**两条运动指令叠在未知接触状态上**。
