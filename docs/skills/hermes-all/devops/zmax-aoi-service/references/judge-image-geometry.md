# 判据图几何：摆正、零拉伸、尺寸恒定

场景：老倪说「标记不是模块的轮廓」「判据图要摆放水平」「图像不要一会变大一会小」。
三个症状三种不同根因，别混在一起改。

## 1. 标记框错 = ROI 搜索把工件自己当成夹具（表面 10083）

`surface_roi` 判「夹具贯穿列」用的是「本列亮像素数 > 0.39H」。
实测竖放的光模块长边 1395px，**自己就超过 0.39H(799px)** ⇒ 模块被判成夹具，
ROI 右界收到 x≈1334，模块(x≈1300~1680)被切掉大半，剩下的碎块成了 743×110 横条。

判据要改成双条件 AND：

```python
_below = (col > int(0.39*H)) & (span >= int(0.90*H))   # span = 每列亮像素 y 跨度
```

夹具是**整列贯穿**(y 跨度≈满高)，竖放模块只占自己那一段(实测 58~69%H)。
实测该帧：原判据命中 306 列，真正贯穿(y≥0.9H)的列 = 0。

修后同一帧：743×110 / fill 0.522 → 375×1395 / fill 0.877，长宽比 2.349→4.62，清晰度 28.5→109.2。

## 2. 一会大一会小 = 输出尺寸随每帧搜索抖动

症状：MJPEG 里高度在 301/355 之间跳（18%）。
根因：输出高度取自**本帧**搜到的矩形高度(375~440 波动)，再按长边缩到 out_long。

修法：**输出尺寸锁** —— 首个合格帧算定 (out_w,out_h) 后恒定，之后每帧把裁剪块
等比「装进」固定画布(只缩不放 s=min(1,…))、居中留边。
验收：同一帧 × 5 档亮度(0.85~1.15) 全部输出 1400×302。

## 3. 不水平 = 残留倾斜（旋转治不了梯形）

判据：上沿斜率 vs 下沿斜率。
- 两者**平行但整体斜** ⇒ 补旋一次即可(实测 −1.04° → 按测得角度本身转 → −0.01°)
- 两者**不平行(夹角 >0.3°)** ⇒ 透视，旋转治不了，要四角 warpPerspective

**量倾角必须在最终画布上量**：金手指先改的是「在未加白边的条带上量」，
结果只从 −1.04° 纠到 −0.78°；改成在成品画布上量(白底 <250 = 内容)并迭代 3 次，
收敛到 +0.00°/−0.03°。量具和眼睛不在同一张图上，就会出现「量着 0、看着还歪」。

## 4. 硬 resize 到定尺 = 隐形拉伸（金手指 10082）

`render_judge` 原来 `cv2.resize(img,(900,332))`，而条带原始 2131×75(比 28.4)，
定尺 900×332(比 2.71) ⇒ **垂直放大 10.5 倍**。代码注释写的是「内容按比例适配」，代码没兑现。

修法：等比 contain + 白底居中，meta 记 `no_stretch/fit_scale/fit_content`。
修后内容 900×34，长宽比 26.5 ≈ 输入 28.4。

⚠️ 改判据图几何前先确认**检测输入不是判据图**：10082 的 `model_in = crop`(960×960 方形)，
判据图只用于显示/落盘 ⇒ 改几何不影响召回。若模型直接吃判据图，改尺寸会掉召回。

## 5. 曝光接口会把进程打崩（10083 `/exposure`）

实测：`POST /exposure?us=3000` → 10083 端口消失；`us=8000` → Connection reset。
Python 的 try/except 兜不住 —— 是相机 SDK 在 native 层崩。

两个措施（本机已改，尚未部署）：
1. `us` 下发前夹取到 `[3500, 200000]`
2. 改参数必须与抓帧**同一把锁**（`_cam_lock`），原来只有 `_EXPO_LOCK` 管自己，
   抓图线程仍能同时碰相机 ⇒ 竞态崩

崩溃后拉起：`import aoi_remote_deploy as dp; dp.start_pair()`（比手搓 scp 安全）。

## 6. 「曝光太强」要先分清是哪张图

10083 在 5000us/gain1.8 下：原始帧 mean 40.2、死白 6.6%、暗 77.9% —— **是暗的**。
「太亮」来自判据图里模块镜面反光(mean 177、死白 31%)。
压显示亮度会把交付判据图改暗(老倪拿它当证据)，降相机曝光会把厚度判据打死(40000us 时 3/3 False)。
⇒ 只能改光源角度/加偏振片，或重写不依赖过曝条的判据。

## 7. 部署源目录陷阱

`aoi_remote_deploy.py` 默认从 `zmax_data/aoi_v4/` 取文件（`--surface/--finger`），
而 `production_sync.py pull` 写到 `tools/aoi/`。
改了 `tools/aoi/` 却直接部署 = **推上去的还是旧文件**（实测发布 61649 B 而本地已 62650 B）。
⇒ 改完先同步到 `zmax_data/aoi_v4/`，或部署时显式传 `--surface/--finger`；发布后核对字节数+SHA。
