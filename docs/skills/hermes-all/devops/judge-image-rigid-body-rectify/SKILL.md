# 判据图整形: 矩形刚体动态搜索 + 摆正

## When to Use
- 用户说「判据图应该是摆放平整/平行的图, 不是斜着放着的, 只要模块的刚体」。
- 用户说「不给拉伸, 把斜着的位姿摆正即可」/「不要又叠加一个摆正的图」/「曝光、亮度应该一模一样」。
- 要做**旁路外观检测/表面检查**的输入图整形, 或要把工位画面裁成“只有工件”的正视图。

## 一、需求口径 (老倪原话, 每条都踩过)
| 口径 | 原话 | 反面 (做错会被打回) |
|---|---|---|
| 摆正·平行·只留刚体 | 「判据图应该是摆放平整，平行的图，不是斜着放着的，只要模块的刚体」 | 斜着的原图直接当判据图 |
| **动态搜索**, 不许固定四角 | 「以后的位置还会变，找出矩形刚体是搜索任务，是动态任务」 | 写死四角 / 用“固定四角套低曝光帧” |
| **不许拉伸** | 「你不能给光模块拉伸，就是把原来的斜着的位姿摆正即可，没让你拉伸那么宽」 | 把检出四边形重映射成自定尺寸矩形(比例被改) |
| 原图保持原样, **不叠**摆正图 | 「原始图你就保持就好了，不要又叠加一个摆正的图，把原始图上叠加一个搜索到的方框，即准备截取的区域」 | 把“原图+摆正图”拼成一张对照图 |
| 两图**亮度一模一样** | 「转了方向的光模块，怎么跟斜着的原始图像，曝光，亮度不一样，应该是一模一样的亮度」 | 用高曝光帧定几何、低曝光帧取像素(两张图亮度不同) |

## 二、做法 (在役验证过的一版)
1. **几何: 阈值找亮块, 不用 Canny**。
   `CLAHE(2.0,(8,8))` → `GaussianBlur(5,5)` → `Otsu` 二值; 若前景 >60% 像素(过曝帧会把 Otsu 拉坏)则退 80 分位阈值;
   再 `MORPH_CLOSE(15)` + `MORPH_OPEN(25)`。
   - ❌ **Canny 边缘法在本场景不成立**: 闭合后的轮廓是**细边环**, 矩形度只有 0.05, 永远进不了候选(实测 27 轮廓 0 候选)。
2. **候选与评分 (位置无关 = 动态)**: 每个轮廓取 `minAreaRect`;
   `score = 面积占比 × 矩形度(contourArea/rectArea) × 对边平行度`; 约束 `面积占比 ∈ [0.5%, 75%]`; 择优。
3. **摆正 = 纯旋转 + 按真实像素尺寸裁剪** (零缩放、零透视重映射):
   ```python
   (cx, cy), (w, h), ang = rect          # minAreaRect: 四角天然平行
   M = cv2.getRotationMatrix2D((cx, cy), ang, 1.0)      # 缩放必须 1.0
   rot = cv2.warpAffine(img, M, (img.shape[1], img.shape[0]), flags=cv2.INTER_CUBIC)
   crop = cv2.getRectSubPix(rot, (int(round(W)), int(round(H))), (cx, cy))   # W,H = 检出尺寸
   ```
   要让长边水平就再转 90°(`ang+90` 并交换 W/H), 仍然只旋转。
4. **几何与像素同帧**: 定几何和取像素用**同一帧** ⇒ 亮度必然一致。
   模块在高曝光下会过曝时, 选“够亮但不过曝”的那一档重拍; **不要**把几何帧与测光帧分开(那就是被打回的亮度不一致)。

## 三、交付形态 (各一张图, 不拼)
- 主图: **原图上叠搜索框**(绿框 + 四角点标注, 文字写 `crop area: 1764x440 tilt -61.9deg`)。
- 次图: **单独文件**的摆正结果(不与原图拼成一张)。
- 报数口径: 检出倾角 / 矩形度 / 平行度 / 检出尺寸 / 饱和像素占比 / 与原图同像素亮度差。
- 图上文字一律 **ASCII**(中文会渲成方框)。

## 四、自检判据 (缺一条就不算做到)
- **不拉伸**: `输出尺寸 == 检出尺寸`(实测 1764×440 → 1764×440 ✓); 长宽比一致(3.38 vs 3.37)。
- **亮度一致**: 原图该矩形内像素 vs 摆正图的均值/中位差应 ≈0(实测均值差 **−0.08**、中位差 **0.0**)。
- **搜索稳定**: 多档曝光分别搜, 应命中同一刚体(实测各档倾角 −60.5°~−62.4°, 矩形度/平行度 1.00)。

## 五、已知短板 (未收口, 别当已完成)
