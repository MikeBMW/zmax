# 判据图整形: 矩形刚体动态搜索 + 摆正

## When to Use
- 用户说「判据图应该是摆放平整/平行的图, 不是斜着放着的, 只要模块的刚体」。
- 用户说「不给拉伸, 把斜着的位姿摆正即可」/「不要又叠加一个摆正的图」/「曝光、亮度应该一模一样」。
- 要做**旁路外观检测/表面检查**的输入图整形, 或要把工位画面裁成“只有工件”的正视图。

## 一、需求口径 (老倪原话, 每条都踩过)
| 口径 | 原话 | 反面 (做错会被打回) |
|---|---|---|
| 摆正·平行·只留刚体 | 「判据图应该是摆放平整，平行的图，不是斜着放着的，只要模块的刚体」 | 斜着的原图直接当判据图 |
| **动态搜索**, 不许固定四角 | 「以后的位置还会变，找出矩形刚体是搜索任务，是动态任务」 | 预先固定四角 / 用“固定四角套低曝光帧” |
| **不许拉伸** | 「你不能给光模块拉伸，就是把原来的斜着的位姿摆正即可，没让你拉伸那么宽」 | 把检出四边形重映射成自定尺寸矩形(比例被改) |
| 原图保持原样, **不叠**摆正图 | 「原始图你就保持就好了，不要又叠加一个摆正的图，把原始图上叠加一个搜索到的方框，即准备截取的区域」 | 把“原图+摆正图”拼成一张对照图 |
| 两图**亮度一模一样** | 「转了方向的光模块，怎么跟斜着的原始图像，曝光，亮度不一样，应该是一模一样的亮度」 | 用高曝光帧定几何、低曝光帧取像素(两张图亮度不同) |

## 二、做法 (在役验证过的一版)
0. **先判图像可用性, 再谈搜索**。`kind=origin&grab=1` 会**返回全黑帧**(现场灯/曝光状态; 实测整帧均值 0.0、
   标准差 0.0)。取到图先算灰度均值与标准差: `mean<3` 或 `std<2` ⇒ 直接报“图像不可用”并停, 不要在上面跑
   搜索/检测(YOLO)/VLM——黑图上的 0 检出会被误读成“模型没用/找不到目标”。
   同一张图做 A/B 前也先确认两次都可用。
1. **几何: 阈值找亮块, 不用 Canny**。
   `CLAHE(2.0,(8,8))` → `GaussianBlur(5,5)` → `Otsu` 二值; 若前景 >60% 像素(过曝帧会把 Otsu 拉坏)则退 80 分位阈值;
   再 `MORPH_CLOSE(15)` + `MORPH_OPEN(25)`。
   - ❌ **Canny 边缘法在本场景不成立**: 闭合后的轮廓是**细边环**, 矩形度只有 0.05, 永远进不了候选(实测 27 轮廓 0 候选)。
2. **候选与评分 (位置无关 = 动态)**: 每个轮廓取 `minAreaRect`;
   `score = 面积占比 × 矩形度(contourArea/rectArea) × 对边平行度`;
   约束 `面积占比 ∈ [0.5%, 75%]` + 🔴 **长宽比下限 ≥2.5**; 择优。
   - **长宽比闸是防「搜到台面」的唯一有效手段**: 工件是扁长的(光模块实测 **5.97~6.82:1**),
     台面/夹具接近方形(实测 1.35~1.88:1)。没有这道闸, 一旦过曝把工件与台面糊成一片,
     评分最高的候选就是 **1717×1269 的台面**(矩形度 0.41 仍能压过真工件),
     后面所有摆正/裁图/检测都建立在错的框上 —— 而且它长得像个合理结果, 不会报错。
   - 闸放 2.5 而不贴着 5.97: 留出工件型号与长宽方向的余量; 每次把 `aspect` 与 `fill` 一并报出来供复核。
3. **摆正 = 纯旋转 + 按真实像素尺寸裁剪** (零缩放、零透视重映射):
   ```python
   (cx, cy), (w, h), ang = rect          # minAreaRect: 四角天然平行
   M = cv2.getRotationMatrix2D((cx, cy), ang, 1.0)      # 缩放必须 1.0
   rot = cv2.warpAffine(img, M, (img.shape[1], img.shape[0]), flags=cv2.INTER_CUBIC)
   crop = cv2.getRectSubPix(rot, (int(round(W)), int(round(H))), (cx, cy))   # W,H = 检出尺寸
   ```
   要让长边水平就再转 90°(`ang+90` 并交换 W/H), 仍然只旋转。
4. **几何与像素的分帧规则, 按「给谁看」分两种口径** (别混用):
   - **给人看的判据图 ⇒ 必须同帧**。定几何和取像素用**同一帧** ⇒ 亮度必然一致。
     模块在高曝光下会过曝时, 选「够亮但不过曝」的那一档重拍; **不要**把几何帧与测光帧分开
     (那就是被打回的「亮度不一致」)。
   - **送模型(检测/分类)的图 ⇒ 反而要分帧**。模型的输入分布是**训练时的曝光**, 不是「人看着舒服」的曝光;
     而低曝光帧的对比度才够干净地搜出刚体。做法: 低曝光档搜几何 → 切回模型训练那档取像素 → 按搜到的角度
     旋转**整幅图**再送检测。
     🔴 代价必须写明: 两帧之间工件可能动过 ⇒ 分帧前先确认工件静止(量两次几何的角度/中心, 一致才继续),
     并在产出里标「几何帧 <档位> · 像素帧 <档位> · 跨帧」。
     ⚠️ 送检测要旋**整幅**、不要只送裁出来的模块条 —— 裁剪改的是画面构图(模型见过的比例/留白全变了),
     检出结果不可比。
     🔴 **像素帧选哪一档, 不只看对比度 —— 要看模块不过曝**。实测同姿态同摆正只改曝光:
     48000us(ROI 死白 90.7%) → 检出 **0** 个; 3000us(死白 1.7%) → 检出 **1** 个 conf 0.473。
     过曝会把缺陷细节直接冲掉。而且 3000us 下**既能搜到刚体**(实测 1095×188 / 长宽比 5.83)
     又不过曝 ⇒ 多数情况根本不用分帧, 不用付两趟 settle 的代价。
     选点表/完整链路(含直接调产线加密 YOLO)见 `surface-defect-vision-detection` 技能。
5. **「保留整块模块」与「零拉伸」不冲突 —— 别为了凑 no_stretch 而不扩**
   (用户先说过「只要模块的刚体」「不能拉伸」, 后来又说「保留整块模块」; 两个要求都要满足):
   - `expand=False` → 1123×188 · 长宽比 **5.97** · 只框到亮的 87%, **暗头被切掉**
   - `expand=True`  → 1282×188 · 长宽比 **6.82** · 整块模块 · `expand_px=[154,0]` ← **交付用这个**

   ✅ 正解: 扩裁剪窗口**本身就是允许的** —— `getRectSubPix` 按真实像素 1:1 取出, 没有插值。
   "单轴多取 14%" 改的是**裁剪范围**, 不是把像素拉宽。真拉伸只发生在 `cv2.resize`。
   所以 `expand=True` 是默认交付口径, 同时把 `expand_px` 单列报出来让人能复核扩了多少。
   ❌ 错法(踩过): 把 `no_stretch` 定义成「裁剪宽 == 亮度检出宽」⇒ 一扩暗头就 False ⇒
   为了好看去关掉 expand ⇒ 反而把用户要的整块模块切掉一半。
   注意: 扩出来的区域含暗背景 ⇒ `same_pixel_mean_diff` 从 −0.57 涨到 ~16, 那是**视野变宽**
   不是亮度被改; 严格比亮度要只比两版共有的像素区。

## 三、交付形态 (各一张图, 不拼)
- 主图: **原图上叠搜索框**(绿框 + 四角点标注, 文字写 `crop area: 1764x440 tilt -61.9deg`)。
- 次图: **单独文件**的摆正结果(不与原图拼成一张)。
- 报数口径: 检出倾角 / 矩形度 / 平行度 / 检出尺寸 / 饱和像素占比 / 与原图同像素亮度差。
- 图上文字: 给用户看的对比图用 **PIL + 系统 CJK 字体**(`NotoSansCJK-Regular.ttc`)可以写中文;
  只有用 `cv2.putText` 时才必须 ASCII。别因为"cv2 画不了中文"就把标题全写成英文。
- 🔴 **参数拿不准时给「多档并排对比」, 不要一档一档问**: 同一帧把候选档位(曝光几档 / expand 开与关 /
  压高光 knee-top 几组 / 摆正几版)各渲一格, 每格标 mean·p90·死白·关键尺寸, 让用户一眼指"要这个"。
  实测: 单档逐个改会被连问三次"还是太亮"; 改成五档并排后一次就定。区别在于**后者把判断权交给看得见的人**,
  而不是让用户拿一句话去描述一个他自己也看不到的数值。

## 四、自检判据 (缺一条就不算做到)
- **不拉伸**: `no_stretch = (out_size == crop_size) 且未走 resize`(实测 1282×188 → 1282×188 ✓)。
  🔴 判据必须是「**有没有 resize 插值**」, **不是**「裁剪宽 == 亮度检出宽」。后者是错的:
  它把"扩暗头"误报成拉伸(实测 `no_stretch=False` 而 `crop==out` 逐位相同, 根本没有 resize)。
- **扩展单独报**: `expand_px = [长边扩多少, 短边扩多少]` 与 `no_stretch` 分开写, 别混成一个字段;
  扩的像素是 `thr` 阈值判定属于工件的真实像素, 1:1 取出。
- ⚠️ **`no_stretch` 必须在 resize 分支之后定值**: 写在 `if out_long and ...: cv2.resize(...)` 之前,
  走到 resize 时会把"有插值"报成 True(实测静默错报)。
- **亮度一致**: 原图该矩形内像素 vs 摆正图的均值/中位差应 ≈0(实测均值差 **−0.08**、中位差 **0.0**)。
  但**扩过暗头就不能拿整图均值比** —— 扩进来的暗背景会把差值推到 ~16; 要比只能比两版**共有**的像素区。
- **搜索稳定**: 多档曝光分别搜, 应命中同一刚体(实测各档倾角 −60.5°~−62.4°, 矩形度/平行度 1.00)。

## 五、已知短板 (未收口, 别当已完成)
- 🔴 **过曝档上根本搜不到工件, 别在那里搜**。实测同一工位: 5000us 下模块 `1124×188`(长宽比 5.97、
  矩形度 0.833)干净可搜; 切到 48000us 时 **Otsu 前景占比 = 1.000**(整幅被判成前景),
  退 80 分位阈值后最大候选是 `1717×1269` 的台面(长宽比 1.35), **一个合格候选都没有**。
  ⇒ 定式: **低曝光档定几何 → 模型训练那档取像素**, 靠长宽比闸兜住台面误抓(见 §二.2)。
  只是「前景 >60% 就退 p80」不够 —— 台面本身也是亮的, 阈值法救不回来, 必须靠形状先验。
- ~~下一步: 加形状先验~~ **已落地**: 长宽比下限 ≥2.5 已进评分约束(实测工件 5.97~6.82, 台面 1.35~1.88)。
  早期记的「长宽比 ≈3.4」是别的工位/别的型号, 不要当代替值 —— 换工位先量一版再定闸。
- 相机侧前置条件: 侧面相机 = 工控机 OPT **10083**(10082 = 金手指顶视); **10083 写曝光必须 `POST /exposure?us=<微秒>&gain=<dB>`**
  (`GET` 只读, 带参数会静默无效)。取像量具必须用 `GET /picture?kind=origin&grab=1`(`kind=judge` 是派生缓存图, 拿它做 A/B 会得出“改了没变化”的假结论)。
