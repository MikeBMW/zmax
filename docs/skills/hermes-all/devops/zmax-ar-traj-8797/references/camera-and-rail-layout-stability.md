# AR3D 画面「上下漂浮」与左栏布局抖动

## 1. 相机不许每帧自动取景

症状：三维画面整体上下漂——不是手臂在动，是「图在漂」。

机制：`drawVR()` 每帧 `if(VR.auto) vrFitBox();`，而 `vrFitBox()` 把**会动的臂点云**算进包围盒 ⇒ 相机目标点跟着臂上下移动。

规则：自动取景只做一次（点 🎯对准 / 双击「执行轨迹」时），之后相机锁死，只有手动拖动才动：

```js
if(VR.auto){ VR.auto=false; vrFitBox(); }   // 一次性，不是每帧
```

判据（必做）：跟随播放中连测 ≥3s，`VR.tgt` / `VR.dist` 必须逐位不变，同时 `PREV.ssSeq` / 信号在推进——两者同时成立才能说「动的是臂不是相机」。

## 2. 左栏不许有「出现/消失」的行

症状：左侧按钮整体上下跳。

机制：提示行/按钮行按状态 show/hide，或窄栏 `flex-wrap` 换行 ⇒ 行数变化 ⇒ 下方所有按钮重排。用户会直接说「搞得左侧所有按钮在上下跳」。

规则：

- 开关下的常驻提示行**整行删掉**（连 JS 写它的函数一起清，留空函数要 `return` 并写明为什么，别留 `getElementById` 空引用）。
- 信号摘要（seq / 帧龄 / 段 / 元任务）只放**顶部横幅**——绝对定位，不占栏高。
- 次要按钮与开关**同一行内联**，行上 `flex-wrap:nowrap; white-space:nowrap`，按钮 `padding:2px 8px;font-size:11.5px`，保证窄栏不换行。
- 判据：开关 关→开→跟随→回关 四态各取一次 `getBoundingClientRect().y` 与栏高，必须完全相等（实测 275/275/275/275、栏高 577）。

## 3. 播放命令的时效口径（页面自动跟版会吃掉刚点的运行）

- 页面有跟版自检（`/api/ar/build` + `arBuildStale()`），改版会自动 reload ⇒ 内存里的播放态丢失。
- 口径统一为 **120s**：服务端 `play.fresh = age_s <= 120`；页面 `PLANT._lastPlayTs` 初值 = `Date.now()/1000 - 120`。这样「2 分钟内人点过的运行」刷新后仍然跟随，更老的命令不会自己拉起播放。
- 改完页面版本后，要给正在挂着的标签页**补一条 fresh `start`**（写 `ar_play.json`），否则用户看到「开关开着却不动」。
- 排障时先看 `/dev/shm/zmax_ar_diag.jsonl` 里该标签页自报的 `bld`：页面版本号比线上旧 ⇒ 结论是「页面没跟上」，不是信号没来。
