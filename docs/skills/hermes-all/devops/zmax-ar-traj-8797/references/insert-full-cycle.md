# 右臂插拔全流程仿真: 抓取→插孔→双相机检测→分流 (OK 下料盘 / NG 废料盘)

用途: 让用户看见「上料完之后, 右臂把一整盘模块逐个插进插孔、拔出、送两个相机检测、按结果分流」的全过程。
纯可视化仿真, 真机零指令(不调 l2_daemon、不走 39071、不发 moveStart)。

与 `references/larm-sim-transport.md`(左臂搬运)是**两条不同的流**: 那条是同一动作重复搬盘,
这条每循环多出「插入/检测/分流」三个决策点, 目标盘还不固定。播放器可以共用 `PREV`(紫色幽灵臂),
但段表结构与时间口径不同, 不要互相套用。

## 数据流(与左臂搬运同构, 四层)

```
tools/sim_insert_plan.py  →  zmax_data/runtime/traj/sim_insert.json
                          →  GET /api/sim_insert   (只读 JSON, "ok": True)
                          →  页面按钮「🔁 插拔全流程」(驱动 PREV) + 检测标签 + 盘边计数
```

- 后端路由照抄 `/api/sim_transport` 写法, 路径必须 `os.path.join(REPO, "zmax_data", ...)`
  (常量名是 `REPO`, 写 `ZMAX_DATA` 会 NameError 而接口只回 `{ok:false, err}`, 页面看着像「没规划」)。

## 段表: 每循环 25 段

```
 1 move    → 槽上方(slot.z + 100)
 2 down    下降到槽盒中心(slot.z)
 3 grip    夹爪闭合        t=0.4s   carry false→true
 4 up      抓起抬起
 5 move    → 准备点上方(z=340)
 6 down    下降到准备点     (691,227,271)
 7 move    → 插入口         (767,228,278)
 8 insert  插入到位 47mm     (814,228,278)  carry true→false
 9 check   插孔检测        t=0.5s   check{kind:'hole'}
10 pull    拔出到口        carry false→true
11 up      拔出抬起        → (767,228,340)
12 move    → 金手指点1      (360,-117,654)          右臂前方上方
13 golden 📷 金手指检测     t=0.8s   check{kind:'golden', result, camera}
14 move    → 侧面点0        (399,-406,546)
15 side    📷 侧面点0 检测  t=0.5s   check{kind:'side', face, result, camera}
16 move    → 侧面点1        (401,-435,555)
17 side    📷 侧面点1 检测
18 move    → 侧面点2        (384,-434,551)
19 side    📷 侧面点2 检测
20 move    → 侧面点3        (408,-408,569)
21 side    📷 侧面点3 检测
22 move    → 目标盘上方
23 down    下降到目标盘
24 release 松开            t=0.4s   carry true→false
25 up      抬起脱离
```

- 🔴 **抓取点/模块位置 = 槽盒中心, 不是号位示教点**。同一格实测差 **159mm**: 示教点 `(649,498,110)` 是
  **夹爪**停的位置, 槽盒中心 `(490,499,117.5)` 才是模块躺的地方。用示教点画 ⇒ 模块甩到盘外、下料盘落位全偏。
  槽盒中心取自 `GET /api/fence` 的 `槽1~14`(远排 x≈491 · 近排 x≈615, z 117.5)与 `下槽1~14`。
  落位 = 对应下槽盒中心, 复核误差应 <1mm(实测 0.6~0.7mm)。
- 8~14 号位(近排)当初没示教 ⇒ `槽8~14` 的坐标是推算的, 真机开跑前必须补示教, 否则抓取高度差几毫米,
  仿真里完全看不出来。汇报时要标明哪些是推算。
- 目标盘路由: 5 项检测(金手指 + 侧面0~3)**全 OK** → 下料盘 `下槽1..N`(槽位 = 黑盘槽 y − 423.4mm, x/z 不动);
  任一项 NG → 废料盘(盘内取几个落点, 200×200 盘放 2 个就够)。
- `NG_SPEC` 是**预设**, 建议给不同原因以覆盖多条判据(实测槽4 = 金手指 NG, 槽11 = 侧面点2 NG)。
  用户没说哪几个不良时必须显式声明「预设值, 改一行常量即可」, 别把预设当检测结论报出去。

## 时间口径(与左臂那套「每循环 N 秒」不是一回事)

- 左臂搬运有现场口径(「每个模块 3 秒」)⇒ 以 `TACT_CYCLE` 为主参数硬摊。
  这条**没有这种口径**, 用物理量摊更自然: `t = max(0.30, 距离/V) + 固定项`, `V=200mm/s`,
  抓/放 `0.4s`、插孔检测 `0.5s`、金手指 `0.8s`、侧面每面 `0.5s`。
- 实测: 加入双相机检测后每循环 18.0~21.5s、14 循环 **265.8s**(4 分 26 秒)、350 段。
  比只有插拔的版本(145s)翻不到一倍, 大头是「插入口 ↔ 金手指点1」这段 656mm 往返(单程 3.1s)。
- ⚠ 两套口径不许混: 混了就会得出「每循环既 3 秒又 9 秒」。汇报时把「循环节拍」与「播放倍速」分开说。
- 金手指点1 与侧面点0 相距 311mm, 现在按直线插值走(1.55s); 要更稳可加一个 z≈700 的中间抬升点,
  属于可选加固, 默认不加。

## 播放: 段端点 IK + 关节插值

- 长段表(350 段)不要逐帧解 IK。**每段两端各解一次**(≈700 次), 段内 6 关节线性插值:
  ```js
  s.qa = ikTool1(s.a.map(v=>v/1000), q);        // mm → m
  s.qb = (same) ? s.qa : ikTool1(s.b.map(v=>v/1000), ra.q);
  q = s.qb;                                     // 下一段接着上次的关节角, 保持连续
  ```
- 播放按节拍时钟找段(`acc+P[si].t<=el`), 倍速要能在播放中改(`INSP.rate` 每帧读)。265s 的流程 10× 是 26s。
- 🔴 **状态必须按段内序号 `seq` 判, 不能按「命中某类段」判**: 10× 倍速下每帧推进的虚拟时间可能跨过整段,
  `kind==='grip' && u>=0.5` 会整段漏掉 ⇒ 抓取计数停在 2/14 而放下计数正常 14(实测踩过)。
  段表里写 `seq`(循环内 1..25), 状态统一算: `已抓走 = (seq>=3 ? k : k-1)`、`已放下 = (seq>=25 ? k : k-1)`, 单调 `Math.max`。

## 三态渲染(缺一个用户就说「看不到模块」)

| 态 | 判据 | 画在哪 | 颜色 |
|---|---|---|---|
| 源盘剩余 | `i >= pickedK` | `SLOT_MM[i]` | 蓝 `#60a5fa` |
| 手里 | `carry` | `PREV.M['tool1'].t + [L/2,0,0]`, **轴对齐不用 FK 姿态** | 绿 `#a3e635` |
| 插在孔里 | `inHole`(kind==='check' 期间) | `(0.7905, 0.228, 0.278)` | 绿 `#a3e635` |
| 已落盘 | `i < doneK` | `cycles[i].target` | 良品绿 `#34d399` / NG 红 `#ef4444` |

- carry/inHole 按段语义判, 别用 `u<0.5 ? carry_from : carry_to` 插值: insert 段后半段用插值会让模块
  在“手里”和“孔里”之间空一帧, 看着像掉了。定式:
  ```js
  if(kind==='check'){carry=false; inHole=true;}
  else if(kind==='insert'){carry=true; inHole=(u>=0.999);}
  else if(kind==='pull'){carry=true; inHole=false;}
  else if(kind==='release'){carry=(u<0.85);}
  else carry=!!carry_to;
  ```
- 盘边再标「良品 N/12 → 下料盘」「NG N/2 → 废料盘」, 检测段在末端旁标「📷 金手指 OK/NG」——
  数量与判定是用户最先看的东西。
- 🔴 **计数必须单调递增**: 每帧只补 `doneK..done` 这段, 按“当前段 k”直接累加会同一循环重复计数。

## 像素判据的三个坑(都实测踩过)

1. 🔴 **填充 alpha 0.55 会把纯色改成混合色**。`drawFlatModule` 顶面 `globalAlpha 0.55`, 深底混后实测:
   `#34d399`→`(44,130,98)` · `#ef4444`→`(145,49,49)` · `#60a5fa`→`(59,98,148)` · `#a3e635`→`(96,134,39)`。
   按原色 ±26 统计只剩 49px, 看着像「12 个模块一个都没画」。⇒ 用**混后色** + 连通域(≥25px)数块, 块数才是个数。
   同类: 幽灵臂 `#7c3aed` alpha 0.55 用精确色数是 0, 要用色序 `b>r+25 && r>g+15`。
2. 🔴 **全屏计数会被左栏/右栏 UI 同色像素污染**。同一张图全屏统计「插孔紫」得 528~539px 且 bbox 跨全屏,
   裁到画布(`x 230..1200`)再精确色差 ±10 后是 365px、bbox 只落在插孔那一小块。
   凡是画布内的判据, 一律先裁掉左栏(300px)与右侧节拍栏(392px)。
3. 🔴 **动画类判据不能靠截图**: offscreen QWebEngine 里 `requestAnimationFrame` 不触发 ⇒ 状态在变而两张截图
   逐像素相同(实测 mid/fin 差 0px, 差点回去改渲染)。用真浏览器的 `getElementById('vr').getContext('2d').getImageData()`
   直接读像素, 并把两个时刻的计数做**差**(见验收表「蓝像素差」那行)。

## 汇报口径

先给 段数/节拍/分流数(12+2)/每循环时长区间, 再讲每循环 25 段在干什么(特别是两个检测站), 最后点出:
① 8~14 号位的坐标是推算值, 真跑之前要补示教; ② NG 是哪两个槽位、什么原因, 都是预设的;
③ 插入深度: 模块 56.5mm 长、孔深 47mm(767→814) ⇒ 插到位后尾端露在孔外 9.5mm, 这是正常的,
   不要把模块几何中心 `(767+814)/2=790.5` 当成「孔中心 = 模块中心」。
