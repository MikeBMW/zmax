# 左臂仿真搬运 (🚚 仿真搬运): plan 节点排段表 → ar3d 播关节角

用途: 让用户看见「左臂把 N 个光模块从一个料盘搬到另一个料盘」的全过程。纯可视化仿真, 真机零指令
(不调 l2_daemon、不走 39071、不发 moveStart) —— 这是唯一能承诺「真机不动」的做法。

## 三层, 各管各的

### ① 任务层 = 状态空间工程的 plan 节点
- 唯一依据: `src/lerobot/policies/left_right/state_space/planner.py` → `TaskPlanner().plan(instruction)`
- ⚠ 路径是 `src/lerobot/policies/left_right/state_space/`, **不是** `left_right/state_space/`(那个不存在)。
  `find . -name planner.py | grep -v venvs` 一次就能定位, 别照记忆里的旧路径硬编 import。
- 未配 `llm_url` 时走确定性规则回退(零重依赖、只 import json/os), 输出 token 序列,
  实测「从左料盘逐个抓取光模块, 横移, 依次放到右侧料盘的14个槽位」→
  `[SKILL_NPO006] [SKILL_NPO011] [SKILL_NPO031] [SKILL_XPO032]`
- 🔴 规则回退把「搬运」拆成 取料→对准→插入→检测。**「插入/检测」是插装场景的动作, 搬到另一个料盘没有插入**。
  ⇒ token 只作任务层意图留证(`plan_tokens` 字段), 几何段按物理动作编排, 两者都存进产物。
  **不要拿 token 序列冒充几何路径**, 也不要在汇报里说「按 plan 节点规划的路径走的」——说清是两层。

### ② 几何层 = `tools/sim_transport_plan.py`
- 槽位从 `fences.json` 读: 名称以 `左槽` 开头 = 左侧组, `槽` = 右侧组, 取 `(p1+p2)/2` 中心
- 每个模块 8 段: 移到上方 → 降安全高度 → 降到抓取 → 抓起抬到横移高度 → 横移 → 降安全高度 → 对准 → 放下抬起
- 高度口径: `Z_CLEAR=0.35`(横移) · `Z_SAFE=0.20`(进料盘前的过渡) · `Z_GRASP=0.14`(抓/放, 模块顶面约 0.125)
- N 个模块 = N×8 段, 落盘 `zmax_data/runtime/traj/sim_transport.json`(`{at, plan_tokens, cycles, segs[], n_segs}`)
- 首段起点用 `cur or p_l_up` 时会产生零长度段, 播放端跳过即可(或初始化 cur = 左臂 home)

### ③ 播放层 = 页面按钮 + `GET /api/sim_transport`
- 后端只读 JSON, `self._json({**d, "ok": True})`; 路径用 `os.path.join(REPO, "zmax_data", ...)`
  —— ⚠ 常量名是 `REPO`(tcp_ar_server.py:46), 写 `ZMAX_DATA`/`DATA_DIR` 会 `NameError: not defined`
  而接口只回 `{ok:false, err:...}`, 页面看着就是「没有可用路径」。

## 页面实现要点 (tools/web/tcp-ar.html)

- `LARM.q`(6 关节角, 弧度) + `LARMFK=urdfFK(LARM.q)`: 左臂有自己的姿态, 不再照抄右臂 `LINKM`
- 🔴 **绘制处两处都要用 `LARMFK || LINKM`**, 缺一处就是「数据变了画面不动」:
  - 取景(近似 `drawVR` 前段): `if(typeof LARM!=='undefined' && LARM.show && VR.urdf && URDF && LINKM){ ... pts.push(...) }`
  - 实绘(后段): `if(LARM.show && URDF && LINKM){ const X=larmXform(); drawUrdf(g, pr, LARMFK || LINKM, X); }`
  实测只改取景那处时: `LARM.q` 变了、`LARMFK` 算出来了、`tool1` 坐标对了, 而两次截图**逐像素相同(差异 0px)**。
  这种症状特别像「IK 没生效」, 实际只差一个变量名。
- IK 用现成的 `ikTool1(target, q0)`(DLS 位置逆解, 末端 link = `tool1`, 迭代 ≤140, <0.5mm 收敛),
  🔴 target 必须换算到**左臂自身系** = 世界点 − `LARM.off`([0, 0.5, 0]); 直接喂世界点解出来的是右臂姿态。
- 播放器: 每段两端点各解一次 IK, 段内 6 关节线性插值; 取帧 `n=max(4, min(16, dist/0.012))`(每 12mm 一帧),
  每 2 帧 `drawVR()` 一次(`painted++ % 2`) —— 全帧重绘会把浏览器拖死。
- 🔴 **推进必须按节拍时钟, 不是按帧号**: `requestAnimationFrame` 里 `TRANS.fi++` 会在二十几秒内把
  整条节拍(1472 帧 × 60fps)跑完, 而侧栏写着每循环几秒 ⇒ 用户肉眼立刻发现"时间对不上"。
  每帧要带 `t`, 播放侧按已播秒数找帧(见下文「播放时钟」)。
- ⏳ IK 是串行预解算(112 段 × 2 ≈ 224 次, 实测约 11s): 用 `cacheKey = off.join(',') + '|' + segs.length
  + '|' + segs[0].p_from.join(',') + '|' + TACT_CYCLE` 缓存整个 frames 数组, 命中就跳过全部 IK 直接播
  (实测第二次点按钮秒开)。`LARM.off` 或节拍常数一改 key 就变, 自然失效重算; **节拍常数必须进 key**,
  否则改了 `TACT_CYCLE` 还在播旧时间轴的缓存帧。
- 帧必须带四样才能推出盘面状态: `{q, carry, k, y, seg}` —— `carry`=这一刻手里有没有(「抓起」段起 true ·
  「放下」段 35% 之后 false) · `k`=第几个模块 · `y`=当前末端世界 y(用来判"在左盘侧还是右盘侧", 阈值取两盘之间的 0.55) ·
  `seg`=**段号 `s.i`**(节拍甘特图靠它定位当前步, 见下文)。
- 播放器每帧 `TRANS.carry / TRANS.curK / TRANS.curY` 三个字段同步, 绘制侧据此推状态 —— **不需要另建状态机**。

## 模块可视化: tool1 模块头 + 两个料盘 (r32)
老倪: 「光模块呢？没看到啊；左臂也有个 tool1 模块头，你要画出来，放到左臂 tool1 的位置，与右臂一样；
料盘也要有对应的光模块，表示从左侧料盘搬运到右侧料盘」。
- 三种盒子共用一套画法(`drawModuleAt` / `drawFlatModule`), 口径与右臂 `drawModuleBox` 一致:
  **X=厚度 8.5 · Y=宽度 13.4 · Z=长度 56.5mm, 头在 tool1 原点, 体沿 Z 朝法兰退 L/2**。
- 🔴 **光模块长轴 = 世界 X 轴, 不是 Y**(用户口径: 「长度方向几乎都是与 x 轴平行的, 误差来自于料盘槽位的间隙;
  理论上都是平行于 x 轴摆放, 而且整齐放置」)。别靠眼估, 用标定反算核对: `zmax_data/ar_rs/module_calib_ref.json`
  的抓取 `quat=[w,x,y,z]=[0.728266,0.022327,0.684847,0.010713]` 换成旋转矩阵后, 第三列(tool1 的 Z=长度方向)
  = `[0.998,-0.018,0.061]` ⇒ 几乎就是世界 +X(偏 3.5°); 第一列(厚度) `[0.062,0.046,-0.997]` 朝下。
  ⇒ 料盘里躺着的模块 `56.5 沿 x · 13.4 沿 y · 8.5 沿 z`, 28 个全部 X 对齐, 槽隙的几度误差不建模。
- 左臂模块头: 位置取 `LARMFK['tool1'].t` 再按 `larmXform()` 搬到世界, **姿态固定用 `R_GRASP`**(即上面那个实测抓取姿态,
  不要把 `LARMFK['tool1'].R` 乘进去 —— 那等于让模块头跟着 IK 的腕部朝向乱转); 空手橙 `#ff8c1a` / 抓着绿 `#a3e635`。
  显示闸写 `(VR.mod || TRANS.carry)`: 搬运时不管 🔩 开关都画, 否则用户看到的还是"没有光模块"。
  同一处不要再叠一个 10px 小方块当"手里的模块"(删掉, 只留正经的长方体)。
- 料盘模块躺平在槽里: 中心 z=0.1175, 长轴沿 X; 左盘待搬 `#60a5fa` · 右盘已搬 `#34d399`。
- 🔴 **只画 12 条棱的话, 28 个长条在深底上太细, 用户直接说"看不见"** ⇒ 给顶面加半透明填充
  (`globalAlpha 0.55`, 填 sz=+1 的那 4 个角 1,3,7,5)+ 棱加粗到 1.7px; 实测左盘蓝色像素 918 → 2599。
  填充后同色像素被抗锯齿改色 ⇒ 数量判据仍只认 `TRANS.drawnL/drawnR`, 像素统计降级为旁证。
- 显示条件(左盘): `num>curK` 或 `(num==curK && !carry && !atRight)`; 右盘: `num<curK` 或 `(num==curK && !carry && atRight)`;
  `curK==0`(还没播)时左盘全显示、右盘全空。抓走即消失、放下才出现, 不用单独记"已搬几个"。
- 🔴 **颜色不能与既有元素撞**: 料盘 `#22d3ee`/`#f59e0b`、槽 `#ffd400` 都在画面上, 模块色必须挑开(实测用
  `#60a5fa`/`#34d399`), 否则开/关判据分不清是模块还是料盘框。
- `LARM.q` 要能被「↺ 跟右臂」清掉(`LARM.q=null; LARMFK=null`), 否则复位按钮对左臂失效。
- 播放中途再点 = 停(`cancelAnimationFrame`), 文案回「🚚 仿真搬运」; 走完回同文案 + tip 写「走完 N 个模块 · 真机没动」。

## 🔴 带姿态的逆解: 差分要减基准, 解不动就止损

要求「末端姿态也对齐」(如模块长度∥世界 X)时, 不要在浏览器里硬做 6 维 IK:

- **第一处必错**: 位置雅可比 `(M2.t-p)/D` 是对的, 姿态三行必须写 `(w2-eo)/D`。漏掉基准 `eo` 就成了
  "绝对值/D", 症状极隐蔽 —— 位置残差 0.00mm、姿态纹丝不动(实测连 `Rdes=单位矩阵` 都卡在 121°),
  页面也不报错。改完先跑这条自检: 解 `[0.5,0,0.30]` + 单位姿态, 必须 `mm<1 且 deg<5`。
- 修好也不等于能用: 6 轴 6 任务多解, DLS 从差初值出发会跳到别的支 —— 实测同一点三次出现 0°/121°/165°,
  还有"姿态 4° 但位置差 127mm"的解。⇒ 选解不能只比位置误差, 要用 `位置mm + 姿态deg×3` 综合代价;
  收敛后还要按 `err_deg>8°` 把次品段单独计数, 不能拿 best 冒充"全段达标"。
- **止损口径(实测可行)**: 路径仍用可靠的位置 IK(`ikTool1`, 残差 0.03mm), 姿态按物理约束固定成作图口径,
  并在汇报里明说"位置是真解出来的, 姿态是设定值"; 要腕部关节真转到目标姿态就走 MoveIt 位姿规划
  (带 IK 插件与关节限位)。别在页面里反复调 λ/步长/迭代去追 6 维数值解, 那是无底洞。

## 节拍甘特图侧栏 (r33)
老倪: 「根据左盘的操作, 在屏幕右侧, 画出节拍, 显示实际每个步骤的时间; 你来设计流程节拍, 每步都要有时间,
用甘特图这种表现, 你来设计UI, 右边栏要可以隐藏, 也可以展开」。

**时间口径(唯一算式, 以循环节拍为主参数)**: 先定 `TACT_CYCLE`(每循环秒数), 再在循环内分摊
- 🔴 **节拍必须用「每循环 N 秒」当主参数, 不许用假设的速度反推**。先用 `V=150mm/s` 算出的
  11.6s/循环、162.6s 总长被用户当场否掉: 「11.6秒不是显示的速度, 我感觉是每个模块是3秒, 就按照3秒一个」
  —— 现场对节拍有直觉, 且拿"看得见的动画"当基准; 任何自己假设的速度档都会和它打架。
  当前口径 `TACT_CYCLE = 3.0`, 14 循环 = **42.0s**; 速度是推导量, 不摆在面板上。
- 循环内 8 步按**等效位移**分摊这 N 秒: `w = 三维距离mm`(纯位移段) 或 `w = 距离mm + 120`(「抓起」「放下」段,
  夹爪动作折算 120mm 等效位移)。`w<1` 抬到 1 防零权。段时长 `t = TACT_CYCLE * w / Σw` ⇒ 每循环精确等于 N 秒。
  只用距离不含夹爪项时, 抓起/放下会被压成 0 秒(它们位移很小), 面板上看着像少了两步。
- 3.0s 摊出来实测: 移到上方 0.00(k1, 无回程)/k2~k14 更多 · 降安全高度 0.30 · 接近抓取 0.12 ·
  抓起并抬起 0.66 · 横移 0.84 · 降安全高度 0.30 · 对准右槽 0.12 · 放下并抬起 0.66 = 3.00s
- ⚠ **每行时长相同是对的, 不是 bug**: 生产节拍 = 重复同一动作, 动作量相同 ⇒ 时长必然相同。
  被问「怎么很多都是同一个秒数」时直接说"对, 因为动作量一样", 逐行给数并点明首循环缺回程段,
  **不要用平均值糊平, 更不要把它当缺陷去改**(把 k1 也强行拉到 3.00s 反而更符合现场直觉)。

**UI(我设计的版式)**
- 右侧 `position:fixed;right:0;top:0;bottom:0`, 宽 392px, 深底 `rgba(13,17,23,.975)`, 左边框 `#30363d`。
- 顶部: 「⏱ 左臂摆盘节拍」+ 右侧大字单循环节拍; 下一行汇总(循环数/总时长/设计速度/夹爪时间)。
- 主体: 每循环一行 `grid-template-columns:28px 1fr 44px` = 标签 k1..k14 · 条带 · 行末循环时长;
  条带内 8 个 `i`, `width = t/total*100%`, **下限 2%**(否则 0.00s 那步根本画不出来, 看着像缺一步)。
- 配色: 平移 `#58a6ff` · 下降/接近/对准 `#22d3ee` · 抓取/放下(含抬起) `#f59e0b`
  ⚠ 分类优先级 **抓/放 > 下降 > 抬起 > 其余**: 「抓起并抬起」「放下并抬起」都含"抬"字, 先判"抬"就全变绿,
  图例里还会留一个**永远没有段的空类目**(实测绿色只剩 73px) ⇒ 图例按实际出现的类目写。
- 折叠: 侧栏左边缘竖条钮(`left:-28px`, `border-right:none`, 圆角只留左侧) + `.hide{transform:translateX(100%)}`;
  文字随状态切 `⏱ ▸`(展开中, 点它收起) / `⏱ ◂`(已收起, 点它展开) —— **箭头指"移动方向"**, 初值要与 "默认展开" 一致。
- wrapper `pointer-events:none` + 面板 `pointer-events:auto`: 否则收起后的透明区域会吃掉画布鼠标事件。
- 每块 `title = "<label> · <秒> s"`, hover 就能读到单步时间 —— 他要的就是"每步都有时间", 别只给总数。

**播放联动**
`setInterval(160ms)` 读 `TRANS.{playing,curK,curSeg}`: 命中行加 `.on`(底色 `rgba(88,166,255,.10)` + 内描边),
命中块加 `.on`(`outline:2px solid #fff; outline-offset:-2px; filter:brightness(1.4)`)。
不做事件订阅 —— 播放器只往 `TRANS` 写字段, 面板轮询最简单也最不会漏。

**播放时钟(侧栏时间与画面一致的前提)**
- 生成 frames 时累加 `tt += segDur(seg)`, 每帧写 `t = tt + dur*(i/n)`; 收尾 `TRANS.durTotal = tt`。
- 播放循环:
  ```js
  const el = (performance.now() - TRANS.t0)/1000 * (TRANS.rate||1);
  let i = TRANS.fi; while(i < frames.length-1 && frames[i+1].t <= el) i++;
  TRANS.fi = i; applyFrame(frames[i]);      // applyFrame 里同步 curK/curSeg/curT/carry/curY
  if(el >= TRANS.durTotal){ /* 收尾: curT = durTotal, 按钮复原 */ return; }
  ```
  `TRANS.fi` 只做「不回退的搜索起点」, 不再 `TRANS.fi++`。
- 倍速 `TRANS.rate`: **默认 1×(节拍 42s 就是真实观看时长, 已经能看)**, 提供 1/2/4/10×; 切换时若正在播,
  `el = 已播节拍; TRANS.t0 = now - el/rr*1000` 重锚, 进度条不跳。
- 侧栏进度 `#tProg` = `curT.toFixed(1) + ' / ' + durTotal.toFixed(1) + 's'`, 与行高亮同一个 160ms 轮询里更新。
- 实测: `durTotal = 42.0s`(14 × 3.0); 1× 播完约 42s; 播完面板 `42.0 / 42.0s`、`curT == durTotal`、
  tip「走完 14 个模块 · 节拍 42.0s · 真机没动」; 同步自验 = 读 `curT` 与 `curK` 必须满足 `curK ≈ floor(curT/3)+1`
  (实测 17.74s 时正好 `curK=6`, 17.74÷3=5.91)。
- ⚠ 三个"速度"当场分清, 否则用户会问"到底按哪个走": ①**循环节拍** `TACT_CYCLE` 秒(唯一真参数)
  ②**播放倍速** 1/2/4/10×(只是看多快) ③**真机 5/10/50 mm/s**(『执行轨迹』下发用)。
  改节拍只改 ①, 不要动播放倍速去"凑"时长。

**验收(浏览器内取数 + 截图像素旁证)**
- DOM: `.tRow` 14 行 · `.tBar i` 112 块 · `#tCycle` 文本 `3.0 s` · `#tSum` 含 `42.0 s` · 每行 `.tT` 都是 `3.0s`。
- 高亮: 置 `TRANS.curK=3; TRANS.curSeg=21` ⇒ `.tRow.on` 1 个(data-k=3) · `.tBar i.on` 1 个(data-seg=21) ·
  `outlineColor=rgb(255,255,255)` · `filter=brightness(1.4)`。

  行高亮与块高亮要分开断言: 行对了块没对 = 段号错, 两个都 0 = 轮询没跑。
