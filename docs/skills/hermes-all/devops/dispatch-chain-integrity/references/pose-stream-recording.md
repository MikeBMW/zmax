# 真机真值流录制与取证报告口径

用于回答"刚才动了没有 / 这段数据能不能用"。结论必须由逐帧真值支撑, 不用肉眼也不要口头保证。

## 必报六项
1. **窗口与帧数**: 起止墙钟、有效帧数、实测 Hz、失败帧数。
2. **连续性**: 相邻帧间隔 >0.1s 的处数与最大间隔。只说帧数不说间隔 = 等于没验能不能用。
3. **起止位姿**: `endInRef`(m/rad) 与 `jointPos`(rad) 的 start / end / Δ, 三项一起给。
4. **交叉印证**: `flangeInBase` 的位移要与 TCP 同向同量级(差值来自工具偏移的旋转分量)。
   **不同步 = 工具偏移或坐标系口径搞错**, 不是"数据噪声"。
5. **运动结构**: 分段数、累计运动时长、TCP 路径长度(mm)、每段峰值步长。手动示教一般 50~100mm/s;
   出现单采样 ≥10mm(≈0.3m/s)的孤立跳变要单独摊开看, 别混进平均速度。
6. **模式与电源**: `operateMode`(manual/automatic) + `powerState` —— 证明采集期间是手拖还是程序在动。

## 角度必须先 unwrap
rpy 用 ±π 表示: 越过 ±π 就翻转, 直接取 max−min 会算出 **6.28rad** 的假极差(或 3.14 的假半圈)。
- 报位移用 **end − start 的 Δ**(必要时先 unwrap); 极差只用于位置三轴。
- 见到 6.28 / 3.14 先怀疑回绕, 不要写成"转了一圈/半圈"。

## 运动分段(可复现)
逐帧算 `dist(tcp_i, tcp_{i-1})`:
- 判运动: `0.3mm < step < 50mm` —— 上界用来滤掉重启/会话重连造成的整段跳变。
- 段内持续 >0.2s 才算一段; 段数与累计时长回答"他到底动了多久"。
- 路径长度 = 逐步距离累加, 与净位移一起给(净位移会掩盖来回摆动)。

## 采集链断点定位(为什么没记到)
按 **网卡/网段 → 采集进程或容器 → 桥/接口 → 落盘文件** 逆着查, 每条都给硬证据:
- 落盘文件 mtime + 最后一行 wall clock(帧龄) → 停在哪一刻;
- 容器/进程状态与其日志最后 20 行(连接失败的原文就是根因);
- `ip -br link` / `lsusb` / `ping` 判网段; 网段断时边缘机可能仍可达, 用它的只读桥当备用真值源。
- 报"不能用"必须落到**具体断点**, 不要写"可能有问题"。

## 报告措辞
- 先一句结论(记到了/没记到), 再上数字, 数字带单位与口径(`endInRef` = 产线 `/robot/tcp_pose` 同口径)。
- 明确说清这次**采到了哪几路**、缺哪几路(例如只有臂真值, 相机/画布轨迹因网段断了没有)——不要让对方以为全录了。
