# 观察窗口要「反映模型实际状态」(太阳系/3D/信号面板)

## 什么时候看这个
- 用户问「窗口上的数是模型的真实状态吗」「主参数和模型推理一致吗」
- 要给某个观察窗口设计「能否反映 L2~L5 状态」的交互
- 窗口开着但数字不动/模型停了界面不变/图表像个静态图
- 要给「主参数 M」页这类观察页加一层**结构语义**(太阳系 ↔ 流形引擎之类)
- 用户说某块「字体太小看不到 / 不要显示那么多字 / 精简」
- 用户说「太阳系所有显示禁止跳跃 / 不能有任何连线的跳跃 / 不要来回跳」
- 用户说「文字描述不要飘来漂去, 都靠右侧显示, 不要动」/「文字块在跳」
- 用户说「窗口太小 / 要能用鼠标拖拽大小 / 不方便查看」
- 用户说「某个模型运行推理时, 对应天体要有高亮/柔顺闪烁」(每个模型都要有对应关系)
- 用户说「把四元数显示在太阳系 / 状态方向 / S³ 上的姿态」
- 用户说「地球的引力箭头要大/长/粗/明显」「太阳力、行星力都是分力」「用四元数表达力场总观」
- 用户说「现在没有运行, 为什么力的方向还在变化」⇒ 铁律 7b (要冻的是**重算**, 不只是绘制)
- 用户连着说「还是太小 / 根本看不到 / 合力的小窗口太小」⇒ 不要小步加字号, 读末尾「精简的最终形态」+ 铁律 16

## 铁律 1: 视图数据必须每拍重读真源, 不能只在 __init__ 建一次
`OrbitalArchView` 曾经把 `self.data.build()` 只在构造函数里跑一次, `_tick` 只推虚线相位 ⇒
引擎在跑 (10Hz) 而屏上数字 2.5s 内一动不动, 用户看到的是「打开那一刻」的死值。
改法: `OrbitalArchData.reload()` 重读全部真源 + 视图 `QTimer(500ms)` → `refresh()`, 且
`if not self.isVisible(): return` 省主线程。代价实测: 8 份 JSON + canvas 138KB ≈ 4ms/次, 2Hz 无感;
判据要能量到"真的重读": 临时包装 `data._j` 计次 (一次 refresh 应 ≥6 次), 别只看定时器存在。

## 铁律 2: 状态按「每个实体自己的真源」算, 不许一个灯代表全部
帧龄阈值: ≤2.5s = 在跑(绿) · ≤60s = 陈旧(黄) · 更旧/无真源 = 离线(灰)。
太阳系映射的实测真源: 太阳=engine_latest+torque_live · 水星/木星/火星=engine_latest(吃同一帧位姿) ·
地球/卫星=skill_latest · 月球=skill_error。**引擎在跑 ≠ L2/L3/L4 在跑** —— 层状态单独取
`zmax_data/ss_live/layer_calls.jsonl` 末行的 ok/ms/ts (只 seek 尾部 8KB, 别整读几十 MB 日志)。
文件停写就显示陈旧/离线, 不拿旧 `ok=True` 装绿 (图注字形同理: 整条流水离线时一律 ○)。

## 铁律 3: 数据口径写在画面上, 不让人猜
扭矩 τ = M·(−∇Φ): M 来自标定 `config/calib/zmax_manifold.json`, −∇Φ 来自 potential_field **解析梯度**。
模型张量 (action/u_ff/chunk) 没进 τ 时, 标签必须写「τ源=解析势场(未接模型张量)」; 被限幅就写「已限幅(T>T_max)」。
判断"一致"要逐项核: M 是不是标定量 · τ 的梯度来源 · 模型输出走没走进 τ · 位姿 x 是不是真值 ·
层调用流水最后一帧是多久前。任一项对不上, 结论就是「两条独立链路」, 不要用「差不多」糊过去。

## 铁律 4: 想加信息先算遮挡代价 (像素判据很脆)
- 给天体标签加一行 = 块变高, 贴球底的太阳块会压住球面 ⇒ 「球色像素数」判据从 500 掉到 152 变红。
- 在右上角画四格状态带 = 正好压住「太阳→木星」那条虚线, 该线像素命中 4/18 变红。
⇒ 状态类文字放进**底部图注**(已预留高度, 不参与避让), 球体附近只留 ●/◐/○ 字形 + 一行帧龄;
   详细读数走**悬停 tooltip**(名/运行态/帧龄/该体真值/真源路径), 不往画布上加控件。

## 铁律 5: 判据红先分清「我引入的」还是「本来就红」
像素采样必须夹到图内 (`0<=y<H and 0<=x<W`): 贴边天体 (木星 x+r>宽) 会让探针 IndexError。
怀疑是既有红项时, `git stash push -- <改动文件>` 后跑同一条判据再 `git stash pop` —— 别在红项上反复改产品代码。
活真源会让像素判据**时红时绿** (几何随数据变): 连跑两三次看失败集合是否稳定, 只盯稳定红项。
差分型判据 ("两次采样文本不同 ⇒ 表格真的跟着帧走") 会给**假绿**: widget 从冻结切回在跑时,
第一次采样读的还是旧 field, 两次自然不同。要注入帧号/数值并断言**逐帧连续变化**(或单调),
否则分不清"真跟随"与"冻结→解冻的过渡"—— 旧版判据就是靠这个过渡过的, 实际数据是静态的。
反向的假红同样要防: 断言"两次 refresh 文本必须变"也靠不住 —— 表读的是 episode 的同一帧,
同帧当然同值, 数据静态时这条会随机红。判"没定格"要判**过程量**: 每次 refresh 的 `field` 对象是否重建
(`_f0 is not _f1`) + `_frozen is False` + 页头非 ⏸, 显示值只作信息打印。

## 铁律 6: 图元「画了但没画出来」的三种静默失败
顺序排查 (都无异常、无报错, 只能靠采样像素发现):
1. **坐标单位错**: 投影函数常约定平面坐标是「半径 R 的倍数」(内部再乘 R)。传像素值 ⇒ 坐标 1e5 量级,
   `drawPolygon` 画到画布外, 静默无输出。诊断: 先打图元各点的包围盒量级 (×10⁵ = 单位错), 再查函数签名。
2. **低 α 在深底上等于没画**: 深色背景上 α≤20 的填充, 采样点仍是纯底色。要"看得见的面" α ≥ ~100;
   只想做暗示就改点阵/网格。
3. **亮度跟实时量联动 ⇒ 判据跟着抖**: 拿 ‖∇Φ‖/置信度这类趋 0 的量当透明度, 谷底时图元暗到肉眼与判据都看不见。
   中心/基准图元固定亮度, 强弱改用扁率/数值/弧长表达。
采样确认法: 取几个**已知在图元内部**的点断言 ≠ 底色; 只数"非底色像素总数"会被标签/连线干扰。

## 铁律 7: "在跑"必须由控制台发布, 不能拿文件新鲜度判断
后台常驻进程 (`ss_engine_loop.py --hz 10` / `ss_fw_trace_pub.py` / `ss_skill_dispatch.py`) 会一直写
`engine_latest.json` / `torque_live.json` ⇒ 按 mtime ≤30s 判"实跑"**永远为真**: 用户没点运行,
窗口照样显示力/在转, 用户会直接问「我还没点运行, 应该没有力啊」。
正解: 控制台在 `start_sim→_start_real_sim` / `_start_state_space_sim` 里写
`zmax_data/ss_live/ui_run.json {running, ts, pid, task}`, `stop_sim` 写 false;
观察窗口与 `gravity_table.run_state()` 只认这个文件 **且 `os.kill(pid,0)` 还活着**
(崩溃/被杀 ⇒ 自动判没跑, 不留假在跑; 没有该文件 ⇒ 未运行)。
没在跑就必须真的"没有力": 不画力线 (连 ghost 透描层一起跳) · 不画自转弧 · 相位完全冻结 (ω=0, 不留惯性) ·
每体状态写"未运行" · 太阳标签只写 `M=… · 未运行 (无实时力)`, **不写 T** (写 T 等于把上一帧当实时) ·
图顶一行横幅说明"没点 ▶ 运行" · 表格头 ⏸。

### 铁律 7b: 要冻结「重算」, 不只是冻结「绘制」
只门控"画不画线"不够。派生数据 (合力/分力/四元数) 每 500ms 从 trace_live + 万有引力表重算一次,
而后台常驻引擎 10Hz 一直在写那些文件 ⇒ 用户没点运行, 照样看见力方向在转, 会直接问
「现在没有运行, 为什么力的方向还在变化?」。数据比画面更"活"本身就是 bug。四件事同批做:
1. `build()` 里**未运行就不重算**: `if self.running: _compute_quat(); _compute_earth_forces()`;
   未运行时保留上次运行的值或留空, 不许继续读新帧。
2. 力箭头 0 根 · 姿态轴不画 · S³ 面板留**空骨架**(盘在、无射线、标题「⏸ 未运行」) —— 整块消失会让布局跳。
3. **数值行也改写「未运行」**: 水星进度 / 火星 λ / 木星 η / 月球残差 都来自 engine_latest,
   它们同样跟着后台文件跳。只把太阳标签写成"未运行"是不够的, 用户看到别的行在变一样会问。
4. 动画全部停: 虚线相位 `_phase`、公转积分 `_advance`、呼吸基 `_pulse_t` 一起用 `if running` 包住。
   实测只冻相位不冻呼吸, 1.2s 内仍有 ~5% 像素在变。
判据 V1~V3: 未运行 ⇒ `_last_arrows` 为 0 根且 fE 为空 · 相隔 1.2s 两帧像素差 ≤0.5% (实测 0.32%, 阈值留余量给文字低通收敛) ·
运行后箭头 >0 且 fE 有值。
三个测试坑:
- `_last_arrows` 这类"本帧画的账"必须**进函数先清空**, 否则未运行帧读到上一帧的记录 ⇒ 假红 (报"5 根箭头")。
- `data.running = True` 会被 `build()` 重新读的 `ui_run.json` 覆盖 ⇒ 判据只能 patch 类属性
  `OrbitalArchData._ui_run = lambda self: (flag, ...)`。
- patch 要在**构造 view 之前**: 晚一步 `show()` 已经用旧分支画过一帧, 后续检查读到残留 (fE 有值、箭头 5 根)。
  同一进程里多个 check 共享这个类属性, 每个 check 都要显式重置自己那一支。

## 铁律 8: 运动必须积分, 相位不许每帧按数据重算
`相位 = f(实测量)` 的实现会让行星随数据**来回跳** (用户原话「不要来回跳, 要连续旋转」)。
正解: 每个天体一维相位 `_ph[k] += ω·dt`, 目标角速度由该层实测量定快慢 (`ω = 0.25 + 1.0·归一量`,
在跑时恒 >0), 且 `ω += (ω_tgt − ω)·min(1, dt·1.8)` 平滑加速; 没在跑 ω=0 且相位不动。
相位是 mod 2π 的: 判据算每步增量时先把跨 0 的一步折回 (+2π), 否则会误判成倒退。
另: `_geom()` 的底部留白若依赖图注行数, 数据一变行数变 ⇒ 半径 S 变 ⇒ 整张图"呼吸"。
行数加滞回 (差 ≥2 才重算), 实测两次采样标签块位移 0px。

## 铁律 8b: 连线与文字块也必须连续 (「不能有任何连线的跳跃」)
积分相位只治好了球; 剩下的"跳"全在线和字上, 四处都要低通, 缺一处用户就还能看见:
- **线的出现/消失**: `_signal_ok` 一翻就画/不画是硬切 (看着像线闪一下没了)。给每条边存 alpha 状态,
  每帧 `a += (target−a)·min(1, dt·3.2)`, `a ≤ 0.03` 才真不画, 颜色 α 乘 `a`。
  只在第一遍 (ghost 透描) 更新状态、第二遍只读 —— 一遍绘制内推进两次, 渐隐会快一倍。
- **近共线偏移**: 两条线夹角 <10° 且带间距 <6px 时把后一条沿法向推 4px, 这个 0↔4px 也是硬切 ⇒ 同样缓动 (dt·5)。
  偏移量用 `abs(o) > 0.05` 判是否施加, 别用 `if o:` (缓动残差永远非零)。
- **文字块** (仅当文字非跟着天体走不可时): 布局 target 会因避让换候选位 (甚至页边栏空槽) 而瞬移。
  位置一阶逼近**加单帧位移上限 14px** —— 纯指数逼近时 target 从画面一侧换到另一侧一步能走 160px,
  看着仍是跳 (实测 165px/帧 → 封顶后 14px/帧)。key 用**去掉状态字形后的首行**
  (`lines[0].split(" ",1)[-1]`), 否则状态一变 ●→◐/○ 就被当成新块、直接落位;
  引线按**平滑后**的块位重算 (`_lead_of[i]` 记归属球心), 不然引线跟块脱节。
  ⚠ 低通只是补救: 球在走 + 避让时不时换候选位 ⇒ 用户仍会说「文字飘来漂去」。首选**固定右栏**(铁律 10),
  文字位移恒为 0px; 只有版面确实要求标签贴球时才用这条低通。
- **跟数据走的半径**: 月球轨道半径 = f(残差) 会在残差阶跃时把月球弹出去 ⇒ 一阶低通 (dt·3), `positions()` 读平滑值。
判据 `tools/verify_orbital_nojump.py` (真 widget + 真 paint 跑 60 帧, 5 条): N1 公转相位步长 ≤0.30rad/帧 ·
N2 文字块位移 ≤22px/帧 · N3 连线透明度 ≤0.35/帧 · N4 残差 0→0.30 阶跃下月球半径 ≤0.06/帧 · N5 连线端点取得到当前球心。
注意: 量"球位位移"会被正常公转污染 (R·ω·dt 就有 10px/帧) —— 连续性要用**角步长**判, 不要用像素位移定阈值。

## 铁律 10: 文字描述固定右侧栏, 一个像素都不许动
用户口径: 「文字描述不要飘来漂去, 都靠右侧显示, 不要动」。凡是"贴着球"的标签, 无论低通多平滑都还是飘
(球在走 + 避让时不时换候选位)。根治办法是把文字区与图形区**物理分开**, 不是把动画调慢:
- `_geom()` 右侧让出固定栏宽 `_col_w(W) = min(300, max(190, 0.30·W))`, 圆心 `cx=(W-colw)/2` 左移、
  `S=min(W-colw-14, H-pad)`。文字永远压不到球 ⇒ 不需要避让 ⇒ target 恒定 ⇒ 无需平滑。
- 行序固定 (太阳→水星→地球→月球→火星→木星→SK 群), 每行**一行字**, 右边缘钉在 `W-6`,
  宽度按文字自适应 (右对齐: 左边缘随字数, 内容不变 ⇒ 位置不变)。实测块单帧位移 0.00px。
- 状态只由行首字形 ●/◐/○ 表达, 别每行重复写"未运行" (6 行同样三个字 = 噪音)。
- **归属只靠颜色, 不画引线**: 用户口径「把文字与球体的连线去掉, 太乱了; 有颜色对应就可以了」。
  引线一多就把画面糊掉 (7 行文字 = 7 条线), 颜色一一对应就够: 每行文字色直接用该天体的球体色
  (`QColor(COL[key])`), `_labels` 里不再 `drawLine`, `self._leaders` 保持空。
  ⇒ 前提是**调色板两两可区分**: 实测撞过两对 —— 水星 #b9bec7 ↔ 月球 #dfe4ec、木星 #d2a45f ↔ 太阳 #ffd166;
  改冷灰 #8d99a8 / 青铜 #c98f3c 才分得开。加新天体先比 RGB 距离再定色, 否则"颜色对应"等于没对应。
- 判据 N4 随之改成「一条引线都不许画 + 每行文字色 == 球体色」; 匹配行必须用**天体符号**
  (☀ ☿ ♁ 🌙 ♂ ♃) 而不是中文名 —— SK 行写着「8 颗绕地球」会误命中地球那一行。
- 像素判据的容差会把**天体自身的暗边**当成线色: 地月线原色 (120,132,150) 与月球球体 `darker(170)`
  的边缘 (≈131,135,139) 差 <45 ⇒ 「球心区无线色像素」误报 7~11px。改线色 (92,104,122) 收紧对比,
  不要去改球体绘制或放大容差。
- 成组标号 (SK01~SK08 这类 8 颗卫星) 不要逐颗浮标 —— 它们绕地球转 = 文字在转圈; 压成一行
  `SK01…SK08 · N 颗` 写进右栏。
判据维护: 栏化后旧契约会红, 改判据不改 UI ——
L5 ("逐颗有 SK 号文字块") 改成"8 颗都在 + 右栏标出首尾 SK 号 + 颗数";
M2 ("块宽不等") 的宽度自适应必须在**真实尺寸 1080×360** 下量: 682px 宽时右栏只剩 204px、
每行都被截到上限 ⇒ 宽度当然一样, 那是"栏太窄"不是"没自适应"。

## 铁律 11: 观察窗口要能拖拽放大, 高度必须跟宽度联动
用户口径「主参数的窗口大小要可以用鼠标拖拽大小, 现在的窗口太小, 不方便查看」。
- `QSplitter` 的 handle 默认 5px 且与底色同色 ⇒ 用户看不见也抓不到 (以为"不能拖")。
  `setHandleWidth(10)` + QSS: 常态 `#1b2430` 带左右 1px 描边, `::handle:horizontal:hover` 变 `#2f81f7`,
  `:pressed` 更亮; `setChildrenCollapsible(False)`; handle 上 `setCursor(Qt.SplitHCursor)` + tooltip 写明能拖。
- 宽度**落盘**: `zmax_data/ui_layout.json {"main_split":[w1,w2]}`, `.tmp` + `os.replace` 原子写,
  `splitterMoved` → save。恢复必须 `QTimer.singleShot(260, restore)`: 立刻 restore 会被子控件 min width
  顶回去 (实测设 [1671,1367] 实际落 [1521,1517])。窗口宽度变了按比例缩放, 右栏下限 1080, 无历史档默认 1250。
  双击 handle = 在"上次宽 / 62% 宽"之间切换 (免精确拖)。
- ⚠ 真正的坑: 视图用 `setFixedHeight(360)` 钉死时, 右栏拖宽**只是横向空出来**, 球一个像素都不放大,
  用户还是说太小。高度要跟**页宽**联动: 在 `_fit_heights()` 里
  `setFixedHeight(int(max(320, min(620, 0.34*page_w))))`, 并**删掉**之后对同一 widget 的
  `setMaximumHeight(视口−表块)` —— fixed 状态下再调 max, Qt 会把 min 一起压到 max, 视图高度直接塌掉。
  实测: 右栏 1080 → 太阳系 1050×364(地球 18px) · 1600 → 1570×541(30px) · 1900 → 1870×620(35px),
  1900 以上才出现整页滚动条 (~59px), 可以接受。
- 巨文件加方法的落点陷阱: `simulink_module.py` 有十几个 class, 用 `def _log_msg` 之类做锚点插方法
  很容易落进相邻的 dialog 类 (运行时 `AttributeError: has no attribute`)。插完先
  `grep -n '^class '` 核行号区间, 再 `getattr(cls, '新方法')` 断一次。
  另: **同名方法后定义的静默覆盖前面那个** (类体内后者赢)。加 `_arrow`/`_label`/`_tick` 这类通用名前
  先 `grep -n 'def _arrow'` 数一遍; 撞名时报 `TypeError: got an unexpected keyword argument`, 看着像签名写错,
  实际是另一个同名旧方法在生效 —— 改名 (如 `_force_arrow`) 比改签名快。

## 铁律 12: 「谁在推理」要看得见 —— 每层一个呼吸光晕 + 外扩环
用户口径: 「前馈加速模型运行 ⇒ 地球就有高亮且柔顺闪烁; 依次类推, 每个模型运行推理时都有对应关系」。
- 状态量 `_live_s[key]` = live→1 / stale→0.35 / off→0, 一阶低通 (dt·2.4); 来源是**该层自己的真源帧龄**, 不是猜。
  未点 ▶ 运行时全 0 ⇒ 画面完全静 (与铁律 7 一致: 没跑就不许动)。
- 光晕 `_infer_halo`: 画在球体**之下**, 半径 2.2r 径向渐变, alpha = 0.34·_live_s·(0.55+0.45·sin(2πt/2s));
  2s 一呼一吸 (柔顺不是闪烁), 颜色 = 该天体色 `COL[key]` (和右栏文字同色, 天然形成对应关系)。
- 外扩环 `_infer_ripple`: 画在球体**之外** (r+5 → r+18), 两环错半周期, 1.5px, alpha=(1−f)^1.7·135·_live_s ——
  半径与透明度都是时间连续函数 ⇒ "一直在算"看得出来, 又不会跳。
- 相位按 key 错开 (`abs(hash(key))%97/97`) ⇒ 六个天体不会整齐划一地闪。
- 判据别用「外圈亮度」: 流动虚线也经过这个环带, 会给**没在推理**的球造出 ~15% 假波动。用 A/B 同帧对照
  (冻结 `_phase`, 只翻 `_live_s`, 取 3 个呼吸相位的最大值比较), 或按球体颜色筛像素。

## 铁律 13: 四元数怎么显示才不撒谎
用户口径: 「将四元数显示在太阳系」(映射: 四元数=状态方向, 约束在 S³ 球面; 公转=位置, 自转=方向)。
- **两套口径别混**: 万有引力表的「力四元数」= (|F|/u_ref, Fx/u_ref, Fy/u_ref, Fz/u_ref) **故意不归一**
  (合力 = 主力 + Σ赋能力, 要能逐位对账); 太阳系显示的是它的**归一四元数 q̂ = q/‖q‖** —— 只有单位四元数
  才是 S³ 上的点, 矢量部分 = 该层合力方向。表和视图各给一套: 表给 q (对账), 视图给 q̂ (方向),
  悬停卡同时给 ‖q‖ (力度) 与平方和 (验单位)。
- 数据来源 `gravity_table.GravityField.col_resultant(layer) → _qnorm`; 模块级缓存 `_QUAT_FIELD`,
  每次 build 只 reload (~3ms)。每帧新建 GravityField 要 ~31ms, 会顶掉 500ms 刷新节奏。
- 无列合力 ⇒ 写「未算」, **不拿 (0,0,0,0) 冒充姿态** (四个 0 既不是四元数, 也不在 S³ 上)。
- 图形: 状态点 (地球) 画完整三轴 X#f85149 / Y#3fb950 / Z#4da3ff, 其余层各一根方向轴;
  **一律从球面外侧 r+1 起画** —— 三轴里那根绿轴与「动作」连线同色, 压在球面上会让"线穿球"像素判据变红。
- 诚实边界: 真机**姿态**四元数常常没有真源 (`rotation="未建模"`, `tcp_pose.rx/ry/rz=None`,
  `pose.angle=-1`)。这种情况显示「力/方向四元数」并明确告诉用户不是姿态, 不要编一个姿态糊上去;
  姿态真值接入后只换字段, UI 不动。

## 铁律 14: 「以地球为主要观察对象」= 合力粗、分力细、头尾链 + S³ 总观面板
用户口径: 「地球的引力箭头要大/长/粗/明显 —— 那是前馈加速器自己的合力(主力); 太阳力、行星力都是组成地球合力的分力」。
- 数只能从万有引力表**同一拍**拿, 不许另算一套: `_compute_earth_forces()` 取 `dominant_now()` 的行 →
  `cells[L].vec/mag/q` (四层分力) + `row.vec/mag_res` (合力) + `row.dev` (Δ主↔合) + `row.coh` (一致度)。
  缓存实例 `_QUAT_FIELD` 必须与视图共用; 判据里新建 `GravityField()` 会读到**下一拍** (数据每拍都在变) ⇒ 假红。
  对账写法: `f = OA._QUAT_FIELD; f.reload(); v.data._compute_earth_forces()` 再逐项比。
- 层级: 合力 5.4px 亮蓝 #58a6ff、分力 1.7px (**被标为主力的那层** 3.2px —— 主力是哪层由力场构造定, 见铁律 15);
  再加一条**头尾相接的虚线链**, 把分力一段段加起来正好落到合力箭头尖 —— 「合力由谁组成」不用文字解释。
  长度用**固定参考的平方根尺度** `L = arrow_max_px·√(|F|/arrow_ref_mps)` (合力再 ×1.35): 同一 |F| 永远同样长 ⇒ 跨帧可比。
  别按当帧最大值归一 (帧间不可比, 用户会问"箭头怎么忽长忽短"); 也别用线性尺度 (|F| 跨 10 倍时全线贴顶, 大小关系全丢)。
- 「S³ 力场总观」面板 (左下 214×96): 合力 + 四层分力的 q̂ **矢量部**画成方向射线 (长=|v|, 亮度=|w|),
  标题写 Δ主↔合 与一致度。这是「用四元数表达力场总观」的最小可用形式; 想要真总观要画势场等高线 +
  梯度流线 (场), 箭头只是瞬时读数, 别靠加箭头堆信息。
  比箭头更有信息量的是 **q̂ 角距矩阵**: S³ 上两四元数角距 = 2·acos|⟨q1,q2⟩|, 4×4 一眼看出哪层在拖方向。
- 右栏新增 `F合 (地球) ‖0.35 m/s‖ · Δ主↔合 14° · 一致 0.90`。**这行不写天体符号 ♁**: 判据 N4 用
  「文字色 == 球体色」核对应关系, 合力行是力色 (#58a6ff) 会被判成配色错。
- 栏高预算 = `H − 22 − 图注行数×LH` (那 22 要含起点 y=10; 只减 12 会让末行压到图注上)。间距不够先压行距,
  压到 1px 仍放不下就一定压图注。太阳系最小高 **360** (H=320 必重叠, 实测 13px)。
  实测 H=399: 10 行×14px + 3 行图注 ⇒ 末行底 323 / 图注顶 334, 刚好不压。加行、加图注前先算这个预算。
- 诚实边界: 未加权时 `main=L2` 只是**语义上的主力** (前馈直驱), 数值上四层常同量级, Δ主↔合 10~20°。
  要让主力真压过其它分力, 得改**力场构造** (铁律 15 的 `u_ff_gain`), 不是把箭头画粗 —— 画粗等于拿画面冒充数据。

- 判据 `verify_orbital_state.py` R1~R4: 合力笔宽与像素长都 > 每根分力 · 合力模长与 Δ 与表逐项一致 ·
  四层分力齐全且**主力层**比其它分力粗 · S³ 面板有墨 (≥20 点)。

## 铁律 15: 力场构造按层加权 (u_ff 增益) —— 一处生效、全程可追
用户口径: 「改力场构造（给 u_ff 加权）」= 让前馈项真的成为主力, 而不是把箭头画粗。
- 真源**只有一份** `config/calib/force_field.json`: `u_ff_gain`(α) · `arrow_ref_mps`/`arrow_max_px` · `apply_to_tau`。
  `GravityField.reload()` 每拍读 ⇒ 改文件即生效, 不用重启控制台; 别在常量里写第二份默认值。
- 加权点必须在**格子构造之后、算四元数/行合力/列合力之前** (`cells[前馈层].vec *= α`, mag 同步):
  这样格子、表、列合力、太阳系箭头、S³ 面板、悬停卡才是同一份权重。在绘制层乘系数 = 表与画面对不上, 用户一对账就露。
  实测各阶段 前馈层/其它层: α=3 → 1.7~3.1× (**转移**阶段其它层顶到 u_ref, 只剩 1.7×, 用户看着仍不够压);
  α=4 → 2.28~4.11×, 最弱也有 2.3× ⇒ 缺省 **α=4.0**, 判据按 ≥2× 卡。α 是设计参数、不是实测最优,
  报数时把两者分开说。
- 加权后**主力定义必须跟着改**: α>1 ⇒ `_main_layer()` 返回被加权的层 (前馈是主动项), α=1 回到执行收口层。
  否则表里高亮的那层不是力度最大的层。旧判据里写死主力层的 (⑥/⑦) 要同批改成"按 α 推定期望层", 不然全是假红。
- 格子 `src` 追加 `· u_ff 加权 ×α (force_field.json)`: 加权是**设计参数**, 必须能在界面上追到, 不能是暗改的数。
- 进控制回路是另一件事: `τ = M·(−∇Φ + α·u_ff)`, 开关 `apply_to_tau` **默认 false** (只改显示与表)。
  打开必须报实测 Δτ 与是否已贴 ±T_max 限幅 (限幅后 Δτ 会显得很小, 别据此说"加权没生效"); 真机通路等用户点头再开。
- u_ff 真源是 trace_live 的 **`前馈速度_*_mms`** (毫米/秒) ⇒ 必须 /1000; 该文件**没有 `_mps` 键**,
  按 `_mps` 取会静默得到 None, 表现成"加权打开了却毫无变化"。
- 想表达"力场总观"时, 角距比箭头有信息量: S³ 角距 `2·acos|⟨q1,q2⟩|` (同 q 0°, 正交 180°)。
  ⚠ 别把六对压成 9px 两行塞进面板 —— 那正是用户说的"字太小、字太多"; 画布只留一句 `∠主力↔合力 xx°`,
  六对矩阵进悬停卡。验证公式要用 (1,0,0,0) 对 (0,1,0,0); 拿点积=0.5 的半分量点去验只得到 120°, 会误判成公式错。
- 视角切换只改视觉不改数据: 左上胶囊切「地球视角」(其余天体压暗 + 箭头放大), 点击命中区与胶囊矩形共用一份坐标。
- 缺真源的分力不许编: 月球↔地球只有状态校正器**残差**, 画虚线箭 + 标「潮汐 |残差|」, 不要写成引力。
- 判据 W1~W4: 主力=加权层且力度 ≥2× 其它层 · 权重写进 src · 长度 == `Lmax·√(|F|/F_ref)`
  (**合力还要 ×1.35, 判据漏这个系数就假红**) · 胶囊可切 · 角距口径正确。

## 铁律 16: 放大字号/加卡片后, 版面必须有"占位"与"降级"
字变大、卡片变大之后, 碰撞全从几何上来 —— 光调字号不改几何, 球会掉到卡片底下、轨道会被卡片切掉。四条不变量:
1. **左下面板必须在几何里占位**: 卡片放大到 369×218 后, 实测地球 (316,293)、火星 (236,269) 直接落在卡内。
   `_geom()` 里留左侧走廊 (`gutter = 卡宽+16`), 圆心右移, 且**半径压到 "卡右缘↔右栏左缘" 能放下**
   (`R ≤ (栏左缘−卡右缘−10)/2`), 而不是只推圆心 —— 只推圆心而 R 不变, 轨道照样钻进卡里。
2. **球永远不许进右侧文字栏** (窄窗时上面两条都会失效): 最后一道硬夹 `R ≤ (W−栏宽−gutter−16)/2`。
   实测 680px 窄窗下木星曾压到第 8 行文字 (判据 K1 红)。
3. **放不下就不画, 不要硬塞**: `_s3_visible(W)` = 卡右缘到栏左缘 ≥200px 才画卡片, 否则隐藏 ——
   数仍在右栏 `q̂合/q̂主` 两行里。硬塞的结果是卡片盖住轨道、或测试尺寸下判据全红。
4. **实底卡片要裁剪自己下的元素**: 卡片改成不透明后, 先画的力箭头会被切一半 ⇒ 箭头那遍用
   `setClipRegion(QRegion(画布).subtracted(卡矩形))` 包起来。
另有三条"看着像 bug"的排版坑:
- **别给每行文字加 1px 边框**: 文字宽自适应 ⇒ 边框右缘三档不齐 (实测 1147/1140/1106)、相邻两行贴成一体。
  右对齐的纯文字才是一条干净的基准线。
- **多矢量别共用一个原点**: 5 支射线同原点时中段只差 4~8px, 糊成一束 (视觉复核直接判"分不开")。
  改成一人一格小表盘 (各自圆心 + 三角箭尖 + 盘下标签), 5 个盘在 369px 里能摆开。
- **数据里本来就同向的两个量不要画成两条不同的线**: 执行收口与调度限幅常常同向 (u_exec==u_limit),
  加权后的前馈也同向 ⇒ 表盘里三根重叠。在标签上标 `L3≡L2` 把同向说出来, 不要为了"好看"给它们加随机偏移。
- **别用 join 出来的长字符串按下标切**: `" ".join(...)` 拼出来的"L5● L4○ …"再取 `s[1]/s[4]/s[7]`
  会拼出 `L55 L4L` 这种错字 (视觉复核一眼抓到)。层名与状态各自成对存 tuple 再拼。

## 像素/几何判据的三个假红 (都实测撞过)
1. 「每条线至少 N 个采样点」: 8px 的短线 (火星↔地球) 只能采到 1 个点 ⇒ 永远红。改成「≥1 点且有墨」,
   命中率比例仍按 ≥45%, 短线不参与比例门槛。
2. 共线去重叠判据: 端点法向距会被「共用顶点」污染 (链式边共用端点必然 0px); 换成**中点**距仍会红 ——
   两条近平行线在中点附近**交叉一次**同样是 0px, 而交叉是正常画法, 不是「糊成一条」。最终口径:
   沿线段取 5 个采样 t (0.2/0.35/0.5/0.65/0.8) 的法向距取**中位数** ≥3px —— 整体重合才判红。
3. 偏移方向固定 +4px: 汇于同一顶点的两条近共线会被推向**靠近**对方的一侧, 局部贴成 0px。
   按有符号距离取"远离对方"的方向。
4. **投影≈0 时像素判据必假红**: 3D 姿态轴正对镜头时屏幕投影长≈ 0, "三轴都画了"按像素数取样只得到 1 个点。
   正解: 绘制时记几何 (`self._tri_axes=[(色,投影长)]`, 力箭头记 `(类,笔宽,像素长)`), 判据核**几何记录**
   (三轴齐 + 最长轴≥8px), 像素数只做旁证 (至少一个轴色≥3px)。力箭头"合力最粗最长"也直接比记录的笔宽/长度。
5. **窄窗下量版面会假红**: 探针/判据常在 680×900 那种测试尺寸下跑, 那里卡片本来就该降级隐藏。
   布局类判据要么披定真实尺寸 (1154×540), 要么先把降级分支算进去。

## 可复用的判据骨架 (tools/verify_orbital_state.py, 21 条全绿)
1. 7 个天体的状态帧龄与**独立复算**的源文件 mtime 一致 (±1.5s); 未运行态下文案必须是"未运行"
2. 三个阈值边界 (0.5s/10s/600s → live/stale/off)、age=None → off 且文案「无真源」
3. 层状态与 `layer_calls.jsonl` 末行逐项一致
4. 在临时目录把同一份流水的 ts 改成 现在/10s 前/600s 前 ⇒ 状态必须 live→stale→off
5. refresh 真重读 (计次) · 2.2s 内引擎 cycle/φ 变化 · 悬停六项齐 · 标签有字形 · 图注有 L2~L5 行
6. 结构映射侧: 映射行 8 组关键字齐 · 度量是真值(M/dim) · 列头 tooltip 层↔天体 · 块高含新增行
7. 运行态两分支: 未运行 ⇒ 太阳标签写"未运行 (无实时力)"且不出现 `N·m`; 在跑且 τ 仍来自解析势场 ⇒ 必须写"未接模型张量"
8. 连续性: 在跑连推 200 步 (0.06s) ⇒ 每步增量恒 >0 且 <0.09rad, 无一次倒退/跳变 (跨 0 折回后再算)
9. 门控: 没在跑 ⇒ 相位一步不动 (差 <1e-12); 计数包装 `_draw_forces` ⇒ 未运行时调用 0 次、在跑时 >0
覆盖运行态的办法: 判据里 `OrbitalArchData._ui_run = lambda self: (True/False, "判据覆盖")` + `gravity_table._RUN_OVERRIDE`,
**跑完恢复**; 测渲染能力的旧判据 (`verify_orbital_arch.py`) 必须显式钉成"在跑"分支, 否则一条线都测不到、批量变红。
这条最容易踩: 加了运行门控后, 所有"画线/虚线/线宽"判据会同时红 —— 先确认是不是门控导致, 别回去改渲染代码。
判据比产品旧时要改判据 (例: 多页签合成一个后仍断言"4 页签" ⇒ 长期红), 先读模块 docstring 的规格变更说明.

## 铁律 9: 字号按「这台屏看得见」定, 不是按 Web 习惯
本机 eDP-1 3200x2000 · DPR=1.0 · 物理 236 DPI ⇒ **Qt 里 9px 字实际只有 ~3pt**, 用户会说「字体太小了看不到」。
可读基线 (主参数 M 页第一版实测, **已被末尾「精简的最终形态」的 20px/LH27/栏宽 380 取代, 以那里为准**):
画布标签 12px · 标题 15px · 图注 11px · 行高常量 `LH=16`;
表格 表体 16px · 表头 15px · 结构映射行 12px · 页脚 14px · 右下角 ≥ 表体且**粗体** (兜底分支也要 setBold)。
字号一放大就跟三件事打架, 必须同批处理:
1. **高度预算固定** (整页 1206px, 用户不接受页内滚动): 放大文字要从小处省回来 —— 表行高 40→36、
   右下角格 124→104、页脚 3 行→2 行, 换 `viz_stack` 300→360。改完必量 `page.height()==viewport.height()`。
2. **列宽**: 16px 下 `+90.6 +10.1 +28.5 +1.6` 会撑爆 194px 列 ⇒ `_q_str` 按量级自动降小数位
   (|x|≥10 少一位, ≥100 取整); 只靠"缩字号"解决会把用户要的大字又缩回去。
3. **像素判据**: 放大球径 (×1.25) 后 "球心区无线色像素" 类判据会红 (月球线 11px 命中) ⇒ 小体
   (moon/satellite) 的半径不要跟着放大, 改完连跑两三次确认失败集合稳定。

## 精简文案时, 判据断言的字符串就是锚点 (先查再删)
用户要求「不要显示那么多字」时, 别直接删句子 —— 判据常按字面断言: `真源:` · `帧龄` · `节点映射核对` ·
`线义` 与 `青=…虚线` (同一条) · `L2~L5` · `力的相互作用` · `角度映射` · `本刻总合力` · `全表32格和` ·
`主 ` · `Δ主` · `定格` · `font-size:14px`。做法:
- 先 `grep -n "关键词" tools/verify_*.py` 找锚点, 再把图注压成 4 行短句, 每行塞 2~4 个锚点;
- 详读量 (真源路径/归一值/平方和/角度映射细则) 移进**悬停 tooltip**, 画布只留名字 + 1 行关键量;
- 保留 `_body_text()` 原样给判据用, 另加 `_body_short()` 给标签 —— 删函数会让"不截断"类判据误红;
- 判据要求与用户要求冲突时, 优先满足用户, 同时把判据断言改成新口径 (并在回复里说改了哪条判据)。

### 精简的最终形态 (被连着说三轮"字太小/字太多"之后的定稿 — 再调字体先看这里)
- 右栏 **10 行 · 20px · LH=27 · 栏宽 380**: 6 个天体各一行 (`○ ☀ 太阳·中心 M=3.64 T=44≤`), 角色名压到 **2 个字**
  (中心/接触/前馈/校正/DiT/性能); 关键量只留 1 个数, 去掉单位与"进度/请求"这类提示词。
  再 3 行: `F合 0.61 m/s · Δ主↔合 9°` / `q̂合 …` / `q̂主 …` (四元数只留**合**与**主**, 其余层进悬停) + `● SK01…SK08`。
- 图注 **3 行短句 · 14px** (11px 与 20px 正文差一一截, 必被说小), 但必须留住判据锚点: `线义` · `L2~L5` ·
  `真源` · `torque_live`; SK 行必须保住**首尾号** (`SK01…SK08`) —— 判据 L5 就断言这两个串, 压成 `SK×8` 立刻红。
- **两次"太小"就不要小步试**: 12→14→17→20 这种 +2px 递进会白白多跑三轮。听到第二次"看不清"直接跳到
  能一眼看清的档 (本机定稿 20px), 宁可同行降行数/提视图高 (0.34→0.46×页宽, 最低 520), 不再做小步试探。
- 放大后必须用 `QFontMetrics(elided=False).width(行) + 内边距 ≤ 栏宽` **逐行打印验算** (实测最宽 297px / 可用 380),
  不能只看截图。行块高 = LH+6; 行起点 y≈46 (给标题带让位), 可用高 = `H − 起点 − 底栏`, 这三个数一起改。
- 行数/字号/图注是一个预算三角: 任何一项加大都要从另两项省。改完必量"末行底 ≤ 图注顶" (实测 430 vs 452)。
