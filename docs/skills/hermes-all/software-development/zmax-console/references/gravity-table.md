# 🌍 万有引力表 (主参数 M 页 · 太阳系下面那张表)

老倪口述规格 → 落地口径。**照抄这张表前先看「标准式」和「坑」两节**, 每条都是当场踩出来的。

## 规格 (老倪口述)

> 画布右侧栏, 主参数的太阳系, 下面的参数, 不要测量 标定 诊断 配置, 只要一个标签「万有引力」,
> 列一个表格, 第一列实际对应状态空间(当前配置的元任务), 依次的列为 L2 L3 L4 L5 合力;
> 每格是一个四元数, 右下角是四元数的合力; 每一时刻**有一个**主力, 其它是赋能力, 主力高亮;
> 例: 插拔的时刻插拔技能的 L2 是主力, L3 规划的 action、L4 L5 都是赋能力。

另外两条硬要求 (老倪两次纠正的落点):

- **一格一行四个数** (「四元数不应该是 4 个数么」) —— 任何宽度都不许打省略号;
- **四个数要能直接相加对账** (「合力的实部还是 0, 这明显没有将主力加上」) —— 见「标准式」。

实现: `tools/gui/gravity_table.py` (`GravityField` 数据层 + `GravityTableWidget` 视图层), 接入
`tools/gui/model_tree.py::MasterParamMView` (页签只剩一个 `🌍 万有引力`), 判据 `tools/verify_gravity_table.py` (36 条)。

## 标准式: 力四元数 = 可逐位相加 (别改回别种编法)

**每格** `q = (w, x, y, z) = (|F|/u_ref, Fx/u_ref, Fy/u_ref, Fz/u_ref)`。w 就是归一后的力度, xyz 是方向分量。

- 行合力 = 该行四层 q **逐位相加**; 列合力 = 该列逐位相加; 右下角 = **全表所有格子**逐位相加。
  浮点精确, 判据按 1e-12 逐位核 —— 老倪会拿屏幕上的数字自己加, 加不出来就是没做完。
- 满速基准 `u_ref` = 该阶段限速 (逐帧来自 3D 面板快照), 与屏幕 HUD 同源; 不许用旧 episode 的 `u_norm0`。
- 主力↔合力夹角、一致度仍用**矢量**算 (`F_i=|F_i|·û_i`, `ΣF_i`; 一致度 `|ΣF|/Σ|F|`), 矢量 ΣF 只服务夹角/几何/残差,
  **不用它生成表上那四个数**。
- ❌ 不要用 `q=(cosθ/2, sinθ/2·û)`, `θ=π·|F|/u_ref`: 力度一满 w=cos(θ/2)=**0**, 老倪一眼看出「合力没把主力加上」;
  而且四元数靠**相乘**复合 ⇒ 四个数之间根本不相加, 按数字一加就对不上账。
- ❌ 不要用「四层四元数等权平均 (Markley)」: |F合| 恒 0、主力↔合力夹角 37~83°, 与「主力和合力相差不大」直接矛盾。
- ❌ 不要写成 `vec_to_quat(ΣF)`: w=|ΣF|/u_ref 会把方向相消的部分从 w 里扣掉, 老倪一加又对不上。
- 表上要让老倪一眼看到等式: 合力格带 `Δ主 xx°`; 页脚写 `等式: 合力 = 主力 + Σ赋能力`, 附残差 max / 夹角 max / 一致度。

## 每一格从哪来 (只许从真源算, 缺就写「未算」+ 写清缺哪个文件)

表跟**活帧**走, 正在跑的那一项直接用 3D 面板自己那双眼睛里的数 (与屏幕同一帧同一批数 ⇒ 天然同步):

| 列 | 活帧真源 (`trace_live.json`, m/s) | 含义 |
|---|---|---|
| L2 执行收口 | `动作调制_{x,y,z}_mps` | 本拍真正执行下去的 |
| L3 调度规划 | `安全边界_{x,y,z}_mps` | 过闸门后允许的量 |
| L4 认知策略 | `前馈速度_{x,y,z}_mps` | 认知层前馈 |
| L5 意图规划 | `û(动作调制方向) × |前馈速度|` | 意图只给**条件/方向**, 力度借认知前馈的实际力度 |

对照源: `reports/ss_episode_latest.npz` 逐帧 `u_exec_vec`=L2 · `u_limit_vec`=L3 · `u_ff_vec`=L4 · `prior_vec`=L5 方向。

### 与 3D 场景同步

3D 面板 (`tools/gui/ss_dreamview.py`) **自己**逐帧发布 `zmax_data/ss_live/trace_live.json` (帧/总帧/阶段/三个速度 m/s),
契约是「快照 == 屏幕上正在显示的那一帧, 换帧必写」⇒ 表读它 = 与 3D 场景同一帧, 最大滞后只有表的 0.7s 轮询。
反过来别拿 `.npz` 当同步依据: 它可能是**上一段 rollout** (帧号对得上、数据不是同一次的), 只有对照价值。

## 主力口径: 每一时刻**只有一格**

- 正在跑的那一项 ⇒ 该行 **L2 执行收口** 是主力, 其余格子全是赋能力。
- **别的行一律不高亮** (main=None): 「每行取影响力最大层」会给一屏 8 个高亮, 老倪一问就是
  「我选的是 L2, 为什么 L5 的四元数也有高亮」。影响力最大层只写进 tooltip, 不上色。
- 纯按幅值 argmax 会判错: 插入拍 `_请求_mps`(0.1417) > `_mps`(0.085) ⇒ argmax 把主力判给 L5, 与老倪口径相反。
- 主力格 = 实心琥珀底 (alpha 165) + 加粗 + 亮黄字; ★ 只在主力那一行的首列。

## 实时性 (老倪: 「运行插拔工程了, 四元数都不动」)

两层都要活, 缺一层就冻住:

1. **UI 心跳**: 只在「页面重建/切页」refresh ⇒ 进页读一拍就定格。`GravityTableWidget.__init__` 挂 `QTimer` 0.7s
   → `refresh_if_visible()` (页面不可见立即返回, 零成本)。
2. **数据跟活帧**: `trace_live.json` (秒级) + `.npz` (逐帧动作)。
   - ❌ 两个「看似实时实则常量/陈旧」的源: `skill_latest.<阶段>_mps` 是**标称速度常量** (每拍写一样);
     `chunk_latest`/`engine_latest` 可能几小时不写 (帧龄 >10000s) ⇒ 别当实时源, 只准列在帧龄行里。
3. **尺度要同源**: 隐空间先验量级 0.6 vs 动作量级 0.01 ⇒ 直接相加会让 L5 独占合力、把主↔合夹角拉到 105°。L5 只取方向。
4. **L5 力度别用「阶段限速」**: 限速是上限, 恒 ≥ 实际 ⇒ L5 的 w 恒为 1.000, 一家独占合力。用 `|前馈速度|` 与 L2/L4 同量级。
5. **取证用命令通道 `gt_dump`** (不是看图): `echo gt_dump > /tmp/zmax_nav_cmd` ⇒ 日志出
   `活帧 N · 阶段 X · 总合力 [...]` + 本刻行四层四元数与逐位相加结果。隔 8s 调两次: 帧号走而总合力不变 = 真冻住; 都变 = 实时。
6. 判据要带 **⑤g 实时性**: 两次取样活帧往前走了 ⇒ 总合力必须变 (>1e-6), 否则判失败。
7. `print(..., flush=True)`: stdout 重定向到文件是块缓冲, 命令通道的小输出会卡在缓冲里, 看着像「命令没生效」。
8. **在不在跑要单独判** (老倪: 「现在什么都没有运行, 为什么合力还在变化」): 3D 面板**自己会回放**录制的 episode
   ⇒ `trace_live` 帧龄恒 0s, 拿它当运行证据必然误判。判据 = 引擎认知块 (`engine_latest`/`chunk_latest`) mtime ≤30s。
   没在跑 ⇒ **数据定格** (页头挂 ⏸ + 活源行写「未运行 ⇒ 表定格, 判据: 引擎认知块 N 分钟前写过」), 在跑 ⇒ 照旧实时。
   **只冻数据, 不冻界面** (字号/列宽仍随宽度重排); 两分支判据 + 观测点选择见 `references/live-value-freshness.md` 第三类假当前。
   `_RUN_OVERRIDE` 是留给判据跑「在跑/没跑」两分支的开关。

## 坑

1. **窄栏省略号**: Qt 的省略阈值 = 列宽 - padding。实测侧栏 682px ⇒ 6 列各 ~98px (可用 90px)。
   `+0.24 +0.42` (11 字符) = 91px **会被打省略号** ⇒ 小数省前导 0 写成 `+.24 +.42` (84px)。
   同理 `一致度=0.64`(94px) 放不下 ⇒ 缩写 `致 0.64`; `主力 插入·L2`(90px) ⇒ `★插入·L2`(62px)。
2. **★ 不许进数值格**: ★ 走字体回退, 实际更宽 ⇒ 把一行四个数挤成省略号。★ 放首列。
3. **判据要按字宽机械核**: 单元测/视觉都会被省略号骗。用 `QFontMetrics(max(item.font(), table.font()))` 逐格逐行核, 因为
   表格字体来自 stylesheet, `item.font()` 拿到的可能是默认字体 (低估 → 假绿)。视觉子代理两轮都报「有省略号」, 机械核验 0 溢出
   (首列内容只有 28px) ⇒ **以机械核验为准**, 但要在报告里如实写清两边不一致。
4. **上下要能用鼠标调**: `addWidget(w, stretch)` 是死的, 鼠标拖不动 ⇒ 必须 `QSplitter(Qt.Vertical)`, 且
   `setChildrenCollapsible(False)` (否则一拖就拖没)、抓手 ≥ 10px + 描边 (深色底 7px 纯色看不到, 老倪会说「没有」)、
   `handle(i).setToolTip(...)`。拖过的比例落盘 (`splitterMoved` → QSettings), 但**只有人拖才写** (绑 `.activated`, 不绑 `currentIndexChanged`)。
5. **字号**: 老倪在 3068×1862 上, 10px 看不到 ⇒ 当前档位: 表体按宽度自适应 12~14px, 表头/页头/页脚 13px。字号一改就要重跑宽度核验 (见坑 1)。
   **右下角那一格单独放大**: 按该列可用宽度从 18px 往下找第一个放得下的字号 + 粗体 (实测 1072px 侧栏取到 18px, 表体 13px)。
   字号写死必踩两头: 小了老倪说「右下角的字体太小了」; 大了被 Qt 打省略号。
6. **页脚放一份保底总合力**: 表可能被窗口裁掉 ⇒ 页脚第一行固定写 `★★ 全表总合力 … · 一致度 … · 本刻主力 … ★★`,
   并把逐真源帧龄列出来, 过期项标 `⚠️ 非本刻`。
7. **打包**: `gravity_table.py` 是 M 页的静态 import, 但仍显式加进 pyinstaller `--add-data` (win `;.` / mac `:.`) ——
   与 `proj_state.py` 同一类坑, 别赌 PyInstaller 自己能分析到。
8. **改格式串必数参数**: 去掉一个 `%.2f` 却少删一个实参 ⇒ `TypeError: not all arguments converted`,
   而 refresh 里那层 try 只捕获读真源的异常 ⇒ 活控制台只显示「万有引力: 表建不起来」, 判据还可能全绿。
   ⇒ 判据第一条必须是 **⓪ 控件能建起来 (行数>0 且格子有内容)**; 再加 ⑬ 主力上色/★, 否则「画得对不对」全是空谈。
9. **宽度自适应不要用「表给大最小宽」**: M 页套在 QScrollArea 里, 表的 minWidth 只会把表撑出视口
   (右边被裁, 看着像省略号)。要么给右栏 `ModelTreeDock.setMinimumWidth(>680)`, 要么按宽度降小数位:
   `_pick_fmt()` 逐档量字宽选 (3/2/1 位小数) 并 `resizeEvent/showEvent` 后 `QTimer.singleShot(0, ...)` 重定
   (resize 当时 viewport 还是旧宽度, 不延后一拍会永久选错档)。**默认侧栏宽下必须是一行四个数**, 只有 <1000px 才允许回落 2×2。
10. **Qt 自带选中底纹会被当成第二个主力**: QTableWidget 默认给 current/selected 格画一块色 ⇒ 老倪看到「两格高亮」。
   用 `setSelectionMode(NoSelection)` 关掉 (数值靠 tooltip/页脚读), 否则任何「只剩一格高亮」的判据都是假的。
11. **右下角数字会到几十**: 全表 32 格逐位相加 ⇒ 1 位小数 (`+20.9 +2.5 -1.5`, 19 字符) 才放得下, 否则撑爆列宽打省略号; 全精度进 tooltip。
   格式档位的**样本要按表体实际量级取**, 别拿汇总格的 +20 去挑档 (会把整表降到 2×2); 汇总格单独用 1 位小数。
12. **判「有没有上色」别用 `background().color().alpha()`**: 默认 item 的 QBrush 是 NoBrush, `color()` 照样返回 alpha=255
   ⇒ 每一格都被判成「上色了」, 「全表只有一格高亮」的判据忽假忽真。用 `it.background().style() == Qt.SolidPattern` 判实心刷。
13. **控件级判据块必须落在 `QApplication` 建好之后**: 往判据脚本插新检查时锚点若在 app 创建之前 ⇒
   `QWidget: Must construct a QApplication before a QWidget`, 整套判据一条不跑 (只会看到异常栈)。加完先整脚本跑一遍数条数。
