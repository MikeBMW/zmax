# 集成层级审计 (节点级 ≠ 档位级)

## 为什么需要

用户 (老倪) 对工程真实性零容忍, 高频追问「**实际怎么执行的**」, 且明确: **节点双击自检不算接上**,
"模型/类必须被真实链路每帧调用"。所以声称"已接入"之前必须**分级取证**, 否则就是把演示当交付。

**结论公式: 组件能单步真跑 ≠ 它进了那条每帧执行链。**

🔴 **审计第一步是先定“哪套系统”**。同一个词在不同链上指不同东西，先确认现场开着的是哪个页面/端口、它读的是哪个数据源，
再选判据。实测「右臂不动」就有四套完全不同的对象: ① 仿真站的 mujoco 双臂 (看 `/state.json#truth.tcpR` + `/status.json` 的 `ok/n`)
② 可视化页的 URDF 臂 (看 `/api/tcp` 的 `age_s/stale` + 位姿桥活没活) ③ 真机珞石臂
(看 `/ctl/status` 的 `power/operation/mode` + 授权 + 位姿真值双采 mtime)
④ **同一个页面里并排的两条臂** —— 仿真臂 (`ar_cmd.json` 段表 → 页面自己的逆解，驱动力是常驻引擎)
与真机臂 (`tcp_out/latest.json` 关节角，**设计上就是静的**)。
拿错一套的判据跑一整轮，结论全是废的，而用户一眼就知道你问错了东西 —— **先花 30 秒定边界，再开工**。

🔴 **验收口径：用户在这个上下文里说「右臂/左臂」默认指 AR 页上的仿真双臂**，不是产线那台真机。
答错对象会把你带进 estop/授权/手动模式那条岔路 (那些是真机的事，与 AR 画面零关系)，现场只会回一句
「我说的是 AR场景的虚拟右臂」。判据顺序: ① `cat zmax_data/ss_live/ar_cmd.json` 两次看 `seq/elapsed_s` 是否推进 +
`systemctl is-active zmax-ss-canvas-loop` ② `curl 127.0.0.1:8797/api/ar/mode` 的 `ar_scene/fresh` +
页面状态对象 (`SSMODE`/`ARCMD`/`PLANT`，**不是** 按钮的 `onclick` —— 页面走 `addEventListener`)
③ 才是 `/api/tcp` 与真机 `/ctl/status`。
🔴 **为调试断点停常驻引擎 = 这条链立刻冻住**: `stop zmax-ss-canvas-loop/zmax-ss-engine-loop` 后
`ar_cmd.json` 停更，页面「状态空间」拨开也没数据 ⇒ 用户看到的就是「状态空间驱动的双臂不动」。
停之前先说清这个副作用，调完立刻 `start` 回去并回读 `ar_cmd.json` mtime 在跳。

🔴 **“不动”先查生产端健康，再查消费者参数**。产品输出为零/冻结时，优先看**上游是否根本没在出东西**
(`ok:false` + `n=0` + 真值字段为空)，而不是先怀疑动作数值/算法。把一个“上游没启动”报成“action 不对”，
会把用户带去看一整天的调参。

## 四级阶梯 (逐级给证据, 别跳级, 别含糊)

| 级 | 名称 | 判据 (全部可查) |
|---|---|---|
| L0 | 封装 | 文件在位: 契约/数据源/适配器/节点/自检 + 跨进程 worker (若有独立 venv) |
| L1 | 单步真跑 | 自检 A 闸通过 (拒绝零动作) + 真权重路径 chunk **非零且随观测变化**; 画布双击/右键/⏭单步真出动作 |
| L2 | **档位链** | ①注册 (`_reg("<key>")` / 工厂注册表) ②图上节点存在 **且 links 里有连线** ③**档位/能力清单里有此名** ④引擎与面板文案不再写"未接入" |
| L3 | 硬件 | 真机 IO 真实现 (不是 `NotImplementedError` 预留), 或有明确的仿真等价物 |

## L2 审计命令 (照抄, 5 步)

```bash
# ① 注册
grep -n '_reg("<key>"' tools/gui/node_logic.py
grep -rn '<key>' src/**/node_registry.py          # 其它工程的注册表
# ② 节点在位 + ③ 孤岛检查 (节点在位 ≠ 接入)
python3 -c "
import json;d=json.load(open('flows/state_space_obs.json'))
nid='ssintact'
print('节点在位:', any(n['id']==nid for n in d['nodes']))
print('连线数:', len([l for l in d['links'] if nid in (l.get('f'),l.get('t'))]))"
# ④ 档位/能力清单
grep -rn '<key>' src/lerobot/verification/capability_levels.py
# ⑤ 代码自己的诚实标注 (引擎/面板是否仍写"未接入")
grep -rn '未接入\|S3 前\|占位' tools/gui/state_space_sim_real.py
```

🔴 **查库/查连线前先避开两个假数据源**: ① 工程库**真文件**在 `data/database/zmax/zmax_engineering.db`,
仓库根目录同名文件可能是 **0 字节空壳** (build 写前者) ⇒ 查根目录会得出"没有这张表"的假结论;
`canvas_nodes` 列只有 `project_id,name,type,x,y,w,h,params` (**没有 id 列**)。
② **连线一律读 flow JSON** `src/lerobot/engineering/flows/state_space_obs.json` (`nodes[].id` + `links[]{f,t,label}`),
DB 的 `canvas_links` 行可能 `src/dst` 全 NULL (build 缺陷) —— 拿它下"没接线"的结论是假阴性。
节点参数里的 `params.source` 指向哪个源文件, 才是"这个能力有没有节点"的唯一硬证据。

**孤岛 (links 数 = 0) 是最强信号**: 节点画在图上、能被双击, 但没进任何链路。
⑤ 尤其有用 —— 好代码自己就标了"未接入引擎", 汇报前先读它, 别和它打架。

### 追"X 用在哪里"的取证顺序 (用户问一句, 你要能列全)
一个模型/能力在系统里可能被**四条路**碰到, 逐条查, 别只看一条就回答:
1. **常驻服务**: 先看 unit 的 `ExecStart` (落点/端口/是否 `--lazy`/权重目录 env) —— 这是它"在跑"的硬证据。
2. **人的入口**: 页面按钮/CLI 往往**不直连**服务, 而是经中转 (实测: 页面按钮 → 推流服务 `GET /seg?...` → `_seg_run()` 带 `write_spec=True` 转发到推理服务)。
   搜法: 以**页面的请求串**为锚 (`grep -rn '"/seg"\|/seg?'`), 顺着中转函数一路走到真正推理的那个 endpoint。
3. **画布节点**: 按节点 id 查 `nodes` + 把**每条 link 的两端与 label** 读出来 (帧从哪来 / 意图从哪来 / 输出给谁) —— 一列就可答"它吃谁、喂谁"。
4. **训练/评估入口**: 同一能力的微调/验收脚本 (教师伪标签、A/B 判据)。
🔴 **同一端口可能同时承载两个面向** (模型/硬件状态聚合 + 推理), 看到端口号就断定"没有推理调用"是假阴性 —— 先看路由表再下结论。

🔴 **实现可能在两台机器上, 注册符号要两边都 grep**: 进化/部署类组件常把代码**拷一份**到部署机
(实测: 源码在 `src/.../se3_impedance.py`, 跑的那份在另一台机的 `~/se3_gravity/se3_impedance.py`),
两份是**不同文件**。只查源码机得出"实现了", 只查部署机得出"只有进化回路在用" —— 两个都不完整。
判":没接进在役链"的唯一硬证据是**两台机器上 grep 注册符号 (`set_xxx_provider` / `Se3GravityProvider` / `_reg("key")`)
都只命中验证脚本本身**, 而常驻回路 (`ss_engine_loop.py` / `*_daemon.py`) 零引用。
两机同一份实现先比 `sha256sum`, 不相等就先对齐再谈行为。

**用户问"你是在哪里实现的 / 代码在哪"的答题格式** (他要的是可核的坐标, 不是描述):
① **文件 + 行数 + 提交号**的清单 (源码侧 · 适配层/挂载点 · 判据脚本 · 部署机目录 · systemd unit);
② 判据**当场重跑并贴数字** (`Φ 8.000e-02 → 2.000e-06` 这类), 不引用上一轮结论;
③ 台账里的分数只证明"搜索能跑", 不证明精度 —— 并且要如实指出**末代比首代更差**这种漂移;
④ 单独一行写"**没有注册进任何在役回路 / 真机力矩通道没接 / 数据是仿真**", 别让它埋在段落里。

**汇报时要分层, 不用一个模型名拍死**: 「2D 掩膜 · 单帧 3D 位姿 · 场景重建」是三层不同的东西。
实测问「它用在哪里? 是建图么?」时, 正确答法 = 先说定位 (感知原语产 2D 掩膜)、再给 3D 通路 (掩膜+深度 → 掩膜内中位深度 ⇒ **单帧**位姿, 缺深度/手眼必须如实拒答)、
最后明确"建图(走点扫描/重建)是另一条链, 它不在其中"。含糊一句"能做 3D"就是误导。

## 「X 进 Y 节点了么 / 这个话题是谁发的」—— DDS 三层核验 (顺序固定)

用户问某个量"有没有进某个节点"时, 不许凭画布连线或"看着在动"回答, 按三层走:

1. **类型字段表**: `dds/ss_types.py` 里那个 dataclass 有没有目标字段。没有 = 结构上不可能带入, 一句话结案,
   不用跑实验 (实测 `SSPlan` 只有 joints_path/tcp_path/start_joints/goal_xyz/end_err/gate_*, 无 u_ff/v_ff
   ⇒ "前馈 v_ff 没进 plan 节点"是定义级结论)。
2. **发布端填充 + 闸门**: `grep -rn 'publish("<topic>"' tools/ src/ dds/` → 读那个函数填了哪些字段、前置闸是什么;
   新旧实现并存 (`tools/zmax_dds_*.py` 与 `tools/dds/ss_daemon.py`) 时, 认主循环里被调用的那个。
3. **实时证据**: `zmax_data/dataspace/live.json` 的 `count / age_s / lamp`, 加上这条话题**上游源文件**的 mtime。
   黑灯 (count=0 / age=null) 先比上游 mtime 与闸门阈值, 再谈"节点没接"。

实测话题归属 (变了以 grep 为准):

| 话题 | 发布节点 | 上游 | 闸 |
|---|---|---|---|
| ss_action | `tools/dds/ss_daemon.py: pub_action()` (主循环 1219 行) | `zmax_data/ss_live/proposal_*.jsonl` 末行 (infer-8790 产物) | 源龄 > `STALE_S=5s` 直接不发 |
| ss_state | 同文件 `pub_state()` | `zmax_data/ss_live/state_*.json` | 同上 STALE_S |
| ss_plan | 同文件 `pub_plan()` | `~/zmax_moveit_plan` 里 moveit_plan_live 追加行 (容器没起 ⇒ 目录都不存在) | 同源闸: FK vs 真机 TCP ≤5mm |
| ss_engine / skill_* | `ss_engine_loop.py` / `ss_skill_dispatch.py` | 引擎回路 / 技能库 | 设计 Hz |

**"在动"要落到消费者才叫进链**: 前馈 `u_ff`(v_ff) 的消费方是 `cognition.decide(u_ff, u_fb)` → 阶段限速/安全边界 →
`ss_action`; 与 plan 节点 (MoveIt 只规划不执行) 是两条线。回答时把"显示链通 / 执行链通"分开报, 别用一个话题名拍死。

## 四档一次跑通取证 (`run_all_models.py --caps l2,l3,l4,l5`)

用户问「**所有层模型可以跑通了么**」时的硬证据 = 逐档真跑 + 逐档调用计数, 不是读代码说有接线:

```bash
./gui-venv311/bin/python tools/run_all_models.py --caps l2,l3,l4,l5 --steps 20 --seed 104
# 证据落盘 reports/run_all_models_<ts>.json
```

汇总表每档给五列: 终点mm · YOLO帧/检出 · MLP真身 · INTACT真推理 · 墙钟s。读法固定:

- **每帧真推理**看 `YOLO帧/检出`: 帧数 == 步数 (20 步 = 20 帧), 检出/帧 ≈ 目标数。
- **只有 L4 档该有两列非零**: `MLP真身` 与 `INTACT真推理` 都 **== 步数** (20/20) 才算每步真调;
  少于步数就是有步被守卫拦了, 要查 `_intact_stats.gate_pass/refused`。
- **L2/L3/L5 那两列 = 0 是正常** (`CAP_ENV` 里这三档没 set `SS_INTACT/SS_USE_MLP`),
  别把 0 报成"失败", 也别把 L4 的 20 反推成"四层都在跑"。
- `done=False` 在 20 步属正常 (完整任务约 150 步), 报口径要写清步数, 不说"没跑通"。

🔴 **四档同时报同一个 FileNotFoundError ⇒ 先验路径常量, 别逐个档查逻辑**。
实测: `runtime.py` 的 `_REPO = dirname(__file__) + "../.."` 算出 `<repo>/src` (应为 `<repo>`),
于是 `_yolo_dir = _REPO + "src/lerobot/..."` 拼成 `<repo>/src/src/lerobot/...`, 四档 100% 挂。
判据: 报错路径里出现**重复段** (`src/src` · `tools/tools`) ⇒ 100% 是 `..` 层数算错, 与各档逻辑无关。
修法: 从 `__file__` 数清层级 (`<repo>/src/lerobot/engine/runtime.py` → `<repo>` 是**三级**),
并确认该常量下挂的**所有**资源都在同一层 —— `runs/` `outputs/` `src/` 都在仓库根才成立;
只对得上其中几个就说明不能靠改层数, 要改成按包 `__path__` 定位。

## 回答模板 (老倪认这种结构)

> 「节点级已集成: 注册 / 单步真跑 / 防假闸 三项都有实测 (贴数字)。
> 档位级**还没接**: 工程图 0 连线、能力清单无此名、面板明写"未接入引擎"、IO 只到 Sim。
> 差的正是 S3 适配。」

**禁止**一句"接上了"或"已经集成"。分级的答案才既诚实又可执行。

## 假接入的常见形态 (审计时逐个排)

1. 节点在图上但 **0 连线** → 画上去了没接线。
2. 注册了但**档位/能力清单里没有** → L4 档 ▶运行/单步永远不会调它 (只有双击才跑)。
3. 引擎/面板写着"未接入", 汇报却说"已接入" → 直接自相矛盾, 以代码为准。
4. IO 是 `NotImplementedError` 预留, 却称"输出直连硬件"。
5. 自检只测**形状/有限性** → 全零 chunk 也算通过 (必须有"非零 + 非常量 + 随观测变化"判据 + 零动作硬闸)。
6. 输入是**合成/占位数据** (npz 无渲染帧 → 造运动序列) 却当成真实感知。
7. 用**占位数值**冒充真实输出 (写死 conf 0.99 / 抄真值当检测结果) —— 老倪红线第一条。
8. **接口开着但没人调 (0 客户端的孤立服务/action)**: 服务端在、类型对、名字能列出来 —— 但**没有任何调用方**。
   实测 MoveIt 的 `/move_action` (moveit_msgs/action/MoveGroup) 与 `/execute_trajectory` 都挂着服务端，
   而 `Action clients` 均为 **0** ⇒ 这条出口是空跑的；真正的规划输出走的是 JSON 文件 + DDS 镜像。
   查法: `ros2 action list -t --include-hidden-topics` → `ros2 action info <名>` (看 clients/servers 计数)。
   ⇒ 报口径时三样都要给: **接口在哪 · 谁在真跑 · 哪条只是留着的出口**; 只说"action 有输出"就是把旁路当主线。
9. **数字/参数/能力 的"假在线" (在盘上、在跑, 却不在任何界面里)**: 真源 JSON 在盘上、站台页/技能真在用, 但从没被参数注册表扫到 ⇒ 用户在参数中心
   找不到那个数字, 得下的结论是"**没接**", 不是"没有这个参数"; 反之接进了注册表却不给 `fn_ref` ⇒
   数字→功能链动自链成参数名, 看着链上了其实点开没信息。两者都是接入层缺陷, 不是数据缺失。
   **同一个形态在能力/模型层更隐蔽**: 权重在盘上、systemd 服务 active、画布上有节点且 5 条连线、页面有按钮 ——
   但**不在界面共同读取的那份清单里** (实测 `tools/model_inventory.py` 按层 glob 固定目录收集, 不在那些目录的能力就不进清单)
   ⇒ 配置通道 / 配置中心 / 状态窗**三处一起看不见它**, 直到用户一问"还有个 X 呢"才露。
   查法: 先把"界面读哪几个真源"列出来, 再拿**磁盘 + 在跑服务 + 画布节点**三面去对; 漏了就把能力**补登记在清单侧**,
   别在三个界面上各打一块补丁 (补了还是会各自漂移)。

12. **"看得见在动" ≠ "驱动了执行器" (可视化链完整, 执行链断在出口)**: 力/动作/策略输出**有值、在刷新、
   还进了波形与表格**, 但它的消费者只有显示层/文件/DDS 话题/共享内存 —— 没有任何进程把它变成执行器指令。
   判据三问, 按顺序答: ① **谁产出** (真源文件/话题) ② **谁消费** (grep 该文件/话题的读者, 是否只有画布/报表/探针;
   再 grep 执行器侧有没有读它) ③ **末端真值有没有动** (执行器侧位姿/状态的 mtime 与帧龄 —— 停更几小时就是没被驱动)。
   佐证常直接写在源码注释里 (实测技能派发器明写"不下发任何真机指令") ⇒ 汇报前先读它, 别和它打架。
   报口径必须分两条链: **显示链通 · 执行链断**(断在哪一环、缺什么、要接上去还差什么前置条件),
   不许把"信号在动"说成"机器人在动"。

13. **算出来的覆盖值被下一句无条件赋值抹掉 (opt-in 分支 = 假接入)**: 组件声明了 opt-in 字段
    (例: 技能 `"atomic": "SK03Descend"` ⇒ 目标该由技能口给), 代码里确实调了那层算出目标、还打了成功日志,
    但紧接着一行 `t = list(pts[name]["pos"])` **无条件**覆盖 ⇒ 声明了等于没声明; 更坏的是成功日志与
    "退回原点位解析"警告**同时**打印(success 分支没 return/else) ⇒ 日志看着像"两条路都走过", 只有数字能拆穿。
    判定法: 绕开 GUI/日志, **直接 import 那层函数比输出** —— 期望 = 点位 + 声明偏置, 实测 = 点位本身 ⇒ 被覆盖。
    修法: 用 `_hit` 标志 + `if not _hit:` 落回默认, 成功/失败日志放互斥分支。
    推广: 任何"先按新规则算、再按旧规则兜底"的写法, 兜底那一行必须**条件化**; 否则新规则永远是死代码。
14. **`--auto` / `--watch` 只在启动时解一次源 (daemon 假跟随)**: 常驻 watcher 在进循环**之前**读一次配置
    (实测读闸门文件里的当前段), 之后每拍只刷真值 ⇒ 源变了目标不跟, 输出文件里永远写着启动那一刻的段。
    判定法: 改源文件后 3 拍内输出必须变(不是"重启后才对")。修法: 每拍重解 + 值变了重算并打一行切换日志。
    推广: 任何带 `--auto/--follow/--from-<源>` 的常驻进程, 都要问一句"它每拍真的重读源么"。

15. **判据在函数上绿、界面在另一条取数点上红 (假绿)**: 给某张表的取数函数加了过滤就断言"页面只剩 L2",
    而控件实际填充走的是**另一个**取数点 ⇒ 判据全绿、用户屏幕上仍是全层。**判据要读控件渲染出来的行**
    (`item(r,c).text()` / `topLevelItem(j).text(0)`), 或对在役窗口截图 + OCR 交叉验证; 只断言函数返回值等于没验界面。
    推广: 一个"只保留 X"的口径, 先 `grep -n 'setRowCount\|addTopLevelItem\|insertRow'` 把所有填充点列全,
    逐个确认它取的是过滤后的数据; 面板上的分组统计 ("L5 12 · L4 30 · L3 6") 与按钮上的计数也要一起改,
    否则用户第一眼看到的还是别的层。

16. **改完还要读同一窗口的状态条与告警条**: 表对了不代表面板对了。实测 `SK 位姿全无值` 的 fail 级告警在源没跑时
    属于正常态, 用户会当故障读 ⇒ 正常态降级成 info 或只在技能在跑时判; 汇报时说明这是"源未运行"而非缺陷。
17. **显示层把「缓存/轨迹里的数」当成「本次运行输出」**: 表/图上每一层都有非零的力/动作值, 但当时只跑了一层 ——
   那些数是录制 episode 里的数组 (`u_ff_vec` / `u_limit_vec` / `prior_vec` …) 按帧号取出来的, 与本次调用无关。
   最硬的反证: 该层的**调用台账** (每层 ok/耗时的那份 jsonl) 帧龄几十小时, 而面板还在动 ⇒ 显示的不是调用证据。
   修法三段 (缺一段就还是假接入):
   ① **运行态与能力档位写进同一份 run 真源** (如 `ui_run.json` 里同时有 `running` 与 `cap_level`, 档位取画布档位节点而非默认值);
   ② **每个显示层按档位闸**: 档位 = 跑到第几层 (L2 < L3 < L4 < L5), 未启用的层格子置空并写明
      「缺 L4: 本次未调用 (档位 L2)」, 不许留旧数; 合力量随之只剩启用层;
   ③ **主力/高亮层随档位回落**: 加权系数让 L4 当主力, 但档位没跑到 L4 ⇒ 主力必须是 L2, 箭头/表盘/四元数行一起改,
      不许出现「表说主力是 L4, 图里只有 L2 一条力」。
   顺带把口径名字也改: 叫「势场分解」就别让人读成「这次真跑出来的输出」。

19. **分层力/四元数: 每层读它自己的模型输出, 不是一套解析场换四个名字**。用户给的分层口径是
   L2=前馈 u_ff · L3=动作头 action · L4=流形引擎张量 · L5=VL 场景理解 ⇒ 实现上**每层一个取数路径 + 一条 src 字符串**
   (写明 `文件.字段[帧号]`), 表/图/悬停卡都显示 src, "哪层真在算"才能逐格对账。三条硬规矩:
   ① **缺层不许回填**: 某层真源取不到 ⇒ 该格 `mag=None` + `src="缺 L5: <具体缺什么>"`, 不许留上一段 episode 的数组。
      实现顺序也要对: **先铺回退源 → 再叠权威源 → 最后把缺的层显式清空**; 反过来就会出现"标着缺、数还在"
      (典型 bug: 只对 `vec is not None` 的层 `cells.update()`, 缺的层就保留了回退值)。
   ② **权重与单位换算放配置文件** (`config/calib/<层>.json`: w / k / m_ref), 热生效; 加权在**矢量层**做一次,
      表/箭头/S³ 面板共用同一份结果 —— 别在四个绘制点各乘一次 (口径一定漂)。
   ③ **主力 = 最终显示值的模长最大那层** (前馈默认最重), 要能给出算术; 用户问"这层凭什么是主力"时, 答数字与权重, 不答字母。
      🔴 **选主力与画格子必须是同一份数**: 实测两套口径并存 —— 主力取 `layer_forces()` 里加权后的 argmax,
      而格子 `mag` 又是过完 `|F|=G·M/r²` 重算的值 ⇒ 高亮落在 L3、数字最大却在 L2, 用户一句"高亮跟数对不上"就穿。
      修法 = 在**最终格子上** argmax 再高亮, 构造意图 (α / 权重) 只留痕不覆盖数值; 判据也改成断言这条同源关系。
      判据脚本里同名标签 (两条都叫 W1) 会让报告认错对象 —— 同轮就把后来那条改名 (`W1b`)。
   四元数是**显示编码** (`q=(|F|/u_ref, Fx/u_ref, …)` 不归一; 归一后才是 S³ 上的方向), 汇报里别把它说成姿态或模型张量;
   姿态没有真源时明说"显示的是力/方向四元数"。
   ④ 🔴 **"复制层"判据 = 原始矢量逐位比例恒等于同一个常数**: 某层自称独立张量 (如 `F_L4 = M̂·u_ff`),
      就把它与源层的**原始矢量**(未加权) 逐分量相除 —— 比值全等于同一个数 (实测 `[0.55,0.55,0.55]` ≡ w_L4、
      原始模长 0.017583 与源层完全相同) ⇒ 它只是源层乘常数, **没有独立信息量**, 界面上写着"某引擎力"就名不副实。
      最常见根因: `M̂ = metric_M / m_ref` 而这两个量读的是**同一个配置常量** ⇒ 恒等于 1.0; 且 `metric_M`
      来自 `config/calib/*.json` 而不是引擎现算。修法二选一: 让该层真出张量, 或在格子/悬停卡写
      "= 前馈×1.0 (M̂≡1, 未独立)" —— 两个都不做就是把加权系数当物理层。
   ⑤ 🔴 **三层字段一眼判"真不真", 汇报按这四项分开说**: ① 每层 `src` 里的 `文件.字段` + 该文件 mtime/`fresh`
      (帧龄 16h 的层还在参与合力 = 陈旧数冒充实时, 属"缺层"性质, 要剔出合力或显式标注, 不许参与 argmax);
      🔴 **`age_s` 不许在取数函数里被硬编码成 `None`** —— 那样页脚永远不显示帧龄, "陈旧"在界面上完全不可见
      (实测: L5 源 16.1h、`fresh=False`、值照旧参与合力, 而显示层的 `age_s` 被写死 `None`)。
      判据 = 取数回**真** `age_s`(`now - 源 mtime`), 超 `max_age_s` 即清空该层并标「缺 Lx: 源陈旧 N h」(同 #19①);
      ② 度量/张量类看 `model_tensor` / `tensor_src` —— 为 None ⇒ 没有模型张量参与, 数是配置常量造的;
      ③ "模型跑了" ≠ "吃的是实时": `provider=traj` + `source="真实 episode …npz"` ⇒ 每拍**真前向**但输入是
      **录制回放**的观测; ④ 每层调用台账的 mtime (=最后真调用时刻), 几百 MB 的台账停更几天就是"这栏不是今天的"。
      正确口径 = 「L2 真模型真算 · L3 真算 · L4 是 L2 的复制 · L5 陈旧 N 小时 · 输入是回放而非现场」,
      不许用一句"是真实力"或"都是假的"拍死整块面板。

20. **改了语义, 判据里写死的旧语义会集体假红/假绿 —— 同一轮一起改**。换口径后必然有判据仍假设旧世界
   (实例: "α>1 ⇒ 主力 L4"、"火星不该亮因为没推理"、"四层永远都有值"、"两个窗口各读一次必须逐位相等")。
   三条处理: ① 每条红先问"是回归还是判据的旧世界", 拿 `git stash`/旧 rev 对照再动手;
   ② 假设失效的**换目标/换断言** (L5 无真源 ⇒ 断言"要么有值、要么明确标缺"), 不是放宽阈值;
      同理, **模型体检类判据 (画面/状态敏感度) 单独成条, 该红就红着报**: 图像余弦实测 0.998 时把线从 0.995 抬到 0.99 换绿,
      等于把"欠训练"包装成"图像支路生效"; 正确结论是「接线全绿 · 该权重画面盲 ⇒ 图像那条路换回 INTACT 或重训」。
   ③ 跨窗口一致性判据改容差或共读快照 —— 两处各自 reload 必然差一拍 (实测方向余弦差 ~0.05), 让两边读同一实例才谈逐位相等。
   改完在汇报里点名哪几条判据换了口径、为什么换。

18. **门控只加在「画」上, 没加在「算」上 (未运行仍有力方向变化)**: 未运行时代码 `return` 掉绘制, 但数据对象
   每拍仍在重算 (后台 10Hz 的引擎/回放文件一直写), 于是表里的数、下一个消费者拿到的缓存仍在变;
   相位/虚线流动/呼吸也照常在 `_tick` 里推进 ⇒ 画面「静止」只是没画箭头而已。
   判据: ① 未运行时该对象的重算入口必须整段跳过 (保留上次值并标「未运行/⏸ 定格」), 不是只跳绘制;
   ② 两帧像素差留收敛容差 (文字块低通收敛 0.3% 属正常, 阈值取 0.5%); ③ 运行后同一判据反向必须变。
   三处都要有: 力/数值 · 姿态轴/表盘 · 动画相位。

22. **"有线但没跑" / "跑了但没读到" —— 拓扑、调度、消费代码三层各自都能断**: 用户要"把 A 真的接进 B"时,
    只加一条连线就交 ⇒ 三成假接入里最容易中的两种:
    ① **调度断**: 连线在拓扑里, 但常驻循环只跑白名单节点 (`ZMAX_CANVAS_ONLY=...`) ⇒ B 那一拍根本没 step,
       现象是"图上连着、下游一点都不认";
    ② **消费断**: B 的外壳 `compute()` 先 `if not PURE: return _passthrough(ctx)` 才轮到实现 ⇒
       实现里读 `ctx['in1']` 永远读不到, 日志/轨迹只显示"直通"。
    取证三样一起看 (缺一样就不能说接上了): `canvas_loop.json` 的 `only/n_ran/traces[].status` ·
    下游落盘产物的 `age` · 消费端自报的"驱动源"字段 (例: 页面 `ARCMD.drv` 变成下游节点名)。
    反向证据同样要给: 边界没越 — 如仍在"真机零指令"时下发 FIFO 的 mtime 未变、授权开关未被代写。
    具体接线与消费代码的落法见 `state-space-canvas-engineering` 的"让 A 真的喂 B = 三件套"。

24. **层计数器只记 `ok/src/ms` ⇒ "跑起来了"不等于"检出了"**: 检测层 0 检出时 `ok=True` 照样成立,
    拿它汇报"L2 已接入并在检测"是假证。判据必须落到**条数**: 把 `len(det)` 同时写进 trace 和一份
    外发 json (`/dev/shm/<layer>_det.json`), 0 就是 0。合格口径是一次给两样:
    `n=1 · 帧龄 0.1s · 权重名`; 只有 `ok=True` 单列不算。外发那份顺带解决第二件事 ——
    下游画布节点**复用这次推理**即可, 不必 `PURE=True` 自己再加载一份权重 (8G 显存里两份模型互挤)。

🔴 **判"接口/节点不存在"之前先核 ROS 域**：域不对会让存在的实体**全部凭空消失** (假阴性)。
实测同一个容器里 `ROS_DOMAIN_ID=42`，在默认域 0 下扫也是"空"，结论"没有 action"完全错。
凡是要下"不存在/没接"的结论，先 `echo $ROS_DOMAIN_ID` 对齐域；**action 类话题还默认隐藏，
必须加 `--include-hidden-topics`**，否则拿 `ros2 topic list` 的反面结论同样不可信。

21. **占位节点回显参数 = 最隐蔽的假接入**: 节点把 `d_z1/d_z2/d_z3` 当结果打印出来 (`H-JEPA: z₁=… z₂=…`)
   并 `return True` ⇒ 画布永远绿、日志永远有值, 但**一个权重都没加载、一次前向都没跑**。它的兄弟节点 (`zFlow`/`CrossAttn`)
   往往是同一写法, 所以"同组都绿"不是证据。判定只看函数体有没有 `torch.load`/权重路径/前向调用, 不看 return 文案。
   另: **节点参数里的维度是那一版训练脚本的值, 以权重为准** (实测节点写 128/128/64, 反推权重是 256/256/128)。
   修法三档降级: ①引擎在跑 ⇒ 回读引擎那一路的真值 ②否则自己加载权重跑一次 ③都没有 ⇒ `return False` + 写明缺什么。
   裸权重 (无对应训练脚本) 怎么反推结构、怎么体检、怎么接成潜通道: `references/weights-without-source-and-latent-channel.md`。

23. **同一能力有两个载体: 画布节点是壳, 真推理在常驻服务的内置 worker**。用户问"X 节点真的接入这个场景了么",
   三样一起答, 别只查一边:
   ① **画布节点**: `PURE=False` ⇒ `compute()` 只 `_passthrough`; 再加不在 `ZMAX_CANVAS_ONLY` 白名单 ⇒ 既不推理也不在链上。
   此时连线齐全是**声明**, 不是数据流 (节点入端口的源节点也不在白名单 ⇒ 端口上没值)。
   ② **真载体**: `grep -n 'Thread(target=_\w*worker'` 找常驻服务里起的后台线程; 取证两件 =
   **落盘 Hz**(对产物 `st_mtime` 每 0.1s 采样 10~15s 数变化) + **`py-spy dump --pid <svc> | grep <worker>` 抓到栈**。
   🔴 线程名不可靠: `/proc/<pid>/task/*/comm` 常全是 `python`, 拿它"没看到 worker 线程"下结论是假阴性。
   ③ **权重与页面取数点**: `readlink -f models/<在役权量>` 看清是哪一版权重; 页面 fetch 的那个 `/api/...`
   回读 `ok / age_s / stale / err` —— `ok=false` 且 err 写"没检出"时, 链是通的、模型是漏检, 两件事分开报。
   结论句: 「X 在场景里真跑(Hz + 栈 + 权重), 但**不是**画布那个节点在跑 —— 节点是壳」; 不许用"节点已接入"糊过去。
   要把壳改成真接入时 **别 `PURE=True` 自己再加载一份权重** (8G 显存要抢、相机 UVC 单占要 EBUSY):
   让实现**复用 worker 的产物文件**, 再 `PURE=True` + 加白名单 + 输出端口接下游, 这样节点上是真数据且不重复推理。

25. **恒等函数/空转节点: 占着位置不干活, 但删不得**: `def execute(self, u): return np.asarray(u)` 这类
    "看着在链路上"的一环, 实测进→出逐位相同、直接调连对象都是同一个(没做任何处理)。它不产生语义, 却常撑着四处引用:
    画布 `params.source_symbol`(右键打开源代码锚点) · `_EXTERNAL_LOC[<key>]` · 验证判据(名字往往就叫
    `t_act_pass`/指令透传) · registry docstring。直接删 = 锚点悬空 + 判据红 + 画布参数指向不存在的符号。
    处置: **不删, 让它干真活, 但先保证数值零回归**(零回归就不需要对照实验)。执行器类缺的正是它本该做的事:
    ① NaN/Inf 拦截(脏数归零 + `valid=False`) ② 通道范围**只记不裁**(裁剪权留在上游安全边界, 不越权)
    ③ 变化率超限(`|u−u_prev|>rate` 记为异常信号, 不是误差)。
    三条纪律: (a) **NaN 归零后不要再算变化率** —— 否则"归零"本身会被误报成轴跳变;
    (b) 校验结论必须进返回值/日志(如 `out1.exec_check`), 只写进实例属性等于没做;
    (c) 验零回归用**原有判据重跑**(它本来只断言 shape+finite), 不许把数值改动混进来。
    一句话: 空壳的价值在"接口位", 不在"恒等式" —— 要么给它物理意义, 要么删掉并同步四处锚点; 两者都不做是最坏的。

26. **动态加载的模块断点不绑定 (断点不停≠代码没跑)**: 加载器必须 `spec_from_file_location` +
    `module_from_spec` + `exec_module` **并注册 `sys.modules`** —— pydevd 按模块名回查文件来绑断点,
    不注册则**该文件里所有断点全废**, 而函数照跑、日志照打、界面不报错。判据一行:
    `mod.__spec__ is not None and mod.__name__ in sys.modules`。
    🔴 `exec(compile(...))` 造的模块 `__spec__/__loader__` 都是 None: **首次**按 co_filename 能绑,
    **取消断点再添加就静默失效**(pydevd 要靠 loader 重新定位文件) ⇒ exec 只能当降级路径且必须打可读告警。
    🔴 **一个仓库里常有多个加载器**: 引擎侧 `_load()` 修好了不代表节点侧 `_ss_import()` 也修了;
    更隐蔽的是某个被 spec 加载的**单个文件**漏了注册(实测流形引擎两处加载器都没注册, 该文件断点全废),
    而旁边的模块一直有注册 ⇒ 只按“加载方式”抽查会漏。
    `grep -rn "spec_from_file_location\|exec(compile" src/ tools/` 全列, 逐个确认有 `sys.modules[名] = 模块`。
    第二层原因同在: 同一文件名在 `src/` · `external/` · `staging_*/` 下可能有 **3 份副本**, 断点打在副本上
    永远不命中 ⇒ 先 `find . -name <file>.py` 列出全部, 用 `fn.__code__.co_filename == os.path.realpath(真身)`
    逐字比对, 并确认模块 `__spec__ is None`(exec 加载)。
    第三层: **三套入口的断点位置不同**, 各打一个就能看出用户走的是哪条链:
    ① `▶运行(真实化)` 走引擎 `RealStateSpaceSim` → 打 `engine/runtime.py` 的**调用点**;
    ② GUI 右键「运行节点」→ `_state_space_run_node` → `node_logic.execute_node_logic` → 注册函数,
    这条是**真调用** (打 `nodes/*_impl.py` 的 `run(ctx)` 能停);
    ③ GUI `⏭单步` **不重新调用节点函数** —— 它先 `_ss_ensure_trace()` 跑完整条引擎轨迹(有缓存,
    `force=False` 时直接复用), 之后逐节点只打印轨迹里该节点的 I/O 快照 ⇒ 在 `run()` 里打断点、点 ⏭单步
    可能一次都不停, **别据此判“代码没跑到”**; 要真跑要么点右键运行节点、要么 `_ss_ensure_trace(force=True)`;
    ④ 常驻循环/无头探针走中间件 `prj.step(only=[...])`, 那才是真 step 节点壳。
    🔴 GUI 右键那条把 `execute_node_logic` 包在 `try/except: pass` 里 —— 节点实现抛异常时界面**零提示**,
    “点了没反应”先给这个 except 加一行可读日志, 不然会在“断点是不是没绑”上白转几轮。
    🔴 **第四层 (最便宜, 先查): env 根本没进进程**。
    `tr '\0' '\n' < /proc/<调试进程pid>/environ | grep -E 'ZMAX_|OMP_|TORCH_'` 为空
    ⇒ launch.json 的 `env` 没生效(编辑器用缓存旧配置), 一切靠 env 的断点开关一次都没打开 ——
    此时“断点不进”与代码路径、加载器全都无关。修 = `Developer: Reload Window` + 重启调试;
    别靠读 launch.json 文件“确认已配置”, 文件对 ≠ 进程里有。同层还有一条: `ps -o lstart= -p <pid>`
    与改过的文件 `stat -c %y` 比 —— 进程早于改码就是跑旧代码(Python 不热加载)。
    🔴 **不要用代码内置断点做兜底**(内置 `brk(tag)` 命中就调 `breakpoint()`): 它会和用户自己打的红点抢,
    而且停住时 **Qt 事件循环停转** (py-sty 现场 `wait → _do_wait_suspend`) ⇒ 画布点不动、**新断点也点不了**,
    用户只能先杀进程。用户明确要求“不要干扰我 debug”——已经埋进去的要**全部删除**,
    光把默认改成“只记录不停”不够(日志还在刷就等于还在干扰)。要单步看变量用**独立命令行 pdb 入口**
    (`python -m pdb -c "b <file>:<line>" -c c tools/dbg_x.py <节点id>`), 不碰 GUI 进程、不影响已打的断点。
    🔴 **断点能不能停, 按这四层从上到下排**(任何一层不满足都静默不命中):
    ① 代码有没执行 —— 用**记账文件**判(函数首行 append 时间/pid/参数), 不用断点判;
       缓存/队列会让整段逻辑这一拍不跑 (实测动作队列 `n_action_steps=7` ⇒ 一次推理管 7 拍, 只看断点像“永远不进”);
    ② 这一行是不是可执行语句 —— `def` 签名行 / docstring 行 / `return` 行**都绑不上**
       (实测同文件: 1186 def 不进、1188 docstring 不进、1200 赋值能停、1302 方法调用能停、1303 `return rec` 不停);
    ③ 模块绑没绑 (见 26); ④ 进程对不对 —— 代码可能跑在**常驻服务进程**, 断点打在 F5 起的 GUI 进程
       (判据: 记账文件里的 pid 与调试进程 pid 不同; `py-spy dump` 看到主线程在画界面)。想停就得让调试进程
       成为唯一执行者, 且调试模式启动后**自动跑一次引擎** —— 否则“没有代码在跑”, 红点无处可停。
    🔴 **绝不拿中文节点名做子串匹配**: `"actuator" in "🤖 机器人执行器"` 恒为 False —— 开关看着设了、
    其实永不命中, 还会让你误判“代码没跑到”。要打 tag 就用英文短名且每层一个;
    被按路径动态加载的模块里要**内联实现** (从上层包 import 会成环)。
    第五层: 自写 `sys.settrace` 行追踪会**覆盖 debugpy 的 tracer** ⇒ 断点全不命中;
    这类 tracer 必须先判 `debugpy.is_client_connected()` 为真就直接调目标函数、不做 settrace。

### 让 GUI 调试进程真单线程 (除显示层外)

用户要求“除了显示的 GUI, 所有节点都单线程运行”时, **三层一起做**, 只设 env 只覆盖第一层:

1. **BLAS 层 (只能在解释器早期设)**: `OMP/MKL/OPENBLAS/NUMEXPR/VECLIB/TORCH_NUM_THREADS=1` +
   `MALLOC_ARENA_MAX=2`, 必须在**任何 numpy/torch 导入之前**写进 `os.environ`; 事后
   `torch.set_num_threads()` 改不了 OpenBLAS/MKL 已建的线程池。把这段兜底放在 GUI 脚本顶部,
   桌面双击与调试器启动就同口径 —— 不依赖 launch 配置是否真的生效。
2. **运行期线程池**: `torch.set_num_threads(1)` + `set_num_interop_threads(1)` + `cv2.setNumThreads(1)`
   (env 只管首次初始化, 已有实例必须 set)。做成幂等 `enforce()` 挂在节点注册模块的模块级 ——
   一处覆盖全部节点, 并**返回实测值**(`torch.get_num_threads()`/`cv2.getNumThreads()`) 而不是声称。
3. **节点自己起的线程**: `grep -rn "ThreadPoolExecutor\|threading.Thread\|multiprocessing" nodes/ manifold/ middleware/`。
   推理/重活的异步封装 (如 `infer_async` 起 `*-worker`) 在单线程模式必须走**同步分支**,
   否则“人在主线程停住、算在别处跑”, 单步与断点同时失效; 输出里标 `mode="sync"` 让下游看出这拍是真算还是回放。

验收: `torch.get_num_threads()==1` 且 `threading.current_thread() is threading.main_thread()` 为真。
**口径**: GUI 的 Qt 线程仍在, 所以 `/proc/<pid>/task` 总数不会是 1 —— 判“节点是否单线程”看**计算线程**,
不看进程线程总数; 第三方库自带的监视线程 (如 tqdm) 也不算。留逃生口 `ZMAX_MULTI_THREAD=1`
(跑基准/批量推理), 不做静默切换。

27. **"每节点都能单步" ≠ "每节点都真算" —— 报两个数**:
```python
prj = load_project()
for nid in list(prj.nodes.keys()):
    t = prj.step(only=[nid])[0]      # status: 实现执行 / 直通 (PURE=False: 只走数据面) / 异常
```
    同一声明周期里报: 实现执行 N · 直通 M · 异常 0 · >200ms 慢节点(首次加载权量会到秒级)。
    真算取决于 `params.pure_verified` **且**实现返回 dict。
    🔴 **壳会把业务字字典过滤成空**: 生成器模板 `{k:v for k,v in res.items() if k in PORTS_OUT}` ——
    实现返回 `{M, ok, progress}` 这类业务键(不含 `out1/out2`) 就被滤光, 下游永远拿 None;
    兜底 = 一个端口名都没命中时**整块当首端口值发出**。

28. **`PURE=True` 不是充分条件: 实现还会被三处卡死 (返回 bool / 内部抛异常 / 模型侧硬闸)**。
    审计“X 用上了没有”时, `PURE` 只是第一道; 逐层给证: ① `PURE` 现在是什么 (恒 False / env 开关);
    ② `compute()` 里 `fn(_mctx)` 的**返回值类型** —— 实现 `return True/False` 会被壳当“非 dict”而走直通,
    必须返回业务字典; ③ 实现内部抛异常时壳会把它降成“实现异常 → 直通”, 看起来和“没接”一模一样,
    所以要把 `status` 与 `out1` 的真内容一起报 (out1 里是产品块/入参回显 = 它根本没算)。
    🔴 **`status=实现执行` 不能当成功证据 —— 端口可能全是 null**。实现返回的 dict 里端口键都在、
    但值全 `None` 时, 壳照样标「实现执行」。所以 `status` 只能证明“壳调了实现且回的是 dict”,
    **不能证明算出了东西**。判据必须三项齐: 端口值**是不是那块数据** · **是不是 None** · **是不是上游透传值**
    (开闸前后 `out2` 从“上游 payload”变成“自己算的 u_ff”才是真生效)。
    实测代价: 一版 A/B 报出的 64.3ms 全来自这个失败分支(内部异常已兜底成 null 端口), 拆穿后同对比是 51.9ms。
    ⇒ 报 A/B 前先确认两侧端口值**不同类**, 只比耗时等于把失败当性能。
    🔴 **numpy 对象进返回 dict 会连炸两层, 而且错误文案指错地方**: ① 直接放 `float32` 报
    “不可 JSON 序列化”; ② 加 `default=float` 后对 **ndarray** 报 `only 0-dimensional arrays can be
    converted to Python scalars` ⇒ 壳 step 抛异常、整节点作废。转换必须按类型分流:
    `ndarray→tolist()` · `np.generic→item()` · 其他 `float()` · 兜底 `str()`; 别用 `default=float` 一把梭。
    模型体检类 dict (`probe`/`stats`/`debug`) 最容易带 numpy —— 往外抛之前统一转一遍。
    🔴 **模型侧硬闸是第三层, 而且它会拒绝而不是降级**: ckpt 训练时开了额外通道 (实例: skill 通道),
    推理时缺那路输入就 `raise ValueError("checkpoint was trained with a … but … was not provided")` ⇒
    节点整体失效。正解是**构造那个侧通道**(实测 24 维: 阶段 one-hot + 控制量, 宁缺的 L2 场分量留 0 不伪造),
    不是关闸、不是放宽、也不是回到直通。
    取证顺序: 先**绕开节点直接调策略入口** (`service.run_once(...)` / `model(x)`) 跑通一次并贴 chunk/u_ff 真值,
    再回节点跑一次对同样的字段, 两处一致才算接上。
    开 PURE 必须**同时给反向开关** (env) 并默认安全值, 且要报**两个耗时**: 冷启(加载权重) 与稳态单次 ——
    实测 INTACT 冷启 9.7s / 热态 32ms (可以每拍跑), SmolVLA L3 冷启 22.7s / 878ms (10Hz 塞不进, 只能交周期异步)。
    这两个数决定“能不能进默认档”, 不带它们上就是拍脑袋。
    口径: 即使模型真跑了, 也要单独报**它的输出有没有下游消费者** —— 实例: 意图解码的 `l4_cond` 192 维真值
    到达 L3 端口, 但 L3 ckpt 未训该通道 ⇒ `l4_cond_injected=false`, 对动作数值无因果贡献, 只能说“到位未生效”。

## 「X 机器是不是已经部署完了 / 整套工程都在里面没有」—— 四面取证

用户问“那台机器部署完成了吗”时，**禁止一句“部署好了”或“已搬过去”**。工程代码在同一台机能跑 ≠ 整套系统在那台机上。
按四个面分别取证，缺任一面就是没部署完，并要补一句“因此它不能做什么”：

| 面 | 判据（全部可查） | 查法 |
|---|---|---|
| 代码 | 逐文件 hash 对齐 | 两机各跑一次 manifest（**跟随软链**）→ 按 **path** 比 hash，报 0 多余 / N 缺 / K 不同 |
| 数据/记忆/技能库 | 文件在位且**可读** | 断链普查（软链在、目标不在 = 没搬）；点位/示教点/记忆目录是重灾区 |
| 人机入口 | 端口在听 + systemd 单元在跑 + 主进程在 | 端口探活；`systemctl list-unit-files '<前缀>*'` 两机**取集合差** |
| 版本 | 目标机是 git 仓、能 pull | `git -C <root> log -1`；报 `not a git repository` ⇒ 版本面无，不可追溯 |

**入口用单元差集判，比 grep 代码有力**：单元缺席 = 这个入口从没迁过去；代码在但没人起，用户看到的就是“没部署”。
再补两条健康度：`systemctl list-units '<前缀>*' | grep -c auto-restart`（崩溃循环）与 `--state=failed`（硬失败），
两者都要进报告 —— 只报“N 个在跑”会把不健康的算成完成。

**派生数据（工程库/索引/清单）另算，别只比行数**：行数完全一致而内容不同是常态（旧 build 被整份拷过去）。
要读 `meta.built_at` + `meta.sources` 里每个真源的**指纹**，指纹不同就是源比目标新、库是旧的。
画布类结构比对要分开报 **结构**（节点数/连线数/节点 id 集合）与 **参数**（同结构但 params 不同是正常的编辑漂移）。

### 🔴 跨机对账的三种假一致（都会把“没搬”说成“搬了”）

1. **`rsync -rcn --itemize-changes` 默认不跟软链**：对软链一律输出 `skipping non-regular file`，差异一条不报。
   工程根目录大量软链到数据盘时，这条命令会给出“两台完全一致”的假结论。加 `-l`（比链接目标）/ `-L`（跟随），
   或直接用 `scripts/two_host_manifest_diff.py`（跟随软链 + 记断链 + 按 path 比 hash）。
2. **`du -sh <软链>` 报 0、`stat -c %s <软链>` 报的是链接目标字符串长度**（几十字节）⇒ 会误判“目标机仓库是空壳”
   “某关键文件只有 66B 占位”。真实体积用 `du -shL` / `realpath` 后再 du；真实大小用 `stat -L -c %s`。
3. **两份 manifest 用 `sort -k2` + `comm/join` 对账会把同一路径同时报成“只在 A”和“只在 B”**
   （comm 按**整行**排序，带 hash 的行顺序与按 path 排序不一致）⇒ 自相矛盾的结论。必须按 **path 建 dict** 再比 hash。

**连带面也要一次报清**：网络/服务不在位时，依赖它的常驻容器会在 `Restarting` 循环（`docker ps`）、
真值文件 mtime 停在某个时刻 ⇒ 报链路时同时报“哪几个容器在崩 / 真值帧龄多久”，否则用户只看到“网不通”。

## 参数/数字在线性 (「这个数字/点位在参数中心里怎么改?」)

判"某数字/点位能不能在线改"先分**真源**与**库表**, 再判接没接:

1. **参数中心里能改的数字全部来自数据面 `tools/param_registry.py` 的 `scan_*()`**, 不是 SQLite 库表。
   分组 = calib(标定/真源) · canvas(画布节点) · code(代码常量) · platform(产品/性能) · switch(运行开关) ·
   space(空间点/示教点)。
2. 🔴 **拿 `sqlite3 "select ... from params"` 查不到就断言"没这个参数"是错结论**: 点位类真源常在
   `data/skills/l2_atomic/{space_points,taught_points}.json` 这类 JSON 里, 从来就没被注册过。
   判"有没有"的正确入口 = `python3 tools/param_registry.py list | grep <关键词>` / `stats`。
   站台页 `8793 /ctl/points` 列出的 slots(号位)+spaces(空间点) 是同一批数据的另一个面。
3. **假接入的两个形态**: (a) 没给 `fn_ref`/`sys_hint` ⇒ `param_links` 把功能/模块自链成参数名;
   (b) 没给显式 `min`/`max` ⇒ 范围按当前值推断出 "±10%" 之类假包络, 状态显示"已定义"其实没闸。
4. **改数 ≠ 生效**: 消费方 (站台页 / L2 执行器 / 引擎) **启动时读一次**真源 ⇒ 写完必须重启对应服务再回读,
   否则页面显示新值、动作还是旧值。
5. **在线改数没有真机校验**, 只有范围包络 ⇒ 参数中心只配毫米级微调; 新点位/大改动一律回现场点动 + 页面示教
   (走 `POST /ctl/record_point`)。对称地: `tools/adjust_point_offset.py` 只吃 `taught_points.json`(号位),
   不吃 `space_points.json`(空间点) —— 别把它当通吃工具。
6. **把新真源接进参数中心 = 五处编辑 + 三段验证** (缺一不可):
   `param_registry.py` 加 常量 → `scan_x()` → `CAT_CN`+`CAT_COLOR` → `scan()` 串上 → `set_param()` 加
   `_write_json_path(X, p["ref"], v)` 分支 (它自带备份+回读核对, 别另写写盘); GUI 只需在 `param_center.py` 的
   `CAT_ICON` 添图标 (分类树按 registry 分组动态生成)。
   验证链: `param_registry.py stats`(范围未定义=0) + `verify` → 干跑 `set <id> <v>` → 真写 `--write` →
   **回读源文件** → 写回原值复原 → `engineering_db.py build|check` → `verify_param_center` + `verify_platform_spec`。

## 接入下一级前的硬约束 (先量化再动手)

- **延迟预算**: 单步耗时 vs 目标帧率必须先量 (实例: INTACT 单步 316ms, paper 权重/GPU —— 说"每帧调用"前得先回答帧率够不够)。计算图/大模型接进实时回路时, 316ms 是真实工程约束, 不是细节。
- **推荐推序**: ① **只读旁路** (每帧真调, 结果进数据总线/可视化, **动作不参与下发**) → 先量延迟与稳定性; ② **接管某段** (输出真驱动执行) → 必须**同口径 A/B + 不回退证明**; ③ **硬件**。
- **不回退红线**: 新模型接管不得让插拔任务成功率/性能回退。先回归, 再交付。
- 老倪式验收: 要**视频或数据实证**, 口头不算; 他更关心"改了什么", 不关心过程。

## 输入级取证: 「模型/节点吃的是哪份数据、返回什么」

L2/L3 过了(确实每帧被调用)之后, 还有一层常被追问: **它吃的是哪张图/哪份数据**。这时输出四样:
**代码位置(文件+行号: 实例化/调用/返回值落台账, 并说明调用在后台 worker 而不是路由里)** · **能点开的图 URL** ·
**返回值原样 JSON + 逐字段一行** · **同源硬证据 = 取回图的像素 md5 == 台账里记的 md5**。

铁律:
- "给人看的产物"与"模型吃的输入"是**两份东西**, 各自命名/各自台账; 改了模型输入口径, 把别的接口里的旧字段**全部同步**,
  否则两个接口自己打架(实测发生过: 一个接口写着模型吃判据图, 另一个说吃 960 临时图)。
- 临时产物**只在会入队干活的那条路径上写**, 清理时**跳过待处理队列里的文件**, 队列设上限; 喂模型前先判存在。
  把写操作放在"抓帧"函数里 ⇒ 连"只看一眼"的请求也写, 实测 9 分钟泄漏 2180 张。
- 跑同源闸前**先确认两边的 `n` 是不是同一个计数器**(检测序号 vs 帧号), 再拿它当 join key;
  在线系统一直在动 ⇒ 按帧对齐才下结论, 对不齐就说"未对齐", 不硬凑。
- 详见 `references/runtime-model-input-observability.md`; 可重跑闸 `scripts/verify_model_input_same_source.py`。

## 「这是真正在推理么?」(VLM / 云端大模型) = 解析路径 + 内容依赖 + 与像素真值交叉

用户问某能力"是真模型还是写死的"时, 代码里有 `requests.post` 不算答完。四步, 顺序固定:

1. **让引擎自报走哪条路, 别读 env 猜**: 实例 `SceneVLM().status()` → `{path: http|local, provider, model}`,
   `available()` → `(bool, why)`。同类实现常是**三条路 + 一条 `rule` 兜底**(显式 URL/key · 自带 key 的云端 · 本地 worker),
   必须点名**当前生效那条**, 并说明兜底在什么条件下接管 —— 有降级路径不是缺陷, 不说明才是。
2. **内容依赖双图对照 (最硬的一条)**: 同一入口跑**两张明显不同的真图**, 比输出(框数/标签/角度/构图描述)。
   逐字不同 ⇒ 真看图; 雷同或与图无关 ⇒ 模板回显, 判假。只看一次成功输出区分不了这两者。
3. **与独立像素真值交叉**: 走**现场端点**跑当前那一帧, 把模型文字与你自己已测得的像素状态对账
   (快照 mean≈5/std≈0.9 ⇒ 模型应说"全黑")。模型如实说"看不清"是**加分项**(证明它读的是这一帧),
   别因为"没读到东西"就报失败; 反过来黑帧却描述出托盘和光模块 = 幻觉, 直接判假。
4. **触发方式与耗时**: 分清「点一次一帧」(按钮 fetch、无 `setInterval`) 与「每帧/定时推理」。
   按需调用**不能**当实时检测层汇报; 单次耗时给区间(同一模型两次可差一个数量级, 取决于 API 排队)。

汇报模板: 「真推理 · 路径 `http:deepseek-flash` · 双图输出不同(3 框 / 2 框) · 现场帧读出"全黑"与像素真值一致 ·
按需一帧不是每帧 · 单次 8~68s」。另必答**失败面**: 无 key / 断网 / 本地权重不在盘时, 是回 `rule` 摘要
(要标 `src=rule`) 还是 `ok=False`; 桥接层如实透出 `ok=False`、下游写 `null` 而不是 0, 才算"不冒充"。
端侧权重目录不存在时只能报"本地离线路径不可用", **不能拿云端跑通说成端侧也行**。

### 🆕 档位级验收工具与两条硬纪律 (2026-09-24)

`tools/canvas_level_audit.py` — 逐节点四件套取证: ①执行注册 ②源码映射有效性 ③引擎引用 ④连线数,

`tools/verify_engineering.py` — 全工程判据, 其中「**档位契约无问题**」= 每个档位节点的名都能在逻辑真源
`engineering/nodes/library.py` 的 `NODE_LOGIC` 里找到 key。**画布上有节点、连线也在, 但档位注册表里没这个 key
⇒ 节点级能跑、档位级 (▶运行/单步) 永远拿不到它** —— 这就是"假接入形态 #2"的自动判据, 红项会直接列出节点名
(`L2: N 个节点没有对应逻辑 key: [...]`)。给画布加节点/接线后跑一次, 把"节点级绿"与"档位级绿"**分开报**;
只改了节点文案/params 时, 改前改后回读**节点数 + 连线数**证明结构没动 (描述变了不算结构变更)。

**纪律 1: 判"有没有执行注册"必须 import 真分派函数, 不许自己写正则。**
自写 `_reg\("key"` 正则漏掉**循环注册** (`for _skid,…: _reg(_skid,…)` → SK01-08) → 8 个真节点被误判"缺注册"。
正确做法: `from node_logic import match_node; match_node(画布节点名)` — 与 GUI 双击分派逐字同源。

**纪律 2: 解析 `_EXTERNAL_LOC` 路径不许用 `\(([^)]*)\)`, 更不许按 basename glob。**
嵌套括号 `os.path.join(...)` 会在第一个 `)` 处截断; 按 basename 搜会命中 `gui-venv311/site-packages/torch/.../planner.py`
(同名文件!) → 整片 57 条映射被误判失效。正确做法: **按字面量片段顺序拼绝对路径取最长存在后缀**, 并排除 venv/site-packages。

**判据分层 (别把软指标当缺陷)**: 硬判据 = ①有执行注册 ②不孤岛; 源码映射缺失只是"展示回退到节点函数"(合法)。
一次实测: 70 节点 → R1 每帧 16 · R2 档位级真接 31 · R3 语义 13 · R4 终端 7 · R5 待建 3 · ⚠ 0;
152 连线 → 双端运行时 17 · 单端 67 · 双端非运行时 68 · **真缺口(端点无注册) 0**。

**6 类"画布有节点但没执行函数"的修法 (实测有效, 全是真实现只是没接上)**:
| 症状 | 修法 | 实例 |
|---|---|---|
| 关键词对不上 (函数本来就在) | 给已有 `_reg` 的 match 列表**加画布节点名的独特子串** | ss_llm←"长程序列规划器"; ss_skill←"技能序列编排"; ss_mem_l2←"肌肉记忆操作"; ss_mem_l3←"记忆: 海马体" |
| 真没注册 | 写 `node_xxx(ctx)` 真执行函数 + `_reg` + `_EXTERNAL_LOC` 三件套 | n_board_frame (board_frame_module.run); n_l2_muscle (技能 JSON + ROS2 桥只读) |
⚠ 加关键词时必须查**最长匹配**冲突: 别加"长程序列规划"(会抢 🚀 L3 · 长程序列规划), 用更长的独特串。

10. **"配置驱动"只驱动名不驱动行为 (配置只被打印)**: 任务/配方配置读进来当成 `cfg` 传了一圈, 但执行函数里
   一次都没用 ⇒ 改配置只改了日志。实测: 摆盘链 `run_module(env, ss, i, cfg, ...)` 内 `cfg` 出现 **1 次 (仅形参)**,
   判据阈值写死 `max(|dx|,|dy|)<=0.001 and yaw<=1.0`。
   判定法 = **同一条 episode 换配置跑两遍**: 该配置项真生效 ⇒ 判决/轨迹变; 只被打印 ⇒ 两遍逐字相同。
   实测 A/B: 阈值从配置读 `≤1.000mm` ⇒ 3/3 合格; CLI 覆盖 `≤0.300mm` ⇒ 0/3 不合格 (Δxy 物理量两组完全一致 0.34/0.43/0.47mm)
   ⇒ 阈值确由配置驱动。**修法**: 写 `task_spec()` 真读配置中心 (targets/overrides) 并在报告里逐条报"判据来源",
   让"配置→判决"可追溯; 留 CLI 覆盖口做 A/B。顺带把配置里没量纲意义的项 (字符串"配方上限") 跳过而不是硬转 float。

11. **"状态灯说在跑" ≠ 真跑, 而且灯有真源 —— 先找到它再动手**: 界面那列"推理中/空闲"不是界面算的,
   是它读的**探针**算的。实测链路: 模型引擎窗口读 `GET http://127.0.0.1:8796/status/all` →
   `src/lerobot/engineering/status_hub.py` → `models_manifest.json` 里每个模型的 `probe`; 形状是
   `{"type":"counter|ts|file|json_age", path/url, pointer, window_s/max_age_s}`,
   `inferring=true` 的充要条件是**探针在窗口内真的动了** (counter 增长 / 时间戳新鲜)。
   ⇒ 想让某层亮只有两条正路: ① 让这层**真被调用** ② 把探针指到**它自己**的真调用计数/时间戳上。
   把探针指向别人的计数、或改了清单却不真跑 = 假绿 (同第 7 条红线)。
   汇报按层给结论: "这层真跑 (计数在长) / 这层只是灯 (探针指错) / 这层本就没挂 (为什么)"。
   **接线验收顺序 (照做)**: ① 在**隔离实例**上跑通 (实例隔离 + 不抢单写入器锁, 一律不碰在役回路)
   → ② 回读**每层调用台账** (每层 ok/耗时/来源, 一行一次调用) → ③ 才改 systemd drop-in 生效
   → ④ 重启后在界面回读同一条。**别拿"服务 active"当"层在推理"**。
   常驻回路接整条链的最小代价口径: 10Hz 的回路不要每周期都跑全链 (全链几十 ms/次),
   用"每 N 周期一次" (实测 2Hz 足够让探针持续在窗口内动)。

🔴 **体检脚本的"假断点"比没体检更糟**: 路径写死会产出不存在的缺口, 用户按它去修就白干。
实测两例: 记忆开关真源是 `data/memory/memory_layers.json`, 脚本写成 `data/memory_layers.json` ⇒ 恒 FileNotFoundError;
世界模型权重在 `models/l4_mani_predictor_v*.pt`, 脚本只 glob `checkpoints/**` ⇒ 恒报"无预测器权重 (世界模型项可能恒0)"。
判据: 报"缺 X"之前先 `find`/`ls` 那个东西的**真实落点**, 拿不准就报"未在此路径找到"而非"不存在";
读数也要按消费方口径 (引擎 `d[k]=int(bool(j[k]))`) 解释 —— 注册表形态的文件按扁平开关读会得出反结论。
🔴 **探测脚本里对“用来分类的那份清单”绝不许截断**: `ls -d models/* | head -20` 这类限制会让排在后面的
目标永远被归成“没有” —— 实测 models/ 下 36 项、目标排第 23, 于是审计连报几轮“端侧无该权重”, 而权重早在盘上、
真跑完六个提示都出了实例。判据本身错了, 后面的结论全部作废。改法: 不截断(`ls -d models/*`),
或者按名字 `grep -i` 定位; 任何“计数/名单不全”的探针都要先把**总条数**打出来自证没被截。
🔴 **审计档位要区分“能跑”与“常驻在跑”**: 权重到位 + 依赖可导入 + 手工前向真出结果 = **ready(离线可跑)**,
不是 `absent`(没有能力), 也不是 `run`(每帧在跑)。把“服务没起”与“没能力”混成一档, 会让用户以为一堆东西没装,
也把你自己真正要补的缺口淹掉。报告按 `run / ready / stale / absent / nonexec` 分档给计数,
并写明 ready 那档的实测代价(单次耗时) —— 那才是它能不能上产的决策数据。
