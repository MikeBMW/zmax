# 让「所有层」在常驻回路里真跑（不是点亮状态灯）

## 判据唯一依据：界面那列「推理中/空闲」是怎么来的
状态中心读一份模型 manifest（每条一个 probe：计数字段 / 时间戳 / 文件 / json_age，**窗口内真增长**才算在跑）。
⇒ 只有一条正路：**让该层真的被调用**，并让 probe 指向那个真计数。把 probe 挪到一个不动的文件/字段 = 假绿，
交付/汇报那天一定被追问穿（“哪一帧调的？”答不出来就是假接入）。

## 接进常驻回路的定式（可移植）
1. **装配一次**：pipeline 对象在启动时构建并常驻（每周期重建 = 每周期重载模型）。
2. **周期内调用**：主循环每 N 周期调一次全链（`run(img=<HWC uint8>, obs=<vec>)`），
   把每层 `ok / src / latency_ms` 并进当周期记录 ⇒ tap 里能逐帧复核“哪一层、什么时候、花了多久”。
3. **每层落一行计数**到固定文件（如 `<data>/ss_live/layer_calls.jsonl`），probe 读它（真调用，可审计）。
4. **生效**：给常驻服务加环境变量后 `systemctl restart` **一次**（反复重启在役服务会被投诉）。
   开关变量名必须与代码里读的那个完全一致——另起一个名字会被**静默忽略**（日志没有“已接入”行、探针不亮，
   却以为是接线问题）；加开关前先 grep 代码或看 `--help` 确认变量名。

## 边界：别把“探针指过去”当“接管了”
- 多层 pipeline 里的真层 ≠ manifest 里每条权重：更大的本体权重（VLA 主模型 / 世界模型 / MOE 路由）
  显存不够硬挂会 OOM ⇒ 汇报要分开说【哪些层在真跑（探针读真计数）/ 哪些还没接管（原因）/ 哪些只是登记】。
- 全链耗时对节拍是硬预算：实测 10Hz 回路下全链约 20~60ms/次 ⇒ 每 N 周期跑一次（N=5 ⇒ 2Hz 才不挤爆节拍）；
  先量单层耗时再定 N。

## 输入帧也必须是真的
喂检测/理解层的图要用**唯一依据帧**（在役服务当前提供给产线检测器的那张 / 真相机取像口），不是随手一张渲染图：
反例——仿真渲染帧喂在役检测器 ⇒ 0 检出（训练域=产线），会被误读成“模型没用/层没接上”。
图不可用（全黑/纯色，灰度均值≈0 或标准差≈0）先判掉并如实标降级，不要在黑图上跑出“结论”。
