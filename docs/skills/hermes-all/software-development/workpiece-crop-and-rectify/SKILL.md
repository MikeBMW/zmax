# 工件刚体裁切与摆正（判据图取像口径）

## When to Use
- 要把相机画面里的工件（光模块 / 金手指条 / 盘件…）裁成**判据图**：只留刚体、去背景、摆正。
- 工件**位置与角度会变** ⇒ 每帧都要重新找（这是**搜索任务**），不许写死坐标/固定四角。
- 交付/展示用的是「人看的那张图」，不是模型输入图（两者口径绝不能混）。

## 一、定位刚体 = 动态搜索（候选 → 评分 → 择优）
- ✅ 可用配方（实测多档曝光下稳定命中同一刚体：倾角一致、矩形度/平行度 **1.00**）：
  `createCLAHE(2.0,(8,8))` → `GaussianBlur(5,5)` → **Otsu 二值**（前景占比 >60% 时改用 p80 分位兜底）
  → 形态学 `close(15×15)` + `open(25×25)` → 逐轮廓评分 **面积占比 × 矩形度(contourArea ÷ minAreaRect 面积)**
  → 择优取 `minAreaRect` 的 `boxPoints`（四角**天然平行**）。
  面积闸取 `0.5%~75%`（工件尺度），把碎块与整幅背景排除。
- ⛔ **Canny 边缘 + 闭运算这条路不通**：轮廓拿到的是「细边环」而不是刚体面
  （实测面积占比 3% 却**矩形度只有 0.05**）⇒ 会被面积/矩形度闸全部拒掉（27 个轮廓 → 0 候选）。
  边缘法只在**必须有亚像素边界**时才用，且要改成「边缘点拟直线定四边」。
- ⚠️ 阈值法的已知短板：低曝光时「亮块」只覆盖工件较亮的部分 ⇒ **检出尺寸随曝光漂**
  （实测面积占比 15.5% @低曝光 vs 21.5% @中高曝光）。要框满整个刚体得改用**边缘直线拟合**，
  长宽比这类形状先验只能做**软**约束（硬约束会把形变/装配公差误杀）。

### 1.1 高曝光下 Otsu 会**整个失效** —— p80 兜底也救不回来 (2026-10-20 实测)

实测同一表面相机 48000us 时：**Otsu 前景占比 = 1.000**(工件与台面糊成一整片)、退 p80 后 28 个轮廓、
最大候选 **1717×1269 长宽比 1.35**(台面) —— **模块本体根本没被分开**。同一场景降到 5000us 背景全黑时，
干净命中 **1124×188 长宽比 5.97 · 矩形度 0.833**；3000us 仍能命中 1095×188。

⇒ 两条规矩（缺一条就会拿到错的刚体）：

1. **加长宽比闸锁刚体** `aspect = max(w,h)/min(w,h) ≥ 2.5`。光模块/条带类工件是扁长的(实测 5.8~6.8:1)，
   台面/夹具接近方形(1.88:1)。只靠面积闸会把台面当刚体 ⇒ 摆正就对着台面转，**整张判据图全错**。
   （这比“面积上限调到多小”稳：工件占画面比例会随位姿变，长宽比不会。）
2. **搜不到就去降曝光搜，不要在阈值上硬调**。`fg_frac ≥ 0.99` 就是“整幅当工件”的硬信号 ⇒
   直接换低曝光帧搜，而不是继续改 Otsu/p80/形态学核尺寸。
3. 把 `fg_frac` / 候选数 / `aspect` **打进输出**——否则“搜到了”和“搜到的是台面”在日志里长得一模一样。

⚠️ 用低曝光帧定几何、用另一帧取像素时（送检测器量常见），必须确认 **工件没动**（两次几何结果一致）；
判据图交付**不允许**这么干，见 §三。

## 二、摆正 = 纯旋转，不是重映射（零拉伸）
- 用户的验收口径：**「就是把斜着的位姿摆正即可」** ⇒ 输出必须与检出的**真实像素尺寸**一致。
- ⛔ 把检出四边形 `warpPerspective` 到任意 `W×H`（尺寸取自侧边长）会**改比例 = 拉伸**，
  用户一眼就能看出来（「没让你拉伸那么宽」）。
- ✅ `getRotationMatrix2D(中心, 角度, scale=1.0)` + `warpAffine(同画幅)` + `getRectSubPix(按检出尺寸)`。
- **自检（硬证没拉伸）**：输出尺寸 == 检出框尺寸 且长宽比一致（实测 1764×440 → 1764×440）。
- 只有用户明确要「上下沿平行」**且实测确实是梯形**时才上透视变换；即便上，输出也按实测尺寸，不许拉伸。

## 三、亮度必须「同帧同像素」
- ⛔ 不要做「几何帧定框 + 测光帧取像素」的分离：两帧曝光不同 ⇒ 两张图亮度不同，用户会把画面当结果看，直接判定为错。
- ✅ 一帧到底：同一帧搜框 → 同帧旋转裁剪。
- **自检**：把检出矩形内的原图像素与摆正图逐像素比 —— 实测**均值差 −0.08 / 中位差 0.0** 才算一致。
- **唯一例外：这张图是送给检测器的，不是给人看的**。此时可以“低曝光定几何 → 检测曝光取像素 →
  同角度旋转”，因为检测器要的是它训练分布里的亮度（过曝会把缺陷洗掉，见 `live-camera-detector-adaptation`）。
  前提两条：① 两次取帧之间**工件没动**（两帧各自搜一次，几何要一致）；② 输出里要标清几何来自哪一档/像素来自哪一档。

## 四、交付形式：原图 + 叠加「准备截取的区域」
- 主图 = **原始帧** + 画出搜索到的矩形（绿框 + 四角 A/B/C/D 标记 + `crop area: WxH tilt θ°` 标注）。
- 摆正/裁剪结果**另存独立文件**，**不要拼进同一张图**（用户明确否掉「原图下面又叠一张摆正图」的拼图）。
- 图上文字一律 **ASCII**：OpenCV `putText` 画中文会变成方框。
- 报数只报**可复核的量**：框尺寸、倾角、面积占比、亮度均值/饱和比例、以及「原图 vs 摆正图」的同像素差值。

## 五、画框/出图前的在位自检（宁缺勿假）
- 判据图是**程序画出来的**，工件不在位时它照样能画出一块规整矩形/一排结构 ⇒ **图本身不能当「在位」证据**。
- 上框前先对候选区域做**周期性/结构自检**（列剖面自相关要有峰，且峰不落在搜索边界）；不过就不画、如实报原因。
- 同源判据：模型的判决「0 缺陷」也**不等于合格**（空场景照样 0 缺陷）—— 要另有一条「在位」判据。

## 六、坑速查
| 坑 | 症状 | 修法 |
|---|---|---|
| 用边缘法找刚体 | 轮廓是细边环，矩形度 ~0.05，候选全被拒 | 改用 CLAHE+Otsu 阈值法找亮块 |
| 重映射到 W×H | 输出被拉伸成宽条，用户当场指出 | 纯旋转 scale=1.0 + 按真实尺寸裁剪 |
| 跨帧取像素 | 摆正图与原图亮度不同 | 同帧旋转；用同像素比对自查 |
| 固定四角 | 工件一移位就裁空/裁错 | 每帧重新搜索，评分择优 |
| 拼图交付 | 用户要的是「原图 + 截取框」 | 摆正图另存独立文件 |
| 图上写中文 | 变成方框 | 只用 ASCII 标注 |
| 阈值法尺寸随曝光漂 | 同一工件不同曝光量出不同尺寸 | 已在文档里如实标注 + 长期改边缘拟合 |
| 搜到的是**台面**不是工件 | 候选上万 px、长宽比 ~1.3、摆正后对着台面转 | 加长宽比闸 ≥2.5; `fg_frac≈1.0` 就改低曝光搜 |
| `cv2.minAreaRect` 报 `(-215) total >= 0 && depth == CV_32F/32S` | 连通域直接用 uint8 掩膜求最小外接矩形 | 先 `findContours` 拿轮廓点, 再传 `max(cnts, key=cv2.contourArea)`(且 ≥5 点) |

## 可复用脚本
- `scripts/find_and_deskew.py` —— 一帧到底: 搜索刚体 → 输出「原图+框」叠加图、「同帧摆正」裁剪图,
  并打印尺寸/倾角/面积占比/饱和度/同像素亮度差(把上面每条自检都跑一遍)。
  用法: `python scripts/find_and_deskew.py --image frame.png --out-dir /tmp/x [--url http://host/pic?kind=origin&grab=1]`

## 七、判据图「少了工件头部」—— 剖面扩边界 + **分轴门限** (2026-10-13 实测)

现场: 判据图裁出来"光模块头部没了"。

- 真因: Otsu 只把**足够亮**的部分当刚体。实测头部/金属壳剖面 39~50 而背景电平 4 ⇒ 被当暗背景切掉,
  检出框左端欠 **54px**、右端欠 **11px**。
- 修法: 在旋转后的灰度图上, 以框外一圈估背景 `bg`/`σ` 与框内核心 `core`, 从四边向外走,
  只要剖面仍高于门限就继续扩(长轴每边 ≤25%、短轴 ≤15% 边长):
  - **长轴**门限 `bg + 0.08·(core−bg)` ⇒ 收得进偏暗的头部;
  - **短轴**门限 `bg + 0.25·(core−bg)` ⇒ **只认刚体不吃背景辉光**。
  ⚠️ 实测教训: 用**单一** `bg+2.5σ` 门限时短轴把辉光也吃进来 —— 高度从 172px 涨到 **308px**(判据图全是背景)。
- 自检(必须打): 每边扩了多少 px · 两个门限 · 背景/核心电平 · 扩后两端的列均值(应高于背景而不是≈背景)。
  实测结果: 965×172 → **1028×173**(+53/+10/+1/0), 两端列均值 25.8/24.3 vs 背景 4 ⇒ 头部确实收进来了。

## 八、判据图数据源退化时的**本机口径** (2026-10-13, 工控机 10083)

- 症状: 页面「判据图」永远显示**整幅原图**(老倪: 「判据图还是显示原图, 不对」)。
- 真因: 工控机 `GET /picture?kind=judge` 在没找到模块时**退化**成 `Surface_Letterbox_W1280_H1280_No_<n>.png`
  (整幅 letterbox 规范图) —— 而且实测那份 `last_result` 已是 **20.2 小时前**的 ⇒ 那一格永远是一张旧整幅图。
- 修法: 不从 kind=judge 直通, 改取 `kind=origin`(2448×2048) **本机**搜框+摆正+裁剪(即本技能 §一~§二),
  再把结果当判据图; 「整板原图」那格 = 原图 + 绿框 + 四角 + `crop area: WxH tilt θ°` 标注。
  实现 `tools/aoi_surface_rect.py`(`surface_roi`/`surface_judge`/`overlay_box`) + 判据
  `tools/verify_aoi_surface_rect.py`(合成斜置矩形几何 7/7 + 真实暗帧必须**不出图**)。
  一键回退: 环境变量 `ZMAX_AOI_SURFACE_RECT=0`。
- ⚠️ **抢相机**: `?grab=1` 与本机 8793 的判据图 MJPEG 流会**争同一台 OPT 相机**(SDK 不支持并发抓图),
  实测 6 次里 3 次 `HTTP 500`(46B 截断 JPEG)。要稳定取图就让**同一个进程**抓一次再本地分发, 别两处都抓。
- 落库判据(交付前必跑): 判据图**尺寸>0 且不是 1280×1280 letterbox** + 亮区倾角≈0(行列投影: 列均值 std ≫ 行均值 std
  = 水平条带) + 5s 后再取字节变化(证明是实时不是陈旧)。

## 九、夹具/支架与工件粘连 ⇒ 按「整列贯穿」截断 ROI (2026-10-20 实测)

症状: 候选池空(`n_cand=0`), 判据图那格回退**整幅原图**(不水平 + 带旁边一块大夹具), 而人眼一看"图里明明有工件"。

- 机理: 工件一端**插进夹具**, 两者亮度相近且 x 相邻 ⇒ 同一阈值下轮廓**粘成一块**(实测 2080×1303),
  `minAreaRect` 长宽比只有 **1.70** ⇒ 被 aspect 闸(≥2.5)全挡。
  提高阈值想分开也不行: 工件中间有台阶暗缝, 高阈值把它**断成 3~4 段**, 每段长宽比不够 ⇒ 仍空。
  ⇒ **在阈值上纠缠永远解不开, 先用几何把两者分开。**
- 可分的物理特征: 夹具是**整列贯穿**(每列亮像素 > 0.39×H, 且连续 ≥60 列都满足); 工件只有 ~0.2×H 高。
  沿 x 扫出首个"连续贯穿列"起点 `xc`, 把二值图截到 `[:, :xc]`。
- 🔴 截断后**必须换严格阈值重算**再找轮廓(`g>=180` + 小核 close(9)/open(5), 再补零回原宽)。
  只切 x 不换阈值, 低阈值下粘连依旧(实测仍 `n_cand=0`)。
- 实测: 截断点 x=2023(连续 219 列贯穿) ⇒ 工件独立成 1504×209, 长宽比 **7.28** / 矩形度 **0.73** 全过闸;
  摆正后 1400×182, 且正常点位回归(1273×188 / −69.81°) 一字未变——好帧没有贯穿列, 行为天然不变。
- 验收要看**右端之后**: 判据图右侧应是工件自身结构(接线/台阶), 不是大片锤纹/麻面; 或量右端之后列中位灰度 ≈ 背景。
- 🔴 **同一个几何修法有两份实现, 必须同口径改两处**: 本机出图走 `aoi_surface_rect.py`, 而产线服务端判据
  是另一套(找亮条上边缘再拟合角度)。只改本机 = 页面图对了、服务端照旧报「亮条上边缘点太少(0)」,
  现场会以为没修。改完两边都要验: 本机量摆正尺寸/倾角, 服务端读它自己的判据字段。
  服务端强截取要把新字段(如 `fixture_clamp_x`)**打进它的 met**, 否则你无法区分"新逻辑生效"与"恰好本帧能过"。

## 十、工件竖着且顶部出画 ⇒ vertical 兜底候选(只在主搜索全空时启用)

- 症状: 姿态转过 90° 后工件**竖着**且**顶部被画幅切掉**, 完整矩形搜不到(`fg_frac` 5%~14% 却不是矩形)。
- 实测此时 `minAreaRect` 其实很规整(**fill 0.95**, 长边 599 / 短边 395), 唯一不过的只是长宽比 1.54 < 2.5。
- 做法: aspect 闸失败时**不直接丢**, 记成 `vertical=True` 候选(条件 `fill ≥ 0.85 且短边 ≥200 且长边 ≥450`),
  score 记 **0** ⇒ 只有主候选池为空时才被选中。摆正逻辑本就 `bw<bh ⇒ 交换 + 角+90`, 竖条自动转水平。
- 实测: 803×398 / 倾角 −1.36°, 页面同步刷新; 正常点位回归零变化。
- ⚠️ 诚实口径: 这张"水平"图是**端面/近景**(工件顶部出画, 只露一段), 不是完整长条。
  要完整长条只能改视角(动臂或相机朝向) —— 别把"转平了"说成"拍全了", 用户会当场戳穿。

## 十一、判据图"突然没了/不水平"的排查顺序(别一上来改算法)

1. **先看曝光档**: 高曝光会把工件与台面糊成一片(`fg_frac`→1.0 或 40%+), 算法怎么调都搜不到;
   正确档位下同一份算法能干净命中。档位结论常写在提交说明/文档里(实测「48000 下 Otsu 前景 1.000 搜不到,
   5000 下干净」)—— **先读结论再动手**, 不要自己重测一遍定档。
2. **再确认算法版本**: `git log -1 -- <文件>` 看最后提交; 被人改过就先回退到已验收那版(`git checkout -- <文件>`,
   改动先 `cp` 到 /tmp 留证), 而不是在坏版本上继续叠补丁。
3. **最后才谈改算法**。
- ⚠️ 反例教训: 用「多阈值 + 分位数相对档」可以让原本搜不到的帧"能检出", 但同时会把不该检的目标也检出来,
  并且悄悄改掉好帧的既有口径 ⇒ 被要求整份回退。**放宽检出能力是最后手段, 不是首选。**
