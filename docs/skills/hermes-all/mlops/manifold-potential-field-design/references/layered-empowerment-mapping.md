# 给已有多层栈叠流形约束 (语义 / 空间 / 物理 三层赋能)

场景: 已有 L5 语义 (DeepSeek 类) / L4 空间 (action 预测器) / L2 原子技能 (执行收口) 三层,
要求**不删减任何原有模型、不重训、不动权重**的前提下加几何约束增强。

---

## 1. 先量每层维度, 再决定哪层能上球面

不要按"哪个层更重要"分配约束, 按**维度**分配 (可分辨率表见主技能律 5):

| 层 | 典型维度 | 可分辨率 | 处置 |
|---|---|---|---|
| 语义 (L5) | 意图文本 / JSON | —— | **不投球面**: 文本无天然几何, 用固定正交基把意图词映射成方向即可 |
| 空间 (L4) | 8 维 action | 全 8 维 17% | **拆开**: 位置 3 维入 `S²` (49%), 姿态/夹爪 5 维走 `latent_flat` 直通 |
| 物理 (L2) | 4 维 chunk | 49% | 直接 `S³`, 势函数兜底 + 单调闸 |
| 任意深度 latent | 256 维 (JEPA 等) | **0%** | **禁止直接套**; 降到 3~8 维子空间, 或只在融合层输出做 guidance |

**按语义拆维是标准做法**: 8 维整体投球面只剩 17%, 拆出位置 3 维立刻回到 49%。
球面上的可分辨率随维度是**崩塌式**下降, 不是渐变的, 所以"维度勉强够就整投"是错的经济性判断。

---

## 2. 三层之间的数据契约 (上层只给条件, 执行由最下层收口)

```
L5 意图文本 ──编码──> goal_sem (平直)  ──派生──> goal_spa_pos (单位向量)
                                                    │
L4 8维 action ──> 位置3维朝 goal_spa_pos 收窄 ──> 8维 (幅值不变)
                                                    │
L2 4维 chunk  ──> S³ 势函数兜底 + 单调闸 ──> 4维 (唯一出口)
```

- **语义层不直接改动作**, 只产出目标点。让语义层碰执行量就是把"意图"和"执行"混成一层。
- **每层只改自己那一段**: L4 只收窄方向、不改幅值; L2 只保证 Φ 不增、不改执行链。
- **无法解析的意图要显式放弃**(返回 `ok=False`) 而不是猜一个方向往下传 —— 假目标点比没有目标点更坏。

## 3. 零侵入 = 门控全关时**逐位**相同

```python
def empower_action(self, a8):
    if not self.en_spa or a8.size != 8:
        return a8.copy()                 # 直通: 不 reshape、不 cast、不归一化
```

- 判据用 `np.array_equal(out, inp)` 为真 且 `max|Δ| == 0.00e+00` —— 不是 `<1e-12`(后者只是近似)。
- 直通分支**不要**顺手做归一化/类型转换/reshape, 那就不叫逐位相同了。
- 另给 `health()` 回报 `passthrough: True`, 让上层能自报"我现在是关着的", 避免"以为开着其实没接"。

## 4. 自主进化 = 在线 EMA, 不重训

真源: 目标点与权重都是**运行时状态**, 从执行结果演化, 与模型权重无关。

```python
def update_from_outcome(self, success, end_action=None, end_chunk=None, lr=0.15):
    if success:
        goal = (1-lr) * goal + lr * unit(landed_point)   # 成功 ⇒ 目标朝实际落点挪
        w    = min(W_MAX, w + 0.01)                      # 成功 ⇒ 几何引导占比升
    else:
        w    = max(0.0, w - 0.05)                        # 失败 ⇒ 回退但不归零
```

- **失败样本不许污染 goal**(不更新目标), 只降权重 —— 失败轨迹的终点不是"更好的目标"。
- 权重上限沿用 `W_MAX=0.85`, 留欧氏分量保单调。
- 状态必须**落盘 + 可重启恢复**(实测 `n_updates` / `w` 逐位恢复), 否则"自主进化"每次重启归零。
- 验收判据: 跨 episode 的 Φ 水平**持续下降**(实测 120 段 `0.0914 → 0.0329`, −64%)。
  只报"跑通了"不算, 要报这条曲线。

## 5. 跨平台确定性可以拿来当部署证据

纯 numpy 实现(无 torch / CUDA / 任何硬件分支)时, 两平台跑**同一套判据**应给出**逐位相同**的数值:

| | RTX 4060 工位机 | Intel Core Ultra X7 358H |
|---|---|---|
| 扰动恢复收益 | 17.0 / 17.0 / 19.7 / 28.1 % | **完全相同** |
| 16 拍块耗时 | 0.71 ms | 0.80 ms |
| 通过数 | 20/20 + 5/5 | **14/14** |

- 取证方式: 目标机上 `python3 xxx_verify.py`, 打印 `platform.machine()` / `platform.python_version()` /
  `numpy.__version__` / CPU model name, 并**断言关键指标与源机相同**。
- 顺带自证零依赖: 逐一 `import` `torch` / `cupy` / `pynvml` 并打印"未安装 ⇒ 本层不需要"。
  "能跑"要写成"在这些包都不存在的机器上也能跑"。
- 耗时差异(0.71 vs 0.80 ms)允许; **判据指标差异不允许** —— 有差异说明用了未固定 seed 或
  并行归约顺序不定, 先修这个再谈部署。

## 6. 停在哪一层要提前说清

本类增强能证明到的最高层次:

1. **算法层**: 扰动恢复收益、单调闸不放坏帧、逐位零侵入 —— 可证。
2. **执行层**: 是否真接进下发链 —— 取决于有没有挂到 chunk 产出之后 / L2 收口之前;
   没挂就如实说"离线增强层", 不要说"动作变好了"。
3. **任务级**: 真机抓取成功率 A/B —— 没跑就说没跑。

不要因为 §5 的跨平台一致性漂亮, 就把结论说到第 3 层。
