# 机器人视觉 3D 定位误差诊断与遮挡鲁棒 (视觉伺服感知链)

## 触发条件
- 视觉定位的工件坐标不准 → 抓取/插入失败、反复尝试、手追假目标
- YOLO 2D 检测 + 深度模型反投影的 3D 定位系统性偏差
- 机械臂(夹爪)接近工件后检测漂移/锁到机械臂上(幻影)
- "视觉模式竟然能用模拟器真值保障"的泄漏排查(红线)

## 误差分解三步法 (先分清 2D 框 / 深度 / 公式, 别猜)
定位误差来自三个独立环节, 必须逐项钉死再修:
1. **公式自洽性验证**: 把**真值深度**代入当前反投影公式算 3D, 与真值对比。
   → 误差≈0 = 公式与 2D 中心自洽, 误差全在深度模型输出 (scale/语义);
   → 误差仍大 = 反投影公式或 2D 中心有系统偏差。
2. **2D 检测精度**: 真值 3D 投影到 2D (用**训练数据生成器的投影函数**做 ground truth,
   别信自推的镜像公式 — v 轴符号极易写反) vs YOLO 框中心。
   逐类打印偏差 (x 准 y 偏且各类不同量 ≈ 垂直翻转/标注旋转不一致; 全部准 = 2D 无责)。
3. **深度标定**: 多布局/多姿态初始帧, 隐含真 scale = 真值沿光轴深度 / 模型深度中位数。
   取平均得该模型当前正确 scale。⚠️ 深度取框内**中位数**通常最优 — "小目标框含大量背景
   污染中位数"假设多为证伪 (低分位往往是前景机械臂)。

## 单目深度 (SILog 训练) 的尺度漂移 — 关键认知
- SILog 是 scale-invariant 损失 → 模型输出**每帧尺度可漂移**, 绝对深度需外部标定。
- 固定 scale 校准只在**场景内容不变**时有效: 机械臂一进入画面 (哪怕距目标 10cm+),
  尺度即漂 (实测误差 1mm→30mm)。→ 固定 scale 只对手远离工件的帧可信。
- 若必须绝对深度做毫米级控制: 换多视角/结构光/已知平面约束, 别指望单目固定 scale。

## 遮挡幻影免疫 (检测框锁机械臂)
机械臂接近工件 (斜视角 ~10cm 内) → 检测器把最近杆状物 (机械臂) 当目标 → 3D 点≈手位置,
手追幻影 → 反馈锁死偏位。防御组合:
1. **物理先验 z 窗**: 躺台面/已知平面工件未被夹持时 z 恒≈平面高 → 检测 z 超窗 (±2cm) 即
   幻影丢弃 (真机同构: 托盘高度一次标定; 工件被碰移仍在平面上, 不误杀)。
2. **定位状态机**: 只在"执行器远离"的高置信区刷新定位 (实测 1mm 级), 采信一次即锁存冻结;
   失败回退到安全位再解冻重定位 (工件可能被碰移)。
3. **大跳变多帧确认**: >5cm 跳变单帧丢弃, 连续 2 帧同候选 (<2cm) 才采信 —
   区分单帧误检 vs 工件真被碰移。
4. 诚实红线: 视觉未检出/被拒时**禁止回退模拟器真值冒充检测** — 保持上次估值或原地等待。

## 测量→控制信任切换 (夹持/接触确认后锚定)
视觉定位有残差 (亚像素×距离, 毫米级) 时, 毫米级后续动作 (转移/插入) 会被残差污染
(擦碰→掉件)。工程正解 (真机同构):
- 视觉只负责"找到并接近工件" (粗定位, 毫米级够);
- 夹持/接触经**随动验证确认稳定** (N 帧偏差<阈值) 后, 把工件相对执行器偏移**锚定为实测值**,
  后续按编码器/机械定位走 (精度 0.1mm 级)。
- ⚠️ 锚定阈值别太紧: 工件常在夹爪内轴向滑 5-7mm 才稳定, <5mm 阈值会漏锚 → 用滑脱判据同款
  阈值 (8mm) + 稳定帧数 (15) 组合。
- 控制里用到的"初始高度/基准"常取错 obs 索引 — 多段向量 (xyz) 取单值前先验证字段顺序
  (打印 obs 段 vs 真值 site 对比, 别信注释)。

## 盯住目标跨位姿记「目标 ↔ tool1」关系: 先判谁在动, 再谈标定

现场常有人一边拖臂一边说"你保持看着目标, 记住相机看到的目标和 tool1 的位置关系" —— 这一步要交付的是**判定**, 不是一张均值表。

- **记录一条流**: 每帧写 `ts · tcp(xyz+abc) · 目标中心 base · 目标在 tool1 系 = Rᵀ(p−t) · 到相机距离 · 2D 框 · conf`,
  3Hz 够(读 `/pose` + 取一帧 + 一次检测 ≈0.3s); 落 JSONL, 另写一个 live summary(计数/极差/末条)给终端随时看。
- **归属判定(最硬的判据)**: 目标若**固定在台上**, 臂移 Δ 后它在 tool1 系的坐标必须跟着变 ≈Δ。
  若几乎不变(**实测工具移 20mm, 目标在 tool1 系只变 1.6mm**, 同时到相机距离恒定 159±3mm、框高几乎不变)
  ⇒ 目标**刚性固定在工具/相机一侧**(夹在爪里/装在工装上), **不是**台上的工件。
  这时不许把"(110, 5, 5)mm"当标定结果交出去, 要把它当**发现**报: "相机看到的那只是跟着工具走的, 不是台上那只"。
- **按位姿分组统计, 绝不混着求均值**: 同一静止位姿 n=175 → std (0.33, 0.11, 0.54)mm(可信);
  混进斜视位姿后同一目标 std 涨到 ~13mm, 均值没有意义。报数一律带"位姿段 + n"。
- **斜视会毁掉尺寸反解**: 用框高反解距离时, 20mm 的位姿变化就够让 d 从 159→153mm,
  tool1 坐标随之从 (110, 5, 6) 漂到 (92, 27, −25) —— 那是视角误差, 不是关系变了。
  ⇒ 只采"相机大致正对目标"(d 落在窄带内)的样本, 或先把深度补上再跨视角。
- **检测器会偷偷换目标**: 大范围位姿下它可能锁到远处别的东西(实测 683 条检测里 61 条 d>800mm)或干脆漏检(186 条)。
  ⇒ 报告给**距离直方图 + 漏检数**, 只对窄带样本下结论; 别把整段的 base 极差解读成"目标被挪了 800mm"。
- 用户会追问"换了位姿看到了么" ⇒ 直接回**位姿清单 + 数字**(走了几个不同位姿 / TCP 行程 / 各段 n), 别叙述过程。

## 投影链的坐标系: 先把"要画的点"落到 base, 再谈投影 (零运动可自检)

真几何投影链只有一条: `p_base --(实时 TCP 位姿)--> p_tcp --(手眼 X)--> p_cam --(内参 K)--> (u,v)`。
所以**任何要叠到真机画面上的物体都必须先在机器人 base 系里**; 这一条不满足, 后面全白做。

- **仿真/引擎世界 ≠ robot base**: 引擎侧那套坐标(metaworld 名义布局)与真机现场差得不是一个原点。
  实测同一工位: 引擎光模块抓取点 (0.0966,0.5191,0.030) vs 真机示教一号位 (0.6488,0.4983,0.1104)
  ⇒ x 差 **0.55m**、离底座半径差 0.29m。直接投 = 框飞到天涯。
- **闭合路径**: 现场把臂拖/示教到对应位置再采一次(`ss_geom_calib.py --record peg_head|goal|aoi`, 零运动),
  产物落 base 系(`frame:base_link`)。**标定本身不是我下发运动** ⇒ 现场有人时是最便宜的闭合(30 秒),
  把命令原样交给现场; 没闭合之前宁可不画, 也不要自己编一个映射。
- **固定相机(笔记本内置/顶摄/工位相机)只要一次 `T_base_cam`**(装好就不动), 不需要实时 TCP;
  只有腕上相机要每帧位姿。没标定的路要**如实说"未标定"**, 不画"差不多"的框。

### 基座系的方向约定 + 把三轴标到图上 (用户问「vx vy vz 的原点方向怎么定义」时)

回答前先把坐标系钉死，再谈数值——这类问法通常是在看图核对，答错一个符号他就判不可用：

- **默认是基座(世界)系，不是工具系**。原点 = 机器人底座；**z=0 = 台面上表面**（台面中心 z=-0.012、厚 0.024）。
  X+ = 沿台面长轴、**离开孔/目标位**的方向（本机：孔口 x=-0.1685、AOI 对焦点 x=+0.12 ⇒ **插入 = −X**）；
  Y+ = 从机器人朝台面外侧（台面中心 y≈+0.58，底座 y=0）；Z+ = 竖直向上。
- **符号自检（比读代码快）**：取一帧“抬起”阶段 ⇒ z 分量必为正（实测 +138.89 mm/s）；朝台面外移 ⇒ y 为正；
  插入段 ⇒ x 为负。三个都对上才敢说速度分量与场景几何同系；对不上先查是不是某个视图自己换算了坐标。
- **画轴三件**：①图层开关默认要**开**（默认关＝用户“看不到轴”的唯一原因）②轴长收到 0.1~0.2 m，否则满屏长线
  ③轴端必须用**文字**标 `X+ 离孔位` / `Y+ 朝台面外` / `Z+ 竖直向上` —— 只给颜色用户分不清哪根。
  pyqtgraph 固定配色 X 蓝 / Y 黄 / Z 绿，别自创。
- 🔴 **原点常在画面外**（原点在底座，自动取景/俯视档会把它裁掉，只剩一截线）⇒ 在目标（孔口）旁再加一套
  **同向小三轴**（纯平移，不是第二套坐标系），任何机位下都有一套完整可见，并在图注里写明“两套平行、同一坐标系”。

### 标定素材先清点 —— 派生点不是观测点
- 示教点库里往往只有极少数**真实现场示教点**; 其余
  (`loop20_*` / `afx30_*` / `afx50_*` 之类)是 `make_abs_path.py` 从同一次采样派生的 ±20/30/50mm 偏移
  ⇒ 它们**不独立**, 拿去拟合只会得到"看起来很好"的假精度。
- **共线点集拟合单应会退化**: 只有 2 个槽位(相距几十 mm)时别拟合, 至少要 ≥4 个**非共线**已知点。
- 零运动可用的锚(优先级): ①现场示教的孔位/槽位(取非共线 ≥4) ②**臂自身的关节中心** —— base 系里由 URDF FK
  已知、且臂在画面里可见 ⇒ 直接 PnP(像素读点 ±10px ⇒ 米级距离下 cm 级外参误差, **必须报残差**)
  ③规则阵列(已知节距 + 正交等距假设) ⇒ 必须用**多余点**验证, 残差大就说明假设不成立。

### URDF FK 自检(判据很硬, 零运动只读)
```
关节真值: ros2 topic echo --once /robot/joint_states   (frame_id=base_link)
         容器里必须先 source /opt/ros/humble/setup.bash, 直接 bash -lc "ros2 ..." 会报找不到 ros2
FK      : tools/robot_spec_sync.py 的 parse_urdf + serial_chain + fk_from_chain(chain,q,upto=<link>)
         逐关节把 upto 取到各自 child link ⇒ 得到关节原点在 base 系的位置
判据    : FK(link6) 与 /robot/tcp_pose 真值之差 == control_tcp_offset_m(0.2604m, 实测 261.9mm ✓)
         加工具偏置后的残差才是仓库记的 ~3.5mm; 差不到这个量级 = URDF/关节顺序读错, 别往下用
```
- ⚠️ URDF 路径: worktree 里 `config/robot/xms5_*.urdf` **常常不在**(URDF 不进代码库) ⇒ 依次找
  `config/moveit_xms5/urdf/…`、共享检出(`lerobot-smolvla-lew/config/robot/…`); 唯一依据是 `/robot_description` 话题。
  硬写模块里的 `URDF_DEFAULT` 会直接 `FileNotFoundError`。
- 验收口径: 用**已知 base 坐标的点**投回该相机画面, 与图上实检位置比像素差(报中位 + 最大);
  近似外参必须在画面真值带里标明"未标定/近似"与残差, 不然用户会把画面当结果。

## 分割掩膜 → base 系 3D: 能给什么 / 给不了什么 (被问"这模型能不能做位姿/3D 引导"前必读)

链路只有一条: 上游给提示(区域框/掩膜) → 分割模型出**像素掩膜** → 掩膜内深度反投影(深度=沿光轴 z)
→ 手眼 X → 实时 TCP 真值 → base 系中心 + 足印长宽 + 平面内 yaw + z 分位。
⇒ **分割模型本身不做位姿**: 它只交 2D 掩膜; 位姿精度由**深度噪声与掩膜边界**决定, 不由分割模型决定。

- **能给**: base 系中心点 / 足印长宽 / 平面内朝向 与 z 分位 ⇒ 够抓取规划、粗定位、来料/异物分割区域。
- **给不了** (别越界承诺): ① 6D 位姿 (无绕 x/y 倾角估计); ② 对称件 yaw **180° 歧义** (主轴法 minAreaRect);
  ③ 单目+深度尺度 mm 到 ±20% 视深度质量; ④ **逐帧不可能** (单次 0.4~0.44s) ⇒ 只做触发式/关键帧,
  毫米级最终仍靠视觉伺服/接触锚定收口 (见上文"测量→控制信任切换")。
- **必须如实拒答的四种情况** (不许猜填, 不给"差不多"的框): 深度源龄超阈 / 掩膜内有效深度像素太少 /
  手眼标定不可用 / TCP 真值读不到; 另加**非腕上相机**——本机相机无手眼外参, 3D 掩膜只对腕上深度相机成立。
- **别让模型自己"找料"**: 开放词汇的**文本**提示在现场域极不可靠 (实测同一活帧三个领域词全 0 实例)
  ⇒ 提示必须来自上游 (检测器 / 示教位置 / PLC 触发区域), 模型负责**出掩膜**, 不负责发现目标。
- 取证图必须**自己带状态** (用户会把画面当结果): 多边形描边 + 顶部深底白字横幅写清
  「模型口径 · center_base/z/尺寸/yaw · 掩膜px·深度龄·手眼闭环残差·推理ms · 抓帧时间与帧龄 · 提示来源」。
  中文字体用 Noto CJK (`fc-list | grep -i cjk` 确认), 否则中文横幅变豆腐块。
- 细节与可跑探针: `references/mask-to-3d-guidance.md` + `scripts/probe_mask3d_evidence.py`。

## 深度不可用时: 视线与台面求交 (像素→base 的保障口径)

1. **先判深度到底有没有, 再决定能不能报毫米**: 容器里 `ros2 topic info <depth topic>` 看 **Publisher count**
   —— `0` = 只有订阅者在白等(实测 `/realsense/depth/image_rect_raw` 订阅 1 / 发布 0), 这时落盘 npy 会一直
   停在旧时间戳(本机 `/out/zmax_scene/depth_raw.npy`, 宿主对应 `zmax_data/ss_live/zmax_scene/`, 实测停 3 天)。
   **文件龄 + Publisher 0 = 通道死**, 别拿它算毫米级坐标; 只有彩色发布节点在跑, 不代表深度也在跑。
2. **无深度时的两条保障, 先验平面必须是对的那个平面**:
   ① **视线与已知平面求交**: `p_base = 相机光心 + t·d_base`, t 由 `(z_plane − o_z)/d_z` 解出。
   🔴 `z_plane` 不能想当然取 `z=0`: 本机 base 系里 z=0 是底座安装面/台面上表面, 而**工位孔位在 z≈190mm**
   (`config/calib/zmax_calib.json` → `cell_geometry.points.hole` = (757.5, 227.9, 190.1) mm, 另有 `hole_retract`)。
   判据: 交出来的点与**已知工位点**(孔位/槽位/示教点)差 >100mm ⇒ 目标**根本不在那个平面上**
   (实测同一支光模块, 用 z=0/100/150/190/250 求交, 与孔位差 133~208mm 全都对不上 ⇒ 它不在插孔处而在别处料盘里)
   ⇒ 此时**不要发布这个坐标**, 改走 ② 并如实说"位置依赖假定平面, 与孔位不符"。
   ② **已知件尺寸反解距离**(无平面、无深度时的唯一自洽解): `d = f · H_mm / h_px`(H = 工件真实长轴, h_px = 检测框像素高),
   再用**宽高比**自查: 像素比 `w_px/h_px` 与实物比 `W_mm/H_mm` 必须接近(实测 27/122 = 0.22 vs 13.4/56.5 = 0.24 ✓ ⇒ 尺寸假设成立);
   两个轴各自解出的 d 相差 >10% ⇒ 尺寸猜错了, 别用。
   产物必须写明「平面估算 / 尺寸反解 · 非实测深度 · ±5~20mm 量级」, 不许当抓取坐标交付;
   但**做画面叠加完全够用** —— 在相机系里以该 d 建一个立方体再投回像素, 框会精确贴住检测框(见 camera-extrinsics-calibration)。
3. 🔴 **单位坑(静默错, 最容易骗过人)**: 手眼 `handeye_state.json` 的 `T_cam2tool` 平移是**米**
   (`t_mm=[214.7, 12.5, −115.3]`), 而 TCP 位姿是**毫米** ⇒ 拼 `T_base_cam = T_base_tool @ T_cam2tool`
   前先把平移 ×1000。**判据: 相机光心到 TCP 的距离应 ≈ |t|(本机 244mm); 若光心坐标与 TCP 一模一样,
   那就是漏了换算**(0.215m 被当 0.215mm 加进去, 只剩 ~0.2mm)。旋转部分不受影响 ⇒ 框位"看着差不多",
   只有反投影到米级距离才现形 —— 每次反投影都先打这一行自检。
4. **竖直目标用框底端像素, 不要用中心/顶端**: 顶端像素的视线从目标**上方掠过**, 打到的台面在目标之后
   (实测同一支 122px 高的光模块: 底端落点 x=730mm、中心 640mm、顶端 566mm, 顶端比底端远 164mm)。
   与台面/工装接触的那一端才对应真实落点。
5. 深度不可用时的最低可信度: 让**两个独立来源**对同一目标收敛(在役 YOLO 框 + 视觉模型框重合)再报坐标,
   否则只报 2D 框并说明"拿不到深度"。
6. 在役检测器的**类名与业务名不一定对得上**: 本机 `models/yolo_peg_live.pt` 只有 `peg` / `OPT_Gold` 两类,
   而那支半插在料盘竖槽里的光模块(**银色金属壳体 + 顶端绿色拉环**)被稳定判成 `peg`(conf 0.80),
   `OPT_Gold` 一次都不命中(conf 降到 0.05、imgsz 提到 960 也一样; 画面里的"金色"只有 PCB 焊点) ⇒
   认工件按**框 + 外观**核, 别按类名或"金色小方块"去找。

## Pitfalls
- 🔴 **反投影链不要自造, 先搜唯一依据实现**: `grep -rl 'bbox_base_mm\|depth_scale_mm_per_unit' --include='*.py' .`
  找到写这个 stats 的那份代码, 把 `DEPTH_SCALE` / **有效深度阈值** / 手眼方向 / 四元数顺序逐项对齐。
  实测漏掉唯一依据的 `z > 0.05`(米) 阈值、只写 `z > 0`, 近距飞点被反投影 ⇒ bbox 从
  `Z[-1224,337]` 撑到 `Z[-3322,1158]mm`(代码「看着完全对」, 只有 bbox 离谱)。
  点云/建图类交付的完整细节(离群点剔除、栅格化、地图服务)见 `depth-cloud-map-service`。
- 🔴 **手眼矩阵的**键名**不等于方向**: `handeye_result.json` 的 `T_base_cam` 平移值与 `stats.json` 的
  `X_t_mm` 完全相同 ⇒ 它实际是**相机→末端**的手眼 X, 不是 base←cam。
  判据 = 拿一个已知量对一对(此处: 两处平移数值是否相等), 而不是读名字。
- 反投影前不核手眼平移单位(米 vs 毫米) ⇒ 相机光心正好落在 TCP 上: 判据就是"光心==TCP"这一行自检。
- `_overlay_info.<cam>.tcp_ok=false` 时该路框数静默为 0(看着像生成器没干活): 投影要实时位姿 ⇒
  先看 `tcp_ok`/`origins`/规格龄, 再怀疑生成器。
- 拿派生路点(±20/30/50mm 偏移)当标定点 → 外参"看着很准"实际是自欺。
- 用 2 个共线示教点拟合平面单应 → 欠定/退化, 投出来必然偏。
- 深度分位扫描实验先去掉 NaN 再排序, np.percentile 遇全 NaN 报 IndexError。
- YOLO 类名被覆写 (peg→光模块) 后, 按类名匹配检测结果会永远 False — 匹配业务名或类 id。
- GUI/长驻进程 import 模块缓存旧代码 → 改了源码必须重启进程才生效, 排查"改了没效果"先查这个。
  🔴 且机器上可能**同时跑着多份实例**(手工/IDE 起一份、重启脚本再起一份), 用户眼前的窗口常属于**旧的那份** ⇒
  `wmctrl -l -p | grep <标题>` 拿窗口 pid + `ps -o lstart=` 比提交时间, 确认不了“他看的是新实例”就别说修好了。
- 单帧探针 (reset 后静态帧) 与运行期 (执行器移动) 的定位误差可差 1-2 个数量级 —
  评估必须沿真实轨迹多帧采样。
