# 真机检测器域适应 → 上线闭环 (live-camera detector adaptation)

适用: 生产相机 (UVC/ROS/落盘帧) 上跑 YOLO 类检测器, 用户口径是"**我要在实时画面里看到这个目标**"。
本手册来自一次真实闭环 (仿真域权重真机 0 检出 → 真机微调 → 实时管线每帧检出 conf 0.91)。

## 0. 铁律: 先量在役权重, 再谈训练

"看不到目标"最常见的根因**不是接线**, 而是**在役权重是仿真/其他域的**。
先做一张同口径基线表 (同一批新鲜真机帧 × 每个候选权重), 用数字定位, 别猜:

| 权重 | 真机帧检出 | conf | 结论 |
|---|---|---|---|
| 仿真域生产权重 (一直挂在管线上) | **0/17** | — | 这就是"看不到"的直接原因 |
| 域随机化混训 | 0/17 | — | DR 不能跨到产线真机 |
| 真机微调 10 轮 | 0/17 | — | 轮数不够, 未收敛 |
| 真机微调 100 轮 (中途被杀, 只到 epoch 51) | 17/17 | 0.649 | **已经可用**, 只是没接进管线 |
| 真机微调 250 轮 + 去重数据 (上在役) | 17/17 | **0.914** | ✅ |

教训: 用户"点过训练但没反应"的那一轮, 往往**已经训出能用的权重**, 只是 (a) 权重没上在役
(b) 训练被连杀 (见 §4)。先查产物与在役指针, 再决定是否重训。

## 0·补、"无检出" 是**阈值口径**, 不是"画面里没目标" —— 报结论前先出阈值响应表 (2026-10-15 实测)

现场口径 "在役 YOLO 在活帧和 60 张历史帧上 ndet 全 0 ⇒ 定量视觉证据为空" 会误导。
同一帧 (本机 `8791/local2`, 1280x720, 灰度均值 115.8 = 曝光正常) 上在役权重
`models/yolo_peg_live.pt` (peg/OPT_Gold) 实际**有**目标, 只是分数被域偏移压到 0.2 附近:

| conf 阈值 | ndet | best | 用途 |
|---|---|---|---|
| ≥0.01 | 11~12 | 0.219 | 原始分布 |
| ≥0.05 | 2 | 0.219 | |
| ≥0.10 | 1 | 0.219 | |
| ≥0.15 | 1 | 0.219 | 建议的"弱非空"下界 |
| ≥0.25 | **0** | — | `ss_meta_task_predict.py` 用的阈值 ⇒ 报"无检出" |
| ≥0.40 | **0** | — | `ss_yolo_on_real.py` 在役默认 ⇒ 报"无检出" |

规矩:
- 报"无检出"**必须**先跑本项目 `tools/yolo_threshold_response.py --img <帧>`(或 `--dir <目录>`, 支持 png/jpg)
  出这张表, 结论按置信度分段: **强 ≥0.4 / 弱非空 0.15~0.4 (必须带 conf 才能说"看到") / 空 <0.15**。
- 同一模型**不同相机/分辨率差异巨大**: 训练用真机评测帧 (640x480) 同期最高只有 0.015~0.062 (确实空),
  而 1280x720 工位帧有 0.219 ⇒ 别把两路混成一句话、别用一路的 0 去否定另一路。
- 判"**曝光 vs 现场灯**"用同刻的另一路相机: 实测 8791/local2 均值 115.8 有内容, 而 local / 10083 均值 0.0~6.0
  ⇒ **不是现场没光, 是那两路相机自身的曝光/驱动状态** ⇒ 先抬曝光(可逆) 而不是等现场灯。
- 黑帧 + 低分同时出现的处置顺序: ① 抬曝光把画面救回来(必要不充分) ② 域适应微调权重(§1~§4)
  ③ 口径改成带 conf 的三段 —— 否则 0.219 的真检出会被当成"什么都没有", 把域偏移误判成"没目标/没接线"。

## 1. 四步闭环 (每步都要落盘证据)

1. **量基线** —— 专用评测脚本 (本项目: `tools/yolo_live_eval.py`):
   采 N 张**新鲜**相机帧 (按 mtime 去重, 只认真帧) → 逐权重统计 检出帧率 / conf(mean,max) / 框坐标,
   出 JSON + **画框图** (人工目检); before/after 必须同 imgsz、同 conf 阈值、同帧来源。
2. **建数据** —— 标定目录 → 数据集构建器 (本项目: `yolo_annot_dataset.build_dataset()`);
   **必须去重** (同 md5 只留第一张): 重复帧会同时污染 train/val 两侧, 并让体检永远告警
   (实测 26 张里 8 张是重复保存的同一帧)。
   🔴 **去重过了不等于数据可用 —— 建集前必须先过「多样性闸」**: md5 唯一 + 帧差阈值**都能通过**,
   而整批其实是**同一张图**。实测连采 120 帧: md5 **120/120 全唯一**、相邻帧差 2.09 (远超 0.3 阈值),
   但**与首帧归一化相关系数 0.999**(最小 0.992)、`mean` 跨度仅 **1.95**、锐度 193~198
   ⇒ 全是同一工件同一姿态, 只差传感器噪声。用它训出来的任何指标都是假的。
   三条一起量, 任一不过就判「这批不能训」:
   - **与首帧的归一化相关系数** ≥0.99 ⇒ 同一张图;
   - 整批 `mean` / 锐度(`Laplacian.var`)**跨度**过窄 ⇒ 无光照/姿态变化;
   - 目标**位置/尺寸**的跨帧方差接近 0。
   ⇒ **md5 与帧差只能证明「帧不是逐位相同」, 证明不了「内容不同」—— 噪声就能让它们全过。**
   ⚠️ 帧差阈值要**先量噪声底再定**: 实测全黑帧的帧间差就有 **0.26**(纯传感器噪声),
   把阈值设在 0.3 等于只筛掉逐位重复的帧。
   发现是同一张图时: 如实拄「现场工件未变, 采不到多样化样本」, **不要用增强/复制把它凑成数据集** ——
   那只是在同一张图上过拟合, 指标好看但零泛化。正确交付是「标注/训练管道已就乡 + 明确的采件需求单」。
   **多批数据合并成一套时, 四个坑**:
   - 🔴 **目录存在 ≠ 数据存在**: `data/datasets/<name>/` 下可能只有 `data/ meta/ videos/` 空骨架
     (文件数 0, 但 `ls` 看着很像有数据). 用 `find <dir> -type f | wc -l` 数文件, 别看目录名.
     真数据常在 `zmax_data/` 下(如 `sim2real_dr/<date>/dataset/yolo_*`、`demo_*` 的多路相机帧).
   - 🔴 **软链合并时同名文件会被静默覆盖**: `ln -sf` 两批源数据若图片同名, 第二批直接替掉第一批
     —— 实测 9,000 张被盖成 0 张, 而 labels 数对得上, 只看总数发现不了.
     **每批加前缀**(`dr_` / `drmix_`), 且 **images 与 labels 用同一前缀**; 合并后核对
     `imgs == labels == train + val` 三个数.
   - 🔴 **基座权重的类别表必须与数据一致**: 在役 2 类权重(`{peg, OPT_Gold}`) 不能续训 3 类数据
     (`hand/peg/hole`) —— class id 错位. 类别数不同就从 COCO 基座重训, 别"接着训".
   - **val 只能用 holdout 那批**: 别把 train 的同一批再塞进 val(实测重复塞了 9,000, val 虚高成 9,600,
     mAP 就是对训练集的度量).
   ETA 标尺: 18,900 张 / imgsz 640 / batch 16 在 8G 级显卡上约 **140s/epoch** ⇒ 30 轮 ≈ 70 分钟;
   首轮前有数据扫描开销, 用 1 epoch 的 `ZMAX_*_EPOCHS=1` 小跑先验链路和显存, 别直接上全量.
3. **训** —— 微调而非重训: 基座 = **真机在役权重** (域适应接着走) > 最新产物 > 仿真域权重。
   `imgsz` 要 ≥ 真机帧长边 (真机 640×480 而仿真权重按 480 训 → 细节被抹掉), 早停 + 余弦 LR,
   小数据集开 cache。本项目: `tools/yolo_annot_train.py --epochs 250 --imgsz 640 --patience 60 --detached`。
4. **上线判定** —— 训练脚本**内置**训练后真机帧对照 (新权重 vs 在役, 训练后新采的帧):
   有提升 (检出率↑ 或 conf↑) 才上在役; 持平/回退按纪律**不上默认档**, 只留 opt-in。

## 2. 权重单点指针 (升级只改一个链接)

把"当前在役权重"做成一个符号链接 (本项目 `models/yolo_peg_live.pt` → 当前 best.pt),
让**所有消费方**都读它: 实时管线脚本 / GUI 叠加显示 / 训练脚本的 `--base auto`。
否则每次升级都要改 N 处硬编码, 必然漏 (本项目原先 3 处各写死一个旧权重路径)。

## 3. 域别隔离: 真机权重 ≠ 仿真权重 (最容易犯的错)

先把检测器分成**两个入口**, 别共用一个候选表:

- **仿真/引擎帧链** (渲染帧 + 2D→3D 解算): 用仿真域权重 (多类, 如 hand/peg/hole)。
- **真机帧链** (相机落盘帧 + 旁路可视化): 用真机域权重 (常是**单类**, 且是真实分辨率/域)。

**不要把真机域权重塞进仿真链的候选表** —— 真机域模型在仿真帧上 0 检出、类别数也可能不同
(class id 错位), 一改就把仿真链打回退。本轮实测差点踩: 所幸在写库前按"同时服务仿真"纠正了。

## 4. 起训练: 必须脱离启动者的 cgroup

从 GUI 里 `nohup ... &` 起的训练**不是独立进程**: 它与 GUI 同属该 systemd 服务的 cgroup,
systemd 默认 `KillMode=control-group` → **GUI 一退, 整组子进程被杀**。
实测: 控制台点「训练 YOLO」起的 100 轮训练, GUI 退出后 16 秒 (epoch 51) 静默死亡 ——
**日志无 traceback、GPU 立刻空载、pgrep 查不到**, 极易被误判成模型/数据问题。

```bash
systemd-run --user --collect --unit <job> --working-directory <repo> bash -lc '<cmd> > <log> 2>&1'
systemctl --user status <job> ; journalctl --user -u <job> -f
```
脚本里加 `--detached` 做**自我重入** (主进程起完单元立即返回, 否则 GUI 阻塞等待)。
判断独立性: `ps -o pid,ppid,args -p <pid>` —— 真独立的是 `systemd --user` 下的 `<unit>.service`。

## 4·补、相机被服务独占时: 检测要做在**持有相机的那一侧** (2026-10-11 实测)

RealSense D435(以及多数工业相机)是独占设备: 谁起了 pipeline, 别的进程再开就 `Device or resource busy`。
实测症状: `tools/ar_calib_module.py detect` 单独跑报「没有帧 / xioctl(VIDIOC_S_FMT) failed, errno=16」,
而在**持有相机的 AR 服务进程内**调同一个 `detect()` 立刻拿到结果。
⇒ 规矩: 相机由常驻服务持有时, 检测/取帧**不要另起进程**, 而是在该服务里加端点(本项目 `GET /api/rs_detect`),
把「在役权重 + 深度反投影」封装在同一进程里; 外部工具(标定脚本/CLI)只调端点。

## 5. GUI 交互坑 (检测器接入可视层时)

- **叠加框绝不能污染存档**: 画框要在**显示副本**上; 保存训练样本必须用**原始帧**变量
  (本项目 `self._rgb_raw`)。否则"框烧进像素"的脏数据进训练集, 而且越训越糊。
- **共享帧文件一律原子写** (`open(tmp,"wb")` + `flush/fsync` + `os.replace`): 落盘方 10Hz 覆盖写,
  读者 (窗口 / 旁路 / 取证脚本) 会撞上**半张 PNG** (实测 `cp` 出 0 字节; 最坏把窗口读崩)。
- **PIL `im.save(path)` 按扩展名猜格式** → 原子写用 `.tmp<pid>` 会报 `unknown file extension`
  → 必须 `im.save(tmp, format="PNG")`。
- **读图别把坏数据交给 Qt**: 先整块读入内存再 `cv2.imdecode`; cv2 可用时它就是权威 ——
  解不出直接返回 None, 不要再 fallback `QtGui.QPixmap(path)`。
- **检测失败/无帧都要如实显示**: "无检出"和"链路不通"是两件事; 不允许用旧帧或占位图冒充实时
  (本用户红线, 会目检画面细节)。
- 用户在窗口里点按钮后**窗口内必须有结果回显** (按钮只把日志打进别处 = 用户报"点了没反应");
  后台长任务要在窗口里给进度行 (从产物文件读真值, 不编造)。

## 6. 数据量 vs 域适应 (别夸大)

## 🔴 送检图必须先摆正、且**不过曝** —— 过曝会把缺陷直接冲掉 (2026-10-20 同姿态对照实测)

"检测器报 0 缺陷"最常见的两个前置原因,**都不是模型**: 目标在画面里是**斜的**, 或目标**过曝**。
同一个工件、同一角度、只改曝光档的对照(生产端 YOLO, 摆正整幅图):

| 送检图 | 模块 ROI 死白 | 工控机 YOLO |
|---|---|---|
| 摆正 + 48000us | **90.74%** | **0 缺陷** |
| 摆正 + **3000us** | **1.72%** | **1 缺陷** `housing_pit` conf 0.473 |

⇒ 报"无检出"之前,**必须先给"送检图不过曝"的证据**(模块 ROI 死白率), 否则你报的是曝光问题冒充模型问题。

🔴 **反过来的错误同样常见 —— 别用几何判据的失败去否决检测**: 同一个生产服务里,
**几何量测**(靠"找到过曝亮条 → 上边缘 → 台阶"量厚度)与**缺陷检测**(YOLO)对曝光的要求是**相反**的。
实测同一档位下 `judge_ok=False`(亮条上边缘点太少) 而 YOLO 正常检出缺陷;
换到过曝档 YOLO 又变 0 缺陷而几何判据能跑。
⇒ 两条路各定各的档、各看各的判据。看到 "judge_ok=False" / "测量失败" 就断言"检测不能用",
或者看到 "检测 0 缺陷" 就断言"画面没问题", 都是把一条路的结论套到另一条路上。

**曝光按模块 ROI 扫, 不按整帧**: 高反差台面(工件只占画面几个百分点)下整帧 mean 会被黑背景拉低给出**反向结论**。
实测同一表面的死白率随曝光**单调恶化** —— 48000us 90.74% / 12000us 76.11% / 5000us 19.30% /
**3000us 1.72%**(mean 110 仍有细节) / 2000us 0.21%(mean 73, 细节开始丢 ⇒ 过头)。
**别把"5000us 已经很低了"当极限**, 继续往下降到 ROI 死白进 5% 才叫够。选档取"死白达标档里 mean 最高"那一档。

**摆正送检只旋转不裁剪**: 检测器的训练输入通常是**全幅 letterbox**(如 1280x1280), 送一张 1100x190 的长条裁剪图
等于换了输入分布。做法是绕目标中心把**整幅原图**旋正、画幅不变, 这样既摆正了又保住原分布。

**几何与像素可以不同曝光**: 低曝光下背景全黑反而**更容易**搜出目标刚体(对比强), 正常曝光下 Otsu 可能整个失效 ——
实测 48000us 时 Otsu 前景占比 **1.000**(目标与台面糊成一片, 搜出的是 1717x1269 的台面), 而 5000~3000us
能干净搜到 **1100x188** 的模块。若两档都要, 就"低曝光定几何 → 正常曝光取像素 → 同一角度旋转";
若单档够用(3000us 实测直接能搜到 1095x188)就别来回切档(切档每次要等 ≥1 帧, 白费节拍)。

**刚体搜索必须加长宽比闸**: 目标(如光模块)是扁长的(实测 5.8~6.8:1), 台面/夹具接近方形(1.88:1)。
只按面积筛会把台面当刚体, 摆正就对着台面转、整张判据图全错。闸值取 `aspect ≥ 2.5`, 并在输出里打印 `aspect` 便于复核。

## 🔁 拿不到模型/权重时: 借**生产端进程**的检测能力, 不要把"没有权重"当终点

生产端权重常是**加密的**(如 `.pt.enc`)且解密器只装在那台机器上 —— 本机既无权重也无加载器,
但**仍然可以用它的检测器**: 只要那台机器上有反向通道(本项目 `tools/agent_hub.py`, 生产端跑一个
每 3s 取命令的 PowerShell 循环), 就能把一张图送过去、让它用自己的 venv python 跑 `detector.detect(path)`。

三个必须处理的坑:
1. **反转义**: PowerShell 里嵌 python 代码的引号会互相打架 ⇒ 把脚本 **base64** 编码、PowerShell 侧解码写临时文件再执行。
2. **解释器路径**: 生产机上 `python` 常不在 PATH。从**正在跑服务的进程**里取真路径:
   `Get-CimInstance Win32_Process | Where {$_.Name -like '*python*'} | ForEach { $_.ProcessId.ToString() + ' :: ' + $_.ExecutablePath + ' :: ' + $_.CommandLine }`
3. **回执必须按 mtime 过滤**: 输出目录里的"最新文件"很可能是**上一轮**的结果。实测踩过 ——
   读到的是上一次 probe 的 `saved_incoming`(时间戳早于本轮 2 分钟), 差点当成这一次的判决。
   入队前先记 `max(mtime)`, 只认比它新的文件, 再在里面找结果标记行。

⚠️ 生产端检测器**有类别表上限**: 实测外壳模型只有 4 类(如 `housing_pit` 凹坑), **没有划痕类**。
用户目检说"表面有划痕"而模型报 `pit` ⇒ 那不是漏检, 是**类别缺失** ⇒ 要么扩类重训, 要么划痕走本机算法。

具体命令与完整脚本见 `references/plant-side-detector-invocation.md`。

## 🔍 划痕/线状缺陷: 形态学候选 ≠ 检出结论, 交付时要说清

线状缺陷(划痕/刮伤)与斑点(凹坑/污点)的判据不同, 通用"局部异常"算法会把**棱线**全报成缺陷:
- 用 黑帽(暗细线) + 顶帽(亮细线) 两个通道, 再乘 **4 方向线形核开运算**取最大响应(划痕有方向, 斑点各向同性)。
- 典型误报与对应闸: ① **贴边超长条**(实测 930x12 aspect 77)= 目标上下棱线 ⇒ 排除 `edge_margin` 内的连通域;
  ② **1px 细线**(大量)= 压缩/纹理伪影 ⇒ 宽度下限 2px;
  ③ **低对比线** ⇒ `min_contrast ≥ 40`; ④ aspect 上限(如 80)挡掉跨幅棱线。
- 阈用**稳健 z 分数**(median + 1.4826·MAD), 不用固定灰度阈值(光照漂移下不稳)。
- `cv2.minAreaRect` 要**轮廓点**(`findContours` 的返回值, CV_32F/CV_32S), 直接传 uint8 掩膜会抛
  `(-215) total >= 0 && (depth == CV_32F || depth == CV_32S)`。

🔴 **交付口径**: 这类算法给出的是"候选", 不是"检出"。没有 ground truth、也没有看图能力时,
**不要**把候选当结论报给用户。正确做法是出**放大图 + 每条候选的编号/长/宽/长宽比/对比度**,
请用户指认哪条是真缺陷 —— 那条才能当模板或训练样本。这一条对本用户尤其重要(他目检画面、要求真实性)。

### 📏 划痕"画得太短" = 连通域把一条长划痕切成了多段

连通域是按"当前对比度连续"切的。一条长划痕只要中段有一处亮度过渡/反光就会断成 5~8 段,
算法随后**只捡最亮那一段当成整条** —— 实测报 78px, 而实际那条横贯目标 **1096px 里的 830px(76%)**,
用户一眼看出"你画的太短了, 这条划痕非常长"。

**纯直线的缺陷要用 Hough 共线接续量全长, 不要用连通域外接框**:

- `cv2.HoughLinesP(bw, 1, π/180, threshold=25, minLineLength=60, maxLineGap=60)` —— **`maxLineGap` 是关键**,
  它跨过亮度断点把断开的线段接回同一条直线; 连通域法按对比度断, Hough 按共线接, 这是本质差别。
- 预处理侧再给方向增益: 先 黑帽/顶帽(去光照不均), 再用**水平长核**(41 / 101)闭运算强化该方向。
  几种核都跑、取最长, 别只押一种(不同核接续长度差很多)。
- 🔴 **Hough 会把棱线排在真缺陷前面**: 目标上下沿横贯整幅(实测 `y=0 长985` / `y=186 长1094`),
  永远比真划痕长。必须**先排除距上下沿 <8px 的直线**再排序, 否则第一名永远是棱线。
- `cv2.HoughLinesP` 返回形状随版本变(cv4 `(N,1,4)` / cv5 **`(N,4)`**) ⇒ 用
  `np.asarray(L).reshape(-1)[:4]` 解析, 别写 `L[0]` 解包(会 `'numpy.int32' object is not iterable`)。
- **端点稳定性不等**: 起点通常很稳(两次 179 / 182), 末端常不稳(1009 vs 878, 差 131px) —— 划痕往远端对比度衰减,
  接不接得上随机。首轮如实报"区间 X~Y px"而不是假装一个精确值; 要定死末端就做**多参数一致性**
  (核 41/61/101/141 × `maxLineGap` 40/60/90 各跑, 取端点分布的稳健上界)。
- 输出换算成物理量更好读: `划痕长 / 目标宽 × 实际件长` = 约 X mm(占件长 N%)。件长口径要问用户或查图号。

**工作流(用户已指认时最快的路)**: 先出带编号的候选放大图 → 用户报"第 N 号最严重" → 以该候选的
`xywh` 当种子, 取种子中心所在行带 ±(目标高)±12px 范围, 在里面跑 Hough 只认"覆盖种子 x"的最长直线 ⇒ 得到全长。
之后改成 `seed=None` 全自动(排除棱线后取最长)复跑一遍, **必须复现同一位置**(实测两次 y≈93/94),
位置复现才说明判据可靠, 长度区间不一致要如实说。

固定工位场景下, **20 张级真机标注**就足以把该工位的检出做到 conf 0.9 —— 域适应比数据量更关键。
但: 小样本的 val (本项目 val 仅 2~4 张) 的 mAP **不能当泛化证据**; 泛化到不同姿态/位置/光照仍需
100+ 张。交付话术按此分层: "本工位已检出 (真机帧 17/17, conf 0.91)" ≠ "泛化了"。

## ⚠️ 先定缺陷**形态**再选判据 —— 横贯全宽的直线大多是正常结构, 不是缺陷

用户说"表面有缺陷"时并没有说形态。**判据选错形态的代价是整条检测线白跑**: 实测把目标上一条横贯全宽的水平长直线
(Hough 共线接续出 830px / 占目标宽 76%) 当成"最严重的划痕"追了两轮, 用户一句"那是正常的安装接线"全部作废;
真正的缺陷是**凸凹不平**(成片起伏), 形态完全不同, 判据也完全不同。

⇒ 动手前先问"缺陷是什么形态", 或按三分法各出一张候选放大图让用户指认:

| 形态 | 视觉特征 | 判据 | 典型误报 |
|---|---|---|---|
| 线状 (划痕/刮伤) | 细长、有固定方向 | 黑帽/顶帽 × 4 方向线核 + Hough 共线接续 | 目标上下棱线 (横贯全宽, 永远最长) |
| 斑块 (凹坑/污点) | 小而近圆、对比强 | 局部异常 + 圆度 + 对比度 | 装配孔、字符 |
| **凸凹不平** (起皱/麻面) | **成片、无固定方向** | **局部标准差 + 区域级聚合** | 装配孔、安装接线、夹具 |

**横贯全宽的直线/直边, 默认先假设是正常结构**(接线、棱线、台阶、贴装缝)。要报成缺陷必须用户点头。

## 🔴 排除正常结构的遮罩会把缺陷一起遮死 —— 遮罩必须限总覆盖率

"排除安装接线/棱线"这一步最容易把自己搞死。实测用 Hough 在多通道 × 多核尺寸上找直线再短路遮罩:
同一根接线被重复检出多次, 加上凸凹区自身的方向性纹理也被当成直线 ⇒ **遮掉目标面积的 46.8%**,
而遮掉的正好是用户指出的两片缺陷(缺陷区局部纹理强 ⇒ 最容易被 Hough 命中) ⇒ 检测报 0 片。

规矩:
- **遮罩总覆盖率设上限并打印**, 超限判本次检测无效. 实测收在 **≤12%** 才正常(只遮那一条真接线 + 3px 宽).
- **按网格打印"每格 std / 该格被遮罩百分比"** —— 一张表同时看出"哪片不平"和"哪片被自己遮死了".
  实测缺陷区被遮 80~99%、中间正常区被遮 13~76%, 一眼可辨. 这表应该在**第一版**就打, 不要等用户报漏检才打.
- 同一条线在多尺度检出要**合并成一条**再画, 不要逐条 `cv2.line` 叠加.
- 遮罩只能用于"减干扰", **绝不能用于"删掉看着像缺陷的东西"**.

## 🔍 凸凹不平(成片起伏): 局部标准差 + **区域级**聚合, 不是小斑块

平坦金属面在漫反射下窗口内灰度平稳, 曲率突变处同一小窗里明暗并存 ⇒ **局部标准差**是最直接的判据:

- `std = sqrt(max(blur(g²,k) - blur(g,k)², 0))`, k 取 21×21 量级; 再用 **median + 1.4826·MAD** 转稳健 z.
  实测平坦区 std **5~7**、缺陷区 **30~40**, 量级差 5 倍以上 ⇒ 阈值不敏感.
- 🔴 **大片缺陷用"片内平均 z", 不要用"峰值 z"**: 实测一片占目标 6% 的缺陷峰值 z 只有 3.77,
  逐点卡峰值(z≥6)会把整片漏掉. 做法是**先大核平滑(31×31 量级)把响应摊成片**, 再按连通域统计
  **片内平均 z + 面积占比**.
- 🔴 **不能用圆度筛大片**: 大片形状本就不规则, 卡圆度(如 ≥0.35)会把它们全排掉; 圆度只适合挑小斑块.
- 面积门槛按"占目标面积的百分比"设(如 ≥1.5%), 比绝对像素数稳(目标姿态/距离变化时不用重调).
- 边界"画得太大"是常态反馈: 大核平滑 + 闭运算都会外扩 ⇒ 报完先用**小核 + 高阈值**收一版, 或直接问用户边界对不对.

**装配孔必须单独排除, 否则大孔会被报成缺陷**: 孔的特征是**近圆 + 内部平坦**(长宽比 <1.5、孔内 std 接近背景),
而缺陷是"内部明暗跨度大"(实测孔的明暗跨度小、缺陷跨度 150 量级). 按这两个量做**区域级分类**即可.

🔴 **绝不要用 `HoughCircles` 找孔后 `cv2.circle(mask, c, r, -99, -1)` 把孔从响应图里挖掉**:
参数稍松就检出 16 个假孔, 挖完把整张响应图挖空 ⇒ 报 0 缺陷; 而且"孔内 std"这种量在错位裁切下全是 0.0,
看着像证据其实是噪声. 区域分类只决定"这一片是否上报", 不动响应图.

## ⚠️ 手写阈值算法的边界: 单帧抖动, 且必须如实说"这不是模型"

这类检测器是 **OpenCV 阈值链**(blur 算 std → median/MAD 转 z → 形态学 → 连通域), **没有训练、没有权重**.
它的代价必须讲清, 别让用户以为在用训练过的模型:

- **单帧抖动**: 同一工件、同一曝光、同一姿态连跑两次, 候选列表对不上(实测某片上一轮 z=6.60、下一轮掉出榜;
  另一片反而冒上来). 参数每调一次结果就变一次 —— 这不是"还没调好", 是这类算法的固有性质.
  要稳定就 **多帧中值**(连拍 N 帧逐像素取中值再算 std), 或者直接上训练过的模型.
- 用户问"你用什么模型检测的" ⇒ 直接答"**不是模型, 是手写 OpenCV 阈值算法, 阈值是按这一帧的数值试出来的**",
  并把产线上真正的 YOLO(加密权重、有类别表、稳定)与它并列, 让用户知道差别在哪.
- 交付口径永远是"**候选**"不是"检出"; 没有 ground truth 就不能说"检测出缺陷".
- 🔴 **交付图别为了压体积把整图缩到固定宽度**: 线/凹凸只有 2~5px, 整体缩到 1400px 宽会把它糊成一片
  ⇒ 用户看不到细节, 只能反复说"图发过来". 正确做法是**原分辨率分张发**: ① 整目标 2~3x 放大图
  (带编号/框/尺寸标注) ② 缺陷局部 3~9x 放大图 (带灰度剖面) ③ 不平整度热图.
  照片类用 JPEG q92 比 PNG 小且细节保留更好. 单张宽度超 ~4300px 时不要"缩回去",
  改成**分左右半各放大**两张 —— 缩放比丢细节的代价大得多.
- 要真正稳定只有两条路: ① 给产线 YOLO **加类别**再训(权重与解密器都不用动);
  ② 本机训一个专用缺陷模型, 用"用户指认过的候选"当第一批标签.

## ★ 对着实时画面做位置闭环（微调工件/相机）—— 先证测量通道，再标定，再闭环

“把工件调到相机看得对的位置”是一个闭环问题，但**第一步不是动机构，是证明反馈通道能用**。
顺序固定三拍，每拍都有判据：

1. **证测量通道** —— 取图成功率 + 帧有效性。
   - 🔴 **测量帧必须与判据帧同源**：同一相机常有两条取图路（“触发检测/点灯”与“裸抢一帧”），
     两者光照可能完全不同。混着比“目标在画面里的位移”，会算出**假雅可比**
     （实测：同一姿态两张图的目标位置差 1453px ⇒ 凭空得出 726px/mm），拿它去驱动机构就是拿噪声当偏差。
     **闭环只用走检测流程的那条路**（本项目：`POST /capture_detect` 后再取图，不是直接 `grab=1`）。
   - **取图成功率本身就是指标**：实测上游 `POST /capture_detect` 6 次里 4 次 `http=500 图像抓取失败`，
     单次耗时 1.3~7.5s 抖动。这种状态下**禁止标定/闭环**；先加“重试到 200 + 帧有效性门”
     （亮物像素占比在区间内 + 亮带在目标区域邻域 + 与上一帧差 < 阈值，任一不满足 ⇒ 本次测量判**无效**）。
   - 判据用**上游自己的判词**当 ground truth（如 `judge_ok/judge_why`），别自己看图下结论；
     上游说“没找到目标”时，它给的计数/缺陷数一律不可信（不是“0 缺陷=好”）。
   - 无视觉工具时用像素统计分“内容对不对”：同一路、同尺寸的好帧与当前帧比 `mean`/过曝占比
     （实测好帧 mean=52 · 当前 mean=161 = 拍的是一大片过曝带而不是工件）。
2. **标定（必须真动）** —— 真动 **2 次、每次 ≤2mm、每次只动一个轴**，量出 `px/mm` 与
   “图像上下/左右 ↔ 基座哪个轴”。**不猜轴向**（相机装配角度不可从图上推断）。
   两次测量的**口径要完全一致**（同一取图路、同一阈值、同一姿态基准），否则算出来的是噪声的比值。
3. **闭环** —— 单步 ≤2mm · 单轴累计 ≤15mm · 迭代 ≤25 · 收敛 tol 12px · 跳变闸 3×（预期位移的 3 倍以上 ⇒ 立即停）·
   上游判据不可靠时 **fail-closed 拒发下一步**。

**现场参数要与代码解耦**：把安全区域/速度/检测口径/伺服限幅写进一份单一真源
（本项目 `data/config/aoi_surface_params.json`，每项带 value·unit·range·说明·代码位置），
现场改参数不用翻代码；报参数时**同时给相对量与绝对量**。

**目标区域也要从上游真源取**（程序 ROI / 观察位示教点），不要自己发明目标坐标；
调位置的目标必须落在现场确认过的观察位附近。

## 🆕 给"另一台相机"单独训检测头 (2026-10-20 实测: D435 视角, 700 帧 → 76 标得上)

固定相机(D435)要看到腕相机(D405)才认的目标时, 用户口径常是"**单独训一个头, 只给 2D 框**"(B 路线)——
比标外参投影(A 路线)少依赖, 但**标签从哪来**是真瓶颈。可复用流程:

1. **采**: 只读 HTTP 取帧(`/snap/<k>.jpg`), 同帧落 `md5/帧龄/深度统计/TCP 真值` 到 `meta.jsonl`;
   按"相邻帧平均绝对差 < 0.6 灰阶"丢静止帧, 否则采回来 90% 是同一张。
2. **伪标签 = 别域权重 + 运动判据**。别域权重(腕相机)在新视角上会**大量误检静止杂物**:
   实测 700 帧里出现
   (1) 真目标簇: x 极差 238px(跟着臂动); (2) 两个静止簇 (271,449)/(309,445): 出现 657/639 帧、位置 std <1px。
   ⇒ 跨帧聚类后**按"出现帧数多 + 位置方差小"整簇剔除**。不做这步: 856 框 → 只剩 73 框合格, 即 91% 是脏标签。
3. **val 必须按"有无目标"分层抽样**。按时间切尾会踩: 有标注的帧集中在一段, 尾段全空 ⇒ val 0 实例 ⇒
   `mAP 恒 0` 看着像训崩(实测第一次就这么白跑一轮)。
4. **判据要三条, 缺一不可**:
   - 复现自己的标签: 标注帧上 conf=0.10 → 76/76, IoU 中位 **0.97**;
   - **病治好**: 在原权重被证伪的静止位置上, 700 帧扫下来 **0 个框**(原权重那里 657 帧都误检);
   - 实时 0 检出时**先证画面里真没目标**(用独立通道, 如 L5 VLM 判"未见光模块"), 否则这 0 既可能是漏检也可能是事实。
   注意伪标签 val 的 mAP(0.99) **不能当泛化证据** —— 它度量的是"和伪标签像不像"。
5. **上线接线坑**: AR 服务(8797)在 `do_GET` **开头**就把所有 `/api/rs_*` 早退给独占小服务(8789)代理,
   所以在 elif 链里加 `p == "/api/rs_detect_d435"` 是**死代码**(永远 404)。必须在代理的 `_map` 里加路径映射
   `"/api/rs_detect_d435": "/api/detect_d435"`。判断"死代码"的方法: 先 curl 看谁回的 404 文案。

## 实测: 检测框 ≠ 目标外廓 —— 叠到 AR 上必须扩到整支 (2026-10-18)

给用户“在画面上标出目标”时, **YOLO 框只盖住目标的一段**是常态, 不是模型坏了:
实测光模块 YOLO 框 `[316.8, 0, 373.0, 123.9]`, 而 HSV 行剖面显示实物到 **y≈156** ——
被漏掉的是**头部/连接端那 32px**; 用户一眼就看出“头部没标上”。

规矩:
- **框外再扩一次**: 在框的 x 带内统计 HSV 掩码(金属=低饱和高亮 | 拉环类=特定色相)按行宽度剖面,
  从框内向两端生长, 允许 ≤3 行空洞, 遇连续空洞即停(否则把下方其它工件并进来)。
  本项目: `tools/opt_box3d.py::_refine_extent()`。
- **框贴画面边缘 = 目标被裁**, 此时“框高 ÷ 已知件长”反解距离**必然偏大**:
  实测 374 条贴边样本中位 180mm vs 未贴边 157mm(+23mm, 15%)。
  必须置 `clipped=[top/bottom/left/right]` 并告警; 有近期完整观测就沿用其距离;
  页面上用向上箭头+文字明示“头部出画(在画幅上方)”, **不要假装能框住画布外的部分**。
  3D 框本身可以如实伸到画外(角点 y<0), 由画布裁切 —— 那不是 bug, 是真实呈现。
- 无深度时的距离 = `f × 真实件长 / 画面高`。**件长口径必须问用户或查图号**:
  壳体 56.5mm 与“连拉环总长”差一个头部, 同一框能算出 143mm 与 177mm 两个距离。
  件长做成参数(本项目 `ZMAX_MOD_H_MM`)。
- 把这套封装成**只读端点**(本项目 `GET /api/module3d`, 1.5s 缓存)供 AR 页轮询,
  链上每一环都取真源: TCP 真值 + 手眼 `T_cam2tool` + 出厂内参 K; 结果里带上
  `box2d_det / box2d / refine / clipped / dist / dims / corners_px / corners_base_mm`, 便于逐项核对。

## 检测器换机位前先证“它跟的是目标” —— 帧差响应测试（最容易解的假外参）

换相机/换机位/换场景后，**不要**把“有检出”当成“看到目标”。一条判据就够：

- **跟着动**：把机构移动一个已知距离 D，量检出框中心的像素位移 Δ。真目标应满足 Δ ≈ D·f/z（同量级）；
  差一个数量级、或 Δ=0，就是**静止杂物**。实测把臂横移 110mm，`peg` 框一个像素都没动、位置在几十分钟内完全不变
  ⇒ 拿它和 TCP 真值配对去解固定相机外参，会得到“投影对得上、深度方向全靠猜”的假外参。
  同一物件在两个不同位姿下给出**同一像素**，等于判死。
- **画面变化率对比**：机构动 80mm 引起的全图变化像素占比，要显著高于静止噪声（实测 0.95% vs 静止噪声 0.93%
  ⇒ 无法区分 ⇒ 目标根本没进有效视野）。这一条同时给出“机位够不够”的量化门槛。
- **别把“最高分”当唯一依据**：低置信时最高分那只常在画面另一头。多检出时优先“离上次框最近”；
  冷启动优先“离画面中心最近”（相机装在机构末端时，被看的目标就在光轴附近）。

## 兜底链的自证循环：模板/ROI 结果不许回写参考状态

三级兜底（模板匹配 → 邻域重检 → 沿用上次框）里，如果模板匹配接住的框又被存回去当模板，就构成**自证循环**：
实测一个误检框被 1.00 相似度锁死在画面另一头（框从 [314,0,347,59] 跳到 [272,414,306,479] 后“稳定”不动）。

- **只有主检测器的框才允许更新模板/参考框**；模板、邻域重检、沿用 只负责“不断线”，绝不回写。
- 输出带 `det_src`(yolo/template/roi)，事后能分辨这一帧是谁给的。
- 只判尺寸的连续性闸拦不住“跳到别处”：尺寸相近的误检照样通过 ⇒ 加**位置闸**
  `中心跳变 > max(60px, 1.5×框对角)` 判误检并沿用上次框；新位置**连续 5 帧一致**才改认（真重新捕获不丢）。
- 目标与相机是**刚体关系**（相机在腕上、目标被夹住）时，像素位置本就是常量 ⇒ 可以把结果整体钉住
  （写 `<state>_freeze.json`，请求只回这一份、时间戳刷成当前时刻，画面照旧刷新），比每帧重追更稳。
  钉住前必须确认这一帧来自主检测器且置信正常 —— 把误检钉死是最坏的结果。

## 实测: "看不到刚抓起的模块" = 数据缺口, 不是模型没加载 (2026-09-19)

- 症状: 现场问"YOLO 加载了么? 怎么看不到刚抓起来的光模块?" → 查实: 权重已加载 ✓ 但**检不到** ✗
- 真因: 模块被夹在夹爪指间 → 离镜头只有几厘米 + 被画面上边缘**切掉一半**
  → 训练集全是"完整模块 + 正常距离" ⇒ 新旧权重都 0 检出(conf<0.08)
- 修复闭环(可复用): **现场标注 12 张"半个模块"** → fine-tune(50 轮) → **同口径实机 16 帧对比 0.0 → 1.0**(conf 0.718) → 换软链 → 消费者重启 → 实机日志 peg=0.69~0.71 ✓
- 判据: 换权重必须"**同口径实机同帧对比有提升**"; 自动评测若拍到的是旧场景/运动中帧(双 0 命中) → **判无效, 不作为依据** ✗
- 教训: 标注集要覆盖"**目标被遮挡/被切边/贴脸/被夹持**"这些部署现场会真实出现的视角
