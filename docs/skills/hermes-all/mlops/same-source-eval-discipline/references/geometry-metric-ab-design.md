# 几何/度规 A/B 的实验设计 (怎么比才不被口径坑)

要回答"某个几何约束/度规对控制是否更有效"、"分层是否有必要"这类**架构命题**时, 实验设计本身决定结论。
规则层见 SKILL.md 铁律 15 / 16 / 18; 本文是可照搬的配方。

## 1. 公平性清单 (少一条, 结论就可能反转)

| 项 | 要求 | 不这么做的后果 |
|---|---|---|
| 数据 | 同一份真轨迹; 拟合集与评估集**按 episode 切**, 不随机切帧 | 时序泄漏, 所有臂一起虚高 |
| 目标点 | 同一 episode 末帧, 投影到**各自**流形 | 目标不一致 ⇒ 比的是两个任务 |
| 势函数 | `Φ_m(q)=½·d_m(q,goal)²`, 用**该臂自己的距离** | 共用欧氏 Φ ⇒ 欧氏臂单调率 100%, 结论反转 |
| 拟合 | 每臂**各自 fit** 同一批状态 | 维度/几何不同, 共用 ckpt 不公平 |
| 超参 | dt / M / 步数完全相同 | — |
| 基线 | 必须含**无约束基线**(euclidean / latent_flat) | 没有基线就难以说明"有效" |

## 2. 指标 (要挑有控制意义的, 不是挑好看的)

- `grad_cos` = cos(**−∇Φ**, 真实位移在流形上的像) —— 最有说服力: 度规给的梯度指不指向真运动方向。
  **符号坑**: 控制走 −∇Φ, 所以要取 `−grad` 与位移的 cos; 直接拿 `+grad` 去点乘会得到全负。
- `phi_mono%` = Φ 沿轨迹单调下降的步占比 (李雅普诺夫 V̇<0 才是稳定收敛)。
- `phi_drop%` = Φ 首→末落差; `conv_steps` = Φ 降到 5%·Φ0 的首步。
- `jerk_rms` = 解码动作二阶差分 RMS; `energy` = 平均 Σa²。
- `resid_max` = 投影残差 —— **常全为 0(各臂相同) ⇒ 没有区分度, 别当成"约束满足"的证据**。

## 3. 两个可直接用的脚本

```bash
# 全维: 各度规同场竞技 (含无约束基线)
./gui-venv311/bin/python tools/ab_manifold_metric.py  --eps 30 --run-eps 8

# 子空间扫描: 把状态切块, 看最优配置是否随块变化 (证明分层有依据)
./gui-venv311/bin/python tools/ab_manifold_subspace.py --win 3 --eps 24 --run-eps 8
```

两者都是纯 CPU(numpy), 不占 GPU ⇒ 可以和训练/引擎同时跑。输出落 `zmax_data/eval/*.json`。

判定分两行, 不许合成一句:
1. **约束有用**: 多数子空间上"有约束"的 `grad_cos` > 无约束基线。
2. **单一约束不够**: 最优配置在子空间之间不一致(最集中占比 < 80%)。

## 4. 实测基线 (39 维插拔真轨迹, 5 个 ready 度规)

- 全维: sphere 拿 3/5 项(Φ 单调率、∇Φ↔真位移 0.9329、收敛步数); su2 只拿"动作最平滑";
  euclidean 拿 Φ 落差与残差。⇒ **不能声称"su2 最有效"**。
- 子空间: 8 个有效块里 sphere 5 / su2 2 / euclidean 1(最集中 62%) · 7/8 块有约束优于无约束。
- 可用结论: "度规约束优于无约束, 且没有单一度规通吃 ⇒ 按子空间/分层选度规有依据"。

## 5. 坑

- **常量维**: std=0 的窗口 fit 不出流形 ⇒ 返回 None。先把逐维 std 打出来标注"常量维",
  别把 None 当成"该臂表现差"或算法失败。
- **拟合失败要显式报错**: `eng.fitted == False` 时返回 error, 不要并进对照表当"表现差"。
- **势函数是最大的隐蔽坑**(见公平性清单第 3 行): 同一份数据在两份 Φ 下能给出相反结论。
- 别只报"谁第一": 这类实验的价值一半在**否定项**(哪个度规明显差、哪块没区分度), 一起写出来。

## 6. 度规势 (`phi_metric`) 落地: 三次把"实现病"归因成"度规无用"

背景: 同一份 87k 帧真轨迹, 四臂 (A 基线 / B +度规势 / C +切投影 / D 都开) 两次判出 2/6, B 臂
方向 cos `k=30 0.9651→0.9008`、`k=150 0.8010→0.3692` ⇒ 差一点就写成"度规约束无效"。
**修完 B 0.3692→0.9560、四臂 6/6、几何自检 11/11**。三条病都在实现, 不在数学:

1. **arccos 奇点**: `Φ=½·arccos(c)²` 的导数 `−1/√(1−c²)` 在 c→1 发散; 真实轨迹 k=150 有 **11.3% 样本 c>0.95**
   ⇒ 数值微分把奇点放大成噪声, 方向随机。
2. **`|·|` 丢了符号**: `|⟨p,g⟩|` 在 c=0 不可导; 更致命的是**任何只依赖 c² 的势对 goal 与 −goal 完全同值**
   ⇒ "把 goal 翻到同半球"这种补丁是**数学上不可能生效**的(实测两版结果逐位相同, 都 0.4564),
   看着像"补丁没接上"。而 `_dot<0` 时切向梯度整体反向(k=150 约 **34%** 样本) —— 这才是"k 越大越差"的真因。
3. **量纲混用**: Φ_eu 可任意大而 Φ_met∈[0,1]; "先混标量再整体数值求导"会把奇点和量纲差一起送进梯度。

### 正解 (方向级混合)

- **势改 `Φ_met = ½(1−⟨p̂,ĝ⟩)`, 带符号, 不取绝对值不平方**: 与 Fubini–Study 同族(c 的单调变换),
  但无 arccos、无尖点, **梯度方向唯一指向 goal**。别再用 `½arccos²`, 也别用 `½(1−c²)`。
- **两势分别求导, 只在单位方向按 w 插值, 幅值统一取 `‖∇Φ_eu‖`**: 势只定"往哪走", 不定"多大的力"
  ⇒ 不担心 c→1 时力不衰减, 奇点也放大不到执行量上。
- **`w` 分段**: `c≤0.10` → 0(纯欧氏); `c≥0.35` → `W_MAX(0.85)`; 中间 smoothstep。
  **`W_MAX<1` 是故意留 15% 欧氏腿保单调性**, 设 1.0 单调率会从 1.000 掉到 0.976。
- 🔴 **监视势必须与执行梯度同源**: 返回给判据的 `phi` 若仍用旧 arccos² 混合式、而梯度已换新式,
  收敛与单调率量的是**另一个函数** ⇒ 退化会被记在新算法账上。统一成 `½‖p−goal‖²` 后回 1.000。

### 定位手法 (改势之前先跑, 别凭感觉换公式)

1. **c 直方图 + w 实际值**: 实测 62% 样本完全走度规势、81.3% 实际走度规势; 危险区**双向**
   —— `c>0.95` 占 11.3%、`c<0.10` 占 5.3% ⇒ 单阈值混合根本没覆盖真正的问题区间。
2. **两梯度夹角分桶**: 实测**中位 0° 但 p95 = 180°** ⇒ 一半正常、一半完全反向 ⇒ 是**符号问题**不是形状问题。
3. **按 `⟨p,goal⟩` 符号分组看 cos**: 正号组 0.98~1.00、负号组精确 −1.0000 ⇒ 立刻定位。分桶比看总量快得多。

### 结果

| 臂 | k=30 cos | k=150 cos | 法向泄漏(k=150) | 收敛拍 | 单调率 |
|---|---|---|---|---|---|
| A 基线 | 0.9651 | 0.8010 | 0.5161 | 38.08 | 1.000 |
| B +度规势 | 0.9815 | **0.3692 → 0.9560** | 0.1804 | 38.08 | 1.000 |
| C +切投影 | 1.0000 | 1.0000 | 0.0000 | 38.09 | 1.000 |
| D 都开 | 1.0000 | 1.0000 | 0.0000 | 38.09 | 1.000 |

⚠️ 范围: 这只证明**算法层**有效。真机扭矩链若仍用欧氏 `grad_raw`、不经过流形引擎, 动作不会变 ——
别把 cos 提升当作"机器人动作变好了"。
