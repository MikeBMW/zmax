# 质量判据与采集基线（建图能不能用，先看这两个）

## 判据用项目自己的量具，不要用自设口径否掉它
`tools/gs_quality.py --model <dir>` 是 3DGS 资产的正式判据，三顶（实测口径）：
- `beats_trivial`：留出视角 PSNR 要比“整幅填常数”的**平凡基线**高 ≥3 dB（平凡基线~11–12 dB）；
- `render_has_structure`：渲染图唯一色数（纯色=1 说明没建出场景）；
- `fits_training_views`：训练视角 PSNR 比基线高 ≥5 dB。

汇报口径：给判据原文 + 两个数（留出/训练视角 PSNR）。留出 PSNR 低（十几 dB）说成“**新视角质量一般**”，
不要自己另立严口径直说“不合格”——先把项目判据说清楚，再补一句局限。反之，判据 PASS 也不等于高质量，两个都要给。

## 决定出图质量的是采集的**视点基线**，不是训练超参
原地（机械臂不动）取图 ⇒ “真正不同视点”只有几十个、留出 PSNR 停在 ~18 dB，训练侧怎么调都救不回来
（3DGS 靠视差定深度）。自查两个数：采帧日志的位姿跨度（x/y/z 是否真变化）+ 数据集判定的“真正不同视点”数
（≥100 才看得到提升）。要动臂采多视点，先要到现场授权；不动臂只能接受同档质量，别把训练时长当变量。

## 采帧与训练不要并发写同一个 dataset 目录
重采会覆盖 `<dataset>/images/*` ⇒ 正在跑的 `gs_train.py` 抛 `FileNotFoundError: images/img_*.jpg` 中断
（旧日志被改名 `train.interrupted_*`），十几分钟白跑。要重采就先停训练 / 另起目录 / 采完再训。
训练入口必须用 `tools/run_gs_train.sh`（gsplat 的 CUDA 扩展靠它的 shim，直接跑 `gs_train.py` 会报
`'NoneType' object has no attribute 'CameraModelType'`）。

## 进度与 ETA 的报法
日志形如 `[16800/30000] loss ... · 高斯 N · 604.0s` ⇒ 用行内累计秒直接算步/秒，不要用 grep `step N`（日志里没这个格式）。
同时报：当前步/总步、实测步速、剩余分钟、以及“已经跑了多少分钟”。

## 留出必须“整段留出”（决定 PSNR 能不能横向比）
每 k 帧抽 1 帧作留出是**有偏**的：相邻帧视角几乎重合，留出帧常和训练帧来自同一段运动、几乎同视角 ⇒
模型在“刚看过的地方”自测。识别标志很硬：**留出 PSNR 反而高于训练视角**（实测 13.74 > 12.29），
或两版模型差 0.3~0.5 dB 就有人想宣布提升。

定式（`gs_train.py` 里的 `--holdout-mode block|even`，默认 block）：
1. **参数化轨迹**用累计运动量，不是帧序号：逐帧相邻旋转矩阵 `Rrel = R[i-1].T @ R[i]`、
   `ang = degrees(arccos((trace(Rrel)-1)/2))` 取绝对值累加；**总转角 <5° 的纯平移场子改用累计位移**（转角块会退化成空块）。
2. 归一化 `cum/cum[-1]` 后切成 N 段（`--holdout-blocks`，默认 8），按“离中间最近”排序挑 **keep 段**
   （`--holdout-keep`，默认 1）—— 贴首尾的段有边界效应，别挑它。
3. 退化兜底：留出 0 帧或训练帧不足 10 时必须**回退 even 模式并在报告里写 mode="even"**，不许静默用有偏口径。
4. 报告必须落 `holdout{mode,kind,blocks,keep,coverage,span}` + `holdout_indices`（截断存），
   让“留了哪一段”事后可复核；命令行要打印一行 `按转角覆盖 593.5° 切 8 段 ⇒ 留出 47 帧 (跨度 73.6°)`。

⚠️ **换了留出口径，旧数一律作废**：不同留出方式/不同数据集算出的 PSNR 不能放同一张对照表；
同口径对照只允许差一个变量（初始化/致密化），且都要跑到头（只跑到一半步数的 eval 不能当终值）。
⚠️ 判“有没有提升”的门槛随口径变严：block 留出下 0.3~0.5 dB 属抽样噪声，横向比较只认 >1 dB。
