# 机器人扫场 → 3DGS 数字资产 (仿真测试底图)

## When to Use
- 老倪说「(L5 自主运行/自主学习阶段) 建立当前环境的 3DGS 数字资产, 用于算法仿真测试」「你来同时生场景」「扫描/重建场景」「建数字资产」。
- 要给检测/策略做**仿真回归底图**, 或要仿真-真机同口径对照而缺场景几何。
- 已有采集数据, 要重建/重训/导出资产, 或采集画质/覆盖不够要重扫。

## 核心取舍: 位姿已知 ⇒ 不走 COLMAP/SfM
臂上相机随臂动 = 白送的多视角 + **每个视角都有真值位姿**(50Hz TCP 真值 + 手眼残差 0.06mm)。
所以: **相机外参 = 算出来的, 不是 SfM 解出来的**。省掉整条最脆的链(SfM 失败/漂移/尺度不明), 快且可复现。
只有“相机不在臂上/无手眼”时才退回 COLMAP(这条腿未验证, 别当推荐)。

## 流程
1. **先立采集, 再谈重建**。数据错过就没了: 用户说“一会我就动”时, 立刻起采集后台, 再去做环境/训练/接线。
   收工用**会话目录里的 `STOP` 文件**(优雅停, 落 `capture_summary.json`); 别 kill。
   **采集进行中就能判"人到底动没动"**(不用等 STOP): 读 `frames.jsonl` 的 `pose_before`, 对 x/y/z 求 `np.ptp` ——
   实测 917 行 / 73 张唯一图但 `ptp=(0,0,0)` = 同一视角连拍, 训练只会出浅浮雕 ⇒ 当场让人挪 (累计跨度 ≥150mm 才有视差)。
   别把"帧数够了"当"数据够了": 唯帧数与视差是两个独立门。
   ⚠️ **同一会话目录里多轮采集必须续帧号**: 每轮从 0 起编号会让第 N 轮的文件名覆盖第 N-1 轮
   (`frame_000001.jpg…`) ⇒ 只剩最后一轮的画面(多轮建图尤其致命)。判据 = 两轮文件名不重叠(或会话里唯一图数 ≈
   各轮之和)。
   无人值守时(臂一动就采图+记位姿、攒够自己送训)的守护进程判据与三个必踩 bug 见 `references/autocap-daemon.md`
   (同一份里还有: 在 GPU 机上直接订阅 ROS2 话题的变体 · 训练编排器的视点门/指纹 · 从外网两跳推飞书的链路与 paramiko/pkill 真坑)。
2. **采集期间给操作员动作口径**(直接发给他, 别省略): ~30~80mm/s; 加**高度 + 俯仰/侧移**变化, 别只平移一条基线; 相机主要对着工作台/工件区; D405 最近 ~7cm 别贴死; 停在一处不用停久(重复视角无用)。
3. **配对必须用单调时钟**: 墙钟会被 NTP 回拨(本机差 8h)。每帧在**取图前后各读一次位姿** + 记 `fetch_ms`/`pose_t_gap_ms`, 后处理按单调时刻最近邻取; **负帧龄一律拒**。
4. **重建**: 逐帧算 `T_base_cam`, 导出后训练 3DGS。公式/schema/导出格式见 `references/capture-and-pose-math.md`;
   **用 gsplat 自写训练器的骨架/API/归一化/导出与本次真坑见 `references/trainer-with-gsplat.md`**
   (gsplat 的 pip 包只有库、没有 trainer; 交付物优先出 `.splat` + 网页查看器链接, 用户能自己拖转看 ——
   挂查看器/接资产只读路由的定式与真坑见 `references/splat-web-viewer.md`)。
   - **必须先量相机位姿跨度再决定要不要训**(`np.ptp(pos)`): 只有几十毫米(操作员原地微调观察点) ⇒ 视差不足,
     只能出一张"浅浮雕", **不是环境资产** —— 当场跟用户说清"这只能做小基线验证", 要资产先要一次大范围扫掠。
   - **先去畸变再训**: 3DGS 是针孔假设, 带畸变直接喂会让边缘几何错位 ⇒
     `Knew,_ = cv2.getOptimalNewCameraMatrix(K,dist,(w,h),0)` → `cv2.undistort(img,K,dist,None,Knew)`, **用返回的新 K**。
   - **坐标系口径只选一套并写进产物**: 自用 `cameras.json` 存 **OpenCV 光学系**(x右 y下 z前) 的 `T_cam2world`(base_link);
     对外兼容再写一份 nerfstudio `transforms.json`(OpenGL: y上 z后 ⇒ `T_cam2world @ diag(1,-1,-1,1)`)。
     两套混用/戆错翻转是 3DGS 的经典错位源，产物里写清 convention 字符串。
5. **训练环境隔离**(`tools/gs_env_setup.sh`): 用 `uv`(在 `~/.hermes/bin`) 建**独立** venv。**绝不往 `lerobot-venv` 装东西** —— 它是训练环境且是 uv 管的(里面**没有 pip**)。
   - 需编译 CUDA 扩展的包(nerfstudio/tiny-cuda-nn、diff-gaussian-rasterization、gsplat 的 JIT 版)在本机走 **gsplat 预编译轮**
     `uv pip install gsplat --index-url https://docs.gsplat.studio/whl/pt27cu128`(配 `torch==2.7.1 torchvision==0.22.1` cu128)。轮子是否命中以脚本末尾自检打印为准。
   - ⚠️ **训练必须走 `tools/run_gs_train.sh`**: 直接 `python tools/gs_train.py` 会报 `AttributeError: 'NoneType' object has no attribute 'CameraModelType'` —— 真因是 gsplat 的 CUDA 扩展 JIT 编不过、报错被吞; 该脚本包上 CUDA shim 环境(`/home/ubuntu/cuda-shim/bin/nvcc`)就好。
   - 停训练用 `tools/stop_gs_train.sh`(先取 pid 再排除自身); **内联 `pkill -f "gs_train.py …"` 会把自己的 shell 一起杀掉**(已踩两次)。
   - 4060 Laptop **8G 显存**: 同刻只跑一个模型进程; 扫场采集很轻, 但训练与在役推理别叠加。
6. **VLM 指导**(L5 视觉那条): ① 逐帧筛(糊/过曝/遮挡/无效视角)并实时提示换角度; ② 认区域/工装/工件打**语义标签**写进资产元数据; ③ 采集后判覆盖缺口 → 给下一轮**主动视角建议**(位姿级)。
7. **增强件**(按需接, 不阻塞主链): 深度监督(D405 深度图当几何约束, 比纯 RGB 稳) · **4DGS**(每帧 TCP 位姿做时间轴, 可做含臂动态的时间维资产) · **diffusion**(新视角/新光照域随机化; 把机械臂 inpainting 抹掉)。
8. **用途**: 从资产渲染任意视角/光照的“真感”图 → 喂检测/策略做离线回归; 与真机画面做同口径对照(见 `sim-real-scene-overlay`)。
9. **接进画布**: 数据层节点「3DGS 环境资产」, 输入=图像流+位姿流+L5 触发, 输出=资产路径+渲染通道; 跨 venv 子进程桥的写法见 `cross-venv-model-canvas-node`。

## Pitfalls
| 坑 | 症状 | 修法 |
|---|---|---|
| 用墙钟配对位姿与图像 | 全部错位/重建忽明忽暗 | 一律单调时钟; 取图前后各取一次位姿; 负帧龄拒用 |
| 去 `calib_report_*.json` 拿手眼 | 拿到 null 以为没标定 | 手眼真值在 `handeye_state.json`(`T_cam2tool`) |
| 分辨率与 K 不一致 | 重建整体错位/虚 | 取流分辨率与内参分辨率对齐(高速通道是 640x480) |
| 递归查数据根内容 | 命令跑到超时(200s 都不够) | `~/zmax_data` 是几十GB + 上万文件(还有 HF blobs): **只查定点路径** —— `search_files(pattern=…, path=<具体子目录>)` 或 `ls` 逐层下探 |
| 把包装进训练 venv | 训练环境被污染 / 没 pip 装不动 | 另建 `uv venv`; 用 `uv pip install --python <venv>/bin/python` |
| 想装需编译 CUDA 扩展的包 | 报找不到 nvcc | 用预编译轮(index 见上); 或先补 nvcc 再谈源码编译 |
| 把纯 255 过曝面/强反光金属当训练主材 | 3DGS 高斯糊成一片、看不出结构 | 过曝区无梯度: 降曝光/缩光圈, 或纯 255 区掩掉不参与损失; 必要时加深度监督 |
| 采集时把机械臂自身也拍进画面 | 臂被烤进场景, 资材里有幽灵臂 | 相机在臂上时它只对静态场景 ✓; 若其它相机/臂体入镜, 按帧位姿 mask 或 diffusion inpainting 抹掉 |
| 没先拿 K 就开训 | 跑完才发现不可用, 白烧 GPU | 采集第一天就把 K 存进 `session_meta`; 训练前先校分辨率与 K |
| 把上万帧连拍直接喂进训练 | 训练慢/显存吃紧而视角几乎不增 | **先按 6D 位姿最远点贪心抽帧**(平移 + 0.15×朝向差) 到 ~300 张 —— 同视角连拍对重建零贡献。现成工具 `tools/gs_dataset.py`(去畸变 + 选帧 + 出 `cameras.json`/`transforms.json`/`meta.json`) |
| **深度图无效值 65535 没挡** | 点云 bbox 被撑到 6.8m×5.6m×6.2m(实际工作台 ~2.3m)；离群剔除只剔 1.8% | D405 无效深度编码 **65535**×0.1mm=6553.5mm；有效判据必须**双端**: `(z > 50) & (z < 2000)`(`tools/slam_map_service.py` 已加 `ZMAX_MAP_MAX_DEPTH_MM`, 默认 2000)。实测同一帧: 232308 点/bbox 6.8m → 217375 点/bbox 2.3m |
| 想「在 intel(Arc) 上训 3DGS，不占 4060」 | 以为「Arc 上 torch 可用」就等于「能训 3DGS」，去下 860MB torch 轮再发现训不了 | **两件事要分开判**: ①intel 上 torch-xpu + ultralytics 确实可用(实测 2.7.1+xpu: `xpu.is_available()=True`、`get_device_name(0)=Intel(R) Arc(TM) B390 GPU`、矩阵乘真算过、ultralytics 也认这个 device) ②但 **pypi 的 `gsplat` 包不是 SYCL 路线**: `gsplat/cuda/_backend.py` 的门就是 `cuda_toolkit_available()`(只查 nvcc/CUDA_HOME), 装了 `intel-sycl-rt` 让 `No CUDA toolkit found` 警告消失之后 `_C` 仍是 None、`rasterization` 照报 `'NoneType' ... CameraModelType` ⇒ **别在 pypi 轮上反复试**, 要 SYCL 只能用下面的轮 ③但 **官方有 SYCL 路线, 不是只能 CUDA**: `isl-org/gsplat` 分支 `sycl_code_integration` + `docs/Intel_XPU.md`, 预编译轮在 `https://isl-org.github.io/gsplat/whl/gsplat`(索引实测为 `gsplat-1.5.3+pt210xpu-cp310..cp314-linux/win`)。**轮名里的 `pt210xpu` 必须与 torch 对齐 ⇒ 装 `torch==2.10.0+xpu`**, 装 2.13/2.14 会 ABI 不匹配(白下 800MB+); 两者是绑定关系, 不是"装新不装旧"。编译器: Ubuntu 的 oneAPI apt 源已配好时直接 `sudo apt-get install intel-oneapi-compiler-dpcpp-cpp`, 装完核 `/opt/intel/oneapi/compiler/latest/bin/icpx` 存在(只有 `intel-oneapi-runtime-*` 不算装好)。远端密码 sudo 用 `echo <pw> | sudo -S <cmd>`, 不要加 `-p ''`(会报 sudo 用法错)。⚠️ 栅格化已验证、**完整训练循环也已跑通但慢 70~80×**(实测 200 步 502s ≈ 2.5s/步 ⇒ 30000 步 ≈21h, 见 `references/autocap-daemon.md`) ⇒ 别报"intel 能端到端训 3DGS 了"就往线上推, 报步速与折算小时数。**2026-10-23 实测补充(装完 icpx + torch2.10 之后)**: ① 装轮**别用 `--index-url https://isl-org.github.io/gsplat/whl/gsplat`** —— 那个站点是 HTML 列表不是 PEP503 索引, pip 报 `from versions: none`；要么 `--find-links`, 要么直接装发布 URL `https://github.com/isl-org/gsplat/releases/download/v1.5.3-xpu1/gsplat-1.5.3%2Bpt210xpu-cp312-cp312-linux_x86_64.whl` ② 装成后 `import gsplat` 会打印 `gsplat: Using SYCL XPU backend.`、`from gsplat import rasterization` OK ⇒ **能 import 不等于能开训** ③ 首次 `rasterization(...)` 调用实测 **>180s 没返回** —— 那是 SYCL 首次编译,**不是卡死**: 同一条命令再跑 **4s 就出结果**(实测 `渲染输出 (1,480,320,3) dtype torch.float32 device xpu:0`、非零像素 100%) ⇒ 首次一律给 ≥10 分钟预算, 别据此判"intel 训不了"; 但要分清"栅格化跑通"与"训练循环跑通"(前者已验证) ④ 调用签名先对���: `opacities` 要 `(N,)` 不是 `(N,1)`(报 `assert opacities.shape == batch_dims + (N,)`)**建图(非 3DGS)在 intel 上是现成的**: `zmax-map-intel.service`(8801, 已知位姿深度点云 `/map/status|points.bin|topdown.png`) + `zmax-mobile-map.service`(单片 SfM), 纯 CPU、不占 4060；建库/质检也已在 intel CPU 跑通(300 帧/174 视点/5 项 PASS) |
| 在 intel/远端机上 ROS2 订阅 `/robot/tcp_pose` 一条消息都收不到 | 节点起得来、日志只有 `New publisher discovered … offering incompatible QoS. No messages will be received`, 位姿恒 None ⇒ 采集器一张都不存 | 该发布者是 **BEST_EFFORT**(`ros2 topic info -v` 核 Reliability), 默认 RELIABLE 订阅收不到任何消息 ⇒ 订阅端显式 `QoSProfile(depth=2, reliability=ReliabilityPolicy.BEST_EFFORT)`(彩色/深度话题同样); 判据 = 启动日志里没有那条 incompatible 警告 |
| **采集端每取必存**(老版) | 118586 次取图只对应 5830 张唯一画面(重复 95.1%), 且同一画面被存成多份、每份配**不同** TCP 位姿(最大差 193.7mm) = 矛盾监督 ⇒ 训练视角 PSNR 16.5dB、留出 11~13dB(**低于"填常数"平凡基线**) | 采集端按内容 md5 去重(内容没变不落盘, 重复只在 jsonl 记一行); 建库端再兜一层并把位姿取该图**首现时刻** |
| **选帧贪心忘了把选中点自己归零** (`gs_dataset.select`) | 数据集 `unique_images` FAIL(实测 唯一图 **180/400**)，报错话术是"同图配多位姿"，把人往"走得不够好/走太快"上带；数据集里 **400 帧有 221 帧是同一张图**；训出来 PSNR 平在 15dB(正常 33dB+)，怎么改走法都不涨 | 最远点贪心里 `sel.append(nxt)` 后**必须 `dmin[nxt] = 0.0`** —— 否则只要"新点到最后一点"的距离 `d[nxt]` 比 `dmin[nxt]` 大，argmax 每轮都返回同一个索引。判据(10 秒): 跑 `select()` 后断言 `len(set(sel)) == len(sel)`；或读数据集 `cameras.json` 的 `src`，**唯一 src 数必须 == 帧数**。⚠️ 症状与"数据脏"完全同名，先查这一条再叫人重走 |
| 把 "0.0" 当假值做兜底 (`x or 999.0`) | **最理想**的测量值被判成最差: 同一位姿不同时刻画面差 = 0.0(=最一致) 被 `0.0 or 999.0` 替成 999 ⇒ `static_scene` FAIL，干净数据也过不了门(实测同一场数值在 0.4↔999 之间跳) | 兜底一律写成 `v = d.get(k)` + `if v is None: v = 999.0` —— **不要用 `or`**(0.0/0/[]/'' 都是假值)。凡是"0 是最优"的指标(画面差/误差/偏差)都要这么写 |
| 渲染把 **log 域尺度**当线性尺度喂 `gsplat.rasterization` | 整帧单一纯色(唯一色=1)、PNG 1.9KB、`0 split/0 duplicate`、PSNR 平在平凡基线附近; 参数看似没动 | 渲染前 `torch.exp(params["scales"])`(官方 simple_trainer 即如此); 导出 `.ply/.splat` 才存 log/logit 域 |
| 位置学习率**不衰减** + 致密化跑满全程 | 后期 loss 回升(0.16→0.29)、高斯爆到 140 万、留出 PSNR 回落 | 指数衰减到 1e-6; **致密化在 40% 步数停**(官方 30k 训练 / 15k 停) |
| 只看 loss 降就以为建出来了 | loss 一直在降但留出 PSNR 低于平凡基线 | **判据必须与平凡基线比**: 留出 PSNR > 平凡基线+3dB 且渲染唯一色 >100 才算建出东西 ⇒ `tools/gs_quality.py` |
| 用户问「现在有建好的 3DGS 么」/ 要交付 3DGS | 把深度点云 `.ply` + 俯视图当成 3DGS 交出去(两者扩展名同为 `.ply`) | 判“有 3DGS 资产”只认三条: ①模型目录里 `gs.ply`/`gs.splat`(看字段: 高斯属性/每高斯 32B, 不是纯 XYZ+RGB 点云) ②训练日志或 `status.json` 里有步数与留出 PSNR ③采集会话位姿跨度非零。缺任一条就直答「没有」并列出还差哪一步; 点云地图只能叫地图 |
| 带着畸变训练 | 画面边缘几何涨开/错位(更像"优化不动") | 先 `cv2.undistort`，用 `getOptimalNewCameraMatrix(alpha=0)` 返回的**新 K** |
| 高速扫场时图像比位姿晚一截 | 运动模糊 + 位姿与像素错配 ⇒ 重影 | 固定延迟(编码+传输)按速度线性放大: ~8mm/s 时 ~20ms≈0.16mm(可忽),
30~80mm/s 时 0.6~1.6mm(占小基线 2~4%) ⇒ 每帧记**位姿龄**并按阈值拒帧, 别拿"取图那一刻"的位姿 |

## 自动闭环(L5 指导选点 → 移动 → 采集 → 建图 → 质检)
老倪 2026-10-01 口径: 「L5 功能运行后, deepseek 给出环境理解, 指导 3DGS 建图, 一边移动机器人, 一边自己学环境, 一边建立场景视图」。
一键: `~/gs-venv/bin/python tools/gs_map_run.py --rounds 7 --targets l5 --order fixed`
(`--dry-run` 不碰臂验链路; `--from-recording <会话>` 用录像重跑建库+质检)。
- 🔴 **目标只是"把建图流程跑通"时, 一律走固定序 (`--order fixed`), 不要走 L5 选点**: L5 那条链要调外网视觉模型,
  单 IP 抽风时 `urllib` 会在 connect 里干等到硬墙钟预算(实测卡过 3 分钟、更早卡过 5m44s) ⇒ 建图循环就停在那里,
  现场看到的正是"臂不动了"(而臂本身、网络、闸门全部正常)。固定序 = 确定、可复现、零外网依赖;
  另 L5 子进程会占着这条链, 要中途停它得单独 kill 而不是只停主进程。
- **选点** `tools/gs_l5_select.py`: L5 只给**画面语义方向**(画面左/右/上/下/靠近/远离 + mm), 软件按手眼把
  `R_base_cam` 乘上相机系单位向量得到 base 系方向, 再在**已示教可达点**(`space_points.json` + `ctl_abs_skills.json`
  白名单)里挑 `align≥0.30` 且最没拍过的点。原因: 运动白名单目前**只有示教点类技能**, 没有任意笛卡尔原语 ⇒
  "L5 想去哪就去哪"要等开了笛卡尔点动; 到时只换候选目录, 上层契约不变。
  L5 超时/解析失败 ⇒ 自动退**覆盖度兜底**(去离已访问视点最远的可达点)并把原因写进 `l5_err`, 不假装是 L5 选的。
  ⚠️ `gen_overlay_from_vlm.call_vlm` 返回键是 **`txt`**(不是 `text`), 且 200 但 content 空是已知瞬态(内部会重试)。
- **移动**: POST `127.0.0.1:8793/ctl/move {skill:"L2.goto_spaceN"}` —— 与页面按钮同一条授权+收口链;
  到位判据 = TCP 真值 <3mm 且连续 1s 稳定; 真动前先读 `/ctl/status` 的 `motion_armed`, **未授权绝不发动作**(如实停)。
- 🔴 **跑一轮前三件必查(缺一件这轮必废)**:
  ① **授权窗要覆盖整轮**。逐条授权窗通常只有 10 分钟, 而整轮 ≈ 20~40 分钟(单轮 = L5 选点 20~60s +
     移动 ~50s + 采集 8s; 末尾还有一次完整训练) ⇒ 跑一半窗到期, 后面每步都被"真动授权未开"拦下
     (现场看到的就是"走到一半不动了")。定式: 服务端在**点"开始建图"时**(若已在有效窗内)把窗延长到
     覆盖整轮并写审计; **未授权则在按钮层当场拒并说明原因** —— 别起一个必死的后台任务:
     建图任务只在 t=0 读一次 `motion_armed`、fail-closed 一次就退出且**不重试** ⇒
     点"开始"比点"授权"早几秒就是"点了没反应"的全部原因(也不会自己重试)。
  ② **执行腿是谁**。`/ctl/status` 的 `move_transport`: 产线 ROS 栈没在跑时页面/建图这条链一步都走不动
     (臂不动、日志只有"未到位"), 要确认腿 = 本机 SDK 直连才能开跑 ——
     见 `layered-safety-gate-operations` §3g(换执行腿) —— 腿的机械细节(解析/限幅/分片/量纲/姿态口径/只读预检)
     记在该技能的 `execution-leg-swap` reference 里(不在本技能下)。
  ③ **移动速度量纲**。L2 的 `speed` 是相对量 ≈0.09~0.1 mm/s 每单位, **默认 8 只有 0.75mm/s**
     ⇒ 空间点之间 244~576mm 一段要走 ~10 分钟, 一轮都跑不完; 建图用 **120**(≈11mm/s, 仍受技能
     `speed_max=200` 收口, `gs_map_run.py --move-speed` 可调)。
     🔴 **但名义值 ≠ 实测值: 在 SDK 腿上发 120 实测只有 ~1.1mm/s**(比名义 11mm/s 再慢约一个量级;
     50mm 拍升实测 34s) ⇒ **ETA 一律按实测速率算**(先拿真值位姿差分量一段再报数), 一次「拍升+横移+下降」
     的回点实测是分钟级, 别拿名义速度除距离给现场承诺时间。
- 🔴 **建图速度是它自己的旋钮, 与页面速度档无关**: `gs_map_run.py` 的 `MOVE_SPEED`
  (env `GS_MOVE_SPEED` / `--move-speed`) 默认 120 ⇒ SDK 腿上实测 ≈**1.1mm/s**, 一轮 2~3m 要 40+ 分钟。
  要快就改这个数(1000 ⇒ **先量执行腿的上限再换算**: 腿 `MAX_SPEED_MM_S` 提到 150 后, `--move-speed 1000` 实测 ≈**15~30mm/s**,
  同平面 7 点一圈(合计横移 ~500mm)连采集一起 ≈**3 分钟** —— 旧记录的 1.1mm/s 是腿上限 60mm/s 时的值,
  两道收口任一变了就得重测, 别照抄历史数向现场承诺 ETA); 页面速度档填多高都不影响建图。
  边走边采约 **1.9 张/秒** ⇒ 5.8mm/s 时每张相隔 ~3mm, 基线照样密(3DGS 要的是重叠, 不是慢)。
- ④ **点位姿态必须同一组**, 否则跨组移动被 50102 拒 ⇒ 自愈 MoveJ 乱摆 ⇒ 现场按急停, 这一轮全废。
  跑前零运动核一遍(逐点算与当前臂姿态的夹角, 出现两簇就先对齐少数那组到**臂此刻握着的那组**, 位置不动+备份+回读; 判据与修法细则见
  `layered-safety-gate-operations` §3i④)。
- ⑤ **别重复启动**: 「开始建图」按钮与你自己的启动是**两个独立入口** —— 现场刚点过按钮, 你又起一个,
  就是两个 `gs_map_run.py` **抢同一个臂**。定式: 启动脚本里先"清残留"(按**显式 pid** kill 多余的
  `gs_map_run.py` + `gs_capture.py`, **执行器留着**), 再核实真实进程数 = 1, 然后才启。
  ⚠️ **`pgrep -cf 'gs_map_run.py'` 会把 Hermes 自己的 bash 包装进程也算进去**(假阳性, 实测多报 1~2 个) ⇒
  数进程用 `ps -eo pid,etime,cmd | grep 'gs_map_run\.py' | grep -v 'bash -c'`, 别拿 pgrep 的计数向现场报数。
- 📏 **“视点够不够”别拿点位数量猜**: 质检门判的是**去重后的视点**, `gs_quality.py` 口径是
  “位置每动 **5mm** + 姿态每变 **0.01** 就算一个新视点” ⇒ **边走边采时每一帧都算视点**,
  与“7 个点 = 7 个视点”无关(代码里那句注释是过时说法)。不动臂就想知道够不够:
  `--from-recording <会话>` 用已有录像重跑建库+质检, 直接看 `distinct_views`, 再决定加轮数还是加覆盖
  —— 视点数随**移动距离**线性涨, 不是靠加点。
- ⚠️ **已经停在目标点上的那一轮是白跑**: 到位偏差 0.0mm + `位姿跨度 x0.0 y0.0 z0.0 mm` ⇒ 没有新视点。
  第一轮常态如此(臂停在上一轮终点) ⇒ 别据此判“在动但没数据”。
- **一段“回点”是多段计划, 不是一条直线**: 执行器会把 `L2.goto_spaceN` 展开成「就地抬升 → 保持高度横移 →
  逐段下降」(实测 4 段; 抬升相对计划起点 ≤100mm), 每段各自过闸、各自真值核对 ⇒
  单轮移动耗时 ≈ 各段之和(含段间裁决等待), 报 ETA 按段算, 别拿直线距离除速度估。
- **质检** `tools/gs_quality.py` 三层门(任一 FAIL 即停, 不把废资产当成果):
  ① 采集会话: 同一画面(md5)被存成多份且位姿不一致 ⇒ FAIL;
  ② 数据集: 唯一图 >90% · 真正不同视点 ≥50 · 位姿跨度 ≥150mm · 同一位姿画面差异 <8/255(≥5 对样本才判) · 无黑帧;
  ③ 模型: 留出 PSNR > 平凡基线+3dB · 训练视角 > +5dB · 渲染唯一色 >100。
  报告同时给 `n_gaussians`/`psnr_train_db`/`psnr_holdout_db`/平凡基线, 便于横向比。
- **增量/续训**: `gs_train.py --init-ply <上一轮>/gs.ply [--no-refine]` 从已有资产接着训(闭环里
  `gs_map_run.py --incremental --inc-steps N` 每轮采完就重建数据集+续训, 出中间资产)。
  `.ply` 读回来要自己做归一化换算: `means=S*(m_world-center)`、`scales=logS+log(米)`(归一化是纯缩放无旋转, 故安全);
  文件里 SH 是**通道优先**(f_rest 按 R/G/B 分段)⇒ 读回要 `reshape(N,3,K).transpose(0,2,1)`。
  踩坑: 载入时的临时变量名别用 `K` —— 会覆盖相机内参, 渲染时报 `'int' object has no attribute 'shape'`。
  同口径实测(同数据集/同留出/总步数相同): 增量 3000+续训3000 留出 12.24dB vs 一次性 6000 留出 10.76dB
  ⇒ 增量不劣化且过拟合更轻; 续训首评(500步)就回到上一轮水平 = 确实接着训而不是重训。
- **L5 选点两个必备护栏**(都实测过):
  ① **max_tokens 要 4000**: DeepSeek 是推理型, 2000 时 reasoning 吃光额度 ⇒ content 空或只吐
     半句思考(实测同一批图 3/3 失败); 4000 时 19s 出真 JSON(6000 也能但要 162s)。
     `gs_l5_select.py` 已 `os.environ.setdefault("ZMAX_L5_VLM_MAXTOK","4000")`。
  ② **硬墙钟预算**: 云端耗时会从 19s 摆到 149s, 且端点卡顿时 urllib 会在 connect 里干等
     (实测卡过 5m44s, 连 `timeout 300` 都没兜住) ⇒ 必须"线程 + join(预算)"包一层;
     默认 `--l5-timeout 180`(给太紧会把"慢但会成功"的调用砍掉), 超时退覆盖度并写 l5_err。
- 🔴 **收工(STOP)之后还有一段全量训练, 别以为 STOP = 交付完成**: `--manual` 收工时 `gs_map_run.py` 会在
  `<会话>_model` 里起一次 **30000 步全量训练**(`train.log`, `--eval-every 3000 --holdout 20 --refine-stop 12000`),
  完了才过 `gs_quality.py` 模型门出 `quality_model.json`。中途断电/死机 ⇒ **模型目录只剩 `train.log` 与 `renders/`、没有任何 ckpt**(3DGS 训练只在内存里, 不落 ckpt) ⇒ 只能重跑。
  重跑命令(与 driver 逐字同参数, 不会重开会话采帧):
  `bash tools/run_gs_train.sh --data <会话>_ds --out <会话>_model --steps 30000 --eval-every 3000 --holdout 20 --refine-stop 12000`
  (约 15~20 分钟; 3DGS 全程 GPU ~98%、显存约 1.4G, 与在役推理同卡时先让训练独占)。
- 🔴 **机器在建图中途冻死后的取证口径**(实测 2026-10-14 06:13 重启): 判据是 **journal 最后一条的时间点**
  (= 真冻死时刻, 之后到重启之间零日志; 本机 NTP 回拨 8h, 所以那一刻的日志时间戳比真实早 8h, 别读成"凌晨就停了")。
  硬冻结的特征: journald 在下次开机报 `system.journal corrupted or uncleanly shut down` · **0 条 oom-kill / 0 条 swap 写错误** ·
  0 条 NVRM/Xid · 没有关机序列。本机 cmdline 已有 `panic=10 softlockup_panic=1 hardlockup_panic=1` + kdump `ready to kdump`,
  但 `/var/crash` 空 ⇒ **纯卡死型(不触发 panic)抓不到转储** —— 别向用户承诺"有 dump 可以查", 只能按"整机冻结"报, 并说明下一次怎么抓(外部心跳/看门狗)。
- 📊 **报告质量要给两组数, 别只报 PSNR**: 留出 PSNR 与**平凡基线**比 + 相机位姿跨度。实测一版:
  214 帧(560 张去重后)/110 个不同相机位置/相机只动了 80×289×148mm ⇒ 留出 PSNR 16.1~16.8dB 平台(训练视角 34~37dB),
  loss 有 0.009→0.19 的尖刺(个别帧对不上)。这种"小基线 + 一堆重复视点"的场子就算跑满 30000 步也是灰糊浮雕,
  交付话术要直说"要能用的资产得把视点拉开(不只是原地转/同一位姿连拍)"。
- 🔴 **别在训练跑着的时候重建 `<会话>_ds` 数据集 —— 进程会当场崩**: 3DGS 训练器在**每次 eval(eval-every)时重新打开
  `images/<file>`**, 而 `gs_map_run.py --from-recording <会话>` 是**固定重建 `<会话>_ds`**(先清后写) ⇒
  中途重建会让正在跑的训练报 `FileNotFoundError: ..._ds/images/img_00017.jpg` 直接死掉(实测 13000/30000 处崩)。
  定式: **要么先等训练结束再重建, 要么给这一版编到新目录**(不要让评估/体检和训练共用同一个 `_ds`)。
  另外 `--from-recording <会话> --no-train` 是**只建库+质检**的体检口径(不动臂、不烧 GPU), 报完数字就退。
- 状态: `~/zmax_data/gs_map/status.json`(页面 /ctl/gs_map 轮询); 文档 `docs/MAPPING-3DGS.md`。

## 手动走位采集(操作员用控制器自己的“运动到点”, 助手只采集)

什么时候用: 长直线转移被控制器以**奇异点**拒发(`50102`/`50120`, 且把同一根直线拆小步也没用) ⇒ 自动走位那条链
一步都走不动, 改成**操作员用控制器自己的“运动到点”逐点走**(它走关节空间, 实测能穿过去), 助手只负责采集 + 真值核对。

- 🔴 **采集必须“全程连续”, 不能“到点停一下再采”**: 采集端按内容 md5 去重(见下), 臂静止时画面不变 ⇒
  一个停驻点只剩 **1 张唯一帧**, 6 个点 = 6 张, 建不出东西。定式: 操作员起步前就把采集挂上(`--secs 0`,
  收工往会话目录放 `STOP`), 走位全程连续出帧(逐帧配真值位姿); 每个点只让他**停 3~5 秒**供位姿核对。
- **点位核对用真值, 不用他说的名字**: 到位后读 `latest.json` 与示教点比 Δmm 并报出; 手动走位跳过了执行器的
  到位判据(<3mm), 这一步是唯一的口径。
- ⚠️ **别站在臂相机正前方**: 人在画面里那几帧是废帧(伪几何), 采集期间要么不入镜, 要么事后按帧位姿/掩膜剔除。
- 走位纪律(现场照念): 速度放慢 · **平移保持高度**(先到横移高度再平移, 别边降边挪) · 尽量不翻腕。
- 手动走位期间助手侧的运动闸门**照旧关着**(不下发), 只留只读采集与真值核对 —— 现场手上有急停, 别抢。

### 一键「人工走点 · 同步建图」模式 (`gs_map_run.py --manual`) —— 现场首选

老倪口径: 「我走点, 不也可以建图么? 我动, 你同时建图」。比逐点手动采集更省事: 臂始终在现场手上,
助手只做两件事 ⇒ **不走授权真动、不碰手动白名单、不下发任何动作**。

```
~/zmax/venvs/gs-venv/bin/python tools/gs_map_run.py --manual --incremental --inc-steps 3000 [--tag <已有会话时间戳>]
```
- `--manual-every N`(env `GS_MANUAL_EVERY_S`, 默认 45) = 每 N 秒一轮增量建图(建库去重→续训→质检)
  ⇒ **走的过程中地图就在长**, 不是走完才建。会话一直转到 `STOP` 为止(内部把 rounds 抬到 ≥200);
  收工 = 往会话目录放 `STOP`(页面「停止建图」)。
- **会话可续采**: `--tag <时间戳>` 复用已有 `map_sess_<tag>` 目录 —— `gs_capture.py` 的 `frames.jsonl` 是
  **append** ⇒ 换模式/重启接着采, 前面采到的帧一张不丢(实测同一会话连续累积并跨模式接续)。
- 🔴 **被污染过的会话必须换新 tag, 别在旧会话里接着走**: 每轮数据集是从**整个会话目录**按上限选帧
  ⇒ 前面那段"边走边甩"的废帧会**一直留在池子里**, 之后哪怕用户改成"走一步停一步"走得很规范,
  那几轮 `unique_images`/`static_scene` 仍照旧 FAIL、门继续拒 —— 现场看到的就是"我这次明明停稳了怎么还不出图"。
  定式: 用户说"我重新走一遍"时, **用新 tag 起一轮新会话**(默认时间戳即可), 旧会话**存档不删**
  (事后可用 `--from-recording` 单独复核); 判据 = 新会话首轮那两个 FAIL 消失。
- 🖐 **拖动/示教模式(`operation=drag · mode=manual`)与人工走点完全兼容**: 只读采帧 + TCP 真值照常
  (实测帧龄 0.03s), 不用为此切回自动模式。同时提醒现场: **这个状态下工位页的点动/回点位/空间点按钮一律被
  控制器拒**(前置要求 idle+automatic) —— 人工走点用不到它们, 别去点, 点了只会看到"机器人不空闲"。
- 页面「▶ 开始建图」可整体切到该模式(不用再点🔓授权真动); 回旧的"程序自己跑点"模式用 env 开关重启推流服务。
- 🔴 **人工模式别让 L5 VLM 挡路**: 选点那条链单次最长 300s(硬墙钟预算), 而"该往哪走"在用户手上 ⇒
  人工模式把建议点降级为**纯几何兜底**(`--targets spaces --order novelty`, 瞬时可出), 只当提示、绝不下发。
  实测: 留着 L5 时"第一条建议"卡 75s+ 才出现, 人站在机器前等这个没意义。
- 🔴 **重启 driver 前必须按显式 pid 一并停掉 `gs_capture.py`(孤儿采帧)**: 旧 driver 被 kill 后, 它的
  `--secs 0` 采集子进程**会继续活着**; 再起一个新的 = **两个 capture 往同一个 `frames.jsonl` 追加**
  ⇒ 帧率翻倍(实测 8Hz→17Hz)、帧号/位姿序列互相错插。定式: `gs_map_run` 与 `gs_capture` 两个 pid 都停,
  核实 `ps` 里一个不剩再起新的。
- 🔴 **旧自动模式"建图在跑但臂不动"的第一嫌疑 = 热读白名单缺条目**: 白名单 = 代码常量 ∪
  `data/skills/l2_atomic/ctl_abs_skills.json`(**热读覆盖层, 改完立即生效、不用重启服务**);
  覆盖度兜底偏爱"离已访问视点最远"的点(实测选 `L2.goto_space8`), 这条不在白名单里时腿直接回
  "技能 'X' 不在手动控制白名单里" ⇒ 每轮第一下被拒、采帧白跑。加一行 `"L2.goto_spaceX": "🚀 空间X"` 即修。
- 📊 **"人没动 ⇒ 不训"是正确行为不是故障**: 门判的是**去重后视点**, 人停着不动时 `真正不同视点=1(<30)`
  ⇒ 本轮不训(建库/质检照跑)。要让地图长起来必须真的**动**(平移 + 高度 + 角度), 不是加点位名字。
- 🔴 **动得太快 = 数据自相矛盾 ⇒ 门会拒**(现场看到的就是"我走了半天怎么还不出图"): 快速走位时位姿真值(50Hz 最新值)
  与画面**配错**, 三层门会同时报 `unique_images` FAIL(实测 唯一图 149/400 · 重复率 62.7%) +
  `static_scene` FAIL(同一位姿不同时刻画面差 999/255, 应 <8) ⇒ 本轮不训(建库/质检照跑)。
  定式: **走到位 → 停 1~2 秒 → 再走下一个位置**; 停顿时位姿与画面都稳, 配对准, 那一轮就过门
  (实测出留出 PSNR 33.89dB 那一版正是"人没在猛走"时建的)。宁可少走几步慢一点, 别边走边甩。
- 📈 **把"独立视点 N/门限"当进度条实时报给现场**: 只回一句"视点不足 ⇒ 不训", 人不知道该往哪使劲;
  定式 = 每轮在 `run.log` 与 `status.json.status_line` 同时写 `独立视点 N/30 (还差 M)` —— 走一个**新位置**才 +1,
  原地转不加分(现场据此自查这十几分钟到底攒了几个视点)。实测视点数涨得很快: 人一真动, 3 → 96。
  ⚠️ **两套门槛别混**: driver 的开训门 = **30**, 而质检报告对 `distinct_views` 的建议值是 **≥100**
  (报告里那句"3DGS 建议 ≥100"); 到 30 它会自己开训, 但要真像样就奔 100 走。
  换算给现场: 实测**停一次 ≈ +1~2 个视点**(走 3 步 9→15), 到 30 大约还要十几步。
  走法口径: **绕着同一件工件转一圈**(前/右/后/左, 每格 15~20cm 停一次), 别大范围直线乱走 ——
  孤立视点彼此视锥不重叠, 门照样拒。
- 📊 **现场问"我走了几步 / 够不够"时, 从 `frames.jsonl` 客观报数, 不凭印象**: 位姿按 5mm 量化成簇出
  **停驻档**(样本 ≥15 才算一档) · 算 x/y/z 跨度 · 四元数两两夹角给姿态覆盖; 再抽每档代表帧算
  **纹理指标**(相邻差分均值) 判"这几档有料没料": 实测对着工件的档 5.0~6.8, 抬到高处对着空处只有 3.6~4.5,
  近黑/纯色 <1 ⇒ 能当场告诉现场"这几档白停了、该降回去"。
  ⚠️ **姿态覆盖用四元数夹角, 不要读欧拉角跨度**: 欧拉角有 ±π 环绕假象(实测 `rx` 跨度会报 359.6°, 真实最大夹角只有 36°)。
- 🛑 **跨度够了就收工, 别让现场无限走**: 门是**视点 ≥30 · 跨度 ≥150mm**, 实测 12~20 个停驻档就远超(跨度 400~980mm)
  ⇒ 到达这个量级后要提质只能靠**新区域 / 新高度 / 新角度**, 同一平面再加档收益递减;
  收工顺序固定: 放 `STOP` → 确认采集进程退出 + `capture_summary.json` 落了 → **等在用训练退出**再重建数据集
  (就是上面那条撞崩坑) → 全量重训 → 质量门。
- 📎 走点记账: `scripts/gs_walk_steps.py`(只读每秒采一次 TCP 真值, 位姿在 3mm 内稳 ≥1s 且距上一笔 ≥20mm
  ⇒ 记一"步": 序号/时刻/坐标/距上步 mm, 落 `/tmp/gs_walk_steps.jsonl`)。现场问"我走了几步/停够没停够"
  时用它出客观清单(不用凭印象), 也是"走一步停一步"纪律的取证。
- 📋 日志/状态: `~/zmax_data/gs_map/run.log`(逐步留痕) + `~/zmax_data/gs_map/status.json`
  (`step=walk` + 建议视点行, 页面轮询这个文件)。**起后台跑时把 stdout 重定向到 run.log**,
  否则页面日志区看不到新行(状态仍会走 status.json)。

## 交付面的网页查看器 (用户要「自己在窗口里转着看」)

- 产物三件: `gs.ply`(真尺度, 给下游/仿真) · `gs.splat`(32B/高斯, 查看器格式) · `renders/*.png`(留出视角渲染图)。
- 🔴 **先验资产字节, 再怪查看器**: .splat 记录序 = 位置 Float32×3 · 尺度 Float32×3(**已激活, 线性, 别再 `exp`**)
  · 颜色 RGBA uint8 · 四元数 4×uint8。判据: 长度 % 32 == 0; 位置有限; 尺度**全为正的小数**;
  颜色均值与采集画面亮度同量级; alpha 大多不透明; 四元数非全 0。出现负数尺度/颜色全 0 ⇒ 改导出, 不要去调查看器。
  若尺度分布过小(实测 p50 0.2mm / 59 万高斯 / 0.5m 场景)⇒ 查看器里本来就稀疏发暗: 要更"实"就往
  "少而大"调致密化, 别用查看器参数掩盖。
- **页面与资产必须同源**: 挂在**既有页服务**的路径下(页面 + `/gs/latest.splat` 这类只读路由), 不要另起端口
  —— 公网反代入口(/st/ 这类)会自动继承, 且不踩"https 页取 http 流"的混合内容红线。
  定点资产名必须**白名单正则 + realpath 落在资产根内**(越界与非白名单扩展名都要实测回 404)。
- **查看器 JS 下到同域**并把默认资产地址改成同域相对路径 —— 出厂默认打 CDN, 弱网/手机内置浏览器必被拦(永远转圈)。
  ⚠️ `tools/web/lib` 常被 `.gitignore` 的 `lib` 规则挡掉 ⇒ JS 没入库, 别人克隆后页面直接白屏;
  加 `!tools/web/lib/` + `!tools/web/lib/**` 并用 `git check-ignore -v` 验证后 `git add -f` 补提交。
- 🔴 **相机口径决定"看得到/全黑"**: 查看器默认相机对着**原点**、距离固定; 而我们的 .splat 是**真尺度世界坐标**
  (场景中心离原点几十厘米)⇒ 直接用是**全黑**。定式 = 浏览器侧把点云质心**平移到原点**(尺度不动)
  + 用 hash 传视图矩阵、距离按场景半跨度算(该矩阵约定把平移放在最后一行; 查看器读到 hash 会同时关掉自动轮播)。
- ⚠️ **出厂查看器的滚轮语义是“绕轨道旋转”(缩放在 ctrl+滚轮)** ⇒ 现场必报「滚轮怎么不能放大或缩小」
  + 而且 hash 一旦被丢, 它会重新开自动轮播 = 「场景自己乱动」。定式: 把滚轮改成**缩放**(步长按当前距离 ~6%/格),
  左键仍拖转; 改的是下到同域的那份 `main.js`, 改完 `node --check` 并比对"服务端发的字节 md5 == 仓库文件 md5"
  (页面/JS 热读, 不用重启服务, 只需现场刷新)。
- ⚠️ **无头验证"到底渲染出来没有"不能用 rAF 之外的 readPixels/drawImage/toDataURL** —— WebGL 画布默认
  `preserveDrawingBuffer=false`, 那里读到的是**已清空缓冲 ⇒ 假黑**; PNG 体积也**不是**证据(黑图照样几十 KB)。
  可信取法 = 在 rAF 内(排在查看器本轮绘制之后)把画布 drawImage 进 2D 画布再 getImageData 统计。
- 🔴 **"点了实景查看器就卡死" = 显示降采样上限的事, 不是资产大小、也不是服务卡**: 先量服务端 —— 页面 0.7ms、
  `/gs/latest.splat` 3.5ms、`/snapshot/*.jpg` 0.4ms 全毫秒级返回 ⇒ 卡在**浏览器主线程排序高斯**。
  查看器只对**超过 `KMAX`** 的高斯做显示降采样 ⇒ 资产**刚好落在上限以下**时一次都不降, 十万级全量排序
  ⇒ 手机/弱机假死(实测: 上限 12 万 vs 资产 10.1 万)。定式:
  ① 上限压到 **6 万**(砍掉的是半透明雾状粒子, 视觉几乎无损);
  ② 页面提示里的高斯数**必须实时取** `/gs/list`, 硬写"58.9 万高斯"会让现场以为加载的是大资产(资产早换了);
  ③ 给现场的退路写进页面: 「↗ 新窗口打开」(独立连接池, 不与工位页那几路视频抢同源 6 条连接)、
  「🖼 参考渲染图」(静态图不吃 CPU)。
  ⑤ 🔴 **大资产根本不许发给浏览器 —— 服务端先预算一份轻量显示副本**(实测 284 万高斯/86.7MB → 6 万高斯/1.8MB,
  下载量降 47×, 服务端预算 0.04s): 路由给 `/gs/latest_display.splat` + `/gs/<名>.display60k.splat`,
  页面**默认只拉它**; 全量只在用户显式要时才拉(几十 MB ⇒ 必须独立窗口/独立连接池)。
  判据改口径: **卡不卡由两件事决定 —— ①发给浏览器的字节数 ②显示的高斯数**;
  只降采样显示(②)而不减字节(①)照样卡: 下载与解析都在宿主页同一个主线程上。
  ⑥ 🔴 **宿主页(工位页那类)绝不自动加载 3D**: 同标签页里的 iframe 与宿主页**共用主线程和同源连接池**,
  自动去拉全量 splat 会把整个浏览器拖住(现场原话「卡住鼠标和其它窗口」)。定式 = 进页面先给静态图(秒出),
  3D 一律**用户点了才加载**, 且点了只拉轻量副本。
  ④ 🔴 **挑哪 KMAX 个必须用线性算法, 不许对全量高斯做 JS `sort(比较器)`**: 200 万+ 高斯时比较器被调用
  约 4000 万次 ⇒ 主线程一卡十几秒~几十秒, 现场看到的就是**白屏/假死**(此刻服务端一切正常、页面也不报错,
  所以别去查服务端)。定式 = 两趟线性 + **256 桶 alpha 直方图**: 统计 `u8[i*32+27]` → 从 255 往下累加到
  ≥KMAX 得阈值 → 阈值以上整块 `set()` 收下, 不足再从阈值桶补满(`new ArrayBuffer(KMAX*32)` + 每记录 32B 整块 memcpy)。
  实测 216 万高斯从数十秒降到亚秒级。
- 🔴 **工位页那格「怎么没有建好的高斯图」= 默认态是空的, 不是没建**: 那格默认露出的是**未加载的 iframe**
  (`about:blank` = 一个空黑框), 而渲染图其实已经被轮询取回来、也设进了 `#gs_img`, 但它的容器还挂着
  `display:none`(只有点「🖼 参考渲染图」才显示) ⇒ 用户读成"没建出图", 他不会先去点旁边按钮试。
  定式: **服务端只要给了 `image_url` 就默认把它显示出来**(解除容器隐藏 + 收掉"还没有训练好的场景"占位);
  两个按钮只负责**切换形态**(可拖拽实景 ↔ 静态渲染图), 并且切换要打 `dataset.manual='1'` 这类标记,
  同类页面的通用定式见 `user-facing-dashboard-delivery` 的态⑥。
- 🔴 **「打开是白屏」= 大资产还没拉完/没画完那段时间屏幕上什么都没有**: `.splat` 是几十 MB 级
  (实测 69MB / 216 万高斯), 拉取 + 挑显示副本期间界面空无一物 ⇒ 用户读成"坏了/没建出来"。三条定式:
  ① 页面**先垫一张轻量静态图**(同域的参考渲染图, 几百 KB 秒出)盖在画布上 —— 这一条同时是弱网/无 WebGL 的兜底;
  ② 查看器接管后(数秒)再撤掉垫底图, 并留一个**「🖼 参考图」按钮**随时叫回来;
  ③ 宿主页面(工位页那种)给 iframe 加**超时退回**: N 秒还没画出来就切回静态图并写明"要 3D 点「↗ 新窗口打开」"。
  判据: **任何时刻那一格都有画面**(加载中=静态图, 就绪=3D), 不允许"先空着等它加载"。
- 🔴 **白屏的一行诊断口径(你看到的和用户看到的不是同一台机器, 别猜)**: 让现场念**页面顶部那行状态字** ——
  停在「拉取 …」= 没拉下来(同源连接被工位页那几路视频占着/弱网) · 显示「高斯 <N> · 已居中缩放…」而画面还空
  = 拉到了但没画出来(多半 WebGL 被禁/走软件渲染, 让他看 `chrome://gpu` 的 WebGL2 是否 Hardware accelerated) ·
  屏幕上有红框 = 把那句报错原文给我。一行字就能把三种成因分开, 胜过十轮"还是白屏"。
- ⚠️ **这类重资产页面的无头浏览器验收能力有限, 别把它的表现当现场结论**: 软件 GL 拉 200 万高斯时主线程被占满,
  **连读一个 DOM 文本的 JS eval 都会超时**(实测同一个页面先能 eval、重渲染后必超时) ⇒ 此时能作数的证据只有
  服务端侧(页面字节 == 仓库文件 md5 · 资产 200 · 查看器 console 的"加载到 N 个高斯")加上**让用户念那一行字**。
  汇报要如实写"我看不到你那块屏幕", 不要把"代码里改了、按逻辑应该会显示"讲成已验证。
- ⚠️ **资产列表里的 “latest” 是按 mtime 排的, 不能当“训练好了”**: 刚起训的那一版 `gs.splat` 还没落盘,
  于是 `/gs/list` 的 `latest` 可能就是**上一版**的模型 ⇒ 向用户报资产必须带
  **资产名 + 步数 + 高斯数 + 留出 PSNR**(实测 `map_sess_…_model · 30000 步 · 216 万高斯 · 18.83dB`),
  只说"最新资产"会让现场以为看到的就是刚才那版。
- 📈 **高斯数膨胀要跟 PSNR 一起报(过拟合的第一指标)**: 同一份数据 3000 步出 ~10 万高斯,
  30000 步能涨到 **200~290 万**(实测 216 万 → 284 万)而留出 PSNR 只有 16~19dB ⇒ 报数时两个数一起给。
  要压先动**致密化阈值** —— `gs_train.py` 已把旋钮做成命令行参数(默认 = gsplat 官方默认, 不传即老行为):
  `--prune-opa 0.005→0.01`(更狠剪透明) · `--grow-grad2d 2e-4→4e-4`(长得更少) · `--grow-scale3d/-scale2d`;
  另两个仍是 `--refine-stop`(已 40%)与 `--sh-degree`。
  ✅ **实测收益(同数据集/同门/同 30000 步, 只动这两个旋钮)**: 284 万高斯 → **133 万**(减半), 留出 **18.29 → 20.40dB(+2.1)**,
  训练 37.40 → 36.14(过拟合减轻), 且步进快 ~3× ⇒ **先收致密化, 再谈加数据**; 顺序反了就会把“数据不够”当结论。
  🔴 **"加数据就更好"是错的, 一律用同口径多版对照说话**: 同场景同门实测 268 帧/124 视点/216 万高斯 → 留出 **18.83dB**;
  扫到 400 帧/186 视点/284 万高斯 → 留出 **18.29dB**、训练 37.40dB(上一版 34.58) ⇒ 数据 +50%、视差翻倍
  **反而 −0.54dB**, 训练-留出差拉大 = 过拟合, 瓶颈在致密化不在数据量。按交付门槛"要有提升而非仅不回退",
  这一版**不能进默认档**, 留在资产列表里当对照版。
- 🔴 **拿“模型渲染图”当参考画面 = 把历史帧冒充实时帧**: 3DGS 的留出渲染图是**采集那一刻的场景**(模型就是用那批帧训出来的),
  臂/工件一动它就过期。所以实时页面里那一格的**默认位必须是相机实时帧**(图下标“更新于 HH:MM:SS · 实时画面, 不是模型渲染”),
  模型渲染图只放在「🖼 参考渲染图」按钮后面, 并在图上标**来源资产名 + 渲染时刻 + 帧龄**。
  ⚠️ “最新资产/渲染图”只能有**一个**取数函数, 且按**产物 mtime** 取: 实测同一路径 `/gs_render.png` 被**两个处理器**接住
  (链首一个 + elif 链尾一个), 尾随那个是 `sorted(glob('*/renders/holdout_00.png'))[-1]` = 按**路径字母序**取尾
  ⇒ 名字排序靠后的老资产(`verify_train_*`/`scene_*`)会被当成"最新"。这种"一条路径两个处理器"的坑表现为:
  **改了一个, 生效的是另一个**(先量证据: 现场看到的图 md5 与目标资产文件对不上, 别凭代码猜)。
  定式 = 收敛到单个 `_gs_latest_render()`(与 `/gs/list`、查看器同源), 改完按 md5 核对"服务端返回的图 == 目标资产的 renders/holdout_00.png"。
  ⚠️ 但**渲染图本身永远是历史帧**(模型就是用采集那一刻的帧训的), 所以“历史帧”这个观感不能全赖取数:
  实时页面那一格的默认位必须是相机实时帧, 渲染图只作按钮后的对照 —— 这才是根治。
  ⚠️ 页面要展示的这些元数据(资产名/渲染时刻/帧龄)放进**状态 JSON 的字段**返回 —— 不要只塞自定义响应头:
  自带页服务的发送助手常常只透传白名单头(`Cache-Control`/CORS), 自定义 `X-*` 头会被**静默丢掉**(页面永远拿不到)。
- 🔴 **用户说「打开我刚跑的那张图」时, 先核这轮到底有没有出资产, 再决定打开哪一份**: 三看 ——
  ① `~/zmax_data/gs_map/status.json` 的 `step` 与「独立视点 N/30」行 ② 会话目录下有没有 `map_<tag>_m*` 模型目录
  ③ 全盘最新 `.splat` 的 mtime 是否晚于本次开跑时刻。人没动/视点不足时 **一项都不成立**(实测 1/30、最新资产还是几天前的)
  ⇒ 如实回「这轮没出资产」+ 给两条让视点涨起来的路(助手按视点清单驱动臂 / 现场手拖), **别把上一版资产当他的新图交付**。

## 多次扫描合并成一个数据集 (同一场景 · 同一手眼/TCP 真源)

现场问「前后两张图能合并么? 都是同一个场景」⇒ **能, 而且该合**: 覆盖/视差翻倍, 比再扫一遍便宜。
前提只有一条: 两次的位姿在**同一基坐标系** —— 同一台臂 + 同一套手眼标定 + 同一 TCP 真值源即可,
与时间无关(跨天也行)。相机不在臂上 / 换过手眼 ⇒ 不能直接合, 先把外参统一。

- 做法首选是 **合并数据集再一次全量训**(全局一致); 从旧 `.ply` 续训(`--init-ply`)只是快, 一致性弱一档。
- 合并器 `tools/gs_dataset_merge.py --out <新目录> --in <数据集1> <数据集2> …`:
  `images/` 按**源标签前缀**改名复制(防重名覆盖) · `cameras.json` 的 `frames` 拼接并改写 `file` ·
  内参/分辨率不一致**直接拒**(不许把错内参的监督混进来) · `meta.json` 记来源可追溯。
- 🔴 **自测就用“同一数据集合并两次”**(标签必然冲突, 最严): 断言 `帧数 == images 数` + 每个 `file` 都存在
  + `T_cam2world` 逐位一致 + 内参校验通过。踩过: 两源同名时第二份**覆盖**第一份 ⇒ 502 帧指向 251 张图
  (帧数看着对、图少一半), 只看帧数会放过它。
- 合并后跑常规质检门并与上一版**同口径对照**, 报留出 PSNR 是涨还是没变。
- 🔁 **要走的每一趟都顺手采**: 为复位/回起点而走的长轨迹(比如沿操作员拖过的路径反走 3~4 米)本身就是一次扫掠
  ⇒ 走的同时就开采集(`gs_capture.py --secs 0`, 到终点放 `STOP`), 走完并入上一版数据集 ——
  别"先走回去、再重走一遍采"。

## 验证口径(交付资产前)
- 资产: ply 高斯数、留出视角 PSNR、资产 bbox 与真实工作区尺度比(与 `env_model.json` 的包络交叉核)。
- 🔴 **判"合格/不合格"一律用项目自己的门 (`tools/gs_quality.py`), 不要拿你自己更严的主观口径下结论**:
  实测一版留出 18.83dB (训练 34.58) 被我先按"糊了"口头判了不合格 —— 而门的三条 (超平凡基线 ≥3dB /
  渲染有结构 / 拟合训练视角 ≥5dB) **全部 PASS**。正确报法 = **先给门的判决与逐条数字**, 再补一句主观差距
  (留出与训练差 ~16dB ⇒ 新视角质量一般) 并点出真瓶颈 (视点基线 / 致密化)。反向也成立: 门 PASS **不等于**可交付
  —— 交付门槛仍是"有提升而非仅不回退"(同口径对照上一版)。
- 采集: `capture_summary.json` 的 `pose_*_range_mm` 必须非零(**全零 = 臂没动/位姿源不对**), 且帧数与位姿样本数对得上。
- 🔴 **"位姿跨度全零"要分清"臂真停着"还是"位姿源冻了"**: 真值文件 `tcp_out/latest.json` 的 `ts` 在前进
  但 x/y/z 一字不变时两种可能都成立 ⇒ 判据 = **跟控制器直读对一对**(`bash tools/rokae_sdk_run.sh pose`,
  它给 `sampler.age_s`): 直读值 = 文件值 ⇒ 臂**真的停着**(现场说"我动过了"往往指上一段动作,
  当前会话采到的就是静止的 1~2 个视点, 别去修位姿源); 不一致 ⇒ 位姿源冻结, 先修源再谈建图。
- 与真机同口径: 渲染出来的图喂回检测/策略, 与真机同帧做对照(别只报“看着像”)。
