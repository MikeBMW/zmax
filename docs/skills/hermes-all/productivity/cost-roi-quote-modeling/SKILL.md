# 成本 / 报价 / ROI 建模

## When to Use
- 客户立项 / 投标 / POC 要「单套多少钱、几年回本」，或客户拿「2 年回本」压价。
- 给配置中心加/改「成本/报价」页、画布成本节点、立项文档里的账。
- 问「怎么用成本分析算 ROI、商业模式怎么搞」。
- 要判断某个配置组合（工位数/班次/型号数/人力成本）到底能不能成交。

## 铁律一：先分层口径，再报回本年
一个「2.02 年」必须能拆成四层，缺一层就是夸大：

```
A 上限    = 售价 / (heads × 人力)                         人效1.0 · 零OPEX · 零NRE
B +OPEX   = 售价 / (heads × 人力 − OPEX)                  扣维护率 + 复训/年 + 软件年费
C +人效   = 售价 / (η × heads × 人力 − OPEX)              η 来自任务配置 × 性能配置
D +NRE    = (售价 + 实施NRE) / (η × heads × 人力 − OPEX)  客户真实投入
```

对外只报 C / D；A 只能作为上限参考并**明示三条假设**。A 与 C 差一倍是常态（示例：2.02 → 4.09 年），
只报 A 的后果是客户或老板拿一遍计算器就穿，后面所有数字都不再被信。

## 铁律二：客户 ROI 与 我方 ROI 分开算
- 客户侧：净年省 → 回本 → NPV(5 年, r=8%) → IRR。
- 我方侧：首台成本 / 复制台成本 → 毛利 / 毛利率 → LTV。
一张表混着算必然自欺：同一售价在客户侧是「投入」，在我方侧是「收入」。

## 铁律三：先算成交区间，再谈价格
```
底价 floor   = 我方成本 / (1 − 目标毛利率)
客户上限 ceiling = 净年省 × 客户目标回本年限
可谈 ⟺ floor ≤ ceiling
```
不成立时**改配置，不降价**。可动杠杆按有效性排序：多工位（摊软件与 NRE）→ 三班（放大 heads）
→ 换更便宜的力控臂（硬件是主成本）→ 降产品档 → 软件改订阅 → 卖软件授权、硬件让给集成商。

## 铁律四：三个配置驱动成本行，不许另填一遍
| 配置 | 驱动量 | 落到哪一行 |
|---|---|---|
| 模型配置 | 在役层 L2–L5、产品档 | 域控算力档、软件价、年复训 |
| 任务配置 | 工位数 / 班次 / 型号数 / 来料形态 / 换型时间 / 精度档 | 硬件×工位、软件一份、实施 NRE、结构人效 η_struct |
| 性能配置 | CT / 成功率 / uptime / MTBF / 自恢复率 | η 乘子、质保准备金、维保人力 |

性能只引用指标 **id + stage**，不复制数值；模型只引用指针，不抄模型名；任务只读项目档案。
算法收口到一个函数 `estimate_config(model, task, perf)`，页面 / 画布节点 / 文档导出三处调同一个，
派生值（total / payback / 毛利）一律不落盘。

## 铁律五：每个系数标来源
三色标签 `[真源]` / `[实测]` / `[假设]` + 路径，点开能追。
人工单颗 CT、客户侧人力综合成本、实施人天这三项必须现场实测；未实测前不进默认档、不进对外承诺。
拿阶段目标值（EVT/DVT/PVT）当量产承诺也是编造 —— 量产只认 PVT 且须实测。

## 铁律六：利润在复制台，不在首台
首台成本 = 硬件 + 软件研发摊销 + NRE，按目录价卖毛利接近 0；第 2 台起边际成本只剩硬件，
毛利率跳到 40%+。所以商业模式卖的是**可复制的工位数**：首台按成本价 + 验收对赌拿 POC，
复制台按目录价吃边际毛利，第 3 年起叠加软件年费。

## 铁律七：模式按 η 与工位数选，不按客户偏好选
- 买断（整线）：3 工位起、3 班优先，是唯一能吃满复制毛利的形态。
- 买断 + 软件订阅：POC 期首选；降客户 CAPEX、给我方经常性收入，总价可以不变。
- RaaS / 按工位月费：只在 η≥0.9 且多工位时自持；否则交融资租赁方，别自己扛 CAPEX。
- 按颗 / 按盘：单颗人工成本往往只有几分钱（示例 0.037 元/颗），单工位年流水十几万，
  只适合超大产量或多工位阶梯价，不做主模式。
- 软件授权 / 能力包：硬件客户自购，毛利最高，适合竞标与被硬件成本拖死的场景。

## 流程
1. 读三份真源：单套成本模型（hardware/software/labor/line）、项目 BOM 的 roi 段（维护率/量产系数/批量折扣/客户目标回本）、性能指标表（stage 目标值）。
2. 建系数表 `drivers`：model_tiers / task_coeff / perf_map，每个系数写 value + 来源 + 状态。
3. 写 `estimate_config()`，CLI 带 `--json` 给节点与文档吃；页面只调它。
4. 跑边界矩阵（`scripts/quote_matrix.py`）：工位 × 班 × 型号 × 人力成本，输出回本 / 区间 / 判定。
5. 出三件：分层口径表（A/B/C/D）、成交区间（floor vs ceiling）、模式推荐（每条带数字）。
6. 判据：页面 == CLI 逐字段同源；三配置改动触发对应行重算；派生值不落盘；真源字节级还原；其余页签零回归。

## 坑
| 坑 | 症状 | 修法 |
|---|---|---|
| 把「年节省」当净收益 | 回本看着漂亮，客户一问维护费就崩 | 先扣 维护率×售价 + 复训/年 + 软件年费，再算净年省 |
| 人效比拍一个 0.6 / 1.0 | 报价里最关键的一个数没有推导过程 | 拆成 η_struct(任务) × 成功率 × uptime × min(1, 人工CT/机器CT)，逐项标来源 |
| 把 NRE 摊进硬件 | 毛利算错，首台看着赚钱其实亏 | NRE 单独一行；12 万 vs 31 万能让回本差 1.5 年 |
| 拿软件售价当成本 | 首台毛利算成负数或虚高 | 软件成本用研发摊销（单套 3~6 万），售价是份额不是成本 |
| 只压软件价 | 谈了半天毛利没动 | 硬件单价才是主杠杆（机械臂往往是域控的 2 倍以上），换臂省 4.5 万比砍软件有效 |
| 含税/未税、一次性/年费不写 | 毛利率差几个点，越算越乱 | 每个价格显式标 `未税/含税` 与 `一次性/年费` |
| 先报价再跑边界 | 单工位单班 + 9~12 万/人年 + 30% 毛利基本是空区间 | 先跑矩阵找可行窗口，不成立就不接这个形态 |
| 用客户「2 年回本」反推售价 | 倒挂：算出来的价低于成本 | 2 年只用来算 ceiling；定价从 floor 往上走 |

## 汇报口径
三件事：**分层口径下的真实回本 / 成交区间是否成立 / 推荐哪种模式**。
不列长选项清单，不说「可以再研究」；模式建议必须带数字和成立条件。
