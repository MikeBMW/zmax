# 成本 / 报价 / ROI 建模

## When to Use
- 客户立项 / 投标 / POC 要「单套多少钱、几年回本」，或客户拿「2 年回本」压价。
- 给配置中心加/改「成本/报价」页、画布成本节点、立项文档里的账。
- 问「怎么用成本分析算 ROI、商业模式怎么搞」。
- 要判断某个配置组合（工位数/班次/型号数/人力成本）到底能不能成交。

## 铁律一：先分层口径，再报回本年
一个「2.02 年」必须能拆成四层，缺一层就是夸大：

```
A 上限    = 售价 / (heads × 人力)                         人效1.0 · 零OPEX · 零NRE
B +OPEX   = 售价 / (heads × 人力 − OPEX)                  扣维护率 + 复训/年 + 软件年费
C +人效   = 售价 / (η × heads × 人力 − OPEX)              η 来自任务配置 × 性能配置
D +NRE    = (售价 + 实施NRE) / (η × heads × 人力 − OPEX)  客户真实投入
```

对外只报 C / D；A 只能作为上限参考并**明示三条假设**。A 与 C 差一倍是常态（示例：2.02 → 4.09 年），
只报 A 的后果是客户或老板拿一遍计算器就穿，后面所有数字都不再被信。

## 铁律二：客户 ROI 与 我方 ROI 分开算
- 客户侧：净年省 → 回本 → NPV(5 年, r=8%) → IRR。
- 我方侧：首台成本 / 复制台成本 → 毛利 / 毛利率 → LTV。
一张表混着算必然自欺：同一售价在客户侧是「投入」，在我方侧是「收入」。

## 铁律三：先算成交区间，再谈价格
```
底价 floor   = 我方成本 / (1 − 目标毛利率)
客户上限 ceiling = 净年省 × 客户目标回本年限
可谈 ⟺ floor ≤ ceiling
```
不成立时**改配置，不降价**。可动杠杆按有效性排序：多工位（摊软件与 NRE）→ 三班（放大 heads）
→ 换更便宜的力控臂（硬件是主成本）→ 降产品档 → 软件改订阅 → 卖软件授权、硬件让给集成商。

## 铁律四：三个配置驱动成本行，不许另填一遍
| 配置 | 驱动量 | 落到哪一行 |
|---|---|---|
| 模型配置 | 在役层 L2–L5、产品档 | 域控算力档、软件价、年复训 |
| 任务配置 | 工位数 / 班次 / 型号数 / 来料形态 / 换型时间 / 精度档 | 硬件×工位、软件一份、实施 NRE、结构人效 η_struct |
| 性能配置 | CT / 成功率 / uptime / MTBF / 自恢复率 | η 乘子、质保准备金、维保人力 |

性能只引用指标 **id + stage**，不复制数值；模型只引用指针，不抄模型名；任务只读项目档案。
算法收口到一个函数 `estimate_config(model, task, perf)`，页面 / 画布节点 / 文档导出三处调同一个，
派生值（total / payback / 毛利）一律不落盘。

## 铁律五：每个系数标来源
三色标签 `[唯一依据]` / `[实测]` / `[假设]` + 路径，点开能追。
人工单颗 CT、客户侧人力综合成本、实施人天这三项必须现场实测；未实测前不进默认档、不进对外承诺。
拿阶段目标值（EVT/DVT/PVT）当量产承诺也是编造 —— 量产只认 PVT 且须实测。

## 铁律六：利润在复制台，不在首台
首台成本 = 硬件 + 软件研发摊销 + NRE，按目录价卖毛利接近 0；第 2 台起边际成本只剩硬件，
毛利率跳到 40%+。所以商业模式卖的是**可复制的工位数**：首台按成本价 + 验收对赌拿 POC，
复制台按目录价吃边际毛利，第 3 年起叠加软件年费。

## 铁律七：模式按 η 与工位数选，不按客户偏好选
- 买断（整线）：3 工位起、3 班优先，是唯一能吃满复制毛利的形态。
- 买断 + 软件订阅：POC 期首选；降客户 CAPEX、给我方经常性收入，总价可以不变。
- RaaS / 按工位月费：只在 η≥0.9 且多工位时自持；否则交融资租赁方，别自己扛 CAPEX。
- 按颗 / 按盘：单颗人工成本往往只有几分钱（示例 0.037 元/颗），单工位年流水十几万，
  只适合超大产量或多工位阶梯价，不做主模式。
- 软件授权 / 能力包：硬件客户自购，毛利最高，适合竞标与被硬件成本拖死的场景。

## 分层 = 计费单元（可拆可合的计价底座）

产品档不是代码分支，是**配置清单**：能力特征勾选 → 模型清单 + 场景包数 + 算力位 → BOM → 价格。
而每一层能力要绑一种计费形态，否则三条收入线落不到三方分成上：

| 层 | 卖什么 | 计费 |
|---|---|---|
| L5 场景理解 / 工艺包 | 按件运营（含保底年费） | 元/只 |
| L4 世界模型 / 流形 / 势场 | 年订阅（含复训） | 万/台·年 |
| L3 规划编排 / 收口闸 | 平台授权 | 含在设备价 |
| L2 分组小模型 | 随设备交付（新版按包收） | 含在设备价 |

判据：档位差异必须逐项落到「模型清单 + 场景包数 + 算力位」三样，落到 `if 档位` 就是错的——
N 个场景包 = N 个分支，维护成本会吃掉毛利。三条收入线（设备 / 订阅 / 运营）与层的映射写在口径页，
否则「三方各分多少」永远算不清。

## 流程
1. 读三份唯一依据：单套成本模型（hardware/software/labor/line）、项目 BOM 的 roi 段（维护率/量产系数/批量折扣/客户目标回本）、性能指标表（stage 目标值）。
2. 建系数表 `drivers`：model_tiers / task_coeff / perf_map，每个系数写 value + 来源 + 状态。
3. 写 `estimate_config()`，CLI 带 `--json` 给节点与文档吃；页面只调它。
4. 跑边界矩阵（`scripts/quote_matrix.py`）：工位 × 班 × 型号 × 人力成本，输出回本 / 区间 / 判定。
5. 出三件：分层口径表（A/B/C/D）、成交区间（floor vs ceiling）、模式推荐（每条带数字）。
6. 判据：页面 == CLI 逐字段同源；三配置改动触发对应行重算；派生值不落盘；唯一依据字节级还原；其余页签零回归。

## 量产定价: 摊销分母决定"能不能报价"
- 软件研发摊销的分母必须是**5 年装机量**(或明确的项目累计台数), 不是当年台数: 600 万研发 ÷ (年 10 台×5 年) ⇒ 12 万/台, 而 ÷ (1 台×3 年) 会算出 200 万/台。分母写错会把小批量档报成荒谬价。
- 加一道 **现价封顶**: `price = min(成本/(1−目标毛利), 现价)`。小批量算出高于现价时按现价卖, 并如实报"毛利只有 X%"——这比报高价更能解释"为什么必须先上量"。
- **底价与客户上限必须同时算并当场比对**: 底价 = 成本/0.65, 上限 = 净年省 × 客户目标回本年限。本例 500 台档底价 23.2 万 > 客户 1.5 年回本上限 18.8 万 ⇒ 空区间, 结论只能是"对外按 2 年回本谈"。不比对就会给出一个客户算一遍就穿的报价。
- 三方(硬件/软件/运营)1:1:1 要分**毛利池**(售价−硬件BOM−软件摊销)与**净利**: 运营方还要自己付实施+维保, 按池平分它会比另两方少 1.85 万/台 ⇒ 方案里必须给修正(实施费单列 / 维保改年费 / 32:32:36), 否则没人接运营。
- 首年运营缺口要提前说: 装机量未起时运营方 Y1/Y2 为负(Y1 −4 万), 协议里写"缺口由后续年费优先补偿"。
- 单件折旧是照妖镜: 25 万设备 / (71 万件/年×5 年) = 0.071 元/件 ⇒ 定价不能锚产能, 只能锚人力与良率。
- **按件/运营模式必须把设备资本按折旧计入我方成本**: 只记电费+巡检+备件, 5 年毛利会虚高一倍(实算 45.5 万 vs 该有的 26.7 万), 结论会从「按件不如卖断」翻成「按件是主战场」。口径预先固定: 年成本 = 电 + 巡检 + 装机成本/5; 另报资本回收年数 = 装机成本 ÷ 年毛利。
- **同一张对比表必须按 (包, 年销量) 显式取行**: 用下标取档(`rows[0]`)会把 20 台档的 C 和 50 台档的 A/B 并排, 表格毛利池 39.1 与标题 43.6 当场打架。取完还要逐行相加 == 模型池值。
- **单一产品线只摊自己的研发份额**: 公司级引擎资产按份额摊(例: 本产品线 40% / 5 年)。全摊进一条线会把小批量档做成负毛利(成本 27.3 > 售价 26.8), 逼出一个不可能成交的报价。分摊比例必须写在口径页, 不能藏在脚本常量里。
- **先用自下而上装机容量定量档, 再定价**: 装机台数 = 年产量 ÷ (单机年产能 × 稼动)。算出 TAM≈178 台 / SAM≈63 台后, 「500 台/年」这种**单工位**量档自动作废, 价格表只留 20/50/100 三档 —— 否则整份定价建在一个不存在的市场上。
  但这个容量只封顶**这一个工位/这一个工序**; 老板给的是跨工序的平台级量级（「N 万人 × 转化率」）时, 要拆成「场景数 × 每场景台数」再对账, 不能用单工位容量直接否掉（套路见 `references/packaging-and-market-sizing.md` §1.1）。

## 节拍是工艺锁死的, 不是机器人锁死的
插入后必须驻留(点胶固化/到位保持)时, 节拍 = 驻留时间 ÷ 同时在驻孔位数, 与臂速无关:
4 孔两对交替 = 60s/2 = 30 s/个; 加到 6 孔(三对) = 20 s/个; 7 孔 = 17.1 s/个。
报价/ROI 里产能只能这么算; 对外讲"提产能"一律先说加孔(结构件几千块), 再说换臂(几十万)——顺序说反了客户会认为你要他换机器人。

## 坑
| 坑 | 症状 | 修法 |
|---|---|---|
| 把「年节省」当净收益 | 回本看着漂亮，客户一问维护费就崩 | 先扣 维护率×售价 + 复训/年 + 软件年费，再算净年省 |
| 人效比拍一个 0.6 / 1.0 | 报价里最关键的一个数没有推导过程 | 拆成 η_struct(任务) × 成功率 × uptime × min(1, 人工CT/机器CT)，逐项标来源 |
| 把 NRE 摊进硬件 | 毛利算错，首台看着赚钱实际亏 | NRE 单独一行；12 万 vs 31 万能让回本差 1.5 年 |
| 拿软件售价当成本 | 首台毛利算成负数或虚高 | 软件成本用研发摊销（单套 3~6 万），售价是份额不是成本 |
| 只压软件价 | 谈了半天毛利没动 | 硬件单价才是主杠杆（机械臂往往是域控的 2 倍以上），换臂省 4.5 万比砍软件有效 |
| 含税/未税、一次性/年费不写 | 毛利率差几个点，越算越乱 | 每个价格显式标 `未税/含税` 与 `一次性/年费` |
| 先报价再跑边界 | 单工位单班 + 9~12 万/人年 + 30% 毛利基本是空区间 | 先跑矩阵找可行窗口，不成立就不接这个形态 |
| 用客户「2 年回本」反推售价 | 倒挂：算出来的价低于成本 | 2 年只用来算 ceiling；定价从 floor 往上走 |
| 按件模式不摊设备资本 | 5 年毛利虚高一倍，误判「按件最赚」 | 年成本加 装机成本/5，并报资本回收年限 |
| 跨量档混取一行 | 同表 A 用 50 台档、C 用 20 台档，表内数字与模型差几万 | 按 (包, vol) 取行；表格逐行相加对池值 |
| 研发全摊进单条产品线 | 小批量档报出负毛利，价签没人敢签 | 按产品线份额摊（含比例与年数），写进口径页 |

## 汇报口径
三件事：**分层口径下的真实回本 / 成交区间是否成立 / 推荐哪种模式**。
不列长选项清单，不说「可以再研究」；模式建议必须带数字和成立条件。
