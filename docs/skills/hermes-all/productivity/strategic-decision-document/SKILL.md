# 量化决策文档：从分析到「先投什么」

分析层的活是「说清格局」，决策层的活是「给出顺序和判据」。用户要一次能拍板的文档时，
走这套：可复核的打分 → 可考核的 KPI → 决定资源顺序的敏感性 → 每家/每条动作都带触发条件。

## When to Use

- 「破局点在哪 / 要不要做这件事 / 资源先投哪一件 / 12 个月怎么算过」。
- 老板要一份能上会拍板的简报，而不是一份长报告。
- 竞品/ROI/路线图/性能分析已经做完，需要收口成决策。
- 需要一个以后每季度能重算、不是一次性结论的东西。

工具 API 层面（python-pptx 的读写编辑、模板、图表）看 `powerpoint`；
竞品格局的方法论（7 维 SRI、谁在绕过集成商）看 `competitor-positioning-sri`。
本技能只管「怎么把它变成决策」。

## 铁律

1. **分层诚实：事实 / 判断 / 推演，三层分开写，最后一页必带免责。**
   混淆三层的文档一被追问就废；分层之后反而更敢下结论。
2. **从未执行过的能力记「未测」，绝不估数。** 只有一个本体时，跨本体换型时间就是未测。
   编一个数会让整份文档作废；而「未测」常常就是最有价值的结论——它指出战略支点还空着。
3. **数字只有一个真源。** 分数与派生指标写进 JSON，正文/表格图里的数字全部从 JSON 读。
   手抄必然漂移（图上 8.5、表里 8.4），且改分后无法一键重算。
4. **不要为了让结论好看去调权重。** 排名只动一位是正常结果；论据在**分布**，不在名次。
5. **每个动作必须带触发条件。** 只有动作没有「什么时候执行」的决策表，在评审会上等于没写。
6. **同一件事查到两个不同数字：两个都写，并标「合作前必须核实」。** 不许静默二选一 —— 选一个等于替用户做了
   他没授权的判断。外币口径（美股市值等）单独列，**不进人民币合计**，并写明「与一级市场估值不可比」。

## Procedure

### 1. 定标尺：先写维度定义表，再打分
每维一行：维度 / 量化指标（怎么算这个分）/ 数据来源 / 权重。
表里不出现形容词，只出现「可查的数」或「一次可复现的部署」。

### 2. 加一维：把「我方唯一领先的能力」单独立维
对手通吃的维度是**他们的尺子**，照它打分我方必然垫底。补上自己那一维并给最高单项权重。
平台型/集成型公司的这一维通常是「接口与封装」：跨本体标准化程度、换型工时、工艺包与判据资产、是否被第三方复用。

### 3. 两套权重并行，用 slope 图讲「换尺子」
一套是对手/行业现行口径，一套是含新维度的口径。两列排名连线，一眼看出换尺子的后果。
若某维第一名领先第二名数倍，那不是能力，是位置——这句话比名次有用。

### 4. 每维一张证据表
每格一行证据（出货台数、成功率、参数规模、开源仓库、客户数、BOM）。
我方那一行用系统真源取证（配置文件、任务库、技能模板），不手抄印象。

### 5. KPI：定义 + 基线 + 目标 + 失败线 + 考核方式
- 定义必须能算（分子/分母都写出来）。
- 分母里的估算项单独标注「需现场核对」，不能当既定。
- 设**失败线**而不只设目标：没有失败线的指标不会有人负责。
- 考核方式写实物：视频、日志、验收记录、现场复现。

### 6. 敏感性分析定资源顺序（这一步决定文档有没有用）
把可控变量当旋钮，一次只动一个（其余固定），画单变量曲线看斜率。
结论常与直觉相反：**先投看起来最不性感的那件**。敢这么写，文档才叫决策而不是汇报。

### 7. 护城河用「复制成本不对称」论证，不用「我更强」
双组比较：我方补齐对手要多久（采购/接入/积累，月级）vs 对手补齐我方要多久
（与自身商业模式冲突，年级 + 自伤）。倍数差就是存在理由。标明是量级估计，不是承诺。

### 8. 决策矩阵 + 风险排序收口
- 每家/每条一行：定性 / 动作 / 触发条件 / 时间窗。动作必须是动词
  （采购、非独家接入、不合作、对标、观察），不能写「加强合作」。
- 策略每条后面跟一句可执行判据（覆盖率、条款覆盖率、成交结构占比），否则是口号。
- 风险按「会不会让战略失效」排序，第一条永远是「自己的差异化能力测不出来」。

## 从竞品分析到自主进化（feature 表桥）

竞品的模型名（VLA / 世界模型 / diffusion）**不是能力**，直接抄进 roadmap 毫无用处。
要让分析层真的驱动执行层（无论是 roadmap 验收还是自主进化器的 fitness），必须过一道翻译：

```
feature_id | 能力名称（禁算法词）| 完整定义（在 X 条件下做到 Y）| 可测指标+单位+阈值 | 证据强度
F-PREC-01  | 亚毫米盲插对位    | 工件被遮挡时凭力/位移反馈对位| 对位误差 ≤0.2mm   | 论文实测/官方演示/媒体报道
```

三条硬约束：
- 能力名称**不得出现算法词**（VLA、Diffusion、Transformer、世界模型）—— 只写「在什么条件下做到什么」。
  写算法的会退化成模型比大小，而模型比大小是本技能第一步就要避开的陷阱。
- 每条带**可测指标+单位+阈值**，否则无法进 fitness，也无法当验收项。
- 标**证据强度**（论文实测 > 官方演示 > 媒体报道），强度决定它能不能进「对手有我没有」的结论层。

这张表同时是三样东西：竞品差距清单 / roadmap 验收项 / 自主进化的基因与判据来源。
做平台型产品时，它比打分表更重要：打分表说「谁强」，feature 表说「下一步改什么」。

自主进化器要吃的不是公司名，而是这份 feature 表 + 本方可测基线。把进化对象从「超参/阈值」
扩到「能力组合」之前，先确认每一条 feature 都真有一个能算的分子/分母 —— 算不出来的不许进基因。

## 验收（几何 + 眼睛，两者抓的缺陷不重叠）

1. **几何自检**：读回文档，逐 shape 断言 `left>=0, top>=0, left+w<=W, top+h<=H`；
   表格底边距页脚留 ≥0.2 英寸。全幅装饰条会合法贴边，按名字白名单排除，不要放宽阈值。
2. **独立目检**：把渲染出的逐页 PNG 交给子代理/视觉检查，按页给设计契约（这页该有什么），
   只让它报客观缺陷。几何查不出「标签压在散点上」「图被表格盖住」「字被色块边界裁」。
3. **改一处要全量复检**：布局修正会把碰撞从一格推到隔壁一格，只看改过的那页会漏掉新伤。
4. 交付前把「改了什么」和「口径提醒」一起报给用户，不要把过程复述一遍。

## 坑

- **图源比例是版式输入。** `bbox_inches="tight"` 加上远处标注会把横图变成竖图；
  contain-fit 之后只剩一半宽，下面的表格直接盖住它。要给已知框的图，锁 `set_ylim` 且别用 tight bbox。
  **图高不要自己算**：按宽度乘比例推出高度，必然与插图函数实际落盘的高度不一致，
  正文再写死一个 y 就压到图上（实测算出 4.83/3.61 英寸，实际 4.08）。用 `pic()` **返回的 h** 定后续文本起点。
- **散点标签不要手调偏移。** 挪开一个就压到下一个。锁完坐标轴后遍历候选偏移，
  同时判「标签撞标签」和「标签压散点」（点到矩形距离 < 标记半径），取第一个零冲突位。
  纯文本-文本检查会漏掉被点压住的标签。
- **脚本拼中文文案时别用 `%` 格式化。** 文案里本来就带 `25%`、`92%（11/12）`，
  `"...%d..." % args` 会把它们当格式符，抛 `unsupported format character`，而且一次只崩一处。
  混了百分号的段落一律用 f-string，或把字面 `%` 写成 `%%`。
- **中文字体要单独设 east-asian 字面**，只设 `font.name` 只管西文，中文会回落到主题字体。
- **我方低分要照实画**，并在图注点明这是刻意选择（例如「本体 1.0 = 不造本体」）；
  否则读者当成弱点，反而看不出「不追」就是策略。
- **合成指标（被绕过概率一类）标「情景模型 + 系数为设定值」**，只用于比较各旋钮的相对敏感度，
  不预测真实概率。可信度靠分层，不靠数字看起来专业。
- 交付形态固定为「主文档 + 打分 JSON + 重算脚本 + 逐页预览」，让人能改分重算，而不是只能接受结论。
  **但生成脚本只能存在交付目录这一份。** 从 scratch / 备份 / `/tmp` 任何地方 `cp` 覆盖它，会把交付目录里
  改了几十处的排版修正静默回退 —— 产物是对的、脚本是旧的，下次重跑全部白改。
  任何批量 `cp` 之后必须过一道**签名闸**：重新生成到临时路径，逐页逐 shape 比对（名称/坐标/尺寸/文本/表格列宽），
  要求**差异 0** 才允许相信「脚本能重现产物」。改一处文案也要重跑这道闸。
