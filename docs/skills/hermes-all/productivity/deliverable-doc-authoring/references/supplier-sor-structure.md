# 供应商外发 SOR 骨架 (Statement of Requirements)

适用: 向供应商 / 整机厂外发规格书。生成器示例 `tools/sor_export.py`(python-docx 出 Word + 机读 json + manifest)。
数据一律取单一工程库 + 平台真源, 文档里不写死数字。

## 0. 先定采购对象, 再写任何要求

第 2 章的第一张表必须是**交付分工**, 之后才是「被集成系统的作业条件」。写反了整篇口径都会错。

| 分工项 | 供应商 (本次采购) | 我方 (工程集成 / 收口) |
|---|---|---|
| 具身模型 | 取放循环策略与序列规划、多型号自适应配方、异常处置与断点续作 | 提供接口契约与集成环境, 不代研模型 |
| 模型接入 | 按契约交付可替换权重与推理入口 | 接入底层执行链, 保证每帧真调用与收口放行 |
| 硬件本体 | 不提供 | 相机 / 机械臂 / 夹爪 / 真空 / 料盘机构 / 控制系统 |
| 几何真值 | 不提供, 不得自带坐标系 | K / plane_z / cell_geometry / 盘面槽位 (现场标定) |
| 安全红线 | 只读消费, 无否决权 | 急停 / 限速 / 禁区 / 力阈值 (底层独立收口) |
| 底层控制 | 不提供 | 力控与伺服回路 (饱和限幅后下发) |
| 验收 | FAT 工厂验收 (功能/节拍/成功率) | SAT 现场验收 + 全链集成验证 |

- 采购对象是**模型**时, 模板里预置的「整机采购」表不能当采购范围, 改标题为「被集成系统的作业条件」;
  否则与供货边界 `SCOPE_IN` / `SCOPE_OUT` 逐条矛盾, 现场一问就穿。
- 项目级差异(项目名 / 采购范围追加项 / manifest)由**项目档案 overlay** 提供: 一个项目 = 一份 overlay 叠在平台基线真源上,
  导出时传 `--project <PID>`; 并记录合并 sha(改任一份 ⇒ 合并 sha 变 ⇒ 一致性判据抓得到)。

## 1. 章节骨架

| 章 | 内容要点 |
|---|---|
| 封面 | 文件编号(含日期) / 版本 / 项目名 / **交付主体(供应商研制什么 · 我方做什么)** / 导出方式 / 导出时间 / 「待确认」项说明 |
| 1 项目背景与用途 | 作业内容 + 「本规格书由配置中心按当前配置导出, 配置变更后须重新导出对齐版本」 |
| 2 采购范围与交付分工 | 分工表 → 被集成系统作业条件 |
| 3 产品规格 | 工件/载具尺寸重量材质、敏感面(不得压伤的部位) |
| 4 功能需求与功能配置 | 4.1 功能需求(供货边界) · 4.2 在役功能清单(功能ID/名称/层/类型) · 4.3 产品功能条目(可逐条报价/验收) · 4.4 **任务工艺步骤**(步骤/描述/循环/触发/工单规则) |
| 5 性能指标 | 主表按 指标/目标值/口径判据/来源条目/处理; 按阶段 EVT/DVT/PVT 取值; 再列子系统指标与指标体系分组(每条带测法) |
| 6 机器人与末端执行器 | 负载/重复定位精度/末端适配/真空检测与断气保护/夹持力控制/快换 |
| 7 视觉与定位 | 识别对象与三态判定/光照与遮挡退化回退/相机与光源标定方式/坐标系标定口径/不同工作距离的精度**不得混用一个数** |
| 8 料盘与供料机构 | 定位稳定与重复精度/到位与空满异常检测/流转不得损伤/换型时间 |
| 9 电气控制与接口 | 通信协议/IO 点位表与手册/安全等级与防护/**接口契约** |
| 10 环境与安装 | 安装方式/温湿度/电源/气源/洁净度/占地 —— 配置里没有的一律「待确认」 |
| 11 质量与防护 | 接触部位防划伤材料/不得产生碎屑油污/运动部件防护罩/外观线束/关键部件清单 |
| 12 交付物清单 | 整机与末端、供料收料机构、控制系统与软件、图纸、IO 与协议说明、操作维护手册、备件、出厂验收报告、安装调试记录、培训、质保承诺、**配置包(机器可读 JSON + sha256)** |
| 13 验收标准 | FAT / SAT / 外观 / 功能 / 性能(按章 5 逐条) / 兼容性 / 不合格处理时限 |
| 14 质保与售后 | 质保期起算点/远程与现场支持/培训/关键备件与供货周期 |
| 15 变更管理 | 影响节拍/精度/兼容性/安全性/接口/关键部件品牌的变更须书面确认; 变更须同步更新配置并重新导出交付包 |
| 附录 A | 功能配置明细: cfg/cal/dia 三轴逐项 + 在役开关参数(参数ID/中文/当前值/单位/状态) + 引擎侧节点参数(仅供追溯) |
| 附录 B | 系统组成(各子系统 层级/名称/角色/硬件) |
| 附录 C | **待确认项与缺口**, 处置一栏写「谁在什么条件下闭环」 |
| 附录 D | 导出可复现信息: 导出工具 / 数据源 sha256 / 各真源路径 / 子系统口径 / 导出时间 |

## 2. 必带三附录 (供应商可逐条对照, 缺一不可)

### E 配置表关联性 —— 需求 ↔ 配置项 追溯矩阵
- **E.1 关系总览**: 关系表按 (源类型, 目标类型, 关系) 分组计数。典型链条:
  功能→模块(对应模块) · 模块→代码(实现) · 产品特征→模块(用到) · 特征→子系统(归属) · 验收→分级(分级) ·
  能力→接口(IN/OUT) · 特征→能力(能力引用)。
- **E.2 参数关联明细**: 每个可改数字挂到 功能 / 模块 / 系统 / 阶段 / 标准 / 指标组 各多少条。
- **E.3 需求条目 → 配置项**: 每行 = 配置 ID + 条目 + 关联类别 + 真源文件。行源 = 供货边界 / 产品功能条目 / 性能指标 / 工艺步骤。
- **E.4 本任务改写项(overrides)全表**: 逐键给值 —— 这些是供应商必须实现为**可配置**而非硬编码的旋钮。

### F 架构兼容性
- **分层职责表**: 每行 = 层 / 职责 / 与供应商模型的关系 / 接口形态, 明写「供应商交付主体在哪一层」。
- **硬约束逐条**(越界不验收): ① 输入=上游意图/条件, 几何真值由底层提供, 模型不得自带坐标系或标定;
  ② 输出=动作序列, 底层力控与伺服由执行层收口, 模型不产底层控制量; ③ 模型不产生否决权, 安全红线由底层独立收口;
  ④ 全部可调量按三轴(cfg/cal/dia)实现, 不得硬编码; ⑤ 上报格式符合契约(阶段/成功/失败/异常码/断点/CT);
  ⑥ 换权重即换模型, 不改调用方代码。
- **接口契约**按 输入 / 输出 / 节拍时延 分组逐条列。

### G 配置驱动与任务迁移
- **在册任务差异表**: 任务ID / 名称 / 场景 / 档位模式 / 适用段 / 排除段 / 启用节点 / 禁用节点。
- **迁移不变量**(任何任务下都不变): 画布真源+节点连线数 · 功能节点数 · 分层架构与接口契约 · 供货边界 · 配置三轴项数。
- **迁移步骤**(不改代码): 改任务配置 → 重算任务绑定 → 重建工程库并 check → 按新任务重新导出本文档。
- **迁移判据命令**: 绑定 check + 工程库 check, 两条都要绿才算迁移完成。

## 3. 写作纪律(与 SKILL.md 同源)

- 所有条数/行数从工程库与绑定文件**现取**, 不在文档里写死。
- 真源 `value` 为空的指标一律标「待实测 + 实测入口」, 绝不编造实测值; 汇总进附录 C。
- 静态商务项(交付地点/周期/电源/气源/温湿度/占地/质保期)取不到就写「待确认」, 发放前须闭环。
- 同交付面(索引 / 清单 / SOR)口径一并统一, 并在回复里点明顺手改了哪一个。

## 4. 复跑与留档

```bash
python3 tools/delivery/gen_config_inventory.py --ver <发布版号>
gui-venv311/bin/python tools/sor_export.py --project <PROJ-PID> --task <TASK-ID> --json
```

- 生成器写到 `outputs/sor/<时间戳>/`(含 docx / json / manifest.json); 留档再拷进 `docs/deliverables/` 用**稳定文件名**。
- Word 交付件常被 `.gitignore` 排除(`*.docx`): 默认只提交 md / json / manifest; 确需入库才 `git add -f`。
- 交付回复只说三件事: 改了什么 / 核过哪些数 / 还剩什么(附录 C 的缺口清单).

## 5. 一份 SOR 覆盖多个任务(同工程不同任务合并外发)

适用: 同一工程下多个**同类**任务(如两个插接类任务)对外只发一份 SOR —— 多份文档并行维护必然口径分叉。

**章节分两层** (任务级逐任务展开、平台级共用一次):

| 层 | 章节 |
|---|---|
| §0 (开头) | **配置单真源登记**: 逐任务一行 —— 配置单文件名 + 参数注册表项数 + 画布 md5/节点数/启用数 + 配置单 sha256; 再列标定真源 sha 与点位台账条数 |
| 任务级 (逐任务, 用 `【TASK-xx】` 小标题分隔) | 项目与场景 · 性能指标(带逐项来源注) · 场景作业要求(工艺技能序列) · 验收要求 |
| 平台级 (共用一次) | 采购范围与交付分工 · 功能清单与接口要求 · 数据平台与接口 · 交付物 · 待商务/待现场项 |
| 末章 | **多任务差异对照**(每个配置项两列对照: 配方/模式/触发/循环/工单规则/targets/参数覆盖/档位/适用段) + 迁移不变量 |

**实现**: 复用单任务生成器的 blocks, **按 h2 段切片** (任务级段逐任务取、平台级段取第一个任务的), 再补 §0 与末章; 
不要重写第二套文案 —— 同一口径只写一次, 多任务文档不会互相矛盾。归档脚本要把新文档前缀加进复制清单。

**性能指标表逐行标来源**: 项目级硬指标(对每个任务生效) / 任务真源(`tasks.json` + targets/参数覆盖) / 模板继承项。
真源为 `null` 的项(如某任务插入行程未定义)写「待现场标定 / 采购附件确认」并在正文点明, **不代填数值**;
任务名/场景缺失时回落真源字段并标「未登记, 需补登记」, 不输出 `None`。
