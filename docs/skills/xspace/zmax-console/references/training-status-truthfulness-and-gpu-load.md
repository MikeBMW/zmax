# 训练状态与 GPU 负载 — 怎么报、怎么判活、为什么不高

适用于任何要展示/上报「L2~L5 训练状态、GPU 负载」的界面、接口、文档。

## 1. 训练状态只从唯一依据推，并且**先判活再显示**
唯一依据 `tools/model_inventory.py --json` 的 `training[]` 实测有三类脏数据，直接渲染就会骗人：
| 脏数据 | 归一规则 |
|---|---|
| 层名被包成 `JOINT(L2)` / `L2` 两种写法 | 正则 `^JOINT\((\w+)\)$` 取内层，再与 L2~L5 白名单比对，其它层丢弃 |
| 同一层出现 10+ 行（编排器 + 每个 trainer 各一行，共用同一份日志） | 同层多行时优先保留 `progress.found` 为真的那行 |
| 进程已死但行还在（编排器整轮存活，行里挂着**上一层**残留的进度文本） | ① `os.kill(pid, 0)` 判活；② 该层日志 `mtime` 在 90s 内还在写才算“在训”；两条都过才算训练中 |

不做判活的典型假象：**L2 和 L3 同时显示 `70% (14/20)`**（同一段进度文本被归到两层）。

## 2. 绝不编数字
- 进度在 `progress` 子字典里（`{found, raw, step, total}`），**不一定有顶层 `pct`** ⇒ 先取 progress，再回退顶层，都缺才另写。
- 缺进度时的显示顺序：`▶ 40% (8/20)` →（有 `elapsed_s`）`训练中 · 已 72s` → 都没有才 `训练中 · 进度未报`。
- **禁止出现 `None% (None/None)`**：那是“看着有数据实际是坏数据”。这类字符串应该由判据拦住，不靠人眼看。

## 3. 层的真实执行顺序：L4 → L3 → L2
`joint_train_all.py` 按 L4/L3/L2 推阶段（不是 L2→L3→L4）。所以每轮刚开跑时看“L2 还没训”容易误判为链路坏了，实际是 L4/L3 已经跑完（L4 只 20 步 ≈ 21s）。
- 训练入口**单一唯一依据 = 配置中心 `config/mcd/param_registry.json` 的 `model.train_entry`**（四层各一条）。
  演练脚本和 GUI 的「▶ 训练本层」必须**逐字执行同一条命令**，否则“界面能跑、演练挂”或反过来，故障变成两边互相甩锅。
  实现口径：能取到唯一依据就用唯一依据命令（`shlex.split`），传多层/取不到才退回 `--only <层列表> --steps N`。
- **L5 必须独占 GPU**：L5 是本地 3B VLM 意图层（`--only L5 --l5-steps N --l5-merge`），估 7GB 显存 ⇒ 8GB 卡上不能与 L2/L3 并行，也不该被塞进逐任务循环里跑；单独一轮跑一次，跑完再用窗口/唯一依据回读它的“最近训练”。

## 4. GPU 负载不高：先用实测口径，再讲原因
采样（`scripts/gpu_load_probe.sh`：2s×30 采样 + 同时打印训练进程）——
实测 L2（YOLO）阶段：**均值 1.1% / 最高 9% / 698MB / 11.8W**，而该阶段是纯 CPU 活。

可量化的原因（按任务 263s 拆）：
- 训练集很小（实例：49 张 train / 6 张 val）⇒ 30 个 epoch 的 GPU 活只有几秒；
- L3 20 步×2.5s ≈ 50s、L4 20 步 ≈ 21s 真占 GPU ⇒ 单任务 GPU 有效约 71s（≈27%）；
- 其余是数据集扫描/缓存、权重加载、以及**真机帧对照 A/B（CPU）**。
- 采样点落在非 GPU 阶段就会看到个位数利用率 —— 不要用一次瞬时值下结论，用 N 次采样给均值/最高/最低。

真因与可行杠杆（顺序即优先级）：
1. **数据量**（当前瓶颈：小数据喂不饱卡）；
2. 步数/epoch（有界步数只是“能验证通过”的口径，不是压满卡的量）；
3. **去掉重复训练**：逐任务训练时 7 个任务跑的是**同一套**训练数据 ⇒ 白跑 6 遍；改成“全局训练一次 + 每任务只跑任务条件化部分”，能把几十分钟压到几分钟，GPU 负载也更集中。

## 5. 训练结果不得越权上默认档
新增造物的真机帧 A/B 若被判“评测无效”（帧多样性不足，例如相机挡片/隐私开关导致帧两两相同），**不得**把结果写成持平/提升/回退，也不得切换在役软链 —— 按纪律停在“新权重已产出、未上档”。
报告里要同时写清：L2/L3/L4 逐层 `rc`（**别只看总 rc**，一层失败会被“整体验证通过了”掩盖）、产物路径、秒数。
