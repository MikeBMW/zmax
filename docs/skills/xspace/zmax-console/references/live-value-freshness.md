# 显示诚实性: 任何"当前值"都必须过源新鲜度判据

用户把画面当结果 ⇒ 页面上写着"当前"的东西必须是**真的当前**。看板/状态页类改动一律遵守:

## 铁律
- 每个实时量都要能拿到**源时间戳**, 并显示 `拍照时间 · 帧龄`(用户明确要求)。取不到时间戳的量, 不要标"实时"。
- 帧龄超阈值的量: **标失效 + 写清后果, 不要渲染成现状**。例: 控制器状态(急停/碰撞)的源已停更, 界面却仍显示"急停 无 · 碰撞 无", 而它正是"真动前三查"的依据 ⇒ 必须改成 `⚠ 源已静止 Ns ⇒ 下面值勿据判安全(现场以示教器/急停按钮为准)`, 并把最后一帧标成"旧值:"。
- 阈值按量级选: 视频/运动类 1~2s; 状态/心跳类 10s 起。别把 5Hz 的量按 0.2s 判死。
- 同一个数出现在多处(接口 / 页面 / 落盘文件)时, 收工前**逐值对一次**(差 0 才算同口径), 别只对结构。

## 实现要点
- 失效判定算成一个布尔, 失效时给整块前缀 + 追加"旧值:", 而不是删数值——现场需要看到最后一帧是什么。
- 改口径要同时改三处: 后端返回字段、页面渲染、页面顶部的口径说明行。

## 第二类假当前: 源没停更, 是**界面自己没跟着重算**

比源停更更隐蔽 —— 真源是对的, 只有屏幕上那一格错。排查时先分清是哪一类, 再去查刷新链路。

- **一格状态只允许一个函数写**。同一块状态在表里常有两处: 下拉控件 + 单元格文字。重算函数必须
  **两处一起写**; 只写下拉时文字格就永远停在**建表那一刻**。实测(10-13 配置中心任务表): 开机自恢复把
  活跃任务改成 TASK-07-AOI 后, 那行文字格还写「○ 未激活」(与真源相反), 另一个任务的格子反倒写「★ 活跃」。
  行号别假设行序, 按第 0 列 ID 现查。
- **列序右移必查硬编码列号**。加「3D场景」「实时监控」两列后列序到 14 列, 而 `setCellWidget(r, 8, cb)`
  仍写死 ⇒ 下拉跑到「启用节点」列。列号一律用常量, 加/删列后全文件搜 `setCellWidget` 与 `item(r, <数字>)` 复核。
- **让界面能自对齐**: showEvent 比一下真源指纹(mtime:size), 变了就重算 —— 不依赖"正好重开一次"。
  但小程序里已跑的进程不会因为代码改了而变 —— **改完不重启 GUI 当场看不出差别**, 别把它当成没修好。
- **判据按表头真名查列, 不用 `"X" in head`**: head 是列表 ⇒ 那是**精确匹配**, 列名一改(场景→3D场景)
  就假 FAIL, 且随后的 `head.index()` 抛异常会把整个渲染块判死 —— **假 FAIL 会把真问题盖住**。
  新判据同时锁死两条: 「下拉在下拉该在的列」+「格子文字 == 真源推导」。
