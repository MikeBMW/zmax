# 3D 场景渲染 (ss_dreamview.py) — 现场验收踩过的坑

控制台 3D 窗 (`tools/gui/ss_dreamview.py`) 是**唯一**被老倪拿来判"对不对"的画面。
他目检细节、会指出横向偏差/尺寸/透明/消失 ⇒ 每条改动都必须**能在图上量出来**。

## 1. 场景按钮必须与画布数据源同写 (否则被看门狗扳回)
`_switch_scene` 只切窗口; 若画布 `ssdata.src_state` 没同步, 我加的"跟随画布"看门狗 (QTimer 2s) 会把窗口
**扳回**画布那个场景 ⇒ 老倪看到"点插拔却跳到摆盘", 判定按钮失灵。
修法: 按钮走 `_switch_scene_manual()` = 先 `write_canvas_scene()` (复用 `tools/ss_scene_switch.py::switch`,
与配置中心同一条路) 再切窗, 并给按钮 8s 独占期。
判据: 写画布=插拔 → 10s/24s 后窗口标题仍是「3D场景 · 插拔场景」。

## 2. 每个场景认自己的 episode; 缺 meta 字段时**绝不套用别的场景的默认值**
`_peg_center_off` 的默认 `[-0.13,0,-0.01]` 是**插拔**的抓握点补偿; 摆盘 episode 没有 `peg_head_off`
字段时静默套用 ⇒ 画出来的件横向偏 **-0.13/2+0.035 = -30mm**。规则: 缺字段 ⇒ 0, 并打印一行
「光模块抓握偏移 = 0 (episode 无 peg_head_off)」。同类: 件尺寸按场景取 (插拔 200mm / 摆盘 52×20×12mm)。

## 3. "看不见"常常是渲染问题, 不是几何问题
- **孔口 0px**: 纯深色方口 (0.04,0.03,0.02) 画在深色盒体上 = 等于没画; 老倪只能拿夹具实体去猜 ⇒ 看着像错位。
  修: 深色内芯 + **亮青边框** (0.10,0.85,1.00, 唯一色便于反查) + 朝向相机那一面 (`meta['cam_pos']` 判 ±X)。
- **插入终点被盒体挡死**: goal 按物理在盒面内侧 35mm; 用 `setGLOptions('additive')` (depthTest=False) 穿透显示,
  才能"同时看到孔口和插入终点"再判对齐。
- **"透明"= 无光照平涂**: `shader=None` 单色 + 线框穿面 ⇒ 看着像玻璃。改 `shader='shaded'`;
  判据 = 单色像素/明暗像素比 (修前 72/15893)。

## 4. 放下/生命周期: 已完成的动作要**留在画面里**
放好的件按 episode 的「完成」真值帧点亮目标槽位 (摆盘 [798/1723/2654]); 否则"放下后消失", 观感=没干成活。

## 5. 取证方法 (别靠肉眼, 也别靠松掩模)
- 放大 3D 窗**不用重启控制台**: `xdotool windowsize <wid> 2450 1520` (win 太小 ⇒ 掩模全糊)。
- 掩模必须**按连通块 + 唯一色**取: 背景 (13,17,23)、绿桌面 (51,133,76) 会把"深色孔口/绿框"掩模全吃掉
  (曾量到 681351px = 整屏背景)。参考 `tools/verify_v2_look.py` / `tools/verify_mouth_align.py`。
- 拿不准就派**能看图的子代理**逐像素描述, 它会给出"标签浮在盒顶上方 90-130px"这种硬观察。

## 6. 外壳/进程纪律 (踩过)
- `pkill -f "<脚本名>"` 会**匹配到自己的命令行** ⇒ 自杀 (exit -15)。按 pid/端口找 (见 memory)。
- 后台 `terminal` 的**多行脚本会被折成一行**执行 (heredoc/换行丢失) ⇒ 长流程写成 `.sh`/`.py` 文件再跑。
