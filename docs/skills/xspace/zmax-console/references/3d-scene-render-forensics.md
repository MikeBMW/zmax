# 3D 场景 (tools/gui/ss_dreamview.py) — 渲染正确性与像素取证

> 适用: 3D 场景窗(插拔/摆盘/AR) 出现「件位置偏了 / 透明 / 拿起来变长 / 放下就没了 / 夹具与插入点错位」这类**观感即判据**的问题。
> 前提口径: 3D 窗是给人**目检**的窗口 —— **画面里看不见的物理事实等于不存在**。深色件画在深色底上、
> 目标点被不透明体挡住、件被整件隐藏, 都会被判成「没渲染 / 错位」, 即使世界坐标是完全正确的。

## 1. 状态只有一个主人: 画布数据源

* 场景按钮与「跟随画布」看门狗**不能各自拥有状态**。按钮回调必须: ① 先写画布唯一依据 `ssdata.src_state`
  (复用 `tools/ss_scene_switch.py::switch(task)`, 与配置中心切场景同一条路) → ② 再切窗口 →
  ③ 给按钮一段秒级独占期, 让看门狗别抢。否则按钮生效 2s 后被看门狗按旧画布扳回 = 用户看到「点 A 跳到 B」。
* 每个场景认**自己的 episode**: `scene_episode_path(scene_id)`(摆盘 `reports/tray_place_latest.npz` /
  插拔 `reports/ss_episode_latest.npz`); 切场景要**先换 `self.tr` 再重建几何**, 否则新场景里残留上一场景的轨迹线与件尺寸。
* 判据: `wmctrl -l` 窗标题里的场景名 = 切换是否真的生效。

## 2. 几何真值按场景取; 缺字段就是 0, 绝不套用别场景默认值

* **件尺寸按场景**: 摆盘 = 料盘槽位真值 `sim_scene_def._tray_layout()`(实测 52×20×12mm); 插拔 = 200×30×30mm。
  臂上那件必须**可见且用本场景尺寸**; 整件隐藏的后果是露出另一场景的件 ⇒ 观感「拿起来就变长」。
* **抓握偏移**: episode meta 没有 `peg_head_off` 时用 **0** 并打一行日志。静默套用插拔默认 `[-0.13,0,-0.01]`
  ⇒ 偏移 = -0.13/2+0.035 = **横向 30mm**(件心被当成抓握点), 全场件都偏。
* **槽位线框/标记按件真实尺寸**: 半径必须 ≥ 件半长(件 52mm ⇒ r≥0.026)。否则「盘太小放不下」的观感实际是
  「线框装不下件」, 与盘的外廓无关(先量: 件是否真在盘轮廓内)。
* **夹具类定位**: 数据里的 `box_center` 可能是**环境系原点**而不是网格中心(实测 z=-0.0008 被当盒心 ⇒
  孔口浮在盒顶上方 35mm、盒子一半埋进桌面)。正确做法 = 按**孔口/mouth** 反推盒心(盒可见面与孔口面齐平,
  盒心沿该轴偏半个盒长), 盒心 z = 孔口高。

## 3. 材质: 无光照平涂 = 「透明」错觉

* 实心件用 `shader='shaded'`。`shader=None` 平涂 + 线框穿面 + 透出内底 ⇒ 读起来就是玻璃/透明长方体。
* 量化判据: 数单一色值像素 vs 宽色域像素 —— 平涂时几乎只有一个色值(明暗占比≈0), 带光照后明暗面齐全(≈100%)。

## 4. 遮挡、朝向、可见化

* 相机在哪一侧决定**该看到哪个面**: 先用 `meta['cam_pos']` 与孔口 x 比大小(相机 x 大 ⇒ 看 +X 面), 再定面/口朝向, 别猜。
* 目标点若在**不透明体内侧**(插入终点在孔内 35mm), 默认深度测试会把它挡死 ⇒ 需要同屏对齐判读的线框
  用 `setGLOptions('additive')`(depthTest=False) 穿透显示。
* 「孔口/窗口」这类深色开口画在深色盒体+深色背景上 = **全图 0 px** 等于没画 ⇒ 给它一个**唯一亮色边框**
  (例: 青 `(0.10,0.85,1.00)`) + 深色内芯, 既让人看得见, 也让取证脚本能反查。

## 5. 生命周期: 放好的东西要留下

* 重放 episode 时「当前件」跟着 episode 走, 但**已放好的件必须留在目标位**。真值口径: 用 episode `stage` 里
  「完成」的**进入帧**(每颗一次)点亮目标槽位的占位件 —— 不造数, 也不会「放下就消失」。

## 6. 取证怎么量 (松颜色掩模一定假)

不要在 1300×900 的小窗上用全图单色掩模: 深色背景会吞掉「近黑」掩模(能匹配 60 万 px = 整张图),
绿桌面与绿线框同色系, 半透明 HUD 面板会盖住目标区。可信流程:

1. **先放大 3D 窗**(不动控制台、不重启): `xdotool windowsize <wid> 2450 1520; xdotool windowmove <wid> 20 20`, 物体才分得开。
2. 用**唯一色**反查, 并且用 `cv2.connectedComponentsWithStats` **取最大连通块的中心**(不是全图 bbox):
   一个物体一个色 —— 亮青=孔口框, 亮绿(g>200 且与桌面绿区分)=插入终点, 栗色=夹具盒体。
3. 用画面里**已知尺寸**换 mm/px(例: 夹具实宽 190mm ÷ 量到的 px 宽), 把 Δpx 报成 mm。
4. 抓图先 `xdotool windowactivate --sync <wid>` 再 `scrot -u`(抓焦点窗自身, 不受层序影响)。
5. 少颜色/多步的验证**写成脚本文件**跑(`gui-venv311/bin/python tools/<name>.py`), 不要塞在后台命令的多行 heredoc 里 ——
   后台包装会把换行接成一行, 脚本会被改写成别的命令(自己还看不出来)。

## 7. 交付纪律

* 改完 3D 场景代码**必须重启一次控制台**才上屏(用 `tools/studio_ctl.sh restart --force`), 但**攒够改动一次到位**, 别反复重启。
* 报告先给「画面上能看到什么 + 实测数」, 再给下一步; **没有可信数就直说量不出来**, 不要拿松掩模的假数糊过去。
* 量到的数要先跟世界坐标核对(例: 盒心 y 0.6833 vs 插入终点 y 0.6834 = 差 0.1mm ⇒ 横向是齐的),
  再决定是「几何真错」还是「画面上看不见」—— 这两种修法完全不同。
