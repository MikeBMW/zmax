# 配置中心「🧩 商业模式」页 (2026-10-19)

老倪: 「在配置中心，要有商业模式，你看看怎么从前面的配置，导出商业模式」——
不是另做一个报价器, 而是**把成本/性能/任务三份配置推成商业模式决策**, 页面只显示, 不存派生值。

## 两层唯一依据 + 一个算法函数 (别在页面里写第二套算式)
- 成本输入: `config/platform/zmax_cost_model.json` (硬件逐项 + 软件 + 人力 + 产线)
- 业务输入: `config/platform/zmax_business_model.json` — **只存 inputs**, 每个键 `{value, unit, label, source}`,
  `label ∈ {给定, 目标, 实测, 假设}`。派生值 (floor/ceiling/回本/阶段价/毛利) 一律不落盘。
- 算法: `tools/business_model.py` → `derive(cost_model.estimate(), **overrides)`。
  页面、CLI (`--json/--md`)、导出提案三处调同一个; 页面失败只红字, 不退回自己算。

## 推导链 (顺序固定, 跳一步就会自欺)
1. **成本结构**: 变动 = 硬件 × 学习曲线 `n^log2(1−rate)`; 固定 = 软件研发 + NRE。
   → 单台定价成本 `hw×lc(n) + 软件研发/计划摊销台数` (**计划** 摊, 不是按这一单摊, 否则试用 2 台被摊成
   30 万/台研发, 报价直接失真); 规模阈值另用「按实际台数摊」的口径。
2. **分层口径**: A 上限 / B +OPEX / C +人效 / D +NRE, 只对外报 C、D。
   η = η_struct × 成功率 × uptime × min(1, 人工CT/机器CT), 四项各自标来源 (成功率/CT 取 perf_spec 目标值时必须写「未实测」)。
3. **成交区间**: floor = 单位成本/(1−目标毛利); ceiling = T×(η·heads·人力 − 复训 − 软件年费)/(1 + T×维护率)
   —— ceiling 与售价互相依赖 (OPEX 是售价比例), 必须**代数解一次**, 别迭代也别忽略维护费。
4. **改配置的量化出口**: 工位×(1..N 班) 矩阵逐格算 ceiling 与 floor 对比, 给「最小成立组合」。
   区间不成立时唯一正确动作是**改配置**, 不是降价。
5. **三阶段**: S1 报价 0 (风险敞口 = 样机硬件 + NRE, 研发投入已发生不重复计) → S2 解决方案费 (成本+毛利+实施)
   → S3 批量单价 (学习曲线后 + 复制台边际毛利)。
6. **模式判定**按 η 与工位数, 不按客户偏好: 买断整线 (≥3 工位) / 买断+订阅 (POC) / RaaS (η≥0.9 且多工位,
   否则交融资租赁) / 按颗 (只适合超大产量) / 软件授权 (区间不成立时的出口)。每条带数字与成立条件。

## 页面形态 (一屏能看完, 老倪认可的)
成本结构表 (4 行) → 分层口径等宽文字块 (4 行, D 层标「报价只用这一层」) → 成交区间一行 (绿/红,
含差值与规模阈值) → 4 个业务假设 spinbox (毛利率/客户目标回本/批量台数/η_struct, `valueChanged→refresh`)
→ 三阶段表 → 模式表 (推荐行带 ★) → 改配置出口一行 → 价值/风险两行 → 4 按钮 (重新推导/写入假设唯一依据/复制TSV/导出JSON+提案)。

## 判据 (`tools/verify_business_model.py`, 41 项)
页签与控件 · 成本结构四值 · 分层四层单调 + η 乘式 · 成交区间不成立时**必须显示 ❌ 与负差值** ·
三阶段报价关系 (S1=0, S3 单台 < S2 单台) · 推荐模式与 η/工位规则一致 · 页面 == CLI 逐字段 ·
改假设即重算 (毛利率↓floor↓, 目标回本↑区间转成立) · 唯一依据无派生键 · 写回+回读+字节还原 ·
导出 JSON/MD 回读一致 · 剪贴板 TSV · 成本页零回归 + 页签数。
