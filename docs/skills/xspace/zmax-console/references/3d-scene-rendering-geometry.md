# 3D 场景 (ss_dreamview) 渲染 · 几何正确性 —— 专题口径

适用: `tools/gui/ss_dreamview.py`(3D 场景窗) + `tools/sim_scene_def.py`(几何/尺寸真源) +
`data/scene/scenes/<SCN>/objects3d.json` + episode 真源 `reports/{ss_episode,tray_place}_latest.npz`。
症状入口: 件/夹具位置不对 · 孔口有偏差 · 件“变长/变透明” · 拿起后错位 · 放下后消失 · 点场景按钮跳错场景。

入口链: `SKILL.md` → `references/config-sheet-and-scene-colors.md` → 本文件。

## 1. 定位靠**物理锚点**, 不靠字段字面意思
* meta 字段名 ≠ 字段语义: `box_center.z=-0.0008` 实测是**环境系原点**, 代码当网格中心画 ⇒ 孔口浮在盒顶上方 35mm、
  盒体一半埋进桌面。规则: 由物理锚点反推几何 (侧插口在盒 +X 面中部 ⇒ 盒 +X 面与孔口面齐平、盒心 z=孔口高),
  并把**原差**打进日志: `🧩 [3D场景] 带孔盒按孔口重定位 (meta z=-0.0008 → 0.1292, 原差 130.0mm)`。
* 插入终点(goal) 在孔**内侧**(距口面 ~35mm) 是物理事实 ⇒ 报“偏差”前先算 Δ (实测 Δy=0.1mm = 没偏),
  再决定改不改; 若用户仍指画面, 就用像素反查落数, 不要用数值反驳他。

## 2. 偏移/标定类默认值: 缺字段 ⇒ 0, 绝不套用别的场景的常量
* `meta.get("peg_head_off", [-0.13,0,-0.01])` 在没有该字段的 episode(摆盘) 上静默套用插拔默认 ⇒ 偏移 -30mm。
* 规则: `.get(key, DEFAULT)` 的 DEFAULT 只能是**本场景**的量; 缺字段 ⇒ 0/no-op + 一行日志。
* 判定法: 若 episode 的 `peg` 本身就是件中心 (与 `x`(TCP) 竖直差 ~100mm) ⇒ 抓握偏移必须 0。

## 3. “透明”与“放不下”多半不是材质与尺寸问题
* `shader=None` 平涂 + 线框穿面 + 露内底 ⇒ 观感就是玻璃/贴图块。实心件一律 `shader='shaded'`。
  量化判据: 金属件单色像素(±6) 72 → 宽色域(±45) 15893 ⇒ 明暗占比≈100% = 真有面明暗。
* 槽位/线框尺寸按**件**算: 标记 r=0.012(24mm) < 件长 52mm ⇒ 目检“盘太小放不下”。
  真源 `sim_scene_def._tray_layout()`(件 52×20×12mm; 料盘外廓 82×124mm)。
* 跨场景尺寸不同(摆盘 52×20×12 / 插拔 200×30×30): 网格尺寸**按场景取**; **别把臂上件整件隐藏** ——
  隐藏会让拿起的件露出别场景尺寸(“拿起来就变长”)或干脆不见。

## 4. 生命周期: 放下的件要留在工位
* 用 episode 阶段真值点亮已放槽位: `stage` 进入“完成”的次数 = 已放颗数 (摆盘真值帧 798/1723/2654);
  占位件按 `_tray_layout()['markers']` 槽位坐标建, 默认隐藏、逐颗点亮 ⇒ “放下后又消失”消失。

## 5. UI 与自动跟随: 按钮必须写单一真源
* 场景按钮只切窗口、不写画布 `ssdata.src_state` ⇒ “跟随画布”看门狗 2s 内扳回旧场景 (用户: “点击插拔却跳到摆盘”)。
* 规则: 按钮 = 先写单一真源(复用 `tools/ss_scene_switch.py::switch`) 再切窗口 + 手动动作 8s 独占期。
* 验证: 写画布后 **10s 与 24s 各看一次**窗口标题仍停在目标场景。

## 6. 像素反查口径 (数字对齐 ≠ 画面正确)
状态: 用户报的是**画面** ⇒ 数值对齐不算完成, 必须落像素证据 + 截图绝对路径。
```
export DISPLAY=:0                       # 别写 DISP="DISPLAY=:0" 变量前缀 (会 command not found)
W=$(wmctrl -l | grep "3D场景" | awk '{print $1}'); xdotool windowactivate --sync "$W"; scrot -u /tmp/x.png
gui-venv311/bin/python tools/qa_3d_pixels.py     # 颜色常量反查: 面积/bbox/中心/长宽比
```
* 颜色常量写进注释, 用 RGB 阈值 + `connectedComponentsWithStats` 量面积/长宽比 (例: 件在手上时最大金色块
  131×121px、长宽比 1.08 ⇒ 不是 200mm 长条)。
* **对比图必须同分辨率/同窗口几何**: 3068×1862 与 1300×900 直比像素会得假结论 ⇒ 换算 px↔mm (窗口宽/场景宽) 或重抓同尺寸。
* 看不到画面时派**能看图的子代理**只问观察结论 —— 它推翻过“透明=图层叠加”的猜测(真因是无光照平涂);
  它的结论自己要再按数值复核, 两口径都写进交付。
* 抓“事件那一刻”: 轮询 live trace 字段(如 `阶段`/`轨迹_段` 含 抬起/转移) 命中后再激活窗口+截图, 否则只抓到静止帧。
* 3D 窗默认几何偏小 (1300×900 vs 信号窗 3068×1862), 用户目检吃力 —— 改完主动提出按屏幕放大。
