# 太阳系力场可视化 — 运行态闸门 · 数据源 · u_ff 加权 · 四元数 · 可读性

适用: `tools/gui/orbital_arch.py`(太阳系) + `tools/gui/gravity_table.py`(万有引力表) + `tdrive_bus.compute()`(τ)。

## 1. 运行态闸门(四条一起做, 少一条用户就会问”没运行怎么有力”)

1. 唯一判据 = `zmax_data/ss_live/ui_run.json` 且 **pid 仍活**; 引擎文件的 mtime 新鲜**不算**在跑 —— 后台 `ss_engine_loop` 常驻 10Hz 一直写。
2. 未运行时 **所有力相关量不重算**: 合力 `fE`、`quat` 都冻在最后一次运行的值; 只在 `running` 为真时才调 `_compute_*()`。
3. 未运行时**不画**: 力箭头、姿态轴、S³ 表盘射线; 卡片写”⏸ 未运行”, 右栏力行写”未运行”, 六个天体的数值行也写”未运行”(否则水星进度/火星 λ 会跟着后台文件继续跳)。
4. 未运行时**动画全停**: 虚线相位 `_phase`、公转积分 `_advance`、呼吸 `_pulse_t`、光晕低通目标。相位不停 ⇒ 画面永远有动能, 用户就认为在跑。

判据: 未运行 1.2s 两帧像素差 ≤0.5%(实测 0.3%); 力箭头 0 根; `fE` 为空。

## 2. 力的数据源只在 3D 面板手里 —— 没开 3D 窗口就没有力

- `trace_live.json` 的唯一发布者是 3D 面板(`ss_dreamview.publish_trace_live`, 在 `set_frame` 渲染时写)。不开 3D 窗口 ⇒ 文件停在上一轮 ⇒ 太阳系相位还在积分(看着”在动”), 力却冻住。
- 修法(已落): `simulink_module._ss_tick` 统计可见 3D 窗口数, `==0` 时调 `_publish_trace_min(idx, tr)` 直发一份最小快照。字段名/单位必须与 3D 面板逐字一致:
  `前馈速度|安全边界|动作调制` × `_x/_y/_z_mms`, 以及 `帧/总帧/阶段/时间_s/八阶段表/末端_x|y|z`。
- 单位坑: 真源是 **`_mms`(毫米/秒)**; 内部统一 m/s ⇒ `/1000`。没有 `_mps` 键, 按 `_mps` 取会永远拿不到。

## 3. GravityField 是模块级缓存 —— 每次 build 必须 reload 一次

消费者统一走 `self._field()`: 同一 build 只 `reload()` 一次, `_compute_quat` 与 `_compute_earth_forces` 共用**同一拍**。
直接用模块级 `_QUAT_FIELD` 且不 reload ⇒ 进程活久了合力永远停在第一次构造那一帧(user: ”运行后合力怎么没跟着变”)。

## 4. u_ff 加权(改力场构造)

- 真源 `config/calib/force_field.json`, 改文件 500ms 生效, 不用重启: `u_ff_gain`(α=4.0) · `arrow_ref_mps` · `arrow_max_px` · `apply_to_tau`(false)。
- 加权点 = `cells["L4"](u_ff) × α`, 之后才算四元数/行合力/列合力 ⇒ 格子·表·箭头·S³·悬停同一份权重, 不另算一套。
- **主力语义跟着 α 走**: α>1 ⇒ `_main_layer()` 返回 `"L4"`(前馈是主动项), α=1 回 L2 执行收口。旧判据写死 L2 必须同步改。
- 实测: α=3 时各阶段 L4/其它 = 1.7~3.1×(转移最弱); α=4 时 2.3~4.1×。
- τ 通路: `tdrive_bus.compute(ff_gain=None)` 读同一份配置; 默认 `apply_to_tau=false` ⇒ 只改显示与表、不动控制回路。打开时实测 |Δτ|≈0.28 N·m(z 已贴 −30 限幅)。

## 5. 四元数

- 表里的”力四元数” = `(|F|/u_ref, Fx/u_ref, Fy/u_ref, Fz/u_ref)`, **故意不归一**(要能逐位对账); 太阳系显示的是 `q̂ = q/‖q‖`(S³ 上的方向), 悬停同时给 ‖q‖(力度)与平方和(验单位)。
- 角距 = `2·acos|⟨q1,q2⟩|`(同 q → 0°, 正交 → 180°)。
- 无值时写”未算/未运行”, **不拿 (0,0,0,0) 冒充姿态**。
- 真机**姿态**四元数目前无真源(`plan_from_vff.rotation="未建模"`, `tcp_pose` 的 rx/ry/rz 为 None) ⇒ 显示的是力/方向四元数, 不许编一个姿态糊上去。

## 6. 可读性尺寸(用户会连续几轮说”字太小/字数太多”, 一次就按这个给)

- 右栏: **20px 字 / 行高 27 / 宽 380 / 每行不画边框**。边框会让右缘三档不齐、相邻两行贴成一体。
- 每行 ≤ 25 字, 角色名压到 2 字(`太阳·中心` `火星·DiT`), 单位能省就省, 详细口径全进悬停卡。
- 标题带占 0~34px, 右栏行从 `y=46` 起; 任何胶囊/按钮从 `y=40` 起, 否则压标题与说明行。
- 左下力场卡 369×218, 标题 17px, 用**五个独立小表盘**(各自圆心、各自射线)。五根射线共用一个原点时, 中段间距只有 4~8px, 视觉上糊成一束。指针必须画三角箭头尖。
- 布局必须给卡片留**左侧走廊**(圆心右移 + 半径压到”卡右缘↔右栏左缘”之间), 否则地球/火星会落在卡片底下; 窄窗放不下卡片就整体不画(S³ 的数仍在右栏 q̂ 行)。
- 箭头长度用固定参考的平方根尺度 `L = Lmax·√(|F|/F_ref)`, 合力 ×1.35。**不许按当帧最大值归一** —— 那让长度帧间不可比, 看着忽长忽短; 线性尺度又会在 |F| 跨 10 倍时全线贴顶。
- 图注 14px、≤3 行短句。卫星起相位 = `π/n`(半间距, 8 颗 → 22.5°); 固定 0.26rad 只有 15°, 投影压扁后离地月线只剩 5.6px 会压线。
- **表盘射线长度不能用 q̂**: q̂ 是归一四元数, `|v|≈1` 恒定 ⇒ 五个盘画出来一样长, 用户只会说"没显示力"。长度取该层 **|F|** 的对数尺度 `len = max(9, r·(0.28+0.64·log归一))`; 平方根 + 30% 保底会把 5 倍差距压成 1.27 倍, 看图读不出量级。
- 每个盘**下面必须写这一层的 |F|**(三位小数), 字号 ≥15px 粗体 —— 9~13px 是"小字下限", 目检会直接判不达标。量级判断靠数字, 长度只做粗分档。
- 档位没启用的层在盘下写"未跑", **不写 0.000**(0 会被读成"算出来是零")。
- 不要用 `L2≡L3` 之类的合并层名: 读起来像"这是一个层", 而且和表里 L2/L3 两列独立的口径自相矛盾。五个层名一律独立显示。

## 7. 判据与视觉复核

- 判据会**写死旧语义**(0.26rad 起相位 / 主力必须 L2 / 图注 ≥4 行 / 表格 39 条)。构造或版式一改, 同步改判据并说明新口径 —— 不许为过判据把功能改回去, 也不许放宽到永远绿。
- 像素判据会被”某根轴正对镜头投影≈0”和”力箭头压在上面”误伤 ⇒ 以**几何记录**(`_tri_axes` / `_last_arrows`)为准, 像素只作旁证。
- ”文字色 == 球体色”这类结构色判据, 会被新增的”合力行”(力色不是球色)误判 ⇒ 这类行别带球体字形(`♁`)。
- 每帧先清空 `_last_arrows` 再按运行态决定是否填, 否则判据读到上一帧的旧账(未运行也报”5 根箭头”)。
- 视觉自检: 派子代理跑 `vision_analyze` 看截图, 只让它报**像素级事实**(字高 px / 是否越界 / 是否压字 / 箭头是否重合 / 右缘是否对齐)。它会抓出”胶囊压标题”“图注错字两处”“指针没有箭头尖”“三层指针同向”这类自己看不出的问题; 多尺寸(1154/1500 宽)各看一次。
- 判据 banner 里写死条数会与实际不符 ⇒ 用 `PASS+FAIL` 动态算。
- **条数必须在所有 `ck()` 之后统计**: 后追加的判据若在 `npass = sum(...)` 之后跑, 会出现“40 条里 39 通过、每一行却都是 ✅”。把追加判据移到统计之前, 或统计放到最后。
- 四层判据(主力=L4 / 加权 ≥2× / 四层 q̂ / 分力齐全)的前提是**四层都在跑** ⇒ 判据开头把 `ui_run.json.cap_level` 临时改成 `L5` 并保存原文本、判完还原(`_cap_enter/_cap_exit`); “只跑 L2 ⇒ L3/L4/L5 缺”另立一条单判。档位门控上线后旧四层判据必然全红, **不许为了让判据变绿而放宽门控**。

## 8. 能力档位门控 —— 只跑了 L2 就不许 L3/L4/L5 有输出

- 档位语义是包含关系: `L2 ⊂ L3 ⊂ L4 ⊂ L5`(`L4D` 归一成 `L4`)。
- **档位真源有两层, 事实优先于意图**: 画布「能力档位」节点 `params.cap_level` 只是**用户意图**; 真正在跑的子链路是**事实**, 且要盖过意图 —— `zmax_data/l5_loop/state.json` 的 `status=="running"` 且 mtime < 900s ⇒ 这一轮就是 L5 全链。L5 闭环能从别的入口起(不经过画布 radio), 此时画布节点可能还停在 L4 ⇒ 发出去的 `cap_level=L4` ⇒ 表把 L5 判成"未调用"清空, 用户看到的就是"运行 L5 还是没有力的显示"。控制台 `_ui_run_publish` 与 `GravityField._load_layers_on()` **两处都要**按这条覆盖, 否则同一次运行两处口径相反。
- 表里的四层力是**轨迹 npz 里录好的数组**(`u_exec/u_limit/u_ff/prior_vec`), 只按帧号取, 与“这一轮到底跑了哪几层”无关 ⇒ 不加档位收口, 只跑 L2 也会四层有数、主力还被 α 顶成 L4。
- 档位必须写进 `ui_run.json.cap_level`, 而且**两处都写**: ▶/⏹ 发布时写; radio 一切换就写(`_cap_publish()` 只改 `cap_level`+`ts`, 不动 `running/pid`)。只在运行时写 ⇒ 用户切到 L5 后不重跑直接看表, 表里还是上一轮的 L2, 格子写“缺 L5: 本次未调用”, 看起来就是“选了 L5 却没有 L5 的力”。
- `GravityField._load_layers_on()` 在每次 reload 里读档位算 `layers_on`; 读不到档位 ⇒ 全部当启用(老行为, 不误伤)。
- 未启用的层必须在**加权/四元数/行合力之前**清成 `mag=None, vec=None`, src 写 `缺 Lx: 本次未调用 (档位 L2)`(判据 ⑧ 要求未算格带“缺”)。清空晚于 α 加权 ⇒ L4 仍会被顶成主力。
- 主力层随档位回落: α>1 **且** L4 有 `vec` 才是 L4, 否则 L2。太阳系右栏 `q̂主`、S³ 表盘标签、分力箭头用同一规则, 否则会画出一条根本没有输出的层。
- 档位收口上线后, 四层判据(主力/加权/四层 q̂/分力齐全)必须显式把档位改成 `L5` 再判(见 §7 的 `_cap_enter/_cap_exit`), 另立一条"只跑 L2 ⇒ 三层写未调用"。门控与四层判据是两条相反方向的断言, 缺一条都会让另一边默默失真。

## 9. “之前的太阳系怎么没有了” = 视图下拉的落盘, 不是代码丢了

- 主参数 M 页顶部 `视图` 下拉: `0 = 🧊 流形几何·四面板`, `1 = 🪐 球心引力架构·太阳系`; 选择落 `QSettings("ZMAX","studio")` 的 `mparam/viz_view`。
- 这个症状几乎总是**存的值是 0**(且代码默认也是 0) ⇒ 重启后 stack 显示四面板, 用户以为太阳系被删了。先读 `QSettings(...).value('mparam/viz_view')`, 再谈丢失。太阳系是主视图 ⇒ 默认改 1 并把键写成 1。
- 区分“真没了”和“选错了”: 构造 `MasterParamMView` 后看 `cmb_viz_view.currentIndex()` / `viz_stack.currentIndex()` / `orbital.size()`, 再 `grab()` 量墨量; 若 `viz_stack` 里是红字 `QLabel("🪐 球心引力架构视图不可用 …")`, 那才是构造异常(看一眼控制台日志的同名字符串即可确认)。

## 10. 回放值 ≠ 这一轮的输出 —— 报数前先问"这层这一轮真跑了吗"

- 四层力全部来自最近一集 `reports/ss_episode_latest.npz`(`u_exec/u_limit/u_ff/prior_vec`), 按帧号取。L5 档位跑的是 annotate/训练环, **不做状态空间推演** ⇒ 屏上的 L5 力是**回放值**, 不是这一轮 annotate 的实时输出; 页脚帧龄就是这个口径(几十小时 = 明显是旧集)。
- 回答用户时必须把"这一层的数有了"与"这是这一轮算出来的"分开说; 要让某层真随这一轮变, 前提是那一层把每帧输出写成真源, 那是另一条链路, 不能靠显示层补。
- 同理: 运行态闸门只能证明"界面认为在跑", 不证明"这一层在算"。两者是独立断言, 分别取证。
