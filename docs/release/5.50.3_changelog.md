### 8. 融合定位建图 (专用实现, 不与 perception.py 共用)

老倪口径: 「融合定位与 perception.py 公用, 这样不好; 再建立一个融合定位建图的 py 文件, 专门实现定位建图功能」
+「进入系统后自动加载自动建图功能, 启动建图程序, 包括但不限于 ORB-SLAM 等基于视觉、机器人位姿的建图」。

- 新增 `src/lerobot/manifold/localization_mapping.py` (专用实现, 判据断言**不 import** perception.py):
  自带 43D 观测契约 (视觉 39 ⊕ 触觉 4) + `fuse_mapping_obs`; ORB 视觉前端 (比值检验 + 本质矩阵 RANSAC);
  机器人位姿真源通道 (tcp_pose, 全 0/陈旧如实判无, 提供米制尺度); 关键帧策略 + 地图点三角化; 回环检测 +
  简化位姿图松弛; 落盘 map/traj/live 三份真源; 自主进化接口 (质数签名)。
- 帧源三类: 实时相机 (8797/snap, **必须节流**——实测源刷新 100~500ms, 20ms 内连抓平均像素差 0.00)、
  真录像 mp4 抽帧、真机排练帧序列目录。
- 自动加载 + 启动建图程序: `tools/mapping_autostart.py` (start/status/stop/once, 按 pid 停, 幂等) +
  `docs/ops/zmax-mapping.service` (开机自启, 已 enable+active) ⇒ 进系统即自动加载并持续建图,
  活体真源 `zmax_data/mapping/mapping_live.json` 运行中每 ~2s 刷新 (帧龄可见)。
- 实测 (真数据): 摆盘实拍录像 120 帧 ⇒ 26 关键帧 / **1664 地图点** / 1 次回环 (视差中位 24.7px, 0 错误);
  实时相机路径跑通但机械臂场景静止 (未授权运动) ⇒ 重复帧被正确识别、不伪造关键帧、地图不增长。
- 判据 `tools/verify_localization_mapping.py`: **23/23 PASS** (独立性/自检 5 项/真录像建图/去重/静止不撒谎/
  位姿真源/落盘真源/自主进化/自动加载开关/零回归)。
- 本轮修掉的 4 个真 bug: ①自检用同形点阵 ⇒ 匹配歧义 (改成随机纹理+已知单应, 旋转误差 0.186°);
  ②位姿读取器只认嵌套键 ⇒ 把**新鲜**真源静默跳过 (改为认扁平键+四元数, 并把跳过候选报出来);
  ③内参未标定时把 None 传给 findEssentialMat ⇒ OpenCV 断言, 整链全废 (改为显式标注的针孔兜底);
  ④live 真源只在整轮末写 ⇒ 长跑状态陈旧 137s (改为运行中定期原子写)。
- 诚实缺口: 走的是"ORB 视觉前端 + 机器人位姿里程计 + 回环"的 SLAM 式流水线, **不是** ORB-SLAM2/3 完整复刻
  (未实现其词袋/局部 BA/多地图/重定位全特性); 回环为描述子检索+内点门槛的简化版; 位姿图松弛是线性摊还;
  相机内参未标定 (针孔兜底) ⇒ 无独立米制绝对尺度, 尺度来自真机位姿; 手眼未标定 ⇒ 以 TCP 位姿近似相机位姿。
