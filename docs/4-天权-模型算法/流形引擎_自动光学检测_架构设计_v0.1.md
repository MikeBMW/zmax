# 流形引擎 · 自动光学检测 (Manifold AOI) — 架构设计

版本 v0.1 · 2026-10-12 · 设计人: 静静(@xspace) · 依据: 老倪《流形引擎·自动光学检测方案》+ 本机/工控机**实测真值**

> 设计原则: **只把"真可控、真可测"的量写进状态空间**；每条势场/度量都必须有对应的**实测取数口**；
> 手设常数一律降级为"待标定初值"。凡未实测、未标定、或当前链路写不进去的，一律**如实标注**并给出补齐路径。

## 0. 与所给方案的关系（逐条口径）

| 方案内容 | 口径 |
|---|---|
| 任务层（检测任务/检测标准） | **采纳**，落 `config/aoi/tasks.json` + 复用 `tools/yolo/quality_check.py:AOIQualityChecker` |
| 流形层三流形（相机/扫描/缺陷） | **采纳但收窄维度**：相机流形只留曝光/增益/工作距离/ROI(4维)；焦距/光圈在现役相机上**不可控**(见 §1)，降为"硬件约束"不进状态空间 |
| 势场层（清晰度/缺陷/覆盖） | **采纳**，全部换成**可实测量**：ROI 拉普拉斯方差 / 判据模型缺陷概率 / ROI 覆盖率 |
| 控制层（梯度流/测地线/健康监控） | **采纳**；梯度用**有限差分实测**（不在代码里编梯度） |
| 度量张量 `sensitivity` 手设矩阵 | **改口径**：矩阵必须由**扰动-测量标定**得到（§4），手设值仅作初值 |
| `CameraMetric.focal_length` 敏感度 `1+fl/100` | **不采纳**：本机/工控机相机焦距不可软调，该项恒 0；换成实测的曝光-亮度灵敏度 |
| `autofocus()` 调焦 | **不采纳为默认**：现役 OPT 相机与 D435 均无软件对焦；若上自动对焦镜头再启用 |
| `lissajous_scan()` `camera.move_to(x,y)` | **条件采纳**：需 2 轴平台或机械臂承载；当前**无可用扫描轴** ⇒ 先做"定点多视角"（工控机上下料位 + 臂换位），P2 再上轨迹 |
| 缺陷判定 `load_defect_model()`/`extract_features()` | **不采纳为独立模型**：直接复用**在役判据**（工控机 AOI 判决 + YOLO 框），避免第二套口径 |
| 健康度（特征值/条件数/趋势） | **采纳**，张量换成标定后的实测张量，落盘 + 上画布可观测量 |

## 2. 分层映射（方案 → 本仓库真实模块）

```
任务层  检测任务/标准        → config/aoi/tasks.json
                             → tools/yolo/quality_check.py:AOIQualityChecker
流形层  相机参数流形          → src/lerobot/manifold/aoi_manifold.py:CameraManifold   (4维, 实测标定)
        扫描路径流形          → 同文件:ScanManifold (P2; 无轴时 = 单点 + 臂换位档)
        缺陷特征流形          → 复用判据输出(缺陷码/框/置信) + ar_aoi 47 信号
势场层  清晰度/曝光/覆盖/缺陷   → 同文件:SharpnessPotential / ExposurePotential /
                                CoveragePotential / DefectPotential  (全部可实测取数)
控制层  梯度流/测地线/健康     → 同文件:ManifoldAOIEngine.step() + AOIHealthMonitor
                                (复用 energy_manifold.EnergyManifold 记账 + homeostasis 紧迫度范式)
```

## 3. 状态空间定义（收窄后）

**相机参数流形 x_c (4 维)**：`exposure_us`(1~100000)、`gain_db`(0~24)、`roi`(x,y,w,h)、`working_dist_mm`(仅臂承载时)。
**检测状态 x_d (4 维)**：`face`(正/反/侧面/端面)、`coverage`(0~1)、`defect_cnt`、`confidence`。
**扫描状态 x_s (4 维, P2)**：幅度xy / 频率比 / 中心xy —— 无轴时退化为 1 点，预先固定并标注 `axes=none`。

## 4. 度量张量：从手设改为**标定得到**

标定法（对每个可调维做一次单变量扰动，其余固定）：
```
g_ii = |Δ势能| / |Δ参数|   （归一化后）
g_ij = 交叉项: 参数 i 扰动下 j 的响应（有限差分, 见 §6 梯度）
```
**已有实测样例**（10083 侧面, 今晚）：

| 曝光us | 均值 | 中位 | 过曝>235% | 暗部<20% |
|---|---|---|---|---|
| 80000 | 67.5 | 33 | 14.53 | 19.4 |
| 40000 | 67.5 | 33 | 14.53 | 19.4 |

→ 该轮**测出灵敏度为 0** ⇒ 标定直接暴露"该维度当前不可控"（这正是指标该有的作用，而不是被手设矩阵掩盖）。
D435 实测有效样例：`166us→60us` ⇒ 过曝 3.27%→1.01%、均值 49.5→20.3（灵敏度非零，可进梯度流）。

## 5. 势场（每项都必须能"从取数口算出来"）

| 势场 | 实测量 | 公式 | 取数口 |
|---|---|---|---|
| 清晰度 `Φ_sharp` | ROI 拉普拉斯方差 | `Φ = −log(1+var)` | `kind=origin&grab=1` |
| 曝光 `Φ_exp` | 过曝率 ρ_over、暗部率 ρ_dark | `Φ = 10·ρ_over + 4·max(0,0.25−ρ_dark) + |median−T|/T` (T=90 待标定) | 同上 |
| 覆盖 `Φ_cov` | ROI 覆盖率图 | `Φ = Σ(1−cov)` | 判据框 + 位置台账 |
| 缺陷 `Φ_def` | 在役判据缺陷概率/码 | `Φ = −Σ p_defect·w_type` | 工控机判决 + YOLO 框 |
| 总势 | — | `Φ = w_sharp·Φ_sharp + w_exp·Φ_exp + w_cov·Φ_cov + w_def·Φ_def`，权重由标定得 | — |

## 6. 控制

- **梯度流**：`x ← Proj(x − η·∇Φ)`，`∇Φ` 用**中心差分实测**（每步 2 次取像；受取像耗时约束 ⇒ 步长/频率按 §7 预算定）；`Proj` = 物理范围 + 变化率上限（同 L4 平滑口径）。
- **测地线**：多视角序列 = 图搜索（节点=视角/参数档，边=切换代价含节拍），代价 = 目标势能 + 节拍 + 风险；当前轴缺失 ⇒ 图只在"相机档 × 工控机工位"上展开。
- **健康监控 `AOIHealthMonitor`**：标定张量求特征值 → `λ_min`(稳定性)、`κ`(各向同性)、`health` → 分档(优秀/良好/警告/危险) + 趋势；落 `zmax_data/ss_live/aoi_manifold.json` + 上画布 `_SS_STATE['aoi_mani']`（同 `mani_eng.hom` 范式）。
- **安全**：默认**只读旁路**；任何"写相机参数"必须过 L4 层的**变化率/范围闸**并留回执（applied/now 回读），与现有 AOI 纪律一致。

## 7. 节拍预算（全部实测）

单颗 = 取像 + 判据 + 换位（+ 可选多视角）。
- 取像：10083 **0.30s**、10082 **1.00s**
- 判据（工控机模型）：随取像同帧派生（960×960 同帧），未单独计 ⇒ 需实测补
- 现有实测单颗 CT：仿真 10.6~11.6s（非同口径）；PTV 目标 **≤3.15s**
- **瓶颈排序**：① 流服务把侧面刷新压到 0.26fps(3.8s)（`--aoi-fps` 可提，上游 0.30s 带得动 ⇒ 提到 2.0fps 帧龄≈0.5s）② 10082 取像 1.00s ③ 判据耗时未知（待测）
- **预算表（目标 ≤3.15s）**：取像 0.3~1.0s + 判据 t_j + 处理 0.2s ⇒ 需 **t_j ≤ 1.5s** 才达标；先测 t_j 再决定是否多视角。

## 8. 与 L5/L4/L3/L2 的分工（沿用架构原则）

- **L5**：给意图与条件（检哪些面、判定标准、允许节拍、目标曝光窗口 `过曝<6% 且 中位 50~120`），**不下具体参数**。
- **L4**：保安全与平滑（参数变化率闸、越界否决、异常画面上报，不进入判据）。
- **L3**：编流程（抓取→转位→侧面→端面→判定→分拣）、异常重试与视角调度。
- **L2**：收口执行（真正下发曝光/增益、真正取像、真正判据），势函数保障稳定性。
- **可行域逐层收窄**：L5 给窗口 → L3 给档位候选 → L2 在物理范围内实际收敛。

## 9. 旁路外观检测（不碰产线 AOI）

```
[工控机 OPT 10082/10083] --只读取像--> [旁路进程 aoi_bypass.py]
      |                                        |
      |                            CameraManifold(标定) + 势场 + 梯度流
      |                                        |
      +---- 产线判决(不干预) ----+--> 状态空间节点「🔍光学质量检测」(ss_aoi)
                                             → AOIQualityChecker 全套外观检测
                                             → ar_aoi_bus 47 信号 → 8787/8793 页面
```
- **只读**：旁路只用 `GET /picture`、`GET /exposure`、`GET /param`；**写参数仅在显式授权时**，且过 L4 闸。
- 全套外观项（能力语义，落到实现）：金手指**根数/节距/整齐度**、**划伤**、**异物**、**污渍**、**氧化色差**、**崩边/缺角**、**印刷缺陷**；每项 = 阈值 + 置信 + 位置，输出统一缺陷码。
- 与产线 AOI 的关系：**同源取像、独立判定、不覆盖产线判决**；分歧项进对比台账（老倪门槛：未证明提升不进默认档）。

## 11. 未决 / 风险 / 需要的东西

1. **10083/10082 曝光"假可控"** —— 必须在工控机程序侧修（Windows `D:\xspace\ultralytics_AOI\`），否则 §4 标定第 1 维恒为 0。
2. **judge 图是缓存文件** —— 所有 A/B 必须用 `kind=origin&grab=1`；否则会得到"改了没效果"的假结论（本轮已踩）。
3. **无扫描轴** —— "四面全外观"当前只能靠**工位换位 + 臂换位**，轨迹级方案待硬件。
4. **判据耗时未测** —— 节拍能否 ≤3.15s 取决于它。
5. **µ级缺陷识别** —— 需先给定"最小可检缺陷尺寸"与光学分辨率预算（像素当量），否则指标不可验。
