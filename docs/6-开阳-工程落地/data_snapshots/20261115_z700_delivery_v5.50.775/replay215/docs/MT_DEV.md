## 6. 如何复现

```bash
# 1) 生成指令(215 点, speed=100, dwell=0)
./gui-venv311/bin/python - <<'PY'
import json
d=json.load(open('tools/web/real_traj_joints.json'))
J=lambda f:[float(x) for x in (f['j'] if isinstance(f,dict) else f)[:6]]
json.dump({'frames':[J(f) for f in d['frames']],'start':0,'n':len(d['frames']),
           'speed':100.0,'dwell_ms':0,'grip':[]},
          open('zmax_data/rokae_sdk/traj_step_cmd.json','w'),ensure_ascii=False)
PY

# 2) 真机执行 + 采集(位姿/TCP/时间/图)
ZMAX_CAPTURE=1 ZMAX_CAP_DIR=/sdk/capture \
  bash tools/rokae_sdk_run.sh --script arm_step_traj.py \
  > zmax_data/reports/logs/replay215_LAST.log 2>&1

# 3) 旁路把进度同步给页面(否则甘特游标不动)
./gui-venv311/bin/python tools/traj_progress_bridge.py \
  --log zmax_data/reports/logs/replay215_LAST.log \
  --state zmax_data/rokae_sdk/traj_step_state.json --total 215

# 4) 生成派生数据 + 本文档
./gui-venv311/bin/python tools/replay_derive.py --run <快照> --out <run目录>
./gui-venv311/bin/python tools/replay_doc.py --run <run目录> \
  --meta data/database/zmax/sources/config/tasks/ar_meta_tasks.json \
  --out <run目录>/docs/MT_DEV.md
```

## 7. 已知限制与踩过的坑

| # | 限制/坑 | 影响 | 结论 |
|---|---|---|---|
| 1 | 逐点 `MoveAbsJ` 每点有 ~0.33s 固定通信开销（append+start+轮询 opstate） | 单点最快 2.03s，录制时是 0.199s/点 | 逐点物理下限，调参无法突破 |
| 2 | 「一次 append 多条 + 单次 moveStart」被控制器拒 `-60611` | 触发急停，实测碰撞过一次 | **禁止再用**，只能逐条 |
| 3 | `rokae_sdk_run.sh` 原先不透传 `ZMAX_REPLAY_*` | N=10 失效变成整条 215 点 | 已修，全量透传 |
| 4 | `arm_step_traj.py` 只打日志不写 `traj_step_state.json` | 页面游标/甘特卡在陈旧值 | 加 `traj_progress_bridge.py` 旁路 |
| 5 | `cartPosture(endInRef)` 返回单位是**米** | 直接用会当成 mm | 派生层已 ×1000 转 mm |
| 6 | 录制真值 42.85s (84 UPH) 与实跑 436s (8.3 UPH) 差 10 倍 | 容易被当成"变慢了" | 两个口径分开标注，`gap_reason` 写明物理原因 |
