# 0 · 总纲：一套系统，一个思想

这份文件是**唯一入口**。看完它你应该能回答四个问题：这套系统怎么想、东西在哪、改一处会牵动谁、怎么判断改对了。

---

## 一、一句话

> 用**一个状态空间**表示世界，用**一个流形**承载动力学，用**势场与度规**把约束表达成几何，
> 上层只给条件，最下层收口执行。

这不是四个模块的拼装，是同一件事的四个视角：

| 视角 | 数学对象 | 回答的问题 |
|---|---|---|
| 状态空间 | 流形上的点 `x` | 现在是什么状态 |
| 流形/度规 | `(M, g, Γ)` | 状态怎么连、距离怎么量 |
| 势场 | `Φ(x)`, `V_p = ½δᵀWδ` | 该往哪走（梯度方向） |
| 动作 | `ξ`, `u` | 这一步怎么动 |

**关键统一**：约束不是"写在代码里的 if 判断"，而是**编码进度规**。
- 状态空间的 `g`（`config/calib/zmax_manifold.json#metric`）决定**状态怎么走**；
- 动作空间的 `M_act`（同文件 `#inject`）决定**动作往哪个方向修**。

两者是同一思想的两个层次：*度规即约束*。这是专利 ZMP-2026-013 的立足点。

| 序号 | 层 | 管什么 | 一句话判据 |

| 0 | **总纲** | 统一思想、代码映射 | 你在这里 |

## 四、改一处之前先问三个问题

```
1. 它属于哪一层？         → 上表，跨层引用要收敛到相邻层
2. 它是参数还是逻辑？     → 参数改真源；逻辑改实现，别混
3. 它有没有一键退回？     → 没有就不许进默认档
```

## 五、怎么判断改对了（四道闸，缺一不可）

| 闸 | 判据 | 工具 |
|---|---|---|
| ① 语法/契约 | 能 import，端口契约对得上 | `py_compile` · `tools/verify_port_contract.py` |
| ② 真联通 | 端口**真产**值，不是 None，不是直通 | `tools/verify_l2_linkage.py --engine` |
| ③ 有数字 | 改动的效果能量化成数（不是"感觉好了"） | 各自 probe 脚本 → `zmax_data/ss_live/*.json` |
| ④ 零回归 | 全图联通率**不降**，旧行为逐位不变 | `tools/verify_l2_linkage.py --engine --all` |

> **反例红线**：`return True`、返回 dict 但没有 out 键、端口有值但下游读错字段 ——
> 这三种都算"没接通"，不算完成。
