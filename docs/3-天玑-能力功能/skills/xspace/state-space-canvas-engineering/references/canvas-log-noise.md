# 画布日志/反馈刷屏 (周期轮询把面板刷满)

底部终端面板是用户读结果的地方。**同一句话每拍重铺一次 = 面板作废**，用户会直接投诉「别刷屏，看不清文字」。

## 病因形状

`_l5_poll()` 这类 2s 定时器里，状态每拍都「重铺一次反馈」，历史上是给画布上的 QLabel 大横幅用的。
横幅后来被改成「只写终端」(`_l5_banner_show()` 内只剩 `self._log(...)`)，而调用点仍是**无条件每轮询调一次**
⇒ 同一条文案每 1.5~2s 打一行，跑一小时几千行。改反馈渠道时，**调用点的频率语义必须跟着改**，
只改被调函数的输出目标 = 把横幅刷屏换成日志刷屏。

## 定式：按文案去重 + 状态真变时清游标

```python
def _x_banner_show(self, text, kind="note"):
    _txt = "🎬 " + str(text)
    if _txt != str(getattr(self, "_x_log_last", "") or ""):
        self._x_log_last = _txt
        self._log(_txt)
```

并在「状态/阶段/进度 key 变化」的那一处**清游标**：

```python
if self._x_last_key != _key:
    self._x_last_key = _key
    self._x_log_last = None      # 新一轮/新阶段仍要播报，别被去重吞掉
```

两条缺一不可：只去重 ⇒ 第二次跑完用户以为没完成；只清游标 ⇒ 没解决刷屏。

## 定位步骤

1. `grep -c '<日志里的原句>' /tmp/simulink_log.txt` + `tail` 看时间间隔 —— 先确认是周期性还是真的重复执行（间隔均匀 = 定时器）。
2. 用**字面串** `grep -rn '<原句片段>' tools/gui/*.py` 找生产点。注意日志行前面的图标前缀（如 `🎬 `）常是**包装函数**加的，
   不是文案本身 —— 顺着前缀找到那个 `_log("🎬 " + ...)` 才是真调用点。
3. 顺着调用点往上看**谁在定时调用它**（`QTimer` / `_poll` / `showEvent`），频率语义就在这里。

## 验证：把真函数源码抽出来跑 dummy

GUI 模块不便 headless import 时，别靠肉眼看代码：读源码文本、正则切出目标函数、`exec` 进一个 dummy 类，
用假 `_log` 收集行数。三个场景必须同时过：

- 同一文案连调 10 次 → 只 1 行；
- 3 种不同文案（阶段推进）→ 3 行；
- 清游标后再调同一文案 → 2 行。

这就是「不重启 GUI 也能证明修复生效」的取证方式；改动本身仍需重启 studio.py 才在界面上生效（只停不起，重启要点名）。

## 顺带口径

- 状态播报要**够显眼但只一次**：状态/阶段/进度变化各说一次（`═══ … ═══` 一行 + 关键明细几行）。
- 失败横幅那类「只闪 15s」的规则，也不能靠每拍重铺实现 —— 用一次性时间窗变量控制显示，日志侧同样去重。
- 报告里给**实测数字**（如「55 分钟 2184 行、占全部 3246 行的 67%」）比「已优化日志」有说服力。
