# 改完画布文件, 用户为什么说「你也没改啊」

## 症状

你按真源改了 `flows/state_space_obs.json`(mtime 变了、回读内容也对), 界面上还是旧布局。

## 机制(三层, 缺一层就不显示)

1. **界面内存是权威**: 画布启动时把几何读进内存, 文件改动**不热加载**。文件对了 ≠ 屏幕变了。
2. **重载走命令通道**: `/tmp/zmax_nav_cmd`(常量 `NAV`), 逐行命令, `ss_canvas` = 打开/重载状态空间画布。
   只认整行完全相等(`line == "ss_canvas"`), 加空格/注释反而不匹配; 同内容有去重, 重复发同一条会被跳过。
3. **重载会回写**: `normalize_after_load()` 加载 → 尺寸规则 → 按行重排(`_relayout_row_gaps()`: 按 y 分桶、桶内按 x 升序、
   只把重叠的往后推到「前一个右缘 + 56」) → `persist` 写回 x/y/w/h。所以:
   - 你手改的坐标若被判为重叠, 会被推开;
   - GUI 回写后文件通常比你的版本大(补字段), **别拿文件大小当判据**;
   - 反过来说: 回写 mtime 更新 = 界面确实重读了你的版本, 这是"生效"的硬证据。

## 判据(按顺序)

1. 发命令后文件 mtime 应更新(回写);
2. 回写后目标节点的 x 仍是该行最小 ⇒ 位次成立;
3. 截图只作辅证: 画布会自动居中到核心节点, "金色像素中位 x"不代表列序, 别拿它下结论。

## 红线圈

- 用户说「别动画布」⇒ 立刻把坐标改回原值(备份或反向交换), 并在回复里明说"已还原", 不要顺手把其它节点顺延。
- 用户说「X 放到第 N 位」而上一句刚聊 PPT/方案册 ⇒ 指的是册子页序, 不是画布位次(见 `l2-chain-deck-pages.md`)。
  两套东西都可能被理解时, 先按他刚看的东西做; 不确定就问一句, 不要两边都改。
- 写画布前先备份: `cp -p flows/state_space_obs.json zmax_data/backup_state_space_obs_$(date +%H%M%S).json`。
