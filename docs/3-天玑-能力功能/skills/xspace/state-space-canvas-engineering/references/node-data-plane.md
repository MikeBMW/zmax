# 节点间的数据面：内存 cache / 落盘 json / 默认关闭的闸

画布上的连线是**拓扑与语义**，不是数据管道。给节点加一个下游消费者、或判断某节点输出有没有人吃的时候，按这份走。

## 1. 三种通道，别混用

| 通道 | 作用域 | 用途 |
|---|---|---|
| `_YOLO_CACHE`（模块级 dict，在 `shared_runtime.py`） | **同进程** | 节点之间的主数据面。零序列化，2D 框 / 3D 点 / 39D 对齐都在这里 |
| `LAST_OUT[name]` | 同进程 | 每拍真实输出，给节点级 SU(2) 语义映射取值 |
| `zmax_data/**/*.json`（原子写） | **跨进程** | 对外契约：plan、画布 GUI、web 页、取证审计 |

引擎执行节点时 `ctx` 只有 `module / params / log / name / label` —— **没有 `inputs`**。
⇒ 节点 A 的 `out1` **不会自动**灌给下游 B。要在两节点间传值：
- 同一进程内 ⇒ 写 `_YOLO_CACHE[key]`；
- 跨进程 ⇒ 落盘 json 契约。

判据：下游节点里 `grep` 不到任何读上游的代码（既无 cache key、也无文件路径）⇒ **没接**，画布连线只说明依赖关系。

## 2. 「写了没人读」是这类工程最典型的假接入

任何新写进 cache 的 key，落盘前先做一次**读写对账**：

```bash
grep -rn 'obs39_aligned' --include='*.py' src/ tools/
# 1 处写 + 0 处读  ⇒ 算出来的东西悬着，没人消费
```

实测过的同一形态：`yolo_align` 把自监督解算的 3D 写进 `_YOLO_CACHE["obs39_aligned"]`，全仓**只有这一处写**，
下游融合节点走的是 `_ss_env_obs()`（直接读仿真 env 真值）⇒ 2D→3D 的结果只进了日志和 SU(2) 槽。

⚠️ **键名相近不等于接通**：`aligned39`（YOLO 节点 `align()` 产出，有一个消费者）
与 `obs39_aligned`（2D→3D 产出，零消费者）是两个不同键。按名字猜必然会错，必须逐个 grep。

## 3. 接一个新消费者：三条一起做，缺一条就是假接入

1. **新鲜度闸**：用与同层兄弟节点**同一个**环境变量（如 `SS_ALIGN_MAX_AGE_S`，默认 3s）+ 长度校验。
   生产者必须**同时写时间戳**（`<key>_t = time.time()`）—— 只写值不写时间，下游只能猜新鲜度。
2. **默认关闭的闸**：`ZMAX_FUSION_BOX3D=1` 才真覆盖数值；默认只观测。未证明提升不进默认档。
3. **来源与偏差入状态**：`_SS_STATE["fusion_src"] = "env" | "box3d(闸关)" | "box3d"`、
   `_SS_STATE["<x>_dev_mm"]`。**闸关时也要记偏差** —— 这样"接没接、两路差多少"可观测，不靠日志猜。

验收姿势（不要为了测一段接线去起 env，会拖 30s 甚至崩）：
把 env 取数函数 monkeypatch 成固定 39D，注入 cache 值，四轮断言：
无结果→env / 闸关→认到但不覆盖且偏差入状态 / 闸开→真覆盖 / 过期→退回 env。

## 4. `_ss_env_obs()` 在 AR/真机源下会崩

`_ss_env_obs()` 会 `aligner.env.reset()` + `env._get_obs()` —— 它要的是 **metaworld env**。
AR 源模式下 aligner 不是那套 ⇒ 实测直接 **core dump**（日志停在 `[模型] L2 YOLO …` 之后）。

⇒ 结构事实：**吃 env 真值的分支只在仿真里成立**。真机/AR 路径上 39D 必须来自 YOLO / 2D→3D 结果。
所以"融合节点一直读 env 真值"这件事，在仿真里看着正常，在真机上根本跑不通 —— 这正是它长期没被发现的原因。

## 5. 发布/写总线：变量名对不上 + 异常被吞 = 静默零发布

形态：`_load_mod()` 的返回值存进 `_s`，下游却写 `_m.publish(...)` ⇒ `NameError: name '_m' is not defined`，
外层 `except` 只打一句"总线不可用"⇒ **节点每拍都在算，但一个话题都没发出去**，而日志看起来只是在告警。

规矩：
- 发布函数写完，**回读落盘文件数键**（如 `ar_aoi_live.json` 的 `d["s"]`）作为验收，不看"有没有报警告"。
- 任何 `except Exception` 里的告警，都要能在产物上验证对应功能**确实发生了**；否则它就是掩盖故障的噪声。
- 变量名与 `_load_mod` 的返回绑定必须同名，别在同一个函数里混用 `_m`/`_s`/`mod`。

## 6. 返回类型也决定接通与否

节点实现 `return True/False` ⇒ 壳判定"非 dict ⇒ 直通"，下游拿不到任何字段。
必须返回业务字典（`out1` 里有真字段）。这条在 `ssff`（前馈）和 `ssaoi` 上各踩过一次。
