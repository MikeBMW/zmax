# 功能页「要符合当前版本实际功能」审计程序

老倪会指一组页面（系统架构 / 全局数据空间 / 实时监控 / 评估分析 …）说「都要符合当前版本实际功能」。
不是让你看 UI 好不好看，而是找 **页面展示的内容和系统真实状态脱节** 的地方。

## 逐页四步（每页都跑完再下结论）

1. **先定位数据源，不要读文案就下结论**。这些页大多是 `LiveStrip` / `LiveTable` 挂一个脚本：
   `grep -n 'LiveStrip(\|LiveTable(' studio.py` → 看它调哪个 `tools/*.py --json`；
   数据空间类页面在 `data_space.py`（`GlobalDataSpace.scan()` 全扫磁盘）。
2. **把那个数据源真跑一遍**（不是猜）：`./gui-venv311/bin/python tools/<x>.py --json | head`。
   扫盘类要数条数（`ls -d outputs/train/*/ | wc -l`、`ls reports/*.pdf | wc -l`）证明不是空表。
3. **对真源比对**：版本号 vs `VERSION.md` 表首；服务/端口 vs `services/registry.json` + `ss -ltnp`；
   报告时效 vs `date`（`ts` 差几十天 = 过期）。
4. **分类再动手**（见下表），不要一律当成「界面 bug」。

## 结论只有三类

| 类型 | 判据 | 动作 |
|---|---|---|
| 真源就绪 | 数据源真跑有值、条数对、时效新 | **不改**，汇报里给出实测数字作证据 |
| 生成物过期 | 报告/路线图 `ts` 距现在超一个迭代周期，或 `version_current` ≠ 版本真源 | 修生成器（见 `derived-store-staleness-gating` 三之二）+ **重跑生成器** + 回读字段 |
| 功能已删/清单没跟 | 失败项**成组**失败（同域名/同前缀全红），`getent hosts <域名>` 指到 127.0.0.1 | 从探测清单移除，定义保留 + `--with-x` 开关 |

页面里的「未加载 / 等待数据 / 未部署 / 未就绪」是**如实空态**，不是 bug —— 不要为「好看」填假值。

## 取证与验收

- 每页至少一条硬数字：条目数、探测成功数、版本号、报告时间。`offscreen` 截图辅助看排版，不能当数据证据。
- 修完必须重跑生成器 + 重启 GUI（studio.py 改动不进运行中的进程）+ 截图回读。
- 汇报按「页 → 结论 → 数字」组织，**先说哪两页有问题、先说根因再给修法**；不要逐页复述代码。

## 附：本次审计里发现但不该擅自改的

- 产品档位/阶梯（Z700F/Z700/L2-L4 能力描述）是**产品定义**，不是数据，看不懂也不要改。
- 代码里打已下线域名的调用点（模型推送/推理包下载/relay/快照轮询）改之前要先定**替代链路**，
  属于「功能改造」而不是「页面审计」—— 报给用户定，不要顺手改。
