# UI 形状/字体量化取证 + 版本迭代校验

## 为什么量化而不是“看着挺好看”
无视觉工具时, 界面“好不好看”必须变成可复跑的数字: 字号分布 / 文本截断 / 高度离群 / 对比度 / 溢出。
工具落 `tools/verify_ui_metrics.py` (逐页真建窗, 可指 DPI), 必须**带负控自证**: 现场造一个已知缺陷页,
断言它被当次检出 (截断≥N · 对比度≥1 · 溢出≥1) —— 否则“0 缺陷”可能只是探测器瞎了。

## 假阳性必须先清, 否则真缺陷淹没在噪声里
1. **逐层上溯 `parentWidget()` 查 `isVisible()`**: 只查控件自己的 `isVisible()` 不够。未打开的 dock /
   收起的面板里的子控件拿到的是**布局前的陈旧几何** (实测: 某侧边栏标签量到 51px, 实际 640px) ⇒
   祖先任一隐藏就跳过。
2. **宽度 < 60px 的按钮/勾选框直接跳过** (真实可点控件不会这么窄, 那是未布局的窄条)。
3. 清假阳性的同时**负控必须仍被抓到**, 不许把探测器改瞎。
实测收益: 报出的 12 类截断里 8 类是这样清掉的, 剩下 5 类里还有 2 类是负控故意造的。

## 修截断的三条路 (按“字少不挤”的偏好排序)
1. **缩短文案** (如「◀ 收起」→「◀」+ tooltip): 不依赖容器宽度, 最稳, 也符合“字少不挤”。
2. **开自动换行** (`setWordWrap(True)`) 用于长提示句 / 卡副标题; 开了换行的控件应按**高度**判据走, 不再按单行宽。
3. 重新定最小宽 —— 注意 **`sizeHint()` 必须在 `setStyleSheet()` 之后取**: 样式表加的 padding 不进 Qt 自己的
   sizeHint, 拿样式表之前的 hint 定最小值会仍然偏小 (实测: 取到 86px 而定后需要 95px)。

## 对比度: 先找调色板常量, 不是散落的 hex
`grep 'color:#484f58'` 命中 0 不代表没问题 —— 颜色走常量 (`C_DIM = "#484f58"`), 全仓 f-string 引用。
改**一个常量**即可一次修一大片 (实测 92 → 76 处, 其中一次改常量修 14 处)。
口径: WCAG < 3.0 属不可读; 深色卡片 (#1c2333 一类) 上的次要灰字至少到 #7d8590 (≈4.7)。

## 版本迭代: 工具自证不算数, 必须跑独立体检
- 版本迭代脚本只覆盖**它认识的锚点** (QLabel/窗口标题/changelog/…)。未被覆盖的写法很会漏:
  `statusBar().showMessage("Z-MAX vX")`、关于框里的 HTML 富文本 `<b>Z-MAX vX</b>`。
- 所以收尾必须跑**两个独立角度**: 版本同源体检 (同步点 + 远端 tag/Release + GUI 显示) + 大屏数据源的
  “GUI 显示陈旧” 判据。两者都 0 偏差才算完成。
- **发出去的东西才伤用户**: 若 tag 已经触发打包后又发现用户可见的旧版号字符串, 要**重指 tag 重新出包**
  (删远端 tag → 在修正后的 commit 上重打 → 推), 不要“下个版本再说”——用户打开的就是那个包。
