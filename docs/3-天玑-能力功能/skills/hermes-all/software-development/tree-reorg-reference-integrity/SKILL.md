# 目录树重组 · 引用一致性

搬文档树、数据树、交付目录, 或把重复的数据目录合并到一处时用。
**搬迁本身不难, 难的是搬完不留死路径** —— 死路径不报错, 只是读不到, 要等某个工具跑到那一行才炸。

## When to Use
- 用户说「文件太乱 / 这么多文件夹 / 精简分类 / 合并重复目录 / 只留 N 个文件夹」。
- 要把 `docs/`、`data/`、交付件这类**被代码按路径读**的树重排。
- 搬完某个工具报 `FileNotFoundError` / 静默读到空。

## 步骤

### 1. 先量引用, 再定结构
```bash
# 三种常见写法一次数清 (整路径 / 拆参 join / glob 通配)
grep -rno 'docs/[A-Za-z0-9_./-]*' --include=*.py --include=*.json --include=*.sh tools src config \
  | awk -F/ '{print $2}' | sort | uniq -c | sort -rn
grep -rn "[\"']docs[\"'] *, *[\"'][a-z_-]*[\"']" --include=*.py tools src | wc -l   # 拆参形式
grep -rn 'docs/[a-z_]*/\*' --include=*.py --include=*.sh tools src | wc -l            # 通配形式
```
把「被引用的目录」和「没人引用的目录」分开: 前者必须给等价映射, 后者可以自由重排。

### 2. 结构从已有体系里取, 别自己发明
用户已有一套领域分组(配置中心的分区、产品的层、既有命名空间)时, 新目录树**逐条对齐那套分组**, 并在 `README.md` 写明「只有 N 个目录, 没有第 N+1 个」。
自创一套新分类 = 下一轮还要再重排一次。

### 3. 生成 old → new 映射表, 落到 JSON
分类判定写成一个脚本输出 `{旧相对路径: 新相对路径}`, **先只读预览打印分布**(每组几份、样例文件名), 确认判定不荒谬, 再 `--apply`。
- 目录级映射(整目录搬)与**文件级**映射(把散在 `design/` 的 145 份按主题拆到多个星)可以混用, 但必须同一份 JSON 里全给。
- 保留组内子目录名(`deliverables/`、`memory/`、`test-reports/` 原样嵌进去), 代码里 `docs/<子目录>/` 的前缀替换才是一次机械操作。

### 4. 搬: 先移文件, 再判空删目录
```python
os.makedirs(dst_dir, exist_ok=True); os.replace(src, dst)   # 同盘 rename, 数据不动
```
- **可写镜像目录整目录 `rsync -a` 过去, 不要逐文件 walk** —— `walk` 里 `x.startswith('.')` 这类过滤会漏掉隐藏子目录(实测漏 158 个文件), 漏了就是半搬状态。
- 搬完再判「目录空了才 `rmtree`」; 提前删目录会丢还没移走的东西。
- 符号链接: `os.replace` 搬的是链接本身; 相对目标的链接若与目标同目录搬走, 仍能解析 —— 但要 `ls -l` 亲眼确认。

### 5. 改写引用: 三遍, 顺序不能错
1. **逐文件映射替换**(最长路径优先): `docs/<旧文件>` → `docs/<新位置>`。必须先于目录前缀替换, 否则 `docs/skills/xspace` 被前缀规则吃成 `docs/3-…/xspace`, **丢掉中间的 `skills/` 段**。
2. **目录前缀替换**: `docs/<旧目录>/` → `docs/<星>/<旧目录>/`; 再补「裸目录/通配」形态: `docs/design/*`、`docs/memory`(无尾斜杠)。
3. **拆参形式**: `os.path.join(ROOT, "docs", "memory")`、`"docs", "patents"` → 在 `"docs"` 后插入新一级。
   第三遍必须**单独跑一遍**, 因为第 5 步的主循环通常写了 `if "docs/" not in text: continue` 这种快筛 ——
   只含拆参写法、全文没有 `docs/` 子串的文件会被整个跳过(实测 `verify_patent_channel.py` 因此直接 `FileNotFoundError`)。

### 6. 核验: 存在性 + 编译 + 判据
```python
# 提取每一处 docs 路径字面量, 逐条 os.path.exists; 报 file:line
# 缺失但 basename 在树里唯一 → 说明是历史漂移, 顺手改成真身(实测一次修好 243 处本来就指错的引用)
```
- 所有改动的 `.py` 逐个 `py_compile`(只编译「搬完仍存在」的路径, `git status` 里还列着旧路径会报 No such file)。
- 跑关键判据: 读那棵树的功能判据脚本各跑一遍; **GUI 类判据要用项目 venv 的 python**(系统 python 缺 PyQt5 会 `ModuleNotFoundError`, 那是环境不是回归)。
- 新写 `README.md` 当唯一入口: 分组表 + 一句话归属判定 + 只读规矩 + 命名 + 查找命令。

## 合并重复数据目录(顶层旧目录 → 仓库内)
1. 先判它是重复还是独立: 看内容类型(产物/缓存 vs 模型/真数据)、体积、引用数; 职责不同的两棵目录**不合并**, 在文档里写清分工。
2. 合并用 `rsync -a --ignore-existing <旧>/ <新>/` → 目标侧已有同名文件保留目标版本(通常更新更全), 只补新文件。
3. 核对: 遍历旧树每个文件, 断言新树存在同名同相对路径; 再比同名文件大小, 差异逐条说明。
4. 收尾把顶层旧路径换成**符号链接**指向新位置 ⇒ 老写法(`~/xxx/...`)零代码改动继续穿透。
5. root 属主的残留 `rsync --delete` 删不掉(`cannot delete non-empty directory`): 核对文件清单与新位置一致后再 `sudo rm`, 别先删。

## 删顶层遗留别名软链(旧仓库名/旧路径兼容壳)
判定口径(缺一不可, 全部只读):
1. `grep -rl '<别名>' /etc/systemd/system ~/.config/systemd ~/.hermes/{cron,scripts}` + `crontab -l` + 桌面 `*.desktop` 的 `Exec=`;
2. 源码区 grep 后**剔除注释行、迁移/审计工具自身、以及名字相近的别的东西**(实测留下的 17 处全是迁移脚本和 ECS 侧同前缀的服务名, 运行时零依赖);
3. 命中全是上面两类 ⇒ 删链。删后把**技能库/记忆里写的旧绝对路径一起改**(它们会被以后照着执行的 agent 当真), 否则下次跑技能里的命令直接指向不存在的目录。

## 扁平交付件堆 → 按类型分类 + 按版本去重 (顶层 ≤N)

交付目录堆到几十份、用户说「太乱了, 精简合并, 按文件夹分类, 不要超过 N 个」时, 按**文档类型**分文件夹,
绝不按版本号分 —— 版本分类会让同一份文档在每个版本各占一格, 越清越多。

1. 先摸清再动手: `find . -maxdepth 1 | wc -l` + 按扩展名/体积排序 + `du -sh .`, 汇报「顶层 X 项 / Y 文件 / Z MB」。
2. 去重靠**归一化相似度**, 不是字节哈希: 同一份文档在不同发布号下常差几十字节(版本串、git hash、导出时间),
   `sha256` 会报「86 份全不重复」, 实际一半是同一文件的快照。把 `5.50.X`、`v5.50.N`、`20\d{6}`、
   `<日期 时间戳>` 这类噪音 token 正则换成 `<v>` 再算 `difflib.SequenceMatcher(...).ratio()`,
   **≥0.995 判同一份, 留最高档位的那份**。
3. 相似度低 ≠ 必须留: 旧发布号被别人明写「已被本版取代」时, 差异再大也归档旧的那份;
   反之**产品档位(A/B/C 各一套)是真的两套正文** ⇒ 必须留, 按档位删会把内容删掉。
   判据只有一句: 这两份是「同一文档的两次快照」还是「两个不同产品的文档」。
4. 目录名带序号前缀(`1-产品方案`…`8-工程手册`), 顶层再放一个 `README_INDEX.md` 当唯一入口
   (表: 文件夹/内容/份数 + 版本口径 + 归档去向 + 三条归位规矩)。顶层项数 = 文件夹数 + 1, 别超 N。
5. 打包产物 `*.zip` 一律归档: 内容就是 `md`/`json`/`docx` 的重打包, 留着只是又一份副本。
6. 归档进 `_cleanup_<日期>/<主题>_<日期>/`, **不交付目录里留 `_old/`、`_bak/` 子目录**(那还是第 N+1 项)。
7. 搬完必须回到第 5/6 步做引用改写 + 存在性核验: 交付件路径被 `tools/*.py`、文档互引、技能库同时写着,
   不核就是死路径(实测 18 个文件要改)。
8. 顺手清: LibreOffice 锁文件 `.~lock.*#`; `find docs -xtype l` 找断链软链(指向已删文件的旧别名)。

## Pitfalls
1. **「搬完了」不等于引用改了**: 先查引用再搬; 搬完必须做第 6 步存在性核验, 不能只靠 grep 旧前缀为 0(拆参/通配形态 grep 不到)。
2. **快筛条件会漏文件**: 任何 `if "<前缀>" not in text: continue` 都会漏掉用另一形态写路径的文件, 每种形态各跑一遍独立 pass。
3. **替换顺序错了会切断路径段**: 逐文件映射 > 目录前缀 > 裸目录兜底, 长的先替。
4. **只读镜像目录不许在 docs 里改**: 技能库/记忆是 `~/.hermes` 的镜像, 整目录搬、改名只在源头改, 否则下次同步把改动冲掉。
5. **历史留档 vs 真代码**: 代码区必须改; 取证快照类(状态快照、事故留档)按日期冻结, 可以保留当时的旧路径写法, 但要在 README 里说明「按文件名 find 定位」。
6. **别在 `/tmp` 备份完就不管**: 搬完提交后清掉临时备份, 否则等于又造一份重复数据。
7. **仓外文档也是引用**: 技能库、记忆、桌面 `Exec=`、systemd 单元里写死的绝对路径, 与代码一样会变成死路径; 改完代码要同步扫 `~/.hermes` 与 `/etc/systemd`, 并避开 `zmax-relay` 这类同前缀不同物的服务名。
8. **备份/回滚前先看它是不是 git 跟踪的**: 已入库的树搬完自带历史, `/tmp` 副本只是临时保险; 反之未入库的数据树必须留全量副本。

## 本仓的既定结构(直接照用)
`docs/` 顶层只许 7 个目录, 与配置中心七阵同源(唯一依据 `tools/gui/ss_seven_stars.py`);
七组名称、各收什么、一句话归属判定见 `references/docs-seven-stars.md`。
想加第 8 个目录 = 判不准归属, 先想清楚这份文档在定什么。
