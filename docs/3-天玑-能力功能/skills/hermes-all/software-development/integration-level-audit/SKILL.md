# 集成层级审计 (节点级 ≠ 档位级)

## 为什么需要

用户 (老倪) 对工程真实性零容忍, 高频追问「**实际怎么执行的**」, 且明确: **节点双击自检不算接上**,
"模型/类必须被真实链路每帧调用"。所以声称"已接入"之前必须**分级取证**, 否则就是把演示当交付。

**结论公式: 组件能单步真跑 ≠ 它进了那条每帧执行链。**

🔴 **审计第一步是先定“哪套系统”**。同一个词在不同链上指不同东西，先确认现场开着的是哪个页面/端口、它读的是哪个数据源，
再选判据。实测「右臂不动」就有四套完全不同的对象: ① 仿真站的 mujoco 双臂 (看 `/state.json#truth.tcpR` + `/status.json` 的 `ok/n`)
② 可视化页的 URDF 臂 (看 `/api/tcp` 的 `age_s/stale` + 位姿桥活没活) ③ 真机珞石臂
(看 `/ctl/status` 的 `power/operation/mode` + 授权 + 位姿真值双采 mtime)
④ **同一个页面里并排的两条臂** —— 仿真臂 (`ar_cmd.json` 段表 → 页面自己的逆解，驱动力是常驻引擎)
与真机臂 (`tcp_out/latest.json` 关节角，**设计上就是静的**)。
拿错一套的判据跑一整轮，结论全是废的，而用户一眼就知道你问错了东西 —— **先花 30 秒定边界，再开工**。

🔴 **验收口径：用户在这个上下文里说「右臂/左臂」默认指 AR 页上的仿真双臂**，不是产线那台真机。
答错对象会把你带进 estop/授权/手动模式那条岔路 (那些是真机的事，与 AR 画面零关系)，现场只会回一句
「我说的是 AR场景的虚拟右臂」。判据顺序: ① `cat zmax_data/ss_live/ar_cmd.json` 两次看 `seq/elapsed_s` 是否推进 +
`systemctl is-active zmax-ss-canvas-loop` ② `curl 127.0.0.1:8797/api/ar/mode` 的 `ar_scene/fresh` +
页面状态对象 (`SSMODE`/`ARCMD`/`PLANT`，**不是** 按钮的 `onclick` —— 页面走 `addEventListener`)
③ 才是 `/api/tcp` 与真机 `/ctl/status`。
🔴 **为调试断点停常驻引擎 = 这条链立刻冻住**: `stop zmax-ss-canvas-loop/zmax-ss-engine-loop` 后
`ar_cmd.json` 停更，页面「状态空间」拨开也没数据 ⇒ 用户看到的就是「状态空间驱动的双臂不动」。
停之前先说清这个副作用，调完立刻 `start` 回去并回读 `ar_cmd.json` mtime 在跳。

🔴 **“不动”先查生产端健康，再查消费者参数**。产品输出为零/冻结时，优先看**上游是否根本没在出东西**
(`ok:false` + `n=0` + 真值字段为空)，而不是先怀疑动作数值/算法。把一个“上游没启动”报成“action 不对”，
会把用户带去看一整天的调参。

## 四级阶梯 (逐级给证据, 别跳级, 别含糊)

| 级 | 名称 | 判据 (全部可查) |
|---|---|---|
| L0 | 封装 | 文件在位: 契约/数据源/适配器/节点/自检 + 跨进程 worker (若有独立 venv) |
| L1 | 单步真跑 | 自检 A 闸通过 (拒绝零动作) + 真权重路径 chunk **非零且随观测变化**; 画布双击/右键/⏭单步真出动作 |
| L2 | **档位链** | ①注册 (`_reg("<key>")` / 工厂注册表) ②图上节点存在 **且 links 里有连线** ③**档位/能力清单里有此名** ④引擎与面板文案不再写"未接入" |
| L3 | 硬件 | 真机 IO 真实现 (不是 `NotImplementedError` 预留), 或有明确的仿真等价物 |

## L2 审计命令 (照抄, 5 步)

```bash
# ① 注册
grep -n '_reg("<key>"' tools/gui/node_logic.py
grep -rn '<key>' src/**/node_registry.py          # 其它工程的注册表
# ② 节点在位 + ③ 孤岛检查 (节点在位 ≠ 接入)
python3 -c "
import json;d=json.load(open('flows/state_space_obs.json'))
nid='ssintact'
print('节点在位:', any(n['id']==nid for n in d['nodes']))
print('连线数:', len([l for l in d['links'] if nid in (l.get('f'),l.get('t'))]))"
# ④ 档位/能力清单
grep -rn '<key>' src/lerobot/verification/capability_levels.py
# ⑤ 代码自己的诚实标注 (引擎/面板是否仍写"未接入")
grep -rn '未接入\|S3 前\|占位' tools/gui/state_space_sim_real.py
```

🔴 **查库/查连线前先避开两个假数据源**: ① 工程库**真文件**在 `data/database/zmax/zmax_engineering.db`,
仓库根目录同名文件可能是 **0 字节空壳** (build 写前者) ⇒ 查根目录会得出"没有这张表"的假结论;
`canvas_nodes` 列只有 `project_id,name,type,x,y,w,h,params` (**没有 id 列**)。
② **连线一律读 flow JSON** `src/lerobot/engineering/flows/state_space_obs.json` (`nodes[].id` + `links[]{f,t,label}`),
DB 的 `canvas_links` 行可能 `src/dst` 全 NULL (build 缺陷) —— 拿它下"没接线"的结论是假阴性。
节点参数里的 `params.source` 指向哪个源文件, 才是"这个能力有没有节点"的唯一硬证据。

**孤岛 (links 数 = 0) 是最强信号**: 节点画在图上、能被双击, 但没进任何链路。
⑤ 尤其有用 —— 好代码自己就标了"未接入引擎", 汇报前先读它, 别和它打架。

### 追"X 用在哪里"的取证顺序 (用户问一句, 你要能列全)
一个模型/能力在系统里可能被**四条路**碰到, 逐条查, 别只看一条就回答:
1. **常驻服务**: 先看 unit 的 `ExecStart` (落点/端口/是否 `--lazy`/权重目录 env) —— 这是它"在跑"的硬证据。
2. **人的入口**: 页面按钮/CLI 往往**不直连**服务, 而是经中转 (实测: 页面按钮 → 推流服务 `GET /seg?...` → `_seg_run()` 带 `write_spec=True` 转发到推理服务)。
   搜法: 以**页面的请求串**为锚 (`grep -rn '"/seg"\|/seg?'`), 顺着中转函数一路走到真正推理的那个 endpoint。
3. **画布节点**: 按节点 id 查 `nodes` + 把**每条 link 的两端与 label** 读出来 (帧从哪来 / 意图从哪来 / 输出给谁) —— 一列就可答"它吃谁、喂谁"。
4. **训练/评估入口**: 同一能力的微调/验收脚本 (教师伪标签、A/B 判据)。

### L2 感知在某个场景里到底接的是哪条链 (一次问清, 不许只答一个模块名)
用户问「现在的 <场景> L2 都启用接入哪个模块」时, 答案 = **一入口 + N 消费者 + 名同实异 + 判活四条**:

1. 🔴 **先按画布连线定链 —— 本仓有两条互不相干的 L2 检测链, 用户问「AR 场景 L2 感知输入」默认指画布链**:
   - **画布链 (状态空间 L2, 默认)**: flow JSON 里 `ssdata 📦 metaworld 数据源 → ssyolo 🎯 YOLO 目标检测` (label `图像流`)
     ⇒ 输入源 = **metaworld 渲染帧**。实现 `nodes/library.py::node_ss_yolo` → `_yolo_capture` (`env.render()`)
     → `yolo_state_aligner.py::model.predict` → 写 `zmax_data/ss_live/vision_points.json`
     (`source.kind=ss_yolo_node` · `cam=metaworld渲染帧` · 每点带真 `conf`)。节奏: 白名单每拍 14 节点, `ssyolo`
     每 `FULL_EVERY`(30) 拍一次, 节点内再按 `ZMAX_L2_PERIOD_S`(0.5s) 节流 ⇒ 报"每 30 拍 + 0.5s 节流", 不写"每拍"。
     判真推理看 `source.cam/kind` + 各点 `conf` + **隔一次采样坐标是否在变**(变=不是固定帧回放; 别只凭 `reset(seed=0)` 就断言固定帧)。
     🔴 **判"权重真是这一版、真在吃这个域"的办法是两版权重跑同一张同域真帧再比**: 检出数与耗时同时看
     (实测同一张 AR 帧上, AR 域权重 12 框/68ms、真机域权重 1 框/59ms; 换到真机腕相机帧则是真机域 1 框 conf 0.69/59ms、AR 域 12 框)。
     同一权重换域后差一个数量级 = **域不匹配**, 不是模型坏了; 两版在同一帧上框数/耗时几乎相同才要怀疑权重没真换。
     另: 单次耗时含首次加载 —— 冷启(2.5s 级)与热态(60~70ms 级)必须分开报, 别拿冷启数判"能不能进拍子"。
   - **页面链 (8797 AR 页 3D 框, 另一条)**: `tools/det_src.py` (真源 `zmax_data/runtime/det_src.json`),
     帧源与权重**成对**切换 — `real → 8791/snap/arm.jpg + models/yolo_peg_live.pt` ·
     `render → 8802/frame.png + models/yolo_ar_peg.pt` · `auto` 按帧新鲜度选; `_mod3_worker(0.15s)` 写
     `/dev/shm/mod3_latest.json` → `/api/module3d`。一条 GET 看全貌: `curl -s 127.0.0.1:8797/api/det_src`
     → `want/running/frame_src/weights/ok_det/err`; `grep -rln det_src tools/ src/` 的命中集是这条链的全部消费者。
   🔴 用户说"你看连线"就是要画布那条; 拿 det_src 的 `ok_det=false` 回答画布链 = 换了对象答题。
   正确收尾: 先给画布链结论, 再补一句"8797 页面 3D 框走的是另一条 det_src 链"。
2. **消费者通常不止页面那一个**: 实测 8797 的 `_mod3_worker` (0.15s → AR 页 3D 框) · `tools/opt_box3d.py` (3D 解算) ·
   `ss_engine_loop --pipe-img <同一帧源>` (状态空间 L2 节点, 每 N 拍) — 三处共读一份配置,
   所以「改一个地方让它换源」必须同时解释这三处, 否则页面变了引擎没变。
   同目录还有**看着像但不是**的旁路: `ss_yolo_on_real.py` 自己一套权重、写 `zmax_data/ss_bypass/{yolo_detections.json,
   yolo_annotated.png}`, 不读 det_src; 汇报时单列成"旁路可视化", 不许并进主链。
3. **同名 L2 的两个意思**: `tools/l2_daemon.py` 是 L2 **原子技能运动执行器** (FIFO + 授权闸), 不是感知;
   🔴 但它现在只是**20 余行的 runpy 启动壳**, 真实现在 `src/lerobot/engineering/exec/daemon.py` ——
   按 tools/ 里的文件名 grep 逻辑会得到"这文件什么都没干"的假结论。同构地, 节点实现 (`*_impl.py::run`) 只读真值
   不下发, 中间件壳 (`n_<x>.py` 的 `PURE`) 只是闸, 能下发的只有守护进程 ⇒ 回答"谁在执行"按这三层给坐标。
   `ssyolo/ssaoi/ss_seg/sstactile` 是画布节点。用户问 L2 时按上下文选, 两层都答一句比答错一层强。
4. **判活四条, 缺一条就会把"接上了"报成"在跑"**:
   ① `/api/det_src` 的 `ok_det`; ② 输入帧 HTTP 码 (`/snap/arm.jpg` 404 · `/frame.png` 503 都是"没帧");
   ③ 检测产物的 **mtime + 检出条数** (只看 `ok:true` 是假证, 见本 skill #24);
   ④ 画布 L2 节点的连线数 (`links[]` 里 `f/t` 两端命中为 0 = 孤岛, 画上去了没接)。
   口径: `ok_det=false` + 产物 0 条 ⇒ 正确结论是「链已接、当前无输入帧、0 检出」,
   既不是"L2 没接入", 也不是"L2 在检测"。
🔴 **同一端口可能同时承载两个面向** (模型/硬件状态聚合 + 推理), 看到端口号就断定"没有推理调用"是假阴性 —— 先看路由表再下结论。

🔴 **实现可能在两台机器上, 注册符号要两边都 grep**: 进化/部署类组件常把代码**拷一份**到部署机
(实测: 源码在 `src/.../se3_impedance.py`, 跑的那份在另一台机的 `~/se3_gravity/se3_impedance.py`),
两份是**不同文件**。只查源码机得出"实现了", 只查部署机得出"只有进化回路在用" —— 两个都不完整。
判":没接进在役链"的唯一硬证据是**两台机器上 grep 注册符号 (`set_xxx_provider` / `Se3GravityProvider` / `_reg("key")`)
都只命中验证脚本本身**, 而常驻回路 (`ss_engine_loop.py` / `*_daemon.py`) 零引用。
两机同一份实现先比 `sha256sum`, 不相等就先对齐再谈行为。

**用户问"你是在哪里实现的 / 代码在哪"的答题格式** (他要的是可核的坐标, 不是描述):
① **文件 + 行数 + 提交号**的清单 (源码侧 · 适配层/挂载点 · 判据脚本 · 部署机目录 · systemd unit);
② 判据**当场重跑并贴数字** (`Φ 8.000e-02 → 2.000e-06` 这类), 不引用上一轮结论;
③ 台账里的分数只证明"搜索能跑", 不证明精度 —— 并且要如实指出**末代比首代更差**这种漂移;
④ 单独一行写"**没有注册进任何在役回路 / 真机力矩通道没接 / 数据是仿真**", 别让它埋在段落里。

**汇报时要分层, 不用一个模型名拍死**: 「2D 掩膜 · 单帧 3D 位姿 · 场景重建」是三层不同的东西。
实测问「它用在哪里? 是建图么?」时, 正确答法 = 先说定位 (感知原语产 2D 掩膜)、再给 3D 通路 (掩膜+深度 → 掩膜内中位深度 ⇒ **单帧**位姿, 缺深度/手眼必须如实拒答)、
最后明确"建图(走点扫描/重建)是另一条链, 它不在其中"。含糊一句"能做 3D"就是误导。

## 「X 进 Y 节点了么 / 这个话题是谁发的」—— DDS 三层核验 (顺序固定)

用户问某个量"有没有进某个节点"时, 不许凭画布连线或"看着在动"回答, 按三层走:

1. **类型字段表**: `dds/ss_types.py` 里那个 dataclass 有没有目标字段。没有 = 结构上不可能带入, 一句话结案,
   不用跑实验 (实测 `SSPlan` 只有 joints_path/tcp_path/start_joints/goal_xyz/end_err/gate_*, 无 u_ff/v_ff
   ⇒ "前馈 v_ff 没进 plan 节点"是定义级结论)。
2. **发布端填充 + 闸门**: `grep -rn 'publish("<topic>"' tools/ src/ dds/` → 读那个函数填了哪些字段、前置闸是什么;
   新旧实现并存 (`tools/zmax_dds_*.py` 与 `tools/dds/ss_daemon.py`) 时, 认主循环里被调用的那个。
3. **实时证据**: `zmax_data/dataspace/live.json` 的 `count / age_s / lamp`, 加上这条话题**上游源文件**的 mtime。
   黑灯 (count=0 / age=null) 先比上游 mtime 与闸门阈值, 再谈"节点没接"。

实测话题归属 (变了以 grep 为准):

| 话题 | 发布节点 | 上游 | 闸 |
|---|---|---|---|
| ss_action | `tools/dds/ss_daemon.py: pub_action()` (主循环 1219 行) | `zmax_data/ss_live/proposal_*.jsonl` 末行 (infer-8790 产物) | 源龄 > `STALE_S=5s` 直接不发 |
| ss_state | 同文件 `pub_state()` | `zmax_data/ss_live/state_*.json` | 同上 STALE_S |
| ss_plan | 同文件 `pub_plan()` | `~/zmax_moveit_plan` 里 moveit_plan_live 追加行 (容器没起 ⇒ 目录都不存在) | 同源闸: FK vs 真机 TCP ≤5mm |
| ss_engine / skill_* | `ss_engine_loop.py` / `ss_skill_dispatch.py` | 引擎回路 / 技能库 | 设计 Hz |

**"在动"要落到消费者才叫进链**: 前馈 `u_ff`(v_ff) 的消费方是 `cognition.decide(u_ff, u_fb)` → 阶段限速/安全边界 →
`ss_action`; 与 plan 节点 (MoveIt 只规划不执行) 是两条线。回答时把"显示链通 / 执行链通"分开报, 别用一个话题名拍死。

## 四档一次跑通取证 (`run_all_models.py --caps l2,l3,l4,l5`)

用户问「**所有层模型可以跑通了么**」时的硬证据 = 逐档真跑 + 逐档调用计数, 不是读代码说有接线:

```bash
./gui-venv311/bin/python tools/run_all_models.py --caps l2,l3,l4,l5 --steps 20 --seed 104
# 证据落盘 reports/run_all_models_<ts>.json
```

汇总表每档给五列: 终点mm · YOLO帧/检出 · MLP真身 · INTACT真推理 · 墙钟s。读法固定:

- **每帧真推理**看 `YOLO帧/检出`: 帧数 == 步数 (20 步 = 20 帧), 检出/帧 ≈ 目标数。
- **只有 L4 档该有两列非零**: `MLP真身` 与 `INTACT真推理` 都 **== 步数** (20/20) 才算每步真调;
  少于步数就是有步被守卫拦了, 要查 `_intact_stats.gate_pass/refused`。
- **L2/L3/L5 那两列 = 0 是正常** (`CAP_ENV` 里这三档没 set `SS_INTACT/SS_USE_MLP`),
  别把 0 报成"失败", 也别把 L4 的 20 反推成"四层都在跑"。
- `done=False` 在 20 步属正常 (完整任务约 150 步), 报口径要写清步数, 不说"没跑通"。

🔴 **四档同时报同一个 FileNotFoundError ⇒ 先验路径常量, 别逐个档查逻辑**。
实测: `runtime.py` 的 `_REPO = dirname(__file__) + "../.."` 算出 `<repo>/src` (应为 `<repo>`),
于是 `_yolo_dir = _REPO + "src/lerobot/..."` 拼成 `<repo>/src/src/lerobot/...`, 四档 100% 挂。
判据: 报错路径里出现**重复段** (`src/src` · `tools/tools`) ⇒ 100% 是 `..` 层数算错, 与各档逻辑无关。
修法: 从 `__file__` 数清层级 (`<repo>/src/lerobot/engine/runtime.py` → `<repo>` 是**三级**),
并确认该常量下挂的**所有**资源都在同一层 —— `runs/` `outputs/` `src/` 都在仓库根才成立;
只对得上其中几个就说明不能靠改层数, 要改成按包 `__path__` 定位。

## 「这段代码/这组数值真是现场发出来的么」—— 出处取证五步

用户拿一段函数或一组数问「这是正在运行的那条链实际发出的么」时，**不许凭「画布上有这个节点 / 服务是 active /
函数在仓库里」回答**。固定五步，缺一步就不是结论：

1. **列全部调用点**: `grep -rn '<函数名>(' --include=*.py src/ tools/` —— 结果强制分三类：
   ① 在役常驻回路 (engine/runtime · daemon · *_station_engine) ② 离线仿真/单步脚本 ③ 验证/基准脚本
   (verification_layer · bench_*)。只有 ① 能算「现场」，②③ 命中多少次都无关。
2. **核在役回路的两条道**: 常驻循环**每拍只跑 `CORE_IDS`（默认 14 个），其余节点每 `FULL_EVERY`（默认 30）拍跑一次** ⇒
   `canvas_loop.json` 里 `n_ran=14` 的那一拍**不是**节点全集，`only/n_ran` 也不等于「白名单」（`ZMAX_CANVAS_ONLY` 属旧口径/调试用）。
   判「每拍在跑」= 节点在 `CORE_IDS` 且同拍 `traces[]` 有它；只在全量拍出现 = 1/30 拍级，汇报写「每 30 拍一次」，不许写成每拍。
   函数所属节点在**任何一拍**的 `traces[]` 里都没出现 ⇒ 它一次都没执行，结论直接是「不是」，无需再往下算。
3. **全盘搜这组数本身**: 用 `search_files` 拿**具体字面量**（至少三位小数）搜代码/日志/产物。
   在跑的服务写过的东西一定留痕；搜到的全是无关文件 = 没有服务写过它，这就是最强否证。
4. **拿真在发的产物对照形状**: 读 mtime 在秒级跳的产物（`ar_cmd.json` · `skill_latest.json` · `canvas_loop.json`），
   看现场发的到底是什么形态。现场常是**绝对 mm 点位 + 段表 + 比值标量**，与归一化 4 维动作向量**形状就不同**
   ⇒ 形状不符即可否证，不必再解释数值含义。
5. **点名真正的闸**: 找到在役限制来自哪一层并贴原文计数（实测是速度/加速度闸的削因统计，不是 `POS_LIMIT` 的 clip）。
   用户问的是「这条链上谁在管」—— 换一个函数名不是答案。

⚠️ 「代码里存在」≠「在跑」≠「在现场生效」，三档分开答：函数在仓库里（哪几个调用点）· 节点在图上但不在白名单 ·
现场实际发的是 X 形态。合写成一句「已经用上了」或一句「没接」，都是错的。

🔴 **`systemd active` + pid 活着 ≠ 循环在写**: 判常驻循环真在跑只看**它该写的产物 mtime**，不看 unit 状态、不看 pid。
实测进程已跑 5 分钟而它的快照产物停在 2h42m 前 ⇒ 循环没在 step（卡在启动/等锁/命中「已有写入器在跑」分支退出）。
报「服务在跑」之前把 `ls -l --time-style=+%H:%M:%S <产物>` 与 `date` 对一次；停更就是缺陷，要单独报出来。

🔴 **产物停更 + 进程存活但 CPU 近 0 ⇒ 优先查外网重试，不是查业务逻辑**。实测根因: 无外网时
`huggingface_hub` 去 HEAD 拉 `chat_template.jinja`，5 次退避重试把整个常驻循环/模型加载卡在启动段
(进程 `wchan = hrtimer_nanosleep`、CPU 0.3%、`engine_latest.json` 停写、`l3_latest.json` 长期
`degraded=true` + `n_done=0` + 「首拍加载中」)。判据一行: `sudo tail -20 /var/log/<服务>.log | grep -i huggingface`;
修法 = 给该 unit 加 drop-in `HF_HUB_OFFLINE=1` + `TRANSFORMERS_OFFLINE=1`(权重在本地缓存时无副作用),
重启后看产物 mtime 重新跳动 + `degraded` 转 `false` + `n_done` 开始长 —— **这才是“模型在跑”的证据**,
在此之前拿它的输出论证任何结论都是拿陈旧块说话。

🔴 **“两条闸/两条链都真调了”的判据是计数器对账，不是日志里看得到**: 每个消费端把自己的拍数写进产物
(如 `gate_n = {node, kin, dyn, kin_obj, dyn_obj}` 与 `闸_拍数/运动学闸_拍/动力学闸_拍`)，汇报时要求
**三个数逐位相等且随拍数增长**(实测 node187/kin187/dyn187)；任一条比总拍数少 = 那一拍被短路。
配套一条**零回归闸**: 重构/拆分实现时，把新旧两版灌同一串真输入逐拍比对，报「差异 0 拍 + 削点数相等」
(脚本落在 `tools/`，别只在对话里跑一次)；改动后还要回读**块帧龄**(`block_age_s`)确认输入不是陈旧块。

34. **端口按「下游实现读哪个端口」连, 不按标签连; 实现只读模块级状态 = 端口形同虚设**: 三查, 缺一条就会把装饰线当数据流:
   ① **上游 payload 喂下游某端口后回读下游消费字段** —— 实测安全边界的「单步 50mm/向下 20mm」约束 `out3` 接在规划节点 `in1`,
      而规划的实现 `_limits()` 只读 `in2`、`in1` 是目标点 ⇒ 这道限幅被当"目标点"吃进去, 规划从未用上; 改接 `in2` 后
      喂 35/12 能回读 `{step:35, down:12}` 才算通。判据不是"画布上有连线", 是下游回显上游的数。
   ② **数一下实现里 `ctx.get("inN")` 的命中数与端口数**: 契约写了 9 个入端口, 实现却只读模块级 `_SS_STATE` ⇒ 接不接一样,
      输出永远是空/零; 这种"接口开着、数据不进"比不接线更难发现 (trace 显示实现执行、端口值却是空)。
   ③ **同名分支抢端口**: 一个 `run()` 里服务多个节点名时, 某个分支的前置条件 (如 `in2` 里有 `tcp`) 会先命中、把本该走另一分支的节点
      截走 ⇒ 按 `ctx["name"]` 显式分流, 不能靠 dict 形状猜。
   🔴 **判据把「放行」写成「真咬」= 假红**: 上游已削到限内的值喂给下游限幅, 下游本来就不会咬 (实测 0.35 < 0.6 ⇒ 原样透传)。
   正确双子例: 限内逐位透传 + 人工喂超限值必须被压到上限; 只写前者会永远红、只写后者会永远绿。
   🔴 **闸的入参要能自取, 否则静默跳过**: 下游收口函数 (如 `chan_send(call, ..., speed=None)`) 的调用点
   多数根本不传那个参数, 闸读到 None 就回「无参数 ⇒ 不适用」, 一片绿灯而一次没管。入参取值写三级回退
   (显式参数 > 调用体自带字段 > env 默认), 并补一条判据「不传参时按调用体字段仍能削」。
   🔴 **补闸必须同时带零回归开关与逐位断言**: `ZMAX_EXEC_*_GATE=0` 时输出与改动前逐位相同, 判据显式断言这一条;
   否则新闸一旦误削 (例: 把腿内斜坡的 a/jerk 当段速硬闸 ⇒ 合法 300mm/s 被削到 128mm/s) 没人能一眼看出是它。
   🔴 **约束类字段只在规划侧算过 ≠ 执行侧也管**: 确认「闸真在真机收口」就 `grep -n 'V_CAP\|A_MAX\|JERK\|s_step' <收口文件>`,
   零命中即证明真机链上一道都没挂 (规划段的时长合规不能外推为逐段复核)。
   🔴 **插入钩子的脚本用 `if "_fn(call" not in s` 当"已插入"判据会自我匹配**: 同一脚本刚插入的 `def _fn(call, ...)` 就含该串
   ⇒ hook 静默不落, 源码看着有闸实际没挂。判据要静态比偏移 (`def chan_send(` < 调用点 < 下发腿), 并跑一次真降速才算通。

### 「这个节点的信号进 AR 场景了么」= 端口出口 + 文件出口，分开答

画布 `links` 只能证明**端口**出口；AR 走的是**文件出口**，所以“画布上看不见”不等于“没接”：

1. 实现里真写产物才是接入：`grep -rn 'ar_bridge.update' src/` 命中该节点的 `run()`；`ar_bridge` 写**单文件双分区**
   `zmax_data/ss_live/ar_cmd_chain.json`（`plan` = 运动规划写的段几何 a/b/u/label，`exec` = 执行器写的 u_cmd/校验，文件锁串行防互盖）。
   ⇒ 某节点 `out` 只有 1 条连线、甚至 0 条，也可以**真接进了 AR**。
2. 三条一起核：① `ar_bridge.update` 的调用点在实现里 ② 回读产物分区字段 `exec_src`/`plan_src` 等于该节点 id
   ③ `curl 127.0.0.1:8797/api/ar/cmd` 的 `chain/drive/exec_u/exec_src` 与产物一致且 `age_s` 在秒级。
   合格口径：`chain=true · src="chain:n_moveit+ssact" · drive="exec:ssact" · age≈0.07s`。
3. 🔴 **判活只能用 `/api/ar/cmd`，不许用 `/api/ar/exec`**：后者读遗留单分区文件 `ss_live/ar_exec.json`，
   可能停更几天而链其实在跑（实测 `age_s=317419`、`fresh=false`）⇒ 拿它判“没接”是假阴性；它只适合回退/诊断。
   同理页面注释写的还是老 `ar_cmd.json`，服务端已优先读 chain 文件 —— **注释落后于代码，以接口回显为准**。
   两个问题分开答: 「页面被谁驱动」可以说 `/api/ar/exec`（页面源码里它仍在前，fresh 才吃，否则回落 cmd）；
   「这条链到底在不在」只能用 `/api/ar/cmd`。只读真值的节点（如动作执行器）根本不在驱动链上，它在右下角
   「L2 全链 → AR 标注」面板里以 `ar_cmd_chain.json` 的 `annot.nodes[{ok,ms,status}]` 出现 ⇒ 回答"这个节点在 AR 里干什么"
   必须说清「标注源，不是驱动源」，并用 `annot.summary`（ok/err/wall_ms）证明链活着而节点没算。
4. 汇报四件分开：端口上出了几条线 · 文件出口真写（分区字段+龄） · 页面拿到的驱动源 · 是否零下发。
   图上看不见的那条线要在页面/方案册里补一句“⇢ AR（文件出口，只喂渲染）”，否则下一次审计又会把它当成没接。

### 「这个开关真的在切换信号通道么」= 调闸函数 + 摘一道闸看下一道

用户问某个界面开关是否真在切换 AR/真机时，**别读界面文案、别读日志**，按四步：

1. **直接 import 收口模块调闸**，拿到的理由就是现场生效的那一道：
   `from lerobot.engineering.exec import daemon as D; D._auth_guard('move_joint','运动')`
   → `(False, '…')`；返回 True 时才去看它是不是 fail-open（文件过期即不拦）。
2. **证明多道闸是串联的**：内存里摘掉一道再调一次（`D._ar_scene_gate = lambda: None`，用完存句柄恢复），
   下一道的理由浮出来 ⇒ 分清谁在拦。**不落盘、不改 live 文件**，现场零扰动；改开关文件去实验等于拿现场做测试。
3. **否决闸 ≠ 路由**：有的开关只是拦住一条通道，并不把数据**改写**到另一条。声称“关掉 A 就只走 B”前，
   必须 grep B 通道的写者有没有读这个开关 —— 实例：写 AR 链的 `ar_bridge.update()` 完全不看开关 ⇒
   “AR=关” 时渲染数据照写，真正的开关只活在页面模式与真机否决两处。汇报分三列：真机侧闸 / 写链侧闸 / 页面侧模式。
4. **急停白名单按真 call 名核**：白名单是英文服务名（`estop` / `robot_stop` / `rokae_recover_estop` / `recover`），
   自造的名字（`emergency_stop` / 中文「停止」）会被闸拦住 ⇒ 别拿自造名测出“被拦”就报急停失效。
   报“急停放行”必须用链路里实际传的那个名字实测。

🔴 **用户要求「两个开关可以同时打开」时，任何串联的否决闸都是缺陷**：默认放行，旧行为用 env 开关保留
（实例 `ZMAX_AR_HARDVETO=1` 恢复“AR 开 ⇒ 真机不动”），并把这次语义变更写进事故台账。
**别自作主张加“真互斥/写链闸”** —— 用户要组合态，多一道互斥就让组合态静默失效，且改的是别人正看着的通道；
先按用户语义落地，再加可开关的加固项。改安全闸代码后要说明「需重启哪个进程才生效」，不许宣称已上线。

## 「整层全链 → 输出到某产物」的三步取证 (声明前必经)

用户要「某层全部节点、全连路、最后输出到 X」时, 三件事分开给证, 少一件就是夸大:

1. **跑得起来**: 从画布 `nodes + links` 建拓扑序 (Kahn), 每拍给每个壳按连线喂 `ctx[端口]={value, age_s, fresh}` 再调 `compute(ctx)`,
   落逐节点 `{ok, ms, status, outs}` 台账。可复用入口 `tools/l2_full_chain.py` (按 `row_bg` 带取节点 → 拓扑 → 逐拍 → 汇总 →
   写产物分区 + `--json` 报告), 别每轮重写这个 harness。
2. **真算/直通两个数一起报**: 31 个节点可能 31 个 `ok` 而只有 14 个真算 —— 其余 `PURE=False`, 壳返回的就是
   「直通 (PURE=False: 只走数据面)」。把 `ok` 说成「在算」等同 #27 的自欺; 真算数要与画布 `PURE=True` 的计数对得上。
3. **产物侧回读, 不信注释**: 声称「输出到 AR/X」先 `grep -rn 'import ar_bridge' src/` 找 writer, 再回读产物分区字段
   (`plan_src` / `exec_src` / 自己的 `annot_src`)。实测模块头注释写着七节点链路 (规划引导→动作调制→…→执行器),
   真正调 `ar_bridge.update()` 的实现只有 2 个文件 ⇒ 全层 31 个节点只有 2 个在写产物。注释是设计意图, 调用点才是事实。

🔴 **声明「工艺编排/规划由 X 节点自主完成」前, 先证 X 的输入有真源**: 这类节点吃的是某维状态向量; 若那份状态只活在
常驻进程内存里 (`grep` 全盘找不到该维度向量的落盘文件), 节点只能直通 ⇒「编排是它自主完成的」不成立。
正确报法: 节点在链上被调用 (`ok`) · 但 `PURE=False` 且输入无源 ⇒ **编排没发生**; 补齐要两件 ——
① 把该状态落盘或接上融合输出 ② 用与节点同源的参考实现逐行对拍通过后才允许翻 `PURE=True`。

🔴 **新增产物分区要三处同步**, 否则只有一半生效: 写者 (`ar_bridge.update('<分区>', …)`) · 消费端 payload 白名单
(服务端函数里显式带出该分区) · 界面渲染 (新面板 + 定时拉取)。服务端改动**重启才生效**, 而重启常驻服务须用户点头
⇒ 交付话说成「已改好, 需重启 X 生效」, 别宣称已上线; 页面侧可直接用 `node --check` 验抽出的 JS 片段, 服务端函数可用
`importlib` 直接调一次看返回键, 两者都不必重启。

## 由后向前整层贯通 (L5→L4→L3→L2) + 理想值注入的判据

用户要「按 L2/L3/L4/L5 由后向前让节点先发理想值, 再验节拍, 保证所有节点联通有效」时,
照下面跑, 三个判据少一个就会把 65 个节点夸成"全通":

1. **层→画布带从 `row_bg` 名读, 不要手抄节点名**: `ssbg5`=L5(大模型中枢) · `row_mem_l4`+`ssbg7`=L4 ·
   `row_mem_l3`+`ssbg_vlm`=L3 · `row_mem_l2`+`ssbg0/1/2/3/ssbg_skill/ssbg4`=L2 ·
   `ssbg_data`/`ssbg8`/`ssbg9`=旁路(数据源/验证/可视化, 单列不阻断主线)。
   可复用入口 `tools/fullstack_ideal_chain.py` (改带只改 `LAYERS`, 别每轮重写 harness)。
2. 🔴 **离线跑 draw 会把 PURE 闸整个绕过, 于是全节点看着都是"直通"=假阴性**: 常驻循环走 `Node._load_module`
   (默认把 `PURE` 置 True, 只有 `ZMAX_NODE_PURE_ALL=0` 才全直通), 而审计脚本直接
   `importlib.import_module` 时 `PURE` 还是文件里的 False ⇒ 报"实现没跑"。必须**镜像同一闸**
   (`PURE=True` 除非显式关), 否则你会去追一个不存在的接线缺陷。
3. 🔴 **「有效」的唯一判据 = 端口 value 真的非空** (`None`/`{}`/`[]` 都不算)。`bool(outs)` 与
   `status=实现执行` 只证明"壳调了实现", 端口壳子会把 65/65 报成全通; 实测同一遍跑改成 "非空值" 判据后
   先降到 6/65 —— 这才是真基线。**先量基线, 再改代码**, 不然分不清修复与被自己骗。
4. 🔴 **壳会吞掉非 dict 结果, 这是"算了却发不出去"的系统性根因**: 实现返回 `ndarray/float/bool`
   (例 `safety.saturate` 返回限幅后向量) 时模板走 `实现返回非 dict → 直通` 整块丢弃 ⇒ 上游算了、下游永远收不到。
   修法 = 非 None 的一律当首端口值发出 (`return {PORTS_OUT[0]: res}`), 全仓 80 个节点模块一次改;
   改前 6/65 → 改后 30/65, 剩下的是真缺输入 (要图像/力信号/权重), 不许当"已联通"报。
5. 🔴 **实现读端口前先解包 `{"value": …}`**: 总线给的是 `ctx[port] = {value, age_s, fresh}`, 实现若直接
   当数据用(或只认 `{"obs":[…]}` 直塞), 会恒报"无 X 输入"而状态却写"实现执行" ⇒ 整条引导链空转。
   解包 `if isinstance(v, dict) and "value" in v: v = v["value"]` 是通用第一步。
6. **注入的理想值必须标注来源**: 节点自身没有上游时喂的层理想值 (意图/约束/计划/43D) 是**贯通器注入**,
   不是节点自算。汇报两列分开 (`节点自算发出 N` / `注入后可用 M`), 合写一句"已发出理想值"等于把注入当能力。
7. **节拍另算, 别拿层计数推 UPH**: 300UPH 只由工艺动作表的 `循环秒/件数` 与门槛 `3600/300=12.000s` 决定,
   报 `节拍 · UPH · 余量 · 成立/不成立`; 节点全绿和节拍成立是两件事。
   🔴 **UPH 必须双口径并列, 单给一个就是承诺超交付**: 计划口径 (Σ段表 t/件数) 与 实测口径
   (**逐段取台账里同一 `label` 的 `mean_t`** 求和, 并报命中率) 同时给, 再列差额归因 (`move +3.5s / up +1.0s / …`)。
   🔴 **实测口径不许用比例缩放**: 「段表 t × 台账 mean_t ÷ 段表同类计划均值」会把单段差异摊平、把缺口藏掉;
   拿不到同 label 才回落同 kind 均值, 且要写明回落了哪几段。页面/自检/核算必须调**同一个** `compute()` ——
   另写一套的常见形态是拿台账 `plan_t` 当分母 (它是「最后一条样本的 plan_t」, 随引擎每段漂移 ⇒ 同一数据能算出 150 或 200)。
   段表按 **`mod` 字段**取一件一组, **不要用整表均值** (含平铺/搬运段会稀释)。台账是活数据 (n 在长、`plan_t` 也会变)
   ⇒ 报数带采集时刻, 文档里的数按快照写。
   🔴 **差额的固定项必须落到代码行, 不然永远只能报"臂慢"**: 本项目 0.5 s/段的出处是
   `src/lerobot/engineering/exec/daemon.py::wait_arrive(tol_mm=2.0)` —— 进容差后**再 sleep 0.5 s 取第二帧**才算停稳，
   未到位循环同样是 0.5 s 一拍 ⇒ 短段上 c 的主体就是它。降 c 只有三种合法手法 (速度自适应容差 / 采样 0.5→0.1 / 判据换成
   "位移增量+速度阈值")，提 speed 一分不省；不许为凑节拍放大安全阈值或跳掉真值确认。
   同时注意: 节点若在 L2 标注里 `ms=0.0` 且 `status` 含「直通 (PURE=False)」，它每拍没算东西，节拍账**不能记到它头上**——
   能动节拍的只有段表与下发守护进程。快查双口径用 `./gui-venv311/bin/python tools/l2_uph_measure.py --no-run`
   (只读 `/api/sim_insert` + 台账，不跑引擎，秒级，带 `label_hit/n_seg` 覆盖率)；段表会长 (112 段 → 392 段) 而每件秒数不变，
   **方案册/PPT 里的段数与 UPH 会过期但看着仍自洽 ⇒ 一律现算不引用**。
8. **落盘产物路径用 `dirname(__file__)` × N 推仓库根时必错一层, 而错层是静默的**: 写成功、无异常、文件落在
   `src/zmax_data/...` ⇒ 判据只能用 `os.path.exists` + mtime 龄, 不能用返回码/rc=0 证明"已落盘"。
9. **节点逐个接入要三分类 (接入 / 串行 / 待补), 不是二选一**: 判据三条同时成立才算接入 ——
   能跑通 (不抛异常) · 真发值 (端口 value 非空) · 单次 ≤ 拍子预算 (默认 60ms, 10Hz 留余量)。
   超预算但能发值的 → **串行推理队列** (严格一个算完再下一个, 与 10Hz 环解耦); 能跑但不发值的 → **待补**
   (缺真帧/力信号/权重, 灌理想值也返回空)。候选**必须写画布节点 id 不是模块名** (`n_decoder` 是模块,
   节点是 `ssdec`), 写错就得到一排"无实现"的假结论。可复用入口 `tools/node_rollout.py`。
10. **「达不到 300UPH 就不接入」的正确落地是不让慢节点进拍子, 不是砍功能**: 节拍由工艺动作表
   (循环秒/件数) 与门槛 `3600/300=12.000s` 决定, 与这些节点接不接入无关。报告里要把这句写清,
   否则用户会以为"不接入"等于降级。
11. 🔴 **验收脚本的 PASS/FAIL 要正则解析, 不许数子串**: `out.count("FAIL")` 会把结论行
   `9 PASS / 0 FAIL` 里的 `FAIL` 算进去 ⇒ 全绿被报成 "1 PASS / 1 FAIL"。用
   `re.search(r'判据\s*(\d+)\s*PASS\s*/\s*(\d+)\s*FAIL')`, 没匹配到就报 `-1`(未知) 而不是 0。

逐节点替换的预算表、串行推理队列的做法与三机就绪 (代码/训练/部署打 MAC) 的核对清单见
`references/whole-system-rollout.md`。

## 分层搬迁 (算法从中层搬进 policies 这类算法路径) 的验收

用户说「这段算法怎么在中间件里 / 放到算法路径统一管理」时, 搬完**不能只报 import 通过**:

1. **真调一次节点入口**: `node_xxx({'log': print})` 跑一轮, 看返回 dict 的字段 + 话题/产物真发出去,
   import/`py_compile` 只证明路径对。先量单次耗时 (实测三路 HTTP + 一次 YOLO 推理 ≈45s/轮) ⇒
   10Hz 回路的节点层节流 (`ZMAX_*_MIN_INTERVAL_S`) 必须保留, 否则每拍跑会把循环拖死。
2. **依赖方向单查**: `grep -rn 'lerobot.middleware' <新算法包>` 必须 0 命中 —— 缓存 (`cache`) 与发布回调
   (`publish`) 一律由调用方注入; 算法层反向 import 节点层, 等于把这次搬迁白做。
3. **薄壳字段必须真取到值**: 搬迁时最容易留下 `globals().get("XXX")` 兜底读一个**从未定义**的变量 ⇒ 该字段永远
   是默认值 (实测 `remote` 恒「未接」, 而同一轮日志明写「取帧失败: 相机忙」)。判据 = 把返回 dict 里每个来源字段与
   同一轮日志逐条对照, 凡「恒定值 + 日志里有真原因」的字段就是死引用; 修成读算法层回写的缓存字段 + 回落原因为止。
4. 🔴 **重生成会抹掉模块里手写的常量**: `LAYER` / `IMPL_KEY` 这类由 `tools/gen_middleware_nodes.py` 按画布真源重写的字段,
   手改文件保住不了 —— 实测 `LAYER = 'L2'` 被重生成重置成 `''` (画布节点 `layer` 是 null), 于是层归属、
   `verify_*_node.py` 的 ① 判据一起失守。要保住就改**真源** (画布 JSON `nodes[].layer` / DB `mw_node.layer`) 再重生成,
   并回读生成物与 DB 两处一致; 只改 .py 的, 下次重生成静默回退。
5. 生成物的 docstring 与 `PARAMS['source']` 会落后于搬迁 (改 `SOURCE` 常量不覆盖它们), 老路径指向已删目录时
   照样能跑、只在右键「打开源码」时暴露 —— 同步四处见 `references/declared-source-vs-real-implementation-drift.md`。

## 「这个算法/参数真的落地了么」—— 四处落地清单

用户说「作为核心思想，要保证在 X 层具体落地」时的验收口径。**只写到算法文件里 = 没落地**，
四处都要能单独读到、单独关掉，缺一处就只是「一个叫得上名字的 py 文件」：

| 层 | 落点 | 应含内容 | 单独关闭方式 |
|---|---|---|---|
| ① 主参数真源 | 标定/配置 json 的一个命名块 | 全部可调系数 + `enabled` | 改 `enabled=false` |
| ② 画布节点参数 | `nodes[].params.<开关>` (+ 临时覆盖字典) | on/off + 现场覆盖 | 置 `off` |
| ③ 输出端口 | `out1.<功能名>` | 生效标志 + 各分量 + 参数来源 | 同② |
| ④ 数据总线 | 信号注册表 → live 文件 | `功能名.*` 数个信号，live 有真值 | 不注入即不发 |

判据要**逐层回读真值**（真源 json 解析出的数、live 文件里那几个键的实际值），不是找关键词。

🔴 **真源缺参数时不许填默认值**：兜底默认会让标定真源形同虚设 —— 标定改了没生效也看不出来。
正确形态是返回 `{injected:false, reason:"真源未标定 X ⇒ 不注入(不填默认值)"}`，用户一眼能看出是缺标定而不是算法坏了。

🔴 **纯函数与参数读取必须拆开**：算法模块保持「不读写文件、不 import 中间件」的纯函数契约（离线/真机/仿真三处共用），
参数读取单独一个 `*_cfg.py`（只读 json + mtime 失效缓存，现场改标定不用重启常驻进程）。

🔴 **同一真源里两个度规/权重块并列是设计，不是冗余**：命名要能看出各自管什么（如 `metric`=状态怎么走 / `inject`=动作往哪修）。
汇报时说清这两层次比堆功能列表有用 —— 这是「统一思想系统」的具体落点。

🔴 **软链仓库的提交坑**：`config/` 若是软链，`git add config/...` 直接报
`fatal: pathspec ... is beyond a symbolic link` 并**中止整批 add**（前面正在加的也白加）。
按 `readlink -f` 的真路径 add；真路径在 `.gitignore` 的 `data/` 下时用 `git add -f`（配置真源是小文件，不算大文件红线）。

**仍被术语和字段名埋掉** ⇒ 做法不是只改开头一句，而是把这条回答整个重写成不含术语的版本，

## 对外主张必须按接入等级收口 (代码在 → 能跑 → 在生产链上)

同一段实现在三类调用点出现, 可主张的强度完全不同。写专利独权 / 方案册 / 汇报前先 grep 一次:

```bash
grep -rn '<函数名>\|import <模块>' --include=*.py src tools scripts
```
- 命中在 `src/` 的常驻链 (节点 impl / 引擎 / daemon) 且被每帧或每周期调用 ⇒ 可写成「主保护 / 已上线」。
- 只命中 `tools/verify_*.py` / `tools/train_*_loop.py` / `bench_*` ⇒ **实验级**, 只能写成
  「可选加强 / 实施例 / 从属权利要求」, 不得进独权。
- 只命中定义本身 (零调用点) ⇒ 死码, 任何对外文本都不能提。

两条延伸:
- **抽象层次也要对得上**: 真链路是「直接前向、每次推理改一次」, 就不能写「ODE 每个积分步内注入」——
  改成「每个控制周期 / 每推理帧」语义仍成立且能对回实测 (步内 vs 终点叠加 34 倍)。
- **两端收益差一个数量级时, 把弱的那端放进从权是工程事实不是写作技巧**: 先说清为什么不接
  (改 vendored 上游代码每次同步被覆盖 · 钩子粒度是按样本而非按维度 · 收益低两个数量级),
  再动笔改权项 —— 先改文本后找理由, 下次一问就穿。

## 假接入的常见形态 (审计时逐个排)

1. 节点在图上但 **0 连线** → 画上去了没接线。
2. 注册了但**档位/能力清单里没有** → L4 档 ▶运行/单步永远不会调它 (只有双击才跑)。
3. 引擎/面板写着"未接入", 汇报却说"已接入" → 直接自相矛盾, 以代码为准。
4. IO 是 `NotImplementedError` 预留, 却称"输出直连硬件"。
5. 自检只测**形状/有限性** → 全零 chunk 也算通过 (必须有"非零 + 非常量 + 随观测变化"判据 + 零动作硬闸)。
6. 输入是**合成/占位数据** (npz 无渲染帧 → 造运动序列) 却当成真实感知。
7. 用**占位数值**冒充真实输出 (写死 conf 0.99 / 抄真值当检测结果) —— 老倪红线第一条。
8. **接口开着但没人调 (0 客户端的孤立服务/action)**: 服务端在、类型对、名字能列出来 —— 但**没有任何调用方**。
   实测 MoveIt 的 `/move_action` (moveit_msgs/action/MoveGroup) 与 `/execute_trajectory` 都挂着服务端，
   而 `Action clients` 均为 **0** ⇒ 这条出口是空跑的；真正的规划输出走的是 JSON 文件 + DDS 镜像。
   查法: `ros2 action list -t --include-hidden-topics` → `ros2 action info <名>` (看 clients/servers 计数)。
   ⇒ 报口径时三样都要给: **接口在哪 · 谁在真跑 · 哪条只是留着的出口**; 只说"action 有输出"就是把旁路当主线。
9. **数字/参数/能力 的"假在线" (在盘上、在跑, 却不在任何界面里)**: 真源 JSON 在盘上、站台页/技能真在用, 但从没被参数注册表扫到 ⇒ 用户在参数中心
   找不到那个数字, 得下的结论是"**没接**", 不是"没有这个参数"; 反之接进了注册表却不给 `fn_ref` ⇒
   数字→功能链动自链成参数名, 看着链上了其实点开没信息。两者都是接入层缺陷, 不是数据缺失。
   **同一个形态在能力/模型层更隐蔽**: 权重在盘上、systemd 服务 active、画布上有节点且 5 条连线、页面有按钮 ——
   但**不在界面共同读取的那份清单里** (实测 `tools/model_inventory.py` 按层 glob 固定目录收集, 不在那些目录的能力就不进清单)
   ⇒ 配置通道 / 配置中心 / 状态窗**三处一起看不见它**, 直到用户一问"还有个 X 呢"才露。
   查法: 先把"界面读哪几个真源"列出来, 再拿**磁盘 + 在跑服务 + 画布节点**三面去对; 漏了就把能力**补登记在清单侧**,
   别在三个界面上各打一块补丁 (补了还是会各自漂移)。

12. **"看得见在动" ≠ "驱动了执行器" (可视化链完整, 执行链断在出口)**: 力/动作/策略输出**有值、在刷新、
   还进了波形与表格**, 但它的消费者只有显示层/文件/DDS 话题/共享内存 —— 没有任何进程把它变成执行器指令。
   判据三问, 按顺序答: ① **谁产出** (真源文件/话题) ② **谁消费** (grep 该文件/话题的读者, 是否只有画布/报表/探针;
   再 grep 执行器侧有没有读它) ③ **末端真值有没有动** (执行器侧位姿/状态的 mtime 与帧龄 —— 停更几小时就是没被驱动)。
   佐证常直接写在源码注释里 (实测技能派发器明写"不下发任何真机指令") ⇒ 汇报前先读它, 别和它打架。
   报口径必须分两条链: **显示链通 · 执行链断**(断在哪一环、缺什么、要接上去还差什么前置条件),
   不许把"信号在动"说成"机器人在动"。

13. **算出来的覆盖值被下一句无条件赋值抹掉 (opt-in 分支 = 假接入)**: 组件声明了 opt-in 字段
    (例: 技能 `"atomic": "SK03Descend"` ⇒ 目标该由技能口给), 代码里确实调了那层算出目标、还打了成功日志,
    但紧接着一行 `t = list(pts[name]["pos"])` **无条件**覆盖 ⇒ 声明了等于没声明; 更坏的是成功日志与
    "退回原点位解析"警告**同时**打印(success 分支没 return/else) ⇒ 日志看着像"两条路都走过", 只有数字能拆穿。
    判定法: 绕开 GUI/日志, **直接 import 那层函数比输出** —— 期望 = 点位 + 声明偏置, 实测 = 点位本身 ⇒ 被覆盖。
    修法: 用 `_hit` 标志 + `if not _hit:` 落回默认, 成功/失败日志放互斥分支。
    推广: 任何"先按新规则算、再按旧规则兜底"的写法, 兜底那一行必须**条件化**; 否则新规则永远是死代码。
14. **`--auto` / `--watch` 只在启动时解一次源 (daemon 假跟随)**: 常驻 watcher 在进循环**之前**读一次配置
    (实测读闸门文件里的当前段), 之后每拍只刷真值 ⇒ 源变了目标不跟, 输出文件里永远写着启动那一刻的段。
    判定法: 改源文件后 3 拍内输出必须变(不是"重启后才对")。修法: 每拍重解 + 值变了重算并打一行切换日志。
    推广: 任何带 `--auto/--follow/--from-<源>` 的常驻进程, 都要问一句"它每拍真的重读源么"。

15. **判据在函数上绿、界面在另一条取数点上红 (假绿)**: 给某张表的取数函数加了过滤就断言"页面只剩 L2",
    而控件实际填充走的是**另一个**取数点 ⇒ 判据全绿、用户屏幕上仍是全层。**判据要读控件渲染出来的行**
    (`item(r,c).text()` / `topLevelItem(j).text(0)`), 或对在役窗口截图 + OCR 交叉验证; 只断言函数返回值等于没验界面。
    推广: 一个"只保留 X"的口径, 先 `grep -n 'setRowCount\|addTopLevelItem\|insertRow'` 把所有填充点列全,
    逐个确认它取的是过滤后的数据; 面板上的分组统计 ("L5 12 · L4 30 · L3 6") 与按钮上的计数也要一起改,
    否则用户第一眼看到的还是别的层。

16. **改完还要读同一窗口的状态条与告警条**: 表对了不代表面板对了。实测 `SK 位姿全无值` 的 fail 级告警在源没跑时
    属于正常态, 用户会当故障读 ⇒ 正常态降级成 info 或只在技能在跑时判; 汇报时说明这是"源未运行"而非缺陷。
17. **显示层把「缓存/轨迹里的数」当成「本次运行输出」**: 表/图上每一层都有非零的力/动作值, 但当时只跑了一层 ——
   那些数是录制 episode 里的数组 (`u_ff_vec` / `u_limit_vec` / `prior_vec` …) 按帧号取出来的, 与本次调用无关。
   最硬的反证: 该层的**调用台账** (每层 ok/耗时的那份 jsonl) 帧龄几十小时, 而面板还在动 ⇒ 显示的不是调用证据。
   修法三段 (缺一段就还是假接入):
   ① **运行态与能力档位写进同一份 run 真源** (如 `ui_run.json` 里同时有 `running` 与 `cap_level`, 档位取画布档位节点而非默认值);
   ② **每个显示层按档位闸**: 档位 = 跑到第几层 (L2 < L3 < L4 < L5), 未启用的层格子置空并写明
      「缺 L4: 本次未调用 (档位 L2)」, 不许留旧数; 合力量随之只剩启用层;
   ③ **主力/高亮层随档位回落**: 加权系数让 L4 当主力, 但档位没跑到 L4 ⇒ 主力必须是 L2, 箭头/表盘/四元数行一起改,
      不许出现「表说主力是 L4, 图里只有 L2 一条力」。
   顺带把口径名字也改: 叫「势场分解」就别让人读成「这次真跑出来的输出」。

19. **分层力/四元数: 每层读它自己的模型输出, 不是一套解析场换四个名字**。用户给的分层口径是
   L2=前馈 u_ff · L3=动作头 action · L4=流形引擎张量 · L5=VL 场景理解 ⇒ 实现上**每层一个取数路径 + 一条 src 字符串**
   (写明 `文件.字段[帧号]`), 表/图/悬停卡都显示 src, "哪层真在算"才能逐格对账。三条硬规矩:
   ① **缺层不许回填**: 某层真源取不到 ⇒ 该格 `mag=None` + `src="缺 L5: <具体缺什么>"`, 不许留上一段 episode 的数组。
      实现顺序也要对: **先铺回退源 → 再叠权威源 → 最后把缺的层显式清空**; 反过来就会出现"标着缺、数还在"
      (典型 bug: 只对 `vec is not None` 的层 `cells.update()`, 缺的层就保留了回退值)。
   ② **权重与单位换算放配置文件** (`config/calib/<层>.json`: w / k / m_ref), 热生效; 加权在**矢量层**做一次,
      表/箭头/S³ 面板共用同一份结果 —— 别在四个绘制点各乘一次 (口径一定漂)。
   ③ **主力 = 最终显示值的模长最大那层** (前馈默认最重), 要能给出算术; 用户问"这层凭什么是主力"时, 答数字与权重, 不答字母。
      🔴 **选主力与画格子必须是同一份数**: 实测两套口径并存 —— 主力取 `layer_forces()` 里加权后的 argmax,
      而格子 `mag` 又是过完 `|F|=G·M/r²` 重算的值 ⇒ 高亮落在 L3、数字最大却在 L2, 用户一句"高亮跟数对不上"就穿。
      修法 = 在**最终格子上** argmax 再高亮, 构造意图 (α / 权重) 只留痕不覆盖数值; 判据也改成断言这条同源关系。
      判据脚本里同名标签 (两条都叫 W1) 会让报告认错对象 —— 同轮就把后来那条改名 (`W1b`)。
   四元数是**显示编码** (`q=(|F|/u_ref, Fx/u_ref, …)` 不归一; 归一后才是 S³ 上的方向), 汇报里别把它说成姿态或模型张量;
   姿态没有真源时明说"显示的是力/方向四元数"。
   ④ 🔴 **"复制层"判据 = 原始矢量逐位比例恒等于同一个常数**: 某层自称独立张量 (如 `F_L4 = M̂·u_ff`),
      就把它与源层的**原始矢量**(未加权) 逐分量相除 —— 比值全等于同一个数 (实测 `[0.55,0.55,0.55]` ≡ w_L4、
      原始模长 0.017583 与源层完全相同) ⇒ 它只是源层乘常数, **没有独立信息量**, 界面上写着"某引擎力"就名不副实。
      最常见根因: `M̂ = metric_M / m_ref` 而这两个量读的是**同一个配置常量** ⇒ 恒等于 1.0; 且 `metric_M`
      来自 `config/calib/*.json` 而不是引擎现算。修法二选一: 让该层真出张量, 或在格子/悬停卡写
      "= 前馈×1.0 (M̂≡1, 未独立)" —— 两个都不做就是把加权系数当物理层。
   ⑤ 🔴 **三层字段一眼判"真不真", 汇报按这四项分开说**: ① 每层 `src` 里的 `文件.字段` + 该文件 mtime/`fresh`
      (帧龄 16h 的层还在参与合力 = 陈旧数冒充实时, 属"缺层"性质, 要剔出合力或显式标注, 不许参与 argmax);
      🔴 **`age_s` 不许在取数函数里被硬编码成 `None`** —— 那样页脚永远不显示帧龄, "陈旧"在界面上完全不可见
      (实测: L5 源 16.1h、`fresh=False`、值照旧参与合力, 而显示层的 `age_s` 被写死 `None`)。
      判据 = 取数回**真** `age_s`(`now - 源 mtime`), 超 `max_age_s` 即清空该层并标「缺 Lx: 源陈旧 N h」(同 #19①);
      ② 度量/张量类看 `model_tensor` / `tensor_src` —— 为 None ⇒ 没有模型张量参与, 数是配置常量造的;
      ③ "模型跑了" ≠ "吃的是实时": `provider=traj` + `source="真实 episode …npz"` ⇒ 每拍**真前向**但输入是
      **录制回放**的观测; ④ 每层调用台账的 mtime (=最后真调用时刻), 几百 MB 的台账停更几天就是"这栏不是今天的"。
      正确口径 = 「L2 真模型真算 · L3 真算 · L4 是 L2 的复制 · L5 陈旧 N 小时 · 输入是回放而非现场」,
      不许用一句"是真实力"或"都是假的"拍死整块面板。

20. **改了语义, 判据里写死的旧语义会集体假红/假绿 —— 同一轮一起改**。换口径后必然有判据仍假设旧世界
   (实例: "α>1 ⇒ 主力 L4"、"火星不该亮因为没推理"、"四层永远都有值"、"两个窗口各读一次必须逐位相等")。
   三条处理: ① 每条红先问"是回归还是判据的旧世界", 拿 `git stash`/旧 rev 对照再动手;
   ② 假设失效的**换目标/换断言** (L5 无真源 ⇒ 断言"要么有值、要么明确标缺"), 不是放宽阈值;
      同理, **模型体检类判据 (画面/状态敏感度) 单独成条, 该红就红着报**: 图像余弦实测 0.998 时把线从 0.995 抬到 0.99 换绿,
      等于把"欠训练"包装成"图像支路生效"; 正确结论是「接线全绿 · 该权重画面盲 ⇒ 图像那条路换回 INTACT 或重训」。
   ③ 跨窗口一致性判据改容差或共读快照 —— 两处各自 reload 必然差一拍 (实测方向余弦差 ~0.05), 让两边读同一实例才谈逐位相等。
   改完在汇报里点名哪几条判据换了口径、为什么换。

18. **门控只加在「画」上, 没加在「算」上 (未运行仍有力方向变化)**: 未运行时代码 `return` 掉绘制, 但数据对象
   每拍仍在重算 (后台 10Hz 的引擎/回放文件一直写), 于是表里的数、下一个消费者拿到的缓存仍在变;
   相位/虚线流动/呼吸也照常在 `_tick` 里推进 ⇒ 画面「静止」只是没画箭头而已。
   判据: ① 未运行时该对象的重算入口必须整段跳过 (保留上次值并标「未运行/⏸ 定格」), 不是只跳绘制;
   ② 两帧像素差留收敛容差 (文字块低通收敛 0.3% 属正常, 阈值取 0.5%); ③ 运行后同一判据反向必须变。
   三处都要有: 力/数值 · 姿态轴/表盘 · 动画相位。

22. **"有线但没跑" / "跑了但没读到" —— 拓扑、调度、消费代码三层各自都能断**: 用户要"把 A 真的接进 B"时,
    只加一条连线就交 ⇒ 三成假接入里最容易中的两种:
    ① **调度断**: 连线在拓扑里, 但常驻循环只跑白名单节点 (`ZMAX_CANVAS_ONLY=...`) ⇒ B 那一拍根本没 step,
       现象是"图上连着、下游一点都不认";
    ② **消费断**: B 的外壳 `compute()` 先 `if not PURE: return _passthrough(ctx)` 才轮到实现 ⇒
       实现里读 `ctx['in1']` 永远读不到, 日志/轨迹只显示"直通"。
    取证三样一起看 (缺一样就不能说接上了): `canvas_loop.json` 的 `only/n_ran/traces[].status` ·
    下游落盘产物的 `age` · 消费端自报的"驱动源"字段 (例: 页面 `ARCMD.drv` 变成下游节点名)。
    反向证据同样要给: 边界没越 — 如仍在"真机零指令"时下发 FIFO 的 mtime 未变、授权开关未被代写。
    具体接线与消费代码的落法见 `state-space-canvas-engineering` 的"让 A 真的喂 B = 三件套"。

24. **层计数器只记 `ok/src/ms` ⇒ "跑起来了"不等于"检出了"**: 检测层 0 检出时 `ok=True` 照样成立,
    拿它汇报"L2 已接入并在检测"是假证。判据必须落到**条数**: 把 `len(det)` 同时写进 trace 和一份
    外发 json (`/dev/shm/<layer>_det.json`), 0 就是 0。合格口径是一次给两样:
    `n=1 · 帧龄 0.1s · 权重名`; 只有 `ok=True` 单列不算。外发那份顺带解决第二件事 ——
    下游画布节点**复用这次推理**即可, 不必 `PURE=True` 自己再加载一份权重 (8G 显存里两份模型互挤)。

🔴 **判"接口/节点不存在"之前先核 ROS 域**：域不对会让存在的实体**全部凭空消失** (假阴性)。
实测同一个容器里 `ROS_DOMAIN_ID=42`，在默认域 0 下扫也是"空"，结论"没有 action"完全错。
凡是要下"不存在/没接"的结论，先 `echo $ROS_DOMAIN_ID` 对齐域；**action 类话题还默认隐藏，
必须加 `--include-hidden-topics`**，否则拿 `ros2 topic list` 的反面结论同样不可信。

21. **占位节点回显参数 = 最隐蔽的假接入**: 节点把 `d_z1/d_z2/d_z3` 当结果打印出来 (`H-JEPA: z₁=… z₂=…`)
   并 `return True` ⇒ 画布永远绿、日志永远有值, 但**一个权重都没加载、一次前向都没跑**。它的兄弟节点 (`zFlow`/`CrossAttn`)
   往往是同一写法, 所以"同组都绿"不是证据。判定只看函数体有没有 `torch.load`/权重路径/前向调用, 不看 return 文案。
   另: **节点参数里的维度是那一版训练脚本的值, 以权重为准** (实测节点写 128/128/64, 反推权重是 256/256/128)。
   修法三档降级: ①引擎在跑 ⇒ 回读引擎那一路的真值 ②否则自己加载权重跑一次 ③都没有 ⇒ `return False` + 写明缺什么。
   裸权重 (无对应训练脚本) 怎么反推结构、怎么体检、怎么接成潜通道: `references/weights-without-source-and-latent-channel.md`。

23. **同一能力有两个载体: 画布节点是壳, 真推理在常驻服务的内置 worker**。用户问"X 节点真的接入这个场景了么",
   三样一起答, 别只查一边:
   ① **画布节点**: `PURE=False` ⇒ `compute()` 只 `_passthrough`; 再加不在 `ZMAX_CANVAS_ONLY` 白名单 ⇒ 既不推理也不在链上。
   此时连线齐全是**声明**, 不是数据流 (节点入端口的源节点也不在白名单 ⇒ 端口上没值)。
   ② **真载体**: `grep -n 'Thread(target=_\w*worker'` 找常驻服务里起的后台线程; 取证两件 =
   **落盘 Hz**(对产物 `st_mtime` 每 0.1s 采样 10~15s 数变化) + **`py-spy dump --pid <svc> | grep <worker>` 抓到栈**。
   🔴 线程名不可靠: `/proc/<pid>/task/*/comm` 常全是 `python`, 拿它"没看到 worker 线程"下结论是假阴性。
   ③ **权重与页面取数点**: `readlink -f models/<在役权量>` 看清是哪一版权重; 页面 fetch 的那个 `/api/...`
   回读 `ok / age_s / stale / err` —— `ok=false` 且 err 写"没检出"时, 链是通的、模型是漏检, 两件事分开报。
   结论句: 「X 在场景里真跑(Hz + 栈 + 权重), 但**不是**画布那个节点在跑 —— 节点是壳」; 不许用"节点已接入"糊过去。
   要把壳改成真接入时 **别 `PURE=True` 自己再加载一份权重** (8G 显存要抢、相机 UVC 单占要 EBUSY):
   让实现**复用 worker 的产物文件**, 再 `PURE=True` + 加白名单 + 输出端口接下游, 这样节点上是真数据且不重复推理。

   变体: **闸/约束类节点在画布上直通, 真闸在引擎关键路径里内联** (实例: 动力学约束 `ssphys` 画布 `PURE=False`,
   而每拍真跑的 `InertiaLimiter` 在 `engine/runtime.py` · `engine/sim.py`). 取证不看 `PURE`, 看闸自己落的真值文件里
   `gate_n = {node, kin, dyn}` **三计数逐位相等且随时间增长**; 再读 `u_in` vs `u_out`(相等=本拍没削)与各类削因计数。
   答"这个节点干什么"时把**物理上限的真源文件**一起给(速度/加速度/加加速度/行程/力/质量/质量变化率按技能分别存标定文件),
   并说明"改段表或改速度没用, 闸会按标定削回去" —— 没有这句, 用户会以为提速只需要改数字。

   变体之二: **原子技能节点的输出是两个口, 报"技能输出什么"必须两口分开**:
   `out1 = skill_act`(目标点 mm + 请求速度 4 维 `[vx,vy,vz,夹爪]` + stage/active) → 运动规划;
   `out2 = skill_gate`(`f_need_N` · `u_gate` · `why` 削因 · `err_mm` · `saturated`) → 物理闸。
   技能**不出轨迹也不出力矩** —— 轨迹由规划段表给、力矩由执行器给、限幅由闸给。
   每段的物理包络 (v 上限 / 质量 / 力上限) 逐段不同 (抓取与插入的质量最大、插入/完成的 F 最小), 报数值必须按段读标定表,
   不许用同一个数套八个技能。
   🔴 **每段指标产物里的 `-1.0` / `-1` 是「本轮未执行该段」哨兵, 不是 0 也不是失败**: 实测 `skill_latest.json`
   只有在职那一段有真值 (其余 `mps=-1.0 · 拍=-1`), 与"0 速度 / 没接线"在字面上完全不像 ——
   报"各段速度"时要写明哪几段本轮没跑到, 别把 -1 当 0 参与均值或判据。

25. **恒等函数/空转节点: 占着位置不干活, 但删不得**: `def execute(self, u): return np.asarray(u)` 这类
    "看着在链路上"的一环, 实测进→出逐位相同、直接调连对象都是同一个(没做任何处理)。它不产生语义, 却常撑着四处引用:
    画布 `params.source_symbol`(右键打开源代码锚点) · `_EXTERNAL_LOC[<key>]` · 验证判据(名字往往就叫
    `t_act_pass`/指令透传) · registry docstring。直接删 = 锚点悬空 + 判据红 + 画布参数指向不存在的符号。
    处置: **不删, 让它干真活, 但先保证数值零回归**(零回归就不需要对照实验)。执行器类缺的正是它本该做的事:
    ① NaN/Inf 拦截(脏数归零 + `valid=False`) ② 通道范围**只记不裁**(裁剪权留在上游安全边界, 不越权)
    ③ 变化率超限(`|u−u_prev|>rate` 记为异常信号, 不是误差)。
    三条纪律: (a) **NaN 归零后不要再算变化率** —— 否则"归零"本身会被误报成轴跳变;
    (b) 校验结论必须进返回值/日志(如 `out1.exec_check`), 只写进实例属性等于没做;
    (c) 验零回归用**原有判据重跑**(它本来只断言 shape+finite), 不许把数值改动混进来。
    一句话: 空壳的价值在"接口位", 不在"恒等式" —— 要么给它物理意义, 要么删掉并同步四处锚点; 两者都不做是最坏的。

26. **动态加载的模块断点不绑定 (断点不停≠代码没跑)**: 加载器必须 `spec_from_file_location` +
    `module_from_spec` + `exec_module` **并注册 `sys.modules`** —— pydevd 按模块名回查文件来绑断点,
    不注册则**该文件里所有断点全废**, 而函数照跑、日志照打、界面不报错。判据一行:
    `mod.__spec__ is not None and mod.__name__ in sys.modules`。
    🔴 `exec(compile(...))` 造的模块 `__spec__/__loader__` 都是 None: **首次**按 co_filename 能绑,
    **取消断点再添加就静默失效**(pydevd 要靠 loader 重新定位文件) ⇒ exec 只能当降级路径且必须打可读告警。
    🔴 **一个仓库里常有多个加载器**: 引擎侧 `_load()` 修好了不代表节点侧 `_ss_import()` 也修了;
    更隐蔽的是某个被 spec 加载的**单个文件**漏了注册(实测流形引擎两处加载器都没注册, 该文件断点全废),
    而旁边的模块一直有注册 ⇒ 只按“加载方式”抽查会漏。
    `grep -rn "spec_from_file_location\|exec(compile" src/ tools/` 全列, 逐个确认有 `sys.modules[名] = 模块`。
    第二层原因同在: 同一文件名在 `src/` · `external/` · `staging_*/` 下可能有 **3 份副本**, 断点打在副本上
    永远不命中 ⇒ 先 `find . -name <file>.py` 列出全部, 用 `fn.__code__.co_filename == os.path.realpath(真身)`
    逐字比对, 并确认模块 `__spec__ is None`(exec 加载)。
    第三层: **三套入口的断点位置不同**, 各打一个就能看出用户走的是哪条链:
    ① `▶运行(真实化)` 走引擎 `RealStateSpaceSim` → 打 `engine/runtime.py` 的**调用点**;
    ② GUI 右键「运行节点」→ `_state_space_run_node` → `node_logic.execute_node_logic` → 注册函数,
    这条是**真调用** (打 `nodes/*_impl.py` 的 `run(ctx)` 能停);
    ③ GUI `⏭单步` **不重新调用节点函数** —— 它先 `_ss_ensure_trace()` 跑完整条引擎轨迹(有缓存,
    `force=False` 时直接复用), 之后逐节点只打印轨迹里该节点的 I/O 快照 ⇒ 在 `run()` 里打断点、点 ⏭单步
    可能一次都不停, **别据此判“代码没跑到”**; 要真跑要么点右键运行节点、要么 `_ss_ensure_trace(force=True)`;
    ④ 常驻循环/无头探针走中间件 `prj.step(only=[...])`, 那才是真 step 节点壳。
    🔴 GUI 右键那条把 `execute_node_logic` 包在 `try/except: pass` 里 —— 节点实现抛异常时界面**零提示**,
    “点了没反应”先给这个 except 加一行可读日志, 不然会在“断点是不是没绑”上白转几轮。
    🔴 **第四层 (最便宜, 先查): env 根本没进进程**。
    `tr '\0' '\n' < /proc/<调试进程pid>/environ | grep -E 'ZMAX_|OMP_|TORCH_'` 为空
    ⇒ launch.json 的 `env` 没生效(编辑器用缓存旧配置), 一切靠 env 的断点开关一次都没打开 ——
    此时“断点不进”与代码路径、加载器全都无关。修 = `Developer: Reload Window` + 重启调试;
    别靠读 launch.json 文件“确认已配置”, 文件对 ≠ 进程里有。同层还有一条: `ps -o lstart= -p <pid>`
    与改过的文件 `stat -c %y` 比 —— 进程早于改码就是跑旧代码(Python 不热加载)。
    🔴 **不要用代码内置断点做兜底**(内置 `brk(tag)` 命中就调 `breakpoint()`): 它会和用户自己打的红点抢,
    而且停住时 **Qt 事件循环停转** (py-sty 现场 `wait → _do_wait_suspend`) ⇒ 画布点不动、**新断点也点不了**,
    用户只能先杀进程。用户明确要求“不要干扰我 debug”——已经埋进去的要**全部删除**,
    光把默认改成“只记录不停”不够(日志还在刷就等于还在干扰)。要单步看变量用**独立命令行 pdb 入口**
    (`python -m pdb -c "b <file>:<line>" -c c tools/dbg_x.py <节点id>`), 不碰 GUI 进程、不影响已打的断点。
    🔴 **断点能不能停, 按这四层从上到下排**(任何一层不满足都静默不命中):
    ① 代码有没执行 —— 用**记账文件**判(函数首行 append 时间/pid/参数), 不用断点判;
       缓存/队列会让整段逻辑这一拍不跑 (实测动作队列 `n_action_steps=7` ⇒ 一次推理管 7 拍, 只看断点像“永远不进”);
    ② 这一行是不是可执行语句 —— `def` 签名行 / docstring 行 / `return` 行**都绑不上**
       (实测同文件: 1186 def 不进、1188 docstring 不进、1200 赋值能停、1302 方法调用能停、1303 `return rec` 不停);
    ③ 模块绑没绑 (见 26); ④ 进程对不对 —— 代码可能跑在**常驻服务进程**, 断点打在 F5 起的 GUI 进程
       (判据: 记账文件里的 pid 与调试进程 pid 不同; `py-spy dump` 看到主线程在画界面)。想停就得让调试进程
       成为唯一执行者, 且调试模式启动后**自动跑一次引擎** —— 否则“没有代码在跑”, 红点无处可停。
    🔴 **绝不拿中文节点名做子串匹配**: `"actuator" in "🤖 机器人执行器"` 恒为 False —— 开关看着设了、
    其实永不命中, 还会让你误判“代码没跑到”。要打 tag 就用英文短名且每层一个;
    被按路径动态加载的模块里要**内联实现** (从上层包 import 会成环)。
    第五层: 自写 `sys.settrace` 行追踪会**覆盖 debugpy 的 tracer** ⇒ 断点全不命中;
    这类 tracer 必须先判 `debugpy.is_client_connected()` 为真就直接调目标函数、不做 settrace。

### 让 GUI 调试进程真单线程 (除显示层外)

用户要求“除了显示的 GUI, 所有节点都单线程运行”时, **三层一起做**, 只设 env 只覆盖第一层:

1. **BLAS 层 (只能在解释器早期设)**: `OMP/MKL/OPENBLAS/NUMEXPR/VECLIB/TORCH_NUM_THREADS=1` +
   `MALLOC_ARENA_MAX=2`, 必须在**任何 numpy/torch 导入之前**写进 `os.environ`; 事后
   `torch.set_num_threads()` 改不了 OpenBLAS/MKL 已建的线程池。把这段兜底放在 GUI 脚本顶部,
   桌面双击与调试器启动就同口径 —— 不依赖 launch 配置是否真的生效。
2. **运行期线程池**: `torch.set_num_threads(1)` + `set_num_interop_threads(1)` + `cv2.setNumThreads(1)`
   (env 只管首次初始化, 已有实例必须 set)。做成幂等 `enforce()` 挂在节点注册模块的模块级 ——
   一处覆盖全部节点, 并**返回实测值**(`torch.get_num_threads()`/`cv2.getNumThreads()`) 而不是声称。
3. **节点自己起的线程**: `grep -rn "ThreadPoolExecutor\|threading.Thread\|multiprocessing" nodes/ manifold/ middleware/`。
   推理/重活的异步封装 (如 `infer_async` 起 `*-worker`) 在单线程模式必须走**同步分支**,
   否则“人在主线程停住、算在别处跑”, 单步与断点同时失效; 输出里标 `mode="sync"` 让下游看出这拍是真算还是回放。

验收: `torch.get_num_threads()==1` 且 `threading.current_thread() is threading.main_thread()` 为真。
**口径**: GUI 的 Qt 线程仍在, 所以 `/proc/<pid>/task` 总数不会是 1 —— 判“节点是否单线程”看**计算线程**,
不看进程线程总数; 第三方库自带的监视线程 (如 tqdm) 也不算。留逃生口 `ZMAX_MULTI_THREAD=1`
(跑基准/批量推理), 不做静默切换。

27. **"每节点都能单步" ≠ "每节点都真算" —— 报两个数**:
```python
prj = load_project()
for nid in list(prj.nodes.keys()):
    t = prj.step(only=[nid])[0]      # status: 实现执行 / 直通 (PURE=False: 只走数据面) / 异常
```
    同一声明周期里报: 实现执行 N · 直通 M · 异常 0 · >200ms 慢节点(首次加载权量会到秒级)。
    真算取决于 `params.pure_verified` **且**实现返回 dict。
    🔴 **壳会把业务字字典过滤成空**: 生成器模板 `{k:v for k,v in res.items() if k in PORTS_OUT}` ——
    实现返回 `{M, ok, progress}` 这类业务键(不含 `out1/out2`) 就被滤光, 下游永远拿 None;
    兜底 = 一个端口名都没命中时**整块当首端口值发出**。

28. **`PURE=True` 不是充分条件: 实现还会被三处卡死 (返回 bool / 内部抛异常 / 模型侧硬闸)**。
    审计“X 用上了没有”时, `PURE` 只是第一道; 逐层给证: ① `PURE` 现在是什么 (恒 False / env 开关);
    ② `compute()` 里 `fn(_mctx)` 的**返回值类型** —— 实现 `return True/False` 会被壳当“非 dict”而走直通,
    必须返回业务字典; ③ 实现内部抛异常时壳会把它降成“实现异常 → 直通”, 看起来和“没接”一模一样,
    所以要把 `status` 与 `out1` 的真内容一起报 (out1 里是产品块/入参回显 = 它根本没算)。
    🔴 **`status=实现执行` 不能当成功证据 —— 端口可能全是 null**。实现返回的 dict 里端口键都在、
    但值全 `None` 时, 壳照样标「实现执行」。所以 `status` 只能证明“壳调了实现且回的是 dict”,
    **不能证明算出了东西**。判据必须三项齐: 端口值**是不是那块数据** · **是不是 None** · **是不是上游透传值**
    (开闸前后 `out2` 从“上游 payload”变成“自己算的 u_ff”才是真生效)。
    实测代价: 一版 A/B 报出的 64.3ms 全来自这个失败分支(内部异常已兜底成 null 端口), 拆穿后同对比是 51.9ms。
    ⇒ 报 A/B 前先确认两侧端口值**不同类**, 只比耗时等于把失败当性能。
    🔴 **numpy 对象进返回 dict 会连炸两层, 而且错误文案指错地方**: ① 直接放 `float32` 报
    “不可 JSON 序列化”; ② 加 `default=float` 后对 **ndarray** 报 `only 0-dimensional arrays can be
    converted to Python scalars` ⇒ 壳 step 抛异常、整节点作废。转换必须按类型分流:
    `ndarray→tolist()` · `np.generic→item()` · 其他 `float()` · 兜底 `str()`; 别用 `default=float` 一把梭。
    模型体检类 dict (`probe`/`stats`/`debug`) 最容易带 numpy —— 往外抛之前统一转一遍。
    🔴 **还有一种完全不报错的丢字段: 拿 `isinstance(x, list)` 当类型闸, ndarray 被静默判成「没有」**: 实现算出
    `np.round(np.diag(M)[:4],3)` 再写 `[float(v) for v in (x if isinstance(x,(list,)) else [])]` ⇒ 端口里那个字段
    **恒为空数组**，而日志/print 显示的是非空数值，无异常、`status` 照样「实现执行」。判据: 把节点 `out1` **原样打印**，
    任何「日志里有值、端口里是空」的字段都按这条查；转换统一 `np.asarray(x).ravel().tolist()`，别用 `isinstance(..., list)` 当闸。
    🔴 **报节点耗时必须标冷启/热态**: 同一节点首调含模块导入 3373ms、稳态 0.37ms —— 两个数混用既会把「能进拍」说成
    「太慢进不去」，也会掩盖真实每拍开销；`prj.step(only=[…])` 的单次读数默认就是冷启。
    🔴 **模型侧硬闸是第三层, 而且它会拒绝而不是降级**: ckpt 训练时开了额外通道 (实例: skill 通道),
    推理时缺那路输入就 `raise ValueError("checkpoint was trained with a … but … was not provided")` ⇒
    节点整体失效。正解是**构造那个侧通道**(实测 24 维: 阶段 one-hot + 控制量, 宁缺的 L2 场分量留 0 不伪造),
    不是关闸、不是放宽、也不是回到直通。
    取证顺序: 先**绕开节点直接调策略入口** (`service.run_once(...)` / `model(x)`) 跑通一次并贴 chunk/u_ff 真值,
    再回节点跑一次对同样的字段, 两处一致才算接上。
    开 PURE 必须**同时给反向开关** (env) 并默认安全值, 且要报**两个耗时**: 冷启(加载权重) 与稳态单次 ——
    实测 INTACT 冷启 9.7s / 热态 32ms (可以每拍跑), SmolVLA L3 冷启 22.7s / 878ms (10Hz 塞不进, 只能交周期异步)。
    这两个数决定“能不能进默认档”, 不带它们上就是拍脑袋。
    口径: 即使模型真跑了, 也要单独报**它的输出有没有下游消费者** —— 实例: 意图解码的 `l4_cond` 192 维真值
    到达 L3 端口, 但 L3 ckpt 未训该通道 ⇒ `l4_cond_injected=false`, 对动作数值无因果贡献, 只能说“到位未生效”。

29. **记忆层“接上了”但没改动作 / 改的是显示 (三种假生效 + 假节拍)**: 记忆类节点最容易“图上有、台账有、数字好看”，
   四条判据逐条过，缺一条就是没接:
   ① **在不在每拍核心链** —— 回路分两条道: `CORE_IDS`（每拍）+ 全量拍（每 `FULL_EVERY` 拍），`canvas_loop.json` 的 `traces`
      里**没有**它就是画上看；只在全量拍出现的按 1/N 拍报，别写成每拍; 旧 `ZMAX_CANVAS_ONLY` 白名单已不是判据;
   ② **`PURE`** —— False 只直通（trace 写“直通(PURE=False)”)；**`IMPL_KEY` 漂移**会让壳跑别的节点的实现
      (实测 L4 记忆节点指到 `ss_world` → 跑的是执行节点)；实现 `return True` 会被当“非 dict”再过滤一次 ⇒ 要 return 业务 dict;
   ③ **记忆真的进了动作**: 看规划节点的输出字段本身（例 `seg_t_eff ≠ seg_t_raw`、时间轴随记忆变），
      而不只看 feed/台账在刷新 —— 记忆读到但规划不用，等于只接了显示;
   ④ **回路节点里不许做重活**: 大文件（几 MB 的库）必须按 `(mtime_ns,size)` 缓存、写共享记忆要节流（60s）、
      热通道 `publish` 1Hz 足够（带 `fresh` 判过期）。加节点前后对比 `canvas_loop.json` 的 `cost_ms` 与逐节点 `ms`。
   ⑤ **“要记忆的东西”必须单一真源 + 只读入口**: 技能定义/接口、工艺卡、固定点位、标杆、轨迹全部由**记忆节点**落库，
      其它节点只 `query()` 查（`query({"skill"|"card"|"point"|"champ"|"traj"})`）。写接口在代码里限定 writer 名
      (非记忆节点直接 `PermissionError`)；每条 entry 带 `src`+`sha`，改真源不重建 ⇒ 自检红。
      实测同一仓曾有三份标杆库各存一半（引擎读 `src/data/…`、节点读 `data/memory/…`、第三份 `data/…`）⇒ “库是空的”先查读的是哪份。
   ⑥ **`mm_hits=0` 三因先分后报**: 该 seed 没练过 / 读到了另一份库 / L4 干扰按设计旁路。逐条对完再说“没接管”，
      取证输出要写「该 seed 无标杆 (n=0)」而不是 ❌，否则会被当成缺陷修一轮。
   **假节拍（同族、最伤人）**: 把时间轴 `el` 放大或在段间“瞬移”来凑目标 UPH —— 前者把每段速度推过上限，
   后者靠单帧位移白拿时间（实测每圈 10 处换位缺口、合计 14.9m，凭这个能虚报 +7%）。真节拍判据 = 
   `圈墙钟 ≈ Σ 物理下限`（差 <1s）+ `tact = 墙钟/件数` + `ok` 对 `3600/uph_target` 判；换位缺口要补过渡时间。
   学习侧还要防“越练越慢”: 段被回路 tick 量化（6Hz 时每段多算 ~半拍）⇒ 先中位数去公共偏置，再缩放到 `Σt·k=Σt`，
   让记忆只决定“段间怎么分配”，一圈总长归节拍。接法与公式见 `references/memory-layer-in-loop-wiring.md`。

30. **训练/数据服务回 `ok:true` + “开始训练” ≠ 训练发生**: 回执是接口层，产物才是证据。
   判据只认盘上**当天的新文件**: 任务目录（`jobs/`）有没有 job 记录、输出目录（`<work>/<id>`）有没有 `*.splat`/`*.ckpt`，
   带字节数与 mtime（`ls -l --time-style=+%m-%d_%H:%M` / `find <out> -newermt <今天>`）。
   实测形态: 会话采集有图有帧数（真）· 提交训练有回执（真）· **任务目录根本不存在、输出目录零文件（假）** ⇒ 报“训练链空转: 只回执无产物”。
   汇报把这三层**分开列**，不许用“已有训练”一句盖住第三层的 0。

31. **学习链的采样率必须与真值同源，否则“学到了”不成立**: 声明学到动作前先量两个数 ——
   真值频率（`ros2 topic hz <话题>`，实测 `/robot/tcp_pose` ~48Hz）与采集侧频率（HTTP 快照常只有 2Hz ⇒ 丢 96% 且混叠，
   单拍位移 243mm 就是混叠的直接证据）。第二看**字段集**: 只有末端位姿、没有 joint/gripper/指令，学不出策略（只能做记录）。
   口径: 「记了图+位姿」是采集；「有 joint+gripper+commanded action 且 Hz 匹配」才是可训练的动作样本。

32. **"这个闸门/函数真在起作用么" = 三层分开答 (调用了 / 生效了 / 谁决定调用), 一层证据不能跨用**:
   ① **真调用** — 计数器对账 + **算术自证采样率**: 每条闸自报拍数并逐位相等且随拍数增长
      (`gate_n={node,kin,dyn}`, `闸_拍数==运动学闸_拍==动力学闸_拍`), 再用 `拍数 ÷ (技能数 × Hz) ≈ 服务开机时长`
      交叉验证 (实测 566754 ÷ (8×60) ≈ 1180s ≈ up 19min) —— 这条算术比任何日志都硬。
   ② **真生效** — 拿 **pre/post 值对照**, 不看 `why` 文案: 实测夹爪维 pre=1.0 / post=0.6 且 288/288 拍全中 = 真削;
      平移三维 pre 从未过 0.6 = 从没削过。同时看**上限 vs 请求**: 上限 0.35 而请求 0.12 ⇒ 该段永不触发,
      它的 `err=0` 是"没触发"而不是"通过验证", 两者汇报措辞必须不同。
   ③ **结构性空转 (最容易被报成"起作用了")** — 两条闸的上限若出自同一个公式, 后者数学上永不可能触发。
      实测 `a_max ≡ F/m` (插入 2.0/1.35=1.4815 · 抓取 12/1.28=9.375, 与实测 a_max 一字不差) ⇒ ②已把 ‖Δv‖ 压在
      `(F/m)·dt` 内, ④ `|m·Δv+v·Δm| ≤ F·dt` 必然通过 (f_need 0.0015N vs 2N = 0.076%)。
      判据 = **把限值代入算一遍**, 不等它报错; 要让它真约束必须换口径 (只判质量率项 `v·Δm`, 或力上限取伺服许用力),
      调阈值没用。同理 "加速度闸 0 次" 常是因为前一条已把它挡在外面, 属设计顺序而非缺陷 —— 但要如实报"空转"。

33. **常驻块的"在职"标记会失真 —— 一拍块只覆盖当前段往后**: 块 (H 拍) 按 `stage_idx+i` 铺段,
   `stage_idx` 之前的技能**不在本块里**, 拿的是上次轮到自己的旧拍 (`age_s` 实测 11.4s / 5.4s), 而派发器
   仍每 tick 对全部 8 个技能各调一次闸 (8×Hz)。后果与口径:
   · 报"某技能在跑"必须同时给 **`age_s` + `step`**; 只看 `在职=1` 会把陈旧值当成在干活;
   · 两份产物数字差几倍不代表两套真相 —— 先换算采样率 (实测 10Hz 画布侧 6669 vs 60Hz×8 派发侧 317256, ×48 同源);
   · 用户问「不该有个调度节点负责选一个技能么」⇒ 先回答**现在谁在决定**: 读阶段/档位字段的 `src`
     (实测 `trace_live.json.src="操作视频同源 episode … 回放"` ⇒ 阶段=回放帧进度算出来的, 没人选)。
     状态机 (`ActionModulator.advance/confirm_n`) 与编排节点存在但没接管派发 —— 缺口要这么表述,
     别回答"没有这个节点" (存在≠接管), 也别把存在当接管。

35. **节点名/desc 写的是设计意图，不是实现: 按字面字段去 `out1` 里找, 找不到就是没做**: 实例「🌍 物理世界」名与描述写
    "执行结果 → 传感器反馈 z_k → 卡尔曼校正闭环"，实测 `out1` 只有 `total_mass` + 广义质量对角（硬件常量），没有 z_k；
    唯一产 z_k 的 `observe()` 全仓只有**仿真引擎** `engine/sim.py` 调用，真实化引擎 `engine/runtime.py` 建了对象却一次没调；
    6 条下游连线里状态校正器是自己从 obs+合成触觉算 z_k（不读这个端口），其余是验证层/展示层。
    三步: ① `out1` 原样打印，逐字段对 desc 承诺的量 ② `grep -rn '<承诺字段或生产函数>'` 列**全部**调用点，分
    「仿真引擎 / 真实引擎 / 节点」三类 ③ 若实现只写共享状态 (`_SS_STATE["x"]=…`)，再 grep 它的**读**方 —— 只写无读 = 备着，不是接入。
    报法四件分开: 「每拍真跑 (ms + 在 CORE_IDS 内) · 算的是硬件参数 · desc 里的 X 闭环没实现 · 下游无消费者」——
    既不写"已接入"，也不写"假节点"（两者都是错结论）。

36. **多条连线接同一个 `in` 端口 = 后者覆盖，那条线只是“拓扑可见”**: 判“上游到底喂没喂到下游”之前先数上游条数 ——
   三个语义完全不同的上游（真下发动作命令 / 长程任务段 / 旁路状态回显）全画进 `in1` 时，总线是 last-write-wins
   （`publish` 直接覆盖同一话题），谁最后 step 谁的值生效；实测 `ssplan → n_exec → ssact` 的顺序使元任务段在下游
   step 之前就被覆盖。更彻底的一种：实现只读模块级状态，根本不读该端口 ⇒ 这条线的作用仅是“拓扑可见 + 保证端口非空”。
   🔴 **执行引擎层面就是 `ins[port] = src`** (`tools/gui/simulink_module.py::_collect_inputs`), 所以验证器判边必须取
   **任一上游非空**, 并把「N 条上游, 其中 M 条有值」单独列成告警 —— 只看最后一条会把「有信号被丢」报成「没断」。
   典型: `ssdec.in5 ← 接触流形 / 性能流形 / 潜空间` 三条, 动作头实际只吃到一条。修法优先让**下游从 `_SS_STATE` 补读**
   其余几路 (改动最小、不动画布契约), 其次才是拆成不同入端口。
   三步判定: ① 列 `links` 里 `t_port` 相同的上游有几条 ② 读 `canvas_loop.json` 的 `traces` 顺序，看谁在目标节点之前写
   ③ 实现里 `grep 'ctx.get("in1")'` 的**命中位置** —— 只在“端口为空时”被用到就不再是数据通路。
   汇报分三段: 「端口上连了几条 · 实际生效的是哪条 · 哪条只是可见」。修法 = 给旁支开独立端口（如 `in3` 只喂渲染），
   或让旁支直连真正的消费者；两条语义不同的线永远不要抢同一个口。

37. **「A 的结果进 B 了么」= 数写方/读方, 不是数连线 (一条命令定案)**: 缓存键/产物/端口都做
    `grep -rn '<key>' --include=*.py src/ tools/`, 然后**分写方/读方两类计数**。实测
    `_YOLO_CACHE["obs39_aligned"]` 是 **1 写 0 读** ⇒ 2D→3D 的自监督 3D 在整条真实链路里悬空,
    而融合节点每拍照样绿、日志照样有人话 —— 只有变量名对不上才看得出来。
    🔴 **画布连线不承载数据**: 引擎执行节点时 `ctx = {module, params, log, name, label}` —— **没有 inputs 字段**,
    上游 `out1` 只进 `LAST_OUT`(供 SU(2) 映射)。同进程内节点共享走**模块级 dict** (`_YOLO_CACHE` / `_SS_STATE` /
    `_BOX3D`), 跨进程/对外才落固定名 JSON (`zmax_data/ss_live/*.json`)。⇒「图上有连线」证明不了数据流,
    「进程内 dict」也证明不了跨进程; 两条通道分开答, 并说明这两个节点当前是不是同一个 pid
    (`systemctl is-active <两个回路名>` + `pgrep -af`)。
    🔴 **把悬空输出接上 = 新闸默认关 + 来源如实入状态**: 未证明提升不进默认档 ⇒ `ZMAX_FUSION_BOX3D=1`
    才真覆盖数值; 闸关时也要把两路偏差 (`box3d_dev_mm`) 与「认到哪一路」(`fusion_src` = `env` /
    `box3d(闸关)` / `box3d`) 写进 `_SS_STATE`, 让「接没接、差多少」可观测, 而不是靠日志猜。
    新鲜度闸必须与既有入口同口径 (`SS_ALIGN_MAX_AGE_S`, 默认 3s), 且写值的一方要**同时写时间戳**
    (`*_t`) —— 只写值不写时间, 下游只能猜新鲜度。
    🔴 **验这类节点不要跑全链**: 真机/AR 源下 `_ss_env_obs()` 会去起 metaworld env ⇒ core dump。
    单测把 `_ss_env_obs` 换成一个返回固定 39D 的假函数, 只验四态 (无值→env · 闸关→认到但不覆盖 ·
    闸开→真覆盖 · 过期→退回 env) + 39D 是否被覆盖, 四态全 PASS 才算接对。

38. **「下游节点能接到什么」= 产出字典键集 vs 消费端候选键集, 不看连线也不看 PORTS 契约**:
   ① **产出端 `PURE`**: False ⇒ `compute()` 走 `_passthrough`, `out1` 的值就是上游 `in1` 的原值,
      本节点的产物一个字节都没上总线 (它只进了进程内缓存 + 文件话题总线)。此时连线再全也没用。
   ② **下游实现到底读哪个口**: `grep -n 'ctx.get("inN")' <下游实现>` —— 端口契约写了 6 个入,
      实现可能一个都不读 (实测融合节点 in4 零命中, 只从模块级缓存取数), 那条线纯装饰。
   ③ **候选键集求交**: 读下游取数的键候选 (`_pick("in5", ("contact_p","p","score"))` 这种),
      与产出端 dict 的实际键集求交; 交集为空 ⇒ 永远取 None 回落默认值, 接等于没接
      (实测产出是 pass/verdict/defect_n/scratch…, 下游找 contact_p/p/score)。
   ④ **语义错位要单独报**: 质量判决被当「接触概率 cp」的兜底源, 键名就算对上了也是错接;
      这类写「语义错位」而不是「没接上」, 修法是把该量按它自己的名字发出去 (如 quality_score),
      不硬塞进别人的字段。
   报法三段: 契约声明的输出 · 运行时 `out1` 的真实来源 (自身产物 / 上游透传) · 下游实读端口与命中键。
   只有第三段命中非空, 才允许写"下游接得到"; 三段任一缺, 结论都是"判决在算, 但下游拿不到"。

39. **转调壳指向的文件整仓不存在 —— 注册表全绿、源码映射也全绿, 节点点了必崩**:
    `shared_runtime.py` 里成批的 `def node_xxx(ctx): """实现正文已迁出; 这只转调""" from .yyy import …`
    在"执行链外迁"后**只删了实现文件, 没删壳**。判定一条命令(别肉眼抽查):
    ```bash
    python3 - <<'PY'
    import re, os
    p='src/lerobot/middleware/nodes/impl/shared_runtime.py'; base=os.path.dirname(p)
    src=open(p,encoding='utf-8').read()
    for m in re.finditer(r'def (node_\w+)\(ctx\):\s*\n\s*"""[^"]*"""\s*\n\s*from \.(\w+) import (\w+)', src):
        fn,mod,sym=m.groups();  f=os.path.join(base,mod+'.py')
        if not os.path.exists(f): print('缺少', fn, '->', mod+'.py')
    PY
    ```
    实测 48 条完好 / **5 条悬空**(`ss_est`·`ss_correct`·`ss_world`·`sssk8`·`ss_mani_p`), 挨个直调都 `ModuleNotFoundError`。
    🔴 **`_EXTERNAL_LOC` 不是执行入口**: 文件头注释写的是"位置映射: VSCode 打开真实源码", 它只喂右键看源码,
    `_reg()` 绑的函数才被执行。所以"注册有 + `_EXTERNAL_LOC` 指到还在的文件 + 画布有节点"三者同时成立,
    节点仍然一次都跑不起来 —— 别拿这三样当可执行证据, 唯一证据是真调一次。
    🔴 **改法先分清哪一半还活着**: 引擎(`engine/runtime.py`) 往往**直接调 policies 里的类**, 不经过这些节点 ⇒
    `systemctl active`、8797 页面正常、日志有行, 全都不能证明节点可用。报口径写「引擎侧活 · 画布节点侧死(哪几个)」。
    补壳时**只补能确认算法归属的**(用同一个类、参数与引擎对齐), 命令/签名对不上的(节点 ABI 是 `run(ctx)`, 真实实现常是
    `execute(...)`) 不要硬改 —— 改错会从"响亮的 ImportError"退化成"静默直通", 更难查。
    🔴 **源码整份丢了、只剩 `__pycache__/<名>.cpython-311.pyc` 时, 按 pyc 反编译还原, 不要凭空重写**:
    接口从 pyc 里读 —— `marshal.loads(open(pyc,'rb').read()[16:])` 取 code object, 用 `co_names` / 顶层
    `co_consts` 里的 docstring 看导出符号与语义, 用 `dis.get_instructions` 逐函数看实现,
    函数签名从 `c.co_varnames[:c.co_argcount]`。⚠️ **`dis` 必须用与被编译版本相同的解释器**
    (3.11 的 pyc 拿 3.14 的 `dis` 会 `IndexError: tuple index out of range`), 用项目 venv 的 python 跑。
    实测还原后 `enabled()/enforce(log)/in_caller_thread()/brk(tag)` 四个函数语义与 pyc 一致,
    3 个原本必崩的节点当场恢复。反编译出的空函数体(`LOAD_CONST None; RETURN`)就照实保留成 no-op + 留钩子,
    别自作主张给它加阻塞逻辑 —— 这类闸模块多半是护栏, 加错会把 GUI 卡死。
    🔴 **`_reg()` 里两个 key 绑同一个函数, 不一定是绑错**: 实现常按 `if "估计" in ctx["name"]` 分流两个节点。
    先查权威映射表 `src/lerobot/engineering/l2_basic/__init__.py::NODES`
    (每项 `(节点id, 名称, key, 实现文件, 入口函数)`), 它写着同函数就是设计。
    没查就"修"的代价: 一度把 `ss_est` 改绑新建函数, 而该表在运行期覆盖回来 —— 白改, 还差点让前馈加速器跑成状态估计器。
    🔴 **实现文件"全仓零 import"是断路由的症状, 不是死代码**: `impl/ss_ff.py`(96 行, 含左脑 MLP + 解析守卫)
    没有任何地方 import 它, 因为指向它的壳转去了一个不存在的文件。补壳时优先找这类孤儿实现文件, 别新写一套。

40. **`grep 'A(\|B('` 在 BRE 下 `\(` 是字面括号, 会得出"零调用方"的假结论**: 实测据此差点把一个真实类判成死代码
    (它在引擎和两个节点里都用)。查调用方一律 `grep -E` 或直接 Python `re.search(r'%s\(' % cls)`;
    用 `ls`/`find` 出的"文件不存在"才是硬事实, 正则类的结论一律复核一遍。

节点间**交互信号**分三层(端口 / 总线信封 / 进程内共享 dict)、55D 分段表的唯一口径、单位与语义坑
(obs 是米而引导位姿是毫米 · `contact_p` 是概率不是牛顿 · `_pick` 六候选别名容错)、以及四个并存节点的
算法归属与参数来历 (状态估计=固定增益 alpha-beta 无协方差 / 前馈=逆动力学 / 测地线=最小加加速度+S²大圆 /
校正器为何必须后置) → `references/node-interaction-signal-layers.md`。
流形层 (引擎→Φ_c/V_p→接触/性能流形→`ssdec.in5`) 与记忆层四条通道 (势场叠加 / 图谱 / 总装再分发 / L2 直接赋能)
的完整拓扑、端口表与实测断点 → `references/manifold-and-memory-layer-wiring.md`。

## 端口级联通率: 真跑拓扑 ×2 拍 (静态读代码不算证)

判「这些节点之间的信号真的通了」只有一个办法: **按画布 `nodes + links` 建拓扑序, 拿真 payload 把上游
`outN` 喂进下游 `ctx[inM]`, 逐个真调实现**, 逐条边判 `OK / 空口 / 未送达 / 崩`, 最后报一个百分比。
直接跑 `scripts/verify_node_linkage_topo.py` (别每轮重写 harness)。一轮实测把 35.3% 修到 97.1%,
每一点提升都对应一个可指名的缺陷。

四条铁律, 缺一条这个数就是假的:

1. 🔴 **必须跑两拍**。图里有环 (`sslimit→n_exec→ssinnov→sssched→sslimit`), 环上的边第一拍拿不到
   上一拍的值 ⇒ 单拍会把 5 条边误报成"未送达"。第二拍拿第一拍累积的 `produced` 回灌 `ctx`。
2. 🔴 **判据是「端口值非空」**, 不是「返回了 dict」也不是 `ok=True`。`None` / `{}` / `[]` 一律算空口。
3. 🔴 **「空口」与「崩」分开报**: 崩 = 路由断了 (见 #39), 空口 = 实现了但不交结果 (见
   `references/node-interaction-signal-layers.md` 第 1 节)。修法完全不同, 合成一个数会让人追错方向。
4. 🔴 **剩下的不通要给真因, 不许写成"没接"**。实测唯一空口 `ss2d3d.out1` 的日志明写
   「本帧没有可用的 YOLO 2D 框」—— 验器进程无相机帧, 属**真值缺失**, 有帧就有输出。

🔴 **必须分层跑, 不能只跑主干**: 同一套断点在**每一层复现**。验证器加 `--nodes a,b,c` 只跑子图,
主干 / 流形 / 记忆各跑一次, 数字互不掩盖。实测主干已 97.1% 时, 流形+记忆子图 (20 节点/45 边) 只有 **20.0%**:
接触/性能流形的转调壳指向不存在的 `ss_mani_p.py`、6 个记忆节点全空、`n_calib_mani` 的输出端口全空。
按同样四类补完到 64.4%。**「上层全绿」不能外推下层**。

🔴 **「需引擎播放态」是第五种结论, 别混进 bug 里白修一轮**: 有些节点只从 `ctx["module"]._ss_tr` (GUI 播放态内存)
取轨迹, 要的是 `latent_vec` / `prior_vec` / `corrected_vec` —— 这些是**引擎运行期量**, 落盘的 `ss_traj_last.json`
只有 `obs` 与 `u_exec_vec`。于是离线验证必然返回 False 并打「无引擎轨迹 — 先点 ▶ 运行状态空间」。
判据: 先用 `_ss_frame({})` 直接试一次 —— 它能取到帧 (实测 idx=259/357) 而节点说没有 ⇒ 问题在**节点没走统一取帧入口**,
不是链路断。归类「需引擎播放态」, **不要**改成读文件、**不要**伪造 latent、**也不要**报成已通。
同理, 注册表里明写「建设中」的节点 (如 `ss_moe`) 属未实现, 不是断线。

🔴 **补端口只在实现返回 dict 时做; 返回 `bool` 说明它根本没算出东西**, 包成 `{"ok": True}` 就是编造。
工程上最省的写法是**在模块末尾重绑函数名** (importer 的 `from X import Y` 在模块整体加载后才执行,
拿到的是包过的版本), 一次覆盖同一文件里的多个节点 —— 实测 6 个记忆节点 + `n_calib_mani` 都这么补,
不动任何业务逻辑。

🔴 **验器自己的报表也会撒谎**: 一致性指标 (`skew` / `stale_keys` / `stale_ratio`) 必须基于**全部已知通道**算,
不许基于"已经进了这一帧的键"—— 后者里根本不含被拒的通道, 于是永远报 0 陈旧。实测 4 通道只有 2 个进帧,
`stale_ratio` 应为 0.50 而报表报 0。凡"过滤后再统计"的监控字段, 都要回源到过滤前的全集再算。

## 跨机旁路链 (搬运/推理消费者) 的「假活」判据

两台机之间的旁路 (A 机出图/出判决, B 机拉过来转发或自己算) 失效时表现统一:
**进程 active、循环在跑、日志有行、数据是空的**。

1. **判活只看统计口**: `ticks` / `samples` / `reach_rate` / `last_err`。`systemctl is-active` 不算通过 ——
   实测某旁路空转 1 小时 (`ticks=766` 每拍打一行启动横幅 · `samples=0` · `reach_rate=0.0`),
   从 unit 状态到日志一条异常都看不出来。`samples` 不随 `ticks` 长 = 通道没通; `last_err` 是唯一指根因的字段,
   先读它再动手。
   合法例外: `reach_rate=1.0` 而 `samples_with_count=0` = 通、但对面一直"未检"(没人触发拍照/检测);
   无产线节拍时属正常态, 别当故障去改。
2. **两类"假不可达", 都看着像对端挂了**:
   ① **不带 UA** —— `urllib` 默认 UA 会被对端 Flask 丢掉, 而 `curl` 自带 UA 所以手工测永远正常;
   请求一律带 `User-Agent: zmax-probe`。
   ② 🔴 **把 `404 尚无检测结果` 当失败** —— `urlopen()` 对 404 抛 `HTTPError`, 裸 `_get` 会记成
   「拉取失败: HTTPError」 ⇒ 整条通道被判不可达。必须 `except HTTPError as e: body = e.read()` 再解析,
   按 `_http == 404` ⇒ 判决=2 未检 (**绝不填 0 冒充 OK**)。只加 UA 常常还不通, 第二步才是真根因。
3. **发布/写总线的静默零发布**: `_load_mod()` 的返回值存进 `_s`, 下游却写 `_m.publish(...)`
   ⇒ `NameError` 被外层 `except` 吞成一句「总线不可用」, 节点每拍照样在算、**一个话题都没发出去**。
   验收不看"有没有报警告", 看**回读落盘产物数键**; 任何 `except Exception` 里的告警, 都必须能在产物上
   验证对应功能确实发生过, 否则它就是掩盖故障的噪声。
4. **跨机时间戳配准一律用「本机收到那一刻的墙钟」, 对端 header 戳只留证**: 控制器/对端时钟可与本地差几十秒
   且持续漂 (实测 86.4s)。记录里同时存 `ts_*_raw`(对端自报) 与 `ts_*_recv`(本机墙钟), 配准用后者,
   `clock_drift_ms` 单列一项当证据; 健康判据是**图-位姿 skew 的 p50** (实测 1.0ms), 不是 drift 是否为 0。
   **别为对齐去改系统时钟** —— 先看记录器是不是已经这样做了, 别把已正确的实现当缺陷修。
5. **「模型 0 检出」两步归因, 顺序不能反**: ① 先证模型没坏 —— 拿它**自己的训练/验证集**图跑, 有检出且
   conf 高 (实测 val 4/4 · conf 0.98 · 框与标注逐位吻合); ② 再证画面里确实没有 —— 读对端的在位判据
   (如 `gold_px` / `gold_cover`) 与帧统计 (`focus`、`mean`)。几个数一起塌 (`gold_px=0` · `focus 2.4`
   vs 正常 86~137 · `mean 12.9` vs 正常 p50≈63) 就是"没拍到", **不要改阈值、不要重训**。
   判据类中间产物 (渲染出的判据图/裁剪图) 在工件不在位时照样会被画出来, 它不是"在位证据"。
6. **推理型旁路必须做模型单例**: 冷启 (首次 predict 3.0~3.7s) 与热态 (13~16ms) 差两个数量级,
   每拍 `YOLO(path)` 会直接把 10Hz 循环打死。取图优先选**只读内存帧**的端点 (如 `/picture?kind=origin`
   不带 grab), 不抢相机、不触发对端检测。

领域细节 (工控机 10082/10083 端口口径、本机金手指权重的规格与实测数字) 见 `zmax-aoi-service`
(用户自有, 只读参考)。

## 「X 机器是不是已经部署完了 / 整套工程都在里面没有」—— 四面取证

用户问“那台机器部署完成了吗”时，**禁止一句“部署好了”或“已搬过去”**。工程代码在同一台机能跑 ≠ 整套系统在那台机上。
按四个面分别取证，缺任一面就是没部署完，并要补一句“因此它不能做什么”：

| 面 | 判据（全部可查） | 查法 |
|---|---|---|
| 代码 | 逐文件 hash 对齐 | 两机各跑一次 manifest（**跟随软链**）→ 按 **path** 比 hash，报 0 多余 / N 缺 / K 不同 |
| 数据/记忆/技能库 | 文件在位且**可读** | 断链普查（软链在、目标不在 = 没搬）；点位/示教点/记忆目录是重灾区 |
| 人机入口 | 端口在听 + systemd 单元在跑 + 主进程在 | 端口探活；`systemctl list-unit-files '<前缀>*'` 两机**取集合差** |
| 版本 | 目标机是 git 仓、能 pull | `git -C <root> log -1`；报 `not a git repository` ⇒ 版本面无，不可追溯 |

**入口用单元差集判，比 grep 代码有力**：单元缺席 = 这个入口从没迁过去；代码在但没人起，用户看到的就是“没部署”。
再补两条健康度：`systemctl list-units '<前缀>*' | grep -c auto-restart`（崩溃循环）与 `--state=failed`（硬失败），
两者都要进报告 —— 只报“N 个在跑”会把不健康的算成完成。

**派生数据（工程库/索引/清单）另算，别只比行数**：行数完全一致而内容不同是常态（旧 build 被整份拷过去）。
要读 `meta.built_at` + `meta.sources` 里每个真源的**指纹**，指纹不同就是源比目标新、库是旧的。
画布类结构比对要分开报 **结构**（节点数/连线数/节点 id 集合）与 **参数**（同结构但 params 不同是正常的编辑漂移）。

### 🔴 跨机对账的三种假一致（都会把“没搬”说成“搬了”）

1. **`rsync -rcn --itemize-changes` 默认不跟软链**：对软链一律输出 `skipping non-regular file`，差异一条不报。
   工程根目录大量软链到数据盘时，这条命令会给出“两台完全一致”的假结论。加 `-l`（比链接目标）/ `-L`（跟随），
   或直接用 `scripts/two_host_manifest_diff.py`（跟随软链 + 记断链 + 按 path 比 hash）。
2. **`du -sh <软链>` 报 0、`stat -c %s <软链>` 报的是链接目标字符串长度**（几十字节）⇒ 会误判“目标机仓库是空壳”
   “某关键文件只有 66B 占位”。真实体积用 `du -shL` / `realpath` 后再 du；真实大小用 `stat -L -c %s`。
3. **两份 manifest 用 `sort -k2` + `comm/join` 对账会把同一路径同时报成“只在 A”和“只在 B”**
   （comm 按**整行**排序，带 hash 的行顺序与按 path 排序不一致）⇒ 自相矛盾的结论。必须按 **path 建 dict** 再比 hash。

**连带面也要一次报清**：网络/服务不在位时，依赖它的常驻容器会在 `Restarting` 循环（`docker ps`）、
真值文件 mtime 停在某个时刻 ⇒ 报链路时同时报“哪几个容器在崩 / 真值帧龄多久”，否则用户只看到“网不通”。

## 参数/数字在线性 (「这个数字/点位在参数中心里怎么改?」)

判"某数字/点位能不能在线改"先分**真源**与**库表**, 再判接没接:

1. **参数中心里能改的数字全部来自数据面 `tools/param_registry.py` 的 `scan_*()`**, 不是 SQLite 库表。
   分组 = calib(标定/真源) · canvas(画布节点) · code(代码常量) · platform(产品/性能) · switch(运行开关) ·
   space(空间点/示教点)。
2. 🔴 **拿 `sqlite3 "select ... from params"` 查不到就断言"没这个参数"是错结论**: 点位类真源常在
   `data/skills/l2_atomic/{space_points,taught_points}.json` 这类 JSON 里, 从来就没被注册过。
   判"有没有"的正确入口 = `python3 tools/param_registry.py list | grep <关键词>` / `stats`。
   站台页 `8793 /ctl/points` 列出的 slots(号位)+spaces(空间点) 是同一批数据的另一个面。
3. **假接入的两个形态**: (a) 没给 `fn_ref`/`sys_hint` ⇒ `param_links` 把功能/模块自链成参数名;
   (b) 没给显式 `min`/`max` ⇒ 范围按当前值推断出 "±10%" 之类假包络, 状态显示"已定义"其实没闸。
4. **改数 ≠ 生效**: 消费方 (站台页 / L2 执行器 / 引擎) **启动时读一次**真源 ⇒ 写完必须重启对应服务再回读,
   否则页面显示新值、动作还是旧值。
5. **在线改数没有真机校验**, 只有范围包络 ⇒ 参数中心只配毫米级微调; 新点位/大改动一律回现场点动 + 页面示教
   (走 `POST /ctl/record_point`)。对称地: `tools/adjust_point_offset.py` 只吃 `taught_points.json`(号位),
   不吃 `space_points.json`(空间点) —— 别把它当通吃工具。
6. **把新真源接进参数中心 = 五处编辑 + 三段验证** (缺一不可):
   `param_registry.py` 加 常量 → `scan_x()` → `CAT_CN`+`CAT_COLOR` → `scan()` 串上 → `set_param()` 加
   `_write_json_path(X, p["ref"], v)` 分支 (它自带备份+回读核对, 别另写写盘); GUI 只需在 `param_center.py` 的
   `CAT_ICON` 添图标 (分类树按 registry 分组动态生成)。
   验证链: `param_registry.py stats`(范围未定义=0) + `verify` → 干跑 `set <id> <v>` → 真写 `--write` →
   **回读源文件** → 写回原值复原 → `engineering_db.py build|check` → `verify_param_center` + `verify_platform_spec`。

## 接入下一级前的硬约束 (先量化再动手)

- **延迟预算**: 单步耗时 vs 目标帧率必须先量 (实例: INTACT 单步 316ms, paper 权重/GPU —— 说"每帧调用"前得先回答帧率够不够)。计算图/大模型接进实时回路时, 316ms 是真实工程约束, 不是细节。
- **推荐推序**: ① **只读旁路** (每帧真调, 结果进数据总线/可视化, **动作不参与下发**) → 先量延迟与稳定性; ② **接管某段** (输出真驱动执行) → 必须**同口径 A/B + 不回退证明**; ③ **硬件**。
- **不回退红线**: 新模型接管不得让插拔任务成功率/性能回退。先回归, 再交付。
- 老倪式验收: 要**视频或数据实证**, 口头不算; 他更关心"改了什么", 不关心过程。

## 输入级取证: 「模型/节点吃的是哪份数据、返回什么」

L2/L3 过了(确实每帧被调用)之后, 还有一层常被追问: **它吃的是哪张图/哪份数据**。这时输出四样:
**代码位置(文件+行号: 实例化/调用/返回值落台账, 并说明调用在后台 worker 而不是路由里)** · **能点开的图 URL** ·
**返回值原样 JSON + 逐字段一行** · **同源硬证据 = 取回图的像素 md5 == 台账里记的 md5**。

铁律:
- "给人看的产物"与"模型吃的输入"是**两份东西**, 各自命名/各自台账; 改了模型输入口径, 把别的接口里的旧字段**全部同步**,
  否则两个接口自己打架(实测发生过: 一个接口写着模型吃判据图, 另一个说吃 960 临时图)。
- 临时产物**只在会入队干活的那条路径上写**, 清理时**跳过待处理队列里的文件**, 队列设上限; 喂模型前先判存在。
  把写操作放在"抓帧"函数里 ⇒ 连"只看一眼"的请求也写, 实测 9 分钟泄漏 2180 张。
- 跑同源闸前**先确认两边的 `n` 是不是同一个计数器**(检测序号 vs 帧号), 再拿它当 join key;
  在线系统一直在动 ⇒ 按帧对齐才下结论, 对不齐就说"未对齐", 不硬凑。
- 详见 `references/runtime-model-input-observability.md`; 可重跑闸 `scripts/verify_model_input_same_source.py`。

## 「这是真正在推理么?」(VLM / 云端大模型) = 解析路径 + 内容依赖 + 与像素真值交叉

用户问某能力"是真模型还是写死的"时, 代码里有 `requests.post` 不算答完。四步, 顺序固定:

1. **让引擎自报走哪条路, 别读 env 猜**: 实例 `SceneVLM().status()` → `{path: http|local, provider, model}`,
   `available()` → `(bool, why)`。同类实现常是**三条路 + 一条 `rule` 兜底**(显式 URL/key · 自带 key 的云端 · 本地 worker),
   必须点名**当前生效那条**, 并说明兜底在什么条件下接管 —— 有降级路径不是缺陷, 不说明才是。
2. **内容依赖双图对照 (最硬的一条)**: 同一入口跑**两张明显不同的真图**, 比输出(框数/标签/角度/构图描述)。
   逐字不同 ⇒ 真看图; 雷同或与图无关 ⇒ 模板回显, 判假。只看一次成功输出区分不了这两者。
3. **与独立像素真值交叉**: 走**现场端点**跑当前那一帧, 把模型文字与你自己已测得的像素状态对账
   (快照 mean≈5/std≈0.9 ⇒ 模型应说"全黑")。模型如实说"看不清"是**加分项**(证明它读的是这一帧),
   别因为"没读到东西"就报失败; 反过来黑帧却描述出托盘和光模块 = 幻觉, 直接判假。
4. **触发方式与耗时**: 分清「点一次一帧」(按钮 fetch、无 `setInterval`) 与「每帧/定时推理」。
   按需调用**不能**当实时检测层汇报; 单次耗时给区间(同一模型两次可差一个数量级, 取决于 API 排队)。

汇报模板: 「真推理 · 路径 `http:deepseek-flash` · 双图输出不同(3 框 / 2 框) · 现场帧读出"全黑"与像素真值一致 ·
按需一帧不是每帧 · 单次 8~68s」。另必答**失败面**: 无 key / 断网 / 本地权重不在盘时, 是回 `rule` 摘要
(要标 `src=rule`) 还是 `ok=False`; 桥接层如实透出 `ok=False`、下游写 `null` 而不是 0, 才算"不冒充"。
端侧权重目录不存在时只能报"本地离线路径不可用", **不能拿云端跑通说成端侧也行**。

`tools/canvas_level_audit.py` — 逐节点四件套取证: ①执行注册 ②源码映射有效性 ③引擎引用 ④连线数,

`tools/verify_engineering.py` — 全工程判据, 其中「**档位契约无问题**」= 每个档位节点的名都能在逻辑真源
`engineering/nodes/library.py` 的 `NODE_LOGIC` 里找到 key。**画布上有节点、连线也在, 但档位注册表里没这个 key
⇒ 节点级能跑、档位级 (▶运行/单步) 永远拿不到它** —— 这就是"假接入形态 #2"的自动判据, 红项会直接列出节点名
(`L2: N 个节点没有对应逻辑 key: [...]`)。给画布加节点/接线后跑一次, 把"节点级绿"与"档位级绿"**分开报**;
只改了节点文案/params 时, 改前改后回读**节点数 + 连线数**证明结构没动 (描述变了不算结构变更)。

**纪律 1: 判"有没有执行注册"必须 import 真分派函数, 不许自己写正则。**
自写 `_reg\("key"` 正则漏掉**循环注册** (`for _skid,…: _reg(_skid,…)` → SK01-08) → 8 个真节点被误判"缺注册"。
正确做法: `from node_logic import match_node; match_node(画布节点名)` — 与 GUI 双击分派逐字同源。

**纪律 2: 解析 `_EXTERNAL_LOC` 路径不许用 `\(([^)]*)\)`, 更不许按 basename glob。**
嵌套括号 `os.path.join(...)` 会在第一个 `)` 处截断; 按 basename 搜会命中 `gui-venv311/site-packages/torch/.../planner.py`
(同名文件!) → 整片 57 条映射被误判失效。正确做法: **按字面量片段顺序拼绝对路径取最长存在后缀**, 并排除 venv/site-packages。

**判据分层 (别把软指标当缺陷)**: 硬判据 = ①有执行注册 ②不孤岛; 源码映射缺失只是"展示回退到节点函数"(合法)。
一次实测: 70 节点 → R1 每帧 16 · R2 档位级真接 31 · R3 语义 13 · R4 终端 7 · R5 待建 3 · ⚠ 0;
152 连线 → 双端运行时 17 · 单端 67 · 双端非运行时 68 · **真缺口(端点无注册) 0**。

**6 类"画布有节点但没执行函数"的修法 (实测有效, 全是真实现只是没接上)**:
| 症状 | 修法 | 实例 |
|---|---|---|
| 关键词对不上 (函数本来就在) | 给已有 `_reg` 的 match 列表**加画布节点名的独特子串** | ss_llm←"长程序列规划器"; ss_skill←"技能序列编排"; ss_mem_l2←"肌肉记忆操作"; ss_mem_l3←"记忆: 海马体" |
| 真没注册 | 写 `node_xxx(ctx)` 真执行函数 + `_reg` + `_EXTERNAL_LOC` 三件套 | n_board_frame (board_frame_module.run); n_l2_muscle (技能 JSON + ROS2 桥只读) |
⚠ 加关键词时必须查**最长匹配**冲突: 别加"长程序列规划"(会抢 🚀 L3 · 长程序列规划), 用更长的独特串。

10. **"配置驱动"只驱动名不驱动行为 (配置只被打印)**: 任务/配方配置读进来当成 `cfg` 传了一圈, 但执行函数里
   一次都没用 ⇒ 改配置只改了日志。实测: 摆盘链 `run_module(env, ss, i, cfg, ...)` 内 `cfg` 出现 **1 次 (仅形参)**,
   判据阈值写死 `max(|dx|,|dy|)<=0.001 and yaw<=1.0`。
   判定法 = **同一条 episode 换配置跑两遍**: 该配置项真生效 ⇒ 判决/轨迹变; 只被打印 ⇒ 两遍逐字相同。
   实测 A/B: 阈值从配置读 `≤1.000mm` ⇒ 3/3 合格; CLI 覆盖 `≤0.300mm` ⇒ 0/3 不合格 (Δxy 物理量两组完全一致 0.34/0.43/0.47mm)
   ⇒ 阈值确由配置驱动。**修法**: 写 `task_spec()` 真读配置中心 (targets/overrides) 并在报告里逐条报"判据来源",
   让"配置→判决"可追溯; 留 CLI 覆盖口做 A/B。顺带把配置里没量纲意义的项 (字符串"配方上限") 跳过而不是硬转 float。

11. **"状态灯说在跑" ≠ 真跑, 而且灯有真源 —— 先找到它再动手**: 界面那列"推理中/空闲"不是界面算的,
   是它读的**探针**算的。实测链路: 模型引擎窗口读 `GET http://127.0.0.1:8796/status/all` →
   `src/lerobot/engineering/status_hub.py` → `models_manifest.json` 里每个模型的 `probe`; 形状是
   `{"type":"counter|ts|file|json_age", path/url, pointer, window_s/max_age_s}`,
   `inferring=true` 的充要条件是**探针在窗口内真的动了** (counter 增长 / 时间戳新鲜)。
   ⇒ 想让某层亮只有两条正路: ① 让这层**真被调用** ② 把探针指到**它自己**的真调用计数/时间戳上。
   把探针指向别人的计数、或改了清单却不真跑 = 假绿 (同第 7 条红线)。
   汇报按层给结论: "这层真跑 (计数在长) / 这层只是灯 (探针指错) / 这层本就没挂 (为什么)"。
   **接线验收顺序 (照做)**: ① 在**隔离实例**上跑通 (实例隔离 + 不抢单写入器锁, 一律不碰在役回路)
   → ② 回读**每层调用台账** (每层 ok/耗时/来源, 一行一次调用) → ③ 才改 systemd drop-in 生效
   → ④ 重启后在界面回读同一条。**别拿"服务 active"当"层在推理"**。
   常驻回路接整条链的最小代价口径: 10Hz 的回路不要每周期都跑全链 (全链几十 ms/次),
   用"每 N 周期一次" (实测 2Hz 足够让探针持续在窗口内动)。

🔴 **体检脚本的"假断点"比没体检更糟**: 路径写死会产出不存在的缺口, 用户按它去修就白干。
实测两例: 记忆开关真源是 `data/memory/memory_layers.json`, 脚本写成 `data/memory_layers.json` ⇒ 恒 FileNotFoundError;
世界模型权重在 `models/l4_mani_predictor_v*.pt`, 脚本只 glob `checkpoints/**` ⇒ 恒报"无预测器权重 (世界模型项可能恒0)"。
判据: 报"缺 X"之前先 `find`/`ls` 那个东西的**真实落点**, 拿不准就报"未在此路径找到"而非"不存在";
读数也要按消费方口径 (引擎 `d[k]=int(bool(j[k]))`) 解释 —— 注册表形态的文件按扁平开关读会得出反结论。
🔴 **探测脚本里对“用来分类的那份清单”绝不许截断**: `ls -d models/* | head -20` 这类限制会让排在后面的
目标永远被归成“没有” —— 实测 models/ 下 36 项、目标排第 23, 于是审计连报几轮“端侧无该权重”, 而权重早在盘上、
真跑完六个提示都出了实例。判据本身错了, 后面的结论全部作废。改法: 不截断(`ls -d models/*`),
或者按名字 `grep -i` 定位; 任何“计数/名单不全”的探针都要先把**总条数**打出来自证没被截。
🔴 **审计档位要区分“能跑”与“常驻在跑”**: 权重到位 + 依赖可导入 + 手工前向真出结果 = **ready(离线可跑)**,
不是 `absent`(没有能力), 也不是 `run`(每帧在跑)。把“服务没起”与“没能力”混成一档, 会让用户以为一堆东西没装,
也把你自己真正要补的缺口淹掉。报告按 `run / ready / stale / absent / nonexec` 分档给计数,
并写明 ready 那档的实测代价(单次耗时) —— 那才是它能不能上产的决策数据。
