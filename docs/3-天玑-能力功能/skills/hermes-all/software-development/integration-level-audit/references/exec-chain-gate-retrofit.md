# 在真机下发收口补「约束复核」的改造清单

适用: 约束只在仿真/派发链里生效, 真机链的收口函数里一次都没复核 (判据:
`grep -n 'V_CAP\|A_MAX\|JERK\|s_step' <收口文件>` 零命中)。

## 五步

1. **定收口**: 找到**唯一**那个既过授权闸、又真正下发的那一层 (例 `chan_send(call, ..., speed=None)`)。
   别挂在调用点 — 调用点有好几个, 挂漏一个就有一条路不受管。
2. **判阶段**: 用调用体自身的语义推 (`ros`/`axis`/`kind`/显式 `stage`): `insert→插入` · `pull→拔出` ·
   `grip→抓取` · `z_pos→抬起` · `z_neg→下降` · `line_abs`/横移→`转移`。推不出 ⇒ **明示跳过**并计数,
   不静默当通过 (跳过必须有 why, 否则将来没人知道它没管)。
3. **选口径**: 段速硬闸 = `min(V_CAP, S_STEP/DT_S)` (顶速 + 单拍位移, 都取自该阶段技能类/标定真源)。
   加速度与加加速度属**腿内斜坡**, 段级下发改不动它 ⇒ 只算 `ramp_s = v/A_MAX(+jer是估算)` 进取证, 不降速。
4. **挂闸 + 速度来源三级回退**: `speed = 参数 or call[\"speed\"] or env 默认`; 削出来的值必须传进真正的下发函数。
5. **开关与取证**: `ZMAX_EXEC_*_GATE=0` ⇒ 原始值逐位透传; 每次被削追加一行
   `ss_live/exec_skill_gate.jsonl` (`stage/skill/v_req/v_allow/bottleneck/ramp_s/limits`)。

## 验收八条 (写成 `tools/verify_exec_skill_gate.py`)

| # | 断言 |
|---|---|
| ① | 超限请求 ⇒ 降到允许值 (例 500→300 mm/s), `cut=True` |
| ② | 限内请求 ⇒ 原值返回, 不无端降速 |
| ③ | 允许值 == 用技能类常量**独立算一遍**的最小值 (防硬编码) |
| ④ | 无阶段 ⇒ `applied=False` + why 写「跳过」 |
| ⑤ | `GATE=0` ⇒ 请求值一位不动 (零回归) |
| ⑥ | 被削 ⇒ 取证文件新增一行且末行可回读 |
| ⑦ | **不传速度参数**时能按调用体 `call.speed` 复核 |
| ⑧ | **静态偏移**: 闸调用点位于 `def <收口>(` 与下发腿之间 |

## 坑

- **「已插入」判据自我匹配**: `if "_fn(call" not in s` — 刚插入的 `def _fn(call, ...)` 本身就含该串 ⇒ hook 静默不落,
  源码翻着有闸、实际没挂。改用偏移比较 (`s.index("def 收口(") < s.find("闸调用") < s.find("下发腿")`),
  并跑一次真降速。
- **闸读不到速度就静默放行**: 收口函数的 `speed` 参数经常是 None, 真实速度藏在调用体或 env 里。
- **a/jerk 当段速硬闸 = 误削**: 从静止首拍界 `J·DT²` 会把合法段速砍到 ~40%, 节拍跟着崩; 它是斜坡指标, 不是段速上限。
- **验证工具里别 import 常驻服务的主函数**: 用 `importlib.util.spec_from_file_location` 加载模块
  (主循环在 `__main__` 里才建 FIFO), 直接调那个纯函数。
- 改完先跑既有回归判据 (UPH · 技能物理 · 调度) 再报数: 新闸只作用于执行侧时, UPH 应与改动前逐位相同。
