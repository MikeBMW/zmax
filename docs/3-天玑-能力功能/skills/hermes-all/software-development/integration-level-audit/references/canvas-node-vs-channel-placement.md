# 画布节点定位 · 与"这个功能该放哪个节点"评审

## 1. 定位某能力到底挂在哪个节点（顺序固定）

1. **先确认库文件是真的**：节点参数表在 SQLite。
   `ls -l data/database/zmax/zmax_engineering.db`（真文件）对比仓库根目录同名文件 —— 根目录那份可能是
   **0 字节空壳**（`build` 往 data/database 写，不写根目录）⇒ 直接查根目录会得到"没有这张表"的假结论。
2. **按关键字扫参数**：
   ```bash
   python3 - <<'PY'
   import sqlite3, json
   c=sqlite3.connect('data/database/zmax/zmax_engineering.db')
   for n,t,p in c.execute("select name,type,params from canvas_nodes"):
       if any(k in (n+p or '') for k in ('<关键字>',)):
           print(n, '|', json.loads(p).get('source'))
   PY
   ```
   `canvas_nodes` 的列是 `project_id,name,type,x,y,w,h,params`（**没有 id 列**，id 只在 flow JSON 里）。
3. **判"有没有节点"只看 `params.source`**：它指向哪个源文件是唯一硬证据。
   目标文件（如 `se3_impedance.py` / `se3_gravity_provider.py`）**没有任何节点的 source 指向它** ⇒
   画布层面不存在这个节点，别因为描述里出现同义词就认定有。
4. **连线一律读 flow JSON，不要读 DB**：
   `src/lerobot/engineering/flows/state_space_obs.json`（软链到 `data/database/zmax/sources/canvas/…`），
   结构 = `nodes[].id` + `links[]{f,t,f_port,t_port,label}`。
   DB 的 `canvas_links` 行可能 `src/dst` **全为 NULL**（build 缺陷）—— 拿它下"没接线"的结论是假阴性。
5. **孤岛判据**：`links` 里 f/t 都不含该 node id ⇒ 0 连线 = 画上去了没接线。
   两份口径的节点数可以不等（flow JSON 多、DB 的 `canvas_nodes` 少），回答"画布上有什么"以 flow JSON 为准。

## 2. 同一个词盖住不同层（最容易答错的形态）

用户在画布上看到"引力 / 万有引力 / 势场"这类词时，先分清它是**意图层**还是**力层**，再回答"有没有那个通道"。

- 实测同一个画布上三处都不是力矩：
  标定层「引力-斥力-动作」= Kp 快速动作标定 + 阶段限速；
  「势场联络」= Φ_SK/Φ_process/障碍场 → 意图 −∇Φ（位置意图）；
  流形引擎 `gradient_flow` = 势函数梯度流（也是位置/动作建议）。
- **判据是输出量纲**：动作块 / 速度 / Δpose = 意图层；`[F;M]` 六维力扭 = 力层。
- 要回答"力矩通道在哪"必须找到 u→τ（`Jᵀu`）的**消费方**：`grep -c 'torque\|力矩\|J_b' <执行器源>`，命中 0
  ⇒ 执行链根本没有力矩入口，此时正确答案是"逻辑在、通道没有"，不是"在某节点里"。

## 3. "这个功能塞进 X 节点合适么"评审四查

用户常提议把控制律/后处理塞进"汇总输出动作的那个节点"。不要照做，按四条给判断，并且**用他画布上现成的那条 link 当证据**：

| 查什么 | 判据 | 典型结论 |
|---|---|---|
| 量纲/语义 | 该节点 out 口现在是什么，新东西输出什么 | 同口两义 ⇒ 下游分不清，`action 直通` 那条边会被污染 |
| 频率 | 控制环频率 = 最慢环节 | 生成式策略节点（几个~十几 Hz）装不下 ≥100Hz 阻抗/力控环（引擎自报 0.056ms/帧 ≈ 3500Hz，差两三个数量级） |
| 反馈源 | 控制律必须吃实时真值（50Hz 位姿/接触力） | 若该节点入边全是潜空间/流形/条件、无真值口 ⇒ 塞进去等于新开一条 50Hz 反馈边，策略节点变控制节点 |
| 版本/口径 | 训练权重 vs 可进化参数 | 同节点 ⇒ 改权重与调参数共用一个版本号，故障不能分层定位 |

**正确接法**：找到"该节点 → 规划/执行"的那条 link，把中间切开插一个独立节点
（独立源文件 · 独立频率 · 独立开关）；策略节点的输出当**目标/前馈**（ξ_d、v_d），不参与出力。

**折中**（用户就想少一个框时）：在该节点加**第二个输出口**（如 `u_imp`），不并入主动作口；
代码仍分文件、频率仍分离 —— 可以接受，但不作默认。

## 4. 汇报结构（这个用户认的顺序）

1. 先一句话结论：该 / 不该；
2. 四条理由各一句，每条带一个结构事实（连线 label / 频率数字 / 入边清单 / 版本口径）；
3. 给具体插入点：哪两个 node id、哪条 link 切开；
4. 最后单独一行写"还差什么前置条件"（例：执行器没有力矩入口，u 只能先落回位置修正）。
