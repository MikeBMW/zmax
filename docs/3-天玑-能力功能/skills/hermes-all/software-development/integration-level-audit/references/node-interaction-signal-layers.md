# 节点间"交互信号"的三层 + 55D 唯一口径 + 算法归属

回答「这些节点的交互信号都是什么」「下游能接到什么」之前先读这份。核心结论:
**端口契约、总线信封、进程内 dict 是三条通道, 只有一条真在传数。**

## 1. 三条通道 (先分清, 否则必然答错)

| 通道 | 形态 | 谁在用 | 怎么验 |
|---|---|---|---|
| 画布端口 | `{out1: {...}}` / `ctx["inN"]` | 声明层 (拓扑语义) | 打印节点 `out1` 原样, 看是不是那块数据 |
| 总线信封 | `{"value":…, "age_s":…, "fresh":…}` | 跨节点/跨进程 | `_pick` 读的是 `pv["value"]`, 不是裸值 |
| **进程内共享 dict** | `_SS_STATE` / `_YOLO_CACHE` | **同 pid 的节点** | `grep -rn '_SS_STATE\['` 数写方/读方 |

最常见的假象: 节点 `return True`, 值全 `_SS_STATE.update({...})` ⇒ **out1/out2 是空的**,
而画布上 out1→下游.in8 的连线照样画着。这与 `PURE=False` 直通是同一类: 声明层接通, 实现层无值。
判据只有一条: 把端口值打出来看是不是上游/自身的那块数据。

## 3. 三个必报的语义/单位坑

1. **单位不统一**: obs 全表是**米**; 引导位姿/块是**毫米** (`smooth_traj` 内部仍以米算, 只有输出字段
   叫 `L_mm = round(L*1000,1)`)。混着走就是 1000 倍事故。
2. **`contact_p` 不是力**: `σ(gain·‖residual‖)`, gain=8.0, 输出 0~1 概率。它是"残差大 ⇒ 大概接触了"的代理,
   不是力传感器读数。
3. **`_pick` 六候选别名是容错, 也掩盖了契约不一致**:
   `_pick("in6", ("u_ff","u","vec","chunk0","a","best"))` —— 六个 key 挨个试。能跑不等于有契约;
   报"上游给了什么"要按产出端 dict 的真实键集说, 不说候选列表。

## 4. 四个并存节点的算法归属与参数来历

| 节点 | 实际算法 | 关键参数 | 业界同级 |
|---|---|---|---|
| 自适应状态估计器 `ssest` | **固定增益 alpha-beta**: `x̂⁻=A·x̂+B·u` · `x̂=x̂⁻+K·(z−x̂⁻)` | A=1.0 · B=0.02(=dt@50Hz) · K=0.2 | 卡尔曼/AMCL |
| 先验动力学预测器 `sspred` | 右脑 WM 真权重 + 线性回退; **位置先验实际走线性** | A=1.0 · B=0.02 | World Models/Dreamer |
| 前馈加速器 `ssff` | **逆动力学策略** (左脑 MLP 蒸馏, 547K, 纯 numpy) | Kp=1.2 (反推 1.227, MAE 0.0009) | 行为克隆/ACT |
| 测地线规划引导 `n_geoplan` | 五次多项式 **最小加加速度** + S² 大圆测地线 | v_cap/a_max 反解 T | Flash-Hogan/CHOMP |
| 状态校正器 `ssinnov` | 卡尔曼 **update 步**: `x̂=x̂⁻+K·(z−x̂⁻)` | K=0.5 · w_err=0.5 | 卡尔曼 update |

**必须如实说的三条**:
- **不是卡尔曼**: 全仓 `covariance|协方差|np.cov|filterpy` 零命中 ⇒ 没有 P 矩阵, K 是常数。
  "自适应"目前名不副实 (真自适应要 `K = P⁻/(P⁻+R)`)。
- **右脑只用在 `contact_of`** (接触分类 acc 0.998); 位置先验走线性, 因为代码注释的实测结论是
  "引擎纯积分动力学下线性先验即最优, 右脑 1cm 级误差反而加噪"。学到的模型适合做**事件判别**, 不适合替代**物理积分**。
- `smooth_traj` 的 `s = 10τ³ − 15τ⁴ + 6τ⁵` **就是 Flash & Hogan (1985) 从人类手臂实测反推的最小加加速度曲线**,
  不是工程近似 —— 讲"大脑怎么做"时这是同一个公式, 不是类比。

### B=0.02 的来历 (参数不是拍出来的)
`metaworld act=u/0.5` 伺服稳态 ~9mm/步@act1, 位移 ≈ u×0.018s, 引擎 dt=0.02 巧合同量级。
原 B=0.1 → 预测过冲 5 倍 → 残差 0.5 级爆发 → `contact_p` 误判接触 → 夹爪离销 20cm 就空闭合 → 卡死循环。

## 5. 为什么状态校正器必须在最后 (拓扑 + 数学两个答案)

五输入汇聚点: `in1` 潜状态 · `in2` next_obs 预测 · `in3` 观测 z_k · `in4` 物理偏差 · `in5` 执行结果。
- 数学: update 的定义就是 `x̂ = x̂⁻ + K·(z−x̂⁻)`, 先验是输入 —— predict/update 顺序是定义的一部分。
- 数据: 三路是"事后"信息 (世界观测/执行结果/物理偏差), 只有动作已规划、已建议、已被物理闸判过才存在。
- 语义: 它的输出 `u_fb` 是**修正量**不是动作, 动作先要有才谈得上修。

输出两路把闭环闭上: `out1 → sssched.in8` (u_fb 回动作调制器) · `out2 → sssensor.in5` (校正后状态回灌融合定位)
⇒ 校正器 → 融合定位 → obs55 → est/pred → 校正器。

🔴 **小偏差就地修, 大偏差不许在这修**: `state_correction` 注释写明 err 按 `w_err` 吸收的是
"物理上跟不动"的那部分; 大偏差走 `skill_error.json → ss_engine_loop` 顶层补偿。
理由: 校正器增益是固定的, 拿它吸收结构性偏差会把状态直接拉飞。
