# 日志文案 = 完整句子 / 朴素白话 (2026-10-17 老倪定规)

老倪原话：「这些启动日志，写的太抽象了，改成平滑朴素的说明，要整个完整的句子，要成为一个完整的段落」
「你全局搜索，以后不允许这样，不要用词语」

## 规矩

* **每条日志 = 一个完整段落**：主谓宾齐全、用「。」断句、可以是多句。
  **禁止**「标题: 名词短语 · 名词短语 · 名词短语」这种词块堆砌 —— `·` 只能连接**同层级的完整短句**，
  不许当项目符号/分隔符去堆标签。
* **朴素白话**：不堆术语。
  「真源预读」→「从各自的正式来源读进来」；
  「数据源回写 无需改」→「画布上的数据源和上次一样，不用改」；
  「✅ 在位」→「在位」/「没能取到」。
* **路径/数字照实写全**：场景路径、任务名、配置项数不许用「—」糊过去。
* **失败分支同样成句**：`工程状态自恢复跳过: %r` → `上次的工作状态这次没能自动接上，原因是：%r`。
* **理由**：日志是现场唯一「发生了什么」的叙述；词块堆砌读不出因果，老倪要能直接读懂的整段说明。

## 反面 → 正面 (studio.py 启动两行, 2026-10-17 已改)

❌ `📌 工程状态自恢复: 场景 X · 数据源回写 无需改 · 存档任务 A / 当前 B`
✅ `📌 上次的工作状态已经自动接上了：场景仍然是 X；画布上的数据源和上次一样，不用改；存档的任务是 A，这次实际要做的任务也是 B。`

❌ `📚 启动期配置真源预读: 配置 8 项 (总工程文件 · 任务绑定 · …) · 工程库 ✅ 在位 · 实际任务 A B`
✅ `📚 启动的时候，我已经把这 8 项配置从它们各自的正式来源读进来了，依次是：总工程文件、任务绑定、…。工程库在位；这次实际要做的任务是 A B。`
