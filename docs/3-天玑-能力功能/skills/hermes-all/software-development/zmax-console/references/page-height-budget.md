# 📐 侧栏/面板「一屏放得下」的高度账 (GUI 硬约束)

老倪说「XX 显示不全, 增加高度」时照这份做。**先量后改**, 别凭感觉调。

## 用户口径 (standing preference)

- 「显示不全」= 每一块要**整块可见**, 不是「能滚到就算」。但同时会要求「增大高度」。两条一起要时:
  **给出高度账 + 明确的 either/or**, 别悄悄牺牲其中一块。
- 整页只留**一条**右侧滚动条; 各块自己不许有滚动条; **滚轮不许把表/块推走** (就地吃掉 Wheel 事件)。
- 高度不够时的收口顺序: ① 收「与页头/别处重复的信息」那一行 (重复的标题、节点摘要); ② 压行高 / 页脚行数 / 回显行数;
  ③ 最后才动「块本身的最小高」。别一上来就砍内容块。

## 必踩的坑: 子控件的 setMinimumHeight 顶死布局

症状: 某块看着被**压成一条**(实测: 太阳系渲染成一条弧线, 不是一个圆), 同时同一层另一个 label 莫名拿到超大高度 (实测一个 QLabel 占 480px)。

机制: 子控件 `minimumHeight`/`minimumSizeHint` 大于父级实际分给它的高度 ⇒ 布局总需求 > 视口 ⇒ 父级必须超配 ⇒
焦点块被压到最小值以下 (渲染变形), 多出来的高度被同层某个 label 吃掉。

规矩: 面板里每个可视块的 `setMinimumHeight` 控制在真实下限 (~150px);
高度由**父级 setFixedHeight / 自动配平**决定, 不要用子块的最小高去「要」空间。

取证: dump 每个子的 `height()` + `minimumSizeHint()`。**看到 minHint 远大于实际 height 就是这个病**。
再往上核父链: `[(_parent_class, h) for p in widget.parents()]` ⇒ 一眼看出高度是在哪一层被吃掉的。

## 自动配平 (两块都要全见 + 不滚的做法)

让灵活块吃掉剩余: `viz = clamp(viewport − (inner_height − viz_height), floor, cap)`
(即把内容总高补齐到视口), floor ≈ 196 保底, cap ≈ 620 防离谱。

这样「数据块(表) + 上面的功能行」永远整块可见, 灵活块(可视化视图)拿走剩下的全部高度, 整页不需要滚。

## 取证 (命令通道 + 视觉两条腿)

- `echo orbital > /tmp/zmax_nav_cmd` 切页 · `echo mparam_shot > /tmp/zmax_nav_cmd` ⇒面板实拍 `reports/ui_shots/*.png`;
  活实例把高度账写成 JSON 落盘, 直接读它:
  `M 页 {page_h} | 视口 {vh} | 灵活块 {viz_h} | 数据块 {gravity_h} (表 {table_h}) | 需滚 {scroll_max}`
  **`需滚 ≤4` = 两块都全见 ✓** (判据按这个数, 不按肉眼)。
- 视觉复核用 `tools/selfcheck_vision.py <图> "<4 问>"`, 问法要能戳中退化: 「完整圆形 还是 被压扁/一条弧线」·「全部行在不在」·
  「各自有没有滚动条」。视觉只作旁证, 机械读数不一致时以机械为准并在报告里如实写清两边不同。

## 窗口几何也会吃高度 (先量再改代码)

控制台窗口尺寸走 QSettings 存盘 ⇒ 可能被存成小窗 (1400×900 ⇒ M 页只剩 ~509px, 与满屏差 ~200px, 直接决定「装不下」)。
⇒ `tools/gui/restart_studio.sh` 起来后**显式**把窗口拉到整屏 (`xdotool windowsize/windowmove`), 别依赖存盘几何;
**报高度账前先确认窗口是满屏** —— 否则会把「窗口小」误诊成「布局不行」, 白改一轮布局代码。
