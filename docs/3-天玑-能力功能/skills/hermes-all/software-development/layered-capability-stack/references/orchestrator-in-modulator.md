# 总调度(仲裁器)装进动作调制器 — 落法与坑

## 为什么装调制器而不是新画布节点
- 调制器(`state_space/cognition.py::ActionModulator`)同时握有: 各层提案 + 阶段机 + 物理闸(原子技能 SK01-08 / `physics_constraints.InertiaLimiter`)。
- 另开节点 = 把物理闸复制一份 ⇒ 两个真源, 迟早打架。仲裁只决定「听谁的/要不要停」, 限幅仍走原唯一路径。
- 画布里 `sssched` 节点的 `source` 本来就指 `cognition.py::decide` ⇒ 图上语义与代码位置天然对齐, 不用改图。

## 结构
- 新增 `state_space/orchestrator.py`(`Orchestrator.arbitrate()`), 只做四件事: 层权重按阶段配比 / 一票否决 / 加权融合 / 遥测。
- `cognition.decide()` 顶部加一个分支: `self.orch is None` 走原路径(逐位不变), 否则用仲裁结果替代 `u_ff + k_fb·u_fb`, 后面 ③阶段限速 ④元任务门控 原样继续。
- 开关 `ZMAX_ORCH=1`; 默认 0 ⇒ `self.orch=None`。

## 硬坑(都踩过)
1. **全零动作 ≠ 该层没有提案**。若把 `np.zeros` 当合法提案, "所有层都没提案"永远不成立, 永远不进"保持"。判据用 `norm > 1e-12`。
2. **端侧按文件加载没有包结构**。`from .orchestrator import` 会 ImportError, 而 `from orchestrator import` 也失败(目录不在 sys.path) ⇒ 必须 `importlib.util.spec_from_file_location(__file__ 同目录)` 兜底。
3. **力否决/相位调制要有入电点**。`decide()` 原本没有 force 入参, 仲裁里的力否决就是死代码; 必须给 `decide(..., force_n=None, su2=None)` 加默认 None 的关键字并透传, 才算真通线(默认 None 保证逐位不变)。
4. **回归证据要用 HEAD 版本对拍**, 不能只跑新代码: `git show HEAD:<file>` 导出到临时文件 + 同种子 60 例 `np.array_equal`, 才算"默认关不改行为"。端侧无 git ⇒ 打印 SKIP, 不许假装通过; 用 md5 与主机端一致来把证据搬过去。
5. **别假设 1kHz**。画布循环 10Hz、物理闸 dt 来自标定(`zmax_skill_physics.json`, 0.1s; 引擎口径 0.02s)。判据一律用调用方传的 `dt`。
6. **层缺失要归一化权重, 不能拿 0 补位**。真机当前只有 L2(u_ff)/L4(u_fb), VLA 的 H 步动作块没有实时注入管线 ⇒ 用 `set_layer("L3", vec)` 预留, 缺就按在场层归一化, 遥测里 `layers` 明确写在场集合。

## 阶段权重与阈值(可调, 但要有依据)
- 自由段(接近/抬起/转移/回程) L3 主导(0.50~0.55); 对位/下降/AOI检测 L4 主导(0.55~0.60); 抓取/插入/拔出/放下 L3 压到 0.10, L4 0.60。
- 力否决阈值按现场红线: 插入/抓取 40N, 对位/下降 25N, 接近 30N, AOI检测 20N (`STAGE_FORCE_N`)。方案里写 2N 是金手指接触阈值, 不是插入力, 别照抄。
- 残差: 单次越阈 ⇒ 保守化(只信几何, 不停, 避免抖动); 连续 3 拍 ⇒ 停(`max_veto`)。
- su2 遥测: `|w| < 0.55` 视为层间发散 ⇒ L3 砍半; 非交换 > 0.80 rad 且处于敏感段 ⇒ L3 砍半给 L4(实测 L3|L4=1.19rad≈68° 是真强耦合)。

## 验收
`tools/verify_orchestrator.py`: 闸1 逐位回归(60 例) + 闸2 语义(9 场景) + 闸3 集成(含 force 注入) ⇒ 13 项断言。本机与 550C 同码各跑一遍。

# 调度状态机也住这里 (工厂调度 = 调制器, 入口只当节拍器)

用户口径: 「程序入口应该是一个状态机; 状态机放在动作调制节点比较合理, 对应小脑基底节的状态, 工厂调度」。

## 为什么是这里
基底节的职能就是「按状态选通路 + 一票否决」; 调制器已同时握有 当前状态 / 各层提案 / 物理闸。
把状态机另放一处 ⇒ 状态在这处、闸在那处, 又是双真源。入口脚本(`tools/*_loop.py`)只做节拍器:
每拍把观测灌进状态空间, **不承载业务状态**。

## 结构
- 新增 `state_space/scheduler_fsm.py`: `STATES`(段名与序必须与 `ActionModulator.STAGES` 一致) +
  `POLICY`(每段 `w_L3/w_L4/w_L2` + `v_cap`/`v_min` + `f_veto_n`) + `DispatchFSM.step(obs)`(转移守卫)。
- `ActionModulator.__init__` 建 `self.fsm`; `advance()` 只做**观测适配 + 同步**(`stage_idx`/`v_cap`/`v_min` 从 POLICY 回写),
  旧内联逻辑留在 `ZMAX_FSM=0` 分支里当对照臂 —— 不许直接删, 那是唯一能证明"没改行为"的东西。
- **POLICY 是唯一真源**: 仲裁器不再自带一张 `STAGE_W`, 改成 `w = am.fsm.policy()`; 两处各一张表迟早对不上
  (改了一处忘了另一处 ⇒ "状态在这个段、权重还是上个段的")。
- 每次切换落 `zmax_data/ss_live/ss_fsm.json`(`state/idx/since_s/n_trans/last_reason/history` + 当前策略),
  现场和页面都能一眼看到调度器在哪一段、为什么切过来。
- 开关在入口给默认值, 写入代码而不是只写进 systemd: `ZMAX_FSM=1`(0 = 旧内联逻辑) · `ZMAX_ORCH=1`;
  服务侧用 drop-in 加同名 `Environment=` 覆盖, 别改 unit 本体。

## 硬坑
1. **只在切换时落盘 ⇒ 安静的一跑里一个文件都没有**。初始状态必须在 `__init__` 里也 dump 一次, 否则
   "状态机到底起没起"无法取证(实测跑了 12 秒零切换 ⇒ 无 JSON, 差点误判成没实例化)。
2. **守卫只吃可证据化的观测量**(水平距离/接触概率/夹持力/抬升高度/插入深度/落位), 不用"应该到这段了"。
   缺证据 = 不切、不猜; `confirm_n` 连续 N 拍才算成立, 单拍噪声不许推进。
3. **失败分支写在状态机里, 不写在上层重试循环里**: 夹持丢失(抬起~回程, 连 5 帧夹持力<0.05 且件已落回
   抓握高度) → 回退「接近」重抓; 但「放下」段开爪属正常工艺, 回退区间上界必须排除它。
4. **等价性对拍要同观测序列两边跑**: 建两个 `ActionModulator`(开/关 FSM), 喂同一串含抖动的观测,
   逐拍比较状态名序列(多 mode × 多 seed)。只跑一条链走不完所有段, 单条链绿了不代表等价。
5. **限速表的顺序断言按段类比均值, 不要 max/min 混着比**: 抓取段天然比 AOI检测 更慢,
   `max(接触段) < min(精段)` 会永远失败 —— 判据口径写错比实现写错更常见(见主 SKILL 六查 D′)。

## 验收
`tools/verify_scheduler_fsm.py` 四道闸共 25 项: ①等价性(insert/tray/full × 3 seed × 400 拍逐拍相同)
②策略表(权重和=1 / 接触段 L3≤0.10 且 L4≥0.55 / 限速 接触<精<自由) ③守卫链 + 夹持丢失回退 +
转移→插入(悬高容差) + 插入达标→完成 ④与仲裁器集成(插入段 L4 权重最大; 力 45N>40N 否决 L3)。
本机与 550C 各跑一遍, 三文件 md5 对齐。
