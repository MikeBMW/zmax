# 分层能力栈接线 (上层只给意图/条件, 执行由最下层收口)

## 为什么需要

分层架构最常见的事故不是"某层不够强", 而是**层之间是替换关系而不是叠加关系**:
每档各管一段、装配时把别的档关掉 ⇒ 上层拿不到下层的能力, 只能靠自己那点权重硬扛
(实测: L4 直驱过冲 152~331mm, 而解析链只有 10.9~62.6mm)。

**判据 (先做这一步)**: `grep -nE "SS_L3|SS_L4|if .*enable.*layer" tools/gui/*.py` 找有没有
"开 A 就 pop 掉 B" 的开关。有 = **档位互斥**, 能力不可能叠加; 必须先改成"参考+收口"结构再谈提升。

## 一、分层契约 (单向依赖: 上层依赖下层的准确执行)

| 层 | 只准产出 | 禁止 |
|---|---|---|
| L4 意图层 (世界模型/意图解码器) | 意图 `m_t` (目标位移/姿态/交权) | 写执行量、直接产动作 |
| L3 条件层 (VLM/DiT/流程) | 条件 `c_t` (相位/子目标/条件向量) | 写执行量 |
| L2 执行层 (解析伺服/技能/状态机) | 执行量 `u ∈ U_L2` —— **唯一出口** | —— (有对上层参考的最终否决权) |

把"层语义"做进**类型**里 (如 `LayerOut(layer="L4", kind="action")` 直接抛异常), 越权就是运行期错误,
而不是靠 review 记得。

## 二、四条硬约束 (缺一条就是假接线)

1. **单出口 I1**: 只有最下层写执行量 (引擎里 = `sched.decide()` + `safety.saturate()`); 上层只写参考槽 (`u_ff`)。
   接线后 `grep -c "u, stage = self.sched.decide("` 必须仍是 **1** —— 出口被复制/绕过即接错。
2. **收缩投影 I2**: `u = proj_{U_L2}((1−w)·u_L2 + w·u_up)`; 越界必夹紧并记账 (`clip_max`), 不许直接采信上层。
   可行域逐层收窄: `U_L2 ⊇ U_L3 ⊇ U_L4`。
3. **语义护栏 I3**: 见上 (类型强制)。
4. **稳定性判据 I4**: 选一个李雅普诺夫候选, 例如 `V = ‖peg/hand − hole‖² + w·θ_err²`,
   要求沿阶段**逐帧单调不增**; 改动前后**同 seed 两臂对照**, V 不升才算"导引有效"。

## 三·补、给上层换"喂什么进去"而不重训 (实测有效的一招)

需求"把 A 模型预测出的潜空间喂给 B 预测器"时, B 既然已经有训练好的权重, 维度又对不上,
**不要重训 B**, 而是标定一个**丛映射** `ẑ = A_map · z_pred + b` (ridge + LOO R² 闸 ≥0.3),
让 B 的输入维与口径保持不变, 只换数据来源。实测: z_pred(192) → ẑ7(7), R²_loso=0.607,
B 权重一字未改而"预测潜空间"真的进了执行链 (证据: 预测器输入来源字段 = `fiber(A·z_pred+b)`)。

## 四、加一条可选条件通道 = 数学上真零回退 (最易踩的坑)

- ❌ **concat 进既有 MLP 输入** (`torch.cat([z, a, m])`): 第一层对应输入列的权重是随机初始化的 →
  即使把 m 置零、门控置零, 输出也**不逐位相同**。"关掉就零变化"的要求会被当场戳穿。
- ✅ **独立 additive 分支 + 末层零初始化**:

  ```python
  z_pred = self.mlp(torch.cat([z, a], dim=-1))
  if m is not None and self.intent_proj is not None:      # m_dim>0 才建分支
      z_pred = z_pred + self.gate * self.intent_proj(m)   # proj 末层 weight/bias 全零
  ```
  `nn.init.zeros_(self.intent_proj[-1].weight); nn.init.zeros_(self.intent_proj[-1].bias)`
  → `m=None` 或未训练时增益恒 0, 输出**逐位等于旧实现**; 训练后打开才有影响。
- **取证 (必须做)**: 同一套主干权重下三态输出 hash 相同 —— 旧实现 / `m=None` / 给了 m 但零初始化:
  `hashlib.sha256(np.ascontiguousarray(x, dtype=np.float64).tobytes()).hexdigest()[:16]`
- **"通道是活的"取证**: 手工给末层加小随机权重 → 增益 >0 **且下游读数变化** (证明不是摆设)。
- **未训练时的纪律**: 线路**照跑出证据** (每帧真前向 + 来源标注 + 面板写"在跑 · 未训练 → 不注入"),
  注入权重 = 0; 绝不拿未训练的输出污染执行口, 也不许因为"没训练"就把线路悄悄关掉 (那是假接入的另一种形态)。

## 四·补、要"给在跑的系统加一层新视图/新叠加"时: 另开副本, 原件一字不改

用户口径(原话): 「保留原来的 3D 视图和仿真元素先不动, 你做一个副本, 叠加到 …」 —— 这是本项目的默认工作方式,
也是"零回退"最彻底的一种实现:

- **副本 = 独立规格段 + 独立流/页面**; 原页面、原流、原生成器**全部不动**(现场正在用, 碰它就是拿产线冒险)。
  已有同类管道就直接复用(如已有的 `ov_*` 叠加流) —— 副本的成本要花在内容上, 不是造一套新管道。
- 好处三件: ①可对照(原件 vs 副本并排取证) ②可回退(删副本即可, 不用回滚原件) ③不打断在跑的活。
- **副本必须在画面/标题上自报家门**(来源/模式/帧龄/是否已标定或为近似值), 否则现场会把副本当原件;
  交付时把"原件没动"当成一条实证说出来(原件文件 hash / 端点行为不变), 别只说"我另做了一个"。
- **不许为了"让副本出结果"去放宽原件上的闸门**(守卫/限幅/授权) —— 那是拿假结果换观感。
  副本缺条件时如实标"未标定 / 近似 / 未验证", 并在真值带里写清误差量级。

## 四·补二、给**在役节点**加旁路能力: 复用已有节点, 别新建重复的

用户说「把这个能力做到 L2 的 XX 节点」时, **先把现有节点清单拉出来** —— 常有同名节点早已存在,
只是层号是空串、实现没绑(实测「光学质量检测」节点一直在画布上, 没人给它分层)。新建一个只会得到
两个语义重复的节点, 而且旧的那个还接着线。

```bash
./gui-venv311/bin/python -c "
import sqlite3
c=sqlite3.connect('data/database/zmax/zmax_engineering.db')
for r in c.execute('select node_id,name,layer,exec_mode,impl_key,source from mw_node'): print(r)"
```

**分层标注三处必须一致**, 少一处就是「画布上看着是 L2, 代码里不知道自己是谁」:
模块常量(`LAYER='L2'`) · DB 字段(`mw_node.layer`) · 画布 JSON `params`(加 `layer_note` + 本次新能力的开关字段)。

**实现在原函数尾部加分支, 原通道一字不改** (同 §四·补 的副本思路), 并强制降级:

```python
def node_xxx(ctx):
    ...                                  # 原有通道原样保留
    try:                                 # 🆕 旁路
        r = _bypass()
        if r.get("ok"): _publish(r["signal"], log)
        else: log("旁路未启用: " + r.get("why", ""))
    except Exception as e:
        log("旁路异常(不影响主通道): %s" % e)     # 上游挂了不许拖垮在役链路
    return ctx
```

- 🔴 **旁路消费者一律 try/except 包住**: 它的上游可能是另一台机器/另一个服务; 挂了只能少一路数据,
  不能让整个节点抛异常。取证方式: 把上游地址改错重跑, 主通道输出必须不变。
- 旁路产物的话题/键用**独立前缀**(如「表面光学.」), 别复用原通道的键 —— 同名会在下游互相覆盖,
  而且看日志时分不清是谁发的。
- 自检盖四类, 不是「能 import」: ①分层三处一致 ②`impl_key` 能取到实现 ③真跑一次拿到结果与话题
  ④**上游不可达时优雅降级**。写成 `tools/verify_<node>.py` 打 N/N PASS 再交付。

🔴 **用户说「应该是 XX 节点负责这件事」时, 就是让你复用那个节点, 不是让你新建一个同类节点。**
实测: 新写一个「调度节点」并注册进画布被当场退回 —— 工艺规划本来就归已有的「测地线规划引导」节点。
正确做法: **把能力做成一个纯逻辑模块** (`nodes/<x>_impl.py`, 不碰硬件、不写运行文件), 由既有节点的 `run()`
调用并把结果挂进它的输出 (如 `out1.value.craft`), 原输出字段一字不改; 之前新注册的那个节点撤回。
好处: 画布拓扑不变 (用户手上那张图不用重连)、下游按老端口就能用上新字段、迁移时只有一个入口。

## 四·补三、推进器归属: 循环脚本只当定时器, 编排/推进必须落在规划节点

**判据**: 如果"下一步做什么"只写在 `tools/*_loop.py` 里, 那就是把业务策略放进了跑批脚本 ——
换机器/换入口就丢, 迁移时没人知道该搬哪一半。

- **分层**: `tools/xxx_loop.py` = 纯定时器 (每拍把所有节点 `run(ctx)` 一遍, 不读业务配置);
  **编排状态机 (任务→元任务→第几步) 在规划节点内**; 配置 (元任务表/段几何) 是 git 跟踪的真源,
  运行态 (当前步/进度/事件) 写 `ss_live/`, 两类不混。
- 🔴 **推进条件只能来自 L2 的执行反馈, 不能来自墙钟或"没消息就当完事"**:
  每步要同时满足 ①状态新鲜 (`age_s ≤ 2s`) ②没有被拦 (`blocked_by` 空, 含授权/位姿/安全闸)
  ③真到位 (`phase ∈ {arrived, done}` 或 段走完且残差 ≤ tol) 才推进一步; 否则 `hold` 并带 `why`。
- 🔴 **`idle` 不是"这一步做完了"**。把 idle 计入完成相位 ⇒ 首拍就从第 1 步跳到第 2 步, 一步没动就把
  整条元任务跑完 (实测)。只在"已发过这一步且拿到到位回执"时推进; 加 pending 时间戳, 超时报
  "等不到位 Xs" 仍然不往下走。
- **可迁移靠环境变量, 不靠改代码**: `ZMAX_REPO` / `ZMAX_<X>_CFG` / `ZMAX_<X>_STATE` 三个覆盖点;
  默认值从模块文件向上找 (`.git` + 数据目录同时存在才算仓库根)。envexport 了但文件不存在 ⇒ **明确报错,
  不许静默回退到默认路径** (静默回退会让换机后"跑的是另一台机器的配置"没人发现)。
- 判据写 `tools/<x>_selfcheck.py`, 至少含: 首拍 idle 不推进 · arrived 推进 · 被拦 hold · 状态过期 hold ·
  跨元任务切换 · **换路径照常推进** (临时目录一份配置跑同一份代码) · 配置缺失明确报错 · 引导节点确实输出该字段。
- **踩过的环境坑**: 仓库里若存在一个同名杂项目录 (如 `src/zmax_data/` 由相对路径误写产生), 向上找仓库根的
  逻辑会停在那一层。用"`.git` 与数据目录同时存在"双条件, 并把杂项目录归档走, 别只靠找目录名。

## 四·补四、总调度(仲裁)装进**已有调制器**, 不新开节点

"每拍对多层提案投票/否决/限幅"的总调度, 归属那个**同时握有各层提案 + 阶段机 + 物理闸**的模块
(本项目 = `state_space/cognition.py::ActionModulator`)。另开一个调度节点 = 把物理闸复制第二份 ⇒
两个真源, 迟早打起来; 画布上也不用重连线(节点 `source` 本来就指调制器)。

- **开关默认关 + 逐位零回退**: 仲裁器挂 `self.orch`, 环境变量未开则 `None`, `decide()` 走原路径。
  取证不能只跑语义用例: 关态输出要与改动前**逐位相同**(`np.array_equal`, 几十例随机输入), 不能只看“看起来没变”。
- **缺层按在场层归一化, 不补零**: 某层没提案(全零/没注入)时**不参与权重配比**, 否则有效层被 0 层稀释;
  遥测里照实写 `layers=[...]`, 绝不拿零向量冒充大模型在场。
- **物理限幅只有一份**: 仲裁只做"谁说了算 + 权重融合", 阶段限速与技能物理约束仍走原模块, 不复制。
- **力阈值按现场红线, 不照抄文档**: 接触检测阈值(如 2N 保护镀层) ≠ 插入力红线(如 40N), 阶段表要分开写。
- **入参要真接电**: 仲裁器的 `force_n` / 相位量给了默认 `None` 的新入参只是"通了线", 引擎调用点不传就等于没通电 ——
  汇报必须写"已通线未通电", 并列出差哪一步。
- **调度状态机也属于这里, 不属于入口脚本**: 用户说"程序入口应该是一个状态机"时, 真正的意思是
  「阶段/转移/每段策略只有一份, 住在同时握着提案与物理闸的调制器里」; `tools/*_loop.py` 只做节拍器。
  新建 `state_space/scheduler_fsm.py`(STATES + POLICY + 守卫), 策略表同时是仲裁器权重的唯一真源; 旧内联推进
  逻辑保留在 `ZMAX_FSM=0` 分支当对照臂, 用"同观测序列逐拍对拍"证明没改行为。
- **入口文件与引擎分开, 且要能分清"入口"和"装载点"**: 正式入口放 `src/<pkg>/engineering/start.py`,
  只做四件事 —— 打状态集合/策略表、装每拍钩子、单实例锁、优雅停机; 工程本体(节点图)是在引擎
  `load_project()` 读画布 JSON 那一刻装载的。用户问"这是总的工程入口对吧"时按两层回答:
  **入口 = start.py, 装载点 = 引擎的 load_project()**, 别把执行腿说成入口。
- 🔴 **状态机必须进程级单例, 注册表挂 `builtins` 而不是模块全局**: 调制器每拍 `new`(`mod = cog.ActionModulator()`)
  ⇒ 状态跟着重置, 永远停在首状态; 而同一文件既被包导入又被 `spec_from_file_location` 按路径加载时是**两个模块对象**,
  模块级全局互通不了 ⇒ 症状是"引擎日志已经把状态推到抬起, 入口一行切换都不打"。两个坑不修, 状态机就是"看着有、实际不懂"。
- **入口的两条生产纪律(交付前必须补)**: ①`flock(LOCK_NB)` 单实例锁 —— 两个入口 = 两个状态机, 会双写状态文件
  并抢派发宿主(`dispatch_inproc.owner` 只认一个), 现场表现是"一会儿动一会儿不动"; ②SIGTERM/SIGINT 打一行再退。
  取证: 起第二个被拒并打出持有 pid、`kill -TERM` 能看到停止行、退出码 0/2/130 有意义。
- **入口自己的话必须写 `sys.__stdout__`**: 引擎降噪会把 `print` 重定向进日志文件(本项目 `/tmp/ss_canvas_loop.log`),
  否则 F5 后终端一片空白, 用户以为没启动。

## 四、六查探针 (照抄这个结构, 每查都要有机器可判的判据)

| 查 | 判据 |
|---|---|
| A 零回退 | 三态输出 hash 相同; 未训练增益 = 0.0; 训练后增益 >0 且下游变化 |
| B 收缩性 | 5000 组越界参考 → 0 违规; `w=0` 时逐位等于下层原值; 层语义护栏真抛异常 |
| C 接口真跑 | 意图 → 预测器 → (流形式/中间读量) → 动作头 → u 非零且带来源 (随机权重只证"通") |
| D 判据自检 | 单调序列判通过 / **注入一次回升**必须被抓 (证明检查器不是恒真) |
| D′ 判据**自身**的口径 | 每条期望值先用**手算小例**核一遍; 报「失败」先怀疑判据, 再怀疑实现 (见下) |
| E 上层字段 | 新字段有值带来源; 被排除的阶段**诚实拒绝**; 老字段一个未变 |
| F 引擎接线静态 | 方法在位 / 环境守卫在位 / 融合调用在收口之前 / 唯一出口计数 = 1 |

⚠️ **静态自检 ≠ 运行时联调**。汇报必须分开写"接线已证 / 运行时未联调 (需开控制台)"。
点击自检、双击节点、只测形状与有限性, 都不算接上。

🔴 **自检报失败时, 先查判据口径, 再查实现** —— 实测一批 8 条判据里 **5 条是判据自己写错**, 实现是对的:
- 实现返回 `round(x, 6)` 而判据按 `1e-15` 比精度 ⇒ 永远不相等(不是实现不准, 是精度口径定错);
- **上界抄错**: 不同流形的弧长上界不一样(一个 π、一个 π/2), 混用就把合法值判成越界;
- **符号取两次**: 实现已返回 `-∇Φ`, 判据又取一次负 ⇒ 方向永远反;
- **拿 A 模式的输出去验 B 开关**: 功能根本没打开, 判据当然失败。

⇒ 每条判据都必须能说清"这个期望值是怎么算出来的"(手算小例 / 定义式 / 上游文档)。
说不清的那一条**删掉也别留着** —— 一个口径错的判据会把真实现报成 bug, 白查一下午。

## 五、汇报模板 (三段分开, 不许一句"打通了"盖过)

> 接线段: 逐条给 hash / 计数 / 夹紧量 (可复现命令)。
> 质量段: 模型是否**已训练**; 未训练就写"不注入, 指标待训后出 (R²/LOSO 闸值 ≥0.3 之类)"。
> 闭环段: 未跑就写"未跑"。

## 五·补、把每层输出显示成一个可读量（分层力 / 合力）：读数必须能逐层追溯到真源

用户会要求“每层的力/贡献 + 合力都显示出来，能看出哪层真在算”。做法上把它当成**投影 + 加权**，
不是再写一套物理：

1. **每层只读自己的真源**，取不到就 `vec=None` 且 `src` 写清缺哪个文件/字段；界面上画空槽 + 「缺」，
   绝不用别的层、上一段 rollout 回放、或 0 冒充。每格 `src` 带文件+字段（可逐格对账）是这类显示能信的底线。
2. **权重在矢量层乘一次** (`v = w·k·v_raw`)，之后四元数/合力/表格/各视图全用这一份；
   显示层再乘一次 = “表里对、图上不对”。`w`/`k` 放配置文件里热生效，别写死在代码。
3. **主力 = 加权后模长最大那层**，不写死。但各层原始量级天然不同（动作头常是前馈的 ~2 倍）⇒
   不调 `w` 的话“你以为的主力”根本不是主力；改 `w` 后要重跑所有依赖“主力是谁”的判据。
4. **量纲不同的层必须各自给一个 `k` 换到同一当量**：无量纲输出（方向×置信度）直接入场就会压过执行量，
   乘一个明确的当量系数并在配置里写理由。
5. **别拿差矢量（规划−前馈）当“力”**：差矢量常与运动反向 ⇒ 合力翻向（实测主力↔合力 123°）。
   张量要作用在**主导矢量**上（`F = M̂·u`，`M̂` 夹在 0.5~2），这样它是“同向缩放项”，合力才稳定。
6. **档位发布 vs 真源在跑 冲突时以真源为准**：上层（GUI 点选）的档位只活在它自己的文件里，
   层实现可能是**独立进程**在跑 ⇒ 只看档位会把正在算的层清空。两个都要看，并以“真源 fresh”覆盖档位。
7. **同一矢量多处显示必须共用一个投影/取数函数**；两处各写一份公式迟早分叉，且用户一眼就能看出
   “两个地方方向不一样”。判据用“扰动视角/参数后两处同步变化且仍相等”来证明同源（详见 `pyqt-gui-auto-verification`）。

## 六、落地顺序 (最便宜的线先上)

0. 诊断档位互斥 → 定契约与不变量
1. 下层消费者加**可选条件口** (additive + 零初始化)
2. 上层解码器输出该条件 (老字段不动, 新字段带来源与门控)
3. 仲裁模块 (契约类型 / 收缩投影 / 记账 / V 检查) —— 纯 numpy、可单测, 不依赖引擎
4. 引擎接线 (环境变量守卫; 不设 = 逐位零变化)
5. 六查探针 + 报告落盘
6. 训练该通道 → 出质量指标 → **同口径两臂 A/B** (开/关) 才允许进默认档
7. 再往上叠下一个专家 (接口最齐的那条先接, 如已有 `φ_ref` 入口的姿态/偏航专家)
