# 文档目录重组（不改坏引用）

## When to Use
- 用户说「文档太乱 / 精简 / 科学分类 / 别超过 N 个文件夹」。
- 要把散落的方案、记录、交付件归位，或合并重复目录。
- 目录重排会牵动代码里的硬编码路径 —— 这才是真正的风险点，不是搬文件。

## 先判：是分类问题，还是联系问题

用户说「文档太多 / 太乱」时，先量三件事，再决定动不动目录：
1. **骨架是否已经跟产品同源**（七颗星 / 配置类别 / 菜单结构）。已经是了，就不要再重排一遍。
2. **文件构成**：`find docs -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn`，再按二级目录数一遍。
   常见情况是 70–90% 的文件其实是 `skills/`、`memory/` 这类外部工具**镜像**，真正的本体文档只有几百份 ——
   「太多」的体感往往来自镜像，不是文档本身。
3. **交叉引用**：有没有任何地方能回答「这个功能落在哪个节点、哪份代码、哪件专利、哪些文档」。

骨架对 + 镜像占大头 + 文档之间互不指向 ⇒ **这是联系问题，不是分类问题**。
此时重排目录是纯亏：几百个文件搬一遍要牵动几百处硬编码路径（真实数字是几百处，不是几处），
换来的只是「看起来整齐」，缺的东西一点没补。

### 联系问题的正解：加一层索引，不搬文件

新建 `docs/0-索引/`（目录页，**不算第八颗星**，别去动用户定的上限），里面放 2–4 个**现算**出来的索引：
- 正向：核心轴 → 落地轴逐段 join，例如「专利 → 功能条目 → 画布节点 → 源码 → 文档」。
- 反向：节点 / 文档 → 属于哪件专利；并单独列出「没有任何上层覆盖」的条目 —— 这是索引最有价值的产出。
- `index.json` 机器可读 + 一个生成器（放 `tools/`），跑一次全量重建，禁止增量手改。

三条硬规矩：
1. **索引必须现算**。手写的索引在第一次加文件、改配置之后就骗人，而读者还会信它。
2. **零搬移**。索引里的路径运行时求；明天别人搬了目录，重跑一遍就自动跟上。
   正因如此，和另一台机 / 另一个 agent 并行重构也不冲突：**对方的结构优先**，你只保留索引层和生成器。
3. 入口各加一行指针（`docs/README.md` 顶部、必要时各星目录），否则没人找得到索引层。

交付汇报：`专利 N 件 / 节点 M 个 / 已覆盖 x 个（y%）/ 无覆盖 z 个 / 本体文档 k 份 / 已关联 v 份`，
外加**索引暴露出来的两条真问题**（无上层覆盖的条目、真源之间对不齐的字段）。
索引的价值就在于把「以前没人回答过的问题」问出来，而不是把文件摆整齐。

## 定骨架：先找产品自己的分类，再自己发明
1. 仓库里若已有**产品自身的分类真源**（配置中心的配置类别、菜单结构、配置页签），
   **直接按它分类，并标明同源**（`唯一依据 <module>.py`）。自己发明的分类会和产品界面打架，用户第一次就会问「为什么不跟配置中心一致」。
2. 顶层文件夹数量**照用户给的上限**（常见是 7 —— 与配置体系的星/类同源）。超了就合并语义最近的，而不是新增一层嵌套。
3. 目录名带序号 + 职能前缀（`1-<星名>-<主司>/`），让人按序号背得出结构。
4. 允许目录内保留原有子目录名（`deliverables/` `memory/` `skills/` `test-reports/`），
   这样**大部分引用只需改前缀**，不必逐文件改。

## 搬之前先量引用
```bash
# 不同路径数 / 出现次数 / 按顶层分布
grep -rn "docs/" --include=*.py --include=*.json --include=*.sh tools/ src/ config/ | wc -l
```
- 统计两种形态，**都要覆盖**：
  ① 字符串形态 `docs/<old>/<file>`；② 拆参数形态 `os.path.join(ROOT, "docs", "<old>", ...)` —— 只改 ① 会让 ② 在运行时报 `FileNotFoundError`。
- 还要覆盖裸目录 / 通配 / 注释里的路径：`docs/<old>/`（无文件名）、`docs/<old>/*`、`docs/<old>/<prefix>_*.md`。

## 步骤
1. **写一个映射脚本（只读预览先行）**：把「旧相对路径 → 新相对路径」逐文件算出来，打印每类的文件数与样例，人过一眼再 `--apply`。
   分类规则用「文件名关键词 + 原父目录」两段判定，命中即停；兜底归到最大的那一类（通常是「工程落地」）。
2. `--apply` 用 `os.replace` 搬文件，同时落一份 `<old> → <new>` 的 JSON 映射表（放 scratch，别进库）。搬完**删空目录**（`find -type d -empty` 或脚本判断）。
3. **改写引用**，按「长的先替」排序，再补三类兜底：
   - 逐文件：`docs/<old_file> → docs/<new_file>`
   - 目录前缀：`docs/<old_dir>/ → docs/<star>/<old_dir>/`
   - 裸串：`docs/<old_dir>` → 带新前缀（否则 `docs/memory` 这种会漏）
4. **逐个处理 join 形态**：正则 `(["'])docs\1\s*,\s*(["'])([a-z_\-]+)\2` 命中已知旧目录名时插入新前缀元素。
   🔴 单独跑这一遍时要**放宽「文件里有没有 `docs/`」这个前置过滤** —— 只用 join 写法、没有斜杠串的文件会被整体跳过（实测漏掉 8 个文件/15 处）。
5. **修完再扫一遍缺文件**：把所有 `docs/<path>` 字面量抽出来，逐条 `os.path.exists`；不存在的按 basename 在树里唯一定位回填。
   这一步会顺手修好**本来就指错**的历史引用（实测 243 处），交付时说一句。
6. **别让路径漂移把子目录吃掉**：整目录级映射时容易只保留末段（`docs/skills/x` → `docs/<star>/x`，`skills` 没了）。
   扫法：`3-<星名>/(?!skills)` 这类反向断言，命中就补回缺失段。
7. 校验与提交：`py_compile` 所有改动过的 `.py`（只编存在的文件，`git status` 里的旧路径会报 ENOENT）→ 跑 1~2 个能真读到新路径的功能脚本 → 全量 grep 旧路径应为 0 → 提交 + 推送。

## 单一真源文件用软链保双引用
- 同一份文件被**两处代码各按不同路径**引用时（台账、状态 JSON），真源放语义最对的目录，另一处放**相对软链**：
  `ln -s incidents/INCIDENT-INDEX.md docs/<star>/INCIDENT-INDEX.md`。git 记 mode `120000`，两处代码都不用改。
- 两份同名文件内容不一致（一个新一个旧）时**必须合并**，别留两份继续各自被引用。

## 目录里既有镜像又有证据时
- 镜像目录（`skills/`、`memory/` 来自外部工具的导出）**只改前缀不改内容**；同步脚本的 DEST 路径要跟着改，并在 README 写明「要改改源」。
- 证据快照目录标「按日期冻结，只增不改」；测试报告目录若被校验脚本按路径断言，写明「缺文件即判 FAIL」。

## 交付件目录收口（扁平 80+ 个文件 → ≤10 项）

用户说「交付件太乱 / 合并精简 / 按文件夹分类，不要超过 N 个」时的固定做法：**按文档类型分，不按版本号分**，
顶层 = ≤9 个类型夹 + 1 个 `README_INDEX.md`（索引也算一项，别忘占位）。

- 典型骨架：产品方案 / 机器人方案 / 供应商SOR / 交付包-<场景A> / 交付包-<场景B> / 立项与协议 / 配置与测试 / 工程手册。
  分类依据写进入口 README（一句话归属判定 + 版本口径 + “新版覆盖旧版时旧件去哪”）。
- 🔴 **版本 token 有两类，处理的动作相反**：
  - **产品档位**（`5.50.A/B/C`）= 不同机型/不同配置，正文可能真不同 ⇒ **各留一份**，删了就丢内容；
  - **发布号**（`5.50.5` / `5.50.758`）= 同一份文档的不同代 ⇒ **只留最新**，旧件归档。
  搞反的两种后果：把某档文档删掉（丢内容），或留着 3 份 99% 一样的 SOR（用户当场再让你精简一次）。
- 🔴 **相似度判重前先做 token 归一化**：同一文档换发布号往往只差表头（版本串 / 生成时间 / git HEAD / `20261013`）。
  原始 `difflib` 会给出 0.90~0.96 ⇒ 误判“不同”。先把 `\d\.\d+\.[A-Za-z0-9.]+`、`v?\d+\.\d+\.\d+`、
  `20\d{6}`、`20\d\d-\d\d-\d\d[ T]\d\d:\d\d:\d\d`、`\d+(\.\d+)?\s*(分钟|min|s)` 统一替换成 `<v>` 再比，阈值 **0.995**。
  归一化后仍低（如两份 INDEX 只有 0.20）= 真是两代不同文档，保留并在索引里标“新版取代 X”。
- **同族同扩展名才比**：`交付文档_插拔.md` 与 `.json` 是同一份的两种格式，**都要留**（人读 / 机器读），
  家族键 =（去掉版本号的 stem, 扩展名）。
- **打包件（`.zip`）不进交付目录**：都是能从 md/json 重打的生成物，一律归档，索引里注明可重打。
- 🔴 **同时改生成脚本的输出路径, 否则下周又堆回来**: 负责出 PPT/PDF 的构建脚本 `OUT_PPT/OUT_DIR`
  直接指向交付位 (`docs/<星>-产品边界/deliverables/<类型>/`); 旧路线的脚本不要删, 把它的输出改到
  `zmax_data/tmp/legacy_<x>/`。只搬现有文件而不管生成端, 同样是重复劳动。
- **顺手清两种垃圾**：LibreOffice 锁文件 `.~lock.*#`；断链软链（`find docs -xtype l`）—— 后者会让 glob 扫树时直接读崩。
- 搬完仍按上一节做引用改写 + 逐条核存在性；但 `A.md/.docx` 这种**拼写残缺的引用**、以及已经归档的附件路径，脚本改不了，
  要去扫一遍“悬空引用”报告手工落到真实路径或归档位（并在索引里指向归档位，别留死路径）。
- 汇报口径：`之前 N 项 / M 文件 / X MB → 现在 n 项 / m 文件 / Y MB`，+ 归档去多少份及归档目录 + 悬空引用 0。

## 坑
| 坑 | 症状 | 修法 |
|---|---|---|
| 只改字符串引用 | 运行时 `FileNotFoundError`，grep 却查不到旧路径 | 先把 `os.path.join("docs", "x")` 形态统计干净，单独一遍修 |
| 逐文件替换器加了 `if "docs/" not in text: continue` | join-only 文件静默漏改 | 前置过滤放宽到 `"docs"` 也命中 |
| 目录级替换吃掉中间段 | `docs/<star>/xspace`（少了 `skills/`）| 反向断言扫一遍补回 |
| 搬完留着空目录 | 顶层还是十几个「看起来还在」的空壳 | 搬完删空目录，再用 `search_files (target='files')` 数一遍顶层 |
| 只搬不改文档内部互相引用 | `.md` 里链到旧路径，点进去 404 | 把 `docs/**` 也纳入改写范围 |
| 认为「历史文档不许改」 | 旧路径在交付件里，读者点不开 | 路径引用可以改写；日期冻结的是内容事实，不是路径 |
| 搬移脚本走 `os.walk` 默认跳过 `.` 开头目录 | 隐藏子目录（`.archive/`、`.curator_backups/`）整批留在原地 | 搬完对比两边文件数，不等就 `rsync -a` 补搬再删源 |
| 权限不允许覆盖（root 属主的 unit/json） | `PermissionError` 中断整批改写 | 逐文件 try/except，失败的用 `sudo cp` 落地并打印清单 |
| 把产品档位当旧版本删掉 | 用户追问“B 档那份呢”，内容已丢 | 档位（.A/.B/.C）各留一份；只有发布号（.5/.758）才是新旧 |
| 拿原始相似度判重 | 只差表头的两份文档被判“不同”，数量不降 | 先归一化版本/时间/git hash 再比，阈值 0.995 |

## 汇报口径
交付时说三件事：**新结构（几类/几个目录 + 每类文件数）/ 改写与核过多少处引用 / 还剩什么**（未解的历史引用、需重建的镜像）。
不要贴迁移过程。
