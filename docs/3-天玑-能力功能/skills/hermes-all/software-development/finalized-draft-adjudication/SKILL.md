# 收到「定稿/评审稿」怎么接

## When to Use

- 用户以「审查员 / 研发总监 / 客户评审」身份返一份完整定稿，要求「你据此修改」
- 拿到一份声称已定稿的文档（交底书、技术协议、方案、计划），需要落地到代码/系统
- 文档里的数字、公式、结论要拿去对外（代理所、客户、投标）

核心矛盾：**照抄等于把别人的错一起交上去；全盘顶回去等于不干活。**
正确姿势是分层——**采纳绝大部分、逐条核对、对错的那几处用文档自己的逻辑反证**。

## 铁律

### 1. 每条声明都要有「落点 + 实测」，指不出来就补实现或删声明

定稿里写的每一条（权利要求、指标、机制），交付前必须能同时指出：

- **实现落点**：哪个符号/文件真的实现它（符号必须真存在，不是「应该在那」）
- **实测证据**：哪个脚本/哪次运行真的跑出了这个数

指不出来的只有两个选择：**补实现** 或 **删掉该条**。**不能留着当「纸面声明」**——
文档里有一条没实现，整份文档的可信度就没了，而且用户一追问「实际怎么执行的」就现原形。

架构性声明（「无需重训」「系统包括…」这类跑不出数值的）用**结构检查**代替数值实测：
签名里没有 model/weights/net、模块不 import 训练框架、接口同时接受两路输入。

配方（逐条核对的脚本骨架 + 断言写法）见 `references/claims-to-code-verification.md`。

### 2. 文档里的错，用文档自己的推导反证——这是唯一无法被反驳的驳法

说「我觉得不对」没用（对方是审查员，你是实现者）；但说「按你这个式子，你自己的结论不成立」无法反驳。

方法：在文档里找那个**只有符号/方向/量纲正确时才成立**的等式（稳定性证明、守恒律、收敛条件），
把错的那一处代进去，看它是否与该等式冲突。

实例（可当模板）：文档写「接触力是排斥力 ⇒ ∇V ∝ −F」，而它自己的稳定性证明是
`V̇ = −α·∇VᵀM⁻¹∇V ≤ 0`。代进去：符号取反则 `V̇ > 0`，与该节结论自相矛盾 ⇒ 符号被该式唯一确定为 `+F`。

给出结论时三件套一起给，不要只给结论：**物理/数学理由 + 文档自身矛盾的引文 + 反向的数值反例**
（「偏 −0.40mm、F=(−2.4,0,0) ⇒ 按 −F 越修越偏」）。

### 3. 不要因为定稿条数少就砍掉工程上真有支撑的条目

定稿常比工程现状**少几条**（漏掉已有实测的机制）。保留并说明理由，比机械对齐更有价值；
但每条新增都必须是代码里真跑得出来的，不能借机夹带未验证的东西。

### 4. 对外脱敏是交付动作，不是「记得删一下」

提交版正文 **0 处内部路径**；把「代码实现结构」换成**功能模块职责表**（只说职责、不说文件）；
落点表迁到内部归档文档（如 `patents/README.md`），可追溯但不外发。

验收必须命令化，靠眼睛一定会漏：

```bash
grep -cE 'src/|tools/|\.py' <交底书>.md      # 必须是 0
```

### 5. 被取代的版本归档，并清掉主目录里旧文件名的产物

新旧版本往往**不是同一个文件名**（改标题就换了名）。只归档 md 会留下主目录里旧名字的 docx/pdf
一直冒充现行版。归档后回读目录：`ls <编号>*` 应只剩一份源文件 + 一份成品。

`.gitignore` 通常排除 `*.docx`/`*.pdf` ⇒ 成品只在本机，交出去要手动拷，别以为 git 里有。

### 6. 附图：必须验到成品里，不能只看生成日志

文档要图时，图**落盘 + 在正文引用 + 真的嵌进成品**是三件事：

```markdown
![图1 几何投影](./figs/013_fig1_geometry.png)   # 路径相对 md 所在目录
```

- md→docx 的转换器**常常不认 `![]()`**：照样打印 `OK ... bytes`，但成品里 0 张图。必须加
  `add_picture` 分支（`Inches(5.9)` + 居中；缺图写红字提示，不要静默跳过）。
- **验收看容器结构，不看字节数**：`zipfile.ZipFile(p).namelist()` 里数 `word/media/`，
  图进了才算成（字节数只能当提示）。
- 图内文字用**英文标注**（`DejaVu Sans`），中文写进 md 图注。中文字符串直接进图会因缺字体变方框。
- 同一套图要可重生成：写成 `tools/make_<编号>_figs.py`，别手拼一次就丢。

## 交付时怎么说话

先给「采纳了什么」，再给「我反对哪一处、为什么、改成什么」。不要先铺垫过程。
反对项要单独成段并给出可复现的反例数字——用户要的是能拿去跟对方对话的弹药，不是态度。

## 坑

1. **把「定稿」当成免检**：定稿是**对方**的完成度，不是你的验收结果。核对一次的成本远低于对外被问住一次。
2. **核对脚本跟着文档一起错**：断言写死了文档里的错误期望值，于是「测过了」等于没测。
   断言必须来自**独立推导**（物理/数学）或**参照实现**，不能来自被检文档本身。
3. **数值算重复**：判「放大倍数比」这类量时，若已经取了范数之比，就别再平方一次
   （实测把 400 算成 160000）。每写一个比值断言，先手推一遍量纲与数量级。
4. **测试场景自己设错**：构造对照实验时轴与力同向，会被径向投影全部剔除 ⇒ 修正恒 0，
   看起来像「算法失效」。先确认实验几何与算法假设一致，再怀疑算法。
5. **0 检出 ≠ 检测器有效**：判据报「无问题」时，用一条**已知故障样本**回放证明它真能判出问题，
   否则「没查出来」和「查不了」分不开。
