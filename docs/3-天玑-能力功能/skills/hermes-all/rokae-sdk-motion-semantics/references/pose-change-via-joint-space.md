# 改姿态：为什么不能直接下发 rpy 增量

## 结论
姿态改动一律走关节空间：URDF FK → 在关节目标上改 → IK → `MoveAbsJCommand` 下发。
CartesianPosition 可用来下发“已经验证过的平移”，也可用控制器回读的实测 rpy 原样回传；
**但不要自己对 rpy 做加减运算再下发**。

## 两个独立原因
1. **表示歧义**：欧拉角在 ±π 附近同一旋转有多种写法。实测：期望只转 15°，回读却差 180°；
   把“弧度”当“度”再试一次，TCP 直接跑掉 25mm。先验同一姿态的旋转矩阵夹角，再谈增量。
2. **旋转中心错**：固定法兰位姿、只改姿态 ⇒ 工具尖画圆弧，弧长 = 工具长 × sinθ
   （实测 259mm × sin12° ≈ 54mm），这正是“只想转一下看看”结果撞上工装的原因。
   要“绕工件点转”（相机盯着同一点扫视），必须同时平移法兰：`p_flange = p_tcp − R_new·[0,0,L]`。

## 每段必带的三个判据
- `|ΔTCP| > 25mm` 停（姿态动作应几乎不动点；超了就是规划错了）
- 关节误差 > 1° 停（下发后没到位）
- `|ΔF| > 25N` 停，并 `stopOverlay + fcStop`
分段执行、每段落盘日志（每段实测偏差），下一次才拿得到“这个角度变化”的真实代价。

## 可达性
大俯仰在腕部限位会先撞死：实测 +8°/+10° 的 IK 误差到 110mm / 13.8°，表现为“下了指令臂不动”。
种情况应当**判别式停手**（下发了但位置没变 ⇒ 立即回退），不要重试加大幅度。
要更大角度先沿轴退 40mm 绕开限位，再转。
