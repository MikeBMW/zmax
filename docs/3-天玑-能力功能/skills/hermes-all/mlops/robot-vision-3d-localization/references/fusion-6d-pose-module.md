# 融合模块: 2D 检测 ⊕ 2D→3D ⊕ 状态反馈 ⇒ 工件 6D 位姿 (可交付版)

适用: 用户要求「融合模块根据 2D 检测、2D 转 3D、状态反馈信息输出 3D 位姿」, 并要它成为
统一状态空间的一等输出。参考实现: `src/lerobot/policies/left_right/state_space/perception_fusion6d.py`
+ 服务 `tools/peg_pose_server.py` (JSON `/peg_pose` · 叠加图 `/peg_pose.jpg` · `/healthz`)。

## 1. 三路输入各自负责哪个轴 (这是设计, 不是调参)

| 输入 | 强项轴 | 弱项轴 | 典型 σ (mm) |
|---|---|---|---|
| 2D 检测 (框中心/长轴) | 图像内 x·y | 光轴方向的深度 z | 6~8 |
| 2D→3D (深度近层 + 内参 + 去畸变) | 相对位置 | 经外参到基座后 z 偏 | 8~10 (+外参系统项) |
| 槽位几何 (状态反馈) | y (排布)·z (槽底+半高) | x (模块可能掉头) | 8 / 4 / 40 |
| 夹持 TCP 真值 (状态反馈) | 全部 | — | 2 |

⇒ **逐轴 1/σ² 加权**, 不要一个标量 σ、不要先算一个「综合误差」。合成 σ 用
`1/sqrt(Σw)` 给用户报, 门限用马氏距离。

## 2. 2D→3D 与姿态的具体做法

1. 框内深度取 **3~35 分位**当「最近层」(工件顶面), 不是中位数(含背景)、不是最小值(含飞点)。
2. 像素先 `cv2.undistortPoints` 再反投影 —— 有畸变系数时省这一步, 误差随距离放大。
3. 深度单位实测量级 (D405 = 0.1mm/unit): `raw 3044 ⇒ 304mm`; 按 1mm/unit 算会得到 3 米外的荒唐框。
4. 姿态: 框内暗区 `minAreaRect` 的长轴方向 → 同深度取两点 → 相机系方向向量 → 
   `R_cb.T` 转到基座 → **把 z 分量清零后再归一** (工件躺在槽里, 长轴必在水平面内; 这条约束比自由 3D 旋转强得多)。
5. 符号: 图像 +v 向下 = 相机 +Y。用户定义的原点在**金手指/连接器端**, 而那一端在图像下沿 ⇒
   X 轴(原点→体)必须指向图像上方 ⇒ `dir_cam[1] > 0` 就取反。
6. 原点换算: `origin = body_center − (L/2)·X̂`; 顶面质心先减 `H/2` 降到体中心。
   用户若说「抓取时模块坐标系 ≡ tool1」, 那 `L/2` 的方向必须与抓取时 tool1 的 +X 一致, 否则每次抓取差半长。

## 3. 在线偏置估计 (外参不可信时唯一能救的一手)

4 点平面 PnP 解出的外参在 3D 上可偏 60mm (z), 但重投影只偏 1~14px —— 两者不矛盾, 是平面 PnP 的
深度弱约束。做法: 槽号已知时 `e = meas − prior_slot` 就是一个偏置样本, EMA (α 0.25 首帧后 0.2),
σ_bias = 60/sqrt(n) 下限 3mm, 用它修正后续测量。

⚠️ 这条也意味着:**偏置样本数一多, 测量就被拉到先验上**, 详见第 6 节。

## 4. 槽号自推断: 在**像素域**比最近, 不在 3D 域

把 14 个槽位体中心用外参投到图上, 与检测框中心比像素距离, ≤70px 才认。
实测: 槽10 = 34.9px, 槽11 = 57.9px ⇒ 判对; 同样的候选在 3D 域比距离时
`差 57mm vs 64mm` ⇒ **判错槽** (60mm 的 z 偏置把排序带偏了)。
槽距 ≈48mm ≈70px, 而重投影误差只有 1~14px ⇒ 像素域排序可靠。

## 5. 退化路径 (缺哪路都要能跑, 但必须标出来)

| 缺什么 | 输出 | 标记 |
|---|---|---|
| 无外参 | 只有相机系测量 | `info.why = 无外参(仅相机系)`; 不参与融合 |
| 无深度点 (<150) | 先验或 invalid | `valid=false` |
| 无检出 | 槽位/上一帧先验 | `src=prior_slot/prior_last` |
| 测量与先验马氏距离 >9 | 先验 | `src=gated` (明确判测量失效) |

原则: **宁可输出「无效」, 也不输出一个看起来合理但错的位姿** —— 下游会当真值用。

## 6. 🔴 验证陷阱: 拿它锚定的先验打分 = 循环论证

槽号已知时输出≈槽位先验; 在线偏置又把「测量−真值」的均值吃掉 ⇒ 拿槽位真值打分得到
`0.20 ± 0.34mm` 是**定义上的必然**, 不是视觉精度。同一套代码的**独立精度 = 偏置量级**
(实测收敛后 x 6mm · y 17mm · z 33mm)。

必须用**与先验无关**的真值验证, 二选一:
- 抓起来 ⇒ 位姿 ≡ tool1 真值 (0.1mm 级), 与融合输出对账 (需要动臂授权);
- 把工件**摆偏离槽位 30mm 以上**再量 (脱离先验锚点)。

报数时先写一句「这个 0mm 是先验对先验」, 再给独立证据 —— 否则等于把标定误差洗成精度。

## 7. 叠加图要投“状态里的那个位姿”, 不许补偏置

画图时补偏置会让白点落在模块正中, 好看但对不上状态; 直接投状态位姿, 60mm 外参偏置会以
~25px 偏移**肉眼可见**地暴露出来, 并在角标注 `bias x,y,z mm`。用户看的是图, 图必须等于数。

## 8. 更新率与检测率解耦 (CPU 被占时)

YOLO 在 CPU 上 848×480 实测 **2.2~3.0s/帧** (GPU 已被其它进程吃满时)。别因此把整条链拖成 0.3Hz:
把「检框」与「算位姿」拆开 —— 框每 2s 刷一次, 深度+融合每帧重算 ⇒ 服务 10~22Hz, 输出角标写
`box_age_s`。托盘静止时框 2s 不刷够用; 工件在动就把刷新间隔调小。

## 9. 标定文件单位自检

`handeye_tool1_cam.json` 里 `tvec` 是 **mm** (|t|≈650), 模块内部一律用 m ⇒ 载入时按量级判:
`|t| > 10 ⇒ /1000`。判据: 相机光心到基座原点的距离应在 0.3~2m; 若反投影出 60 万 mm 的坐标,
就是漏了这一步 (实测 gate 距离 650618mm 才发现)。

## 10. 状态空间落点

- 位置 `peg_xyz = [4:7]` (m); 姿态 `peg_quat = [51:55]` (wxyz, 全 0 = 未观测)。
- 写入一律 `SLICE[name]` 按名取, 消费端不许数下标; 旋转塞进 `4:7` 曾产出 9.9m 鬼值。
- 改 `spare` 段这种契约变更要跑 `tools/verify_state55.py` 回归 (19 段首尾相接覆盖 0:55)。

**「预留段正式定义」是合法动作, 不是偷借** (四元数恰好 4 维, 对上 `51:55` 的备用 4):
- 只改 `Segment(...)` 的**名字/单位/来源/注释** (记一句「原 spare · 改版日期 · 为何不占更多维」), 段数仍 19、
  0:43 在役口径一字不动 ⇒ 老数据补 0 后零扰动。
- 语义写两种: 有效 `‖q‖∈[0.99,1.01]`; 无效写**全 0**, 不是单位四元数也不是上一帧。消费端用前必须查范数。
  (全 0 被当单位四元数会静默当成「没转角」, 这是最隐蔽的假数据。)
- 位置与姿态分开占段: 精度差一个量级 (mm vs deg)、代价不同、可异步降频, 混一段就无法各自判有效。
- 🔴 改前先 grep 同名段的所有**写入点**: 曾有一份模块把工件坐标写进 `[18:21]` (关节速/prev_hand 段),
  真段 `4:7`/`22:25` 反而永不进城 ⇒ 训练泄漏。过时的 `perception_yolo._SEG` 以 `perception_3d` 与
  `unified_state55` 为准。

## 11. 下游消费: 规划/引导节点只输出**一个**目标位姿

融合位姿的价值在于被动作层消费。常见错法: 引导节点每拍输出 `tcp + u·step`(下一小步)、姿态用当前 TCP 旋转
⇒ 一个周期出现 N 个不同位姿, 下游不知道"最终要去哪抓", 而且姿态与工件朝向无关。

契约五条:
1. **一个周期只有一个目标**: `target_pose = {pos(m), quat(wxyz), approach, pre_pos, module_x_axis,
   valid, src, sigma, slot, age}`; 引导步/朝向量/预抓点全部由它派生, 不各立口径。
2. **位置 = 抓取点本身**, 不要自己加 hover —— 把目标抬到 hover 上方, "目标"就不再是抓取点。
   hover 只用于派生预抓点 `pre = pos − approach·hover`, approach 默认 `[0,0,-1]`(从上往下抓)。
3. **姿态 = 工件 6D 位姿的四元数**(抓取瞬间工件系 ≡ tool1), 不是当前 TCP 旋转; 夹爪装歪再乘一个
   工具对齐常量(默认单位阵), 别把对齐误差混进标定。
4. **来源分级 + 陈旧判据**: ctx 直塞 > 位姿服务 HTTP。常驻 10Hz 循环**必须加缓存**(0.2s 缓存 /
   0.25s 超时), 否则服务一挂每拍都卡满超时; 帧龄 >1.5s 判陈旧; 拿不到就降级 `obs[4:7] + 当前 TCP 旋转`
   并 `valid=false` 写清原因 —— 降级可以给, 但不能假。
5. **向后兼容**: 下游认的 `value.tcp`(mm, 引导步) 语义不要改, 目标位姿另开字段并存; 一次接口变更
   会打断画布上所有下游。

方向一致性只作注记: 测地线 chunk 若来自未标定解码, 其方向可能与几何相反(实测 cos=−0.86),
`dir_src` 里写明"几何主导", 目标位姿不依赖它。
