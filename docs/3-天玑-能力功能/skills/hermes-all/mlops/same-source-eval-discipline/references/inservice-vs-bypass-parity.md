# 在役实现 vs 旁路/本机实现 —— 同源判定清单

用于回答"本机这套跟产线/工控机/在役那套一样么"。结论必须三项逐项取证, 不能凭"我照它的逻辑写的"。

## 一、三要素核对表 (缺一项就不能说同源)

| # | 核对项 | 怎么取 | 不同源的指纹 |
|---|---|---|---|
| ① | 代码/判据集 | 两侧判定函数/版本串各打一份; grep 对方副本里是否引用本侧模块 (零命中 = 两套代码) | 同名概念但一面判根数/锐度, 一面判划痕/污染 |
| ② | 权重 + `imgsz` | 权重文件名/大小/md5 + 实际 `imgsz` | `.pt.enc` 加密 + 解密器只在对方机 ⇒ 本侧根本跑不了 |
| ③ | **输入预处理** | 取图端点 (`kind=origin` 原图 vs `kind=crop` 裁剪) + 归一化/letterbox 目标边长 | 960×960 裁剪方图 vs origin 原图 imgsz 512 |

**任一项不同 ⇒ 两个模型不可互当替身, 也不可比准确率** (比的不是同一条链)。

## 二、旁路件只有在两种情况下才算"同源"

1. **搬运**: 直接把在役服务的 `/last_result` 拉过来 (判决数值就是在役原样) —— 同源的是**结果**, 不是判据。
2. **共用同一实现**: 两侧 import 同一个函数 (例: 本机判据图与交付判据图共用一个 `surface_judge`)。

否则就写"判据不同源"。反例口诀: 自蒸馏小权重 + 不同 imgsz + 不同取图口径 ⇒ 只能当观测, **gate 默认关**,
要它参与判决必须显式环境变量开 —— 且未证明提升不得进默认档。

## 三、"仓库副本还是在役那一版吗" —— 单独一道闸

调试副本会被人手改过 ⇒ 用同步工具 `status/verify` 比三个 sha:
**清单登记 / 远端真身 / 仓库副本**。三者一致才算对齐。
- 远端不可达时只能报"对齐状态**未验证**", 并列出网线插回后要跑的 `verify`;
- 不得把本地副本当远端现状复述, 也不得因"文件名版本号高"就假定内容新 (文件名固定、内容多代并存很常见)。

## 四、缺数不冒充

- 对方返回 404/"尚无检测结果" ⇒ 判决码 **2 = 未检**, 绝不填 0 冒充 PASS。
- 键缺失就不写该键; 无帧/异常 → `pass=None` 让下游知道没真值。
- 派生量必须有定义 (如 缺陷数 = 划伤 + 污点, 两个都在才算), 不允许"缺一个也照样加"。

## 五、交付口径

一句话结论先给性质 ("不一样; 只搬运那条链同源"), 再给三要素证据, 最后给缺口
(哪些必须在对方机上跑、哪些本机可自证)。不写"基本一致"这类模糊词 —— 下一句就会被拿去反驳。
