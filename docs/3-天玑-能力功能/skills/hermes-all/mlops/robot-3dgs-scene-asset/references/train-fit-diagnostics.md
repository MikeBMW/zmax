# 3DGS 训练诊断：三个判据，PSNR 排最后

采完数据、开训之后，判断「这版能不能用」的顺序。

## 1. 先看渲染图，再看 PSNR

**在役 PSNR 不能当目标线**。PSNR 只反映「像不像那批训练图」：在役资产若来自失焦贴脸特写，忠实重建糊图就能到 22.9 dB；换成清晰复杂场景只有 15.2 dB，数字更差但内容更真。

判交付必须把 `renders/*_gt.png` 和同视角渲染图**并排看**：GT 有料盘/PCB 边缘而渲染是模糊色块 ⇒ 崩了，PSNR 具体多少不重要。

跨数据集不可比；同数据集不同留出协议也不可比 —— 要 A/B 就固定 init、`--holdout-blocks/--holdout-keep`、步数三者。

## 2. 训练视角 vs 留出视角倒挂 ⇒ 欠拟合

正常是训练略高于留出。实测出现过 训练 12.31 / 留出 15.22，且多个训练视角的 PSNR 一模一样 ⇒ 高斯塌成一团、从哪个角度看都一样。

这时算「每张图被看了几遍」= 步数 / 图数：

| 配置 | 步数 | 图数 | 遍数 | 结果 |
|---|---|---|---|---|
| 历史稳定 | 400 | 80 | 5 | OK |
| 本次 | 700 | 326 | 2 | 崩，模糊色块 |

**起步按 ≥5 遍算步数**；料盘+工装+PCB 这种多物体场景给到 3000 步量级。

## 3. 时间估算

约 1.0 s/步（150k 高斯 / 300+ 张 / Intel XPU），高斯加到 200k 会变慢。先按步数报 ETA 再开跑，别开跑后才估。

## 训练跑完但 report 没落盘

`gs_train.py` 崩溃在收尾评估（`gsplat` 对零交集视角抛 `IndexError`）时，`gs.ply` 其实已写出，只是没有 `train_report.json`。别重训，按 `cameras.json` 复算归一化参数补写：

```python
import json, numpy as np
cam = json.load(open('<out>/cameras.json'))          # 每项含 position / T_cam2world
P = np.array([c['position'] for c in cam])
center = P.mean(0)
spread = float(np.abs(P - center).max())
S      = 1.0 / spread
```

写回 `train_report.json`（字段至少 `psnr_holdout_db / psnr_train_db / n_gaussians / steps / center / spread / S`）。

**不合格资产用 `mv train_report.json → *.holdoff` 挂起，不要删**：渲染循环按 PSNR 自动挑轮次，缺 report 就不会被选中，同时证据还留着能复查。

## 深度初始化值不值得接

先查代码有没有：「`grep -n depth gs_train.py`」零命中 ⇒ 不是评估后决定不用，是压根没接。

接了以后收益**跟帧数相关**：635 帧时 −0.2~−0.4 dB，202 帧时 +0.61 dB。帧数稀时 geometry 才真进模型，所以「深度有用/没用」不能一句话结案，要带帧数说。

接之前还得先解决：①深度空洞（实测黑色料盘/反光 PCB 区域有效像素只 43%，4×4 分块里有两块 100% 全空，直接反投影会先撒一堆错点）；②深度与彩色不同源不同频（深度 0.5Hz vs 彩色 8Hz），时间对不齐。

## 采完先算覆盖，不是先算帧数

「帧数够」是假指标。要用**目标区域范围 vs 相机位置范围**判：

- 料盘号位 y 206~498，实测相机只走了 y 121~294 ⇒ 一半料盘没拍到，326 个视角也补不回来。
- 相机位置跨度取**整个数据集的最大−最小**（`cameras.json` 里的 `position`），别只看单段：单段 160mm 看着够，合并后可能仍集中在同一块。
- 视差要**横着走**（垂直于光轴）。沿光轴推拉只改距离，不产生三角化基线，基线数字好看但重建照样糊。
- 两段采集合并（`gs_dataset_merge.py --out <合并> --in <ds1> <ds2>`）的前提是**同一 handeye session + 同一内参**；合并前先比对两个 `meta.json` 的 `handeye` 字段，不一致就会拼出撕裂的点云。

## 采集弧线的两个执行细节

- **起点对齐**：第一路点离当前 TCP >80mm 时执行器 ABORT（这是对的，别放宽门槛）。改法是旋转弧线起始角
  `start_deg = atan2(当前y−cy, 当前x−cx)`，让第一点落在半径上离当前位置最近处。
- **中途改要求就先停**：弧线跑到一半用户说「向下一点」⇒ 停脚本、确认 `jointVel` 归零，再改参数、
  用新 z 重算路点并重新对齐起点角。**不要边跑边改**：控制器对相邻目标点过近会报 `50003`，
  且旧路点带着旧 z 会混进新轨迹。

## 采集安全：围栏表里没登记的障碍物，预检 PASS 是假的

`precheck` 只检查 `/api/fence` 登记的东西。用户说「上边有 AOI 相机」时，**把它建成围栏箱体**
（要位置+尺寸）回来登记，只回一句「不往上抬了」完全不够 —— 预检会继续报「✅ PASS 最小余量 98.1mm」，
而那个数是夹爪包络到**黑色料盘**的距离，跟 AOI 相机毫无关系。撞了之后说「我没看到」就是真的没看到：
不是图像看不清，是这个物体从来没进过检查表。`collision_detection_enabled` 默认关，控制器不会报碰撞，
日志里只会有 `13013` 急停（人为）而没有 `30400/13036` —— 取证时要按这个区分，不把 near-miss 写成「撞了」。
