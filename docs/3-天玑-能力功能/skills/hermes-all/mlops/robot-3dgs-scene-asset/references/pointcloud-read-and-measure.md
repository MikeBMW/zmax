# 点云读入与「用点云量工件尺寸」的前提

## 1. PLY 必须按属性表解析, 不能假设只有 xyz

仓里 `cloud_world_*.ply` 是 `x y z r g b` 六属性。用「只读 3 个 float」的 dtype 硬解会让每点跨错字节
⇒ **全变成 NaN**, 后续平面/栅格分析全部空结果而**不报错**(表现为“RANSAC 找不到平面 / 没有任何孔洞”)。

```python
props = [l.split()[1] for l in hdr.split(b"end_header")[0].splitlines()
         if l.startswith(b"property float") or l.startswith(b"property uchar")]
types = {"x": np.float32, "y": np.float32, "z": np.float32, "r": np.uint8, "g": np.uint8, "b": np.uint8}
dt = np.dtype([(p, types.get(p, np.float32)) for p in props])
P = np.frombuffer(body, dtype=dt)
P = P[np.isfinite(P["x"]) & np.isfinite(P["y"]) & np.isfinite(P["z"])]
```

读入后立即断言三件: 点数 > 0 · `isfinite` 过滤比例 · bbox 量级合理(整个工位 ~2m, 不是 6m/0.001m)。
NaN 静默传播是这类脚本最常见的假结果来源。

## 2. 下手前先算密度 —— 决定「能不能量」的是间距, 不是点数

```
点数 / 覆盖面积 = 每 cm² 点数   等效间距 ≈ 1 / sqrt(每cm²点数)
```

实测 98,448 点铺 ~1.4×1.8m ⇒ 平均间距 ~3mm ⇒ 2mm 栅格下**不可能闭出 5~20mm 的槽孔**, 主平面封闭孔洞数全是 0。

判据: **等效间距 > 目标特征尺寸 / 3 就直接说量不了**, 不要跑一轮 RANSAC + 孔洞检测再报“没找到”
(那会让人以为是算法问题、再调一轮参数)。要量小尺寸只有两条路: 近距俯视(手机/近景相机)
或深度相机近距离采集。

## 3. 「推的」与「量的」在汇报里必须分开

- **位置**可以展示教真值 + 动作真值交叉验证(示教槽心 vs 抓取位姿差 6.1mm ⇒ 可信), 但要写清这是
  **交叉验证**, 不是视觉测得。
- **尺寸**没有直接测量时不许用「7 个槽点 + 边距」反推一个包围盒当尺寸 —— 那是假设值。
  唯一能当先验的是**槽间距**(相邻槽心差); 间距也不是尺寸。
- 结论分三档写: 有真值 · 交叉验证过 · 未测(附缺失原因与最小代价的补救动作)。

## 4. 判断「相机到底看不看得见目标」不要靠投影假设

没有有效手眼外参时, 任何投影都是假设。硬口径 = **在真实帧上跑现有检测器统计命中**,
并把“权重里没有这一类”与“有类但检不到”分开说; 再用经典视觉做一道独立校验
(阈值 + 连通域 + 等间距共线), 两边都 0 命中才敢说“看不见”。

⚠️ **老的手眼文件(follow `models/handeye_state.json`)不代表现在准**: 相机换过/重装过就整批失效。
零运动验一下: 把一个已知基座坐标点投到某帧已知位姿的画面上, 落点应该在那个物体上;
落在“亮度均匀的空区”而物体在亮区 ⇒ 外参已失效, 不要拿它出任何几何结论。
