# 3DGS 插口提质教训（真机实测，2026-11）

## 1. 建集必须先确认「标定比例 vs 实拍比例」
- `real_cam_calib.json` 是 640×480(4:3)，D405 实拍是 1280×720(16:9)。直接拿标定内参 remap 实拍图，
  实际只吃到画面**左上角 640×480**（1/4 面积）。
- 判据：把源图分别做「左上裁剪 / 居中裁剪 / 整幅 resize」与留出真值比平均绝对差。
  实测 4.4 / 60.5 / 42.7 ⇒ 只有左上裁剪能对上，坐实了裁剪错。
- 正解：`map_build_3dgs_ds.py --crop 960x720`（居中裁、内参同比 ×1.5）。像素量 2.25 倍。
- 判据永远先做：**PSNR 上不去而步数在涨，十有八九是数据口径错，不是训练不够**
  （实测 3000 步/177 帧 17.03 dB < 400 步/80 帧 18.16 dB）。

## 2. 渲染宽度会被 systemd drop-in 压回去
- 改 `GSRENDER_WIDTH` 环境变量无效：`zmax-gs-render-stream.service.d/load.conf` 里硬写 640/3。
- 必须改 drop-in 文件 → `daemon-reload` → `restart`，再用 `/health` 核 `w/h/fps`。

## 3. 画面自己转 = 缺位姿文件
- 渲染器拿不到 `/tmp/arm_tcp_pose.json` 时退回 `tour`（环绕相机自动转）。
- 修：550C 上跑 `arm_pose_relay_intel.py`（5 Hz 拉 8797 `/api/tcp`）+ systemd `arm-pose-relay`。
- 判据：`/health` 的 `src` 必须是 `arm`（不是 `tour`），且间隔 3 s 两帧 md5 相同。

## 4. 视差类型决定能不能解出「孔」
- 纯平移只解平面；插口内壁/立面必须有**斜视**：±12° 俯仰才看得见杯口内圈。
- 采集配比：0° / −12° / +6° 三档俯仰 × y 横线 ±80mm，3121 帧 @10Hz 足够建 360 帧 960×720。

## 5. 俯仰只能走关节空间，且必须绕 TCP 转
- 控制器 `cartPosture` 的 rpy 在 ±π 附近**表示歧义**：同一姿态多种欧拉写法。
  按 rpy 增量下发实测把 TCP 甩到 675/246/191（离工装面板仅 14.7 mm）⇒ **碰过一次**。
- 第二坑：规划若固定「法兰位姿」只转姿态，工具尖会画弧 259mm×sin(12°)=54.1 mm。
- 正解 `pitch_plan_joints.py`：`p_flange = TCP - R·e₃·TOOL_LEN`，即**绕 TCP 点转**，输出关节角；
  下发用 MoveAbsJ，横线段仍用笛卡尔 + **回传实测 rpy**（不去改它）。
- 执行器必带闸：`|ΔTCP|>25mm` / 关节误差>1° / `|ΔF|>25N` 即停。实测靠这道闸把 54.1mm 那次拦下了。

## 6. IK 可达性要按「档」验，不能只做线性外推
- 同一 TCP，+8° 可达（0.01mm）、+10° 勉强（1.71mm/1.02°）、**+12° 崩（110.69mm/13.8°）**。
- 而且可达 ≠ 能走：+8° 那档某段 MoveL 下发后**臂没动**（dy +80mm），必须逐段核验实到位。

## 7. 稠密化过冲会让 PSNR 中途崩塌
- 现象：2000 步 20.0 → 3000 步 11~13 dB（高斯 10.8 万→13.2 万）→ 4000 步 `refine-stop` 剪枝后回 20.9。
- 别在中途判死；看 `refine-stop` 之后的值。

## 8. `gs.ply → .splat` 记录宽度
- `np.zeros((n,8))` 是错的，必须 `(n,32)`（32 字节/高斯）。

## 9. 页面上看不到新模型 ≠ 流没切
- `/station` 3D 层读本地 `zmax_data/gs_assets/<名>/gs.splat`；8816 直播流是另一份（550C 渲染）。
- 切模型要三处齐：550C `out_*` 训练完 → `gs_ply2splat` → 装 `gs_assets` + 8816 重挑资产。
- `gs_assets/rt_live` 每分钟被 550C cron rsync 覆盖，改本地会被还原，必须改源头。
- 特写模型的留出 PSNR 只在特写视角成立，**不要拿它顶全景地图**。
