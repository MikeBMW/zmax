# 3DGS 渲染推流与工位页显示 — 择优、清晰度量化、延迟拆解

## 1. 推流「选哪份模型」：必须按 PSNR 择优，且数据集目录要能回退

渲染脚本按 `gs_rt/out_*` 目录挑 PSNR 最高的产物，默认假设数据集在 `gs_rt/ds_<后缀>/`。
大轮次训练常用**采集会话目录**当数据集(`--data ~/gs_autocap/sessions/<会话>`)，此时 `ds_*` 不存在 ⇒ 该产物被 `continue` 跳过，推流永远只剩小轮次(400 步)的模型。

规则：
- 挑产物时先试 `out_*/ds_*`，再回退 `train_report.json` 的 `data` 字段指向的目录，两处都没有 `cameras.json` 才跳过。
- 删除 `if not os.path.isfile(ds/cameras.json): continue` 这类**在 json 读取之前**的提前过滤——回退逻辑写在 json 读完之后，否则永远走不到。
- 判据：推流健康接口的 `gaussians` 应与最优产物的高斯数一致(例 445,521)，不是固定的 100,000。

实例口径(同一条轨迹的数据)：
```
小轮次(out_<时间戳>)  400 步   100,000 高斯  PSNR 15.10  清晰度 1.4~1.6
大轮次(out_big2_*)  24000 步  445,521 高斯  PSNR 17.22  清晰度 11.0
```
换对模型后清晰度 8 倍，不需要重训。

**环绕路径(tour)视角天然发虚**：3DGS 只在采集过的视角附近清晰，把头转到没拍过的方位必然糊，这不是训练失败。

## 3. 「页面上没变化」是三段延迟，不是一个 bug

```
① 一轮实时建图训练 + 发布   约 40~60s(400 步, 10Hz 采集窗口攒够才触发)
② 主机同步(rsync cron)      默认 5min → 降到 1min
③ 页面拉图间隔              静态图 15s / 推流 1~2s
```
验证「它其实在变」而不是靠肉眼：隔 60~70s 取两次 `/gs_render.png` 或 `/gs/live.jpg` 的 md5，md5 不同即证明链路活着；再看 `gs/list` 的最新资产名/PSNR 是否换了。
页面 URL 必须带缓存破除(`?t=Date.now()`)，否则浏览器缓存会让你永远看到同一张。

## 4. 采集守护是否在收帧：看静态跳过计数是不是在涨

`8806/health` 里 `frames_total` 不变时，隔 6~10s 两次采样 `frames_skipped_static`：
- 计数在涨(约 10/s) ⇒ 守护进程活着、位姿新鲜，只是**臂没动** ⇒ 去查机器人到底动没动。
- 计数不涨且 `frames_total` 不涨 ⇒ 守护/桥卡住 ⇒ 查 `pose_age`、重启 ros-bridge。
这一条能把「建图没变化」的二义性一次拆开：是没数据，还是有数据没训。

## 5. 工位页 3DGS 格：只开一个窗口

同一格曾同时挂三样：推流渲染 `<img>`、手臂相机帧容器、`/gsview` WebGL iframe；旧代码进页就强制全点亮 ⇒ 用户看到 3 个窗口分不清。
规则：
- 默认只显示**一个**(推流渲染)；其余容器 `display:none`，只由按钮打开。
- 按钮切换必须**互斥**：打开 A 时收起 B/C(含 iframe 的 `src` 置空或 `display:none`)。
- 不要在进页面时无条件 `style.display='block'` 兜底旧容器；兜底只在探测到推流 503 时执行。
- 字幕写清来源与新鲜度：`🖥 <设备> 渲染 · <n>k 高斯 · <fps> fps · 帧龄 <s>s · 视角=<模式>`，用户会用这张图当结果。

## 6. 内存闸与档位

- 渲染前查可用内存，低于阈值不渲染并每 30s 重试（宁可冻图也不要 OOM 把训练/采集一起带走）。
- 与训练同跑时 640×480@2~3fps 是安全档；960×720@8fps 曾把 16G 级机器压到内存满、load 50、SSH banner 超时。
- 阈值要按机器实际可用量设：默认 6G 时训练中(可用 5G)会一直拒渲；降到 3.5G 才能在训练同时出流。改阈值 = 改 unit drop-in + 重启该服务(属"点名"操作)。
