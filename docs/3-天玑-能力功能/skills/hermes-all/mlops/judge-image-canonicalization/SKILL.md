# 判据图规范化 (摆正 · 只留刚体 · 零拉伸)

## When to Use
- 用户说「判据图应该是摆放平整、平行的」「不要斜着的」「只要模块的刚体」。
- 用户说「**位置会变**, 找矩形刚体是**搜索任务**/**动态任务**」⇒ 禁用固定四角/固定坐标。
- 用户说「**不能拉伸**」「转了方向的图和斜着的原图**亮度要一模一样**」。
- 要把判据图(送检测器的图)规范化后再送模型, 或要交「原图 + 截取框」的取证图。

## 铁律 (每条都是被现场纠正出来的, 先看这里再写代码)

1. **找刚体 = 动态搜索, 不许固定四角、不许固定阈值坐标** —— 位置会变, 每帧重新搜。
   候选 = 画面里**每块亮区**(阈值分割后的连通域, **不含任何固定坐标**) →
   评分 = 面积占比 × 矩形度(`contourArea / minAreaRect 面积`) × 对边平行度 → 择优;
   四角取 `minAreaRect` 的 `boxPoints`(天生平行) ⇒ 天然满足「平整、平行」。
   验收判据: 跨曝光/跨帧命中**同一刚体**(倾角稳定在 ±0.5° 内, 矩形度/平行度 ≈1.00)。
2. **阈值法优先, 别用 Canny 边缘闭合**: 边缘闭合拿到的是**细边环**(实测矩形度 0.05 / 面积占比 3%),
   在低对比或过曝场景会被面积与填充度约束全部拒掉(现象="搜不到刚体")。
   定式 = CLAHE(2.0,8x8) 抗曝光不均 → Otsu(前景占比>60% 时退到 80 分位) → 形态学闭(15)+开(25) →
   取最大连通域 → `minAreaRect`。
3. **摆正 = 纯旋转(缩放恒 1.0) + 按真实像素尺寸裁剪; 禁透视重映射**:
   ```python
   M = cv2.getRotationMatrix2D(center, angle, 1.0)          # 缩放必须 1.0
   rot = cv2.warpAffine(img, M, (W0, H0), flags=cv2.INTER_CUBIC)
   crop = cv2.getRectSubPix(rot, (int(W), int(H)), center)  # W,H = 检出框真实像素尺寸
   ```
   长边要摆平时角度再 +90。**用户会直接读输出尺寸** ⇒ 判据 = **输出尺寸 == 检出框尺寸**、长宽比不变。
   ✗ 把四个角重映射成矩形 = 改比例, 用户原话就是「你不能给光模块拉伸」。
4. **摆正与取像素必须同一帧** —— 「几何用能看清整个刚体的帧、像素用不过曝的帧」会让两张图**亮度不一样**(用户一眼看出)。
   定式: 定好一档曝光后**一帧到底**(直接旋转裁剪), 亮度必然一致。
   一致性判据(可复核, 汇报时给这个数): 原图上该矩形内像素 vs 摆正图 ⇒ 均值/中位差 ≈0(实测 −0.08 / 0.0)。
   确因不过曝必须分离几何与测光时, **交付前逐像素比对证明亮度一致**, 否则不用这招。
5. **交付形态**: 原图**保持原样**, 只在上面叠加**搜到的截取框**(绿框 + 四角标注 + 尺寸/倾角文字, 文字只用 ASCII);
   摆正图作为**单独文件**给 —— 不要把摆正图叠在同一张画布上(用户原话「不要又叠加一个摆正的图」)。
6. **量具口径**: A/B 与量测一律用判据**自己的取像口**(如 `GET /picture?kind=origin&grab=1`);
   派生缓存图(如 `kind=judge`)做 A/B 会得出「改了没变化」的假结论。

## 已知短板 (主动说, 别等用户发现)
- 低曝光下「亮块」只覆盖刚体较亮的部分 ⇒ 检出面积**随曝光漂移**(实测 16000us 21.2% → 10000us 15.5%, 尺寸差 ~20%),
  于是摆正尺寸也跟着漂。修法: 用**边缘直线拟合**收紧四边, 或加**形状先验**(从高曝光帧标出长宽比当软约束看)。
- 几何帧不能是削顶的过曝帧(模块面削顶 ⇒ 边界不可信), 但换低曝光帧又碰铁律 4 ⇒ 先解决曝光再谈精度。
