# 段表 → 可执行节拍: 三项物理复核 + 姿态可行集

用途: 有人问「UPH 能不能到 300」「算出来的轨迹能不能真执行」时, 先把下面三项量完再报数。
段表 `Σt` 只是「按末端速度排的时间」, 不是执行端能跑出来的节拍。

## 1. 段间瞬移 (没人补时间的那一段)

段表只在段内插值; 相邻段 `prev.b != next.a` 的位置差, 执行端要么自己插过渡, 要么等于「瞬间到位」。

```python
import numpy as np
gap = np.linalg.norm(np.array(seg["b"], float) - np.array(next_seg["a"], float))
```

实测 (插拔 392 段): 插拔窗口 mods1-4 有 7 处、最大 564mm; 全表 27 处、最大 905mm。
补过渡时间 `dist/v_cap` 后: 11.49s/件 → 12.35s/件 (313 → 292 UPH)。

## 2. 峰值超限 (均值速度与 S 曲线峰值差 1.875 倍)

五次最小加加速度剖面峰速 = **1.875 × 平均速度**。平均 631mm/s 的段峰速就是 1183mm/s, 撞现场
1000mm/s 限幅 (窗口内 20 段) ⇒ 必须拉长 `t`。修正后 12.99s/件 (277 UPH)。
若改用 `linear`(恒速) 剖面则峰值≈均值, 但动效与加减速受限情况另算 —— 剖面口径必须与闸同源。

## 3. 关节速度 (末端达标 ≠ 关节达标)

用现场 URDF 参数做数值 IK (DLS, 6×6 数值雅可比) 反解整条轨迹, 量 `max|Δq|/dt`:

```
现场 URDF: tools/rokae/gravity_torque_check.py 的 JOINTS / TOOL_XYZ / TOOL_RPY (纯离线, 不碰真机)
工具:       tools/pose_offline_sim.py --rule hold|geom   (hold=位置基线, geom=几何姿态)
            tools/se3_pose_path.py                        (段表 → 位置+四元数逐拍轨迹)
```

实测 (10Hz 采样, 574 点): 关节速度峰值 **554°/s** (hold 姿态基线, 573/574 点位置可达, 最大残差 8.11mm)。
常规 180°/s 口径下过不去 ⇒ 该拉的时长必须补进节拍, 否则 UPH 是纸面值。

## 姿态可行集 (固定姿态不能"按几何写死")

同一「工具 z 轴对齐某方向」的约束下, 绕该轴还有 yaw 自由度; 24 个 yaw 实测相当:

| 点 | yaw 0/30/60/90° | yaw 120~300° |
|---|---|---|
| 料盘槽底 (0.49,0.499,0.118) | 27.4 / 52.0 / 56.7 / 25.4 mm | **0.0 mm** |
| 孔口 (0.767,0.228,0.278) | 144.0 / 153.1 / 116.7 / 59.6 mm | **0.0 mm** |

(30 次随机重启 IK 确认: 竖直姿态在坏 yaw 上确实不可达, 不是迭代没收敛 —— 但**也不是唯一解**。)

结论口径: 姿态是一个**带关节约束的可行集**, 不是一个「真值四元数」。规则:
1. yaw 必须与位置**联合**选 (先按位置求 IK 可行 yaw, 再按连续性挑最近的);
2. 每段用哪个 yaw、为什么, 记进段表/报告, 否则复现不了;
3. 段间切 yaw 不能硬跳 (角速度顶关节限)。
