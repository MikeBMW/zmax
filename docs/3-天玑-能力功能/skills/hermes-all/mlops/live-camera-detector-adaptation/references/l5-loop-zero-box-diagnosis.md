# L5 闭环 0 有效框：三类真因 + 报错口径坑

判据（红线，保持）：supervision 阶段 `mapped_boxes == 0` ⇒ 判失败、不继续训练。但**原因必须分类**，绝不能一句「相机离线」。

## 三类真因（用本阶段真有的量判）
1. `n_frames == 0` / 各路 `ok=false` ⇒ 流没起、相机离线
2. 有帧但 `objects == 0`（latency 极大）⇒ VLM 返回空或超时、图过暗
3. VLM 标了框但全不在训练类别表 ⇒ **本批画面里没有可训练目标**（不是相机/流的问题）

原因串里必须带证据：各路 ok 数 · 帧数 · `skipped_labels` 明细 · VLM 的 `scene` 描述。

## 已修的坑
失败原因判定读 `r["summary"]["n_ok"]`，而 `stage_supervision` 从不设置该键 ⇒ 恒为 0 ⇒ 无论真因都报「①所有相机都没拿到帧（相机离线）」，与现场矛盾。**判原因只能用本阶段真有的量**：`n_frames` / 各路 json 的 `ok` / `objects` 数 / `latency_s` / `skipped_labels` / `scene`。

## 口径
L2 训练类别表只有 `peg` / `OPT_Gold`；VLM 常标「插槽/托盘槽位、夹爪、线缆、手」⇒ 全被 skip 是**正确行为**，不要为了“跑通”去扩类别表。

## 排查顺序
1. 看批次目录里每路 json：`cam / ok / n_obj / latency_s / scene`
2. 看 phase 统计：`mapped_boxes / skipped_boxes / skipped_labels / images_written / frames_no_box`
3. 全黑帧（`scene` 写「曝光为零/全黑」）= 相机问题，与标注链无关
4. 真跑通的前提是画面里**有工件**：对准工件、或 `--cams` 只留有目标的路、或 `--batch-dir` 复用有目标的批次

## 训练后「0 框」判词：三种来源，别混

`L2_full` 阶段的「训练跑完但真推理验证 0 框 → 不算成功」有两种完全不同的原因：

1. **真 0 框**：1 轮小跑 / 未收敛 / 权重真的坏 —— 判失败是对的。
2. **假 0 框（解析 bug）**：门禁从训练日志里取框数，日志从 `→ 4 框` 改写成 `→ 共检出 4 框`，
   `int()` 失败被 `except` 吞掉 ⇒ 当成 0 框。实测把一个 mAP50 0.995 / 手工复核 4-4 框 conf 0.80
   的候选判成「权重不可用」。
3. **rc≠0 崩溃**：训练进程抛异常（实测 epoch 53 / 56），阶段报 `rc=1 · best.pt 在位`。
   **`best.pt 在位` 不等于训完**，看 rc 和日志尾的 `N epochs completed`。

规矩：
- 判词解析用正则，取不到数就报「解析失败」，**不要默认成 0** —— 默认值会把 bug 伪装成模型问题。
- 每次报「0 框」必须同时给：抽样张数 / 检出框数 / 平均 conf / 权重路径，缺任一项就无法复核。

## 日志必须每次运行留副本

阶段日志是**单文件覆盖写**（`<work>/L2_full.log`），下一次运行直接抹掉上一次的崩溃栈 ——
实测两次崩溃（epoch 53 / 56）的 traceback 全部不可回溯，只能确认「失败了」，说不清原因。
⇒ 每个阶段跑完把 `<stage>.log` 复制成 `<stage>_<run_ts>.log`。崩溃根因**不确认就不写**，
只如实报「rc=1、异常中断、栈已丢」，别拿「可能是显存」当结论。

## val 与在役同分布时，打平没有信息量

在役权重在同一 val 上拿 0.995、候选 0.995 —— 不是「一样好」，是**这套 val 没有判别力**
（val 就来自在役的训练分布，且只有 6 张 / 5 个实例）。
⇒ 结论写「无提升，按纪律不切在役指针」；要判优劣，val 必须来自新采帧或不同工位姿态。
数据量在这个量级时，任何名次的差异都是噪声，别拿去说服任何人。

## 编排纪律
控制台可派生该闭环（studio.py 起 `tools/l5_annotate_train_loop.py --run`）。单实例锁按 pid 判活，陈旧锁自动接管；报「已有编排在跑」= 旧进程**还活着**（被调试器断在异常里也算活着）⇒ 先 Shift+F5 停掉。
