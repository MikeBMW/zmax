# 渲染帧上的真感知与几何真值自动标注

场景: 检测器的"实时画面"是 MuJoCo 渲染帧 (数字孪生/AR 工位), 要求"模型真的读这段视频"。
本文件只写这类链路特有的几条, 通用域适应流程仍按 SKILL.md 主体。

## 1. 先算像素尺度, 再谈训练
```
px_per_m ≈ H / (2 · dist · tan(fovy/2))
```
实测反例: H=720、dist=2.0m、fovy=69° ⇒ **1px≈4.3mm**; 56.5×13.4mm 的模块只占 **13×3px**。
这种机位不管换多大模型、降到多低 conf 都学不到 ⇒ 感知机位必须是**跟物特写**
(机位钉在被夹物件上、沿物件厚度轴正视, 0.20~0.38m, 同口径下 71×140px)。
全景机位只用来学上下文/挠误检, 不能当主感知通道。
判据: 标注框短边 <6px 就先怀疑机位, 不要先怀疑模型。

## 2. "0 检出"的三个真因, 按此顺序查
1. **权重域 ≠ 帧域**: 真机照片训的权重在渲染图上 conf 0.15 也是 0 (实测全景/特写都是 det=0)。
   这是域差, 不是阈值 —— 先跑一张阈值响应表再下结论。
2. **机位不够近**: 算 §1 的 px/mm; 目标不足 ~10px 短边时结论是"机位不对"。
3. **画面没光/相机埋在物体里**: 见 §4。

报指标时必须同时给 **recall** 与**真帧检出率**: 一套 mAP50 0.466·P0.89·**R0.41** 的权重, 在回路里
表现出来就是"有时检到、有时空", 用户看到的是掉帧。R 不到 0.7 就直说"召回不够",
不要用整集 mAP 宣布"感知已通"。

## 3. 几何真值自动标注 (零人工)
- 框从 geom 真值算: `data.geom_xpos` + `geom_xmat` + `geom_size` 的**八角**, 投到像素取外接框。
- 投影必须用**当时那次渲染的那个相机** (`scn.camera[0]` 的 pos/forward/up + `model.vis.global_.fovy`),
  不要另算一套 az/el/dist: 那样框和像素就不是同源, 看着像漏标。
- 可见性闸: 框中心 7×7 邻域均值 <12 判"在遮挡物后面"丢掉; 框长/宽 <6px 丢掉。
- 小目标 (孔口) 投 site 位置 ±半宽, 别用一个点。
- 留出集按样本切 15%, `data.yaml` 的 `val:` 只写目录。

## 4. 渲染黑帧: 机位在物体内部 ≠ 曝光问题
- 症状: 框位置完全正确 (投影 56×194px), 但图像 `mean≈9`, 亮像素几乎为 0。
- 真因: 机械臂在**零位/直臂**时, 0.26m 特写相机落在**前臂/执行器内部**, 内表面背面剔除 ⇒ 全黑。
  同一套代码换成"产线在跑的那组关节角"立刻 `mean≈71`。
- 规矩: 造数基准位姿取**在跑的真值** (`zmax_data/ss_live/ar_mj_q.json`) 再 ±14° 抖动, 不要从零位随机;
  并保留 "画面 mean<20 ⇒ 换机位重试 ≤4 次, 仍不行就丢样本" 的闸。
- 抬手姿态还常常"机位对了但偏暗" (场景灯只在料盘上方) ⇒ 在腕部加一盖**随动环光**
  (light 挂在工具坐标系上, 指向工件), 否则训练集和在线特写都偏黑。

## 5. 相机模型自检 (不用手眼标定)
三个检查同时跑, 全过才算相机可信:
1. `project(tgt)` 必须等于画面中心 (`w/2, h/2`);
2. 像素 → 平面点 → 像素 往返误差 **0.0px**;
3. 静态参照物 (料盘/台面角点) 投回去, 落点周围彩色像素占比 ~1.0 (背景≈可忽略)。
机位参数变了要重跑这三个 —— 尤其**画幅变了** (4:3 ↔ 1.7:1) 时内参跟着变, 用错画幅投影会偏几度。

⚠️ 这三个检查只证明"我的投影器自洽", 不证明"它和服务端用的那台相机是同一台"。
服务端自己算的机位 (track/face 跟物、`live` 页面同步) 必须**同帧把参数交出来** (`/cam.json`:
lookat/az/el/dist/fovy/w/h), 消费侧以它为准; 拿页面参数去猜会把件投到画面外,
深度读到远平面 (实测 127m)。真判据是: 把 lookat 投回去落在 `(w/2, h/2)` 偏差 0px。

## 6. 真 3D: 深度帧, 不是平面反投影
- 端点: `/frame.png?...&depth=1` → 16bit **毫米** PNG。渲染侧 `enable_depth_rendering()` 必须在
  `update_scene()` **之前**, 渲完 `disable`。
- 有效性: `>0` 才算数; 远平面 **127.49m** = 这条光线上没有几何 (常见于机位/画幅算错)。
- 反投影用件中心附近 **3px 窗口的中值深度**, 单像素量化噪声 (1/1000 m 级) 甩得开。
- 自检: 画幅中心那一点的深度 ≈ 相机到 lookat 的距离。实测 0.254m vs 0.26m ⇒ 6mm, 可用。
- 🔴 **平面假设只对躺在那平面上的件成立**: 腕部特写里件在 0.56m 高, 按料盘面 z=0.109 反投影
  实测差 **452mm**。要报 3D 就给深度, 给不了就只报 2D + 明确写 `gaps`。

## 7. 在线接线 (节点侧)
- 主通道用特写, 特写被自身遮挡/0 框时**回退全景**并记 `cam` 字段 —— 别把两机位的数据混成一条。
- 同拍内多节点共用**同一帧** (TTL 0.3~0.4s 缓存), 不能各拉一帧: 臂在动, 两帧之间差几十毫秒就对不上。
- 权重按 **mtime** 做缓存键 (`(path, mtime)`), 否则换了 `models/*.pt` 进程还在用旧的; 软链权重同理看 link 目标 mtime。
- 帧龄必须随结果一起上报 (源时间戳 + 年龄), 页面/日志用"新鲜度"判回退, 不要静默用旧帧冒充实时。

## 8. 常驻回路里的感知/理解节点: "改完代码"≠"它真跑了"

- 🔴 **先确认这个节点在不在 tick 里, 再改它**: 同一层常有多个节点 (如 `ssyolo` 和 `ssllm_in` 都在做感知),
  只有日志里**真出现过**的那个每拍执行。命中方法: 按节点日志前缀 grep 循环日志
  (`grep -o '^\[[a-z_0-9]*\]' loop.log | sort -u`), 不在列表里的节点改一百遍也不会生效。
- 🔴 **节点缺主输入就 return False = 整层在看戏**: VLM/规划这类节点常写成"没有引擎轨迹就直接返回"
  (GUI 里点 ▶ 才有 `_ss_tr`)。常驻无头回路永远没有轨迹 ⇒ 该层永远空转, 下游只能报"未就绪"。
  规则: 主输入缺失时**退到实时帧源真跑一遍** (取同拍帧 → 推理 → 返回结构化结果),
  取不到帧才返回 False, 并在输出里写清 `frame_src` / `frame_age_s` / `latency_ms`。
- **验收看日志行, 不看代码在意**: 通过标准是一行带 `src · 模型 · 耗时` 的真实结果
  (实测 `VLM 场景理解 (ar · http:deepseek-flash · 1770ms): 目标可见=True …`),
  以及下游编排层文本从"环境帧不可用"变成"环境=AR 场景 (帧…, 帧龄 0.0s)"。
- **大模型走 HTTP 不占显存**: 8GB 卡上 L3 用远程视觉模型 (1.7s/次, 12s 节拍内够用),
  本地 VLM 只在需要多帧/离线时上; 两者产出字段要一致, 下游不改。
