# 视觉契约里的姿态字段：从"一个点"到"朝哪、多大"

配套 SKILL.md「检测器对外输出」一节。场景：用户追问「输出只是一个点么？让下游能拿到姿态」。

## 语义先摆清（回答"是不是只有一个点"）

| 层 | 内容 | 有没有朝向 | 谁产出 |
|---|---|---|---|
| 2D 框 | xyxy / conf / cls | 无 | 检测器内部 |
| 3D 点 | `{类名: [x,y,z]}`，每类一个中心点 | **无** | `estimate_3d` / `detect_3d` |
| 3D 框 | 中心 + 旋转 + 尺寸 + 外参 + 残差 | 有 | 多帧解算器 `Box3DSolver.fit()` |

一个 2D 框只能定住一个像素中心，沿射线取一次深度 ⇒ 结果是**射线上的一点**，
朝向和尺寸在几何上不可能从单帧单框得到。别在点里"编"一个朝向。

## 解算器给什么（这才是有姿态的那条路）

`fit()` 的返回里与姿态相关的键：

- `off_mm`：模块相对 TCP 的平移偏置（毫米）
- `rrel_deg`：相对旋转（度，roll/pitch/yaw）
- `size_mm` / `size_a`：模块框尺寸（毫米）
- `T_cam_from_base`：顺手解出的相机外参
- `rms_px` / `holdout_rms_px`：拟合残差，`>20px` 判 `degenerate`
- `diversity`：位姿多样性，不够就拒绝拟合

夹持态出中心的快捷式：`center = TCP + R(quat)·off`。

## 契约扩字段的写法（加法，不破坏旧读者）

```python
points[name] = {..., "quat": [x,y,z,w], "size_mm": [L,W,H],
                "pose_src": "gripper:TCP×R_rel", "pose_frame": "base_link"}
```

规矩：
- **可选**：拿不到姿态就不写这两个键，旧读者不受影响；绝不写 `[0,0,0,1]` 冒充"正着放"。
- **四元数归一化后再写**，长度不是 4 或范数为 0 直接丢弃（别落一个半成品进契约）。
- **只有尺寸没有姿态**是合法状态：写 `size_mm` + `pose_src: "size_only:…"`，`quat` 留空。
- 生产端 `publish(...)` 增加 `pose={类名: {...}}` 参数即可，不必改旧调用。
- 读端提供 `read_pose(name)`：返回 `None` = 没有这个点；返回 dict 但无 `quat` = 有点无姿态。
  两种"空"必须能分开，否则下游分不清"没检到"和"没标定"。

## 姿态合成的约定必须与解算器一致

`R_world = R_tcp · R_rel`，其中 `R_rel = Rz(yaw)·Ry(pitch)·Rx(roll)`（与 `box3d_solver` 同一套）。
自己另立一个欧拉序，姿态会"看起来对、实际转了错轴"，而且只在某个角度才暴露。
写库前先对齐：把解算器的 `quat_to_R` 和自己实现的四元数→矩阵做一次同输入对拍。

## 接线检查表（缺一步就一直拿不到姿态）

1. 生产端：检测节点在写契约时附 `pose`（有解算结果 + 有 TCP 四元数 → quat；只有解算 → size）。
2. 中间层：任何把点**重建成新 dict** 的地方都要把 `quat/size_mm/pose_src/pose_frame` 加进白名单
   （这是最常漏的一环，漏了上游写成功、下游恒空）。
3. 消费端：规划器/伺服把姿态放进输出（`goal_quat` / `goal_size_mm` / `goal_has_pose`），
   **同时给 `goal_has_pose`**，让下游能显式判"这一拍能不能做朝向对齐"。
4. 声明式开关：需要一个"补姿态"的独立入口时，做成工具读现有契约 + 解算结果 + TCP，
   三种缺失分别 exit 2 / 只写尺寸 / 写全，别在工具里默认一个姿态。

## 验证方法（不污染真值文件）

- 单元：无姿态 → 契约里连键都没有；带姿态 → 归一化后的 quat；坏四元数被丢弃。
- 数学：TCP 绕 z 90° → `[0,0,0.7071,0.7071]`；`R_rel` 绕 x 90° → `[0.7071,0,0,0.7071]`。
- 真实链路：把一份**已存盘的真实拟合结果**临时放到解算状态位置，TCP 用临时文件 + 环境变量覆盖
  路径（不要把假四元数写进真值文件），跑一次检测节点，确认契约里出现 quat；验证完立刻删掉临时件。
- 消费端：同一份契约跑规划器，`goal_has_pose` 在有无 quat 两版里分别为 False/True。

## 精度前提：接口通了 ≠ 能按姿态插拔

实测一次自检里，夹持态旋转误差中位 **49.77°**、尺寸误差 9.59 mm —— 接口能拿到姿态，
但那个姿态还撑不起"按朝向插入"。报交付时必须分开说：
（a）字段与链路已就绪；（b）旋转精度未达标，需先在多姿态 holdout 上把误差压到几度以内。
别让"能取到 quat"被读成"能对齐"。
