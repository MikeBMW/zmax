# 接管一个已有控制器: 保留内置兜底 + 一致性守卫 (2026-09-13 实测)

> 配套 SKILL.md 的 §5 (算力预算) 与 §6 (Pitfalls)。这里记"模型要接管一个**本来就能工作**的控制器"时的
> 正确接法与阈值实测 —— 与 §2 的"离线回放闸"互补: 离线闸判"模型有没有学会", 本文判"接管到哪一档才不掉分"。

## 1. 症状: 纯前馈接管 0/N, 而且守卫一次都不触发

实测: 自训 actor 离线 MAE 0.0028 (0.28mm 级, 好到不像话), 闭环 0/10。
诊断链最终定位到**引擎原版控制器自带保护被我们替换掉了**:

```python
class FeedforwardAccelerator:
    """主路径 = 蒸馏 MLP; **状态出训练域 → 解析守卫兜底** (全局稳定, 同教师)
       域判定: (a) hand→target 3D 距离 d_guard ≤ D_GUARD
               (b) 归一化逐通道 |x| ≤ DOMAIN_SIGMA (target 通道自身域外 = 布局偏离蒸馏数据)"""
```

我们把 `sim.accel` 整个换成自己的 wrapper → 兜底路径消失 → 模型在域外输出坏动作,
没有任何人接管 → 卡死。**替换一个带保护的控制节点时, 保护必须由你显式保留。**

## 2. 正确接法: 一致性守卫

```python
u_eng = inner.forward(obs)        # 先算引擎原版 (含域判定 + 兜底) = 安全基线, 永远保留
u_act = model(...)                # 模型建议
u = u_act if np.abs(u_act - u_eng).max() <= TOL else u_eng
```

同时统计 **actor 采纳次数 / 兜底次数** 并打进结果 —— 没有这两个计数,
"成功"就无法区分"模型在控"还是"退化成了原控制器"。

## 3. 阈值扫描 (10 seed, 同进程内确定性)

| TOL | actor 采纳率 | 成功率 | 判定 |
|---|---|---|---|
| 0.05 | 0% | 100% | **退化 = 模型只是摆设** |
| **0.08** | **24%** | **100%** | 工作点 |
| 0.15 | 27% | 100% | 同量级 |
| 0.30 | 86% | 0% | 介入过多 |
| 0.60 | 100% | 0% | 全模型 → 崩 |

- 同进程内 3 次重跑结果**逐位相同** (1024/2773); 换进程就变 → metaworld 布局跨进程漂移,
  **泛化证据必须跨进程重复** (实测跨进程 6 seed 全成功才算数)。
- 失败形态很整齐: 崩的 seed 都是 `actor≈100%`, 说明是"接管太多"而非"模型学得差"。

## 4. 两个反直觉结论 (都有实测数据)

### 4.1 补全可观测性**不能**突破参与上限
把引擎内部状态加进观测 (46D → 53D: `u_fb`(反馈动作) + `w_ff`(调度权重) + 上一建议),
并按**真正执行的动作**(`u_fuse = w_ff·u_ff + (1-w_ff)·u_fb`)当标签重训:

| 版本 | 观测 | 成功率 | actor 参与 |
|---|---|---|---|
| v3 | 46D (obs+stage) | 100% | 27% |
| v5 | 53D (信息完备) | 80% | 54% |

模型能力确实提升了 (参与率 27%→54%), **但 100% 成功率下的上限仍是 ~24-27%**。
⇒ 上限是**任务/控制器结构**决定的, 不是信息不足。别把"加观测维度"当万能解。

### 4.2 latent 预测误差守卫对"卡住"完全无感
世界模型 held-out MSE 6e-5 (极准), 于是守卫以为一切正常: **0/599 次触发, 成功率 0**。
原因: "卡住"的状态变化**同样可预测** —— latent 误差防的是"模型被欺骗", 不是"任务停滞"。
要检测停滞, 用**任务量**: 到目标距离 N 步无改善 / 阶段不推进。

### 4.3 硬限流 (CAP) 反而把参与率打死
"actor 累计采纳率 > CAP 就强制兜底" → 触及后 rate 回升很慢 → 参与率从 54% 掉到 **7%**。
要限流就**调 TOL**(平滑, 天然控制"多相似才采纳"), 不要用硬 CAP。

## 5. 完成判据与几何自检 (被用户目检戳穿的教训)

- 判据 `insert_depth=6mm` 太松 → `done=True` 时 peg 头离孔底还有 **5.03mm**,
  视觉上"像没插进去", 用户一眼看穿。收到 **2mm** 后成功率从 ~100% 掉到 73% (更真实)。
- 验证几何**别用记录数组的近似字段**: `tr["peg"]` 存的是 `obs[4:7]` = **速度**,
  用它算出的"离孔 135mm"是假结论; 引擎自己的口径 `peg_head()` 才是真位置 (实测残余 4.5-5mm)。
- 交付前自检顺序: ① 用几何量确认动作真的完成了物理目标 ② 再看 done 标志 ③ 最后才谈成功率。

## 7. 真机版: 影子 → 接管三档 + "算错就发回轨迹真值"

真机接管与仿真接管的差别: 基线不是"引擎控制器"而是**一条已经在跑的录制轨迹(215 点)**,
所以缺口不是"模型不如控制器"而是"轨迹本来就跑得通" ⇒ 接管必须**可逆、可回退、默认不介入**。

### 7.1 三档开关, 默认 off

```
ZMAX_DD_MODE = off | shadow | armed
off     完全不介入: 不写文件、不改 u、不改 tag (逐位等同于改造前)
shadow  每拍把 u 与实测运动比对, 只落 dd_guard.json —— ★绝不改 u, 轨迹照走
armed   连续 N 拍(ZMAX_DD_OK_TICKS, 默认 30) verdict=allow 才对外报 allow=True
```

判 allow 的条件(任一不满足 ⇒ deny 且 `ok_ticks = 0`, **立即**回退, 不做衰减):
指令 finite · 幅值 ≤ 阶段上限 · 与实测速度夹角 ≤ 25° · 指令/实测速度比 ∈ [0.2, 5]。
护栏函数必须自己 try/except 兜住并返回 `{"mode":"off"}` —— 护栏不许把主链搞挂。

### 7.2 参考真值用实测速度, 不要引 FK

`zmax_data/rokae_sdk/tcp_out/latest.json` 相邻两帧差分即实测速度(`m/s`)。好处:
闭环要的本来就是"指令与实际运动一致", 而且省掉正逆解与标定假设。
- 臂静止(`|v| < 5 mm/s`)时不判方向, 只判幅值 —— 否则每拍都因"方向无定义"误 deny。
- 真值文件按 **mtime 新鲜度**判活用(`> 1s` 或 `x/y/z` 全 0 ⇒ 参考不可信, 这拍不判方向)。

### 7.3 "a 算错" 的定义 + 算错时输出什么

算错 = 任一条成立: `NaN/Inf` · 通道超限(`|v| > _LIMIT`) · 变化率超(`|a - a_prev| > max_rate`)。
三步落法(全部在 `RobotExecutor.execute()` 尾部, 默认 `allow_traj_fallback=False` ⇒ 零回归):

```
算对            → 输出 a (4 维: 3 速度 + 夹爪), chk["fallback"] = None
算错 + 回退开   → 输出 **该点轨迹真值关节** (6 维, deg), chk["fallback"]="traj215:第 i/N 点"
算错 + 回退关   → 输出 0 并标 hold(不直驱, 轨迹通道照常) —— 绝不能把 0 当"停车指令"又当"正常输出"
```

轨迹真值读法: `zmax_data/rokae_sdk/traj_step_state.json` 的 `cursor` + `tools/web/real_traj_joints.json`
的 `frames[i].j`(rad) → deg。写成一个独立函数(如 `traj215_target()`), 取不到就返回 None 让上层走 hold, 不要抛。

### 7.4 维度契约(最容易埋雷的一处)

回退输出换了维度(4→6), 所有沿用旧字段的下游都会把**关节角当速度**。必须同时:
- 出口显式带维度与来源: `u_cmd_dim` · `fallback` · `traj_cmd_deg`(6 维时), 4 维字段一律给空列表而不是切片。
- 6 维那一拍**不写** `u_prev`(速度), 改存 `traj_cmd_deg`, 并把 `u_prev` **置零** ——
  否则上一拍的速度留在账上, 结算时被当成"本拍指令"。
- 外部广播(如 AR 链 `exec` 分区)同时给 `u_dim` 与 `fallback`, 让页面能区分"直驱指令"与"轨迹真值"。

### 7.5 零回归与守门验证

- 同一份输入在 `off` 与 `shadow` 下各调一次 `decide()`, 断言 `u` **逐位相等**(实测 `atol=0`) —— 这是"影子不改行为"的唯一硬证据, 别用肉眼。
- 单测要覆盖: 正常 → 4 维原样; NaN → 6 维真值; 跳变(变化率超) → 6 维真值; 回退关 → 0 + hold;
  回退当拍 `u_prev` 已归零。
- ⚠️ 造真值样本时 **mtime 必须用当前时间**: 用 `time.time()-100` 造的时间戳会被新鲜度判陈旧 ⇒
  方向校验整段被跳过, 测试"通过"但你根本没测到方向(实测症状: `angle=None` 却 allow=True)。

### 7.6 路径解析坑: 往上找仓库根别只认一个目录

`src/zmax_data/` 这个历史误建目录真实存在 ⇒ "向上找含 `zmax_data/` 的目录"会命中 `src/`,
拼出的 `src/zmax_data/...` 不存在, 写文件静默失败(被 try/except 吞掉)。
要求**同时**存在 `zmax_data/` 与 `src/lerobot/` 才算仓库根。

### 7.7 单一输出: 把最终结果收成一条 `action` 总线

用户要「监控这个 action 变量 / 后端用这个值操作机器人」时, 不要再让每个节点各算各的输出、后端各处各自解释。
只留**一份**:

```
action = {
  src      "traj215"(调试/回退) | "ss"(状态空间算的)      ← 唯一的分支判据
  x y z    mm      ┐ 与机器人读数同格式(同一套字段名, 页面/调试器/后端直接读)
  a b c    deg     ├ 欧拉角口径 = 单一真源 tools/pt_pose.py:abc_deg()
  qx qy qz qw      ┘ 姿态的四元数表示(给策略/插值用)
  j1..j6   deg     · joints_src 标明来源(轨迹真值 / 实测)
  grip_mm · grip_act(open|close|hold) · grip_state(开|合) · grip_src
  grip_meas_mm · grip_meas_age_s        ← 实测回证(读不到就 None + 年龄, 不猜)
  i        轨迹点序号    why  人话原因    ts
}
```

- 写入侧: 每拍原子写一次 `zmax_data/ss_live/action.json`(`tmp` + `os.replace`), 同时进节点 `out1.action`。
- 读取侧: 后端**只读这一份**做分支 —— `src=traj215` ⇒ 照旧回放轨迹; `src=ss` 但执行接口没落地/开关没开 ⇒
  **明确回退并写原因**到 `why`/`last_msg`, 不许静默按旧路跑。
- 缺真值、护栏未放行、NaN ⇒ `src` **一律** `traj215`: 宁可回放已验证的轨迹, 也不输出算不出来的位姿。
- 夹爪在 `ss` 档**不由 u 决定**时就写 `grip_act="hold"` + 实测值, 别拿计划值冒充实测。

### 7.8 变量就叫 `action`, 不要叫 `a`

一处叫 `a`、输出字段叫 `action`、文件叫 `action.json` ⇒ 每次调试都要解释一次"这个 a 是什么"。
统一成 `action`(含节点内 `u_vec` 之类的旧名一并改): 断点里看到的名字 = 输出契约里的名字 = 用户监控的名字。
改完必须重跑离线四分支, 确认数值一字未变(纯改名不许伴随行为变化)。

### 7.9 位姿输出的两个来源与一个陷阱

- 直驱档: `pose = 当前位置(latest.json, mm/deg) + u*dt`, 姿态沿用当前四元数; `src` 标 `pos+u*dt`。
  ⚠️ `dt` 必须取**上一拍时间戳差**, 首拍/缺时间戳时用名义周期(10Hz ⇒ 0.1s)。用 0 或未初始化值会
  算出 −58mm 级假位移(实测) —— 位姿输出一错, 用户会当场判"程序乱算"。
- 回退档: `pose = frames[cursor]` 的目标位置 + 目标四元数(`src` 标到具体点号)。
- 两份 pose 都带 `age_s`(真值帧龄) 与 `src`: 用户拿它直接和示教器读数对照, 没这两项等于无法核对。

## 6. 汇报口径

- 写清"模型真参与 N% / 兜底 M%" —— 只有成功率 = 无法区分接管与退化。
- 写清是**单进程**还是**跨进程**重复 (前者只能证明可重复性, 不能证明泛化)。
- 引擎解析链已最优时, 模型的正确位置是"安全的小修正"; 要真超越得靠 RL 或换数据分布,
  靠调守卫调不出来。
