# 录制轨迹：真停留点 vs 事件点，以及状态标签

用于「页面上/环上要标停留点」或「这段轨迹哪些地方真停住了」这类问题。
不要拿「速度局部极小」或「硬编的到点索引」直接当停留点 —— 两者都会多标。

## 1. 两种口径，别混

**A. 研究口径「静止停点」**（只想知道哪里真的停过）：

```
停留点 ⇔ speed[i] < 0.15 · med  且 方向变化(±3 帧) >= 25°  且 两侧位移都 > 10 mm
```

实测 215 点 / 42.85s / 中位 166 mm/s：纯速度极小给 **47** 个候选，加方向判据后只留 **4** 个。

**B. 回放口径「换向停点」**（要臂在每个方向突变处停一下 —— 用户明确要的就是这个）：
**不要卡速度**。录制轨迹是折线，绝大多数拐点只是在转向、根本没有零速平台，卡速度会漏掉他看到的拐点。

```
换向点 ⇔ 方向变化(±W 帧, W=5) >= 45° 且 两侧位移都 > 10 mm 且 5 帧内只留转角最大的
```

同一份 215 帧实测：**22 个点**（`#10 #18 #29 #35 #42 #60 #69 #79 #86 #101 #107 #119
#125 #132 #140 #149 #167 #177 #184 #190 #199 #209`）。这 22 个直接当 `ZMAX_RT_HOLD_AT`、
`HOLD_MS=1000`。⚠️ 停留时间要算进 ETA（22 个 × 1s = 22s）。
参数交给环境变量（`ZMAX_STOP_TURN` / `ZMAX_STOP_WIN`），别写死在代码里。

方向变化 = `acos( cos⟨p[i]-p[i-W], p[i+W]-p[i]⟩ )`。

## 2. 事件点不是停留点（最容易多标的地方）

夹爪/AOI 这类「到点触发」的动作点，在**录制轨迹里往往是在动的**（到达即触发，不停机）：

| 点 | 名义动作 | 实测速度 | 换向 | 结论 |
|---|---|---|---|---|
| #9   | 合爪·抓取 | 0.8 mm/s (0%)   | 165° | 真停点 |
| #125 | 金手指 AOI | 454 mm/s (274%) | 102° | **在飞，不是停点** |
| #151 | 金手指 AOI | 214 mm/s (129%) | 6°   | **在走且方向平顺** |
| #172 | 表面 AOI   | 161 mm/s (97%)  | 81°  | **在走** |
| #205 | 松爪·放置 | 179 mm/s (108%) | 25°  | **在走** |

做法：把触发点单独存成 `EVENTS`（只用于给状态贴标签），`STOPS` 完全由几何判据现算。
两者别混在一个列表里，否则环上会多出 4 个假菱形。

## 3. 单位坑：`p` 可能是米

`real_traj_joints.json` 的 `frames[i].p` 是 **米**（0.665 m），而阈值按 mm 写（10 mm）。
直接比 ⇒ 一个停点都找不到，且**不报错**。归一化：

```python
q = list(f.get("p") or [0,0,0])
if max(abs(c) for c in q) < 20:      # 量级 <20 ⇒ 单位是 m
    q = [c*1000.0 for c in q]
```

同 fichier 里 `traj_hopf.json` 的 `p_mm` 已是 mm，两个源别混用。

## 4. 状态标签要诚实，且只由一张表定名

录制文件本身没有阶段标注真源。能核的只有两条证据：① 停留点/事件点的触发记录 ② 该段的实测几何
（水平位移 vs 垂直位移比）。所以：能对上的给具体名，对不上的**留空**（页面显示 `#帧号`），
等他填 —— 不要用 `停留(速度≈0·换向)` 这种系统词占位，它会让人以为名字已经定了；也不要自己编
「对位/检测」这种听起来像真值的词。

名字存**独立的小 JSON**（`zmax_data/rokae_sdk/stop_labels.json`，`{"<帧号>": {"name":…, "del":true}}`），
别写回轨迹真源：轨迹是录制事实，名字是他的工艺意见，两者生命周期不同。
删点 = 在该 JSON 里打 `del` 标记，服务端 `_stops()` 过滤掉，`holds` 列表自动跟着少一个
（不要从 PHASES 表里真的删行，那会让帧区间出现洞）。

### 4a. 用户的工艺词汇 = 唯一真源，落地成一张帧区间表

现场是按**他自己的工艺顺序**看轨迹的，几何推断只是候选。一旦他给了名字，就把名字收进服务端
**一张 `PHASES = [(i0, i1, 名字), …]` 表**（按帧区间），块状态先查这张表、查不到才退回速度/事件推断。
不要按名字单独打补丁，否则下一句纠正时改不干净。

一条真机上下插口装配链路的实测词汇（可直接复用，缺的让他补）：

```
起始点 → 转移 → 下降 → 抓取点 → 上升 → 转移 → 扫码点 → 转移 → 对位
      → 力控搜索(里萨如) → 插入 → 设备工作点 → 离开 → 拔出 → 拔出点 → 转移 → …
```

### 4b. 他会纠正的位置，提前按几何把候选算好

实测纠正的类型就三种，先算好数据再回话，别争：

| 纠正 | 判据 |
|---|---|
| 「A 和 B 之间还有转移」 | 两段之间有一帧的大位移，`水平位移 ≫ 垂直` ⇒ 单独一行 `转移`，别把它并进前一段 |
| 「刚才那个是拔出点，不是准备拔出点」 | 动作完成态的点 ≠ 动作前准备的停止点；完成点独立一行（零宽度地标） |
| 「工作点之后、拔出点之前，增加离开阶段」 | 段内再切：贴住工件外抽 → 抬起 → 停止 |

切段用**逐帧 dxy/dz 分类**（`dxy>15 且 |dz|<10` = 转移；`dxy<12 且 dz<-6` = 下压；
`dxy<12 且 dz>6` = 上抬；`dxy<12 且 |dz|<=6` = 微调/对位），再把连续同类帧归并成间隙。

### 4c. 一个物理点可以身兼多义，不要硬起一个名字

同一帧在不同阶段有不同语义，实测一例：插到底的那一帧 = **插入终点 = 设备检测点 = 设备工作点
= 拔出动作的起点**，四种说法都对。地标行只写最常用的那个（`设备工作点`），在汇报和 `EVENTS`
的 `desc` 里把其余语义写全；换成只覆盖其中一义的名称（如「插入完成点」）会让他在别的阶段找不到这个点。

### 4d. 人工阶段表与实测块的接缝

- 实测块（按速度档切出来的）只在 `i0 > PHASES[-1][1]` 之后才回退使用 —— 边界写死成某个帧号
  会让同一段出现两行同名（实测「力控搜索」「退出」各出现两次）。
- 新阶段落地后先 `print` 前 13 行状态，重名/缺段一屏就能看出来，别让它藏在后面。

### 4e. 他说「这些点我都标过」⇒ 去点位真源找，别在清单里重构掉

停点/地标名字一旦按**帧号**存储，清单的「点集合」一换代（例如从人工阶段表改成「几何检测的 22 个换向点」），
旧名字全部落空，页面上一片 `#帧号` 或只剩几个名字 —— 他会直接说「金手指点2、侧面点0~3 我都标记过，你忘了么」。

- 名字的**真源**是点位表 `config/points/cell_points.json`（`slots` 槽1~14 / `holes` 口+插入 / `sides` 侧面点0~3 /
  `scrap` 废料位 / `goldens` 金手指点1~2，每条带 `src` 说明是示教实测还是轨迹落点实测）。
  说「这些点丢了」之前先 `grep -rl "侧面点" --include=*.json` 定位它，再拿坐标对轨迹取最近帧。
- 映射方法：对每个点名在 215 帧上算最近落点，同时报**距离**；>30mm 的直说「这条轨迹没经过这个点」，
  不要硬挂到某一帧上（一堆槽位距轨迹 100~280mm，硬挂就是造假）。
- 🔴 **清单 = ∪(他说过名的点按最近帧映射) ∪ (几何换向点)**，不是二选一。分配帧号时「先到先得、不重复占帧」，
  同一帧上有两个名字就取更近的那个、另一个顺延到次近帧并说明。
- 他要「全都列出来」时给四列表：`点名 / 坐标(mm) / 最近帧 / 距离(mm)`，并单标出「轨迹实际经过(<30mm)」的那几个。
- 停点勾选表的**初始值也取这个并集**（地标全部预勾上），别只给几何那 22 个：他是在工艺点上停，不是在拐角上停。

### 4f. 「你自动标记」= 按工序顺序 + 到位容差给每帧贴名

他要的不是“你自己编”，是**不需要他动手就能得到一张顺序正确的段表**。三种做法只有第三种能用：

| 做法 | 实测结果 | 为什么错 |
|---|---|---|
| 帧比例映射（第 k 段占帧数按比例分） | 首段变成「初始点 0-181」，整列错位 | 停留时间与弧长不成比例；一个长转移就吃掉半张表 |
| 每帧找最近工位点 | 插入到底整段丢失、钩拉环跑到插入之前 | 两个工序点可以只差 **13mm**（插到底 818,227,190 vs 钩位 806,230,189），同一个位置同时命中两点 |
| **顺序约束 + 逐点容差** | 26 段，与现场顺序逐条对上 | 见下 |

算法（`tools/states_from_traj.py`，90 行）：

```python
ORDER = [("初始点",(663.9,-29.3,293.5)), ("槽2抓取",(649,454,111)), ("扫码",…), ("插入到底",…),
         ("等待检测",…), ("钩拉环解锁",…), ("金手指检测1",…), ("金手指检测2",…),
         ("侧面点1",…), … ("下盘放料",…), ("回初始位",…)]      # 只写**工序顺序**，不是几何顺序
TOL = 15.0
TOL_PT = {"插入到底":7.0, "钩拉环解锁":7.0, "金手指检测1":4.0, "金手指检测点2":4.0}  # 近重合点收紧
k = 0; seen = set()
for p in P:
    d0 = dist(p, ORDER[k][1]);  t0 = TOL_PT.get(ORDER[k][0], TOL)
    d1 = dist(p, ORDER[k+1][1]); t1 = TOL_PT.get(ORDER[k+1][0], TOL)
    if d0 <= t0 and d0 <= d1 and ORDER[k][0] not in seen:      # ① 只能前不后
        labels.append(ORDER[k][0]); seen.add(ORDER[k][0])       # ② 一名一圈只标一次
    elif d1 <= t1 and ORDER[k+1][0] not in seen:
        k += 1; labels.append(ORDER[k][0]); seen.add(ORDER[k][0])
    else:
        labels.append(None)                                     # 其余帧 = 移动
```

后面接三步收尾，缺一步他都会当场看见：

1. 连续同类归并成段；`None` 段命名为 `移动→<下一个操作名>`（与他口述的“把搬运都改成移动”一致）；
2. **操作段补到 ≥3 帧**，帧从**前一段移动**里借（借完移动至少留 1 帧）—— 否则臂停在点上时投影被转移段抢走，出现“侧面点4 有点不同步”；
3. **同名相邻段合并**。不合并的实测现象：`12 移动→金手指检测1 / 13 金手指检测1 / 14 移动→金手指检测1 / 15 金手指检测1`，他一句「12 和 14、13 和 15 重复了，删掉」—— 臂往返经过同一个点时，几何上必然重复，靠 `seen` 去重+合并才能消掉。

补一条取整圈的前提：**一圈 = HOME 常量 → 回到 HOME**，不是“日志第一天到日志最后一天”。日志末尾机械臂常在**高位停放**（z≈999），把末帧当 home 会把 2~3 圈拼成 5000 帧、14813mm 的怪物（状态表也就全乱）。判据：以 `HOME=(663.9,-29.3,293.5)` 为锚找相邻 home 帧，取**路径长度 3~9m** 的那一段。

## 5. 验收

- API 里回传 `stop_rule`（`speed_frac / turn_deg / dedup`）+ 每个点的 `speed_mm_s / speed_pct / turn_deg`，
  让判据可复核；页面只渲染不重算。
- 画布侧数标记像素：琥珀（夹爪 `#ffd166`）与青（其他 `#9fe8ff`）都要 >0，且与 `len(stops)` 一致。
- 汇报给用户时用「idx / 速度(占中位%) / 换向° / 保留或剔除」的表格，别只说“清理了假停点”。

## 6. 要用户给停点标动作名：在每个停点**原地停一下**

光在页面上标点他认不出动作；让他“看到臂停住”再告诉你是什么动作最有效。

`tools/rokae/arm_rt_stream2.py`（RT 流式回放）已支持：

```
ZMAX_RT_HOLD_AT=9,19,135,176   # 录制帧号（逗号分隔）
ZMAX_RT_HOLD_MS=2500           # 每处停多久，默认 0 = 不停
```

实现：1ms 表建好后，用关节角 L∞ 距离为每帧找最近表项，在那里插 `HOLD_MS` 条**同姿态**表项（位置不变、只是不走）。
实测姿态偏差 ≤0.003°，总时长 = 原时长 + n×HOLD_MS（260.8s → 270.8s）。

meas 日志每条多一个 `h` 字段（1 = 正在停留），可数“进了几次停留、在哪个相位”；
汇报时给「第几个 / 帧号 / 相位 / 位置(mm)」四列，他在臂停住那一下对号。

⚠️ 新环境变量必须在 `tools/rokae_sdk_run.sh` 的 `-e` 列表里透传，否则容器内读不到（不报错，只是不停）。
先跑 `ZMAX_RT_DRY=1` 看 `{"step":"holds"}` 的 `detail` 与 `dur_s` 再上真机。
