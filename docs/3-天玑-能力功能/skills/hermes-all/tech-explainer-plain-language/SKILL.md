# 把技术讲给不做这项工作的人听 (人话 · 时间线 · 类比 · 我们的数字)

## When to Use

- 用户问「原理是什么 / 这是什么东西 / 这技术怎么来的 / 历史」
- 用户说「说人话」「慢一点」「形象一点」「从基础讲起」—— **这三句是同一件事的三次纠错信号**, 下一轮直接按本文写
- 要向非技术决策者解释一个模型/管线/工程选择, 且他之后会拿这套理解去拍板或对外讲

## 四段结构 (顺序固定, 别倒置)

1. **一句人话结论** —— 不带字段名、不带缩写、不带单位符号。例: 「它本质上是在做一件事: 把一堆照片反推成一个能转着看的立体模型。」
2. **时间线** —— 按年代推进, 每一代讲三件事: 它解决上一代的什么病 · 它自己卡在哪 · 下一代怎么绕过去。
   不要平铺「A 有 X 特性, B 有 Y 特性」。
3. **一个能自洽的类比** —— 挑一个日常物件, 用它解释**机制**而不是外观; 类比一旦选好就沿用到结尾, 不中途换隐喻。
   类比必须与事实不冲突: 说「一袋彩色小气球」可以, 说成「一堆点」就错了 (点没有大小和方向)。
4. **落回我们自己的坐标** —— 我们现在用的是哪一代/哪个实现 · 我们的实测数字是什么 · 我们的短板具体在哪一项。
   最后一句给「下一步最小可做的一步」, 而不是一串选项。

## 硬规则

- **术语可以出现, 但每个术语出现时顺手给一句人话解释**; 不要开头堆术语再统一解释。
  被要求「说人话」的第二轮仍堆术语 = 这一轮作废, 整段重写而不是只改开头。
- **只用可核的数字**: 引用实测值 (训练步数 · 耗时 · 精度 · 误差) 时说清口径; 拿不到就说「这项我没量」,
  不许给「大概」「差不多」。
- **指标不许跨口径比**: 同一个指标换数据集/换留出协议就不可比 —— 对比时先声明两边口径, 口径不同就分开列, 不排名。
- **讲失败要给机制, 不只是现象**: 「糊」要落到「哪些信息没进模型」(视角不够 / 分辨率被裁 / 剪枝过度), 否则听众只能记住「不行」。
- **一次讲一层**: 用户说「慢一点」意味着上一轮信息密度过高 ⇒ 这轮只讲主线, 分支留到被问时再展开。
- 图文并列时先文字结论, 图只作证据; 不要把「请看图」当成解释。

## 常见坑

- **把历史讲成产品广告**: 每代技术都有它当时失败的场景, 讲出来才解释得清「为什么下一代长这样」。
- **类比盖过事实**: 为了顺口把「概率分布」说成「一张图」, 听众后面会拿这个类比推错误结论。
- **只讲「我们能做什么」不讲「它做不到什么」**: 能力边界 (只看起来像、量不准 / 只对某类物体有效) 必须明说,
  否则下一次现场演示会被当场戳穿。
- **用「先进/领先」这类形容词替代数字**: 换成一个可核的量 (分辨率、误差、耗时) 才有说服力。

## 收尾模板

> 「一句话: <人话结论>。它这一路怎么来的: <三个年代各自解决什么>。用个比方: <类比>。
> 我们现在在: <哪一代/哪个实现> · 实测 <数字>. 短板是 <具体那一项>. 下一步最小的一步是 <一个动作>.」
