# 固定外参正投影: 把「虚拟物体」画到相机像素上

## When to Use
- 末端**没有实物**(没夹住工件), 但用户要在画面里"看到一个光模块/连接器/工具"。
- 物体与相机**刚性固连**在同一刚体上(相机装在腕上 + 零件在末端), 需要把它画到画面里。
- 要把一个已知尺寸的长方体/几何体按外参投到像素并叠到实时帧(只可视化, 不下发动作)。
- 反例不属此列: 物体在世界/料盘里、相机在动 ⇒ 走 `sim-real-scene-overlay` 的 base→TCP→手眼链。

## 🔴 第一件事: 判定该走哪条链

| 情形 | 链路 | 为什么 |
|---|---|---|
| 物体**在末端**(tool 系), 相机**在腕上** | `P_cam = inv(T_cam2tool) @ P_tool` | 两者相对位姿恒定 ⇒ 像素是**常数**, 与当前位姿无关 |
| 物体在**世界/料盘**里, 相机随臂动 | `base → TCP位姿 → 手眼 → 内参` | 相对位姿每隔就变, 必须用实时位姿 |

把第二种链用在第一种情形上, 等于把一个**恒等关系**变成随位姿漂移的函数 —— 臂一动就错。
这是本项目实际踩过的: 多乘了一次 `base→tool1` 的位姿再加一次 URDF 的 `tool0→tool1`,
深度正好变成 **2 倍**, 像素整体飞到画面另一处。

## 步骤

### 1. 先对账, 不通过就别调绘制
```python
T = load(T_cam2tool)
if np.linalg.norm(T[:3,3]) < 2.0:      # 米 → 毫米, 与既有服务同一判据
    T[:3,3] *= 1000.0
P_cam = (np.linalg.inv(T) @ np.array([0,0,0,1.0]))[:3]
# 这个 P_cam[2] 就是"相机到物体原点"的距离
```
- 和该机既有服务自算的相机距比(例: ar3d 的 `/api/toolframe` 的 `cam_z_mm`), 应到 0.01mm 量级。
- **深度差正好 2 倍** ⇒ 多乘了一次 URDF 的 `tool0→tool1`。手眼标定里的 "tool" 很可能**已经是 tool1**(末端零件坐标系), 不是法兰。
- **深度差上千倍** ⇒ 单位判据被写死(把本就是毫米的值又乘了 1000)。
- 对不上就是**口径错**, 不要再花时间调画法/颜色/线宽。

### 2. 几何轴定义从真源取, 不要自己定
零件长方体的轴定义必须来自服务/规格文件(通常带一句 `axes: X=法向(厚度) Y=法向(宽度) Z=中轴线(长度) 原点=头部中心`)。
- 8 顶点索引定死 `index = 4*z + 2*y + x`, 12 条棱写成常量表, 永不再算。
- **宽/厚互换是最易犯且目检最难发现的错**: 形状对、朝向错, 看着像"歪了一点", 实际差一整个维度。
- 尺寸从 spec 端点取(通常 L/W/T 都带 `src` 说明), 别把标称值硬编码在绘图脚本里。

### 3. 系统偏移: 一定有, 但必须来自实测
几何投影能对上深度, 仍可能与画面里的实物差上百 px —— tool 原点的**物理定义**与实物位置有系统差,
手眼残差再小也补不了这一块。定式:
```
shift = 实测物体中心 － 几何投影中心        # 像素常数(因为都刚性固定)
```
- 写成常数, 出处写进代码注释和 `/status`, 让人能复核。
- 🔴 **不要用运行时检测器给的偏移量**(如 `align_shift_px`): 它只在**当帧有检出**时非零,
  没检出时返回 `[0,0]` ⇒ 同一份代码一会儿对一会儿错。用户会当成"框在随机抖动"。
- 方向有多解时(沿 ±Z), 一次出多张对比图, 让视觉模型分别判, 不要在一张图上靠肉眼猜。

### 4. 自验: 让场景 VLM 判二值问题
画完必须自证。把叠加后的图喂给场景模型, 只要 4~6 个字段的小 JSON:
```json
{"on_gripper": true/false, "looks_like_module_slot": true/false,
 "box_desc": "框在哪", "note": "一句话"}
```
- 这把"我算得对不对"变成**外部可反驳**的结论。本项目正是靠 `on_gripper:false` 加 "框套在竖直金属杆/线缆上"
  才定位到那 130px 的偏移。
- `on_gripper:false` **不必然是错**: 臂不在抓取姿态时, 末端前上方看到的本来就是插槽而非夹爪。
  看 `looks_like_module_slot` 这类"语义是否落在该物体该在的位置"比看"是否压在夹爪上"更有意义。
- 别只报"画了 12 条棱"当验证。

### 5. 交付形态: 新增独立服务, 不动在役采集
- **不改不重启在役采集/推流进程**(用户在看着, 重启有风险)。
- 定式: 单独一个轻量 HTTP 服务(自己的端口) → 拉在役服务的快照 → 叠加 → 返 JPEG。原链路一字不改, 随时可停。
- 路由: `/mod.jpg?cam=<源>&along=<方向>&real=<0|1>` 返回图; `/status` 返回外参/残差/当前偏移**及其出处**/
  支持哪几路/**哪几路为什么算不了**。
- 前端加**新按钮开图**(可右键保存), 别去改原页面的 canvas 绘制逻辑 —— 原画法往往带
  `if(!MOD || !MOD.ok) return 0;` 这类"没检出就不画"的闸, 虚拟模式绕不过它, 硬改风险大。
  弹窗被拦时把 URL 当文本给出来让用户自己开。

### 6. 算不了的相机要如实拒绝
固定工位相机(金手指/表面检测这类 AOI 相机)与机器人底座之间**没标定过外参**:
物体在它们画面里的位置随臂变, 没外参就算不出来。`/status` 里给 `aoi_ready: false` + 原因,
不能静默少画。补外参要拿末端带标定板走到它视野里采 6~8 个点 —— **那要驱动机器人**, 属要授权的动作。

## Pitfalls

| 坑 | 症状 | 修法 |
|---|---|---|
| 对刚性固连的物体仍乘 TCP/base 位姿 | 框画到画面另一处, 深度差 2 倍或像素偏上百 px | 像素是**常数**, 只用 `inv(T_cam2tool)`; 先拿深度与服务自算的 `cam_z_mm` 对账 |
| 手眼里的 "tool" 当成了法兰 | 深度正好 2 倍 | 它很可能已经是末端零件系(tool1); 判据就是深度比 |
| 单位判据写死 ×1000 | 深度上千倍、框全在画面外 | `if norm(t) < 2.0: ×1000`, 与既有服务同判据 |
| 拿运行时 `align_shift_px` 当通用偏移 | 有检出一会对、无检出一会错, 看着像随机抖动 | 偏移取**实测−几何**的固定常数 + 写明出处 |
| 几何深度对得上但仍与实物差百多 px | 以为手眼标定坏了 | 手眼残差可能只零点几 mm; 差的是 tool 原点的**物理定义** ⇒ 用实测常数补偿 |
| 宽/厚轴定义搞反 | 形状对、朝向错, 目检"像歪了一点" | 轴定义抄 spec 原句; 宽/厚互换是一个整维度的错 |
| 只报"画了 12 条棱" | 用户说框不在东西上 | 必须让场景 VLM 判二值(`looks_like_*`) |
| 改了原页面的 3D 框开关 | 点了还是一像素都没画 | 那是检测模式, 没检出直接 `return 0`; 给虚拟模式**单独按钮 + 单独服务** |
| 为叠一个框重启在役采集 | 用户在看着的实时画面断一下 | 新服务自己的端口, 拉在役快照, 原链路一字不改 |
