# 交付清单与反例

## 独立叠加服务的最小骨架

```python
# 路由
GET /<obj>.jpg?cam=arm&along=+z&real=0|1   -> image/jpeg
GET /status                                -> {
#   ok, port, mod_spec{L,W,T}, handeye{t_mm,rpy_deg,resid_*,views},
#   shift_px + shift_src,             # 偏移 + 出处，必须能复核
#   cams,                             # 支持哪几路
#   aoi_ready: false,
#   aoi_note: "<哪台相机因为什么算不了>"
# }
```

- 取图走**在役服务的快照端点**(不自己开相机, 避免设备独占/抢流)。
- `real=1` 走检测器的真实框(有检出时更贴合实物), 默认走几何虚拟框(无检测也能画)。
- 叠加绘制: 两面半透明填充 + 12 条实线棱 + 顶点圆点; 填充用 `fillConvexPoly`, 不会溢出凸包。
- 标签放**轮廓外**, 别贴在盒子中心 —— 不透明底色会把凸包盖死, 看起来像没画。

## 页面接入

- 原页面常有 `if(!MOD || !MOD.ok) return 0;` 这类"没检出就不画"的闸。**虚拟模式绕不过它**, 硬改风险大。
- 定式: 加一个**独立按钮**, 点击后 `window.open('http://' + location.hostname + ':<新端口>/<obj>.jpg?cam=arm')`。
  弹窗被拦时给出可复制的 URL 让用户自己打开。
- 按钮 tooltip 写清"不依赖检测器/尺寸来源/点击出图可右键保存", 避免用户以为是原按钮的补丁。

## 逐项核对(交付前)

| 项 | 判据 |
|---|---|
| 外参口径 | `inv(T_cam2tool)` 平移投影深度 == 服务端 `cam_z_mm`(0.01mm 级) |
| 单位 | 平移 norm < 2.0 才 ×1000; 不写死 |
| 顶点 | 8 个, 索引 = 4z+2y+x, 12 棱常量表 |
| 尺寸 | 来自 spec 端点, 非标称硬编码; 宽/厚未互换 |
| 偏移 | 常数 + 出处注释 + `/status` 可见; 不依赖运行时检测 |
| 语义 | 场景 VLM 判 `looks_like_object_slot` / `on_target` 为真 |
| 副作用 | 在役采集进程**未重启**; 新服务单独端口 |
| 页面 | 新按钮存在, 服务端热读文件已生效(不用重启) |
| 诚实 | 算不了的相机在 `/status` 明写原因, 不静默少画 |

## 何时如实拒绝

固定工位相机(金手指/表面检测这类 AOI 相机)与机器人底座之间**没有标定过外参**:
物体在它们画面里的位置随臂的位置变化, 没有外参就算不出来。

- `/status` 里给 `aoi_ready: false` + 一句话原因。
- 补齐办法是拿末端带标定板走到该相机视野里采 6~8 个点解外参; 但**这要驱动机器人**, 属于要授权的动作,
  不能顺手做掉 —— 先把能做的做完, 把这一条作为明确缺口报出去。

## 与既有 skill 的分工

- `sim-real-scene-overlay`: 物体在世界/料盘里、相机在动的情形(base→TCP→手眼→像素链、深度反投影、
  多路叠加页、3D 线框画法、各种页面/连接数坑)。**本 skill 是它的一个特例分支**: 刚性固连时该链可省。
- `l5-live-arm-marking`: 用检测器实时标注臂相机画面 + "绿框定主"(锁住检测结果不抖动)。
  本 skill 进一步: 位置既是常数, 就可以**纯几何算出来, 完全不依赖检测**。
- `real-arm-handeye-calibration`: 外参怎么标出来。
