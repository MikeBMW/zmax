# 位姿驱动的分布式感知调度 (到区域就开相应感知)

## 触发条件
- 现场有多台相机(臂上/顶摄/工位检测)且分属不同作业区, 需求是「走到哪个区域, 就启用那个区域该用的感知」
- 要在轨迹/工艺通道上自动切换相机与采样率, 而不是人工点按钮
- 被问「融合定位节点该不该实现位置细胞」「大脑怎么按位置激活场景」

## 核心模型: 连续增益, 不是二值开关

大脑不是「进圈 → 触发服务」(那是手机 LBS/地理围栏), 而是**一直在低带宽看全场景, 到位后把精度权重挪过去**。
工程上必须照这个形状做, 否则靠近过程全漏。四态:

| 状态 | 判据 | gain | 相机动作 |
|---|---|---|---|
| WATCH | 不在命名区内、也不逼近 | 0.2 | 只开 overview(顶摄低帧率跟拍) |
| ALERT | **在区外但距某区面 ≤ alert_band(100mm)** | 0.6 | 预热即将进入那个区的相机(1Hz), 还不采信 |
| FOVEATE | **已在命名区内** | 1.0 | 高分辨率相机 10Hz, 出 3D 引导 |
| RELEASE | 刚从区内退出 | 0.2 | 回落 WATCH, 不瞬间断电(保留余像) |

gain 的用途: 下游按它决定采样帧率与「是否采信本次定位」—— 这就是精度加权。

🔴 **FOVEATE 判据必须是「是否已在区内」, 不能是「离区内边界多远」**。
工位区常是薄片(实测插入工位区 z 方向只有 11mm 厚), 工件贴在区底时内缩距离恒 ≈0,
那样**永远进不了高精度态**。ALERT 用「逼近某区(区外 100mm 内)」, 二者不重叠、不互斥。

## Step 1: 相机注册表 —— 能力用表定义, 3D 闸门写成代码约束

一张 `camera_registry.json`, 每台一条:
```
{id, kind: eye_in_hand|fixed, intrinsic{fx,fy,cx,cy,dist,size},
 extrinsic{mode: tcp_compose|fixed_matrix|uncalibrated, T_cam2tool, resid_mm_rms, _reason},
 depth{src,unit_mm,max_age_s}|null, role[localize|guide|quality|overview|debug],
 level: L2|L1|L0, coverage{zones,radius_m}, calibrated}
```
- **闸门**: 只有 `extrinsic.mode ∈ {tcp_compose, fixed_matrix}` 准出 3D; 其余降到 L0 只出 2D,
  返回值里**带 why(缺什么)** —— 不许静默放行、不许"差不多"地反投影。
- 只有 `role` 含 guide 且能出 3D 的相机才当主引导; 想用但缺标定的进 `blocked` 列表并写明原因。
- **registry 落 gitignore 数据盘时, 进库的是生成器**: 从内参 json + 手眼 json + 相机服务 `/api/cams` 重生成。
  换机器靠跑脚本复现, 不靠手抄数值。

## Step 2: 区域表 —— 工程真源 + 轨迹派生两层, 真源永远优先

- 工程真源(如 `env_model.json::zones`)常是**点位台账聚类**出来的, 覆盖不到工作空间全貌:
  实测 96 个真实轨迹点只有 11 个(11.5%)落在命名区内, 其余全进兜底区 ⇒ 调度大段时间"无区可依"。
- 解法: 加一层**轨迹派生区**(从相机服务的命名轨迹取点 → bbox + 20~30mm 余量), 合并时用 `setdefault`:
  同名时工程真源胜出, 派生层不许覆盖真源。
- 派生区可自带 `"cams": {"cam_id": "role"}` 绑定, 优先于 registry 的 coverage —— 但要仍过 3D 闸门。
- **兜底区不许抢具体区**: 多区 bbox 重叠时, 排序前先把「其它/包络外」剔出候选池, 只在具体区里取中心最近。

## Step 3: 位置细胞层 —— 需要的是「表征与校验」, 不是「定位」

有编码器真值(零漂移)时, "我在哪"不需要位置细胞(那是更低层的本体感觉做的)。真正缺的是三件事:

1. **群体编码**: 位置不是一个点, 是一群细胞的加权激活。网格 50mm + 高斯核 σ=100mm。
   🔴 **radius 必须按 3σ 覆盖**: σ=100mm 只算 ±2 格会截断高斯, 质心解码偏 13.6mm;
   改成 `radius = ceil(3σ/CELL)` 后误差 0.2167mm。
2. **模式补全**: 群体向量解码(质心), 只留最强 40% 细胞仍能解到 0.0986mm ⇒ 部分线索可锚定。
3. **重映射检测**: 同一物理地点、表征突变 ⇒ 环境变了或真值漂了。这是我们平时完全没有的异常检测。

🔴 **只用位置的群体编码物理上不可能检出重映射** —— 同一位置必然产生同样 code, 相似度恒 1.0
(实测 0/15 全漏)。真正的重映射是「**同一地点 + 不同环境**」, 判据必须带上下文:
- 同一地点(<100mm) + `ctx_key` 不同 ⇒ remap(换场)
- 同一地点 + ctx 相同 + 激活相似度骤低(<0.5) ⇒ remap(真值抖动/编码异常)
- 且要比对**邻域**样本(±2 格), 只比同一网格不行 —— 偏 200mm 时格子早换了。

接法: 在融合节点里**只读调用**, 输出 `{sim_best, dist_mm, remap, why}` 进状态记录;
不改 fuse_sensors 的数值, 不打开任何融合闸门。

## Step 4: 验收判据 (每条都要能复跑)

- 每个区中心回投 → 判定回自己; 四态按轨迹逐点输出且无抖(区域边界 20mm 滞回)
- 3D 闸门: 能出的那台出 True, 其余全 False 且带 why
- 轨迹扫描: 输出区域切换序列 + 每段主引导相机; **无点位的轨迹要如实报 0 点**, 不编
- 编解码自洽 <1mm; 删 60% 细胞仍 <2mm; 换场检出 ≥n−1(首点无历史基准必然不报); 正常复跑与小幅漂移 0 误报

## Pitfalls
- 把「到位置开相机」做成 if/else 硬编码: 必须是一张表(区 → 相机角色), 调参不改代码。
- 用「离区内边界多远」当精度判据 → 薄区永远进不了 FOVEATE(见上)。
- 相机注册表手抄数值 → 换机器就错; 必须落生成器。
- 派生区覆盖真源 → 工程配置被悄悄改掉; 用 `setdefault` 锁死优先级。
- 检测相机(0.25Hz)拿来做视觉伺服/位姿引导 → 采样率物理上不够(4000ms/帧), 它只能做「到位后判一次」。
  伺服侧的符号坑与采样率门槛见 `robot-vision-3d-localization`。
- 轨迹数据缺点位时(台账没标), 如实报 0 点并说明缺哪个点 —— 不要拿别处坐标凑一条出来。
