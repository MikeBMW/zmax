# 夹具搬盘动作（工位 A → 工位 B，连续播放）

> 典型需求：「用夹具把位置3的 tray 盘，夹到位置2；要动作连续，计算高度」。
> 交付物 = 页面上一个按钮跑完一段 6~8s 的连续动画 + 回复里一张高度推导表 + 实测误差数。
> 别把它做成"瞬移"或"几步跳"，也别把高度写成拍脑袋的数。

## 一、高度先算，再写动画
从夹具几何反推 tool1 该多高，公式只有一条：

```
tool1_z = 盘底高度 + 指尖下探量 + 抓合余量
```
- **指尖只能是竖直平行面，不许有向内的水平延伸（底部内勾）**：带勾 = 从盘底下兜，盘坐在桌面/叠盘上时根本伸不进去，
  一眼就被判「不能从下面夹，要从上面夹」。工作面就是竖直段的内侧面，正好贴 `x = ±跨度/2`（跨 380 ⇒ ±190）。
- 指尖下探量 = 梁厚 + 本体高 + 指尖长（实测 26+67+60 = **153**），`PAN_DROP = 153 + 离盘底余量 9 = 162`。
  **9mm 余量不是拍脑袋**：叠盘取件时指尖是从上一层盘底上方下来的，太低会顶到下面那一盘。
  这个数写成一个常量（`PAN_DROP`），三档高度全部由它派生，改夹具只改这一个数。
  （历史坑：早期指尖带 12mm 底勾，下探算成 169、`PAN_DROP` 写 178；勾子既夹不动也伸不进去 ⇒ 夹具改形后三档高度全部重算，别沿用旧数。）
- 三档实测（盘壁高 25、面盘高 40）：
  - 取件 `盘底=0`（盘坐桌面）⇒ tool1 **162**，指尖落在 9~69mm，与盘壁(z 0~25) 重叠 16mm；40 高的方盘重叠 31mm。
  - 搬运 `盘底=120`：沿运动路径扫一遍所有物体顶面取最大（本例最高是中方盘 40），余量 80mm。
  - 放置 `盘底=40`（叠在面盘顶面）⇒ tool1 **202**；落 25 高的托盘盘沿 ⇒ 187。
- **落位面要在回复里点名**：盘放在"另一只盘顶面"还是"桌面"是两个不同结论；后者需要先把占位盘搬走。
- **落点换了就重算三档高度，别沿用上一轮的数**（用户点错工位、后一轮改口是常态，一条需求曾连改两次落点）：
  - `PLACE_Z` = 落点那只盘的 `H`：叠在同规格 545 托盘盘沿 = **25**、叠在 4#方盘顶面 = **40**、落桌面 = 0。
  - `CARRY_Z` 按**新路径**重扫最高障碍。判"路径是否经过某个高物体"用参数化线段在它的 y 带里解 x：
    `x = x0 + (x1-x0)*(yt-y0)/(y1-y0)`，解出的 x 落在该物体 x 区间外 = **不经过**。
    实例：8 层 320mm 堆叠在 x870~1100 / y735~1050；路径 (920,232)→(540,777) 在 y=735 处 x≈569 ⇒ 不经过，
    搬运高度按 25mm 盘沿取 120 够（实测最低 119）。
  - 改口只动 `from`/`to` 两个 `{cx,cy}` + `PLACE_Z` 三个数，动画/IK/定格/自检代码一行不改；
    坐标从工位表取（`TPAN5`=位置3、`TPANL`=位置4、`TPANM`=位置2 的 `cx,cy`），**别在代码里手写 mm 常量** ——
    否则下一次改口必然漏一处。
- 搬运高度用**中段拱起**（走弧，+25mm）而不是纯直线：直线平移会擦过路径上盘的边沿。

## 二、IK：三类坑，一个都别踩

**坑 1：拿错代价函数 ⇒ 假的"够不到"。**
用器件插入那套 `_costReach`（要求器件长轴水平、厚度法向朝上）去解搬盘目标点，实测差 46~81mm，
看起来像"这条臂够不到那个工位"。诊断口径只有一步：
```js
// 纯位置、无姿态罚的全局粗搜, 量出来还差多少
best = min over q of |FK(q).tool1 - T|
```
纯位置 err 掉到几毫米 ⇒ 是**姿态约束**卡的，不是工作空间不够，收起"挪底座/换臂"这类结论。
搬盘用的代价：`dp*10 + tilt*60`，`tilt = sqrt(R[0][2]^2 + R[1][2]^2)`（工具轴偏离竖直的程度）。

**坑 2：每个路径点各自全局搜索 ⇒ 关节跳 150°、插值出来手臂乱甩。**
全局最优会在多个等效手臂姿态间跳（实测相邻点 [13,2,-130] → [-150,-78,-29]）。
正解：**逐点从上一点的关节角起解**，且解算器要"受限"而不是纯局部：
```js
function _ikSeed(T, seed){
  // ① 只在 seed ±48°、步长 16° 的格子里粗搜（4 个活动关节）
  // ② 代价 = _costCarry(q,T) + 1.5~2 * Σ|q-seed|   ← 关节偏离罚, 让手臂尽量别换姿态
  // ③ 从粗搜最优处做坐标下降（步长 6°/3°/1.5°/0.7°），每步查 _qOk() 限位
}
```
纯局部下降（不粗搜）在长臂展处会卡局部极小（实测差 46~81mm）；纯全局会换姿态。两者都不行。
首点可以全局粗搜一次，其后每点 `_ikSeed(T, prev.q)`。

**坑 3：个别点确实超差 ⇒ 朝基座收，并把这个数报出去。**
收法：`T += 单位向量(基座-目标) * err*0.7`，重解，最多 12 轮；收多少记在 plan 里（`clamp` 字段），
回复里写"盘心落在 x=…，比目标差 …mm，就是够不到的那 …mm"。**不要静默夹住不说。**

## 二·五、夹爪「在转」≠ IK 问题：朝向要在绘制层锁死
夹具的水平基准是从 tool1 模块轴的**水平投影**算的（`B = normalize(z.xy)`，`A = 垂直于 B`）。
手臂底座方位必须扫过一段角度才够得到目标工位（实测 207°→163°），投影跟着变 ⇒ 画面里夹爪自转 44°。
- 正解：规划时算一个 `CARRY.yawB`，`_t1world()` 里若存在就改用它，`A` 由它派生。
  实测朝向波动 44° → **0.00°**。判据：逐帧采样 `atan2(B[1],B[0])`，max−min 必须是 0。
- **`yawB` 必须是盘边的方向，不能直接照抄手臂投影**：只做到“不转”还不够，卡爪会停在和盘边斜交的角度上，
  物理上夹不起来（紧接着就会被指「应该平行或垂直 tray 盘，你这样夹不起来」）。
  规则：盘宽 W 等于夹持跨度时，卡爪开合沿 W 所在的边、进给沿另一条边；380 跨度的托盘 ⇒ `B=[0,±1,0]`，
  手臂投影**只用来定 ± 号**。验收报三个数：左右卡爪间距 `(380.0mm, 0.0mm)`（X 向拉满、Y 向归零）、
  卡爪中心 vs 盘心偏差 `(0,0)mm`、与盘边夹角 `0.00°`。
- **别用 IK 姿态锁死代替**：把整个旋转矩阵当硬约束（权重 1200）实测把手臂逼成 j1 甩 179°、j5 甩 249°、
  终点差 256~300mm —— 该约束在这个工作空间里不可行。5 自由度（位置 + 工具 Z 方向）DLS 也直接发散。
- j4/j6 是绕工具轴自转的关节，位置/倾角代价对它们**完全不敏感** ⇒ 解算器在里面乱漂（实测 j6 漂 123°，
  画面上就是手腕自转）。加罚项 `400*(|q[3]-j4ref| + |q[5]-j6ref|)`，实测 j6 摆动 123° → 0°。
  **不要硬钉死**（粗搜与下降都不许动 j4/j6）：远端点位解不出来，整个 plan 返回 null。
- 回复里给一句人话结论：手臂本体必须转（底座方位要扫），夹爪和托盘朝向不变 —— 否则用户以为你没改。

## 二·六、自己写数值 IK 时，先验算器再跑路径
坐标下降不够用时会上 DLS（阻尼最小二乘）。动手前先做三条自测，不过就是公式错，别拿去跑真实路径：
1. 目标 = 当前 FK 姿态 ⇒ 误差 0、关节不动。
2. 目标 = 当前 + 20mm（保持姿态）⇒ 收敛到 0。
3. 目标 = 平移 100mm ⇒ 收敛到几 mm。
- 公式是 `dq = Jᵀ (J Jᵀ + λ²I)⁻¹ e`。**漏掉外层 `Jᵀ` 的表现是关节一动不动**（不是缓慢收敛），最容易误判成“没解出来”。
- 右端项就是误差向量 `e` 本身；写成 `J·e` 维度就不对，表现是每步只挪 0.02rad、看着像卡住。
- 雅可比用数值差分即可：每关节扰 1e-4，量 `d(位置)/dq` 与旋转向量 `d/dq`，姿态项按 1rad ≈ 0.2m 折算。
- 新增矩阵工具函数**先搜同名**：本文件里 `_mm(v)` 是 mm→m 的标量换算，把矩阵乘也叫 `_mm` 会顶掉它，
  整场景坐标变 NaN（全部物体错位/消失）。矩阵乘叫 `_mm3`、转置叫 `_mT3`。

## 三、动画：关节空间插值 + 保住终点姿态
- 用 5~7 个关键位（`{w:世界mm, t:毫秒, hold:'grip'|'lift'}`），每段 `smoothstep`（`3t²-2t³`）插值，
  段末速度归零 ⇒ 启停是软的，用户说的"动作连续"就是不要一帧一跳。
  判据：逐帧抓 `q`，**每帧最大关节步 < 4°**（实测 3.18°）、末端峰值 < 520mm/s（实测 511）。
- 时间轴走 `requestAnimationFrame` + 累计时间定位当前段；`el > 总时长` 收尾。
- **播完不要清 FK**：`CARRY.M=null` 会让手臂在最后一帧瞬间弹回真实姿态（肉眼就是"咔"一下）。
  保留终点 FK，把"动画期间用 FK"改成"只要 `CARRY.M` 存在就用它"：
```js
function _slaveArmM(){ return (CARRY && CARRY.M) ? CARRY.M : LINKM; }
```
  同一个 getter 要给**臂绘制**（`drawUrdf(...,_slaveArmM(),…)`）和**夹具取帧**（`_frameOf(_slaveArmM(),'tool1')`）两处共用，
  否则臂动了夹爪还留在原位。
- 手上有盘时：复用 `drawTrayPan(g,pr,spec,zoff)`，每帧按 tool1 位置反算盘心/盘底（`盘底 = tool1_z - PAN_DROP`），
  原位置那只 `spec.show=false`；播完把盘留在目标位（存一个 `CARRY.done={cx,cy,z}` 供后续帧画）。
- 起点/终点要用**从机器人世界系**：主臂系 = 绕竖直轴 180° 的反变换 `[SLAVE.x-w[0], SLAVE.y-w[1], w[2]]`。

## 三·五、定格取证：播放与静态帧共用一个 `carrySetAt(t)`
- 把"给定时刻 t(ms) → 关节/盘心/盘底/阶段"抽成纯函数 `carrySetAt(t)`，rAF 播放器和静态定格都调它，
  口径天然一致，不会出现"截图和动画对不上"。
- 页面加一个 `?carry=<秒>` 参数：算完 plan 后 `carrySetAt(秒*1000); drawVR();` 只画一帧不播放。
  取证/对方向/给用户看都用它（`?carry=1.5` 取件、`4.2` 半路、`7.2` 已放好），比让对方等一轮动画可靠。
- **别用 headless chromium 截这个页面**：页里有常驻 rAF + websocket，`--virtual-time-budget` 永不到空闲，
  `--screenshot` 会挂住（实测 300s 超时、连 profile 锁一起卡）。要图就发 `?carry=` 链接，或让用户自己按 Ctrl+Shift+R 看。
- 被质疑"方向反了"时的核对顺序：① 打印 `CARRY.from` / `CARRY.to` 的 mm 坐标 ② 报一个定格帧的盘心 x
  （如"4.2s 时 x=727，正从 920 往 465 走"）③ 最后才提缓存/对端旧页面。先自证，别急着改代码。

## 四、自检清单（浏览器 console 跑，逐条报数）
1. `carryPlan()` 每点 `err ≤ 4mm`、`clamp=0`，并打印关节序列——相邻点同一关节变化应 < 50°，
   出现 150° 级跳变就是退回了"每点全局搜索"。
2. 播放中每 250ms 采样：`阶段 / 持盘 / tool1 mm / 盘底 mm / 盘心 mm`。盘底曲线应为 `0 → 抬升 → 120±5 → 降到 40`，
   **全程不得 < 0**，搬运段最低值要报出来（实测 110，余量 70）。
3. 播完：`tool1 ≈ 目标(±5mm)`、盘心 = 目标、原工位的盘 `show=false`、终点姿态保留（`CARRY.M` 非空）。
4. 帧耗时：动画中 `drawVR` 单帧 ≤ 6ms（实测 5.7）；超了就是每帧重复解 IK，把解算只放在播前一次。
5. 读像素/量差分前先 `await sleep(250)`，`drawVR()` 返回 ≠ 像素已落盘（不等会得到 `diff=0` 的假阴性）。
6. 朝向：逐帧 `atan2(_t1world().B[1], _t1world().B[0])` 波动必须 0.00°，同时打印 6 个关节的摆动幅度表
   （j4/j6 应接近 0；j1 随工位方位变化几十度属正常，不是 bug）。
7. 清理残留浏览器进程用端口/pid（`ss -ltnp`），别 `pkill -f "chromium.*headless"` ——
   这个模式会匹配到你自己那条命令行，把当前会话一起杀掉（表现为命令被 SIGTERM）。

## 五、第二个搬运需求 = 加一个 job，不复制动画
把搬运参数收进 `CARRY.JOBS = { tray:{...}, box:{...} }`，`carrySetup(job)` 只覆盖
`from/to · span · pickZ · carryZ · placeZ · 盘外形(L/W/H/色)` 六项；插值、`_ikSeed`、夹爪对齐、
`carrySetAt`、定格、自检全部复用。要点：
- **堆叠取件取最上一层**：盘底 = `(层数-1) * H`（8 层 40mm ⇒ 280，tool1 = 280+162 = **436**）；
  夹持跨度自动切到方盘 W（230），层数**在夹住那一帧**才 `nLayer--`（提前减会在下降段看到盘已消失）。
- **落盘位置按实际解出的最后一点画**，不要用名义坐标：`done = plan[placeIdx].w`。
  手臂在远工位可能差几毫米够不满，按名义点画盘就是自骗（实测差 9.5mm）。回复里把这个差值写出来。
- **源工位改成多层堆叠时，取件高度和搬起高度要在 `carrySetup` 里按层数现算**，不要写死：
  `PICK_Z=(nLayer-1)*H*1000`（取最上一盘的盘底）、`CARRY_Z=max(作业给的carryZ, PICK_Z+115)`
  （越过整摞顶面再抬 115mm，否则从 6 层顶端往低处走会先下扎再平移）。
  实测 6 层 25mm 托盘：盘底 125、tool1 287、搬运盘底 240、落 位置4 盘沿 25，误差 7.7mm、clamp 0。
- **多层堆叠不要在动画开始时整摞 `show=false`**（旧做法是单只盘，隐藏即可）。多层要：夹住那一帧 `nLayer--`，
  `nLayer<=0` 才隐藏整摞。判据：播前 6、播后 5，画面上那一摞少一层而不是凭空消失。
- 层数在数据里改了**不等于画面上画出来了**：验证用 monkey-patch 数绘制次数
  ```js
  const orig=drawTrayPan; let zs=[];
  window.drawTrayPan=function(g,pr,T,zoff){ if(T===TPAN5) zs.push(zoff*1000); return orig.apply(this,arguments); };
  drawVR(); window.drawTrayPan=orig;   // zs 应为 [0,25,50,75,100,125]，长度=层数
  ```
  只报"nLayer=6"是做数据自证，用户看的是画面。

### 多分支规划（单分支必然有作业解不出来）
首点只取“代价最优”的那一条解 ⇒ 整条链可能落在远处够不到的分支上（实测落点差 74mm、被迫收点）。
做法：首点全局网格里按**关节差 > 25°** 挑 **8** 个候选（5 个不够），每候选链完全程，打分
`score = maxClamp*10 + maxErr + 关节总行程*2`（先不许缺距离，再要误差小、别绕远），取最优链。
实测：5 个候选时方盘作业仍差 21mm；加到 8 个后两条搬运（托盘 3→4、方盘 1→2）落点都 **0mm**，
规划耗时 0.68~0.85s（只在点击时算一次，可接受）。
- **别用“放松手腕自转罚”换精度**：把 j4/j6 罚从 400 降到 60，落点确实能压到 1mm，但 j6 全程甩 79° ——
  卡爪跟着自转 79°，物理上就和盘边斜交、夹不住。宁可多试分支，也不要松这条罚。
- **`CARRY.j4/j6` 参考值在 `carryPlan()` 开头清空**：它是逐候选/逐作业写下标的，不清就会拿上一个作业的参考值去罚。

## 六、回复口径
- 先一句人话结论（“搬完了，落在位置4”），再上是**高度推导表**（取件/搬运/放置三档 + 余量），
  再上**实测数**（规划误差、落点偏差、每帧关节步、朝向波动），最后才是提交号/对端同步。
- 落点差了几毫米、缺距离多少，如实报数并说明是“这条分支的手臂极限”，不要用“已到位”盖过去。
- 用户改口工位（“应该是从3到4”）时不要辩解，直接改 `from/to/placeZ` 三个数并重新报实测表。

## 六·五、提交
- 多行中文 commit message 里出现 `"` 时**别内联 `-m "..."`**：引号在 shell 层就被吃掉，git 把后半行当路径，
  报 `error: pathspec '...' did not match any file(s)`，文件其实没提交上（还以为提交了，接着去同步对端）。
  正确做法：`write_file` 写 `/tmp/msg.txt`，再 `git commit -F /tmp/msg.txt`；提交后 `git log --oneline -1` 回读确认。
