# ar3d 场景显示：挡住视线的东西 / 规格常量对了但画错

适用：老倪说「场景里有两个黑条挡我视线」「这个盘的尺寸跟实际不一致」「你得按方盘的尺寸画」。

## 1. 画布上的「黑条」= 自绘的文字牌，不是 DOM

`trayTableDims()` 里用 `fillRect` + `rgba(0,0,0,.96)` 画了两块 **42px 高**的黑底文字牌：

| 牌 | 内容 | 位置 |
|---|---|---|
| 桌子尺寸牌 | `桌子 长 … × 宽 … × 高 … mm` + `桌面 z=0 · 与箱体顶板/两臂安装面平齐` | 桌子四角取 x 最大点 +24 |
| 左右臂状态牌 | `🦾 右臂: 显示` / `🤖 左臂: 显示` | `(8, H-58)` |

- **怎么找**：这些字在 `document.body` 里查不到（`querySelectorAll` / `innerHTML` 都是 0），因为它们在 canvas 里。
  搜 `grep -n "fillStyle *= *'rgba(0,0,0" tools/web/tcp-ar.html`，按 `fillRect(..., 42)` 高度对号。
  不要用 DOM 扫描去「删元素」，会白跑一轮。
- **删除口径**：删掉这两块，**尺寸线（`dimLine` 的长/宽/高）保留** —— 它贴着模型轮廓走，不挡视线。
  状态牌那类纯调试信息删掉即可，臂显隐看顶部按钮的 on/off。
- 删完必须回报「JS 零错误 + canvas 数量不变」：`browser_console` 读 `document.querySelectorAll('canvas').length`
  与 js_errors；删 `const lines/bw/bh` 时留意后面还有没有引用（这类块常被后面几行复用变量）。

## 2. 规格常量对了 ≠ 画出来对：查隐藏的基准偏移

盘的定义 `L:0.315, W:0.230, H:0.040`、`tpanRange` 投影 **230×315mm** 全对，但屏幕上那个盘只有 **32mm 厚** —— 因为
`drawTrayPan` 把盘底写死在 `zb=0.008`（桌面板厚），盘顶在 `H=0.040` ⇒ 只画了 8mm→40mm。

⇒ **验收要量「投影出来的范围」，不要只读常量**：
```js
var R=tpanRange(TPAN2); [(R.x1-R.x0)*1000, (R.y1-R.y0)*1000]   // 期望 [230, 315]
```
再加一条：`grep -n 'TPAN[A-Z0-9]*\.\(L\|W\|H\|cx\|cy\)\s*='` 应**零命中**（证明没有按钮/动画在运行时改尺寸）。
用户说「尺寸不一致」时先跑这两条，能把「常量错」和「渲染错」分开。

## 3. 托盘的真实外观（按手臂相机实拍校准）

旧的三个方盘是棕色 `fill:#8a5a2b / inner:#4a2f16 / edge:#e0b070`，实拍是 **哑光黑腔 + 白/浅灰翻边**
⇒ 改成 `#1c1c1e / #0b0b0d / #d9d9d9`。改颜色要主动交底（用户可能靠颜色区分盘），并给出回退路径。

## 4. 方盘 vs 托盘的规格（别混）

- **4# 方盘 315×230×40**，盘内 16 个光模块（**2 排 × 8 个**，8×22.58=180.6 ≤ 内腔 220、2×149.7=299.4 ≤ 305）
- **545×380×25 托盘**，盘内 30 个（**3 排 × 10 个**）
- 用画面比例反算盘尺寸时，标尺物体与盘不在同一平面 ⇒ 会算错层级（实测 0.573 mm/px 得 481mm 误判成大托盘），
  分层标定与坑见 `camera-frame-forensics` 的「从画面反推实际尺寸」。

## 5. 节拍面板显示错阶段，不在这里改

`mtNow()` 按 `PLANT.simT % cycle_s` 空转导致「真机在插入、面板显示拔出」—— 定式（按真机游标分档）见
`zmax-real-traj-215-autorun` 的「节拍/MT 面板必须按真机游标判阶段」。
