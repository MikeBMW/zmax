# 画布/页面上的文字遮挡（“黑条挡视线”）

## 症状与真因
用户指着屏幕说「那个黑条是什么？删掉，挡我视线」时，问题几乎都是**自己画进 canvas 的文本标签**：
轨迹/HUD 标签是先用 `fillRect` 画深色底、再 `fillText`（底框宽 = `measureText + 12`，底色 `rgba(0,0,0,.78)`）。
文案一长（实测 70+ 汉字：轨迹名 + 点数 + 点位 + 备注整段拼进 label），底框就成了 **900~1000px 的横带**，
在 980px 宽的画布上就是一条横贯画面的黑条，看上去像聊胜于无的“遮罩”。

## 定式（两边同时做）
1. **服务端只给短标签**：类型 + 点数 + 行程，≤ 20 字；备注/说明走旁边的文字面板，不进画布。
2. **页面侧硬上限**：`lbl = lbl.length > 30 ? lbl.slice(0,30)+'…' : lbl`，兜住任何来源（含旧缓存）的长文案。
3. 同一页面里所有 `fillText` + 深色底的 HUD（状态行、图例、坐标轴注释）按同一口径扫一遍，不只修报错那一条。

## 判据（不用截图）
在浏览器 console 里量：
```js
const c=document.createElement('canvas').getContext('2d'); c.font='bold 13px monospace';
Math.round(c.measureText('规划轨迹 · '+TRAJ.planLabel).width)   // 与画布宽比
```
实测修前 >900px / 画布 980px；修后 **227px**。另外顺手确认画布上仍看得到青色航路（数一下青像素数量），
别把“清掉黑条”做成“清掉了线”。

## 相关
- 页面无缓存时要带 `Cache-Control: no-store`，否则现场刷新看不到修改（会把“没改”当成“改了没用”）。
- 真机/仿真两条臂重合时也会报“看不见真机”：在画布第二行加状态 HUD（`● 真机臂 在画/○ 已隐藏/○ 无真值`），
  并告诉用户“想只留真机就把仿真臂关掉”——让用户自己看得见状态，而不是靠他猜按钮。
