# AR3D 右臂「位置突变」— 同一时刻只能有一个写者在写 PREV.q

症状: 页面上右臂单帧跳几度到 200°+ («位置突变»), 但真机 / 历史轨迹本身没问题。

## 根因只有四类 (都实测过)

1. **IK 解到另一个支**: 本地全流程期间 `plantAt()` 仍在每拍解 IK 并直接写 `PREV.q`,
   翻腕支可达 4.06 rad ⇒ 一帧跳过去。
2. **异步 fetch 抢写**: `mirrorTick()` 的 `fetch('/api/tcp')` 发出时全流程还没开始, 回来时已开始 ⇒
   又把真机位姿盖回去 (实测 3.65 rad)。
3. **循环边界跳变**: 轨迹按 `simT % T` 采样 ⇒ 末点直接跳回首点 (不是平滑回位)。
4. **停止时硬切**: 全流程停下立即改由镜像写真机位姿 ⇒ 0.97 rad 瞬跳。

## 定式 (改 ar3d 页面时照抄)

- **单写者**: 播放/回放期间把 `PREV.src` 锁成 `traj215`(或当前播放源); `plantAt()` 解 IK 后写 `PREV.q` 前
  必须 `if (PLANT.local || PREV.src==='traj215') return;`; `mirrorTick().then()` 里也要**复查**同一条件
  (发请求时的状态已过期, 不复查等于没加)。
- **开始时平滑接入**: 起点不用"轨迹第一帧", 取**与当前关节角最近的帧**作起点, 再 600ms 线性过渡。
- **停止时也过渡**: 切回真机位姿同样 600ms 线性过渡, 不要直接赋值。
- **循环边界**: `simT % T` 处做连续性保护(就近帧 + 过渡), 不许从末点跳首点。
- **预热**: `ensureTrajJoints()` 开机即加载真轨迹关节角, 避免第一拍先用 IK 解顶一帧。

## 取证法 (别只凭眼看)

```js
// 截获 setter, 记录每拍最大关节差 + 写入调用栈
let _q = PREV.q.slice();
Object.defineProperty(PREV,'q',{configurable:true,get(){return _q;},
  set(v){ const d = Math.max(...v.map((x,i)=>Math.abs(x-_q[i])));
          if (d > 0.15) window.__J.push([d, new Error().stack]);
          _q = v; }});
```

- 判据: 运行中**单帧关节变化 ≤0.15 rad**(≈8.6°), 停下回切允许 ≤0.25 rad; `>0.5 rad` 的写入必须 0 次。
- 修复前后实测: 4.06 rad → 0.120 rad; 停止切回 0.97 → 0.227 rad; 停下后 `PREV.q` 与
  `/api/tcp joints` **逐位相同**才算真的对齐。
- 栈里出现 `plantAt(...) → plantStep(...)` = 第①类; 行号来自 `mirrorTick` = 第②类。

## 顺带: 页面默认态

用户要求「默认不显示/不自动跑」的东西 (Mujoco 同视角、工程配置点位、实验桌、通道/引导线) 一律默认关,
并**把旧数据也清掉**(如 `fences.json` 里 `COR-*` 设 `enabled=false`), 否则「默认关」只关开关、旧线照样显示。
