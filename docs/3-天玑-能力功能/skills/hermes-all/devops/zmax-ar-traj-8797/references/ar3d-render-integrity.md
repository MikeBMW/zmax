# ar3d 渲染完整性 · tool1/光模块语义

## drawVR 是长链: 中途 return 或抛错 ⇒ 整屏丢元素, 浏览器**零报错**

改这个函数里任何帧对象 / 局部变量之前，先把**下游用到的全部字段**列清：

- `TCP.frames.tool1` 的真实结构是 **`{origin, x, y, z}` —— 没有 `R`**。需要旋转矩阵时用三轴拼成**列**矩阵：
  `R = [[x0,y0,z0],[x1,y1,z1],[x2,y2,z2]]`（`_cols(R)` 取三列=三轴，`R[i][2]` 才是长度轴）。
- 只给 `{t: ...}` ⟹ `_cols(undefined)` 抛异常 ⟹ **后面的桌子/盘/模块/围栏/坐标轴全部不画**。
  现场症状就是“怎么丢了那么多元素”，控制台一条错都没有 —— 因为异常被外层吞了或发生在首帧。
- **禁止在 drawVR 中间 `return`**。想“没位姿就不画”要么安全占位（原点+单位阵，且标 `_none`），要么把该段包进 `if`，绝不能退出函数。
- 新增局部变量前 `grep` 同名：`_rpC` 这类短名在同一个 `if` 块里常已被占用（例如三轴颜色数组），重复 `var` 会让后面的颜色取到数字。
- 改完的验收（console 一次问完）：`TPAN2.show`、`TAB`、`MOD30.show`、`MOD16.show`、`VR.mod`、`document.querySelectorAll('canvas').length` 全在才算链条没断。

## tool1 原点 = 光模块**头部中心**，不是尾部、不是体心

- `tool1.origin` = 模块**头**中心；本体从头部朝法兰方向长出长度 L。
- `drawModuleAt(O, AX)` / `drawModuleBox`：`O` 是头部，内部自己算 `C = O + AX[2]*(L/2)`。
- `drawFlatModule(c)`：`c` 是**体心**。传 `origin + [L/2,0,0]` 就等于把“头部”挪到 L/2 处 ⟹ 整体退半个身长 ⟹ 用户会说**“你画成尾部中心”**。
- 同一个模块被两处画（真机 `TCP.frames.tool1` + 幽灵臂 `PREV.M['tool1']`）⟹ 两个长方体错开，看起来“前面还多一个绿色模块”。要么都锚同一位姿，要么只画一个。
- 锚同一位姿时，本体朝向的 `sgn`（`(tool0.origin − tool1.origin)·长度轴` 的符号）**两边必须同号**；否则头对头、身子朝反向，视觉上是一个双倍长的模块。
- `sgn` 判不出来时不要给 `±L/2` 瞎猜：先读 `TCP.frames.tool0` 有没有，没有就退回 `+AX[2]` 并在注释里写明退化条件。

## 硬编码的 z 必须与孔位真值核对

`INSIM.inserted` 那个“已插入”的模块曾写死 `z=0.278`，而 2# 孔真值 `z=187.6` ⟹ 高 90mm，画面上飘在孔上方。
孔位真值在 `zmax_data/runtime/traj/sim_insert.json`（下口 `761.3/229.8/187.6`、插到位 `811.6/…/187.6`、孔轴 +x，模块中心取两者中值）。
凡是场景里出现 `0.xxx` 这种硬编码米制坐标，都拿真值文件对一遍再留。

## 节拍/阶段显示必须跟真机游标, 不能按时间空转

- 面板原来用 `PLANT.simT % cycle_s` 自己循环 ⟹ 真机还在插入，面板已经跳到下一个元任务（“拔出”）。
- 修法：**有真机游标时按游标判阶段**，`simT` 只作无游标时的兜底。阶段边界要和段表 + 几何同时自洽。
- 段名必须与实跑几何对得上：游标 95 的 TCP `x=776` 落在插入区间（761→811）⟹ 那一段是**插入**，把 91–113 叫“拔出模块”就是错的。判断依据取 **该点 TCP 相对孔位的 x**，不靠猜动作名称。

## 画面文字牌: 用户嫌挡视线就整块删, 但保留贴模型的尺寸线

“两个黑条挡视线”= `trayTableDims()` 里那两块 **42px 黑底文字牌**（桌子尺寸牌 + 左右臂状态牌）。删它们；
贴着模型走的尺寸线（dimLine + 小标签）保留 —— 那是标注不是遮挡。尺寸数值本来就已在右侧面板/按钮里。

## 静态页改动一律 Ctrl+F5

`tcp-ar.html` 是静态页，改完不加 `?v=` 或硬刷新看到的还是旧渲染，别把缓存当成“改了没生效”。
