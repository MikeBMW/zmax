# /ar3d 画面可读性：黑条从哪来、真机臂为什么"看不见"、状态怎么自证

## 黑色横条 = 画布里文本标签的底色矩形，不是 DOM 元素

- 3D 视图的轨迹标签是 `fillStyle='rgba(0,0,0,.78)'` + `fillRect(lx-4, ly-15, tw+12, 21)` 画的底框，`tw` 随文案线性增长。
- 一段 70 字的标签（把备注/说明也拼进去）⇒ 底框宽度逼近画布宽（980px）⇒ 用户看到的就是"一条黑带挡住视线"。
- 排查口径：**先在浏览器里量 `measureText`**，别去 DOM 找 —— 黑条不是 DOM，`getElementById` 可能返回 null（元素根本不存在）。
- 双向修：①服务端 label 只放短字段（点数/行程），**别把 note/说明拼进 label**；②页面绘制前硬截断（≤30 字，超出加 …）。实测底框从近千 px 降到 227px。

## 「怎么没有真机」= 仿真臂盖在真机臂上

- `/ar3d` 同时画两条臂：真机臂（读 `/api/tcp` 真值，静止）与仿真臂（跟随真机）。位姿**完全重合** ⇒ 视觉上永远只有一条。
- 先证数据通，再谈显示：`GET /api/tcp` 看 `age_s<2`、`stale=false`、`joints` 6 个都在；`tool01_const.dist_mm` 就是工具长（≈259.8mm）。
- 让用户自己看见真机：①`🦾 右臂_真机` / `🦾 右臂_仿真` 是两个独立开关，关掉仿真臂剩下的就是真机臂；②画布左上固定写状态行（绿=真机在画+TCP+帧龄 / 橙=被按钮隐藏+指路 / 灰=真值过期+指路），别让用户猜。
- 状态行要由页面自己判（`VR.real` + `TCP.stale` + `TCP.age_s`），不要依赖会话里记忆的开关值 —— 用户的浏览器可能点过。

## 通用教训

- 画面上"多出来/挡住了"的东西，先判它在**画布内**还是 DOM 内；两者排查与修法完全不同，判错方向会一直在错误的地方找元素。
- 播放类按钮（仿真回放/跟随）结束后必须回到"跟随真机"并把真机位姿重新灌回去，否则画面停在仿真末帧，看起来像"真机没了"。
