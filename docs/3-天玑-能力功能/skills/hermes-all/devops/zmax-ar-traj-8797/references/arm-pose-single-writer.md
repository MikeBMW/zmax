# 仿真臂“位置突变”的三个真因与单一写者原则

ar3d 页的右臂在回放/全流程时**一帧跳几十度~几弧度**（用户口径:"右臂位置突变, 不对"）。
不是渲染问题, 是**同一时刻有多个来源在写同一个位姿状态**。

## 真因清单（按实际抓到栈的顺序）

1. **IK 解到另一个分支**: `plantAt()` 每拍解 IK 后直接写 `PREV.q`, 关节解翻腕 ⇒ 与真轨迹差 **4.06 rad**,
   一帧跳过去。拦截赋值抓到的栈是 `plantAt → plantStep`。
2. **异步 fetch 迟到**: 镜像真机位姿的 `fetch(...).then()` 回来了, 而全流程已经启动 ⇒ 又把真机位姿盖进去(**3.65 rad**)。
   典型竞态: 判"当前模式"只写在发起处, 没写在回调里。
3. **模式切回硬切**: 停回放切回真机位姿时直接赋值(**0.97 rad** 硬跳)。
4. **轨迹循环边界**: `simT % T` 让 215 点末帧直接跳回首帧。

## 修法（四条, 缺一条就还会跳）

- **单一写者**: 一次只允许一个来源写 `PREV.q`, 并记来源(`PREV.src = 'traj215' | 'mirror'`);
  轨迹模式下 IK 解、镜像都不许覆盖。新加任何位姿来源, 必须先过这个 owner。
- **异步回调里复查模式**: `.then()` 里再判一次 `PLANT.local`, 不是只在发起处判一次。
- **切换必过渡, 不许硬切**: 启动时按"与当前关节角最近的真轨迹帧"对齐 + 600ms 线性过渡; 停时切回真机位姿也 600ms 过渡。
- **回绕做连续性保护**: 末帧→首帧不能瞬移; 轨迹数据开机预热(`ensureTrajJoints()`), 别让首帧先用 IK 解顶一下。

## 取证方法（可复用）

用 setter 钩住位姿对象, 记录每次写入的幅度并抓栈, 只报超阈值的:

```js
let _q = PREV.q.slice();
Object.defineProperty(PREV, 'q', {configurable:true, get(){return _q;},
  set(v){ const d = Math.max(...v.map((x,i)=>Math.abs(x-_q[i])));
           if (d > 0.5) window.__BIGW.push({d:+d.toFixed(3), stack:new Error().stack.split('\n').slice(1,3)});
           _q = v; }});
```

实测判据（点全流程跑 3s 再停）:

```
跑的时候 单帧最大关节变化   0.120 rad (6.9°)     原来 4.06 rad
停的时候 回切最大变化       0.227 rad (13°)      原来 0.97 rad 硬跳
>0.5 rad 的写入             0 次
停后姿态                   与 /api/tcp joints 逐位相同
```

## 同页的两条相邻规则

- **引导/通道默认关**: 用户否掉过一次“自动显示约束”, 从此默认 `enabled=false`, 只能手动点。
  即使给了真值引导(`frames[i+1..i+10]` 查表, 不是模型外推), 也要先证明 `guide_eq_realtraj=true` 再交付。
- **几何数量从配置读, 代码按 `len()` 自适应**: 工位数/孔数/插口数不许写死(曾写死 4 个孔、
  `{1:[孔1,孔2], 2:[孔3,孔4]}` 两对轮转, 现场实际只有 2 个)。改法: `holes` 读 `config/points/cell_points.json`,
  `pairs = [holes[i:i+2] for i in range(0,len(holes),2)]`, 占用桶按 `len(pairs)` 建;
  页面绘制也要每个孔用自己的 z(曾把高度硬编码 278, 下口被画到上口位置)。
