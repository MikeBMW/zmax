# 仿真双臂的姿态动作（关节空间直接摆姿势，不走 IK）

用于「点一个按钮，两条臂摆成某个姿态」这类需求（伸展/收缩/指方向/待机位）。
只覆盖画面里的关节角，真机不动、不下发指令、不需要 8793 授权。

## 链条与关节（XMS5-R800，`/api/urdf` 实测）
```
base →j1(z,0.328) link1 →j2(y) link2 →j3(-y, xyz 0.05,0,0.4) link3
     →j4(z, xyz -0.05,0,0.4) link4 →j5(-y, xyz 0,0.136,0) link5
     →j6(z, xyz 0,0,0.103) link6 →tool0 →tool1(xyz -0.016,0.018,0.259)
```
- `urdfFK(q)`（6 个弧度，按 `URDF.joints` 里 revolute 的顺序）→ `{ 链名: {R,t} }`；末端看 `M['tool1'].t`。
- **URDF 里没有 limit 字段** ⇒ 求解器必须自己夹关节范围，否则会解出 `j2=-280°` 这种卷绕角，画面看着直但真机不可能。
- 左臂同一套 URDF：`LARM.off=[0,0.5,0]`（+500mm Y）；`LARM.q` 非空时用 `urdfFK(LARM.q)` 单独算，否则照抄右臂链。

## 驱动方式：覆盖每帧的链矩阵
`drawVR()` 里 `LINKM=urdfFK(TCP.joints)` 那行之后插入：
```js
if(GEST && GEST.q){
  LINKM=urdfFK(GEST.q);
  if(GEST.qL) LARMFK=urdfFK(GEST.qL);
  GESTF={tool1:_frameOf(LINKM,'tool1'), tool0:_frameOf(LINKM,'tool0')};
} else if(GESTF) GESTF=null;
```
- `_frameOf(M,name)`：`origin=M[name].t`，x/y/z 取 `M[name].R` 的**列**；喂给 `drawModuleBox(g,pr,FR)`（加一个可选 frame 参数，默认仍用 `TCP.frames`），末端光模块才会跟着动画走。
- 姿态动作期间不画 `TCP.frames` 的 `tool0/tool1` 三轴 —— 那是真值，会停在旧位姿。
- 动画：`requestAnimationFrame` + smoothstep（`t<0.5?2t²:1-(-2t+2)²/2`），每帧 `drawVR()`；1.2–1.5s。

## 「伸到最大距离」怎么解（stretchQ(dir)）
不做 IK，直接在关节空间搜：
```
score(q) = along - 4.0*perp - 2.0*|z - ZT|
  along = 水平面 p·dir        （dir 单位向量、z=0）
  perp  = |水平分量 - along*dir|    ← 方位角准不准靠它，权重要大
  ZT    = 0.40m                    ← 期望末端离桌面高度
```
- 粗搜 `j1:-90..90/10°`、`j2:-150..20/10°`、`j3:-120..120/10°`、`j5:-90..90/15°`（`j4=j6=0`，只影响朝向不影响位置），再在最优解附近 `±8°/步长2°` 细化。
- 硬限位（细化时 `continue`）：`|j1|≤170°`、`j2∈[-160,30]`、`|j3|,|j5|≤150°`。
- **只优化"最远"会得到贴桌面的姿势**（实测 z≈5mm、伸距 1093mm，像要刮台面）⇒ 必须加高度项。
- 双臂各解一套：右 `dir=[√2/2,-√2/2,0]`、左 `dir=[√2/2,+√2/2,0]`；别拿一条 q 镜像，链里 5cm/13.6cm 横向偏置会让镜像后方位角偏。
- 验收基线（45° 伸展）：右末端 `(634,-610,399)mm` 方位角 **-44°**、水平伸距 **879mm**；左 `(610,634,399)mm` **+46°/879mm**；关节 `[-54,20,-86,0,-25,0]°` / `[36,20,-86,0,-25,0]°`。±1–2° 方位角残差来自横向偏置，属正常。

## 「够到某个点」（solveReachT：桌角、点位、任意世界坐标）

要"末端（模块头中心）落在某个具体点、并且模块大致平躺"时，仍不做 IK，用**带容差的位姿搜索**：

```
cost(q) = dp > CAP ? 500 + (dp-CAP)*20 + orient*0.05      // 位置没到位就先压位置
                   : orient + dp*0.5                       // 位置够了就尽量摆平
  dp     = |tool1.t - T| * 1000   (mm)          CAP = 25mm
  orient = 20*|Z 轴竖直分量| + 20*(1 - X 轴竖直分量)   // 长度方向水平 + 厚度法向朝上
```
- **纯加权和压不住姿态**：`dp*1 + 40*orient` 这种写法在可达边界上会被位置项赢走，解出来的模块斜 28°；改成上面的 cap（先保位置、再保姿态，本质是字典序）后同一目标倾斜降到 9.8°。
- 粗搜 `j1/j2/j3` 20°、`j5` 30°（`j4=j6=0` 先不解），再对**全部 6 个关节**做坐标下降 6°→3°→1.5°→0.7°，每步都过同一套硬限位。
- 左右臂**各解一次**：左臂把目标先减 `LARM.off`（+500mm Y）换成自己基座系，再解。
  ⚠️ 镜像法不成立：`q_left=[-j1,j2,j3,-j4,j5,-j6]` 实测末端偏 233mm，链里的横向偏置不是关于 XZ 面对称的。
- 目标点直接由几何算，不写死：桌角 = `[TAB.x1, TAB.cy±TAB.w/2, 0]`；要让模块搭在桌面上，z 取 `+0.008`（一半厚度），否则模型会插进桌面。

验收基线（桌前侧两角，桌 1600×600，桌面 z=0）：
- 右臂末端 `(959,-557,3)mm` vs 角 `(950,-550,8)` ⇒ 偏差 **12mm**，模块倾斜 **9.8°**；
- 左臂末端 `(961,1054,4)mm` vs 角 `(950,1050,8)` ⇒ 偏差 **12mm**，倾斜 **5.9°**；
- 关节 `[156,-100,10,6,0,179]°` / `[-144,-100,10,5,0,172]°`。

可达性结论（用户问"手臂能不能覆盖桌子的所有区域"时直接给这组数）：
- 前侧两角在**可达边界**上（基座到角 ≈1.10m，末端最大半径 1.09m）⇒ 腕部只能拉直、模块斜 ≤10° 贴着角；想让它平躺必须往里退 ~30cm。
- 后侧两角宽裕：右臂到左后角 `(350,1050)` 6.8mm、右后角 6.3mm。
- 交叉够不着：右臂去左前角差 **293mm** ⇒ 左前角归左臂、右前角归右臂。

## 踩过的坑
- **`if(typeof X!=='undefined'){ X=... }` 永远不成立**：没声明过 `typeof` 就是 `'undefined'`，赋值块一次不跑，末端跟随静默失效。先 `var GESTF=null;` 再判。
- **动画结束忘 `GEST.running=false`** ⇒ 再点一次被 `if(running) return` 挡掉，收不回来。
- 二次点击 = 收回：清 `GEST.q/qL` + `LARMFK=null` + 按钮 `.on` 去掉；并给 `#vrRail` 挂**捕获阶段** click，点到任何其它按钮就自动复位，否则伸展姿态会顶掉回放/单步的关节角。
- 这类按钮只在 `/tray` 出现：`if(!__TRAY) $('bStretch').style.display='none'`；`/ar3d` 基线仍是 161 个按钮。
