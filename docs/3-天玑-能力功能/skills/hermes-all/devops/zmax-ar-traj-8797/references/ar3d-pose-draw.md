# /ar3d 上画 3D 引导位姿 / 蔽黑底文字条 / 摆仿真左臂

适用: 用户看着 8797 `/ar3d` 的 3D 视图给几何反馈(「偏上」「应该跟光模块重合」「怎么躺下了」)时,
改的都是**画出来的东西 + 位姿数据源**, 不是真机。判据: 画面上的框/臂是否落在用户指的那块实物上。

## 1. 引导位姿原点
- 原点 = **模块体中心** (= TCP 要去的点), 框以原点**中心对称展开** `sx∈[-0.5,0.5]`。
  坑: 原点取"金手指端"、框单向拉出 72mm ⇒ 画面上比模块前移半个模块长, 用户就说"偏上/不重合", 而数据没错。
- 金手指端留 `head_mm` 备查, 不当位姿原点。
- 预抓点 (`pre_pos_mm`, 上方 hover≈40mm) **默认不画/只画细虚线**; 画成圆环会被当成"位姿偏上"。开关 `T.show_pre`。
- 左右两条同屏: 色差 + label 带臂别 (右 `#ffd23f` / 左 `#4da3ff`); `fitBothTP` 只动相机(两目标中点)不动数据。

## 2. 槽位编号两套
- `tray_slots_14.json` 槽1..7 = 示教编号 (x≈649 上排) = AR 围栏/place_cells 的槽8..14; 围栏槽1..7 在 x≈490 下排, x 差 ~158mm。
- 用户说"槽N"以**画面上那块模块**为准; 引导框错一排, 屏幕上就是"偏上"(相机沿 -X 看时 +X 投影向上)。
- 真机真抓的行以 `cell_points.json` 示教点为准; 拿错一套会在 z≈130 顶住。

## 3. 黑底文字条
- 底板 = `fillStyle='rgba(0,0,0,.62~.85)'` 的矮条 (`h≤26px`), 一处一处删不彻底(换个图层又冒):
  在 2D canvas 上包 `fillRect`, 命中"深黑半透明 + 高≤26 + 宽<900"丢弃, 文字照画; `window.VR_TEXT_BAR=1` 反开。
- 要 patch **所有 canvas** (`vr`/`ov`/`loupe`/`vid`), 并在加载后 `setTimeout` 重 patch(晚创建的不会继承)。
- 验证不靠眼睛: 同像素 `getImageData` 前后比 ⇒ 黑条不变; 再加红色 `fillRect` 对照 ⇒ 必须变红。

## 4. 摆仿真左臂到引导位姿 (单机只有一条真臂)
- 本页 `ikTool1Pose` (6DOF 位姿 IK) 在 URDF 上**不可靠**: 已知可达的右盘目标也解出 300mm+ 偏差。可信的只有 `ikTool1` 位置解(实测 0.02mm)。
- 转左臂基座系: `tgt = P.pos_m - (LARM.off + LARM.d)`; 基座是**纯平移** ⇒ 姿态不用换。
- 种子用**真机示教抓取臂形** (`zmax_data/rokae_sdk/real_traj_absj.json` 抓取帧 q), 只做小幅修正 (`max|Δq|≤0.5rad`)。
  反例: 按"工具轴朝下 + 贴模块长轴"打分会挑出大关节角解, 整条臂躺倒。
- 自检: FK `tool1.t` 与目标差 <1mm; `max|q-q_seed|` 小(臂形还像人)。
