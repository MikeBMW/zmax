# 让仿真右臂“按真实轨迹走一遍”

页面里三个按钮, 数据同源(`poses.jsonl` 的 6 轴关节角真值), 只动仿真:

| 按钮 | 行为 | 用途 |
|---|---|---|
| `bRTraj` 📍 右臂跑真实轨迹 | 按时间连续回放(1× 真实时间 43s, 时间轴线性插值) | 看整条轨迹“怎么跑” |
| `bSyncStep` ⏭ 同步操作 + `iSyncN` 输入点数 | **一点一点走**: 每点 smoothstep 420ms 到位 → dwell 300ms 停住 → 下一点 | 逐点校位/对数, “输入3点就走3点” |
| `bPlant` 🏭 全流程 UPH | 本地时钟跑节拍, **右臂关节角直接取内嵌真轨迹帧** | 看连续生产时的真实姿态 |

## 关节角真值回放（三个按钮共用基础）

位置 IK 只匹配 xyz，姿态由求解器自己挑 ⇒ 真机那 952° 累计转动、J4 −8°→247° 的翻面全会丢。
`tools/real_traj_joints.py` 从录制导出回放帧（双闸抽稀 8mm/3°、只留运动段、静止压缩），215 帧。

## 仿真臂的姿态源头: 只有两个合法来源

1. **跟随真机 (`MIRROR`)**: 10Hz 读 `/api/tcp` 的 `joints`(6 轴弧度) → `PREV.q` → `mjPushQ`/`mjPushQForce`。
   帧龄 >1.5s 直接丢弃（宁停帧不骗人）。`MIRROR.on` 期间 `plantStep` **禁止写 `PREV`** —— 否则 60Hz 的
   `ar_cmd` 合成段表(14 孔计划)会把真机位姿盖掉, 用户看到的就是“仿真臂不按真实轨迹跑”。
2. **真轨迹帧 (`traj215`)**: 本地全流程分支里 `PREV.q` 直接取内嵌 `rtrajData` 的帧，按 `simT % T` 线性插值，
   不再用 `plantAt()` 的 IK 近似线。`plantAt()` 仍然要跑（节拍/计数/料盘状态），只是**姿态由轨迹帧覆盖**。
   停止后自动切回跟随真机。

判据（缺一不可）:
- `PREV.src === 'traj215'`，且 `PREV.q` 与 `simT` 处轨迹帧插值 **逐位相同**（实测 maxErr = 0）；
- `trajT` 随时间推进（3s 采样 8.6→10.7→12.8s），末端目标沿录制路径移动；
- 点停后 `PREV.q` 与 `/api/tcp` 的 `joints` 逐位相同（回到跟随真机）。

## 关键坑

1. **8797 只白名单服务 `tcp-ar.html` 本身**，`/xxx.json` 全 404 ⇒ 数据必须**内嵌**页面：
   `<script id="rtrajData" type="application/json">…</script>`，由 `real_traj_joints.py --embed` 写入。
2. **内嵌块在页面末尾** ⇒ 加载时读不到（DOM 还没到）⇒ 必须**惰性读**（`ensureTrajJoints()` 在点击时才取），
   不能加载时读一次缓存 null。函数声明会提升，`plantStep` 里提前调用也安全。
3. **回放期必须 ~30Hz `mjPushQForce()` 抢 8802 时间片**，否则多开 `/ar3d` 页会两个写者互斗、臂在两姿态间跳。
4. 各回放模式**互斥**：开同步操作/本地全流程前先 `rtrajStop()`，否则两个 rAF 同时改 `PREV.q`。
5. 点数上限取数据帧数（215），运行时 `inp.max=max` 自动设，用户填 999 也不越界。
6. **“在跑”的唯一判据是 `PLANT.local`**。`PLANT.on` 会被状态空间自动跟随一起置 true，用它判断 ⇒ 点一下按钮变成“停”，
   这是“点了不动”的头号原因。连带三处必须同时改：`plantToggle()` 判 `PLANT.on && PLANT.local`；
   `autoMirrorMaybe()` / `ssFollowStart()` 每 100ms 会把 `local` 打回 false 并把 `PREV` 交还 `ar_cmd` ⇒ 开头加
   `if(PLANT.on && PLANT.local) return;`；`plantStep()` 里 `if(SSMODE.on && !isAR) return` 会永久挡本地时钟 ⇒ 改成
   `if(SSMODE.on && !isAR && !PLANT.local)`。改一处无效，四处是一组。
7. **改完必须 bump 版本戳**（页头 `r95→r96…` 与 `bld`），并用 `?v=rNN` 重载验证：不 bump 会看到旧 JS，
   会误判“改了没生效”。

## 验收口径（必须看到的）

- 页面：`SYNC.i` 逐点递增到 N−1、`ph` 在 move/dwell 间切换、文案报“已到第 k/N 点” → “已走 N 点”。
- 8802 侧：`zmax_data/ss_live/ar_mj_q.json` 的 `R` 与页面末帧关节角（度）一致 ⇒ 仿真真到位，不是只改前端。
- 真机零指令：不写执行开关、不调 8793 授权。

## 单步走点（「走一个点」/「单步 +1 点」）

用户要的是「一个点一个点走，这样你就知道我说的是哪个点」—— 所以**严格取该帧关节角、不插值**：
插值后停在第几个点说不清，按 ID 指认就对不上。

- 🔴 必须 `window.PREV_KEEP=true`。单步时 `RTRAJ.playing=false`，页面「空闲即真值」的自动同步会判空闲，
  把幽灵臂收回去 ⇒ 刚定住的第 N 点几秒后自己跳回真机位姿，单步等于白走。
  连续回放入口（`rtrajPlayJoints`）与 `rtrajStop()` 里要清掉，否则长期占住画面、镜像回不来。
- 连续回放中点单步要先 `rtrajStop()`（否则 rAF 下一拍就把 `fi` 抢回去），并 `mirrorStop()` 让镜像让位。
- 读数口径带坐标：`#ID · X.. Y.. Z..`（mm）。只给 ID，用户还得去翻表。
- 快捷键用 `Alt+←/→`：裸方向键在页面上是围栏 1mm 微调。
- 单步落在夹持区间时，末端模块与 `tool1` 坐标系要照常显示（见下节），否则"单步看的那个点"缺一半信息。

## 时间构成甘特的光标

- 取值优先级必须「页面在回放 → `RTRAJ.fi`；跟随真机 → `SYNCUR.cursor`」。真机停在 215/215 时
  `SYNCUR.cursor` 恒等于末点 ⇒ 游标永远 `left:100%`，看起来像"根本没有游标"。
- 位置不能 `cur/215` 线性映射：条宽是**时间占比**，而段与段的「秒/点数」比不同 ⇒
  `Σ(前序段 pct) + 段内完成比例 × 本段 pct`。
- 气泡给的是**实跑口径**（2.028s/点 × 点号）而不是录制时间轴，并带上段名，用户才知道停在哪一段。

## 回放末端的光模块 + tool1 坐标系

- 挂在 `drawVR` 内、跟随 `PREV.M['tool1']`（仿真幽灵臂），**不挂 `TCP.frames`**：回放时真机帧停在轨迹起点，两者早已分离。
- 只在「合爪 → 松爪」区间显示，否则"手是空的却挂着模块"。
- 姿态沿用「长轴平行世界 X」（与料盘/插入仿真同一口径），不跟腕部朝向转。
- 开关归属不得变：`🦾 右臂_仿真` 关掉 ⇒ 模块 + 三轴一起消失；`🧭 坐标系` 关掉 ⇒ 只留模块不留三轴。
- 可见性要**量化达标**：55% alpha + 1.7px 边在整幅三维里只有 5 个绿像素（半透明混色后≈(100,171,78)，纯色阈值根本抓不到）；
  提到 alpha .9 / lw 2.6 + 中心亮点 + 文字标注 → 54 像素；三轴加粗 + 轴端方点 → 22/41/31 变 125/136/53。

## 215 点 ID 表：先证明两份数据是同一次录制

- 页面内嵌轨迹与导出的 ID 表可能来自**不同次录制**（同一套程序跑两遍），逐点差几毫米。
- 对齐判据用**偏移扫描**：offset 0 时平均差最小、±1 点立刻放大一个量级 ⇒ 索引一一对齐、没有错位。
- 交付按 ID 调点位时，必须说明坐标出自哪一次录制（给绝对坐标就要带口径）；纯 ID 指认不受影响。

## 按 ID 改点位：改的是坐标, 必须反解关节角

- 回放是**关节角驱动**（`PREV.q = f.j` → `urdfFK`）。只改 `f.p` 的 x/y/z ⇒ 臂不动、末端被画到别处,
  六轴与末端对不上。改坐标必须同时反解 `f.j`。
- 🔴 位置三自由度反解会让**姿态自己漂**（−8mm 平动就带出 0.15°/0.82° 转角）。用户口径是
  「只是平动, 不要转动」⇒ 用**六自由度约束**: 位置增量 (−8,0,0)mm + 姿态增量严格 = 0。
  做法: URDF 数值雅可比（每轴 ±1e-5 rad 有限差分, 位置 mm + 旋转向量 rad 拼 6×6）+ 阻尼最小二乘,
  迭代到 max|err| < 1e-7; 收敛后复算必须 `dp=(-8.000, 0.000, 0.001)mm`、姿态变化 `0.0000°`。
- 🔴 先查单位再怀疑模型: `real_traj_joints.json` 的 `unit` 明写 `j: rad / p: m`。把 `j` 当角度再
  `radians()` 一次, FK 会差几百 mm（末端跑到 1.2m 高）, 看着像"URDF 不对"。
- FK 与录制 TCP 的对应关系要**先对出来**: `tool1` 与录制 `p` 差 ~2mm, 而 `link6`/`tool0` 差几百 mm。
  反解一律以 `tool1` 为目标。
- 目标是**增量**不是绝对值: FK 相对录制值有 ~1mm 系统偏差, 直接把 FK 拉到 485 会让真实 TCP 变成 486。
  按 Δp=−8mm 解 ⇒ FK 到 483.9、真实 TCP ≈485、显示值写 485, 三者才自洽。
- 落盘方式: **磁盘上的录制真值一字节不动**, 另存覆盖表 `tools/web/traj_adj.json`
  （`{points:{"126":{p_new_mm, j_new_rad, dq_deg, rot_change_deg}}}`）, 服务端热读 `/api/traj_adj`,
  以后加点只改 JSON 刷新页面即可, 不用重启。
- 应用点选在 `ensureTrajJoints()` 解析完帧之后**原地覆盖 `d.frames[i].j/.p`**: 回放/单步/真机执行/读数
  读的是同一个数组 ⇒ 一处生效; 逐条路径打补丁漏一条就是"仿真改了真机没改"。覆盖要**幂等**（写绝对值,
  不累加）, 并给帧打 `_adj` 标记, 单步读数显示「·已修正」。
- 加完必须核 ① 只有目标帧变了（邻点 `_adj=false` 且坐标不动）② 单步实测读数到目标值。
  ID 表(xlsx/csv)此时已与实际不符, 主动问一句要不要同步。

## 改完页面的自验三连

1. 语法：只抽 `type` 非 `application/json` 的 script 块拼起来跑 `node --check` —— 内嵌轨迹 JSON 块会让整页检查假报错。
2. 服务端：`curl` 页面路径，md5 与磁盘逐字节一致（8797 每请求热读，改 HTML 不用重启）。
3. 浏览器插桩：给 `drawTable/drawChassis/drawTopCam/drawUrdf` 之类计数后手动调一次 `drawVR()`，用调用次数证明"画了"，别靠肉眼。

- 🔴 `browser_click` 对**低于视口**的元素点不动且不报错。`elementFromPoint` 返回 `null` 就是"在视口外"，
  不是被遮挡、也不是 ref 过期 —— 别据此去怀疑监听没绑。先 `scrollIntoView({block:'center'})`，
  确认 `elementFromPoint` 命中元素自身再点；或用 `dispatchEvent(new MouseEvent('click'))` 先证逻辑通不通。
