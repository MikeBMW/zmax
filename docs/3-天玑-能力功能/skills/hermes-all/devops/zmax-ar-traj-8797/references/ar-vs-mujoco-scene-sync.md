# AR 页 ↔ 8802 MuJoCo 场景同步 (同一台机器人, 同一台相机)

用户看到的是两幅画面。口径只有一条: **同一个机位 + 同一组关节角**, 少一样就会说"这是两个场景"。

## 1. 机位必须逐字段照搬, 不能"看着差不多就换一套"
- 页面推的 `az/el/dist/tgt/fovy` 全部照用。曾经的"只信方向、目标点钉死 0.52/0.35/0.32、距离 ×0.65"把两幅画面变成两个机位,
  关节角再同步也是两台不同的机器。
- 坐标系差一个符号: AR 页 VR 世界 **z 向下**, MuJoCo **z 向上** ⇒ `tz` 取反, 其余不动。距离只做 0.8–3.0m 限幅。
- 验证手段: 同一个 query 走 `live=1` 与自由机位两条路径, 出图字节数/均值应几乎相同 (实测 259102 vs 259018 B, 均值同为 46.2)。

## 2. 画幅比必须一致 (最容易被忽略的一条)
- 4:3 的帧塞进 1.7:1 的画布, 同一个竖直 fovy 下**横向视场差三成**: 左边的料盘/台面全被压向中间,
  任何参照物都对不上。
- 页面把画布 `clientWidth/clientHeight` 一起推上去 (帧 URL 与相机 POST 都要带), 服务端按尺寸**缓存离屏 renderer**
  (每帧重建代价大, 一个 size 一个实例就够)。
- 🐞 限幅顺序: **先算比例再限幅**。先夹 `w` 会把 1500×882 变成 1280×882 ⇒ 比例 1.45 而不是 1.70。
- 判据: 请求 1.70:1 出 960×564 (1.702), 请求 1.78:1 出 960×540 (1.778)。

## 3. 动作同步 = 关节角直传, 不是两边各自解 IK
- 页面 8Hz 推 `R/L` 六轴 → `POST /armq` → 落 `ar_mj_q.json` → 渲染侧 `_apply_kin()` 直写 `qpos`。
  两套 IK 求同一目标会落不同肘部分支, 永远"看起来不一致"。
- 判据只看数值: 页面 `tool1` 与模型 `R_tcp` 同源比对应为 **0.0mm**。比对前先确认两边取的是**同一个点**
  (拿骨骼末端去比模型 TCP 会得出 276mm 的假差)。
- 推角要 **自动**: 用户不会去拨开关再点"跟随"。检测到指令新鲜就只读镜像 (不启动播放、不下发真机指令),
  人工停过才用 `sessionStorage` 豁免本会话。
- 🔴 自愈: 自动镜像只做一次 (") 是坏的 — 画布循环一停 `ar_cmd` 变陈旧, 页面判不新鲜就退回画**陈旧的 TCP.joints**,
  这时两幅画面差的不是几度而是完全不同的姿态。每次指令新鲜都要重试; 手动"停跟随"才置豁免。

## 4. IK/FK 锚点删不得
- `ik_solve` 找 geom `<side>_tcp`, FK 找 site `<side>_tcp`, 都放在 tool1 原点, geom 归 `group=5` 永不渲染。
- 删掉它们 ⇒ `ik ok False err 找不到 R_tcp` ⇒ `_ar_cmd_ctrl` 每拍返回 None ⇒ **双臂静默停在最后一帧**。
  画面里料盘/工件还在, 很容易误判"渲染坏了"。`/status.json` 暴露 `ac_err`/`ac_tgt` 才能一眼看出驱动断了。

## 5. 夹爪要画在**工具坐标系**, 不是法兰坐标系
- `joint_tool1` 的 Z 轴与法兰轴差 38.7° (URDF 真值) ⇒ 法兰系里建的夹爪夹不到模块, 看上去像"斜着捅"。
- 正确: 指头挂 tool1 系, 夹住模块的**宽度两侧** (14mm 侧), 指内侧间距 = 模块半宽, 执行器本体沿腕轴延长到指根 (否则"执行器顶上悬着两根指头")。
- 判据用几何: `mj_geomDistance` 指↔模块 0.0000 m、执行器↔指 ≤2mm; 再把模块与两指的八角投到画面里, 两侧偏移应**对称** (实测 27.2/27.9 px)。

## 6. 判图不能替代量几何
- 2.0m 全景下 1px≈4.3mm: 56.5×13.4mm 的模块只有 13×3px, 夹持/缝隙根本判不了。要判夹持就换跟物特写:
  `?cam=close` 把 lookat 钉到 `R_tcp`、机位沿模块 x 轴正视 (0.26m 时模块 71×140px)。
- 读图模型会把执行器本体边缘当成手指 (报"右侧差 3–4mm、低了 20px")。凡涉及"夹没夹住/贴没贴", 
  先用模型投影出**期望像素位置**再对, 不要只凭视觉描述下结论。
- 特写机位不要手算 az/el (换算容易反), 让服务端在渲染线程里按 geom 姿态算: 请求带 `track=<geom>` + `face=<geom>`,
  lookat 取 `data.geom_xpos[track]`, 方位取 `face` 的 x 轴。
