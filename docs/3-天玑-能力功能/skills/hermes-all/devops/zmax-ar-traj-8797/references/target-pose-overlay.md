# 3D 引导位姿 (TP) 在 /ar3d 上的画法与验证

适用: 往 /ar3d 画“机器人该抓的那个 3D 引导位姿”，或用户说“位姿画错了 / 偏上 / 跟光模块不重合”时。

## 位姿原点必须落在模块上

- 原点 = 模块**体中心** = 真机 TCP 落点。若原点取“金手指端”(体中心 − L/2·长轴)、框又从原点**单向**拉出 L，
  整块框会比模块靠前半个长度，用户读成“位姿画错了 / 偏上”。
- 表示物体体积的框必须**中心对称展开**(`sx ∈ [-0.5,0.5]`)；单向展开只适合射线类标注(坐标轴箭头)。
- 金手指端仍有视觉定义价值 ⇒ 单独存返回字段 `head_mm`，不复用作位姿原点。

## 预抓点不是位姿

- `pre_pos_mm` 只画一小段虚线 + 端点小圆，且**默认不画**(`T.show_pre`)。
- 把 40mm 高的预抓圈当第二个框画出来，用户会认成“位姿偏上 40mm”—— 先怀疑这个，再怀疑坐标。

## 文字底板一律不画

- 深黑半透明小长条(`rgba(0,0,0,.6~.9)`、高度 ≤26px)是文字底板；要求文字直接压在画面上。
- 只拦“深黑 + 高度 ≤26px + 宽 <900”：全屏底色(`#070a0e`)、彩色标记块不受影响。
- **逐画布打补丁**：页里有 4 块 canvas(`vid`/`ov`/`loupe`/`vr`)，只改主视图的话换个图层又冒出来。
  `document.querySelectorAll('canvas').forEach(cv=>patch(cv.getContext('2d')))`，并在 1.2s / 4s 各补一次(晚创建的画布)。
- 判据用像素打点，不用肉眼：读目标点 `getImageData` → `fillStyle='rgba(0,0,0,.8)'` 画 200×14 → 再读同点，
  **像素不变 = 拦住**；同时画一条 `rgba(255,0,0,.8)` 做对照，必须真的变(证明只拦黑底，不是整条 fillRect 失效)。

## 验证钩子 (console 直接读，不靠截图猜)

- `__TP_SCREEN__`(右) / `__TP_SCREEN___L`(左)：位姿原点投影像素；`__TP_BOX__`：框四角；`__TP_DRAWN_ALL__`：绘制计数。
- 计数别共用一个变量：带后缀与不带后缀会互相覆盖，各自写自己的 key。
- 左右两个目标同时存在时相机要一起取景(`fitBothTP`: 目标取中点、dist≈1.15)，否则一个出画。
- 两薄目标都是“先验”(槽里无实物)时必须带 `valid=false` 与 ⚠ 标记 —— 别让画面把先验画成已观测。

## 用户口径：「画错了」≠「臂走错了」

- 他说“右臂对，但是位姿画错了 / 偏上”时，**机械臂位置是对的**，问题只在显示层。
  正确顺序: 读真值确认臂 → 只改 HTML/位姿数据 → 刷新复核投影坐标。
- 反过来(为一条显示抱怨去挪真机)会真撞：实测按“画面上那个框”把臂挪了 158mm，进另一排槽在 z≈130 卡死。
- 换槽位 / 换编号体系时，先确认用的是**画面画的那一套**(围栏 / place_cells)，不是另一套示教编号 —— 两套差一整排。
