# 画面里的右臂 ≠ 真机位置（8797 / ar3d）

用户说「右臂没跟真实位置同步 / 位置太靠前 / 你是不是记错了」时，**先分清是哪一类**，别直接去改几何：
① 画面画错（图层/外参/URDF）；② 喂给画面的值旧了或被执行信号接管；③ 游标落后（见 sync-step-sim-then-real.md）。
三种表现一模一样，只有第 ③ 类能靠一次 `align` 解决。

## 三条查法（按这个顺序）

1. **真机层有没有被让位**：进 AR/状态空间时 `arViewSet(true)` 会置 `VR.real=false`（真机右臂让位、仿真双臂接管），
   `/ar3d`（vrfull）默认就是这个状态 ⇒ 画面上只剩紫幽灵臂，看着就是「右臂不是真机」。
   左栏 `bArmReal`「🦾 右臂_真机(已隐藏)」点一下切回真机层；`bArmR`「🦾 右臂_仿真」可再把幽灵臂收掉。
   刷新页面/AR 模式跳变会重新让位，这是设计不是 bug —— 要「空闲即真机」靠第 3 条。
2. **紫幽灵臂是不是演完留下的**：仿真、真实轨迹回放、搬运动画、插拔全流程跑完都会把 `PREV.q` 停在最后一帧，
   而真机没动 ⇒ 画面位置 = 「演完的那一帧」。这类动画结束、又没有别的信号在喂时，必须按 TCP 真值重画。
3. **判「在跑」只认信号新鲜**：`ARCMD.fresh === true` 或 `PREV.ssAge < 3`。
   别用 `SSMODE.on/follow`、`PLANT.on`、`TRANS.playing`、`ARCMD.q` 残留当判据 —— 它们会常驻或残留
   （实测 fresh=false、开关全 true ⇒ 「空闲即真值」永不触发，画面永远停在最后一条指令姿态）。

## 「空闲即真值」的规则（页面侧）

- 每条 refresh（1.5s）在**没有仿真正在跑**时：`PREV.on=false`、`PREV.q=TCP.joints`、`VR.real=true`（ar3d 也要能看到真机层）、
  `mjPushQ()` 推 8802，让矢量臂和渲染图都回真机。
- 人主动画的「👻 预览动作」要留：用 `window.PREV_KEEP` 标记，别被自动同步收掉。
- 手动「⟲ 同步真值」按钮在跟随/仿真在跑时必须**拒绝**并说明原因 —— 按真值覆盖会打断正在跟的那条臂
  （用户说「我就是跟着轨迹走」时尤其不能用它去“纠正”画面）。

## 证明「画得对」：URDF 正解对 TCP 真值

`GET :8797/api/urdf` 给了 link/joint 链（`xyz`/`rpy`/`axis`），按链累乘（`T = T·Trans(xyz)·RPY·Rot(axis,q)`，
q 取 `latest.json` 的 `joint`，弧度）算到 `tool1`，与同刻 `/api/tcp` 的 `x/y/z` 比：**≤5mm 才算画得对**
（实测 0.8072/0.2331/0.2258 vs 真值 0.807/0.230/0.2223，差 3.5mm）。差得多才是 URDF/基座/外参的问题。
这条能把「画错」和「值旧/游标旧」一次分开，别跳过它直接去改外参。

## 用户问「我怎么操作」就给按钮路径

1. 打开 `http://<主机>:8797/ar3d`（改过页面就 Ctrl+R —— 页面热读，服务端才要重启）；
2. 左栏「🦾 右臂_真机(已隐藏)」→ 点成「🦾 右臂_真机」；
3. 只想看真机就再把「🦾 右臂_仿真」点成 (已隐藏)；
4. 位置/游标不对：点「◎ 对齐当前位置」，再点「⏭ 同步操作」输 N 接着走。
