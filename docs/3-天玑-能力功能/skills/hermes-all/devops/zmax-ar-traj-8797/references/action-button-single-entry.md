# 8797 /ar3d 页面动作按钮：只留一个真机入口

## 为什么收敛
现场会在几秒内看完一屏，按钮一多就会出现三种误判：点错入口（以为在跑真机，其实只动了仿真）、
不敢点（不知道哪个是真动作）、把仿真进度当成真机状态。定式：**一个页面只留一个“会让真机动”的按钮**，
其余一律删除而不是隐藏（隐藏的按钮会被别的脚本或回退版本重新显示出来）。

## 单一入口的形状
```
[▶ 右臂跑真实轨迹]  游标 k/total · 下一点 #k+1   [↩ 回退 1 点]  [⏭ 单步 +1 点]  速度 x1/x2/⚡真实
```
- 主按钮 = 一次点击从当前游标沿轨迹走到底；游标在末尾时**自己** `POST {"reset":true}` 再跑，不要让用户先去点“回起点”。
- 单步/回退是**检视**工具，保持小号次要样式；单步永远走最慢档（单点不给高速）。
- 进度文字必须写清“已到第几点 / 共几点 / 已用秒数”，不要只写“运行中”。

## 已删除、别恢复（现场逐条点名过的）
👻 预览动作 · ⟲ 同步真值 · 🔌 插入仿真 · 🔁 插拔全流程 · 同步操作 N 点 · 连走 +10 点 ·
回起点 · ◎ 对齐 · 执行轨迹上方那排 `5 / 10 / 50 mm/s` 速度档。

- 速度档按钮删掉后 `SPD_MM_S` 仍要保留（`▶ 执行轨迹` 的下发参数），把 `spdPaint()` 改成空实现、
  **不要删函数**——别处可能在调；`localStorage` 里的旧值照旧可读。
- `cSyncArm`（“真机也走”钩选框）**不要删元素**：单步/同步旧逻辑有 5 处读它。改 `display:none` + `checked`，
  语义恒为真，等价于“页面只剩真机模式”。
- 删控件后要扫一遍 JS 引用：`for id in bPrev bIns bInsp bSyncTruth bSyncReset bSyncStep bTrajStep10 cSyncArm; do
  grep -n "\$('$id')\|getElementById('$id')" tools/web/tcp-ar.html; done`，未加存在性判断的监听要包 `if(el)`，
  否则一个 `null.addEventListener` 会让整页脚本停在那里（其余按钮全部失灵）。

## 命名铁律：按钮名字必须自报“真机 / 只仿真”
- 一个只播放紫色幽灵臂的按钮曾经叫「📍 右臂跑真实轨迹」，现场点完说“我点了，你没动啊”。
  凡是**不下发真机指令**的入口，文案里带「(只仿真·不动真机)」；真机入口才允许出现“真机/真实”。
- 判“点了为什么没动”一行结论：`curl -s 127.0.0.1:8797/api/arm/step_traj/status` 的 `start/n/done` 没变、
  且 `zmax_data/tcp_ar_server_restart.log` 里**没有** `POST /api/arm/step_traj` ⇒ 请求根本没发（纯前端/纯仿真）。
  有 POST 而机器人没动才是服务端闸拒（看返回体 `stage`）；GET 在刷只说明页面在轮询。

## 验收（改完这一屏必做）
1. `curl -s 127.0.0.1:8797/ | grep -c 'bSpdReal\|bSpdX1'` 之类确认新 HTML 真的发出去了（页面 `no-store`，普通 F5 即可）。
2. 用无头浏览器读 DOM：目标按钮存在、被删 id 一个不剩、`typeof runRealTraj === 'function'`、`js_errors == []`。
3. 真机动作用 `dry:true` 打一次同报文，确认服务端受理（`speed_mode` 回显、`grip_plan` 正确），**不真动**。
