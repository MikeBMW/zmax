# 3D 引导位姿怎么画 / 仿真臂怎么摆

适用：8797 /ar3d 上要给某臂画一个「3D 引导位姿」，或让仿真臂（左臂）去该位姿。

## 1. 页面上叫"位姿"的就只画一个框，预抓点不许当位姿画
- `_drawTP` 里 `pre_pos_m` / `pre_pos_mm` 的虚线圆默认关掉（只在 `T.show_pre` 为真时画）。
- 为什么：那个圈比目标高 40mm（= hover），用户会把它当目标，报"位置偏上"，然后你去改 z 越改越偏。
- 自证：`__TP_SCREEN__` / `__TP_SCREEN___L` 必须是**目标点 `pos_m`** 的投影，不是 pre 点的投影。

## 2. 引导几何必须和画面上画的模块同源
右盘有两套槽位编号，不能互相顶替：

| 来源 | 槽1..7 | 槽8..14 | 身份 |
|---|---|---|---|
| `config/points/tray_slots_14.json` | x≈649 | x≈517 | 示教编号 = 真机抓取行（`cell_points.json` 对得上） |
| `zmax_data/ar_rs/fences.json`（AR 围栏） | x≈490 | x≈615 | 画面里画的模块/槽盒 |

- 混用会错一排 ~158mm。而且在 `fitBothTP` 之后的机位（yaw≈197°）世界 **+X 几乎投影到屏幕竖直方向** ⇒ 用户看到的是"上下偏"而不是左右偏，极易误判成 z 错。看到"偏上/偏下"先算 x 差，别直接改 z。
- 口径：`plan_guide._slot_geom` 右侧走 `tray_slots_14`（示教编号），左侧只能走围栏 `左槽N`（左盘没有示教点）。查不到就报错，不要拿另一套顶替。
- 核对真值：`config/points/cell_points.json`（示教抓取点）+ `zmax_data/staging_zmax_repo/data/skills/l2_atomic/place_cells.json`（围栏派生的槽位，带 `prov` 溯源）。

## 3. 仿真臂去一个位姿：位置 IK 不能让它自己挑姿态
- 症状：仿真臂"躺下了"。原因：只有 xyz 约束 + 随机种子 ⇒ 冗余自由度随便走，解出大关节角，整条臂倒。
- 正确做法：
  1. 种子 = **真机示教录制里的抓取臂形**：`zmax_data/rokae_sdk/real_traj_absj.json` 抓取帧的 `q`（槽位抓取那一帧，不是第 0 帧）。
  2. 只接受 `err_mm ≤ 2` 且 `max|Δq| ≤ 0.5rad` 的解；不合格就**不画**，也不编一个歪姿态。
  3. 位置准（实测 0.01mm）+ 臂形自然；姿态达不到目标姿态就如实标注，不许用姿态去换位置。
- 交付自证：`window.__LARM_GO__` 里的 `err_mm` / `dq_seed_rad` / `fk_tool1_m`，以及 `window.__LARM_GO_DONE__`；不看截图猜。

## 4. 改完要给出的数（别只说"画好了"）
- 左右框屏幕坐标 `__TP_SCREEN__` / `__TP_SCREEN___L`
- 仿真臂 FK 落到目标的误差（mm）与相对种子的最大关节角差（rad）
- 两目标相距（m）、角点在画面内几个 / 共 8 个、`js_errors` 是否为空
