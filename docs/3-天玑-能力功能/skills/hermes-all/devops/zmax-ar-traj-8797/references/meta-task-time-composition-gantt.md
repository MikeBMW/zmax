# 元任务「时间构成」显示口径 —— 列义、截断陷阱、甘特条

用户对元任务区的诉求是**每个模块都能看到自己的时间构成**，而且要和双臂泳道一样有甘特图。
三次反复（"节拍没有啊"→"还是没有"→"怎么就不显示每个时间的甘特图了"）分别源于下面三个不同的技术原因，
每个单独看都像"已经显示了"。

## 1. 第 4 列原本放的是 `t_win`，不是 `dur`

`ar_meta_tasks.json` 里每个元任务同时有：
- `t_win` = `[起点, 终点]`（它在双臂泳道里占哪一段，如 `[0, 2.704]`）
- `dur` = 该模块自身耗时（如 `2.704`）

行渲染取的是 `t_win`（`t_win[0]–t_win[1]`）。用户问"时间构成"时指的是 **`dur`** ——
`t_win` 回答的是"它在哪一段"，不是"它要多久"，两者看起来都是秒数，极易混淆。

**做法**: 第 4 列显示 `dur`（`2.70s`，缺省显示 `—`），`t_win` 移到 `title` 悬停里
（连同 `occurrences` 出现次数、`segments` 段数一起给）。列头写明"耗时"，否则没人知道这列是什么。

## 2. `text-overflow: ellipsis` 把要看的数字截掉了

行名格样式是 `white-space:nowrap; overflow:hidden; text-overflow:ellipsis`。名字里含节拍时
（`右臂 · 215 点真轨迹回放 (实跑 424s/轮 · 左臂冻结)`），**节拍恰好落在被省略号截掉的那一段** ——
DOM 里有、`innerText` 能读到、`browser_console` 验证通过，但人眼看页面就是"没有"。

**做法**（两条一起做）:
- 名字缩短到只留身份（`215 点轨迹回放 · 左臂冻结`），把量化信息移出名字格
- 量化信息放进固定宽度的独立列，并给该列 `title` 完整明细

⚠️ 验证这类问题**不能只查 DOM/`innerText`** —— 那证明的是"节点存在"，不是"人眼能看见"。
判据要包括：所在列的宽度、是否 `overflow:hidden`、文本实际渲染宽度是否超出。

## 3. 只有总数没有分段 ⇒ 补甘特条

双臂泳道按 MT-02/03/04 的 `dur` 画横条，MT-08 一开始只有一行 `436s·8.3UPH`。
用户要的是同一套视觉：**436s 花在哪一段**。

做法（可复用）:
1. 把逐点实测耗时固化成真源 JSON（`points: [{i, secs, jump_deg, err_deg}]` + `_total_s` + `_s_per_pt`），
   生成器读它，不要在生成器里重算日志。
2. 分段表用 `(起始下标, 结束下标含, 名称, 色)` 定义，**段间空档单独成「过渡」段** —— 否则各段求和 ≠ 总时长，
   一眼就被看出对不上。
3. 每段耗时 = **逐点 `secs` 求和**，不是按点数均分。按点数均分会把"大范围运动段"和"密集小位移段"抹平
   （实测 转运/举升 2.195s/点 vs 插入 1.692s/点，均分后这个差异就没了，而它正是最有价值的结论）。
4. 前端：一排 `display:flex; height:13px` 的子 div，每块 `width: 该段pct%` + `background: 段色` +
   `title` 写 `#区间 · 点数 · 耗时(占比) · s/点`；下方图例只列 `pct>=2%` 的段，其余合并成
   「其余 N 小段 Xs」—— 否则小段把图例撑成两行还看不清。
5. 校验口径: **各段 `dur_s` 求和必须等于实测总时长**（实测 436.03s == 436.0s）。不等就是分段表漏了区间。

## 4. 双口径必须并排写清来源

同一个 MT-08 有三个数字，混算会被当场指出：

| 名称 | 值 | 来源 |
|---|---|---|
| 录制真值 | 42.85s / 84 UPH（0.199 s/点） | `real_traj_joints.json` 的 `frames[].t` |
| 实跑真值 | 436s / 8.3 UPH（2.028 s/点） | 全程实测逐点求和 |
| 已弃用慢档 | 2352s / 1.5 UPH | 旧 `speed=20% + chunk=1 + dwell=250ms` |

主口径（元任务报的那个）用**实跑**；录制值保留在 `rec_*` 前缀字段里作参考；
差距原因写进 `gap_reason` 一句话（逐点每点 ~0.33s 通信固定开销 > 录制单点间隔 0.199s）。
不要用「理论值/真实值」这种模糊措辞 —— 直接标明是录制还是实跑。

## 5. 嵌套字段的 API 白名单

`tcp_ar_server.py` 的 `long_horizon` 白名单里列了 `replay` ⇒ 整个 dict 透出，新增的 `gantt`/
`gantt_total_s` 自动带上。但如果白名单改成逐字段枚举，**加在 `replay` 里的新字段会被静默丢掉** ⇒
前端拿到 `None` 且不报错（曾踩过 `uph`/`s_per_point`/`speed_pct`/`source` 全 `None`）。
判据: 新增字段后 `curl :8797/api/ar/meta` 直接 grep 该字段名，不要靠页面表现倒推。
