# 8815「E · 相位 ∈ S¹」状态分段(239 点 v2)

老倪 2026-11-21: 「239 个点 … 更新到相位图 S1, 自己标注状态」。

## 口径铁律

1. **状态 ≠ 停点**。停点(`point_stops_v2.json`)是“机械臂在哪停 1 秒”; 状态是“这一段在干什么”。
   早期把停点直接当状态用, 结果 `#99 工作点` 与 `#100 插入` 同坐标(819,227,190)/同弧长(1008.4mm),
   环上切出一个长度 0 的缝。
2. **状态边界取几何拐点**(停点帧 / 最深退让 / 全段最低点 / 速度档切换), 且必须 **首尾相接覆盖 0..238**——
   `tools/make_v2_states.py` 里用 assert 卡住: 第一个必须 #0, 最后一个必须 #238, 相邻 `b0+1==a1`。
3. 行名用**动作段**而不是“落点”(“插入到底”而不是“工作点”), 这样一行的语义 = [i0,i1] 那段动作。

## 边界铁律(现场纠正出来的)

- **最低点必须单独成段**。曾把 `#31–#50` 写成“抓取·抬升”, 而 #31 z=121 还没到底(#32 z=113 才是最低),
  老倪一眼看出「还没到最低的抓取点就显示抬升了」。凡是“到底/到顶”的拐点, 用 
  `min z` / `max X` 算出来单独占一行, 不要和后续动作合写。
- **扫码只有一个点**。采样表里扫码停位就 1 帧(#64), 别把“扫码”和“去插口”写在同一行;
  顺序必须 扫码 → 接近 → 对位 分开。
- **物理上同一动作不要拆两行**。`#114–#133` 那段 1mm 来回属于“拔出”, 拆成“二次插入/孔内微调”
  会让真机抖动时高亮在两行间翻。

## 高亮不能上下跳(两层机制)

1. 几何层: 抖动区不要拆成两行(见上)。
2. 渲染层: 换行需要 **稳 250ms**, 单帧抖动只重置候选不换行;
   但**人拖滑杆/点行(`_scrubT` 800ms 内)立即跟**, 否则拖了不动。
  ```js
  const _scrubbing=(Date.now()-(_scrubT||0)<800);
  if(_scrubbing||window.__ST_HI==null){ __ST_HI=hi; __ST_CAND=hi; __ST_T=now; }
  else if(hi===__ST_HI){ __ST_CAND=hi; __ST_T=now; }
  else { if(__ST_CAND!==hi){__ST_CAND=hi;__ST_T=now;}
         if(now-__ST_T<250) hi=__ST_HI; else __ST_HI=hi; }
  ```
  🔴 坑: 把 `__ST_CAND=hi` 写在分支末尾会把候选又改回去(抑制永远不生效/永远生效各一种),
  必须只在“接受新值”的那个分支里写 `__ST_HI`。

改表只改 `tools/make_v2_states.py` 的 `STATES`, 再 `./gui-venv311/bin/python tools/make_v2_states.py` 重写 JSON,
服务端 `_states()` 读文件生效(sectors 应答多一个 `states` 字段, 带 i0/i1/name/color/kind/t_s/t_frac/s_mm)。

### 高亮单调锁(轨迹自交必踩)

真机最近点是对**整条轨迹**求的, 演示轨迹会自交(回程再次穿过抓取走廊) ⇒ 最近点跳回前面的行,
250ms 稳定判据挡不住, 现象就是“方框上下乱跳”。在稳定判据之上再加一道**行号只增**锁:

```js
const _cycleStart=(cur_i>=0 && cur_i<=st[0].i1);      // 回到段首 = 新一圈, 允许重头
if(_scrubbing||_cycleStart||window.__ST_HI==null){ __ST_HI=hi; __ST_MAX=hi; }
else { /* …250ms 稳定判据… */ hi=Math.max(hi, window.__ST_MAX); __ST_MAX=hi; }
```

副作用要主动告诉现场: 手动把臂拖回中间, 高亮**不会**跟回, 只有回到段首才重置(这是“不上下跳”的代价)。

## 🎥 从现场演示录像生成这套状态表

`tools/build_demo_cycle.py`(等弧长重采样 + 停留段检测 + 点位匹配), 口径:

1. **窗口按时间切死**, 不给“从头到现在”: 采集器在回放期间还在录 ⇒ 我自己的回放动作会混进数据集
   (实测混进 3 万帧, 弧长从 5.9m 变 8.9m)。窗口两端 = 最后一个工序点(下盘放料) + 它之前最近一次抓取点。
2. **停留段 = 速度 <3mm/s 且 ≥0.6s**; 静止时弧长不前进, 重采样会把它压成**一个点**, 所以按
   “停留段”而不是“采样点”分段, 否则每个停位都变成 0 长度。
3. **点的物理距离近 ≠ 工序相邻**: 插到底 (819,227,190) 与钩拉环位 (806,230,189) 只差 13mm,
   30mm 半径匹配会把“插入”误标成“钩拉环”。必须再用**工序先后**消歧(在“扫码→等待检测”之间一律算插入,
   其中最靠右的一个才是插到底), 名字也按现场说法: 插到底之后是“**后退**→等待检测”, 等待检测之后是
   “**移动**→钩拉环解锁”。
4. 🔴 **绝不用“缩放状态索引”去对齐另一条轨迹**: 两条轨迹的重采样基不同, 缩放后段边界整体错位
   (实测“等待检测”指到了 AOI 位置, 差 677mm)。要么**同源重建**(同一次重采样出轨迹和状态),
   要么别换轨迹。
