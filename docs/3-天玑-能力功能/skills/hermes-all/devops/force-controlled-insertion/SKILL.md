# 力控插入(peg-in-hole) —— 通道先证、插入只走力控、进度用真值算

## When to Use
现场说「你正在插入口 / 这个位置你自己记住 / 向前自己插入 / 调用力控算法」, 或任何要把末端工件压进孔的动作。
和「点位转移」不是一类事: 转移靠位姿到位就够, **插入的最后一跳靠力, 且目标点天然在围栏盒里面**。
（本机运动下发/授权的完整细节在用户自有技能 `real-arm-motion-control`; 本文只管插入这一类。）

## 🔴 力红线（高于一切配方）

- **上限以现场当次口头口径为准, 并落成代码常量**: 同一现场会改口（例: 先 30N, 后改为 **40N**）⇒
  改口径时同时改 `FZ_HARD_N`（红线）/ `FZ_TRIP_N`（实际停手, 留 5~6N 余量）、改台账、改记忆, 三处一起;
  `--watchdog-n/--stop-n` 传更大的值也必须被压回 `FZ_TRIP_N`。**不要沿用上一次会话的数值**。
- 判力必须**运动中每 20ms 一次**, 超阈立刻 `stop` + `moveReset`。"等这一步走完再看力"实测就是把力顶到 83.6N 的机理。
- **不做位置步进蹭孔**: 0.5mm 一步顶在刚性孔口面就是 40~80N（实测 8.6→22.6→41.0→63.9→83.6N）, 天然违反红线。
- 红线以内**实测唯一稳定通路 = 位置模式慢推 + 只读力做被动看门狗**（§5）; 力控模式只在自由段成立,
  工件一顶到孔口/止口就必然被控制器保护下电。
- 侧向力是独立红线（"别划伤工件侧面"）: 侧向合力/力矩都要单独设阈值, 不能只盯轴向。
- 超限事件入台账 `docs/6-开阳-工程落地/INCIDENT-INDEX.md`（力序列/机理/处置）, 不要只在对话里说。

## 流程(按这个顺序做, 每一步都有判据)

### 1. 现场说「记住这个位置」= 落库, 不是脑内记
```
<项目>/gui-venv311/bin/python tools/record_point_sdk.py --record <新点名> --desc "<现场原话场景>"
```
- 零运动、不需真动授权，但**臂必须停稳**(工具自带三道闸: 帧龄/位置范数/极差)。
- 录完**回读**逐位值，并算出它与已有点位的关系一并报给现场
  (例: "离已示教的插入点 54.2mm, 姿态差 0.99°")。这句话的意图是“以后能回到这里/拿它当基准”。

### 2. 算清几何再谈动作(只读, 零风险)
- 当前 TCP、目标插入点、工具 Z 轴在基座系的方向: 由 quat 算 R，取第 3 列。
- 插入深度 = |插入点 − 口点| ，方向 = 工具 Z。两者必须**同向**(夹角小)。
- 口点与插入点的**姿态差**决定能不能纯平移: >2° 就要当心(边转边插会别针)。
- 报给现场的口径: 深度多少 mm、沿哪个轴、姿态差几度 —— 这三个数到位才谈下发。
- **工具 Z 必须校平到水平**（插孔基本水平）: `Rz=[2(xz+yw), 2(yz−xw), 1−2(x²+y²)]`, `angle=asin(Rz_z)`;
  |angle|>2° 先绕 `Rz×Rz_des` 做最小旋转校平（位置不动）再推。不校平就推 = 轴向顶在孔口面,
  加多大力都只出 0.4mm 位移 + 十几牛尖峰（实测轴差 4.46° 时 advance 8s 只前进 0.41mm、力峰 16.7N）。
  欧拉角约定先用当前 quat 自算 ZYX rpy 与控制器 `pose` 返回的 rpy 对齐再下发; 验收看**动后工具 Z 夹角**
  （实测校平后 `[+1.0000,+0.0080,−0.0000]`、位置漂移 0.003mm）。
- 校平判据是"行程上的漂移 ≤ 孔径余量", 不是追到 0.00°: 现场说"目视已经平行、不必绝对水平"时,
  按 quat 真值报残余角度和它在实际行程上造成的侧偏量（几度 × 几十 mm = 几百 μm~几 mm）, 由现场决定是否再校;
  目视只能做粗判, 不能替代 quat 真值。

### 2b. 现场说「我卡在插入位置」= 用示教孔位算逐轴账, 不靠画面判

- 三步只读: ①读孔的示教真源 `zmax_data/runtime/traj/sim_insert.json` 的 `holes[]`(`mouth` 口点 / `insert` 到位点, mm)
  ②读**当前 TCP**(Orin SDK 桥 `endInRef`, 不是法兰) ③逐轴报四个数: **沿轴已进多少 / 距 insert 还差多少 / 横向偏差 / 轴向高度偏差**。
  实测一例: 口 `761.3/229.8/187.6`、到位 `811.6/229.8/187.6`, 当前 `806.1/230.1/188.8` ⇒ 已进 44.8mm、差 5.5mm、y 偏 +0.3mm、z 高 +1.2mm
  ⇒ 签名是「进了大头卡在最后几毫米 + 轴向高 1mm」, 先查上侧壁摩擦/轴未校平, **不是**"还没进孔口"。
- 🔴 **eye-in-hand 朝下看台面时, 水平朝向的孔口根本不在视野里**: 画面里"没有孔 / 末端悬空"与"已进孔 45mm"可以同时成立。
  结论只能由几何给; 画面只用来判"末端在不在、有没有明显歪"。要目视确认咬合只能**转腕或换机位**(纯俯视看不到孔)。
- 把帧交给独立目检是**第三证**, 但它常与几何矛盾(实测它报"视野里没有孔、末端与下方平面有间隙") ——
  矛盾时**先查视角覆盖**(相机朝向/是否俯视), 再谈结论: 别把"画面里看不到孔"写成"没插进去", 也别用一个悬空/未到位判定覆盖几何数字。
- 不要拿仿真孔位当真机真值: `holes` 标着"示教实测"才可直接比; 纯仿真轨迹的坐标要写明是仿真坐标系。

### 2c. 两种卡法的签名不一样: “差最后几毫米” vs “根本没对准”

都在口前不动, 但一个是进了大头被摩擦拖住, 一个是前缘骑在口沿。混了就会一直加推力、磨壁。

| 签名 | 实测例 | 判读 | 处置 |
|---|---|---|---|
| 已进大头(≥80%)、差最后几毫米、轴向高 1mm 级 | 口 761.3 / 到位 811.6, 当前 806.1 ⇒ 进 44.8 差 5.5, y +0.3, z +1.2 | 上侧壁摩擦 / 轴未校平 | 先校平轴, 低速慢推, **不加力** |
| 只进 ≈倒角深度(几 mm)、某轴单边贴壁 <1mm、抖动从不穿过孔中心线 | 孔深 50.3, 停在 765.5 ⇒ 进 4.2(8%); z 中位比中心高 +2.8, 峰 191.9 vs 上壁 192.3(余量 0.4); z 抖 3.3mm, 穿中心 0 次 | 工件前缘**骑在孔口上沿**, 推力全被壁吃掉 | 先回中(Δz/Δy 各几 mm)再推, 每段 ≤5mm, 段后取真值 |

- **“抖动从不穿过中心线”是最省事的单边贴壁判据**: 来回振荡一直在同一侧 ⇒ 再加推力也只是磨上沿。
- 孔中心与半尺寸直接从示教孔位算(`(p2−p1)/2` 逐轴), 不要凭“看着差不多”给对准量;
  “离壁余量”比“偏差”更能说服现场("只差 0.4mm 就顶到上壁" 比 "高了 2.8mm" 直观)。
- 没有六维力通道时, 这套**位置几何**就是唯一可信证据; 汇报口径写“位置+图像判, 非力控插入”。

### 2d. 李萨如力控搜索在本机的口径（先证通道 · 轴不能照抄 · 摆幅按余隙定）

用户问“懂不懂李萨如力控搜索”时, 要能给到本机的**轴、摆幅、判据、现成原语**四件, 不是复述概念。

- **先证力通道, 再谈搜索**: `tools/rokae/ft_direct_sampler.py` 只读采 30s(`getEndTorque`, 世界系)看零漂与轴向/侧向比值。
  工具负载/质心没标定过时静止 |F| 就带几十牛自载(控制器会同步报 `41447 力矩传感器与模型偏差较大`)⇒ 此时
  “力回落=入孔”这类判据全是假的。清零用 `tools/rokae/fix_torque_zero.py`, 判据用 Δ(相对静止基线)。
- **轴不许照抄产线配方**: 产线是 `frame=tool · plane=XY · 力沿工具 Z`; 本机插入轴是 **base +x**
  (`ft_direct_sampler` 口径: 轴向力取 `fx`, 侧向取 `hypot(fy,fz)`)⇒ 搜索平面 = **Y-Z**, 恒力加在 +x。
  照抄会把恒力加错轴, 看起来“在搜索”其实在蹭侧壁。
- **摆幅按孔径余隙定, 不按“好找”定**: SFP 口内腔 13.4×8.5 而模块几乎等宽 ⇒ 余隙 <0.5mm ⇒
  `A1/A2 = 1.2~1.5mm`(相位差 π/2)、`F ≈ 5~8N`、搜索盒 ±4mm、超时 6s; 产线那套 6mm@3Hz + 4mm@2Hz
  是给大余量孔位的, 用在 SFP 上第一个摆就把工件顶在口沿。
- **入孔判据要两个同时成立**: 轴向力从设定值掉到 <1/3 **且** 沿轴前移 >1mm ⇒ 停 overlay 转直插;
  只看力回落会被摩擦骗(摩擦同样让力降而不进位)。
- 🔴 **“在固定点以 ~1Hz ±1mm 恒定抖动”不是搜索, 是被动抖**: 实测 z 188.8↔191.1 来回、从不穿过孔中心线
  ⇒ 顶住—回弹—再顶。真搜索是两轴正交正弦、相位差 π/2 的椭圆/8 字。把被动抖当“正在找孔”会一直等下去。
- ⚠️ **接触态不要指望力控模式**: `fcStart`/`setLissajousOverlay` 在硬接触下会触发 `41451` 让控制器下电(见 §5)。
  ⇒ 搜索段只有两种合法姿势: ①口前自由段起力控 overlay ②**位置域李萨如**(位置模式按正弦下发小位移,
  力只做被动判据)。现成原语在 `tools/rokae/insert_sdk_fc.py`(`fcInit/setControlType(1)/setCartesianStiffness/
  setLissajousOverlay/startOverlay`, 自带 25N 看门狗与位移/时间双限); 先只打印参数、不发。

### 2e. 力反证几何: 孔位是谁给的, 决定信谁

- **示教孔位可直接当基准, 尺量/围栏量出来的孔中心只能当假设**。实测同一口: 按对射尺量算出的
  "应对中方向"是 base z −3.0 / y +3.6, 而力扫描给出的最松方向**正好相反** ⇒ 尺量有遮挡/斜面, 力不会撒谎。
  两者冲突时以力扫描为准, 并把旧基准标成"待复核", 不要拿它继续算对中量。
- **十字扫描定方向** = 5 点 × ±0.5mm 位置微动 + 只读力(不进力控): `insert_sdk_fc.py --mode scan`。
  最小侧向点 = 让位方向; **中心点侧向最小、四周单调变大 = 工件顶在面上, 不在孔里**。连续两次扫描形状一致才算稳定。
- **刚度判别"端面接触 vs 孔内导向"**: 侧向 `nudge` ~1mm 读 |ΔF|(`tools/rokae/lateral_nudge.py`, 单次位移上限 3mm)。
  实测 0.94mm 换来 |ΔF| 9.97N ⇒ **≈10 N/mm = 端面级硬接触**; 余隙 <0.5mm 的孔内导向段不会这么硬(几 N/mm 以内)。
- **侧向 > 轴向 = 顶在壁上, 不是到底**: 李萨如两次都只走 0.20/0.36mm 就被力矩判停,
  峰值侧向 4.3~4.6N 而轴向只有 1.8~5.5N ⇒ 推力被壁吃掉, 续推只是磨壁(对照 §2c 的"差最后几毫米"签名)。
- ⇒ **顺序不可颠倒**: 先对正到 ≤0.3mm(视觉或力扫描) → 直插 ~5mm 进入孔内 → 剩余行程才交给李萨如+力控。
  **李萨如只能修孔内 ≤0.5mm 的找正, 修不了端面对正** —— 端面顶住时加摆幅、加推力都只会更别劲。

### 2f. 成功的那一趟 = 唯一可信的对正模板（别用自己算的位姿）

实测 2026-11-19 SFP 口②, 同一台臂、同一个孔, 只换对正位姿:

| | 成功那次(示教/人工) | 按几何自己算的 | 差 |
|---|---|---|---|
| 入点 TCP mm | 761.75 / 228.07 / 190.36 | 764.77 / 225.10 / 188.10 | y +2.97 · z +2.26 |
| rpy | −2.9484 / −1.5163 / −0.1782 | 3.1410 / −1.4342 / +0.0166 | pitch 4.7° · yaw 11.1° |
| 结果 | 进 59.1mm 一次成功 | 8.8~11.4mm 顶死, 预载 75~163N | — |

- **5~11° 的对正角差 = 位置控制把毫米级偏差变成几十牛**; 速度(4 vs 10mm/s)、力控开关都不是变量。
  ⇒ 卡住时先怀疑"入点位姿哪来的", 不要先调摆幅/加推力。
- 成功那趟的节奏可直接复现: 1.3→5.3→8.5→10.2mm 停 2s(fz −6.9) → 12.7mm 停 3s(fz −13.8, 过 cage 卡簧)
  → 一把推过, fz 峰 **−44.4N** → 59.1mm; 拔出时 fz **+20~+73N**(比插入力还大)。
  10.2mm 那个停点就是位置控制卡死的位置 —— 人工是靠停顿+微让过去的, 不是靠更大推力。
- 取模板的方法: 50Hz 直采 `tools/rokae/demo_recorder.py --rate 50`(力+TCP+关节+op),
  事后按 `x>口沿 && |y−yc|<10 && |z−zc|<10` 切出"在口内"的连续段, 存 `success_<date>.json`
  (入点位姿/最深/力包络/逐帧) 进 `zmax_data/insert_fc_1119/` 并同步一份到 docs 事故目录。
- 判据只认 **入点位姿 + 节奏**, 不认"我算出来的孔中心": 对射尺量的孔中心已被力数据两次否定(§2e)。

### 2g. 相机对正: "能取到画面" ≠ "能看懂画面"

- 取帧这步是可靠的: 中央相机 `curl -s -o x.jpg http://127.0.0.1:8812/snap.jpg`(640×480), 均值 ~150 即正常(几十 = 黑屏/挡光)。
- **没有视觉模型时, 灰度/形状检测只能给候选, 不能给结论**: 暗矩形检测(`threshold(g,75)` + 连通域 + 宽高比 1.2~3.2)
  在一帧里只出 2 个候选 ⇒ 把候选框画出来(编号 1/2、附像素与归一化坐标)让现场指认, 比"我觉得是那个"可靠;
  汇报时先写清"能取画面 / 不能看懂画面", 不要用检测结果冒充识别结论。
- 真要闭环对正, 缺的不是检测而是**比例尺**: 让臂沿 base y / z 各走 2mm, 读同一靶点在像素上的位移 ⇒ mm/px,
  之后 `Δmm = Δpixel / px_per_mm` 才能算出对正量。没有这一步, 像素差换算成毫米全是猜。

### 3. 🔴 先证“力控服务在图里”，再谈授权/录点/派发
```
ssh <边端> 'source /opt/ros/humble/setup.bash; export ROS_DOMAIN_ID=0; ros2 service list | grep -Ei "lissajous|insertion"'
```
- **0 条先排 CLI 卡死**: `ros2 daemon stop` 再列。`ros2 node list` 抛 `xmlrpc` 异常 = 守护进程卡死,
  会**假报“图上什么都没有”**(实测同一台机器重列后立刻出现 44 个服务)。
- 仍 0 条 = 驱动/运动栈没起 ⇒ 现场起驱动再谈, 不要派发。
- ⚠️ **TCP 真值新鲜 ≠ 服务在**: 位姿常走 SDK 直连(不经 ROS)，臂“活着”和服务“在图上”是**两个探针**。
- 派发后若回执是 `… · 没拿到 success 字段 · 尾部: waiting for service to become available...` 且 TCP 位移
  `0.00mm` ⇒ 就是服务不在图上，**不是服务慢、不是设备拒动**。立刻停手，别重发第二条。
- 顺序固定: **探服务 → 录点 → 授权 → 派发**。授权窗(300~900s)烧在一条注定没人接的派发上 = 现场白等。

### 4. ��栏预检 FAIL 在插入类任务里是**预期**的
`precheck_move.py --to <插入点>` 常报
`连杆6 侵入<设备> 106.2mm · 夹爪包络 72.9mm · 到目标直线 71.7mm` ——
因为**插孔本来就在那个围栏盒里**。
- 这个签名**不是**“路径不安全”的新信息，而是“最后这一段在盒内”的必然结果。
- ⇒ 既不能硬闯(盲推一条深几十 mm 的直线没有任何力保护)，也不能因此把任务推回去；
  正确做法是**把这一段全部交给力控**(见 §5)，并用围栏原文当“为什么不盲推”的证据讲给现场。

### 5. 插入 = 位置慢推 + 被动力看门狗（力控模式在接触态不可用）
一发 = 力控搜索/压入(搜索盒 ±10mm，以**当前位姿**为盒原点，力沿工具 Z)。驱动侧配方口径(产线状态机):
`6N 沿工具Z`(第二次补 8N) · `K=[6000,6000,0,300,300,100]` · `vmax=[0.1,0.1,0.01,5,5,5]` · 盒 ±10mm / 8s。
⚠️ **硬接触状态下力控模式一律不可用**: 工件顶在孔口/止口时, `fcStart` / `setLissajousOverlay` / `moveStart`
任一步都会触发 `41451 力控模式触发保护, 控制器下电: Cart Velocity OverLimit`（连续 5 次复现;
`K_z` 给 0 / 2000 / 20000 结果一样, 工具 Z 校平到 −0.000° 也照样复现）;
之后所有力控接口报 `ec=-17 motor power state unsupported operation`。**那不是你停的, 是控制器下电** ——
先读 `state` 的 `powerState`, 别以为是脚本坏了; 上电复位只能现场做。
⇒ 插入段**不要进力控模式**: 位置模式 MoveL 慢推（0.45~1.9mm/s）, `getEndTorque` 只做被动看门狗,
六轴阈值（轴向/侧向/力矩）运动中每 20ms 判一次。已验证可连续推 40mm 且全程不下电。
具体配方/参数/判据表见 `references/position-push-insertion.md`。
⚠️ **非力控模式下力含重力偏置**: `getEndTorque` 不扣负载, 静止 |F| 就有 24N 级自载;
一切判据都用 **Δ(相对静止基线)**, 汇报时写"绝对值 X N(含自重 Y N)/ 净接触 Z N", 否则现场会以为已经超红线。
⚠️ **想拟合掉这块偏置, 先看姿态多样性**: 模型 `F = m·R(q)ᵀ·ḡ + b`(m 质量, b 零偏)是线性最小二乘,
但**只有 2 个朝向(原点 + 口沿)时解是退化的** —— 实测 `spread ≈0.01`, 拟合出**负质量**(−2.7 ~ −9226 kg)、
残差 5.5N ⇒ 数值不可用。判据: 同一工具 ≥5~6 个明显不同朝向、`spread = mean(1−dᵢ·dⱼ) ≥ 0.3`(d=工具 z 轴)
才允许 `tools/ft_gravity_fit.py --fit`; 采力与姿态要同帧落盘(`tools/rokae/ft_pose_sampler.py`)。
姿态不够时**只有一个合法口径: 同姿态差分** —— 每发运动前在该姿态静止 0.5s 取基线, 接触力 = F − F_base,
运动全程不许转姿态(一转, 重力项就变, 差分失效)。
⚠️ **力矩同理, 而且漂得更凶**: 静止 |T| 随姿态在 0.7~9Nm 级变化（自载 × 0.2~0.3m 力臂）,
所以“力矩 > N Nm 就停”这种**绝对阈值在这台臂上没有物理意义**; 力矩看门狗必须写成 `max(|Δtx|,|Δty|,|Δtz|)`,
基线在每发运动前用当前姿态重取（同一个口、同一天, 姿态一变力矩就能差 8Nm）。
- 每发**前后各读一次 TCP 真值**，算 Δ 与累计；一发位移 **<0.5mm** ⇒ 判“到底/挡住”，停。
- 累计超上限(按实际孔深设, 别写死) ⇒ 停。
- 服务回执 `success=False` ⇒ 中止，**绝不重发**(重发=在未知接触状态下叠加力)。
- 全程**不发夹爪指令**: 松开是独立一步, 别让"插入"顺手把工件掉了。
- 每发推进前先确认**件还在爪里**: AR 页面锁定框 `box2d` 与实时框相差几十~几百像素 ⇒ 件在夹爪里滑了/歪了,
  此时“找孔/加压”全无意义（实测几十牛顶压后模块框从 (317,0) 掉到 (600,452)）, 先让人重新夹正再谈。
- 一发位移 **<1mm** 且力已升到阈值 ⇒ 判"顶在孔口面上", **不是"快进去了"**, 不许续力; 位移偏 <1mm 一律按顶面处理。
- **侧向持续 + 力矩单调上涨 = 轴没对齐, 不是孔太紧**: 侧向一直 7~9N、力矩从 1.3→3.0Nm 随行程涨,
  而轴向只有 10N ⇒ 工具轴/孔轴残余角度在长行程上累积成侧偏（5.7° / 40mm ≈ 4mm）。此时续推只会磨一侧壁,
  先退出来、校平轴再推; **工件已在孔内时禁止原地转姿态**（绕 TCP 转 5.7° 会把末端扫动 10mm 级）。

### 5b. 🔴 三条硬教训: stop 不等于卸力 · 快段必须在孔口之前结束 · 打断会话不能 kill

- **`stop()` 只保持位置, 不卸力**: 工件楔在孔里时伺服一直顶着, 六维力会**自己往上爬**
  （实测 35N → 119.8N → **178.8N**/|T| 54.8Nm, 期间臂是 idle 静止的）。
  ⇒ 任何 force/axial/lateral/torque_stop 之后**必须自动沿轴退 1.5~3mm 再报数**（`unload_after_stop()`）;
  卸力后 |F| 会立刻回到自由段基准（实测 179N → 12.6N 只用 3mm）。
  **汇报里要区分“峰值 |F|”和“卸力后 |F|”**, 否则现场会以为臂还在顶。
- **快速接近段必须在孔口之前就结束**: seat 点距孔口约 50mm, `--approach-mm 15` 意味着“快段”会
  直接冲进孔口 —— 实测 speed 15(≈6.8mm/s) 在孔口 1mm 内就顶出 35.8N/11Nm, 把工件楔死。
  ⇒ 快段只用到孔口前 ~60mm, 孔口段一律 **≤1mm/s**; 快到孔口却不减速 = 用位移换力, 必楔。
- **打断运动会话用 `sdk_ctl.py stop`(规划停), 不要 `kill -9`**: 被 kill 的会话在控制器里留下
  MoveL 队列, **下一次会话 `moveStart` 会接着把它跑完**（实测臂自走 150mm, 0.80294→0.65198）。
  ⇒ 会话开头强制 `stop() → moveReset() → 0.25s 内位移 >0.05mm 立即拒发新指令`（预静止闸）。
- **李萨如摆幅要跟着偏差量级选**: 尖端差 1~2mm 时 ±0.2mm 摆幅只能推 1.2mm 就顶 30N,
  ±1.2mm 摆幅能推 3.2mm（但侧向涨到 17.6N）。⇒ 先大摆幅找孔, 进入后**收小摆幅**防划侧壁;
  若各档摆幅都卡在同一个力位, 说明不是摆幅问题, 而是**工件在爪里已经歪了**, 先让人重新夹正。

### 5c. 🔴 力读数的「状态口径」—— 跨状态比绝对值必错

- `fcStart` 起力控后读数**自带重力补偿**, 静止基线 ≈0（实测 (−0.26,−0.08,+1.44)N）;
  `fcStop` 之后回到未补偿口径, 同一姿态同一位置立刻变成 (−14.4,−3.1,+3.8)N。
  ⇒ 每条力曲线/阈值都要标注"是否在 fcStart 期间", 判据只能**同状态内差分**;
  跨状态混比会得出"已经压到底 163N"这类荒谬结论, 并据此误判"到底/卡扣"。
- 两套阈值分开写死: 位置模式(未补偿口径)用 Δ 阈值, 力控段(补偿口径)用绝对值阈值。

### 5d. 证伪「这个大力是真预载还是传感器漂零」

- **退 1mm 看力**: 按 ~45~55 N/mm 比例下降 ⇒ 真实弹性预载（实测退 2mm 掉 110N）;
  退了力不动 ⇒ 是偏置/漂零, 先查 fcStart/fcStop 状态与驱动零位, 别当接触力用。
- 同时用**独立 raw 采样器**交叉验证: `tools/rokae/ft_pose_sampler.py`（10Hz, 只读 `getEndTorque`）
  不共享运动脚本的力控状态, 两条曲线同段同幅 ⇒ 排除"脚本自己读错"。

### 5e. 顶住时的过冲 = 速度 × 检测延迟 × 刚度

- 力阈值从"读到超阈"到"真停住"有 ~0.2~0.35s 延迟, 期间位置环继续走:
  实测 4mm/s × 0.3s × 55N/mm ≈ 66N 预载, 6N 的活干成了 160N。
  ⇒ **接触前速度 ≤1mm/s、每段 ≤1mm**（长距离 MoveL 一律禁止）。
- **停手分支要逐个模式 grep 有没有调 `unload_after_stop()`**: 曾经 `insert`/`lissa` 有、
  `advance`/`push` 漏了 ⇒ 同一条已知教训用 75N/163N 又重犯一次。新增或改任何推进模式,
  第一件事是检查 force/ABORT/torque/timeout 四条停手路径都退轴卸力。

### 5f. 「静止 + 力恒定」= 程序停住了, 不是顶住了

- 工件在口里静止十几分钟、力稳定在十几牛**没有任何台阶** ⇒ 这是**指令层没继续推进**, 不是顶壁;
  真顶住的签名是 ①力随微小位移按刚度变 ②~1Hz 被动抖动 ③侧向 > 轴向。
- 反过来最有用的真值参照是**现场手动插成功的那一次**: 实测人手拖动插到底 55.6mm 全程只有 1~2N
  ⇒ 差别在**柔顺**, 不在位置精度。把那一趟的深度/速度/力记下来当判据基线(到位判据照它定)。

### 5g. 🔴 力信号先过滤再当判据: 尖峰是真实存在的

- 实测 74,547 帧(50Hz, 力+位姿同采)里 **10 帧 |F|>200N(0.013%)**, 集中在两次 **op=moving 的快速移动**,
  各持续 30~60ms, 峰值 **948N / 2771N** —— 物理不可能(工具 1.5kg); 插入段本身 −51~+73N, 干净。
- ⇒ 力判据(看门狗 / "力已到" / 入孔判定)一律先 **5 帧中值滤波 + 剔除 |F|>200N**。
  不过滤有两种坏法: 快速移动的尖峰误触发看门狗提前停; 或反过来被判成"力到位"而提前宣布插好。
- 诊断口径: 统计 `|F|>200N` 的帧占比与所在 op —— 在 `moving` 段 = 惯性/传输瞬态(正常, 过滤即可);
  在**静止段**出现 = 传感器零位/通讯问题, 按 §5d 先证伪再谈接触力。

### 5h. 这一次全流程实测(2026-11-19 夜): 进 48.9mm 力峰 7.4N, 原路退 51.9mm

同一个口、同一个成功模板姿态, 从 759.70(口前 2mm) 推到 810.68(**进深 48.93mm**, 底 811.6)= 一次干净插入。
四条可复用的实测结论:

- **速度/段长是决定性的**: 0.5mm/s × 2.5mm 段 ⇒ 峰轴向 **19.5N→25.1N 触线**、停手后继续爬到 **44N**;
  同样位置改 0.3mm/s × 1mm 段 ⇒ 峰轴向 **0.6~1.4N**。⇒ 进孔段固定 **0.3~0.4mm/s, 每段 ≤1mm**, 别用 2.5mm 段。
- **`stop()` 后力还会涨, 而卸力可能根本没发生**: 触线后脚本内的 unload 下了但 **x 一格没动**
  (日志显示 `已退 3.0mm` 实际位置不变), 力停在 **37.8N**; 靠人工补一条 −3mm 才回到 27.1N(=基线)。
  ⇒ unload 必须 **下发后回读位移 + 不到位就重试**, 并把"卸力后 |ΔF|"打进日志, 不能只打印意图。
- **moveStart 后的 idle 竞态会让每段只走 0.3~0.6mm**: 控制器还没切到 moving 时轮询就读到 idle,
  循环立刻退出 ⇒ 实测 4.5mm 的段只走了 0.59mm、2.1mm 的段只走 0.36mm。
  修法: 必须先 `seen_moving=True` 才允许用 idle 判结束。
- **拔出第一段的 60N 是卡扣, 不是挂住**: 沿 −Z 退的第一段 ΔF=60.35N 被 8N 限拦停,
  放宽到 90N 后 16 段全程 ΔF 3~24N、侧漂 ≤0.014mm、转角 0.0001rad, 力从 35.5N 降到 14.1N(≈基线)。
  历史拔出力 20~73N ⇒ **退出段限值按 90N 设**, 否则第一段必误停。
- 退出会沿**工具轴**走: 工具 Z=[+0.998,+0.015,−0.053] ⇒ 退 48mm 在 base 上带出 z +2.6mm 的斜移,
  这是轴的固有 3° 夹角, 不是侧漂; 判侧漂要看每段增量(≤0.014mm)而非总位移。

### 6. 验收与取证(不许用“已下发”当插入成功)
- 现场说“你看着”时的实时口径(四项, 不刷屏): **进入深度 / 轴向力 / 侧向力 / 有没有 >5N 的力台阶**;
  看到力台阶而深度不动就立即喊停(那已经是顶住), 不要等这一发走完。跑完后才出完整力-深度曲线。
- 硬证据三件套: 起点 TCP → 每一发的 Δ 表 → 终点 TCP + 累计前进 mm。
- 落盘 JSON(起终点/每发耗时/Δ/回执)到 `zmax_data/reports/insert_force_<时间>.json`。
- 汇报必须给**逐发位移表**，而不是“已插入”；位移为 0 却报成功是事故级谎报。

### 7. 到底判定 → 存点位 → 同口一步直插
- **到底的硬签名是“力卸载”**: 顶到 56.1N 后只松 0.49mm, |F| 立刻回到自由段静载基准(24.1N) ⇒ 前端是硬止口;
  反之"松一点力仍大" = 摩擦/楔紧, 不是到底。**只靠位移量判到底会过头**（实测多推 3.2mm 才开始抬力矩）。
- 判到底后先松到无残余压力, 再 `record_point_sdk.py --record 插入到位_<口>` 存点（回读 6 帧极差）;
  台账里同时记: 顶上时 |F|/|T| 峰值、松开后的 |F|、自由段静载基准、深度（从哪个基准点算）。
- 同口复现用一步直插模式: 目标点(位置+quat) → 快走到 `点 − 沿轴 approach_mm` → 低速直插 → **到点误差 <0.35mm 判 reached**;
  全程被动看门狗（轴向 30N 停 / 红线压回、侧向 10N、力矩 3.5Nm）。
- **已经在接近点更深处就别再后退去“接近”**: 反向行程会拉卡扣/止口, 实测力矩 3.59Nm 直接停 ⇒ 跳过接近段只走插入段。
- 入止口后**拔出来是独立一步**, 判据只能用 Δ: 真正的保持力签名 = 退出段**侧向 Δ 单调涨**（实测 0.5→5.5→11.4→12.8→13.9N）+ 轴向 Δ 峰 25N。
- 🔴 **力矩绝对值不能当“楔紧/卡扣”证据**: 长力臂姿态下同一台臂的 `ty` 会在 −0.7 ~ −9.1Nm 之间漂,
  那**只是自载重力力矩**（自载约 24N × 力臂约 0.3m）; 把它当接触力会得出完全相反的结论（我据此误判过一次“有卡扣保持力”）。
  力矩只看 Δ(相对**同姿态**静止基线), 每发推进前重取一次基线。
- 退出别硬拔: 先按现场许可把阈值一次性放开（实测 侧向 20N / 力矩 8Nm）, **沿轴直退 3mm、不加任何横动**（横动才划侧壁）,
  判据 = 退完 |F| 回到自由段静载基准（实测 15.1N vs 基准 15.2N）= 已从止口解出; 一次走完, 不要半步来回磨。
  - **退出验收量化到三个数**(每段后核): ①侧向漂移 ≤0.10mm(证明是纯轴向, 没斜着拔) ②姿态变化 ≤0.01rad
    ③单段 |ΔF| ≤8N(挂住/带转/异常阻力立即停)。现成原语 `tools/rokae/axial_retract.py`
    (只沿 −工具Z、rpy 锁定、每段 2mm@1.5mm/s、无前进分支), 实测退 10mm/五段侧漂均 0.001mm、转角 0.0000rad。
- 现场要“看着力插入”时, 把六维力接到信号分析窗口（管道见 `references/force-control-api-map.md` 只读侧）。
  ⚠️ 波形“总是断开”先查总线节流, 不要怀疑信号源: `ar_aoi_bus.py watch` 的 sleep 下限写死 0.5s、
  且每轮 `take(timeout=0.30)` 阻塞 ⇒ 总线上限只有 2Hz（实测 0.5Hz）; 窗口按 20Hz 轮询文件 ⇒ 必然断成点。
  修法: sleep 下限 0.05s + 慢源(DDS)降频 1s 抓一次并用缓存 + 二次起超时 0.02s + 原子写 tmp 文件名按 pid 唯一。
  修完实测 6.3Hz（间隔中位 166ms）波形连续。

## 已知阻塞路径(遇到别再试第二遍)
- 力控服务不在图上 → 只剩两条路: ①现场起驱动，②用 SDK 原语自己实现插入(见 `references/force-control-api-map.md`)。
  走 ② 时**不要进力控模式**(硬接触必然 41451 下电), 按 §5 的位置推 + 被动看门狗做;
  已验证到"插到底 → 存到底点位 → 一步直插复现"这条链路。
- **运动会话同一时刻只能有一条, 只读采样可以并存**: 实测 10Hz 力采样器 + 位姿真值采样器 + 一次位置推同时跑,
  `n_err=0`、真值不断。会踩的不是会话数, 而是**两条运动指令叠在未知接触状态上**。
