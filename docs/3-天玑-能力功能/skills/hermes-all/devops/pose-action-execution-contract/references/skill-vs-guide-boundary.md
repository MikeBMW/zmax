# 技能 vs 引导：谁给目标、谁给包络

「按拉环朝向自动翻转 180° 再放料」这类需求，先分两件事，再决定写在哪：

| 问题 | 归属 | 产出 |
|---|---|---|
| 要不要翻（拉环朝向 vs 目标朝向） | L3 调度/技能选择 + 感知给的朝向 | 选中哪个能力 |
| 翻完的目标 6D 位姿 | 引导层（唯一目标位姿的产出口） | `target_pose`（姿态旋转 + 可行域判定） |
| 分段、每拍多少角度、先抬多高 | 技能/规划层（包络） | 段表 / action |
| 放料动作本身 | 放料技能 + 力/势场收口 | 执行 |

**不要新加一个「翻转节点」**：那会出现第二个产目标位姿的地方，与「一个周期只认一个目标」冲突，规划每拍换目标 ⇒ 半路掉头。

## 新增「按需技能」的四处落地（缺一即死）

1. 技能类（`atomic_skills.py`）：继承共用的限幅基类，只写 `code/stage/name/desc/goal/params/evidence/ctrl/TARGET` + 本段常量。
2. 物理真源（`config/calib/zmax_skill_physics.json` 的 `stages[段名]`）：每项 `{value,min,max,unit,src}`；
   缺这项则 `limits_for` 回 `unknown_stage=1` 并**静默套用别的段的惯性/力**（看不见的降级）。
3. 映射：`skills` 列表 + `skill_code2stage` 各加一条。
4. 注册：`SKILLS_ONDEMAND`，再用 `setdefault` 挂进 `SKILL_BY_CODE` / `SKILL_BY_STAGE`。

**绝不塞进主链技能表**：那是状态机阶段序，`DONE_IDX`、回退窗口都按阶段数算，
插一段不会报错，只会让推进判据与回退阈值整体错位。

## 触发用判据，不用序号

`needs_flip(yaw_now, yaw_target, tol)` 这种纯函数：一致 ⇒ 不翻；相反(±tol) ⇒ 翻 180°；偏 ~90° ⇒ **不硬翻**（翻了更错），
显式返回「交 L3 重选技能」。`auto_call()` 未命中也要说清「为什么不做」，不要静默返回空。

## 姿态类技能的包络形状

① 先抬净空（槽内直接转必扫料盘，默认 30mm）② 按每拍角度上限分段（180° → 36 拍）③ 末步回落原位 ④ 放料仍交放料段。

真源里通常只有平移量（v/a/s/s_step），姿态上限（角速度、每拍角度）要么作为额外项写进真源，要么写在类里并标注
「不是标定值」——不许让它看起来像标定过的。

## 自检（全零运动）

- `limits_for(段).unknown_stage == 0`；`clamp` 削速真生效（如 1.0 m/s → v_cap，`why=速度`）。
- 计划满足：先抬 ≥ 净空、每拍 ≤ 上限、累计角度正好、末步回落。
- 主链技能表**未被改动**（打印 code 列表对照）。
- 若 `clamp` 回 `corridor: {error: 无通道真源}`，说明该段还没有几何包络 —— 如实报「待现场标定」，不要当通过。
