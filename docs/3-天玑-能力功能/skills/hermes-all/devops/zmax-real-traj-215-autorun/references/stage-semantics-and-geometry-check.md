# 插拔工艺: 阶段语义与段名核验

## 动作顺序(按现场确认, 不可按直觉重排)

```
抓取(合爪) → 过渡/举升 → 扫码(对码)
→ 抓取光模块 → 举升/转运
→ 插入孔内 → 松开夹爪(模块留在孔里)
   ↳ 期间模块在孔内通电 FW Loading 刷写程序 (并行工艺时间, 不占机械臂帧)
→ 夹爪回来抓拉环 → 解锁 → 拽出光模块
→ 扫码(举高段) → 金手指检测 → 表面检测 → 下放入盘 → 松开分拣 → 回位
```

要点:

- **FW Loading 不占帧**。它是插入后模块留孔、机械臂退开期间的墙钟时间。算 UPH 时必须计入单件节拍 —— 只按轨迹时长算会虚高。
- **"拔出"是两个动作**: 拉环是光模块的机械锁扣, 先解锁(拉环)再沿孔轴拽出。不能简化成"沿轴拔 47mm"。
- 拽出时 Z 应与插到位几乎相等(实测差 <1mm) ⇒ 严格水平沿孔轴退。斜拉会伤金手指和卡扣。

## 段名必须用几何核验, 不靠直觉

判据: 取该帧 TCP, 与孔位真值比。孔位口径是沿 +x 从下口到插到位约 47mm, y/z 基本不变。

- `TCP.x` 落在 [下口, 插到位] 之间 ⇒ 该段在**孔内** = 插入/拽出, 不是"转运"
- `TCP.z` 比插到位高 30mm 量级、且 `x` 已过插到位 ⇒ 已退开停在孔上方, 那只可能是"回来抓环"

反例(踩过): 把 20–40 标成"插入孔内"、91–113 标成"拔出模块", 实跑完全相反 —— 真机游标 95 的 TCP X776.2 正落在孔内, 说明 91–113 才是插入段。

## 节拍面板不能按仿真时间空转

按 `simT % cycle_s` 循环取当前元任务 = 面板跑在真机前面: 真机还在插入, 面板已经显示下一步。
修法: 有真机游标时**按游标映射阶段**(游标落在哪段就是哪个元任务), 仿真时间轴只做无游标时的兜底。这属于"显示与真机不符", 不是显示 bug, 是判据错。

## 语义改动要三处同步

段表同时存在于:

- 真机执行器 `tools/rokae/arm_step_traj.py`(`GANTRY_SEGS`)
- 元任务/甘特 `tools/ss_meta_task_ar.py`(`_REPLAY_SEGS`)
- 派生统计 `tools/replay_derive.py`(`SEGS`)

只改一处会让"日志段名 / 甘特 / 派生统计"自相矛盾。改完重跑生成器, 并用计数核验: 旧名出现 0 次、新名在场。

## 历史值 ≠ 运行时值

`/api/arm/step_traj/status` 的 `steps[].seg` 是**上次跑批时记下的历史值**, 段表改完要等下一轮跑批才更新。看到旧名不要以为改动没生效 —— 先分清运行时值和历史日志值, 再判断要不要重生。
