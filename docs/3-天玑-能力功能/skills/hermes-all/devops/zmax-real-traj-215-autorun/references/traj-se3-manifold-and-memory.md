# 回放轨迹的流形结构: 哪一层管什么(带实测数)

用户在推进「四元数预测 → 方向牵引 → 状态抑制速度 → 位置下发」这条策略时, 会反复问
「这是什么流形 / 能不能一一对应 / 模块位姿怎么搞」。答案有固定骨架, 照下面答, 不要现场推。

## 1. 结论表: 每样东西归哪一层

```
位置      ℝ³          平的, 3 DOF —— 不要映到球上(见 §2)
姿态      S³          单位四元数; SO(3)=S³/{±1} 二重覆盖
  └ 轴    S²          Hopf 底空间: 笔尖朝哪(2 DOF)
  └ 滚转  S¹          Hopf 纤维: 笔自转多少(1 DOF)
速度      TQ / TSE(3) Q=T⁶, (q,q̇) 12 维; 笛卡尔伺服用 twist ξ=g⁻¹ġ
相位      S¹          沿固定路走到第几成; 速度抑制就作用在这
```

- `SE(3)` 本身是 **ℝ³ 上的 SO(3) 主标架丛**(位置作底、姿态作纤维, 且平凡 ⇒ 可全局写 `g=(p,R)`)。
- **别把位姿说成切丛**: 切丛的纤维是切向量(速度); 固定轨迹上每点切空间只有 1 维(切向), 装不下 6 维位姿。
- 一一对应的对象是三元组 `(s ∈ S¹, g ∈ SE(3), q ∈ T⁶, branch)`; 单看任何一个都不完整。

## 2. 位置不要映到 S³ —— 会造出假曲率

立体投影/归一化到单位球的度量因子是 `4/(1+r²)²`: 中心 4、边缘 1 ⇒ 同一段路在不同半径被拉伸 1~4 倍。
实测工作空间包围盒 `636×922×884 mm`、绕几何中心半径中位 `300 mm`、最大 `775 mm` ⇒ 硬映射后所有阈值
(曲率、管半径、抑制曲线)都得重标定且失去物理意义。位置留在 ℝ³; 唯一好处「紧、无边界」这里用不上(边界在关节限位侧)。

## 3. 姿态本来就在 S³ 上 —— 已经是既成事实

- 215 帧四元数范数 `0.999999~1.000001` ⇒ 天生躺在单位 S³ 上。
- 相邻帧四元数弦长中位 `0.02378` = `2sin(θ/4)`, 与实测姿态转角 `2.532°` 吻合 ⇒ 所谓「转角通道」就是 S³ 上的弦长。
- 相邻帧弦长/测地距离 **就是** 姿态的度量; 不要另造欧拉角距离。

## 4. Hopf 拆分: S³ → S²(轴) + S¹(滚转)

```python
# q 的存储顺序是 (x, y, z, w) —— 末位才是标量
x, y, z, w = q
n  = ( 2*(x*z + w*y), 2*(y*z - w*x), w*w + z*z - x*x - y*y )   # 轴, |n|=1 ⇒ S²
phi = 2*atan2(z, w)                                            # 绕 n 的滚转 ⇒ S¹
# 等价: n = q·k·q̄ 的虚部(右乘 e^{iθk} 只改滚转, 轴不动)
```
🔴 **分量为顺序必须以数据为准, 不能凭习惯**: `real_traj_joints.json` 存的是 `(x,y,z,w)`。
按 `(w,x,y,z)` 读会得到**另一个四元数** —— 算出的 n/φ 仍然单位化、仍在球面上, 所以不报错, 只是轴/滚转整体错位
(实测同一姿态: 正确 `n≈[0.970,−0.162,−0.180] φ≈149.7°` vs 错位 `n=[0.970,0.091,0.225] φ=24.7°`)。
判据: 拿录制 `frames[0].q=(0.7616,0.0730,0.6220,0.1667)` 与真机 `tcp_out/latest.json` 同一姿态的
`(qx,qy,qz,qw)=(0.7635,0.0750,0.6193,0.1672)` 逐位对一次, 对应上就确认了末位是 w。
消费端两处同步: `tools/se3_hopf.py` 与 `arm_step_traj.py::_hopf`; 看板 C 面板同理取 `q[0:3]` 作虚部、`q[3]` 作实部。
自检(必须过): `|n|-1 < 1e-9`; 右乘 `e^{iθk}` 后轴变化 ≈`1e-16`; 公式值与 `q·k·q̄` 虚部差 `0`。
(以上自检只能证公式自洽, **证不了分量顺序** —— 顺序只能用两个独立来源比。)

实测拆分(215 帧逐帧, 按 `(x,y,z,w)`):
```
轴步长  中位 1.98° · P95 9.38° · max 17.42°(#183)
滚转步长 中位 1.53° · P95 18.99° · max −25.89°/帧(#177)
总转角  中位 2.53° · P95 14.66°
插入段 #20~#39    轴均值 0.24°/帧   ← 准静态
插入中 #95~#112   轴均值 0.17°/帧   ← 准静态
放件   #205        轴均值 4.49°/帧   ← 全轨迹最大
```
- 插入期间姿态**准静态**(轴与滚转都在 0.2°/帧量级) ⇒ 轴是**常量约束**, 不是跟踪量: 一旦偏 3° 立刻可判; 滚转接近 0 ⇒ **roll 不该进插入控制回路**, 只在末端对位那一刻用。
- 轴对齐纠偏 = 在 `S²` 上走大圆回孔轴(测地线); 与滚转的阈值必须分开给, 否则「轴偏 3°」和「滚转 3°」被同一个阈值卡死。

## 5. 速度放 TQ, 相位放 S¹ —— 速度抑制的严格写法

```
q̇ = α(s) · q'(s) · ṡ_ref        α(s) ∈ (0,1]: 状态给的抑制因子
ṡ  = v(σ)/L                     相位推进率(L = 总弧长)
```
几何 `q'(s)` 一点不动, 只有切向量的**长度**被调制 ⇒ 「曲线固定, 重新参数化」。
这就是 flow 档(常规 100 / 操作区 60 / 断层 70)在做的事在数学上的样子。

## 6. 为什么 SE(3) 不能一一标识回放点(判游标别用最近点)

- 自交: 相隔 ≥6 帧的帧对里, 关节差 `<1°` 有 **22 对**、`<0.5°` 16 对、`<0.1°` 6 对, 最小 **0.0020°**
  (`#36 vs #108`, 平移差 0.0mm); `<6°` 还有 159 对(0.72%) ⇒ 同一物理位形被走两次, 任何位姿/位形空间都分不开。
- 相位不在像里: SE(3) 的像丢掉速率与时间, 而速度抑制正作用在相位上。
- IK 多解: `Q → SE(3)` 非单射(肘翻/腕奇异) ⇒ 只记位姿无法唯一下发关节。
- 首末缝: 平移 `3.91 mm`、关节 `1.20°`、姿态 `0.64°` ⇒ 近似闭环 ⇒ 拓扑上是 `S¹` 带一道缝; 要么插缝合点闭合,
  要么显式标 seam 并**禁止在 seam 附近线性插值**(会瞬移 3.9mm)。
- 绕行方向用环绕差 `Δs = ((s₂−s₁+0.5) mod 1) − 0.5`, 别用线性减法(过缝会给反向 0.93 圈的错方向)。

## 7. 记忆层缺口: 只有绝对 SE(3), 没有相对 SE(3)

已有什么: `taught_points.json` 69 个示教点(`pos/quat/abc`, 47 条带 `spread_pos_m/spread_quat`, 例 `2.1e-07 m`) ·
`taught_paths.json` · `place_cells.json` · `muscle_memory.json`(键形如 `104|接近` `104|抓取` `104|插入`)。

🔴 **全仓 `grep T_tool / rel_pose / grasp_offset data/skills/` 为空** ⇒ 记忆里存的全是「臂在世界系该到哪」,
没有「工件相对工具在哪」。后果: 料盘/模块一挪, 整层记忆静默失效(它只会准确地重复旧位姿)。
实测例: `#9` 合爪帧 `649.2/252.7/114.9` vs 最近示教槽 `slot6` `647.4/255.9/110.1` 差 **6.1 mm**(次近 47.4mm);
这 6.1mm 会原样打在夹爪上, 而闭环里没有任何环节能发现。

补法(不重做架构, 只在示教条目上加一层):
```json
"rel": {"ref": "slot6", "T": "4x4 或 {dq,dt_mm}",
        "spread_t_mm": 0.004, "spread_r_deg": 0.02, "n_samples": 12}
# 命中时: g_target = g_ref_now · rel.T      ← 对象挪了, 目标自动跟着挪
```
只给能对到对象的点标 `rel`(slot1~7、金手指点1/2、aoi_gold_view), 其余保持绝对。

## 8. 模块位姿这一半要分清职责(别用模块位姿定姿态方向)

- 抓取姿态由**夹爪与模块长轴的相对关系**定; 插入姿态由**孔轴**定。模块位姿只提供「在哪」与「绕孔轴转了几度」。
- 三步接法: ①感知模块位姿(8794 帧 + K + 手眼/固定外参, 或 foundationpose 话题; 门槛 ≤1mm/≤1°)
  ②存常量 `T_tool←module = g_tool⁻¹·g_module`(示教时算一次) ③合成 `g_grasp* = g_module_now · T_tool←module`。
- 只在关键点启用(#9 合爪 · #20~#40 插入起点 · #91~#113 · #205 放件), 其余段仍走录制几何 ⇒ 录制路径 + 感知纠偏的混合。
- 精度不够(6mm 级)时, 纠偏比不纠偏更差 —— 先量再开。

## 9. 回答口径(他会追问到底)

- 先**形象**一句(笔尖方向 + 笔自转 / 跑道里程牌 / 车速表), 再**专业**给公式 + 实测数。他明确要求过「形象解释, 再专业解释」。
- 被问「你现在怎么实现的」时**主动报缺口**: 哪一半是复现、哪一半没接(例: 方向来自录制关节角, 不是预测; 模块位姿完全没用)。
  别把「几何复现 + 状态调速」说成「位姿预测 + 视觉伺服」。
- 报过的数要能被复核: 每个结论附一条可跑的 python 片段(自交统计/闭合差/轴-滚转拆分/Hopf 自检), 别只给形容词。
