# 删控件 / 收敛界面的定式（自绘 8797 / ar3d 类页面）

现场口中的「太复杂了」「删掉 X」「就一个 Y」不是风格建议，是验收条件：他会在下一句继续点名剩下的控件。
一次做干净，别留尾巴让他催第二遍。

## 删之前先分类（三类，只有第一类该动 DOM）

1. **纯 UI 控件** —— 按钮、提示 span、输入框：连提示文字一起删。不要只删 `<button>` 而留下
   「mm/s」「(默认)」「选档后点…」这类旁注（实测删了 5/10/50 三个速度按钮、留下单位和提示行，下一句就是「还有」）。
2. **下发用的常量/变量** —— 删按钮 ≠ 删口径。保留 `SPD_MM_S`（默认 10mm/s）、`TRAJ_SPEED_MODE`（默认 real）这类
   常量，让「▶ 执行轨迹」照旧按默认值下发；只把读写该组 DOM 的初始化函数改成空实现。
3. **被多处旧逻辑读取的元素** —— 不删元素本身（实测 `cSyncArm` 有 5 处读它），改 `style.display='none'` +
   `checked` 恒为真，语义退化成「永远真机也走」，旧逻辑一行不改。

删完 `grep` 一遍被删 id 的**全部**引用，把残留的 `document.querySelectorAll('#<容器> .cls')` 改成空实现
（选择器命中 0 个元素不报错，但以后会让人误以为那组控件还在）。

## 三步自检（缺一步就在现场露馅）

1. `node --check`：把页面里所有 `<script>` 抽出来拼接再 check；**过滤掉 `type="application/json"` 的数据块**
   （轨迹帧 `rtrajData` 那种），否则语法检查会在数据上失败、误判自己改坏了。
2. 浏览器加载后读 console：`js_errors` 必须为 0 —— 删控件最容易留下 `Cannot read properties of null`，
   而页面照常渲染，只有 console 说实话。
   另外：用 `patch` 把 `} else if (cond) { … }` 整段换掉时，模糊匹配可能把前一行的 `}` 一起吃进去，
   `node --check` 报的是「unexpected token else」—— 看到这个报错先数一层大括号，补回 `}` 再 check，
   不要去改逻辑。
3. 读回 DOM：被删 id 全为 `null`；保留的按钮文案/位置符合他点名要的形态。

## 按钮行为验证：用 `.click()`，不要按坐标点

canvas 重页面上按坐标点击可能落空（元素在、可点、事件不触发）。在控制台里
`document.getElementById('<id>').click()` 直接走 handler，再读回页面内部状态（如 `RTRAJ.fi`、状态行文本）
与服务端 `GET /api/.../status` 三样对账 —— 这是判「按钮本身好不好」的唯一可信口径。

## 显示类改动：真机路径也要写一遍

点号/进度/光标这类显示，历史上只有「单步」和仿真回放那条路径会写 ⇒ 真机跑批时永远是「#— · 未开始」，
用户会连着两次问「光标怎么不动」。定式：

- 抽一个 `paintXxx(state)`，输入只依赖 `/status`；跑批中写 `start+done`（**不是** `cursor`，它只在整轮结束才推进），
  停着写 `cursor-1`，并带上 TCP。
- 挂到**所有**轮询点：页面级 2s 轮询 + 跑批自己的 900ms 轮询各调一次（漏一处就有一段时间不刷新）。
- 轮询本身要 `fetch().then(paint)` —— 只取数不重画等于没改。

### 一个页面里的"光标"往往有三份实现, 一次全接上
用户说「光标还是没有」时，他可能看的是另一处，而这一处真的是空的；只修他上一句提到的那一处，就会再来一轮。
实测一个页面上就有三份独立实现：顶部游标文字(`#tSyncStep`)、三维区点号(`#tTrajStep`/`#rpStepId`)、
MT 甘特条上的竖线游标(`#rpGanttCur` + 标签 `#rpGanttLbl`)。定式：**一个 `paintCursor(state)` 喂全部三处**，
不要让某一处继续只由「单步/仿真回放」那条路径写。

### 光标"在但看不见"也是 bug
甘特竖线那种元素光改定位不够：2px 白线贴在深色条上等于没有，且无数据时整块 `display:none` 就等于「光标不见了」。
交付形态：3px 宽 + 发光(`box-shadow`) + 标签直接写 `#N/<total> · <t>s · <段名>`；
没拿到游标值时**默认画在 0 点**，不隐藏。验证不要只看 DOM 存在：读
`getBoundingClientRect()` 的宽高与坐标 + `style.display` + 标签文本，才算看见。

## 状态机别等不存在的字段

前端清轮询的条件必须落在服务端**真的会返回**的字段上（`running=false` + `step.ok` + `why`），
不要等 `finished`/`ok_all` 这类只有某些版本才有的字段 —— 那个字段永不出现时轮询永不清，
之后每次点按钮都只说「正在跑」，现场原话是「怎么卡住了」。再补一道防线：点按钮前先 `GET /status`，
服务端没在跑就清掉旧轮询重发。
