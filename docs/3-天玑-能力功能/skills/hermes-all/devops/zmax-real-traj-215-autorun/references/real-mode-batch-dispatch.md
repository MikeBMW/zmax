# 真实档（整块下发）回放：速度模型、分块与超时

名字叫「真实/原始速度」，但**到不了录制时间轴**。对用户的预期必须先说清，否则他按秒表算你会被当成骗人。

## 实测速度模型（215 点 / 录制 42.85s / 路径 7861.8mm）

| 档位 | 下发方式 | 实测 | 整轮 |
|---|---|---|---|
| x1（speed=20） | 逐点 | 6.1 s/点 | ~21 min |
| x2（speed=40） | 逐点 | 4.0 s/点 | ~14 min |
| 真实（speed_mode=real） | 整块一次 append+moveStart | **1.66 s/点** | ~6 min |

- 逐点慢的真因不是 speed：`t ≈ 1.8 + 82/speed`（秒/点），每点约 1.8s 固定开销，调 speed 只有 1.5~1.6 倍。
- 整块下发快 2.4 倍，但控制器仍**逐点到位后**才进下一条，所以 42.85s 那个名义值只在连续插补下成立 —— 别承诺秒级完成。

## 分块规则（三条都必须满足，否则现场停）

1. 停留点（夹爪合/开、AOI 检测位）**必须作为块的最后一个点**，不能当中间点跳过 —— 夹爪/AOI 动作靠"到点后执行"。
2. 大跨步（相邻点最大关节差 > 20°）**单独收尾成块**，不要并进 12 点的块里。实测把 31° 那个点并进块里 ⇒ 整块超时、误差 27.7°、半路停。
3. 块大小 ~10~12 点；块越大，一个卡点吃掉的预算越多。

## 超时预算（不要用 rec_dt 的倍数）

```
tmo = max(40.0, n_pts*2.5 + rec_dt*2.0, jmax*0.8 + 20.0)   # jmax = 本块最大关节跳变(度)
```

用 `max(20, rec_dt*4+8)` 这种按录制时间算的预算在真机上必然假超时（录制 2.2s 的块要跑 16s+）。
第一块（点 0~9）实测 16.5s 到位、误差 0.09° —— 可以拿这个当健康基准。

## 失败时的现场状态

- 超时即停、**不重发**（现场安全优先）；日志要落 `err_deg` / 目标关节角 / 实际到位点，否则没法判断臂停在哪。
- 停在半路（本例停在 763/61/263mm，离起点 665/-27/297 约 100mm）后：**回起点的判据是关节角，不是 TCP**。
  TCP 对上到 6mm 内，第一块仍可能被 40° 跳变闸拒；要稳就让用户摆臂时连末端姿态一起对回起点关节角，
  或先点一次「单步 +1 点」（固定 x1 慢速，约 6s）把臂温柔带回 #1。
