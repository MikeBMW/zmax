# 协同架构：机内双臂 / 机间多机

## When to Use

- 老倪问「这个功能应该是哪个节点」（双臂/多机/分力/上下料调度）
- 要落双臂成对位姿、机间派发/占位/互锁，或把工作量摊到主机/从机
- 写这两类功能的 PPT 前定口径（机内 vs 机间不能混成一页话）

画 8797 页面的具体坑（左臂 IK 种子、引导框画法、黑底文字条）见 `zmax-ar-traj-8797` 的 `references/dual-arm-guide-and-overlay.md`。

## 一句话分界（先分清再动手）

- **双臂协同** = 一台机器人两条臂、同一物理工作空间、同一组任务 → **引导层**，一周期一对 (L,R)。
- **多机协同** = 两台以上独立设备/机器人系统、跨空间、为产线物料流转（上下料）做**联合调度** → L3 调度层，管任务/资源/时间窗，不产位姿。

把多机塞进几何节点、或把双臂抬到调度层，都会立刻出现「谁在管什么」说不清。

## 落点

- 双臂：测地线引导节点扩端口——`out1` 右臂（带 `pair_id` / `arm` / `hold` / `dual_truth`）、`out3` 左臂、`out4` 协同证据；发布走 `tools/publish_target_pair.py`。
- 多机：新建调度节点，夹在任务来源（段表 / MES 物料单 / 节拍预算）与每台机各自的「技能序列→限幅→执行」之间。
  - 不放几何引导节点（只出单机位姿）、不放单臂规划（跨不了设备）、不放节拍器（只算预算没握手互锁）、不放限幅/执行节点（单机授权收口，不知道第二台机存在）。
- 分力：放在力场节点，但**机份额与层份额分维相乘** `F_(i,l)=α_i·s_l·K·ξᵉ`，两层各自 Σ=1。共用同一份额向量会把同一个 0.30 说成两个意思。

## 判据（每条能现算，不靠形容词）

- 机内：同 tick / 同 ts / 同 `pair_id`；一侧取不到几何 ⇒ 整对 `pair_valid=false`（atomic，不许单飞）。
- 机间：同一取放位唯一 owner + lease TTL，过期回收并记账；跨设备**不用「同拍」**，用时间窗+租约（通信有延迟）；心跳超时 ⇒ 任务回退重派发，且下游不许用过期真值；派单原子 + `task_id` 去重。
- 能量：主机、从机各算一份 `H_i=K_i+U_i`（同一套 K 矩阵），不共用一份数。
- 主机工作量**有数**（计划值）；从机只补缺口 `α_s=(P*−P_实际)/(P+P_s)`；从机能力不足就报 `saturated + shortfall`，**不许把份额抬到保底值**——那会把干不完的量说小。
- 数学闸：`Σ_iΣ_l F − Kξᵉ` 残差 <1e-12；`Σα=1`、`Σ_l s_l=1` <1e-9；α 每拍变化率限幅防抖；分力后逐机 `ΣF_i·ξ̇_i ≤ 0`，不许把系统变主动。

## 现在缺什么（别当已落地汇报）

- 只有一条臂末端真值；第二台/左臂要有旁路真值文件（`zmax_data/ss_live/left_arm_pose.json` 或环境变量指过去）才有 dual truth，否则只能标 `hold=true` 做几何引导。
- 调度节点、力场节点的机份额端口、画布连线、真机双机联跑都还没做；算法层自检（`python -m lerobot.manifold.multi_machine_energy --selftest`）只证明数学与份额恒等式。

## 运行时坑

- 节点加了端口不等于上线：运行时只发**画布连了线**的端口，没连线就是算出来没人收。
- 常驻引擎循环进程改代码后不重启仍跑旧逻辑；重启要指名，别自己动。
