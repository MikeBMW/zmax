# 把"画布外的东西"接进节点: 端口/状态文件/校验口径

适用: 训练/重建/外部服务产出的状态要在画布上可见可追溯, 但不参与 43D 状态向量
(参与就要改所有模型输入维度与 checkpoint —— 那是另一个工程)。

## 四件套: 真源文件 + 常驻刷新 + 只读接口 + 节点输出端口

1. **真源文件一处**: `zmax_data/<area>/<x>_live.json`, 由采集器写; 节点/页面/接口都只读它,
   不各自算一遍 (各自算 = 数字对不上, 而且没人知道哪个是真的)。字段带 `stage`(采集中/训练中/已就绪)
   + `age_s`/`log_age_s`, 让"停了多久"可判。
2. **常驻刷新**: systemd oneshot 环 (30s) 或 `--watch`, 写 history.jsonl 逐轮追加。
3. **只读接口**: 在已经对外的服务上加路由 (例 `/api/gs/recon`), 不要另起端口/另起服务。
4. **节点端口**: 给硬件节点加 `outN` + 一条连到下游 `obs.inK`, 并把真源/生成脚本/服务/接口
   四个锚点写进端口 `params` —— 后人反查不用问人。

## 🔴 校验口径: 存量噪声大, 只判"新增"

这个画布本来就有 ~110 条"端口未声明"(GUI 按连线动态生成端口, 是容忍的)。所以:
- **改前先备份** `flows/state_space_obs.json.bak_<purpose>_<ts>`;
- 校验器**同时跑基线与新文件**, 输出 `存量问题 N 条 / 新增问题 M 条`, 判据只看 **M==0**;
- 拿全量校验的"N>0"当失败 = 永远过不了, 然后就开始绕校验 —— 这是把自己逼到造假的路。
- 自检还要断言: 新端口/新连线 id 唯一、连线两端节点存在、新端口确实挂在目标节点的 outputs 里。

## 硬断言写进校验器(缺一不可)
- JSON 可解析; 节点/连线 id 无重复;
- 新连线 `src.outK → dst.inJ` 双向对得上(源有 outK, 目标有 inJ);
- 新旧差集里**只有**本次预期的增删。

## 改动生效口径
- 画布 GUI 读的是 `_flows_path()` 返回的 `flows/state_space_obs.json`(仓库根下), 不是
  `data/database/zmax/sources/canvas/...` 那份导出副本 —— 改错文件会出现"改完没变化"。
- 不要重启 GUI 让它重载; 让用户在界面上重新打开/刷新画布。
