# 手眼矩阵的读数陷阱（Z-MAX 真机实测）

## 1. 单位是米，不是毫米

`models/handeye_state.json` 里 `T_cam2tool` 的**平移项是米**（0.2147），而同一个文件的
`t_mm` 字段是毫米（214.73）。直接拿矩阵当毫米用，投影出来的点会贴着光心。

```python
T = np.array(he["T_cam2tool"], float)
if np.linalg.norm(T[:3, 3]) < 2.0:      # <2 说明单位是米
    T[:3, 3] *= 1000.0
```

## 2. 方向：矩阵存的是“相机在 tool 系下的位姿”

要把 tool 系的点画到相机画面里，必须取**逆**再用：

```python
Ti = np.linalg.inv(T)                    # tool → cam
P_cam = Ti[:3, :3] @ P_tool + Ti[:3, 3]
```

直接把 T 当 tool→cam 用，tool 原点会落在 **z=−0.1mm（相机背后）**，画面里根本画不出来。
判据：原点反算后 `z` 应为正且接近“相机到末端的真实距离”（本机 217.7mm）。

## 3. 相机装腕上 ⇒ tool 系的像素是常量

手眼不变、相机跟着 tool 走，所以 tool 系在画面里的像素位置**不随位姿变化**。
一次算好就能当常量用；每帧重算纯属浪费，也会抖动。

## 4. 手眼投影 vs 标注框中心：固定偏差要报出来

实测本机两者差 `11.5px`（@217mm ≈ 5mm，方向在画面竖直）。含义是“手眼解出来的原点”和
“视觉标注的中心”必有一方差了这个量。处理口径：

- 按现场定义（如“TCP = 光模块头顶中心”）把原点整体平移到标注点上，**姿态不变**；
- 平移量写进返回体（如 `align_shift_px`），别藏；
- 另留一个 `align=0` 的真值版接口，方便事后算账。

## 5. 校验：不要只看数字，要交叉一条独立链

同一支模块：手眼链说相机到 tool1 是 245mm，视觉按已知件宽反解说 159.2mm，差 86mm。
这种量级的差不可能来自残差（手眼残差 0.06mm），只能是“tool1 原点”和“TCP”定义不同。
遇到这种情况：**两路同时看同一个刚体**做交叉验证，别急着改其中一路。
