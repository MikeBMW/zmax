# 无手眼相机的 AR 叠加: 外参标定 → 投影 → 渲染 → 验收

## When to Use
- 用户要在**第三路固定相机**(笔记本内置 / USB / 电视顶摄)画面上叠 base 系 3D 内容:
  工具中心轨迹管道、3D 边界框、规划航路。
- 用户说「应用 VR/AR 技术把轨迹可视化出来」「要有明显的 3D 渲染, 能清晰感觉出已经走过的通道」。
- 某路相机**没有手眼外参**(也可能没有出厂内参), 但你要把 base 系的东西投到它的像素上。

## 第 0 步: 先判有没有现成外参, 不要重新标
- **只有做过手眼标定的那一路**(臂上 D405)可以直接投; 固定相机**没有**手眼, 通常也拿不到出厂 K(UVC)。
  臂上那套 `base→TCP→cam→px` 的链**不能顺过来用**。
- 没有外参时的选择顺序: ①现场标定(本技能) ②如实拒绝并说清缺哪一步。**不存在"先凑一个"**。
- 🔴 **有外参文件 ≠ 外参现在还对**。相机换型/重装/改支架后，旧矩阵照样能算出一个像素坐标 —— 只是全错。
  残差小(如 14 视角 0.06mm/0.0046°)只证明**当时那轮解算**干净，不证明相机还长在那个位置。
- **现成外参的有效性判据（必做，成本一分钟）**: 取一个**已知示教点**（槽中心/插入口），用它所在那帧的
  机器人位姿 + 待验外参投到真机画面，看落点：
  - 落在目标物体上（料盘/孔口）⇒ 可用；
  - 落在**空/暗区**（实测投影到亮度 7~14 的区域，而同帧料盘本体 145~157）⇒ 外参已失效，**全部投影结论作废**，
    不要拿它去出"哪个点位能看到什么"的表 —— 那种表会看起来很有道理然后误导人一个月。
- 外参失效时的正常收尾: 重标（棋盘/圆阵列/ArUco，≥8 个位姿各异的视角）或如实说"这条做不了"，并说清卡在哪。

### 投进画幅 ≠ 对上了: 三条自证判据 (命中率不是判据)
把已知 3D 点(槽心/插口)按"真位姿 + T_cam2tool + K"投上去，**只数有多少落在画幅内 = 假验收**：
实测 14 个料盘槽投出 **8/14 在画幅内**，看着"能用"，但沿投影所在的行做一维亮度自相关，
找不到与槽节距对应的峰 ⇒ 实际一个都没落在槽上。三条都过才算对上：
1. **周期纹理**: 沿投影行(列)取 ±4px 带宽的一维灰度，自相关在"节距的像素数"处要有峰(本例槽节距 ~150px)。
   全是 <0.15 的噪声峰 ⇒ 未对齐，**不许**继续出"第几槽有模块"的台账。
2. **边缘能量比**: 投影点邻域(±5px)的 Laplacian 均值 ÷ 全图均值应显著 >1(槽边是硬边)。
   实测零偏移只有 0.79 ⇒ 落在平滑区域。
3. **扫描出的偏移只能当线索**: 扫工具系平移(dx/dz 各几档)取边缘能量峰值，实测峰在 dz=−125mm(0.79→2.03)。
   这只说明"工具系口径差了一截"(本机 flange↔tool 差 251mm ≈ 2×125)，**不是修复** ——
   落盘前必须用 3~4 个真槽的人工像素点复算确认，再写 calib。
- 🔴 怀疑外参/手眼之前**先回第 1 步查 K 的像素尺度**: 臂上流 1280×720 而标定文件 640×480 时用 ×2，
  会让所有点整体偏 ~100px，与"外参坏了"完全同形(见 Pitfalls)。
- **没有视觉工具时先粗看画面**: `cv2.resize(g,(64,32),INTER_AREA)` 后按 `' .:-=+*#%@'` 映射打印 ASCII，
  能判断画面里有没有料盘、亮暗怎么分布，再谈对齐；别拿"画面里有东西"反推"槽位已对上"。

### 整组落在错误半幅 ⇒ 先查相机是否物理反转 180°(Rzπ)
投影点**都在画幅内但全挤在对角半幅**(实测 8 个槽在 v 122~324 的上半幅, 而料盘实际在左下), 而操作者又说过
"相机是反的/装翻了" ⇒ 这就是相机绕光轴转了 180°, 不是外参坏了:
- 修法: `T_cam2tool' = T_cam2tool @ Rz(π)`(Rz=diag(−1,−1,1)) 重投, 同一批点应整体挪到对角那一角。
- **必须先做这一步**: 不修 180°, 后面所有平移拟合都是在错的半幅里找最优 —— 自相关没峰、边缘能量扫描
  也会给出一个"最优偏移"假线索, 看着像精度问题, 实际是方向问题。
- 🔴 **「位姿数值与断电前一模一样」不等于位姿冻结**: 只要 `ts` 在刷新、且相机光轴方向变了
  (实测从朝天约 37° 变成指向料盘), 就是臂被摆过/仍在报实时值。判冻结只认 `ts` + 光轴/投影落点,
  不认数值眼不眼熟 —— 否则会把"相机装反"误诊成"位姿陈旧", 再白白等一轮通电。
- 汇报时把「视觉上能判有没有料盘」与「几何上能判第几槽」分开写; VLM 回 "tray=true, 两排约 6+6 槽"
  只支撑前者, 不能当几何证据。

## 第 1 步: 收集 3D↔2D 对应点 (人点优先, 别先去写自动标定)
- 🔴 **先拿 K 的像素尺度口径, 再谈外参**: 标定文件常是 4:3(640×480), 实拍流是 16:9(1280×720)。比值**不是 ×2** ——
  垂直等比 ×1.5、水平再加裁切偏移。实测 `K(1280×720) = fx 591.1, fy 590.2, cx 637.7(=318.44×1.5+160), cy 358.0(=238.66×1.5)`;
  错用 ×2 会让所有投影整体偏 ~100px, 而它和 "外参坏了" 长得一模一样。判据: 把已知插口点投上去,
  与画面里真实对象对不上就先查 K 的尺度, 不要先去重标外参。
- **外部视觉模型的框必须用几何投影验一次再采信**: VLM 给的框与已知点投影落点差 ≤ 框宽的 1/10 才算框可信
  (实测两插口投影落点与 VLM 框差 6px ≈ 3mm ⇒ 框可信但分辨率是厘米级, 只能粗定位)。
  VLM 的 bbox 还可能**超出画幅**(实测 y2=880 而图高 720) ⇒ 这种坐标一律只取"有/没有"的结论, 不取坐标。
  "模型说它看见了" + "几何算出来在那里" 两边对上, 才是证据。
- **主人点夹爪尖**: 臂停稳 → 在页面上点画面里的夹爪尖 → 同刻取 TCP 真值。6~8 下、40 秒就能完事,
  精度比任何自动方式高一截 ⇒ **先把这条做成按钮**, 自动配准是后续优化不是第一版。
- **停稳判据放服务端**: 采 1.2s TCP, 报 max 漂移 mm; 还在动就不收点(否则记脏数据), 页面显示原因。
- **要求空间散布**: 至少 6 点(线性初值需要 6), 且**高低/左右都要变**。落盘时同时报
  逐点误差 + 散布 σ + 三轴范围 —— 点全挤在一处等于没标, 数字一摆就看得出来。
- 自动化备选(散布更好但更重): 运动中的已知物(固定视角里"在动的那一个"做身份)
  × 臂上深度测得的同物 3D; 或臂上深度点云↔固定视角边缘配准。
- 🔴 **近似共面的静态特征解不出可靠外参**: 实测几个绿拉环在 base 系 z 只差 2cm 量级 ⇒
  3 点解 7 参欠定, 硬解能得到"投影对得上、沿视线深度全靠猜"的结果 ⇒ 管道贴歪。
  **用户拿这个画面调算法, 贴歪比不画更坏 ⇒ 不够 6 个散布点就如实不画。**

## 第 2 步: 解算器定式 = DLT 线性初值 + RQ 分解 + 非线性收细
```
① Hartley 归一化(3D/2D 各自) → ② 12 参投影矩阵 DLT(每对点 2 行, SVD 取最小奇异向量)
→ ③ 反归一化 P=inv(T2)@Pn@T3 → ④ 分解 cv2.RQDecomp3x3(P[:,:3]) 取 K,R, f=(K00+K11)/2, t=inv(K)@P[:,3]
→ ⑤ least_squares(method='trf', x_scale='jac') 收细 7 参 f+rvec+t, 主点固定图像中心
```
- 🔴 **只用"多起点 + LM"会收敛到退化解**: 自检实测 f 真值 520 解成 84.6、相机系 z=1.4e4 m、
  RMS 2.4e8 px —— 而且**通过了 `z>0` 的弱检查**(z 全是巨大的正数)。没有 DLT 初值就不要相信结果。
- 🔴 **自检相机必须物理合理**: 用 look-at 构造(`zc=normalize(tgt-C)`、`xc=normalize(cross([0,0,1],zc))`、
  `yc=cross(zc,xc)`、行=相机三轴、`t=-R@C`), 并断言所有点 z>0。第一版自检的"真值相机"把点放到了相机背后
  (z 全负) ⇒ DLT **精确拟合了垃圾**(误差 0.00px), 看着像"解算器完美"。修好后实测 f 误差 0.36%、RMS 0.46px。
- ⚠️ `cv2.RQDecomp3x3` 在该版本返回 **3 个值** `(retval,K,R)`, 写 `K,R=...` 直接 ValueError。
- 解算器**自带 `selftest()` 并把结果写进接口响应**(页面显示"解算器自检=通过"), 否则后人改坏参数没人发现。

## 第 3 步: 独立验收 (两条都不能省)
1. **与标定过程无关的判据**: 把 TCP 真值投到"运动中的手臂掩膜"(帧差法)上, 报命中样本/总样本
   + 到最近运动像素的距离。只有这条过了才敢说外参可用。
2. **两侧投影同口径**: 页面(JS)与后端(Python)各算同一点比最大差(实测 0.001px)。
   省掉这步的后果是"算得对、画得歪", 从日志上看不出来。

## 第 4 步: 渲染成"能感觉出的通道"(不是一条细线)
- 每段粗线 `lineWidth ∝ baseW·ref/z`(远的细+暗、近的粗+亮), 按深度**远的先画**
- 沿程渐变(按路径进度取色) + **中心亮线**(≈0.3×线宽)读出中轴
- 每 N 点画**截面椭圆环** ⇒ 立体管道感(纯粗线只是一条带)
- 起点/终点标记 + 当前 TCP 十字
- 固定视角上同时摊**实测轨迹**(暖色)与**规划航路**(冷色、更细更淡) ⇒ 直接看出规划与实走的差
- VR 侧(纯 3D 软件渲染, 不依赖 CDN): 台面网格 + 基座竖轴 + 同一管道 + 拖动旋转;
  **不需要标定 ⇒ 先给用户看它**, 别让"AR 要标定"把可看的东西卡住

## 第 5 步: 显示语义 (轨迹这类"会越攒越乱"的叠加)
- 轨迹**默认关**, 人工开启(用户明确要求时按他说的做)。
- 🔴 **只有"清除"一定会被当成数据丢失**: 清除类按钮必须同时给"全部历史"(把清除线归 0),
  状态条写"正在画 N 点 / 录制侧已录 M 点"。清除只影响画面、不动录制数据, 要在按钮说明里写明。

## 拿机械臂自己当靶标: 单特征 bundle 必需求退化判据, 否则"收敛了"也是假的

没有标记、没有标定板时的自然做法: 盯住工具上一个**刚性**特征(夹爪棱边/模块头上的贴纸), 机械臂走多个位姿,
用 "TCP 真值 + 常数偏移 v + 未知 f/c/R" 一起解。实测这套**会退化**:

```
观测: 18 条(9 位姿×2) · y±30 / z±30 / x 639→679 · 追踪 conf 0.93~1.00 · 同位姿重复帧像素极差 0.00px
解 A: f=1098.7  c=[505.7,−15.7,80.0]   RMS 1.46px 中位 0.58px
解 B: f=1098.7  c=[363.6,123.3,214.0]  RMS 也 1.46px      ← 同一批数据两组参数同样"好"
```

- **根因: f 与 距离在小于 ~100mm 的基线上不可分**(投影只约束 f/Z 之比 + 视线方向)。RMS 小 ≠ 解唯一。
- **唯一可信的破法: 已知 3D 锚点回投**. 把插口/槽口 6 点按解投上去: 解 B 全落在 u≈905(画面宽 640) ⇒ 当场作废。
  ⇒ **没有锚点验证之前不许写进标定文件、不许对用户说"标定完了"**。
- 剩余可**可信**的部分: 比例尺(实测 4.5px/mm)与相机大致方位(在两轴上的投影方向)。这两条足够用来回答
  "相机在臂的哪一侧"、"往哪边动会让目标进画面", 不够算毫米。
- **要真落地就走已知几何 PnP(DLT 初值, 见第 2 步)**: 6 个已知 3D 点 + 人工点像素, 2 分钟, 无退化 —— 比拉大基线追单特征稳。

### 没板、只有工件时: "逐槽摆放 + PnP" 的天花板在哪, 以及换成捆绑平差

现场常见受限条件: 无标定板、不愿贴板, 只有一个可挪的工件(如料盘里的光模块)。想把工件当靶标, 先看清三条硬约束:

- 🔴 **手工摆放本身有 ±5~10mm 不确定度, 它直接当残差报出来**。实测逐槽 4 点 PnP 残差 13.8 / 12.4 / 2.3 / 1.1 px,
  而且**相邻两槽(相距 46mm)误差方向相反** ⇒ 是摆放噪声, 不是模型偏差。
  判别口径: 残差**随机、逐点、与离轴角无关** ⇒ 摆放噪声; 残差**同向、随离轴角增大** ⇒ 相机模型(先查畸变/内参尺度/分辨率)。
- 🔴 **3 点 PnP 的残差必为 0.00px, 不能当精度**: 3×2 = 6 个方程正好等于 6 个未知量, 结构上必过拟合。
  报精度只能 "N 点拟合 + ≥1 点留出检验" 或 ≥4 点看 RMS。
- 🔴 **暗块掩膜在料盘里会吞掉槽壁/阴影**: 必须把 `minAreaRect` 的实测像素尺寸与 `fx·实物尺寸/Z` 对比。
  实测 blob 宽 67~100px 而理论只有 **23px**(350mm 处 18.35mm) ⇒ 差 3 倍, "中心"根本不是工件中心, 逐位姿差 3~10px。
  **差 >1.5 倍就弃用该掩膜**。斜视下工件顶面沿视线差 ~30mm 深 ⇒ **等深切片分割必碎**, 别用。

**正解: 工件放着别动, 臂走 N≥5 个位姿, 把外参和物点坐标一起解(捆绑平差)** — 摆放误差直接消失:
```
p_cam_i = R_x·(R_tiᵀ (P_base − s_ti)) + t_x
a同解: rotvec_x(3) + t_x(3) + P_base(3) = 9 未知 · 每位姿 2 方程 ⇒ N≥5 才有真残差
工具  tools/handeye_bundle.py --run / --draw
```
- 🔴 **平差必须多起点 + 有界, 否则发散到 1e5 mm**: 位姿间基线(几十 mm)远小于目标距离(~300mm),
  零旋转初值会被"无穷远点"近退化吸走(实测 t 解到 291611 / 268853 mm)。
  定式: 60~120 个随机起点(rotvec ~U(−π,π)) + `method='trf'` + 边界(t ±500mm, P_base 限在料盘范围)。
- **边界同时是体检**: 解参数撞边界(如 P_base.z 顶到上界 400mm 而工件实际 z≈118mm) ⇒ 输入不合格, 判废。
- **相机原点合理性是最快的废解闸门**: 解出的光心必须落在 TCP ± 250mm 内。实测两次废解:
  (782, 364, 452) 和 (512, 351, **−218**)(桌面下 218mm) —— 见到这类值立刻判废, **不要接着画图**。
- 🔴 **相机光轴与工具轴不重合 ⇒ 外参解出来之前拿不到"正对目标"的干净视角**: 把 TCP 摆到工件正上方俯视,
  画面里 0 个检出; 只有后退 + 斜视位姿才看得见料盘。⇒ 别反复试位姿(每轮几十秒, 还会误判成"相机坏了")。
- 像素反投影先 `cv2.undistortPoints` 再去乘深度 —— 但**别指望畸变救精度**: 本机去畸变只挪 2mm,
  主误差在掩膜和摆放。先修大的。
- **结论**: 工件当靶的天花板是 4~9px(≈3~7mm)。要 ≤3px 必须换打印靶标(ArUco 60~80mm / A4 棋盘)。
  拿不到靶标时, 交"3D 视图里的 tool1 坐标系(控制器真值)"并明确标注"相机叠加是趋势级、不是几何依据"。
- **靶标优先级(从高到低, 选之前先排这个序)**:
  ① **位姿已知的刚体** —— 工件夹在爪上时, 用户口径是"工件坐标系与 tool1 坐标系重合" ⇒ 它的位姿就是
     `/api/tcp` 给出的 `frames.tool1` 真值(0.1mm/0.05° 级), 手工摆放误差结构上消失; 相机看爪上的工件
     就是"位姿已知靶"。**这是没板时最该先试的一条**; 本次只走到"模块坐标系=工具坐标系"的口径确认,
     没有跑完闭环 ⇒ 别写成已验证。
  ② 机械固定基准(硬工装/已标定板) ③ 打印靶标(ArUco ≥60mm, 亚像素角点)
  ④ 手动摆放的工件 —— 只能取中心, 取不了尺寸/朝向, 天花板 4~9px。

### 轴探针: 用 ±40mm 的纯平移量出"相机在哪边"(零风险, 不需标定)
在**绝对包络内**(每轴 ±40mm、每站回基准、逐步核 |Δ|<1.5mm/姿态<1°/ΔF<25N)逐轴平移, 用模板匹配量像素位移:
```
实测: x+40 → Δu +128px(Δv≈0) · y−40 → Δu +133px · z+40 → Δv −177px(Δu≈3)
⇒ 相机视线 ≈ (0.74,0.66,0.10), 比例尺 ≈4.5px/mm @ ≈244mm, 相机在 −y 侧偏低
⇒ "+x 与 −y 都让目标往右走"这种非直觉结果, 只有在真实探过后才知道 —— 靠想象选方向就是撞相机
```
- 重复回到基准帧的像素位移必须 ~0.00px(=相机静止 + 臂回位准确), 这是数据可信的硬判据; 不回零就先查相机是否被碰过。
- 单帧追踪异常(某个轴的反向站低置信/跳变)必须**剔除后重解**: 实测含一个坏帧 RMS 29px, 剔掉后 1.46px。
- 被追踪特征在画面上**贴边/被切**时质心会被拉偏 ⇒ 先确认整块在画面内再采点(标签/二维码贴边最常见)。
- **QR/ArUco 贴边时基本解不出来**: `cv2.QRCodeDetector` 全图 1/2/3 倍 + 裁剪区 2~8 倍、`DICT_4X4/5X5/6X6/APRILTAG_36h11` 全族 0 命中。
  **要拿它做单点锚时, 先要三样东西**: 码的真实边长(或内容) + 4 个角在像素上的位置 + 它在 base 的 3D 位置;
  缺一个就写"定不了", 并向用户要"码多大/码里是什么"或"把相机凑近再拍一帧" —— 别在解不出的码上硬拟合偏移。
  VLM 可以给"有没有码 / 在哪一个九宫格 / 画面是否反"(实测这项一次就对), 但**它的 bbox 不能当几何输入**。
  标定**不需要码的内容, 只需要角点** ⇒ 改按"高对比方形轮廓 + 4 角"提点; 但代码块是**黑白模块**不是实心暗块,
  "阈值取最大暗块"会把它和周围金属壳/导轨黏在一起(实测高频区铺满全画面) ⇒ 别拿暗块当二维码。

## Pitfalls
| 坑 | 症状 | 修法 |
|---|---|---|
| 拿臂上那套投影去投固定相机 | 管道/框整体贴歪 | 固定相机没手眼 ⇒ 先标定(第 1~2 步), 标不出如实不画 |
| 只用多起点+LM 解外参 | 结果"看起来收敛"但相机系 z 上千米 | 先 DLT 线性解出 P 再分解做初值; 加自检闸门 |
| 自检相机把点放在相机背后 | 解算器误差 0.00px 的假完美 | 自检相机用 look-at 并断言所有点 z>0 |
| `cv2.RQDecomp3x3` 拆包 | ValueError: too many values | 它可能返回 `(retval,K,R)`, 按长度取 |
| 3 个近似共面点就想解 7 参 | 投影对得上、深度全靠猜 | ≥6 个空间散布点 + 报散布 σ/范围; 不够不落盘 |
| 只在日志里说"已验证" | 无法自证 | 报掩膜命中率 + JS/Python 同口径差 |
| 清除类按钮没配"全部历史" | 用户当历史丢了 | 配对反向按钮 + 状态条写清正在画多少点 |
| 自测用的假外参写完不删 | 系统里留下假标定 | 接口自测后立刻删掉 calib 文件并复核不存在 |
| 换分辨率后照搬旧像素常数 | 槽号/投影整体错位(实测 1280 宽标的 `槽=(940−x)/116.5+1` 用到 848 宽流上) | 所有 px↔物理常数按 `k=W/1280` 归一后使用(→623 / 77.2); 换分辨率后逐条重算, 不要只改内参 |
| 拿旧手眼矩阵出"可见性表" | 表头头是道，与实际画面无关 | 先用已知示教点投影验外参（第 0 步），落空区就作废重标 |
| 拿 3DGS/SfM 点云量尺寸 | 算出来有小数位但不可信 | 密度先算：点数/覆盖面积（实测 98k 点铺 1.4×1.8m ≈ 3mm 间距 ⇒ 量不出 4~60mm 的槽/料盘） |
| 拿 ×2 把 4:3 内参换成 16:9 | 所有投影整体偏 ~100px, 被误判成外参失效; 症状是"多数点仍在画幅内"却全不落在实物上(实测 14 槽中 8 个在画幅内、沿行无节距周期) | 垂直 ×1.5 + 水平加裁切偏移 (见第 1 步); 用已知点投影自查: 先做行向亮度自相关, 有节距峰才继续 |
| 在 VLM 给的大框里做自适应阈值取轮廓 | 前景占 45%, 最大轮廓退化成整个 ROI 边界 | 别把阈值轮廓当剪影: 用**帧差**拿到"真实动过"的像素, 或要求人工点 6 点 |
| 现场是 `op=drag`(人握着夹爪) 就开始采集 | 移动被拒 / 白走一圈 | 先读三态 `power/mode/op`, `drag` 或 `manual` 一律先停手请现场松开关回自动 |
| 单特征 + 小基线解出"收敛"就写标定文件 | 两组参数残差一样好, 其中一组把已知点投到画面外 (u≈905/宽640) | 一律用已知 3D 锚点回投验证; 落不进去就作废, 改走已知点 PnP |
| 拿"当前位姿"当探针起点 | 上一轮残留位姿 + 模板方向 ⇒ 直接朝障碍物走 (实测险撞相机) | 起点用显式绝对基准点; 每个目标先过绝对包络闸(见 real-arm-motion-control §脚本探针) |
| 读 PLY 写死 3 个 float | 读到全 NaN / NaN 坐标 | 按 header `property` 列表构 dtype（带颜色的点云是 x,y,z,r,g,b 六个属性，按 3 float 步长读会错位） |

## 页面侧的三个真坑 (渲染/调试)
- 🔴 **在 MJPEG `<img>` 的 `load` 回调里做布局会清画布**: Safari/部分内核对 multipart/x-mixed-replace 的
  `<img>` **每帧触发 load**, 而 `canvas.width=...` **赋同一个值也会清空画布**(实测 alpha 255→0) ⇒ 叠加层/VR 面板
  每帧清一次 = 屏幕一直闪。定式: 布局带**尺寸签名**(没变直接 return) + canvas 只在宽高真变化时重设 + 只在**数据签名变了**才重画。
- **顶层 `let X` 不是 `window.X`**: 在自动化浏览器里注入测试状态(如假外参)必须直接给裸名赋值(`CALIB={...}`),
  `window.CALIB=...` 不影响脚本闭包, 后续 `proj()` 仍读不到 ⇒ 会误判成"函数坏了"。
- 跨端口调接口(页面在 A 端口、轨迹台在 B 端口)= 跨源 ⇒ 服务端要回 `Access-Control-Allow-Origin: *`
  + 实现 `do_OPTIONS` 回 204, 否则浏览器静默拦掉, 表现为"按钮点了没反应"。
- **相机端口只绑 `127.0.0.1`(ssh 隧道)时页面取不到图**: 不要改相机绑定, 在已经对外的服务上加一条代取路由
  (如 `/central/snap.jpg` 内部拉 `127.0.0.1:8812/snap.jpg` 原样返回), 页面同源就能用。
  先 `curl -o /dev/null -w '%{http_code}'` 分别打 本机/LAN 两个地址确认到底哪层不通, 别猜。

## 臂上相机(有手眼)的实时 3D 框叠加 —— 与固定相机不同的四条

固定相机是"一次外参、静态投影"; 臂上相机是"每帧现算 T_base_cam", 页面集成也完全不同:

1. **位姿链每帧现算**: `T_base_cam = T_base_tool(/pose 真值 ×1000) @ T_cam2tool(手眼平移 ×1000)`。
   先用一行自检把口径钉死: 相机光心到 TCP 的距离应 ≈ |t|(本机 244mm), **光心坐标与 TCP 完全重合 = 漏了米→毫米换算**。
   四元数与 `abc_rad` 两套算法必须一致(实测差 ≤1e-4), 不一致先停手, 别往投影上叠误差。
2. 🔴 **叠加层的绘制顺序**: 页面 `drawOv()` 开头通常有 `if(!CALIB) return` 和 `if(!SHOW) return` 两道早退 ——
   **不吃 AR 标定的叠加(臂上相机自带的框)必须在这两道 return 之前画**, 否则"页面明明加了代码却没框"。
   同时把它的开关状态显示进 hint 行(如"光模块 3D 框已画(12 条棱)"), 让"没画"与"没数据"分开。
3. 🔴 **新状态变量必须并进顶部的 `let` 声明组 + 进重绘指纹**: 只 fetch 到数据不重画 = 看起来毫无变化;
   把 `corners_px`/距离拼进 `drawIfChanged()` 的签名串, 否则数据变了页面也不刷新。
   服务端做 1.5s 结果缓存 + YOLO 惰性加载(单例锁), 别让页面每轮轮询都跑一遍推理。
4. **验收靠 2D 叠加画布数像素, 别靠肉眼看图**: 覆盖层 canvas 是 2D(`getImageData` 直接可用, 不是 WebGL),
   在页面里数目标色像素 + 读 hint 文案就是硬证据(实测绿色 3964px / 12 条棱 / 无 JS 报错)。
   ⚠️ 与 3DGS 那张 WebGL 画布相反 —— 那张必须 rAF 内取, 会假黑。
   ⚠️ **别用“宿主机按窗口几何裁屏”当页面证据**: `wmctrl -lG` 给的是几何不是堆叠顺序, 窗口被别的窗口盖住时
   裁出来的是一片纯色(实测被判成“页面纯白/白屏”, 实际页面已渲染); 可用证据只有页面内 canvas 像素、
   `js_errors`、以及窗口标题是否已变成该页面的 `<title>`。`gnome-screenshot`/DBus 截图有权限门槛时用 `scrot -o`。

立方体几何用相机系构造最稳(横轴=画面 u、长轴=画面 v、厚度沿视线), 8 角点投回像素即精确贴合检测框;
角点再乘 `T_base_cam` 得 base 坐标, 但距离若是尺寸反解出来的, **必须在标签里写明"非实测深度"**。
无深度时怎么算距离、平面先验怎么核, 见 `robot-vision-3d-localization` §深度不可用时。

## 只有近似外参时怎么交付: 位置锚定实时检出 + 角标写偏置

外参方向/尺度对、绝对位置带系统性偏置(实测垂直偏 60~65px ≈ 40mm)时, **不要**把偏了的框当真值交出去,
也不要因此不画 —— 用户要的是"能看着判断"的东西。定式:

1. **每帧算偏置**: `du,dv = 检出框中心 − 标定投影中心`(检出取置信最高那个框), 把投影的所有角点/箭头
   平移到 `(du,dv)` 后画。实测偏置 `(+1, +60)` 时, 叠上去的框中心与检出中心差 **5px**。
2. **把偏置写进画面角标**: `位置锚定实时检出 · 朝向/尺度按标定(残差 9.4px · 偏置 +0,+65px)`。
   角标是给现场判"能不能用"的唯一线索, 不许省。
3. **汇报分清三件事**: 位置来自检出、朝向/尺度来自标定、外参残差是多少。别只说"画上了"。
4. 系统性偏置的成因先查**掩膜的阴影/槽壁**是否有偏(见上一节的 `minAreaRect` 对比法), 再谈重标 ——
   偏置若是**同向**的, 它会被外参整体吸收, 于是"拟合残差很小但整体偏"。
5. 🔴 **改叠加不要重启在役推流服务**: 起一个独立端口的旁路实例(`ZMAX_YOLO_PORT=8897 ZMAX_MOD_SLOT=10
   python tools/arm_yolo_stream.py`), 页面侧改 `data-ext` 指到新端口(页面是**热读**, 不用重启 8793);
  验收 `curl /healthz` + 抓一帧数目标色像素, 别用"服务起来了"当证据。
