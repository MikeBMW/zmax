# 换执行腿(transport)的机械细节 —— 本机 SDK 直连腿

配 SKILL.md §3g 用。§3g 讲**口径与安全边界**(换腿位置、开关、停止改道、任务启动判据),
本文件讲腿自己怎么写、怎么在不动臂的前提下把链路验完。
底层 SDK API 链(机型类 / `moveAppend`+`x.PyString` / `.trans` 取位置 / 容器 `-w` 可写 / 工具系核对)
见用户自有的 `rokae-direct-control` 与 `tools/rokae/sdk_ctl.py` —— 本文件不重复它。

## 1. 腿的位置与数据流

```
收口(chan_send) ──闸门全过──▶ 腿 ──写一行 JSON──▶ FIFO cmd_arm.fifo
   └─(旧腿) ssh 提供方 → ros2 service call /move_line        └─▶ 常驻 SDK 代理(容器) ─▶ xCoreSDK ─▶ 控制器
```

- **复用已有的常驻 SDK 代理会话**, 不要为换腿另起第二条 SDK 会话(控制器会话是共享资源)。
- 腿的执行必须**异步**: 收口只回"已下发"并起线程, 与旧腿同为 fire-and-forget 语义 ⇒ 不阻塞执行器的
  单线程命令循环(卡住它 = 后续所有技能一起排队)。用"在途标志"保证一条在飞时后续拒发。
- 逐条动作必须留**可导出的证据**: 请求位移 / 目标位姿 / 目标 rpy / 实际残差 mm / 耗时 / 代理 verdict,
  追加进 jsonl。现场只认"真值残差", 不认 success。

## 2. 解析: 收口交给腿的是一条完整的服务调用串

形如 `timeout <N> ros2 service call /move_line interfaces/srv/TargetPose "{speed: .., joint_state: {..},
pose: {position: {x: .., y: .., z: ..}, orientation: {x: .., y: .., z: .., w: ..}}}"`。

- 按**字段各自独立**正则匹配: `speed:` / `position:{x,y,z}` / `orientation:{x,y,z,w}` —— **别依赖字段顺序**,
  也别试图一把正则吃下整串。
- 平移 `/move_line`; 旋转 `/move_pose`(位置应保持不变, 只换姿态)。两种都要支持: 回点技能里
  姿态段也走这条收口。
- **认不出 / 解不出目标位姿 ⇒ 如实拒发**(宁可不动), 绝不静默转回已死的旧腿。
- ⚠️ **被截断的日志绝不是样本**: 执行器的干跑行写的是 `call[:200]`, 拿它喂解析器必然"失败",
  会让你误判解析器有 bug。要验就用**执行器自己的模板**生成一条完整串来喂。

## 3. 腿自带的守卫(闸门之外再加一层)

| 项 | 值 | 为什么 |
|---|---|---|
| 单条绝对位移 | **≤800mm**, 超了如实拒(不夹取) | 拦误目标/算错的目标; 空间点之间最远 ~580mm |
| 相对段分片 | **40mm/片**(代理硬上限 50mm) | 长位移靠分片 + 逐片真值核对, 任一片失败立即停 |
| 速度上限 | **30mm/s** | 现场慢速优先, 也是技能 `speed_max` 的再收口 |
| 目标包络 | 过 `env_model.check_target()` | 与执行器同一套已验证包络(默认只记日志, 可 env 升级为拦) |
| 真值新鲜度 | **<3s**, 否则拒 | **不拿旧位姿发动作**(旧位姿算出来的目标 = 错的目标) |
| 到位判据 | 残差 ≤3mm(由代理逐帧真值确认) | 不信 `success` |

## 4. 速度量纲(最易错的一条)

- L2 的 `speed` 是**相对量 ≈0.09~0.1 mm/s 每单位**; 执行器算"等待上限"用的就是 `eff = 0.093 * speed`。
  所以腿把 L2 速度换成控制器 mm/s 时用同一系数, **两边的耗时预估才一致**(否则执行器等不到就报"未到位")。
- **不要用默认 speed=8**: = 0.75mm/s ⇒ 空间点之间 244~576mm 一段要走 10 分钟, 多轮任务一轮都跑不完。
  建图/长转移用 **120**(名义 ≈11mm/s), 仍在技能 `speed_max`(本机 200)内。
- 🔴 **但名义值 ≠ 实测值**: 在 SDK 腿上发 120, 真值实测只有 **~1.1mm/s**(比名义再慢约一个量级;
  50mm 拍升实测 34s) ⇒ **ETA 与"等待预算"都要按实测速率算**(先拿真值位姿差分量一段再报数),
  报给现场的时间用名义值除距离会错一个量级。
- 执行器/腿的"盯到位预算"必须**跟着距离/速度算**(`距离/速度 x 余量 + 常量`), 写死十几秒的长转移上会提前退出,
  现场看到"未到位"而臂还在走 ⇒ 重发 = 并起第二个计划。

## 5. 姿态: 必须下发, 且用对口径

- 控制器 rpy ↔ quat 用 **ZYX**(R = Rz·Ry·Rx)。**只读验法(不动机器人)**:
  1. 真值文件里同时有 `rx,ry,rz` 与 `qx..qw` ⇒ `rpy→quat(ZYX)` 应与 `q*` 逐位一致(差≈1e-5°)。
  2. 拿示教点 quat 与现姿态比: 按 ZYX 得**7~50°**、按 XYZ 得 **~170°**(等于翻转) ⇒ 选 ZYX。
- 示教点的姿态差是**真的**(每个点手腕朝向不同, 为的是把相机对准不同区域) ⇒ 腿必须用 move-abs 带 rpy 下发;
  **只做位置**会把"到点"变成另一个视角(画面/建图口径都偏)。
- 回点技能的段分解由执行器自己做(**就地抬升 → 保持高度横移 → 逐段下降**), 腿**不需要**自己再设计抬升策略 ——
  照每条串下发即可; 但每段都可能带不同姿态, 别把它们当纯平移。

## 6. 换腿前的只读预检(不动机器人, 缺一项就别开)

1. 真值新鲜度 + 现位姿 —— 腿与执行器必须读**同一个**真值文件, 否则口径不一致。
2. 各示教点: 距离(≤上限) / 姿态差 / 包络, 全过一遍并留成表。
3. 解析器用**执行器模板生成的完整串**验证(`/move_line` 与 `/move_pose` 各一条)。
4. **目标 = 当前位姿**的调用 ⇒ 腿应回"已在目标位姿" —— 一次验证 解析+守卫+真值+开关 全通, **零运动**。
5. ⏹ **停止通道实测**: 臂**静止**时发一次 stop(`r.stop` 只会减速, **不可能产生运动**) ⇒ 代理回
   `verdict=STOPPED` 且真值位移 ≈0。停止通道不验, 长任务就不敢跑。
6. 守卫反例: 非运动调用 ⇒ 拒; 目标 3.6m ⇒ 拒。**拒发路径验过才敢让它跑真目标**。

跑完 1~6 再让现场授权; 现场只看到"能不能动", 这些是你自己必须有的底。

## 7. 单段运动被控制器拒发 —— 三类失败模式(实测, 先分清再处置)

腿报 `rc=6` / 位移 0 时, 先分清下面三种:

1. **直线穿过奇异面 ⇒ 控制器拒发**: 报警 `50102`(轨迹前瞻遇奇异点) / `50120`(奇异规避, 沿路径无法到达终点);
   特征是 `moveStart` 返 ec=0 但**位移恒 0**。**把同一根直线拆小步没用** —— 跨过奇异面的那一小步照样被拒
   (分块爬实测过不去) ⇒ 换几何(换中间位/换方向), 不是换步长。手册里 ConfJ off / 牺牲姿态规避两个开关
   对该报警实测无效, 别继续在上面投入。
2. **MoveJ 能过, 但路径不受控**: 直线被拒后自动改 MoveJ(控制器手册的修法)实测真能穿过去, 但关节插值的
   中间位形**可能一路压低 TCP** —— 直发 MoveJ 到示教点曾把 TCP 带到 z≈0.064(低于包络下限 0.0848)撞上工件。
   ⇒ 用 MoveJ 就必须配第 8 节那道实时扫掠闸门。
3. **腿报的"残差"可能是早读, 不等于"没动"**: 慢速长转移时腿的到位判据先耗尽预算退出并报 rc=6(残差=全量
   位移), 而控制器还在走、之后**真到了**(执行器的到位判据读到 0.2mm)。⇒ 见 rc=6 **回读真值再判**, 别据此重发。

- 🔴 **绝不开 MoveL→MoveJ 自动重试**(`allow_movej_retry=false`): 它把一条笛卡尔直线**静默**换成关节空间运动,
  路径类别变了而调用方毫不知情。要换就显式换。
- `checkPath` 预检: **参数口径实测校准前默认关**(env `ZMAX_CHECKPATH=1` 才开)。拿"已知可行"的 ±1mm 去调格式
  仍回 `ec=-50519 move invalid target` 时就别硬开, 走反应式兜底(被拒 → 显式换运动类型)。

## 8. 实时扫掠闸门: 目标点在包络内 ≠ 扫过的路径在包络内

- 只校验**指令的目标点**等于没校验路径; 出过的碰撞就是 MoveJ 把 TCP 一路带到包络下限以下时发生的。
- 实现: 下发请求里带一个**包络盒**(与包络校验同一真源, 例 `{'x':[lo,hi],'y':[lo,hi],'z':[lo,hi]}`);
  代理在**每个真值采样点**(~0.15s)比对一次, 任一轴出界 ⇒ 立刻 `stop()`, 并把越界轴 / 当时 TCP / 时刻写进证据。
- MoveL 与 MoveJ **都要过这道闸**(共用采样循环), 不是只给 MoveJ。
- 验收判据(零运动可验, 改完必须跑): 拿出事的那组坐标(如 z≈0.064)去问它, 必须判"出界"; 拿当前位姿必须判"在盒内"。
