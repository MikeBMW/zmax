# 恒定 z 纯平移弧线采集法（给 3DGS / 多视角重建造数据）

场景：机械臂把工件（或标定板）当目标，自己绕它走弧线拍一圈。上方有横梁、下方有台面 ⇒ 不能升降。

## 核心设计：三条「结构上不可能撞」的约束

1. **z 恒定**，全程一次不升降（例：`z=0.4303` 从第一个路点到最后一个路点逐位相同）。
   不升降 ⇒ 上横梁（z≈0.65~0.75）和下板面（z≈0.15）都不可能碰到。
2. **姿态恒定**，四元数一个字节不改 ⇒ 纯平移，不会触发 `50102` 奇异 / `50113` 姿态阈值。
3. **绕目标半径恒定** ⇒ 目标始终在同一尺度、同一距离上，不会越走越近撞上去。

路点 = `center + R(θ)·(起点−center)`，θ 按 8° 一档，`z` 和 quat 原样带上。

## 净空自检：按部件分别取半径，不要用一个数套所有点

| 部件 | 半径 | 说明 |
|---|---|---|
| 末端 TCP | 45mm | 夹爪 + 工件包络 |
| 法兰 | 90mm | |
| 相机包络 | 90mm | 相机挂在 TCP 后面（本例 214mm 沿 tool X、−115mm 沿 tool Z）|

三个必算的余地：①每个部件↔每个围栏箱体（盒外到面距离−半径）②部件↔围栏线 ③最低点↔板面。

> 坑：**只看 z 会误判**。实测相机包络最低点 `z=0.311` 比「检测设备」箱顶 `z=0.34` 还低，
> 但两者在 X 方向隔 342mm ⇒ 根本不碰。反过来，用连杆半径（95mm）去套末端也会把安全路点判成 FAIL。

## 执行器：一步一条指令 + 真值判到位

- 每条 `/move_line` 只发一个路点，发完直读 `/robot/tcp_pose` 判「偏差 <2mm 且连续 ≥1.5s」。
- 任何一步超时/偏差超限 ⇒ **中止剩余路点，绝不重发**（重发会把两个动作叠起来）。
- 全程监听 `/robot_status`，`has_error / estop / collision` 一出现立即中止。
- 🔴 **订阅 QoS 必须 BEST_EFFORT**：`/robot/tcp_pose` 是 BEST_EFFORT 发布，默认 RELIABLE 订阅会
  `offering incompatible QoS ... RELIABILITY` 一条都收不到 ⇒ 执行器以为「拿不到真值」直接退出。
- 🔴 **脚本里 `set -u` 会让 ROS 的 `setup.bash` 报 `AMENT_TRACE_SETUP_FILES: 未绑定的变量`** ⇒ 先 `set +u` 再 source。
- 🔴 **Orin 上没有裸 `python3` 的 rclpy**，必须 source `/opt/ros/<distro>/setup.bash` + 工作空间后再跑。

## 采集端配平（真正的瓶颈不在机器人）

一次实测：`speed` 参数从 200 降到 33，实际速度只从 6.6 降到 5.4 mm/s —— **低速段不按比例**。
所以「放慢机器人换帧数」这条路不通；瓶颈是采集环：每帧要拉彩色(57KB)+深度(168KB)+算亮度/清晰度+写盘，
**实测只有 1.3~2.5 帧/秒**（不是配置的 10Hz）。

配平公式：`帧数 ≈ 采集帧率 × 路程 / 速度`。给不够就**加路程**（把弧线半径放大 2 倍、或同一路径多走几趟），别去压速度。

- `MOVE_EPS_M`（位姿变化超过多少才存一帧）要 ≤ 每帧位移，否则大量帧被 `skipped_static` 吞掉。
- 采集包的 `MIN_FRAMES`（例 160）不达标就**不会训练**，白走一趟；开跑前先算好能不能过线。

## PSNR 口径纪律（比模型本身更容易骗人）

- **跨数据集不可比**；**同数据集不同留出协议也不可比**。
  默认「留 1 段/8」时，数据密度不同会导致留出段一个是「插值」（前后都有邻居，如 21 帧/0.1m）、
  一个是「外推」（整段角度缺失，如 47 帧/73.6°）—— 两者难度差一个档，拿来做 A/B 就是自欺。
- 要比就**固定协议**：同一 init、同一 `--holdout-blocks/--holdout-keep`、同一步数。
- 拆提升来源：看 `留出 − 训练` 的**间隙**。间隙没变而两者同涨 ⇒ 是成像质量上去了，不是泛化能力上去了。
  实测一例：数据换掉后留出 +4.77 dB、训练 +4.48 dB、间隙 2.97→2.68 ⇒ 贡献在成像一致性，不在外推。
- 初始化（深度反投影 vs 随机盒）的增益**跟帧数相关**：635 帧时 −0.2~−0.4 dB，202 帧时 +0.61 dB。
  帧数稀时 geometry 才真进模型。所以「深度初始化有用/没用」不能一句话结案，要带帧数说。
