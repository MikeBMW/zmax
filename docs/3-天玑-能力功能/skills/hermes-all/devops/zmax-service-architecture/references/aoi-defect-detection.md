# AOI 金手指缺陷检测（氧化 / 划伤）

用户会直接下这种任务：「这 19 根有一半氧化或划伤了，你来自己分类、自主学习，下次能给出缺陷检测，用这个数据训练 YOLO」。看起来是训练任务，实际卡点在**成像**和**样本量**，不在模型。

## 判断顺序（不要跳步）

1. **成像够不够** —— 每根触点有多少像素、边沿是否清晰、照明是否均匀。
2. **样本量够不够** —— 缺陷实例数量、是否覆盖不同板/不同缺陷程度。
3. 才谈标注、训练、部署。

前两步不达标时，正确回答是**如实说明做不了可靠标注**，并给出可执行的下一步，而不是硬标一批框去开训 —— 那样出来的权重只会过拟合到这一块板上，换个工件就失效，比没有更糟。

## 逐根切取（做量化与标注的地基）

`GET /region` 的 `region.quad`（原图坐标，顺序 左上/右上/右下/左下）+ `GET /picture?kind=origin&grab=1`：

```python
M = cv2.getPerspectiveTransform(np.float32(quad), np.float32([[0,0],[ow-1,0],[ow-1,oh-1],[0,oh-1]]))
strip = cv2.warpPerspective(img, M, (ow, oh))            # 例 1455x70, 原像素不插值
# 沿宽度等分 n 份, 每份略外扩 5% 含间隔, 拼成带序号的一张图给人看
```

拼成一张带序号的总览图（每根上方 `cv2.putText` 标 1..n）比让人逐张点开高效得多，也是自己用视觉复核的依据。

## 量化指标（肉眼说不清时先给数）

每根统计：`mean`（平均亮度）、`std`（斑驳程度）、`dark%`（< 0.7×自身均值的占比 = 局部暗斑）、
`line_ratio = |Sobel_y| / |Sobel_x|`（越高越像横纹划痕）、`dn_up_ratio`（下半/上半均值，< 0.8 = 下半发暗）。
综合异常分大约 `(140-mean)/140*40 + std/60*20 + dark/40*25 + (1-dn_up)*60 + (line_ratio-1)*15`，
≥35 才算可疑。这组权重只是排序用的经验值，**不要当绝对判据**，它只负责把最可疑的几根挑到前面。

**必须先把触点本体分割出来再统计。** 直接对切下来的小图做统计，会把触点之间的间隙和上下黑边一起算进去：
实测 `std` 80~98、`dark%` 40~52，19 根里 18 根被判「异常」—— 指标全被背景污染，输出毫无意义。
做法：`threshold(max(60, 0.6*t.max()))` → `connectedComponentsWithStats` 取**最大亮连通块**作掩膜
→ 只在掩膜内算均值/方差/上下半比。修正后同一张图 `std` 回落到 20~31、`dark%` 0~2.3、异常分 7~22。

## 什么时候可以说「能做」

- 每根触点在原图上至少几十像素宽、边沿锐利、照明均匀（能分清「褐黑渐变 = 氧化」与「线状 = 划伤」）。
- 缺陷实例达到几十个量级，且分布在不同板、不同程度上。

任一条不满足，就把这两条作为前置条件讲清楚，并说明现在的量化结果（例如「19 根里只有第 3 根下半比上半暗 23%，其余全在正常区间」）与他的观察对不上，原因是成像分辨率压掉了特征。

## 与「页面 == 模型输入」红线的关系

显示层那些几何加工（对齐、裁切、摆正、放大）**不参与训练**：训练数据取 `kind=origin` 原图或工控机判据图，
不取页面显示帧。给用户做缺陷判读用的是同一份原图裁切，所以两边看到的是同一批像素。
一旦把显示帧当训练素材，就等于让模型学经过插值/拉伸的假像素。

## 没有 VLM 时的初标流程（可复现，不是凭印象挑）

拿到「大约一半是缺陷」这类先验时，按两条可复现依据出初标，三样产出一起交：

1. 用上节的异常分排序（**先分割触点本体**再统计）；
2. 取异常分最高的前 N 根标 NG（N = 先验比例 × 总数），其余 GOOD；
3. 产出：带序号 + 红/绿框的总览图（放大 3~6 倍，`INTER_NEAREST` 才不糊掉边缘）、
   每根的指标表（json）、按 YOLO 格式写好的 labels —— 类别 `0=gold_ok / 1=gold_defect`，
   bbox 用该根在条带里的等分位置（`xc=(x0+bw/2)/w, yc=0.5, bw=w1/w, bh=0.98`）。

回执必须讲清三件事，否则用户会当成模型已经能判缺陷：① 这是**初标**；② 依据是「更暗 / 更斑驳 /
上下更不均」，**不是真的认出了氧化还是划伤**；③ 请他指认哪几根才是真值 —— 标签真值是唯一硬门槛。

现有数据集规模心里要有数（`data/datasets/yolo_annot/dataset/stats.json`：55 张、peg 52 框 /
OPT_Gold 6 框、train 49 / val 6）。19 根全标也只有 1 张图的量：要训就先做数据增强扩样本，
并明确「这一版只验证流程、不能上线」。

## 「两段拍」能不能提高分辨率 —— 先量再动手

用户选了「相机靠近 + 分两段拍」这条路线时，**先写 5mm 小步的探针证伪**，不要先写移动 + 拼接：

每步 `POST 127.0.0.1:8797/api/arm/move_rel {dz:-5}` → 等 1s → `GET /picture?kind=origin&grab=1`
→ 用**亮度剖面**量金手指跨度（取最亮行带 ±8 行求列均值，`>min+0.55*(max-min)` 的左右端），
同时读 `/region` 的 `focus`。

这台工位的实测结论是**这条路不通**：dz 靠近 15mm，跨度 1522 → 1527 px（+0.3%），只是画面里
整体上移（y 904 → 60）；dx / dy 各 ±5mm 的跨度波动在 ±1% 内（其中一次 -7.8% 是移到画面边缘
被遮，不是真变小）。`focus` 从 279.9 掉到 178.6、回位又回 276.4 ⇒ 当前位姿**就是**对焦距离，
往任一方向挪都失焦。

含义：这台金手指相机（OPT-CC1-GG50）的放大率不由机械臂位置决定，要提高「每根多少像素」
只能动相机本体（换镜头 / 加接距圈 / 改支架）或换更高分辨率相机。倍数不涨就**立刻停手**，
把结论告诉用户，别继续加行程去凑 —— 那是拿碰撞风险换一个物理上不会发生的变化。
探针跑完按原路小步回位，并复述最终 xyz 让他核对。

## 初标的质量边界

我按视觉给的框只能当**种子**，必须由人在标注页复核。可说的范围：明暗不均匀、明显暗斑、明显线状痕迹。
不可说的范围：在模糊图上区分氧化与划伤、判断程度等级、给出「合格/不合格」结论。这些必须靠更好成像 + 人工标签。
