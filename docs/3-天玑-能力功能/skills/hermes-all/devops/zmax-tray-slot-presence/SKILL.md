# 料盘槽位有/无件的判读

## When to Use
- 要回答"槽N 有没有光模块/工件", 且要可复核的数字而不是目测。
- 臂相机(D405)画面发暗、看不清料盘或细节。
- 想用"把 TCP 摆到槽正上方"来取景 —— 这条是错的, 先看第 3 节。

## 目标
用臂上 D405 判定某槽有没有光模块, 给出可复核的数字而不是"我看着像"。

## 1. 相机链路 (先认清楚再看)
- 臂相机 = Orin(192.168.23.66) 上的 D405, 由 `zmax-rs-sdk-hd.service` 提供: 同时监听 **8792 和 8794**, `GET /frame.jpg`。
- 本机 8791 是汇聚页: `/arm.mjpg`(Orin D405)、`/local`、`/local2`(中央 MAXHUB)。
- 取一帧: `ffmpeg -y -loglevel error -i http://127.0.0.1:8791/arm.mjpg -frames:v 1 out.jpg`
- 确认是源暗还是中继暗: 直接 `curl http://192.168.23.66:8794/frame.jpg` 比亮度, 两边一样就是源的问题。

## 2. 曝光 (D405 自动曝光不收敛, 必须手设)
- 10000us(默认) → 画面亮度只有 ~30/255, 判读不了。
- 32000us → 亮度 78~165, 过曝 13~26%; 一般用 25000~32000, 过曝 >20% 就降到 28000。
- 改法(Orin, sudo 密码 ts123): drop-in 写 `Environment=RS_EXPOSURE=32000` 到
  `/etc/systemd/system/zmax-rs-sdk-hd.service.d/exposure.conf`, 然后 `daemon-reload` + `restart`。
- 坑: `echo ts123 | sudo -S tee ...` 里再套 `echo` 会把密码写进文件; 用 `sudo -S bash -c 'printf ... > 文件'`。

## 3. 取景: 相机光轴 ≠ 工具轴 (本任务最大的坑)
- **把 TCP 摆到槽正上方俯视(如 649,206,260)看不到料盘**——臂相机装在腕侧, 光轴与工具轴不同线, 摆 TCP 等于没摆相机。
- 已验证可用的锚点位姿: `389.2, 372.2, 127.3 · rpy 3.089, -1.015, 0.071` (斜俯视整盘)。
- 该视角的槽位映射(实测): 槽1 框中心 x≈940, **每槽 ≈116px 递减**(槽2≈824, 槽7≈240) ⇒ `x ≈ 940 − (n−1)×116`。
- ⚠️ **这套像素常数只对 1280 宽成立**。换 `RS_W=848` 后必须乘 0.6625 ⇒ `x ≈ 623 − (n−1)×77.2`；
  用旧口径会把槽4 算成槽5/6(实测预测 391 vs 实检 399~402)。**任何"像素↔槽号"映射写进代码时，
  先 assert 图像宽度与标定时一致，不一致就折算或报错**，不要静默换算。
- 848×480 口径的内参/深度: `fx436.71 fy436.06 cx422.27 cy238.51`，深度 **0.1mm/unit**(4013 = 401mm)，
  畸变 `[-0.0539,0.0571,0.000344,0.00095,-0.0193]` ⇒ 反投影/PNP 前先 `cv2.undistortPoints`，
  否则残差随离轴角增大(实测 10.5→25.4mm)。
- 换槽优先"同姿势只平移一个槽距 48.3mm", 不要重新猜俯视位姿。

## 4. 判据 (可直接用)
- 检测器 `models/yolo_peg_live.pt`, GPU 常被训练占用 ⇒ `device='cpu'`。
- **有件 = 置信 ≥0.5 且框中心连续 3 帧漂移 <10px** (实测槽1 0.76/0.76/0.77, 槽2 0.77×3)。
- **置信 0.1~0.3 不等于误检**: 远/小目标会掉置信(槽7 实测 0.18~0.24, 位置换算到 x≈242 正好对槽7)。低置信时用"同姿势平移 48.3mm 对照"确认真假。

## 5. 反例 (走过的错路, 别再试)
- 整幅 ROI 的平均纹理(拉普拉斯/边缘)判不了: 目标只占画面一小块, 被背景淹没。要么按框内算, 要么用上面的检测口径。
- 同姿势平移一个槽距后画面"几乎一模一样" ⇒ 相机根本没对着料盘(不是料盘没变化)。
- 到位判据不能用三轴平均偏差: 会把"z 还差 5mm"判成到位。用 **最大轴偏差 <1.5mm**。

## 7. 目标 3D 位姿叠到实时画面 (原点口径 + 锚点)

用途: 在 `:8897/arm_yolo.jpg` 上画光模块坐标系给老倪目检(`tools/arm_yolo_stream.py`)。

- **原点口径由用户定义，不许自己选**。当前口径: 原点 = **金手指(连接器)端中间**，不在绿色拉环端；
  抓取时它应与 `tool1` 原点重合（用户: "模块坐标系和 tool1 坐标系可以重合"）。
  拉环端/体心都是错的口径，改前先问。
- **锚点(位置)用检测框边沿中点，不要用暗块/深度层**。实测三条自动锚定互相矛盾:
  灰度暗块 bbox 高 200px、深度最近层 bbox 高 207px，而 72mm 模块在该距离只该 ~125px ⇒ 两个掩膜都吞了槽壁/阴影。
  可复核口径: 原点 = 检测框"金手指端那条边"的中点，实测与白点差 **0~1px**(上边沿版 1px)。
- **锚点必须在画标注之前取**。`_draw(img, boxes)` 会画深色字/底色，之后再算"暗块 bbox"会把标签吞进去，
  锚点上移 70px ⇒ 叠加整体飞出去。顺序固定: `anchor=_anchor_uv(img.copy(), boxes)` → `_draw` → `_draw_module_frame(anchor)`。
- 画面**只能留原点 + 三轴箭头**，3D 长方体默认关(用户: "3d框先不显示，乱")，开关用环境变量(如 `ZMAX_MOD_BOX=1`)。
- 朝向/尺度来自标定投影(残差 9px 级)时可接受，但**必须把口径写在画面角标上**("位置锚定检出·朝向/尺度按标定")
  让用户能自己判断；不要把"投影出来的位置"当成位姿真值到处用。

## 8. 抓取点真源
- `config/points/cell_points.json` 槽N 的 `pos`(示教实测), 例: 槽2 `[648.3,452.4,113.1]`。
- 现役轨迹 `zmax_data/rokae_sdk/real_traj_absj.json` 第 14 帧 = 槽2 抓取深度 `[649.9,454.1,112.7] · rpy 2.961,-1.49,0.205`(两点差 1.7mm, 可互校)。
- 移动用 `tools/rokae/move_view.py`(`ZMAX_VIEW_XYZ`/`ZMAX_VIEW_RPY`/`ZMAX_SEG_SPEED`); **新环境变量必须加进 `tools/rokae_sdk_run.sh` 的 `-e` 白名单**, 否则容器里读到默认值(表现为"目标没变")。

## 6. 操作坑
- `pkill -f 'move_view.py'` 会把自己这条 shell 一起 SIGTERM(命令行里含同样字符串); 先 `pgrep -af` 看清 pid 再杀。
- 控制器在 manual/off 时**任何下发都拒**(`PowerState.off OperateMode.manual`) ⇒ 人正在点动, 只做只读抓图。
- 辅助脚本: `tools/watch_and_shot.py`(等停稳后抓一帧)、`tools/monitor_shots.py`(每 3s 抓一帧记位姿/亮度/检出), 都只读。
