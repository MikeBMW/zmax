# Z-MAX 金手指规整图 · 标准窗口规格

**现场定稿（2026-11-27 老倪「以后每次都要显示这样的窗口大小」）：输出必须是 1341×206、19 根完整。**

## 一、标准处理链

```
原图 kind=origin (2448x2048)
  → /region?grab=1 取金手指四边形 quad + (w,h)
  → 合理性闸: 800 ≤ w ≤ 3000 且 30 ≤ h ≤ 400，否则不更新缓存
  → 以 quad 中心为原点外扩 _GX=0.95 / _GY=1.55（收窄，不是放大）
  → 左边两角各 +3% 宽（_trim），上边两角各 +5% 高（_up），其余三边不动
  → getPerspectiveTransform 拉正成矩形
  → 纵向 ×2（_VS=2.0，只改高度）
  → 1341 × 206
```

代码位置：`D:\ZMAX\server\cam_live_stream.py` 的 `_rectify_gold_show()` / `_gold_region()`。

## 二、相机档位（必须同时设）

```bash
curl -X POST "http://192.168.23.23:10082/param?exposure=2000&gain=10"
```
2000us/10dB 是不饱和、对比度最高那一档。**3000/10 锐度看着最高但触点已经纯白过曝，细节全丢，别选它。**

## 三、两个已经踩过的坑

1. **`/region?grab=0` 会拿过期数据** → 曾返回 w=365 的小区域，把画面裁成 336×54，看起来像「金手指没了、不是19根」。必须用 `grab=1`，并保留 800~3000 的合理性闸。
2. **工控机 `kind=crop` 是拉伸过的假图** → 它把原图 1455×70 纵向拉伸 3.7 倍。任何在它上面做的「还原/压缩」都会越弄越缺（右下角尤其）。只从 `kind=origin` 裁。

## 四、验收（每次改完必做）

```bash
curl -s -o s.bin "http://127.0.0.1:8793/aoi_gold.mjpg"   # 抓一帧，读 JPEG SOF 头确认 1341 x 206
```
- 尺寸对不上 → 先查 `/region` 的 w 是否在 800~3000
- 根数不对 → 数亮块，应为 19 根；少了看 _GX 是否被改大或左边是否多收
- 图发白 → 曝光过了；发暗 → 曝光不足（回到 2000/10）

## 五、不要做的事

- 不要为「看得更清」再纵向拉伸（现场明确否过：越拉越长）
- 不要在 `kind=crop` 上做几何还原
- 不要把曝光留在调试档（1200/6 是看金色用的，生产用 2000/10）
