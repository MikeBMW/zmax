# 自绘 canvas 三维工艺/示意页 (挂在既有服务上)

## When to Use

- 用户给/贴了一份技术协议、布局图、设备清单，要求在**已经在跑的服务**上开个新 URL，用三维视图把“一根产品周围有哪些设备/工位”讲清楚。
- 要求“和已有页面同一坐标系”（典型：在 8797 `/ar` 的 base 世界系里再做一个 `/autoLight`）。
- 要把“从自动化专机 → 机器人”这类迁移/对比用索画出来，且动画里要看得见谁替代了谁。
- **用户要求「按工艺每一步做一个窗口/工艺卡」「在当前窗口下逐步显示」⇒ 交付形态是一页 N 张卡（§7），不是一个场景塞完再让他挑。** 他从“做一个页面”改口成“每步一个”时，是版式要求变了，加个侧栏说明书交不了差。
- 产线/边缘环境无外网，不能引 CDN，必须单文件自包含。

不适用: 手机端 Three.js 复刻状态空间 (`zmax-mobile-3d-console`)、真机相机画面叠加 (`fixed-camera-ar-overlay`)、纯静态架构图 (`architecture-diagram`)。

## 1. 先定坐标系, 再画东西

- **沿用既有页面的 base 世界系**: 打开那个页面的投影代码, 抄它的约定 (本项目 `/ar`: **X 右 / Y 近 / Z 上, 单位 m, 地面 z=0**)。
  自创一套坐标 = 用户拿两个页面对不上, 等于白做。
- 场景里**画出 base 原点坐标轴** (X 红 / Y 绿 / Z 蓝) 和地面网格, 让人一眼能对标。
- 尺寸统一 mm→m 换算, 布局用「设备真实外廓为中心」的局部坐标 (如 3.0×1.5×1.9 m 以原点为中心), 别把设备丢到离原点几米外。
- 交付里必须写清**示意 vs 施工图**: 协议只给模块关系时, 排版是自己定的 ⇒ 明写「按协议模块关系 1:1 比例示意, 非施工图」, 并说明拿到 LAYOUT 图/实测点位后替换哪一份数据。

## 2. 服务侧接线 (热读 + 只重启一次)

路由加在**已有服务**里, 页面文件**每请求热读** ⇒ 之后改 HTML 一律不用重启:

```python
elif p in ("/autoLight", "/autolight", "/autoLight.html"):
    try:
        with open(os.path.join(REPO, "tools", "web", "autoLight.html"), "rb") as f:
            self._send(200, "text/html; charset=utf-8", f.read())
    except Exception as e:                       # 页面缺失要回可读的 404, 不要 500
        self._send(404, "text/plain; charset=utf-8", ("页面缺失: %s" % e).encode())
```

顺序固定 (与 `live-service-change-discipline` 一致): **写页面 → 加路由 → 用服务自己的解释器 `py_compile` → 只重启一次 → 回读**。
回读三样: 新端点 `http=200` 且 `bytes` == 文件实际大小 · 老页面 (`/ar`) 字节数一字未变 · `/api/*` 仍 200。
改页面文件不需要再重启 (热读), 别为调样式反复重启用户在看的服务。
  ⚠️ **热读只对 HTML 成立: 改了服务端常量(如 `PRODUCT_SPECS`/规格文案)必须重启**, 而"restart 报 started"不等于新进程在服务 ——
  fork 型服务残留子进程占着端口时, 新进程 bind 失败, 启动脚本 `curl` 拿到的 200 是**旧进程**答的。
  判据用**只有新代码才有的内容尾串**(不是 200/ok), 详见 `live-service-change-discipline` §3。

- **整份重做旧页先留旧形态**: `cp -a page.html page_v1_<原形态>.html.bak`，然后**删掉旧文件再 `write_file`**。
  `write_file` 会拒绝覆盖「本任务只 patch 过、没读过全文」的文件（报 `has not seen its full current content`）——
  守卫按“本任务是否读过全文”判，跟备份在不在无关；要么 `read_file` 全量读一遍再写，要么 `rm` 后当新文件写（备份已在，可回滚）。
- **别用 terminal heredoc 拼 python 批量补丁脚本**: payload 里同时出现 `"""`、`'''` 和中文引号时会被 shell/python 的引号打穿（实测直接 SyntaxError，白跑一轮）。批量改页面用 `patch` 工具逐条改，或 `write_file` 落一个 `.py` 再跑。

## 3. 渲染骨架 (不引 CDN, 单文件自包含)

边缘/产线环境常无外网 ⇒ 不要引 three.js CDN。用 2D canvas 自己做投影, 一页 30KB 以内:

- `buildCam()`: 由 `yaw/pitch/dist/tgt` 算 `eye / fwd / R / U`, 焦距 `F = min(W,H)*1.3`, 中心按**安全区**而不是画布中心 (见 §4)。
- `pr(P)`: 视线空间 z, `z<0.06` 返回 null (背后不画), `u=CX+F*x/z`, `v=CY-F*y/z`。
- **画家算法**: 每个面/线 `push(depth, fn)` 收集, 画前按 depth **降序**排序再执行; 文字单独一个队列最后画。
- `box(x0,y0,z0,x1,y1,z1)` 只画 5 个可见面, 按法向给不同明度 (顶 1.0 / −Y 0.78 / +Y 0.68 / −X 0.72 / +X 0.86), 立体感立刻出来。
- 动画: 一个状态机 + 平滑插值 (`q += (qTarget-q)*min(1, dt*k)`), 别用固定帧数假设。
- 机器人用**平面 2 连杆 IK** (够了, 别上完整 DH): `q0=atan2(dy,dx)`; `d=hypot(r,dz)` 夹在 `[|L1-Lt|, L1+Lt]`;
  `q2=acos((d²−L1²−Lt²)/(2 L1 Lt))`; `q1=atan2(dz,r)−atan2(Lt·sin q2, L1+Lt·cos q2)`, 工具与第二连杆共线 (`Lt=L2+L3`)。
  路径点先到目标上方 0.2~0.3 m 再下压, 否则连杆会穿过工装。

## 4. 取景必须自适应 (否则窄窗口裁角、宽屏又太小)

固定 `dist` 一定会出事: 同一份场景在 1280 宽和 3000 宽下, 一个裁掉角点, 一个缩成一点。做法:

- 取设备外廓 **8 个角点**, 对 `dist` 二分 (24 次), 每个候选都**遍历一整圈 yaw** (步长 π/12), 全部角落进框才收窄 ⇒ 任何自转角都完整。
- 「进框」判据用**安全区**而不是画布: 宽屏时左右有信息面板 ⇒ `SAFE={l:330,r:352,t:104,b:62}`, 投影中心和判据都按它算,
  场景就不会被面板压住。
- 只在**视口尺寸变化**或点「复位视角」时重算; 用户滚轮缩放后 `userZoom=true`, 不再抢他的取景。

## 5. 标注: 优先级 + 贪心防重叠

场景标注一多必然叠字, 叠上去比不画更糟。规则:

- 每条标注带 `prio` (主角产品 0 · 工位 1 · 部件 2 · 仪表/说明 3 · 机架 4 · 坐标轴/地面 5~7), 排序 `prio` 升序、同优先级远的先放。
- 依次算像素框 (含 pill 背景), 与已放框相交就**整条跳过** —— 不画半截、不叠字。
- 相邻工位用**交错高度** (如 i%2 ? +0.34m : 0) 让它们能同时显示; 场景里用**短名** (① FC 拔帽·端检), 全名放侧栏, 兼顾可读与不挤。
- 标注总开关 (用户会想截图干净版)。

### §5b 用户两次说「看不见这些字」⇒ 换渲染通道, 不在 canvas 颜色上纠缠
canvas 里 `fillStyle`/描边/底板只能救"对比度不够", 救不了"压根不出字"。判据顺序:
1. 先一次把 canvas 内可读性做满(纯黑底板 + 白框 + `bold 16px` + `strokeText` 黑描边再 `fillText` 白), 同时把标注挪到
   深色背景区域(别压在浅色物体上);
2. 用户仍说看不见 ⇒ **立刻把这条标注改成 HTML 覆盖层**, canvas 只保留线/框:
   - 容器建一次 `position:fixed; left:0; top:0; pointer-events:none; z-index` 高于画布, 内部每块 `position:absolute; transform:translate(-50%,-50%)`;
   - 每帧用 **`画布.getBoundingClientRect()` + 投影 `pr()` 的 u/v** 更新 `left/top` 与 `textContent`, 并夹在 `cr.left..cr.right` / `cr.top..cr.bottom` 内;
   - canvas 侧对应的 `fillText` 首行 `if(document.getElementById('<覆盖层id>')) return;`, 否则两套文字叠字;
   - 好处: 文字由浏览器排版, 一定可见, 还能选中复制(用户常要粘走数值)。
3. 判断不要靠"我改了颜色": 钩一次 `fillText` 打印 `(text, fillStyle, font, x, y)`, 若颜色/坐标都对而画面仍无字 ⇒ 这不是颜色问题, 直接进第 2 步。
- 标注只留必要数值/短名: 同一组数值别既在画布上又挂一条"汇总牌"、又在页脚状态行重复 —— 冗余条会被点名删掉。

## 6. 取证: 判据是像素, 不是"我 push 了多少面"

- **面数 ≠ 有画面**: 绘制队列是最后统一执行的, 任何一个 draw 函数抛异常 (例如引用了不存在的字段 `S.station` 而常量叫 `C.station`),
  整帧就什么都不画, 而 `faces` 计数照样是几百 ⇒ 只报面数会把全黑页判成成功。
  判据用 `getImageData` 算**非背景像素占比 + 颜色族数** (实测健康页 46%~50% 非背景、22 个色族)。
- 🔴 **在共享绘制链中间写 `return` 与抛异常等价**: `drawVR()`/`render()` 这种「一条链画完整个场景」的函数,
  中途 `if(!x) return;` 会把后面的桌子/料盘/围栏/坐标轴全部砍掉, 而浏览器**不报错**。
  现场感受就是「丢了那么多元素」, 极难归因。防御性判断一律写成「给安全占位继续走」或把整段包进 `if(_ok){…}`,
  **绝不 return**; 外层再套一个 try/catch + 分块标注, 至少能报出是哪一块挂了而不是整片消失。
- 🔴 **换数据源时, 替换对象必须带齐下游读的每一个字段**: 给某个物体换了位姿来源, 只构造了要用的那个字段
  (`{t: origin}`) 而下游 20 行后还要 `obj.R` → `_cols(undefined)` 抛异常 → 整链中断(同一类事故的第二种成因)。
  动手前 `grep -n '<符号>' 文件` 把该符号的**所有**读取点列出来, 逐字段补齐或给兜底默认值。
  字段口径本身也要照实读: 有的帧对象是 `{origin, x, y, z}`(三个轴向量、**没有 R**), 需要列矩阵时由
  `R=[[x[0],y[0],z[0]],[x[1],y[1],z[1]],[x[2],y[2],z[2]]]` 拼, 不要假设 `obj.R` 存在。
- **改完必须回读探针变量, 不能只看页面像不像**: DOM/UI 渲染出来 ≠ 脚本跑到尾。
  校验方式是读该页自己的全局量(`TPAN2.show` / `MOD30.show` / `TAB` / canvas 数) 并 `try/catch` 包起来 ——
  全都读得到才说明脚本完整执行; 变量全 undefined 就是中途断了。
- 投影自检 (数值断言, 不靠看): Z 向上 ⇒ 顶面 `v` 小于底面 `v`; 8 角点在全 yaw 下都在 `SAFE` 内 (报最小余量 px)。
- 交互自检: 切模式后颜色族要变 (如机器人臂的琥珀色从 0.00% → 0.06%), 目标点与 IK 解的末端差 < 0.06 m。
- 截图: `chromium --headless=new --disable-gpu --no-sandbox --window-size=2400,1300 --virtual-time-budget=6000 --screenshot=<路径> URL`。
  🔴 **输出路径必须指到 `$HOME`**: snap 版 chromium 的 `/tmp` 是它自己的私有挂载, 报 "bytes written to file /tmp/x.png" 而主机上并**没有这个文件**。
- 页面自己暴露一个 `window.__X={ready,stats(),scene(),setMode()}` 探针, 用 `browser_console` 一次拿全 (面数/标注数/fps/语义字段)。
  浏览器工具偶尔报一条 **空 message 的 exception**, 而 `chromium --headless --enable-logging=stderr` 里 `grep -i uncaught` 是 0 ⇒ 那是工具侧伪影,
  用后者定性, 别为它改代码。
- **一页多卡就逐卡取证**: 每个 `canvas` 单独 `getImageData` 算非背景占比 + 亮色包围盒与质心 (主体该占窗口 40%~85%、质心居中); 只报总面数会漏掉“某一张卡黑了”这种最尴尬的交付事故。
- ⚠️ **文字不能拿亮像素计数判**: 缺字形的渲染环境(远程/headless 浏览器)里 canvas glyph 根本不上像素,
  会把正常白字判成"没画", 于是你去改一段本来是对的代码。判文字用钩子(包 `fillText` 记录 text/fillStyle/font/x,y)
  或读 DOM 覆盖层的 `textContent`; 像素只用来判形状(包围盒/帧差分/非背景占比)。
- **中文真的画出来了才算**: `tesseract <全页png> stdout -l chi_sim+eng --psm 4 | grep <某句原文>`。canvas 里中文可能因字形缺失/被裁根本没画, OCR 读回原文才是证据。
- **定位“整帧不画”**: 空 message 的异常没有行号 ⇒ 在 `browser_console` 里把每个 draw 函数单独 `try{fn()}catch(e){e.message+' | '+e.stack.split('\n').slice(0,3)}`, 报错那个就是元凶（常见形态: 引用了不存在的字段, 如 `S.station` 而常量叫 `C.station`, 一个字符整页全黑）。
- 全页截图用高窗口: `--window-size=1600,3800` 一屏拍完 N 张卡, 再按 340 px 条带算非背景占比, 每行都该有内容。

### §6b 重复物体（几十个同款件）与细窄特征
- **无 z-buffer 的自绘渲染器不会自动排序**：一排/一摧同款件按数组顺序画 = 拿数组顺序当遮挡顺序。
  症状：每个件尾部的特征（拉环/标签/色带）画了几十次，画面上一个像素都没有（开关差分 0~2px）。
  机制：件长 149.7mm、行距只有 164.7mm，斜视时后一排正好压在前一排的尾部上。
  做法：先算好每件包围盒，按 `pr(中心).z` **降序（远→近）** 排一遍再画（画布面不是 `push(depth,fn)` 队列时，这个排序得自己写）。
- **4~6px 宽的特征不要描边**：默认 1.1px 的棱线会把填充整个吃掉，看着就是"没画"。
  该面传 `edge=null`；框线/环线只在投影边长 >6px 时才补。
- 深色件与桌下暗部同色系时差分不出来 ⇒ 亮一档（如塑料 `#2b3138 → #3c444f`）。
- 判据：show 开关 on/off 差分 + 每色精确容差像素计数（`|Δ|<22`），**每种颜色都报**（实测 +556 / +53 / +1543）；
  只数一种色，另外几段没画也看不出来。
- 小件在默认机位只有 3~5px/段：颜色能分、结构看不出。要证"确实画对了"就临时放大（`VR.dist` 压到 ~1.15m，三色 15416/80983/7685），
  汇报时给出这个缩放口径，**别承诺默认视角也看得出结构**。
- **一摞同款件（盘/箱体/托盘叠放）用「z 偏移参数 + 只画最上层」**：给绘制函数加可选 `zoff`（`var z0=zoff||0`，
  所有 z 都加 `z0`；不传参时行为与原来逐字一致），底座仍走原调用，往上只补 `nLayer-1` 只、每只抬 `H`。
  下面几层的内容被上一层的底板压住 ⇒ 不画，绘制量 1/N。层数只留一个数字（`nLayer`），改高度不动几何。
  总高要进尺寸覆盖层（`N*H`），且注意槽位数是写死的、加条目别超。
- 页面级验收要跑**多次刷新**：异步建的块会把刚刚隐藏的结果冲掉，同 URL 两次刷新两种样子（实测；处理法见
  `zmax-ar-traj-8797/references/tray-scene-page.md`）。

### §6c 「三维里的尺寸/外观跟现场不一致」⇒ 先算画出多少毫米, 再找隐式偏移

用户说「这个盘跟实际尺寸不一致」时, **常量对 ≠ 画出来对**, 两件事分开查:

- **算, 不读**: 把该对象的投影范围/包围盒按 mm 打出来(`(x1-x0)*1000` · `(y1-y0)*1000` · 厚度),
  与标称表逐项对。实测常量写着 `315×230×40`、投影范围也是 230/315 ✓, 但盘**厚只有 32mm** ——
  绘制函数里底面写死了 `zb = 0.008 + z0`(桌面板厚), 顶面却用 `H=0.040` ⇒ 隐式扣掉 8mm。
  这种偏移在常量里完全看不出来, 只看常量会得出「尺寸没错」的错误结论。
- **凡是「底面/底座/板面」常量混进物体 z 计算的地方都有这一手** (盘底、箱体底、料架底):
  核对时把 `zb` / `z0` / 各种 offset 一起当成几何的一部分来看。
- 🔴 **同一个件被两个绘制函数画时, 先核对两者的「锚点」是头还是体心**: 一个收**端点/头中心**(内部自己沿长度轴
  退 L/2 到体心), 另一个收**体心**。把同一个点分别传给两者, 就会整体错半个身长 —— 现场口径是
  「这个原点应该是头部中心, 你画成了尾部中心」。同理, 物体沿轴伸展的**方向正负号**也要两边同源
  (靠工具法兰方向定 sgn), 否则两块头对头、身子反向, 看着像一个双倍长的件。
  判据: 分别算出两条路径的**体心坐标**并相减, 必须是 `0/0/0`; 只“看着差不多”不算对。
- **外观类不符要照实拍改**: 现场说"和相机看到的不一样"往往同时包含颜色(实测三维里画的是棕色周转盘
  `#8a5a2b`, 实拍是哑光黑腔 + 白/浅灰翻边)。改 `fill/inner/edge` 三个字段, 边沿用浅灰保留翻边的辨识度。
- 🔴 **能改的和不能改的要分开说**: 颜色、厚度这类**可视层**当场改; 而"把目标按相机画面正投影对齐到毫米级"
  需要手眼外参, 残差不够(实测 `axxb_trans 92mm / rot 12.5°`)就不许做, 也不许拿一次粗略反投影冒充对齐 ——
  如实说「数值口径一致, 位置对齐要重标」, 并给出重标所需的那批数据。
- 改完带 `?v=N` 强刷再回读常量 + 投影范围(见 §10); 静态页要让用户 Ctrl+F5 才生效。

### §6d 上万三角面的曲面（数学曲面/点云网格）不要用 2D canvas 画家算法 —— 换 WebGL

自绘 2D canvas 的画家算法在**几千面以内**够用（§1~§6 的工艺卡就是），但换成上万三角面的光滑曲面立刻丑：
- 每面单独 `stroke` 在掠射角处叠成**竖条纹**；关掉描边也只解决一半 —— 没有深度缓冲，互相穿插的片仍然脏。
- 实测同一张 1.3 万面曲面：2D canvas 出"条纹糊面"，WebGL（本地 `tools/three.module.js`，服务端加"/three.module.js" 热读路由，不引 CDN）
  一次就干净。判据仍是 `getImageData` 非透明像素数 > 0 且颜色族 > 5，不是面数。
- 曲面朝向要按几何定：把曲面的"主轴"映射到 three 的 `y`（`pos.push(x, z, y)`），否则默认视角正好沿轴看成一张实心圆盘。

🔴 **首拍 draw 静默空画布**：`fetch` 回来的那一刻布局/字体还没量出来 ⇒ `canvas.width=0`，画完被 resize 一清就永久空白，
而 HUD 文字（同一函数末尾赋值）却是有数的，看着"脚本跑通了"。两条都要：① 每次画前按 `getBoundingClientRect()` 自愈尺寸；
② 留一个 `window.__painted` 标志 + `setInterval(400ms)` 补画 + `ResizeObserver`。验收：控制台读 canvas 非透明像素数为 0 就是没画。

### §6e 数学对象的可视化必须自证，不能只画得像

画"十维/六维流形、亏格、Ricci-flat"这类图时，用户会问"这是真算的还是你画的"。交付口径：
- **约束逐点验**：采样点代回方程算残差（实测 `|x⁵+y⁵−1| ≤ 3.6e-15`），把残差打到页面上，与图同屏。
- **拓扑量用公式算**，不要凭图数：五次平面曲线亏格由 Riemann–Hurwitz `2g−2 = n(2g_b−2) + Σ(e_p−1) = 5(−2)+5·4 = 10 ⇒ g=6`，
  六个孔洞是算出来的；图只用来"看得见"，不当证据。
- 视觉上也让它对得上：把参数半径取到分歧圆（`r_max=1.0`）让 N 个分支在分歧点收拢成环，瓣间空隙就是孔洞，别取到很外面变成几片"叶子"。
- 页面暴露 `/slice.json`（网格+元数据）与 `/slice.obj`（可进 Blender 复核）+ `/health`（带 genus/残差），别人能自己复算一遍。

## 7. 逐步工艺卡版式（一页 N 个独立三维窗口）

用户说「每一步做一个窗口/工艺卡」「在当前窗口下」⇒ 交付是**一页 N 张卡**，N **严格等于**协议工艺流程的步骤数（协议 9 步就是 9 张），不是一个场景配一份说明。
**迁移/对比卡不是标配**：只有用户明确要求「和机器人/另一种方案对比」时才追加一张（写法见 references §4）；他没要就多画一张，等于把自拟方案塞进客户文档，会被整份退回。

- **一张卡 = 一个 `View` 实例 + 一个 `<canvas>`**: 各自有 `yaw/pitch/tgt` 预设和**自己的主体包围盒 `FOCUS[n]`**，共享一个 `requestAnimationFrame` 主循环。
- **取景二分的是该卡主体** `[[x0,y0,z0],[x1,y1,z1]]`（工位 + 载具 + 动作范围），不是整机外廓: 同一台 3 m 机器塞进 268 px 高的小窗口会缩成一个点。
- **`IntersectionObserver`（`rootMargin:'200px'`）只跑视口内的卡**: N 个画布无脑全跑在 60 fps 下白烧 CPU; 首帧先全 `visible=true` 画一遍, 再交给观察器。
- **卡内四段固定顺序**: 动作分解（一句 `A → B → C`）· 技术细节 4~5 条（型号/数量/行程/阈值/接法）· 参数表 3~4 行（节拍/容量/信号方向）· 标签 + 来源条（`§2.2 第 n 步 / §2.1 / §2.3`）。
- 卡头放 **N 段进度条**标该步位置, 顶部导航 `1..N` 跳转: 用户要按流程看, 不是要一个零件库。
- 动画按**真实动作阶段**切（取料→拔帽→下压→清洗→回位）, 一个周期末段回位; 别用整体自转冒充工艺动作。
- **动作分解 = 协议工艺流程表的原文句子**, 只加 `<b>` 标机构名; 不改写、不合并、不补中间动作。技术细节每条句尾带条款号（`（2.1）`/`（2.3.2）`/`（6.1.2.2）`），交付时能一条条对回去。
- 协议没给的（供电规格/接口类型/力控阈值）写「设计评审确认」, 给了的原样照抄, 一个数都别自己补。
- 🔴 **自拟的“专业感”细节是最贵的错**: 力控阈值(N)、缺陷类型清单(划痕/污点/凹坑)、IL、节拍解耦、先进先出、缓存满停送、换型只改程序 —— 这些协议里没有, 写进去用户一眼判定「你假设的」。
- **交付前跑溯源审计**: 从页面/docx 回读每张卡的「动作分解」逐字比对协议原文, 再全量 grep 自拟术语表（上面那份）, 命中就删; 术语别手误（`NG` 写成 `NC` 这类自检也在这一步）。
- **卡片网格要限宽**: 宽屏上 `auto-fit` 会摊成 4~5 列, 每列只剩 560 px、行宽窄到没法读 ⇒
  `#wrap{max-width:1900px;margin:0 auto;grid-template-columns:repeat(auto-fit,minmax(560px,1fr))}`（3000 px 屏正好 3 列）。
- 🔗 **每张卡要能直链**: 卡容器 `id="c1"…"cN"` + `scroll-margin-top: <吸顶头高度>`(实测 ~62px)。
  不然用户拿 `URL#c3` 进来, 卡头被吸顶导航盖住, 他会以为跳错了卡。回读判据: `location.hash` 正确 +
  卡片顶边与吸顶头底边对齐(不是被压住)。卡片某一节真进了工程(拖进状态空间/绑上任务)时再加一个
  「已接入 <SCN/TASK 号>」徒标, 让页面自己说清哪些还只是展示。

抽取清单与卡片数据模型: `references/protocol-to-process-cards.md`。

## 9. 工艺卡一键导出 Word（页面为唯一真源）

用户看完页面基本都会要「导出 Word」。规则:

- **文字真源只在页面**: 点导出时前端把 `CARDS` + 当前视角 `canvas.toDataURL('image/png')` POST 给同一个服务, 服务端只排版。
  **服务端不存工艺文字副本** —— 存一份就必然出现「改了页面忘了改导出」。
- **中文字体必须显式设 `w:eastAsia`**（`run._element.rPr.rFonts.set(qn('w:eastAsia'), '微软雅黑')`），否则 Word 里回落成等线/宋体, 交付件第一眼就不专业。
- **每张图单独 `try/except`**: 一个 data URL 坏了不许整份导出失败（退化成文字卡）。
- **ASCII 文件名给 `Content-Disposition`**, 中文名交给前端 `a.download`。
- 交付前必须**回读 docx + 转 PDF 验页数**（页数 = 1 封面 + N 卡 + 1 说明）; 只报「文件生成了」不算。
- **改了排版模块要再重启一次服务**: `from x_docx import build_docx` 首次请求后就进了 `sys.modules`, 之后改 `.py` **不生效**（与 HTML 热读相反）⇒ 别在旧模块上反复排查「内容怎么还是旧的」, 也别说「热读所以不用重启」。
- **视图约定不许冒充协议内容**: 截图图题只写「图 N-1 …（三维窗口截图）」; 坐标系、1:1 示意比例只在导出说明里写, 并注明「视图约定, 协议未规定」。
  逐条命令、文档结构与坑见 `references/page-to-docx-export.md`。
- 汇报时给**导出件绝对路径 + 字节数 + 页数 + 图片张数**, 并说明「截图是所见即所得, 想要标准视角先关掉自转再导」。

## 9b. 多卡片看板: 版式重排与「文字/标记」的验收

- 🔴 **重排卡片顺序后, 先 grep 所有按位置的选择器**: `:nth-child(n)` / 数组下标这类「第几张卡」写法在重排后指到别的卡
  (实测 5 张卡改成"两行"布局后, 焦点视图把**主角卡自己**隐藏了, 只剩两张后勤卡)。显隐一律按**语义类**
  (`class="g-a"` / `data-card="A"`) 或 CSS `grid-area` 名, 不按 DOM 次序。判据: 焦点视图实际可见的卡 id 集合与期望逐个相等。
- **环/扇形上的名字放不下就不要往外写**: 环的左缘贴近画布边时, 向外排的标签会出界(实测 5 个标签有 3 个 x 变负被裁)。
  定式: 环上只打**序号**(①~⑤), 名字 + 该点时长收到底部一行清单(超宽自动换行); 判据 `右边缘裁切像素 = 0`。
- **同一张卡里多段文字不要各写各的 y**: 3 段以上硬编码 y 必然重叠, 改字号还会崩。合并成一个**按实测宽度算出来的面板**
  (宽 = 各段 `measureText` 最大值 + padding), 行距 = 字号 + gap ⇒ 结构上不可能重叠; 折行按三级降级
  (多空格/中点 → 单空格 → 逐字), 面板高超过画布 52% 就整体缩号, 任何字号都不出画布。
- **验收几何量要代码自报, 不要从画布像素反推**: 面板底色与画布底色同色系时, 扫暗像素找边界会把整张画布当成面板
  (实测报 `panelH=511` 而画布 520)。在绘制函数末尾挂 `window.<X>_PANEL={w,h,lines,fonts}`, 再按字号档
  (0.8 / 1.15 / 1.6 / 2.2) 逐档报 `fitsW` / `fitsH`。
- **判"标记画出来了"用颜色像素计数, 不要用亮度阈值**: 亮度会把弧线/网格/轨迹一起算进去(实测结论直接反过来)。
  按标记自身的颜色区间数(如琥珀 / 亮青), 每种标记单独报像素数, 为 0 才是没画。
- **一图两个编码维度**: 事件点(停留/AOI)与当前态用**不同形状**(菱形 vs 圆点)分开, 颜色留给状态档位, 再用弧长/厚度
  表达第二个量(停留时长/耗时) —— 只换颜色会让两种语义撞在一起。

## 10. 「这个视角重新开一个新页面」= 抽同一份引擎另起一页, 不重抄

用户口径: 「某个三维视角，需要重新开一个新页面」(本项目: 光纤九步场景)。
交付 = 新 URL + 一个吃满屏的大窗口, **几何必须与原来那页同源** —— 另写一份"看起来一样"的引擎, 两页一定分叉。

- **抽切片, 不重写**: 原页的投影引擎 + 场景函数表 + 卡片数据(`CARDS`/`FOCUS`)按**行区间**切出来
  (`execute_code` 读原文件 → 按行切片 → 拼进新壳), 新文件只写壳层(单窗口 / 步进 chip / 侧栏),
  注释里写明「抽自 <原页> §x」。判据: 场景函数与常量**逐字**来自原文件, 不是"我重新摆了一遍差不多"。
- **壳层最小集**: 步骤 chip `1..N` + `◀ ▶` + 键盘 `1..9` / `←→` + 该步的「动作分解 / 技术细节 / 关键口径 / 来源」侧栏;
  `?step=N` 与 `#N` 两10 都要能直达某一步 —— 用户会贴带参数的链接。
- **取景按该步主体重算**: 每步 dist 不同(实测 1.30~1.88 m), 共用一套会让小工序在大窗口里缩成一个点。
- 服务侧只是**多一条热读路由** ⇒ 路由改动要 `restart` 一次, 之后改页面不用重启(见 §2)。
- 入库入口: 原页顶部给一个「🧊 三维视角」按钮 `window.open('/autoLight3d')`, 别只丢一条 URL 让用户手抄。

**取证两条都要, 缺一条就是"没做"**:
- 页面探针 `window.__X={ready, steps(), setStep(n), card(), geom()}`。
  🔴 控制台里**同步连续调 `setStep` 再读绘制队列 = 读到的全是上一帧**, 会得出"九步面数一模一样"的假结论
  ⇒ 每步 `await new Promise(r=>setTimeout(r,120))`(或 rAF 两跳) 之后再采样; 九步的 `faces/labels/dist` 应**互不相同**
  (实测 faces 108~240、labels 7~11)。
- **桌面真窗口证据**(比 headless 截图更贴近他看到的): `wmctrl -lG | grep <窗口标题>` 取几何 → `scrot -o` 全屏 →
  按几何裁剪 → Canny 数边缘像素(实测 3D 区 1390×837、13871 边缘) ⇒ 证明画面在渲染, 不是空白/黑屏。
  只报 HTTP 200 + 面数, 会把白屏/黑屏判成成功。
- 用户屏上要够大: `wmctrl -i -r <winid> -b add,maximized_vert,maximized_horz`
  —— `--start-maximized` 在已有 profile 下可能不生效(实测只开了 912×1072), 当场拍完再量一遍几何。
- 🔴 **验证页面改动前先强刷**: `browser_navigate` 到**同一个 `#hash`** 属于 same-document 导航, **不会重载**
  ⇒ 会对着旧 DOM 判"改了没生效"。带一个自增 query 强刷: `?v=N#1`。
- 🔴 **别关用户手上那个窗口**: 关窗前先 `wmctrl -l` 看窗口**当前标题/URL** —— 他会把你开的 Chromium 拿去搜别的东西
  (实测同一窗口已经变成某供应商产品页)。要验证就用另一个 profile 另开一窗, 绝不对着他的窗口 `wmctrl -c`。

## 11. 侧栏信息栏: 来料产品 → 设备实照 → 该步工艺 (窄栏的排法)

用户会在大三维页旁要「把产品图/参数、设备实拍也放上去」, 并问「怎么跟工艺卡排列」。
顺序固定: **来料产品(做谁) → 设备实照(谁做的) → 该步动作/细节/口径(怎么做)**; 3D 画布永远占主区, 信息栏不抢宽。

- **产品卡先定形态, 再找图**: `MPO-8FC / MPO-16FC` 这类名字 = **一端 MPO 多芯 + 另一端 N 个 FC 的分支缆**。
  拿"两端都是 MPO 的干缆"图去标 `MPO-16FC` 是型号错, 现场一眼就看出来。先确认形态(几个 MPO / 几个 FC / 是否盘缆)再选图。
- **每张图只证明它能证明的事**: 外观图能数出"8 个 FC"; 16 芯的芯孔被端面挡住 ⇒ **芯数以结构图(两端口位 1~16)为准**。
  卡片下方固定一行「图注：…以结构图为准」, 别让外观图冒充芯数证据(会被当成夸大)。
- **窄栏(≈370 px)里图片必须整宽在上、参数整宽在下**。缩略图 118 px + 参数两列并排, 会让值断成两行、说明文字贴到图上。
- 验收用 DOM 行高, 不靠肉眼: `[...document.querySelectorAll('#prodMeta .row i')].map(i=>i.parentElement.getBoundingClientRect().height)`
  过滤 `> 20` 应为空(= 没有断行)。
- 参数压到一行装得下: `插损 MPO ≤0.35 · FC ≤0.30 dB` · `回损 SM ≥60 · MM ≥25~35 dB` · `线径 3.0 主干 / 0.9~2.0 分支 · R≥7.5`;
  标签列 ~56 px, 其余行收进「＋全部参数」`<details>`。
- **现场口径比参数表更有用**: 写「1 件 MPO-16FC = 16 个 FC 端面 = 1 个载具」这类与设备动作挂钩的一句。
- 图片按**型号前缀 + kind** 命名丢进同一目录(`MPO-8FC_实物.jpg` · `MPO-8FC_外观.png` · `MPO-16FC_结构.png` ·
  `MPO-16FC_细节_16FC端子扇形.jpg` · `MPO-16FC_对照_MPO16转2xMPO12_Y缆.png`), 服务端按前缀分组、按 kind 排序
  (**实物 > 外观 > 细节 > 对照 > 结构**)选缩略图 ⇒ 以后只有换图、不改代码。
- **「对照」是独立的 kind, 不是外观**: 别家别的形态的图(如 1×MPO-16→2×MPO-12 的 Y 缆)只能证明"那家的嘴上长什么样",
  **绝不当缩略图、也绝不替代来料形态**; 图注要写"只看 X 端外形"。
- **一张图里出现两件同款产品就淘汰**: 会让人数成"1 件 = 2 根"(实测一张盘了 2 根缆的图直接剔除)。

找图/落盘/验证的完整配方(含被 CDN 403 时的绕法、**从厂商多格总图里裁单格**): `references/product-photo-sourcing.md`。

## 12. 工艺动作链(N 个动作) 与 工位条(M 个站位) 必须两条并排

用户用「动作序列」描述工艺(`上料—拔帽—端面检测—端面清洁—回损测试—盖帽—扫码—分拣下料`), 而三维场景是按**站位**分步的(9 步工位)。
两者不是一对一: 一个工位干多个动作, 一个动作跨多个工位。光把 9 步 chip 摆上, 用户会说「这些步骤得表达出来」。

- **两条并排**: 动作条在上(①~⑧ 圈号 + `→` 串, 亮色) · 工位条在下(1~9 序号 + 站名, 灰)。一条讲"做什么", 一条讲"在哪做"。
  动作条用圈号、工位条用普通数字, 视觉上分开 —— 两条都用 1..N 时用户会追问"到底几个步骤"。
- 前端放一张映射表 `ACTS=[{n,name,steps:[工位号...],hint}]`; 点动作 → `setStep(steps[0]-1)`, 切工位 → 点亮所有 `steps.includes(站号)` 的动作;
  侧栏补一行「本工位动作：拔帽 · 端面检测 · 端面清洁」, 让"一站位多动作"不用文字解释。
- 映射依据协议工艺流程表的**说明列**(如"缓存 1 满后推料至缓存 2"), 不是按动作数平均分配站位。
- 🔴 `CARDS[i].n` 常是**字符串**(`n:'4'`), `[4].includes('4')` 为 false ⇒ 动作条一个都不亮、侧栏显示「—」, 页面看着能点其实全错。
  统一 `const n=+c.n` 再比。
- 版面代价要量回来: 动作条约 39 px, 加完回读画布 `clientWidth/Height` 与顶部起始 y, 别把 3D 压掉一截还说没动布局。
- 验收取**点亮集合**而非截图: 进含多动作的工位应一次亮多个(②③④), 进单动作工位只亮一个; 点动作后 `stepName` 要跳到对应站。

### §12b 导出「动作 ⇄ 工艺卡」对照表(用户下一步必然要的东西)

动作条做完, 用户下一句几乎固定是「增加导出表格, 把工艺动作和工艺卡对应起来」。交付 = **动作条上一个按钮 + 弹窗表 + 复制/下载**。

- **表列固定六条**: 动作序号 · 工艺动作 · 对应工艺卡(工位) · 这一步在做什么 · 技术细节(机构/判据/为什么这么做) · 技术协议依据。
  行数 = 动作数(不是工位数): 一个动作跨多工位就全列出来(`工艺卡 1 … · 2 … · 3 …`), 一个工位多动作就重复出现。
- **数据只写一份** `ACTCARD` 数组, 弹窗表 / 复制 / CSV 全部由它生成 ⇒ 页面与导出件不可能各说一套(与 §9「页面是唯一真源」同一条规矩)。
  别让 `ACTS` 和 `ACTCARD` 各维护一份映射, 两处一漂就是"表里说 4、页面亮 3/4/5"。
- 🔴 **技术细节必须写成完整陈述句**: 用户对交付文字的要求是「通顺易懂、描述清晰、是完整的语句」——
  每格 2~4 句, 讲清"谁做什么 · 靠什么机构/判据保证 · 为什么这么设计", 句尾带条款号;
  **禁** `A→B→C` 顿号堆叠、禁无主语的参数罗列(那是参数表的活), 禁把协议原句拆成电报体。
  自检判据(可脚本化): 每格结尾是「。」且句数 ≥2, 否则重写。
- **CSV 交付口径**: UTF-8 **带 BOM**(`\ufeff`) + CRLF + **全字段加引号**(`"` 内部再转义成 `""`) ⇒ Excel 双击中文不乱码;
  文件名带版本号(`工艺动作_工艺卡对照表_v<版本>.csv`)。复制通道给 TSV(粘进飞书/Word 不散架)。
- 复制走 `navigator.clipboard.writeText`, 失败降级 `textarea + execCommand`(非 https 的局域网页会失败, 必须兜底);
  下载走 `Blob + a[download]`, 用完 `setTimeout(revokeObjectURL, 4000)`。
- **验收用 DOM/JS 拿证据, 不靠肉眼**: 一次 `browser_console` 取回 —— 行数 · 列名 · 每格句数与句尾 ·
  `csv.charCodeAt(0)===0xFEFF` · 引号计数为偶数; 再 monkeypatch `URL.createObjectURL` 与
  `HTMLAnchorElement.prototype.click` 记录 `{size,type,name}` ⇒ 证明"点了真产出 N KB 的 CSV、文件名对",
  比只看按钮有没有动画强。
- ⚠️ 遮罩 `position:fixed;inset:0` 一开就盖住工具栏: 此时用坐标点击工具栏按钮命中的是**遮罩**,
  会被自家 `onclick="if(event.target===this) close"` 关掉弹窗(看着像"按钮失效")。复验在控制台里
  `openMapTable()` 或直接 `#mCsv.click()`, 不要用坐标点击。

### §12c 用户给定稿文字要「同步到两个页面」⇒ 一份文字数据 + 覆盖块, 不改两套 CARDS

工艺卡页与三维页各有自己的 `CARDS`(含 `scene/cam/kv/tags`)。用户贴来 N 段定稿描述要求「同步到两个页面的右侧」时,
**不要**在两份 `CARDS` 里各改 9 处字段(18 处, 必然漂) —— 在每页 `CARDS` 之后、**该页真正渲染之前**插**同一份** `CARD_TEXT`
覆盖块(`CARDS.forEach(c=>Object.assign(c,{pc,owner,oacts,det,desc,basis}))`), 文字从此刻同源; `scene/cam/kv/tags` 仍各页自治。

- 🔴 **覆盖块必须插在渲染语句之前**: 工艺卡页是 `CARDS.forEach(c=>{…WRAP.appendChild})`, 三维页是 `paintSide()` 的调用链。
  插到文件末尾 = 卡已经用旧文案渲染完, 页面看着「没改」, 而你还以为写了。
- 字段口径: `工位归属 / 工艺动作 / 详细描述(一段一条) / 技术协议依据`。**详细描述条目数必须等于原文分段数**
  (实测 [1,1,1,3,2,2,1,1,1]), 别把三段并成一大坨; 每段以「。」结尾。
- **页面依据条与 Word 导出页脚读同一个 `c.basis`**(`fnOf(c)` 也改成读 basis), 否则两处各写一套 —— 与 §9「页面是唯一真源」同一条规矩。
- **有卡号就别再叠序号**: 有 `PC-01` 时标题写 `PC-01 · 待测物料缓存仓一`, 别成 `PC-01 · 1 · 待测…`。
- 验收一次 `browser_console` 拿全: 每卡 `pc/owner/basis` 存在 · 段落数逐卡对照 · 每段句尾「。」 · 标题只含一个编号 ·
  控制台 0 报错; 改完带 `?v=N` 强刷再读(同文档仅改 hash 不会重载, 见 §10)。

条款号从哪来(Word 编号是列表编号, 直接读 docx 拿不到)、以及回答"这几段对应协议哪里"的口径与引用陷阱: `references/protocol-to-process-cards.md` §6。

## 13. 标注页的鼠标编辑 (拖框/缩放/微调) —— 三条必踩的坑

自绘标注页（图上拖框、自动识别 N 个重复特征再人工修）是三件事：坐标换算、命中判定、回显通道。前两件错了
用户只说「拖不动 / 画出来的框不是我点的位置」，第三件错了就是「我画完了，你看不见」。

### 13.1 坐标换算只认 `getBoundingClientRect()` 的实测比例

```js
// ✗ 错的：scale 是“内部画布像素”的比例，CSS 是 width:100%，两者不是一个东西
function pos(ev){const r=cv.getBoundingClientRect(); return {x:(ev.clientX-r.left)/scale, y:(ev.clientY-r.top)/scale};}
// ✓ 对的：鼠标位置 ÷ 实际显示宽度/图像宽度
function pos(ev){const r=cv.getBoundingClientRect();
  const sx=(r.width/IMG.naturalWidth)||scale, sy=(r.height/IMG.naturalHeight)||scale;
  return {x:(ev.clientX-r.left)/sx, y:(ev.clientY-r.top)/sy};}
```

机制：`scale = min(1500, innerWidth-40)/naturalWidth` 用于**内部画布尺寸**，而 canvas 的 CSS 是 `width:100%`
⇒ 实际显示宽度 ≈ `innerWidth-24`。窗口宽于约 1540 时两者差 20%+：点 x=1000 会被算成图像 1612 而真值是 1276，
**偏 336px**，看起来就是“框跑到右边很远”。命中半径 `tol()` 必须用**同一个**实测比例，否则选框也跟着偏。
自检（不用手拖）：对画布 25%/50%/75% 三处构造 `clientX/Y` 调 `pos()`，结果必须等于 `naturalWidth*t`。

### 13.2 一排窄框的命中判定：半径要小于间距/3，重叠时取**中心最近**

N 个同款件排成一排（金手指/焊盘/销），框宽约 45px、相邻间距只有 40px 时：

- 命中半径 10px 屏幕像素在图缩放 0.5 下等效 ±20 图像像素 ⇒ **一根鼠标同时压住左右两根**；
- 再配「倒序遍历、命中即返回」⇒ 点左边那根永远选中右边那根，手感就是“拖不动/跳框”。

定式：① `HIT` 压到 6px ② 先判**选中框**的 4 角 4 边（缩放），不被邻居抢 ③ 其余重叠候选取
`Math.hypot(q - 框中心)` 最小的那个。用户口径是「想调哪根点哪根」，不是“最近的任意一根”。

### 13.2b 光标只许两态：框上 `move`、其余 `crosshair` —— 不按角/边换图标

不要按 4 角/4 边切成 `nwse-resize`/`ns-resize`/`ew-resize`：鼠标在密集框之间只要移动十几像素，
图标就在两种形态间来回闪，用户的第一反应就是“你的光标怎么总变”。缩放功能保留，只是**不换图标**；
`mouseup` 也不要硬设 `crosshair`（交给下一次 `mousemove` 按当前位置判），否则松手那一下会闪一次。
一个函数收口：

```js
function cursorFor(h){ return (MODE==='edit' && h) ? 'move' : 'crosshair'; }
```

### 13.2c 密集框必须显式「画框 / 拖框」模式开关 —— 不要靠命中半径猜意图

框宽 52px、间距 70px ⇒ **框间空隙只有 18px**，而命中半径 ±12px 几乎占满空隙：
一旦“画新框”与“拖旧框”共用同一个 `mousedown` 判定，**起笔点必然落在上一根的命中区** ⇒
画第二根时永远变成拖第一根（用户口径：“我画第二个的时候，你总是变成移动。别变”）。
**收窄命中半径救不了**，因为空隙本身比 2×HIT 还小。

定式：一个显式状态 `MODE='draw'|'edit'`（默认 `draw`）+ 一个切换按钮
（`✏️ 画框(拖=新建)` ↔ `🖐 拖框(点到框=移动)`），且在 draw 模式下 `hitBox` **完全不参与**：

```js
const h = (MODE==='edit') ? hitBox(q) : null;   // mousedown 与 mousemove 两处都要改
```

- 判据：默认进页面就是画框模式；连画三根新框不碰任何旧框；切到拖框后点框内才 move。
- 改完必须重启服务（页面字符串在 Python 里）+ 用户 Ctrl+F5；回读 `curl 页面 | grep -c "MODE==='edit'"` ≥2。
- 这条与 §13.2 是一对：**命中精度**解决“想调哪根点哪根”，**模式开关**解决“想画的时候别动已有的”——两个都要。

### 13.3 N 个重复特征：拖准首尾两根 + 等距生成，不要让他一根根拖

逐根拖 19 次没人愿意干。给一个「等距 N 个」按钮：取**已存在框的最左/最右**（按 x 排序的首尾）的**中心**，
按 `(c1-c0)/(N-1)` 等分生成 N 个；首尾中心差 < N*2 时拒绝并提示“撑不开”。
自动识别给 18 个、间距 40~95px 忽宽忽窄时，点一下就变成 19 个全等（实测间距 65.0px × 18 段全相等）。
⚠️ 等分成立的前提是**这批特征本身等距**；透视导致的端部压缩要用“拖准两根后逐根微调”，别拿等分硬套 —— 先把这点讲清。

🔴 **宽/高取首尾两框的平均，不要沿用第一个框**：手画的首尾两根往往不在同一景深，尺寸差一截
（实测左 52×62 / 右 57×74，高差 12px）⇒ 只用第一根会让另一端整体偏小、贴不住。
`w=((f[2]-f[0])+(l[2]-l[0]))/2`、`y1=(f[1]+l[1])/2`、`y2=(f[3]+l[3])/2`。
要逐根贴合透视才改成线性插值（第 i 根高 `h0+(h1-h0)*i/(N-1)`），并在汇报里点明用的是哪种口径。

### 13.3b 手画 N 个框怎么「对比检查」: 拟合趋势 + 残差, 不逐根肉眼比

用户画完会说「可能有点误差，你要对比的检查」。**逐根念坐标不算检查**，给三组数才叫核过：

| 量 | 怎么算 | 判读 |
|---|---|---|
| 间距 | 中心 x 对序号做线性拟合，斜率 ≈ 间距，报 RMS 残差 | 残差 1~2px（约 2%）= 手画很齐，可直接用 |
| 倾斜 | 中心 y 对序号拟合，斜率 × (N-1) = 竖直跨度 | 单调递增 + 宽高同步变大 = **真实透视**，不许强行等距等高 |
| 框大小 | 宽/高的均值与 RMS 残差 | 宽高 RMS 明显大于位置残差 ⇒ 误差在**框大小**不在位置，先统一尺寸 |

- 报「最大残差落在第几根」——手画的最后一根经常是最偏的那根，让他只改那一根。
- 位置残差 2% 量级对检测标注完全够用（YOLO 容忍度远大于此），**别为了好看做全量重排**，那会抹掉真实细节；
  要重排就把两版都给（原样 / 拟合版），让他选。

### 13.4 框只在浏览器内存里 ⇒ 必须有一条回显通道

用户说「我画完两个边界框了，你看到了么」时，**正确答案是看不到**：框是页面 JS 变量，服务端一无所知。
不要猜、不要拿上一次自动识别的结果冒充他画的。加一个**只读回显**端点最省事：

```python
if p == "/station/x/echo":        # POST {boxes:[[x1,y1,x2,y2],...]}
    # 落 /tmp/<name>_echo.json 即可, 只读用途, 绝不写标注数据集(保存是另一个端点)
```

页面加一个「📤 回显给我看」按钮 POST 当前 `boxes`；之后 agent 读那个 json 就能逐框核对坐标。
顺序带他走：回显(核首尾) → 等距生成 → 再回显(核 19 根) → 保存样本。别让"他画了→我看不到→互相等"循环两轮。

### 13.5 改完这类页面要重启哪个

页面 HTML 由**服务端 Python 里的字符串**生成时（`cam_live_stream.py` 这类），改 JS 也是改 Python ⇒
必须**重启那个服务**，不是 Ctrl+F5 就行。重启按 `/proc/<pid>/cmdline` 原样回放 argv（含 `--port`/`--station-port`
等参数），别手拼命令行 —— 漏一个参数就会起成另一份服务。回读判据：`curl 页面 | grep -c '<新代码特征串>'` 为 1~2。
