# 产品/器件实照: 找真图 → 拓下来 → 验证 → 上页

用在工艺/设备页要标「来料产品是什么、主要参数多少」的时候。目标不是好看，是**型号形态对、每张图不夸大、丢图不改代码**。

## 1. 先把型号翻译成物理形态

| 名字 | 形态（必须对） |
|---|---|
| `MPO-8FC` | 1× MPO 多芯（12 针位只用 8）+ **8× FC** 单芯分支缆 |
| `MPO-16FC` | 1× MPO-16 + **16× FC** 单芯分支缆 |
| `MPO-16` / `MPO16/MPO16` | 两端都是 MPO 的**干缆/跳线**（不是 FC 分支） |

拿干缆图冒充 `xxFC` 是最常见的错；找图前先在心里数一遍"应该有几个 FC 圆头"，再去看图。

## 2. 找图的优先顺序

1. **厂商文档里的结构图/针位图**（如\u534e为 CE 光跳线文档）——它是唯一能证明"哪几芯接哪几个头"的证据。
2. **供应商产品页的实拍整品图** ——证明外观、有几个头、线径/盘缆。
3. 参数表取**厂商规格书 + 行业标准**，写成"典型/上限值",并注明"现场以来料规格与实测为准"。

## 3. 抓图：CDN 403 怎么绕

某些供应商图床对直连 curl 直接拒：HTTP **200 包着 30 字节 `http 403.`**（伪装成 200 的软拦截），`file -b` 一看不是图片。

```bash
# 错误信号: code=200 但 size=30 / type=text/markdown
curl -sL -o /tmp/c1.bin -w 'code=%{http_code} size=%{size_download} type=%{content_type}\n' <url>
```

绕法（按顺序试）：

1. `curl -A 'Mozilla/5.0 …' -e '<产品页URL>'`（部分图床只查 Referer）。
2. 还不行就**换图床**：用 `browser_navigate` 打开产品页 → `browser_get_images` 列出真 URL，
   挑能回真 JPEG 的那家（实测 `cdn.globalso.com` 可直连，而某些 `omo-oss-*` 一律拒）。
3. 同页面的 gallery 图试 `IMG_1051.jpg` 这类原图名（去掉 `-300x300` 缩略后缀），尺寸从 300 px 变 3600 px。

## 4. 落盘就要验证（不能只看字节数）

```bash
file -b /tmp/x.jpg          # 必须是 JPEG image data
python -c "import cv2;im=cv2.imread('/tmp/x.jpg');print(im.shape)"   # 宽 < 400 px 的不要做主图(灯箱放大糊)
```

命名规则（服务端按前缀分组、按 kind 排序选缩略图；排序 实物 > 外观 > 细节 > 对照 > 结构）：

```
<型号>_实物.jpg     真拍整品（优先做主图）
<型号>_外观.png     厂商外观图（可数接头数）
<型号>_细节_<看点>.jpg  接头/端面特写（如 16FC端子扇形）
<型号>_对照_<别的形态>.png  别家/别的形态，只看该端外形，不许当主图
<型号>_结构.png     针位/结构图（芯数只认它）
```

- **同一张图里有两件同款产品 ⇒ 淘汰**：会让人得出"1 件 = 2 根"，比没图更糟。
- **对照图的图注必须写清它不属于本设备来料**（例：`对照=HCI 的 MPO-16→2×MPO-12 Y 缆，只看 MPO-16 端外形`），
  否则下一班人会把 Y 缆当成批量来料形态。

## 7. 从厂商「多格总图」里裁出单格（带型号标签，不带邻居碎片）

厂商常给一张 `MPO类型总览` 式拼图（实测 Fluke Networks 博客：1023×542，2 行 × 4 格，上排 3 格 + 下排 4 格，**格宽不等**）。
要的是其中两格 ⇒ **别按均匀网格估**，用标签坐标 + 列投影定位：

1. 先试大图变体：`_1023x542` → `_1500x999`、去后缀，**不存在会回 XML**（`file -b` 显示 `XML 1.0 document`），别当图片用。
2. OCR 拿标签坐标（`--psm 11` 对稀疏排版最稳，`tsv` 带 left/top/width）：
   ```bash
   tesseract in.jpg ocr -l eng --psm 11 tsv
   ```
   实测读出 `MPO-8 x=142,y=237` / `MPO-12 x=479` / `MPO-24 x=821` / `MPO-16 x=137,y=517` / `MPO-32 x=478` / `SN-MT x=746` / `MMC-16 x=890`。
   标签坐标既是**身份映射**，也是行的 y 分带依据。
3. 逐列非白投影找格边界（比等分可靠，格宽不匀照样切准）：
   ```python
   m = (g[band] < 245).sum(axis=0) >= 3      # 每列是否有内容
   # 连续 run 且宽度 ≥70px 即一格; 实测 row1 11–328 / 353–669 / 695–1012, row2 10–328 / 353–669
   ```
4. 裁「整格 + 下方标签」：x 用 run ±6px，y 从该行顶到**标签底 +4px**；面板本身常只有 ~320px 宽，
   允许 `2.4× LANCZOS` 上采样**只为灯箱可读**，交付时说明是重采样、不冒充原始分辨率。
5. 🔴 裁完必须交给视觉子代理**读图里的标签原文**再入库：格数/顺序猜一次就会张冠李戴（上排 3 格、下排 4 格，
   按"第几格"数必错）。判据三条：标签拼写对 / 芯阵列数与型号一致 / 没有切到邻居的碎片。


## 5. 上页的三条硬要求

- **图注写清它只能证明什么**："外观图可数出 8 个 FC(4 组双工 1A/1B~4A/4B); 结构图为 MPO 12 针位只用 8 芯(1~4 + 9~12)"。
- **芯数禁止由外观图坐实**：芯孔被端面挡住的图只能证明"是 MPO 矩形头",写"以结构图为准"。
- **灯箱**：点缩略开全屏，多张时点图循环（实物→外观→结构），`Esc`/点背景关闭；
  顺便用 `img.complete && naturalWidth>0` 验"真加载"（不是破图）。

## 6. 验收（一次跑完）

```js
// 图真加载 + 页签切换真的换了内容 + 参数不断行
[...document.querySelectorAll('#prodTabs b')].map(b=>b.textContent)
document.querySelector('#prodPic img').naturalWidth     // >0
[...document.querySelectorAll('#prodMeta .row i')].map(i=>i.parentElement.getBoundingClientRect().height)  // 全部 ≤20
```

再加一条事实核查：把落盘的图交给视觉子代理独立判"图里到底是什么接头、几张图与型号是否一致"，
它的结论（包括"这张图数不出芯数"）原样写进图注或汇报里。图注不是装饰，是防自己被夸大的闸。
