# 对外交付/产品文档写作

## When to Use
- 用户要求文档「**不要口语化 / 要正式的产品介绍 / 你要专业**」，或说「**这以后是商品，要销售的**」。
- 要写或改 README、产品手册、规格书、部署说明、投标材料 —— 读者是客户 / 集成方 / 二次开发方，不是自己人。
- 内部口径的文档（含内部称呼、需求原话、吐槽式叙述）要转成对外版。

## 铁律一：先定读者与章节骨架，再动笔
对外文档按**产品手册结构**走，不是按「我这次改了什么」走：
`产品概述(定位 + 产品矩阵 + 核心能力指标) → 系统架构 → 数据模型 → 接口 → 部署与运维 → 治理与质量保证 → 目录内容 → 术语表`。
骨架直接复制 `templates/product-manual.md` 逐节填。

## 铁律二：书面语 + 零内部痕迹
- **不写**：内部称呼或人名、需求原话（如「某人说：…」这类引用）、口语与吐槽（踩过的坑 / 别删 / 拷走 / 咱们 / 搞一下）。
- **可写**：文件路径、命令、表名 —— 但按「读者能照着做」的粒度写；内部代号、内网 IP、凭据一律不写。
- 术语首次出现给定义；同一概念统一写法（别一会中文缩写一会英文）。
- 🔴 **内部架构层级编号与内部机型代号，对外页上一律换成职能语言**：分层编号（L2/L3/L4/L5）、内部版本/机型代号（550A/550B/550C）
  客户读不懂，还暴露内部分工。改写口径：`L5 规划` → 「意图理解 / 规划层」，`L2 检测收口` → 「执行判据（视觉·位姿·力）」；
  `550B 单线程版` → 不写，或写「可单步调试的调试版」。技术选型、竞品对比这类**给客户看的判断页最容易被内部编号污染**，
  因为素材直接来自内部讨论稿。
- **出稿前扫禁用词表**：`grep -cE 'L[2-5]\\b|550[ABC]' <生成脚本>` 必须为 0；词表随项目变，写进交付 README，
  下一轮改版照同一张表扫 —— 只在被点名的那两页改，换页又漏回来。
- 命中要**打上下文再判**，别看计数：`GMSL2` 含 `L2`、附录真源索引里那份文件名（`…-L2-L3-L4方案.md`）是合法引用 ——
  判据是「正文句子里的命中数 = 0」；把命中处前后 40 字打出来再决定删不删，否则每轮都在为一个不存在的违规改文案。
- 🔴 **禁用词扫的是正文，不是页脚**：页脚常印节点 id / 文件名（`n_links`、`ss_links` 这类），整册全文扫会把 `links`
  判成命中（实测整册 1 处 FAIL，实际只出现在页脚 id 里）。取 run 文本时**跳过页脚区**（y ≥ 页高−0.45 in）
  或对 id 区做白名单，判据是「正文命中数 = 0」而不是「全文命中数 = 0」；否则每轮都要为一个不存在的违规改文案。

- 🔴 **项目进展 / 横向对比类汇报册：不写内部分层，也不写技术缩写 —— 这不是「对外才适用」**。
  用户说「不要体现 L2 L3 L4 等架构信息，就说明当前项目状态、对比写他山/无界/智元/自研」时，改的是**整册的世界观**：
  ① 对比对象是供应方/项目，不是技术层（列 = 项目 · 供应方 · 做什么 · 到哪一步 · 给了什么承诺）；
  ② 路径演进只写能力形态（固定轨迹 → 到位置自己找 → 换料不用重教 → 靠手感做完最后一点 → 装箱即用），
     每级配一句「解决了什么问题」，不点名任何算法/模型；
  ③ 每条承诺后面必须跟一条可查判据（连续 N 小时节拍 / 连续 N 次成功率），并写明「承诺 ≠ 实测」；
  ④ 未达标的产品线写成「技术储备，不进交付与报价」，不写成「正在攻关」；区分不同工序时明确写「节拍不可横比」。
  自检：把**技术缩写全集**（分层编号 · 模型族名 · 内部模块名）一次性扫全文，命中为 0；
  只扫分层编号会漏掉模型名与架构词。

## 铁律三：每个数字都必须是实测值，且能被复核
- 写数字前**从真源现取一遍**（查表行数 / 跑 `stats` / 看 `--help`），**绝不从旧文档抄** ——
  旧文档里的数字会过期，照抄等于编造（实测：旧文档写「17 项判据」，现场只有 15 项）。
- 文末给一条**复核命令**，让读者也能自己核（如 `python3 <工具> stats`）。

## 铁律四：每条命令先自己跑一遍再写进去
- 旧文档里的命令**经常是错的**：子命令根本不存在、位置参数被写成 `--to` 形式、默认端口记错。
- 判据：文档里出现的每条命令都在本机真跑过一次（带真实输出）；参数形式以 `--help` 为准。

## 铁律五：交付文档要进版本库
- 文档所在目录被 `.gitignore` 整体排除时，用 **`git add -f <路径>`** 强制纳入
  （父目录被排除时 `!data/xx` 这类否定写法**无效**）。
- 纯内部留痕（清理清单 / 取证记录）放 `docs/7-瑶光-记录追溯/` 之类，不塞进数据目录。

## 铁律六：写完跑自查，不靠「读着挺正式」
两步，都别省：
1. **数字逐项比对**：写个十几行脚本，把文档里每个数字 / 表行数与真源现值逐项比，不一致就报错；
   同时断言关键数字确实出现在**正文**里（防「改了表忘了正文」）。
2. **口径扫描**：用 `search_files`（或 grep）扫一遍人名 + 口语词表确认零残留；顺手扫已废弃的命令形式（旧文档里的错写法很容易被带进来）。

## 方案册重写：一页一个结论 + 大字版（2026-11-02 实测，老倪「字小、没重点、像拼的」）

判据不是「内容多不多」，是「远看能不能看见结论」。落版规则（13.333×7.5 in）：

| 层 | 字号 | 用在哪里 |
|---|---|---|
| 结论标题 | 23~27pt 粗 | 每页一句人话，写在标题位；标题本身就是结论 |
| 关键数字 | 26~38pt 粗 | 一排 3~4 个 KPI 卡，数字 + 单位 + 说明 + 备注 |
| 正文 | 11~13pt | 一页最多 4 条，每条一行半以内 |
| 页脚/来源 | 9~10pt | 版本、页码、数据来源 |

硬约束：正文最小 11pt（页脚可以 9pt）；一页只讲一个结论；标题不带层级代号；
每页页脚写版本与页码，来源写「哪个文件/哪个接口算出来的」。

**「像拼出来的」是结构问题，不是文风问题。** 把表格页（层节点清单、连线清单、参数罗列）从正文里删掉，
换成 12 页一条线：一页看懂 → 物理难点 → 五层总图 → 感知 → 决策 → 执行四道闸 → 力控 → 数字孪生 → 验证证据 → 成本 → 交付边界。
每页一个数字或一个因果链，读者不用翻页拼信息。逐节点说明留在附录（30 页），但也要大字版：
页眉定位 + 做什么/怎么算/输入/输出/怎么验 + 右侧两串事实数字（上游/下游连线数）+ 底部实测毫秒与代码位置。
画布块图、开关小面板、段表小表格一律删 —— 它们的字号（6~8pt）就是「拼凑感」的来源。

**成本页必须有四列同源数据**：售价 / 硬件成本 / 客户单件成本 / 相对人工 / 回本周期，
全部从 `tools/cost_model.build_tiers()` 现算，不许手填；对比基准写清（人工 0.36 元/件怎么来的）。

## 排版体检：两套检查缺一不可（2026-11-02）

1. **压字检查**（`check_deck_overlap2.py` 形态）：用真字体（WQY Zen Hei）按每段自己的字号与行距折行算**实际需要高度**，
   只在「横向重叠 ≥ 较窄者宽度 55%」的列内比上下沿，上一块实际下沿 > 下一块上沿 + 0.03 in 才算压字。
   朴素版（所有块两两比）会把并排 KPI 卡全报成溢出，白改一整天。
2. **字号/边界检查**（写进 verifier）：逐 run 取实际字号，正文下限 11pt、页脚 9pt；
   工程图页（三视图/甘特/稳态）的尺寸标注按图纸惯例单列一档（≥6pt），不参与正文判定 ——
   但**必须单列一项报出**，否则就是靠排除法混过检查。
3. KPI 卡内部行距要留足：38pt 数字需要约 0.58 in 行高，卡高 1.42 in、单位/说明/备注依次 +0.72/+0.98/+1.22。
4. 表格宽度之和 ≤ 内容宽（13.333 − 2×0.82 = 11.69 in），否则整块出界；自检要查形状出界。
5. 🔴 **两个分栏块用同一个 helper 画时，x 必须显式传**：`bullets(s, y, items, w=5.5)` 一类 helper 默认 `x=M`，
   右栏不传 x 就把右栏三条**画在左栏三条的正上方**（同 x 同 y）—— 这不是「轻微压字」，是完全叠字，肉眼一眼就废，
   而压字检查器若带「y 差 < 0.12 视为同块/跳过」的早退，会把它吞成 0 问题。
   判据：检查器必须**单独判一块**「两块文字 x、y 都几乎相同 ⇒ 叠字」，不能只比上下沿。
6. 🔴 **算有效文字盒要按段落对齐方式挪左沿**：`paragraph.alignment == CENTER/RIGHT` 时盒子 `left` 不是文字左沿，
   一堆居中标签（同一 left、越来越大 width 的数字标签）会被误报成全叠在一起。
   正确做法：先按字体量出最长一行的宽度 `wmax`，`CENTER ⇒ x0 += (w-wmax)/2`、`RIGHT ⇒ x0 += w-wmax`，再 `w = min(w, wmax)`。

## 三维轨迹插图：自己写透视投影，不用 mplot3d（2026-11-02 实测）

要「一条轨迹 + 透视感 + 铺满画布」时，`mplot3d` 不够用：它的立方体永远按正方形排版，
2.4:1 的画布上内容只占 39% 宽（实测），宽高比被几何锁死。可靠做法是手写相机：

```python
eye = target + dist·[cos(el)cos(az), cos(el)sin(az), sin(el)]
fw  = normalize(target − eye);  rt = normalize(cross(fw, [0,0,1]));  up = cross(rt, fw)
R   = (rt, up, fw);  d = p − eye;  u = f·(R·d)[0] / z,  v = f·(R·d)[1] / z,  z = (R·d)[2]
```

要点：
- **按幻灯片上的实际尺寸出图**（figsize = 英寸），字号才是真字号；否则 8 英寸图缩到 5.4 英寸，
  图上的 11pt 实际只有 7.5pt —— 这正是「图里字太小」的根因。dpi 给 300+ 保清晰。
- 轨迹按**相机 z 值从远到近**逐段画，近处自然压住远处，透视感靠这个 + 深度比（近/远投影尺寸比）。
  实测：dist 2450 时深度比 0.89（几乎无透视），dist 1300 时 0.78（能看出远近）。
- 阶段标注用 2D 偏移点 + 自动避让（`get_window_extent` 两两比，重叠就往上推），最后断言重叠对数 = 0。
- 数据要现算：段表 `plan[]` 的 `a→b` 就是世界坐标，阶段边界按**段序号**切（首个 insert / 首个「(拔)」/ 首个 golden /
  首个「下料盘」），不要按关键词猜——「夹住(在孔内)」会被误归到插入段。
- 校验不看图也能做：非白像素 bbox 覆盖率、五色相是否都出现、标签重叠对数、投影是否全在画布内。

## 插入页面：页码按「本册第几页」算，不要手填，也不要拿 len(pr.slides) 直接用

页脚页码写死在每页参数里，中间插一页就把后面全错位。做法：生成前置页前先记一次起点
`base = len(pr.slides)`，页码用 `no = len(pr.slides) - base`，总页数用常量并进自检。

插页/克隆页三条硬规则（都是静默错，页数、几何检查全绿才发现不了）：
- **找版式模版页按「左上角编号框的精确文本」**，不能用 `needle in shape.text` 全文子串搜：
  正文里常写着「见 4.03a」这种引用 ⇒ 搜 `4.03a` 会命中 4.03 页本身，克隆出来的是错的版式（整页背景矩形盖住正文）。
  判据：`shape.top < 1.0in and shape.text_frame.text.strip() == "<页号>"`。
- **同一锚点插多页必须倒序插**：每页都插在锚点正后方，正序插会得到 g/f/e 倒序页；
  或每插一页把锚点改成刚插入的那页。插完逐页 dump 编号框回读顺序。
- **封面上的版本号与总页数常在同一个文本框**（`版本 X · 日期 · 范围：N 页`）⇒ 一次读一次写把两个都替掉；
  用 `if 版本 in t: ... elif 范围 in t: ...` 只会改掉第一个，页数就停在旧值。

🔴 **构建顺序决定这个公式对不对**：母版页常是**最先**加载的（7 页工程图），前置页后追加 ⇒
这时 `len(pr.slides)` 是 8、9、10…，页脚就印成「08 / 51」，而真实页序是 01 起。
只要「本册」不是从第 1 张 slide 开始，就必须减起点；同理母版页自己也要按**最终位次**补号（`base + k`）。

🔴 **页码要全册统一，且不印在工程图母版页上**：靠 `for i, sl in enumerate(pr.slides, 1)` 后处理逐页补一个
右下角小页码（跳过封面与母版 7 页）—— 母版页版面自带脚注，补上去会压字（实测压 0.05 in，正是「第 13 页文字重叠」同类问题）。
页码字号同样受正文/页脚 ≥9pt 的自检约束，写 8.5pt 会整片 FAIL。

母版图表页的「最小字号」例外要按**实际页号**动态定位（先找「整机外观」那一页，再 +7），
写死 `range(13,20)` 插页后必然错一页。

## 节点页定版：上文字 / 中框图 / 下两侧接口（2026-11-02 老倪三次纠正后的定论）

用户对「逐节点页」的判据只有一条：**先能看懂这个节点接了谁**，其次才是字大。所以定版版式是：

```
上： 功能描述（做什么 11.5pt / 怎么算 10.5pt / 节拍角色 9.6pt 各一段）
中： 功能框图 —— 左输入盒子堆叠、中间本节点大盒、右输出盒子堆叠
     每个输入一根独立线接入节点左沿的独立锚点，每个输出一根扇出；不要「一根母线全并」（用户会判「连线不清楚」）
     🔴 2026-11-03 再纠正：**斜直线扇入也不行**（用户原话「把线画清晰，别罗列堆叠，每个节点别堆在一起」）——
     7 根斜线挤在 0.74 in 内就是一团刷子。定式是**三段正交**：框右缘水平出 → 阶梯竖直到目标锚点 y → 水平入节点；
     同侧每根线的竖线 x 按 `step=0.055` 错开（`xm = CX-0.26-step*(n-1-i)`，输出侧镜像），
     锚点 `spread = min(NH-0.12, max(0.30, 0.175n))`、框 `pitch=min(0.52, 带高/n)`、`bh=min(0.34, pitch*0.78)`、
     字号 9.2~10.0、名字截断放宽到 18 字、中间盒 `NH=1.30`。判据：每根线 = 3 条 connector（7 进 6 出 ⇒ 39 条），
     同列框最小间隙 ≥0.07 in、无重叠。
下： 左下 输入接口（名称·标签）｜ 右下 输出接口（名称·标签），9.2pt
页脚上方： AR 验证一行 + 计算代码一行
```

几何取值（13.333×7.5 in，已验算不越界）：框图带 y 2.86~5.72；盒子 `pitch = min(0.34, 带高/n)`、
`bh = min(0.28, pitch*0.80)`、字号下限 9.0pt（再挤就截字，不缩字号）；中间盒 3.45×1.16，
锚点在盒左/右沿按 `spread = min(1.02, 0.105n)` 对称铺开；输入盒 x0.86 w3.30、输出盒 x9.10 w3.30、
中间盒 x4.90 —— 扇入扇出都不交叉到对侧。

验证方式（不靠眼睛）：逐页数 `shape_type == 9`（连接器）的个数 = 该节点输入数 + 输出数；
再查每条连接器端点是否落在 0.5~13.0 / 2.5~6.0 内。30 页全对才算过。

🔴 **盒子里字号有内部收缩，全局 9pt 下限要连着改**：`_box` 一类 helper 遇长名会 `size*0.86`/`*0.74` 再乘子行
`size-1.0`，只把外面传的 9.6 提上去，实际渲染仍是 8.4 ⇒ 最小字号自检整片红。做法：helper 内部收缩后 `max(size, 9.0)` 兜一次，
盒子高了就截字，绝不为了塞下而破 9pt 下限。

## 逐节点/逐功能页：每页一段话，不是字段罗列（2026-11-02 实测，四段骨架已被大字版取代，见上）

成套交付册里「每功能一页」的版式，最容易写成机密清单：`节点名 · 层级/类型 · 执行口径 pure · PURE 直通 · 端口 in 1 / out 1` +
截断到 70 字的功能首句。用户会直接判「不成句子、AI 口气、看不懂」。定稿写法是**四段连续叙述**：

1. 它在工位上负责什么（物理对象、动作、判定阈值，用毫米/牛顿/秒说话）；
2. 数据从哪来、交给谁（上游只用中文节点名，不写端口代号；端口显示时写「输入1/输出2」）；
3. 凭什么这样算（算法形式 + 关键限值 + 谁给的依据）；
4. 这一拍到底算没算（真算给实测毫秒与占控制周期比例；仅转发就明说「内部算法尚未参与」，不许含糊）。

落法要点：
- 30 页手工叙事的正文放独立模块（如 `tools/l2_node_prose.py` 的 `PROSE = {节点id: (职责, 方法)}`），页面生成器只负责排版；
  数据来源句与实测耗时**每页现算**（读画布连线 + 常驻循环的 traces），不写死，避免「值变了文案没变」。
- 少数节点的「算没算」不能只看实现开关：真正的计算在常驻进程里（如执行收口节点），要有 `LIVE_OVERRIDE` 逐页写实话。
- **四段固定骨架**（用户点名要的）：`核心功能 / 实现方式` → `输入` → `输出` → `AR 场景验证`，最后加一行灰色「这一拍算没算」。
  每个标签单独占一列（0.94 英寸、右对齐色块），不要把四段混成一大块——用户会直接问「功能描述为什么不详细」。
- **AR 验证必须落到真实接口**：先 `curl` 一遍页面接口拿到当前状态，再写「哪块画面/哪个读数 + 怎么对照 + 现在是什么状态」。
  实测例：四路底图 `/api/cams`、取框 `/api/mod2d_usb`、轨迹与执行面板 `/api/traj/exec/state`、
  判据图 `/api/aoi/state`、仿真插拔 `/api/sim_insert`、位姿 `/api/tcp`。看到 `stale:true` 或 `state:未连接` 就照实写「读数已陈旧、真机未连接」，
  不要写「已验证」；页面上看不到的量（势能、群元素、触觉四维）明写看不到 + 给替代核对路径。
- 层页功能描述来自节点自述，常带内部词：在**显示层**做一遍替换（`口径→计算方式`、`in1→输入1`、`UPH→件/小时`），
  不改画布与节点代码；节点代号与文件名属工程可追溯信息，可以保留。
- 文字区与图区高度要**用真字体量**（PIL `ImageFont.getlength` + 换行估算），别目测：实测 9pt 三行就吃掉 0.4 英寸，
  图区起点必须跟着下移；改完跑一遍「文字块下沿 vs 图区标题线」的自动判据。
- 🔴 改页面文案会连带踩自检脚本：`verify_*.py` 里用正则/needle 匹配页内措辞（`计划口径 … UPH`、`L2 内部连线 N 条`），
  措辞一改就整片变红。**改文案与改判据同一次提交**，改完必须 `45 PASS / 0 FAIL` 才算完。
- 页序若由锚点表控制（如 `PIN_POS = {节点id: 位次}`），插入节点只加一行，别重排别人；并在回复里说清谁往后顺延。

## 同一交付面要统一口径
改一份文档时若发现同目录 / 同交付面的兄弟文档还是旧的内部口径 ⇒ **一并统一**，并在回复里点明「顺手也改了哪一个」。
两份口径不一的文档摆在一起，比一份口语文档更糟。用户会自己判断要不要保留，说一句就够，**不必先问**。

## 汇报口径
交付时只说三件事：**改了什么 / 核过哪些数 / 还剩什么**；再给一行可选的下一步（对外精简版、PDF/Word 导出之类），不要列长选项清单。

## 坑
| 坑 | 症状 | 修法 |
|---|---|---|
| 照抄旧文档里的数字 | 交付物写着过期的判据条数 / 行数，用户一问就穿 | 数字全部现取；文末给复核命令 |
| 把自拟方案/参数写进客户文档 | 用户一句「不要按你假设的写」整份退回重写 | 只写原文 + 条款号；未定项照原样标待确认；交付前逐字溯源 + 术语扫尾（铁律十一） |
| 照抄旧文档里的命令 | 读者照着敲，命令不存在或参数形式错 | 每条先跑一遍，以 `--help` 为准 |
| 只改被点名的那一份 | 同一交付面两份文档口径不一 | 一并统一 + 回复点明 |
| 把「结构对」当成「能交付」 | 章节齐全但通篇口语/内部称呼，还得返工 | 写完跑铁律六的两步自查再交 |
| 生成器模板用 `%` 格式化**中文**交付文本 | 文本里的「99%**」把 `%*` 当格式符 ⇒ `ValueError: unsupported format character '*'`（`%*` 还会报 `TypeError: * wants int`） | 含 `%` 的中文模板一律**占位符 + `.replace('«ROWS»', …)`** 或 f-string，别用 `%` 拼表 |
| 生成器里写死「任务→场景/名称」字典 | 换成新任务一跑就 `KeyError`；该任务缺登记时表里打出 `None / None (色 None)` | 一律 `.get()` + 回落真源字段，缺登记写「**未登记，需补登记**」，绝不输出 `None` |
| 归档/打包脚本的 glob 只列旧文档前缀 | 本轮新交付件（新 SOR、新场景文档）静默不进归档包，MANIFEST 里查不到还以为保存好了 | 归档脚本**显式列出本轮新增文档前缀**；同一任务多批时间戳的配置单**只留最新一批**（按 mtime 取第一条），否则归档一次膨胀一截 |
| 交付件路径落在**软链目录**下(如 `outputs/` 指向数据盘) | `git add` / `check-ignore` 报 `fatal: pathspec ... is beyond a symbolic link`, 或以为提交了其实根本没入仓 | 入库用**真实路径**(数据盘下那个目标路径)或把交付件按**稳定名拷到 `docs/1-天枢-产品边界/`** 再 `git add`; `outputs/` 只当产物区, 不当入库路径 |
| 从 HTML 直接 `--convert-to docx` | `Error: no export filter for <x>.docx found, aborting.` —— 看着像没装 LibreOffice | HTML 被当成 **Writer/Web** 文档, 那种文档类型**没有 docx 导出过滤器** ⇒ 先转 `.odt` 再 `.odt`→docx（铁律十） |
| md→HTML 渲染器没处理 `**粗体**` | 交付件里满屏字面 `**`, 用户一眼看出「这文档没排版」 | 行内标记先 escape 再替换成 `<b>/<i>/<code>`; 出稿后按铁律十抠字复查残留数为 0 |
| 只核「文件生成了」就交付 | 生成成功但内容是豆腐块 / 空表 / 字面标记 | 抠字自检: `pdftotext` 看中文成串 + docx 解 XML 核关键串与标记残留 |
| 中文字体只报「缺字体」就换方案 | reportlab 找不到硬编码的 ttf 路径 | 换 LibreOffice 链路（吃系统字体族），或按系统**实际已装**的 CJK 字体改路径; 别把「某路径没这个文件」当成「没有中文字体」 |
| matplotlib 出中文图（训练曲线/结果图） | 整图全变方块，**连数字和英文也一起变** —— 不只是中文；scipy 也不报错，只是一个 `UserWarning: Glyph … missing` | 被抓到 `Droid Sans Fallback` 时它**缺拉丁字形** ⇒ 别用它。改用 `NotoSansCJK-Regular.ttc`（`/usr/share/fonts/opentype/noto/`），`font_manager.addfont()` 注册后 `FontProperties(fname=…)` **逐元素显式传**（`set_title/set_xlabel/annotate/legend(prop=)` 都要）；先出一张 4 行字体对照小图选字体，再画正式图 |
| 图“生成了”就直接发给用户 | 脚本零异常、文件也有 KB，打开全是豆腐块/标注指向错误 | **发图前自己看一眼像素**（视觉工具）：中文无方块 · 数字可读 · 标注箭头指向对 · 无截断。字体/版式类问题脚本永远不会报错，只会在人眼里错 |
| 交付件目录里多代版本并存(实测同目录同时躺着五套版本号的文档) | 现场/客户分不清哪套才是本轮有效版, 一句话就要清 | 交付件目录只留**一套当前交付版**，旧版归档到 `release_*/docs/` 此类归档目录并在 README 记位置; 版本号必须**单调且格式统一**(别出现 `X.Y.Z` 与 `X.Y.Z1` 这种会被读成数字拼接的写法) |
| 生成器里手写节点简称/标签 | 页面写着「⚙️ n_exec 授权·闸·到位」，真源名是「⚙️ 动作执行器 (L2 收口 · 授权/闸/到位)」；用户一搜发现该串只存在于生成脚本 | 名称一律取真源字段逐字写入 + 自检断言每个名称在 deck 全文命中 |
| 直接递给 `add_text` / `run.text` 的字符串里带 markdown 标记 | 幻灯片上原样显示 `**只有 2 个**`、反引号，用户一眼看出“没排版” | python-pptx 不吃 md：强调用 `bold=True`、色用 `font.color`，文本里不写 `**` / 反引号 / `#`；出稿后按 `pdftotext` 抠字查 `**` 残留为 0 |
| 汇总卡片分项数与总数不符 | 卡片写「30 个节点：感知 6 / 融合 2 / 小模型 5 / 决策 2 / 技能 12 / 执行 1」，加起来 28 | 生成时断言 `sum(分项)==总数`，并让总数也来自真源统计 |
| 删旧版本交付件前没查引用 | 交付件文件名被生成器/归档脚本**硬编码**(如 `sor_export.py` · `delivery/gen_*.py` · `archive_release_<ver>.sh`) ⇒ 删了文件那些工具有的失效、有的一跑又把它生回来 | 动之前用 `search_files` 扫工具目录里的该版本号; 默认**先归档不删**, 确认无引用再删, 删除提交里写明原因与去向 |
| 横带面板底边贴死页脚 | `A1+0.10+h` 算出 6.13 而页脚 `FY=6.12`，框线压字 | 高度别按公式凑满：复检「面板底 ↔ 页脚」之间的缝 ink 必须为 0，超了就减行数/缩字号，不要改 y 往上撞块图 |
| 面板里长句折行溢到框外 | 行带剖面比预期多一条，最后一条越过面板底边 | 先按行带数确认每行是否单行文字，超长就缩字/砍字（砍到能对上真源的粒度），改完重出页图再测 |
| Word 表格被分页切开：表头单独跑到下一页、表注孤零零落在页首 | `trPr` 里 `cantSplit` 写在 `tblHeader` 之后（OOXML 子元素有序，LibreOffice 会静默忽略 cantSplit）；单元格段落不设 keep_with_next 时整表照样被拆 | 每行 `cantSplit` 要排在 `tblHeader` **之前**；表内**所有**段落（含末行）设 `keep_with_next=True`，整表就随标题一起挪页；判据 = `pdftotext` 逐页首行扫，首行不该是表格续行、表注不该单独成页 |

## 铁律七：达标与未达标**分开写**，硬指标不许柔化
- 验收型文档（测试报告 / 原型验证 / 投标应答）必须把命题逐条列出并标结论：**已证明 / 未证明 / 未达标**。
- 硬指标（成功率、节拍、精度上限）未达到就**原样写实测值与差距**（例：目标 <3s、真源验收 ≤3.15s，实测 3.875 s/颗），
  并给出差距归因与下一步；真源里 `value` 为空的指标一律标「待实测 + 实测入口」，**绝不编造实测值**。
- 技术**立场/选型结论页**要标清来源等级：本项目实测的数字单独成句并给口径，引用行业共识的（果冻效应不可逆、小像素衍射极限导致 MTF 不足时高分辨率拍出来一样糊、机械快门寿命/进光量换算）在同一页页脚写明「行业共识，非本项目实测；需按所选机型复核」。两条混写，用户会当成你的实测数据去对供应商，一对就穿。
- 理由：用户会拿文档去现场复测，柔化过的结论比一份不好看的真话代价大得多。

## 标准交付工程(整包) —— 版本升级时按这套出

**版本双轨口径**(用户明确要求): **开发版 = 纯数字**(如 `5.50.1`) · **正式发布版 = 带字母**(如 `5.50.A`)。
两者同批出, 发布包内文档标注发布版号。
- **落法**: 生成器出文档时 `--ver` 传**交付版字母**（如 `5.50.C`），真源 `CURRENT_VERSION` 保持**开发版数字**（如 `5.50.6`）；
  文档抬头与包 README **同时写明映射**（交付版 5.50.C ↔ 开发版 5.50.6），归档/发布包按交付版命名。
- 迭代顺序（实测跑通的一遍）：保存/归档数据 → `bump_version.py --to <新开发版>` → 回读全部版本位 → 按新交付版号重出文档 → 分档打包投递+回读 → `git add <本次文件>` 提交 → 打 tag 推 origin。

**① 总配置清单必须「扫出来」, 不手写**
- 写一个生成器(如 `tools/delivery/gen_config_inventory.py`), 逐节从**在役系统**读: 版本位/git tag · 在役服务端口(带 pid)+systemd 单元状态+crontab ·
  配置真源文件(逐个 sha256) · 任务与场景(读绑定文件) · 模型权重(大小+sha256) · 相机通道(实时 fps/帧龄) · 数据空间话题 · 画布规模 · 运行环境(CPU/内存/磁盘/GPU/Python)。
- **跑生成器前先把生成物重建一遍**: 打开/保存总工程(刷新 `.proj`) 就会让单一工程库报 `drift ['project']`, 不重建则清单里的
  关联数/绑定数还是旧的 —— 定式 `python3 tools/engineering_db.py build` → 生成器 → 回读; 库被常驻服务读进内存的, 中间补一次 restart。
- 输出 md(给人看)+ json(给脚本核)。**每个数字都带来源**, 抬头写明「来源: 在役系统扫描, 每个数都可回读复核」。
- 抽「最新版本/tag」时**先正则过滤再排序**: 仓库里常躺着历史怪 tag(如 `vv5.16.35`), 直接取
  `git tag --sort=-creatordate | head -1` 会报到它头上; 用 `^v\d+\.\d+\.\d+$` 筛过再取; 版本号读文件时也别把
  首行标题当版本号(实测 VERSION.md 首行被读成版本 ⇒ 清单写错)。
- 好处: 清单永不过期(改完重跑一次), 且用户逐条追问时每一项都能回读复现 —— 手写清单做不到。

**② 一份事物有多份副本时, 取「被引用方」的那一份**
- 实测: 任务绑定工程声明的画布是 `src/lerobot/engineering/flows/state_space_obs.json`(**89 节点/184 连线**, 带 md5),
  而仓库根另有同名 `flows/state_space_obs.json`(**251/242**) ⇒ glob/取最新会报出错的那个数。
- 规矩: **先看绑定/引用文件里写的是什么、带 md5 没有**, 用它的值; 并在交付文档里如实注明「另有副本 X, 非本次交付所用」。
- 同类: 工具内部字段名要与真源对齐(实测任务字段真名是 `task_id`/`recipe_type`/`scene_ref`/`site`/`ss_mode`,
  自己猜 `id`/`mode`/`scene` 会全表输出 None —— 生成器第一次跑完必须回读一遍输出)。
- 🔴 **生成器自身不许用「取最大 / 取最新 / glob 第一个」挑副本** —— 这种聚合写法会让本纪律在生成器里静默失效(实测:
  对 `flows/*.json` 取 `max(节点数)` ⇒ 清单报 251/242, 而绑定声明的是 89/184, 交付件里的画布规模是错的)。
  副本只能**从绑定/引用文件读**; 并如实注明「另有副本 N 个, 非本次交付所用」。
- 🔴 **计数口径要取自真源的运行时事实, 不要正则数文本行**: 话题数/注册项数这类应 import 真源模块或起子进程实读
  (实测正则抠 `NAME = "zmax/` 只数出 1, 真源实际注册 25 条); 文本扫描只能当兜底, 且回读必须对得上。

**③ 发布包结构按既定约定**(例: `zmax_data/release_<版本>_<日期>/`)
- 目录: 交付文档(`docs/1-天枢-产品边界/`)、源码/工具、配置、证据(`evidence/`)、报告、`MANIFEST.md`(逐件 sha256 清单)。
- 文档清单至少含: 功能说明 · 全系统总配置清单 · 供应商 SOR · 项目立项文档 · 任务配置单 · 原型验证测试报告 · 架构设计。
- 功能说明按「分层能力 + 模块清单 + 配置驱动对照表(改什么→改哪里→怎么生效)+ 验收口径 + 本版新增」写, 不是变更日志。
- 归档用 `tools/archive_release_<版本>.sh`（代码 / 真源快照 / 画布 / 证据 / 报告 / 文档 + `MANIFEST.md` + `sha256sums.txt`），
  复制清单**显式列出本轮新增文档前缀**（glob 沿用上一轮 ⇒ 新交付件静默漏归档）；同一任务多批时间戳的配置单只留最新一批。
  归档目录属数据盘（不进 git），脚本本身要进库，改完重跑一遍让新件入包并回读 MANIFEST 计数。

**④ 版本号写入器的坑: `--summary-file` 只能是「短」摘要**
- `tools/bump_version.py --to <ver> --summary-file <md>` 会把该文件**整篇**塞进 `VERSION.md` 的一个表格单元格
  (换行被压平) ⇒ 拿变更说明全文当 summary 会撑爆表格、无法阅读。
- 正确做法: summary 写**一段**要点; 详细变更放 `docs/6-开阳-工程落地/<ver>_changelog.md` 并在摘要里指向它。
- 改完必回读: 机器可读版本位(界面品牌 QLabel · 窗口标题 ×2 · `CURRENT_VERSION` · version_sync 的 `zmax_ver` · docs_sync 两键)
  + 人读的 `VERSION.md` 行(长度正常) + `py_compile` 一遍。

**⑤ 并行会话/多人同改一个仓**: 只 `git add <自己改的文件>`, **绝不 `git add -A`**; 版本号/tag 串行(同一时刻只有一个会话打 tag)。
提交后别人的在改文件(` M 某文件`)保持原样 —— 这既是避免覆盖, 也是可出示的分区证据。

**⑥ 供应商外发 SOR: 先定采购对象, 需求必须可追溯且可迁移**
- **第 2 章第一张表就是「交付分工」**(供应商交什么 / 我方工程集成与收口做什么), 再写被集成系统的作业条件。
  采购对象是「具身模型」时, 整机采购表**不能**当采购范围用 —— 模板里预置的整机条款会与供货边界(SCOPE_IN/SCOPE_OUT)
  直接矛盾, 交付前必须逐条对齐(实测踩过: 买模型却写着买机器人本体/相机/末端)。
- 除常规章节与附录 A–D, 必带三件: **配置表关联性**(每条要求 → 配置项 ID → 关联模块/能力/验收判据 的追溯矩阵)、
  **架构兼容性**(分层职责 + 硬约束: 不自带坐标系 / 不产底层控制量 / 无否决权 / 参数不得硬编码 / 上报契约)、
  **任务迁移**(同画布下各任务的差异配置 + 迁移不变量 + 迁移步骤 + 判据命令)。
  骨架与逐节内容见 `references/supplier-sor-structure.md`。

## 铁律八：功能级交付文档 —— 每个功能都要有「输入 topic / 输出 topic / 可测指标 / 真收发实测报告」

用户要的交付粒度是**功能**，不是「系统整体」。模板固定成六段，数字全部由生成器从真源同源渲染：
`①目标与达成(硬指标写明 99% 成功率 / 3.5s 节拍 + 实测差距) → ②工程配置(场景切换·空间点位·位置/角度·
性能指标目标) → ③任务配置(调用的工艺技能序列+参数覆盖+档位) → ④功能清单(每行: 详细描述+输入topic+输出topic+
可测量性能指标) → ⑤每功能 topic 输入输出实测报告 → ⑥结论与达成路径+复核命令`。

- **功能 = 可独立寻址的执行单元**(实测取「画布节点」: 89 节点，去掉装饰行后 74 个真功能)，
  **输入 topic = 上游节点输出 topic 集合 + 连线总线**，**输出 topic = `ss/<节点id>/out`**(由引用表(总线注册表)给，不自造命名)。
- **性能指标是功能属性，可共用**: 不同功能可指向同一可测指标(节拍/精度/成功率)，每条功能行都要能指到指标，
  指标必须**可测量且有判据与验证方法**(不要形容词)。
- **KPI 真源要顺着关系链取**: 能力(BO_)→产品特征(功能)→模块(节点)，一层层连，别按名字模糊匹配。
- **摆盘/插拔 = 两份独立文档**，同一套模板由配置驱动；单场景文档只列该场景启用节点，另注明「全量 N 个」。

**「输入输出测试报告」必须是真收发，不是登记核对**（实测口径，可照抄）:
- 逐功能 topic 做 **DDS 往返**: 发布/订阅用**两个独立参与者**(同一参与者内 writer→reader 是本地直投，测不出真实通道)；
  载体用一个已有 IDL 结构(如 `zmax::SSTest`)写探针；判据 `收到 ≥ 发出/2`。
- **订阅端必须挂单播配置**(`CYCLONEDDS_URI=file://<repo>/dds/cyclonedds_unicast.xml`)。不挂 ⇒ 走默认多播 ⇒
  与单播发布端互相发现不到 ⇒ 实测「收 0 条」的**假失败**(实测踩过: 修配置前 0/16 话题有流量，修后 6/16)。
- Cyclone API 名是 `get_matched_publications()/get_matched_subscriptions()` —— **没有** `matched_*` 属性;
  用 `getattr(obj,'matched_x',[])` 会静默返回 0 ⇒ 把「通道通」误判成「通道断」(实测 74/74 被误判成 0/74)。
- 注册但**本刻无发布端**的话题如实写「无流量(未起)」，**不许**用「已登记」代替「实测通过」。

**分档打包与投递**(大交付件的常规形态): 按场景各一档 + 平台/协议一档，每档自带 `README_<档>.md`(目标/实测/清单/复核命令)，
逐档 zip → 逐档发(文字摘要 + zip) → **逐档服务端回读核验**(bytes + sha256)。
飞书文件消息返回值里 **`message_id` 顺序是「文字在前、文件在后」**(文件那条紧跟在 `bytes` 之后)，
拿反了回读会报 `KeyError: 'file_key'` —— 核验脚本参数是 `<文字mid> <文件mid> <本地文件>`。

## 铁律九：配置单先行 · 一份文档覆盖多任务 · 未定义项不代填

**顺序固定：先配置单，再 SOR/交付文档。** 用户说「先有配置单」时，文档里每条任务要求都要能回到配置单：
`tools/config_sheet.py --task <任务>` 从在役真源扫出（画布/参数注册表/标定真源/点位台账），文档 §0 **逐份登记**
配置单文件名 + `sha256` + 画布 `md5`，读者可回读核对；配置单一起随包投递。

**一份文档覆盖多任务**（同工程不同任务，如两个插接类任务出一份 SOR）：
- 章节分两层：**任务级章节逐任务展开**（项目与场景 / 性能指标 / 作业要求(工艺技能序列) / 验收要求，每任务一组，用 `【TASK-xx】` 小标题分隔），
  **平台级章节共用**（采购范围与分工 / 功能清单与接口 / 数据平台 / 交付物 / 待商务项）。
- 实现：不要重写第二套文案 —— **复用单任务生成器的 blocks，按 h2 段切片合并**（`_slice(blocks, "3. 性能指标要求")` 取任务级段；平台级段取第一个任务的），
  再补两段本份文档独有的内容：§0 配置单真源登记、§末 **多任务差异对照 + 迁移不变量**（画布/话题/QoS/安全链不变，换任务只改配置）。
  同一口径只写一次，多份文档不会互相矛盾。

**表里要标每行来源，未定义项不代填**：
- 硬指标（成功率/节拍）行标注为**项目级要求**（对每个任务生效）；其余行标注来源 = 任务真源（`tasks.json` + targets/参数覆盖）或**模板继承项**。
  不标来源，模板继承项会被当成该任务的真源要求交付出去。
- 真源为 `null` / 未登记的项（如某任务插入行程未定义、场景卡片未登记）记「**待现场标定 / 采购附件确认**」并在正文点明；
  **绝不代填一个看起来合理的数值**，也不要用模板值冒充该任务的实测/真源值。

## 铁律九·补：立项/投标类材料 = 项目档案真源 + 导出器，缺口让工具自己报

立项材料(项目需求/验收指标/单价/销量/竞品)最容易变成"手写一版漂亮数字"。本平台已有机制是**填配置 → 生成**:
`config/platform/projects/<PID>.json`(项目档案) → `tools/project_profile.py --show <PID>`(合并+缺口) →
`tools/project_doc_export.py --project <PID> --check|--out`(立项文档/协议，成本与 ROI 现算不手写)。

- **先建骨架再问人**: 档案只写身份(客户/机型/站点/场景) + 每项待填值写 `"待确认"`, 然后跑 `--show`。
  工具会打出 `BOM 项 N · 缺口 M` 并逐条列(如 `commercial/price_schedule` / `market/acceptance`)。
  **把这份工具输出原样交给用户当"你需要提供什么"** —— 比你自己列清单可信, 且不会漏, 也不会多问。
- **overlay 语义 = 深合并, list 整体替换**: 档案里把某项写成 `"待确认"` 会**盖掉基线数字**。要的就是这个 ——
  新项目复用平台基线 BOM 时, 商务/市场段必须显式覆盖, 否则基线里泰国/其它项目的单价销量会被当成新项目的值算进 ROI。
- **商务三项绝不代填**: 单台金额、销量预测、竞品报价只能来自商务/客户; 没有就留 `待确认` 并在正文标注。
  代填一个"看起来合理"的价格, 一旦进立项材料就是编造, 比不填代价大得多。
- **预计时间要拆两段给**: ①技术侧(需求映射/验收指标/技术附件/成本测算/竞品公开信息) 给出可交付日期;
  ②完整包 = 商务三项到位后 1 天合并。回复里把"硬前提是哪 3 项"写出来, 别只给一个笼统总天数。
- 新建档案前先 `project_profile.py --list`: 已有同类项目就复用它的 `pid` 与 BOM 引用, 不要另起一个几乎一样的。
- **成本与 ROI 的口径不写在本技能里**: 分层回本 (A/B/C/D)、客户/我方双 ROI、成交区间 (floor vs ceiling)、
  首台与复制台毛利、模式选择, 一律按 `cost-roi-quote-modeling` 的算法出数; 本技能只负责把它的输出写成正式文档。
  立项材料里的回本年**必须带口径标签**, 不能只写一个最漂亮的数。
- 立项/方案册里被要求「补算力分析」时, 那一章不是 TOPS 参数表而是**20 ms 拍的时间尺度的账**(时间尺度表 → 单件拍数×前向
  → 同步串行的反证倍数 → 端侧档位 → 算力分工 → 瓶颈表 → 结论三句)。成篇定式与坑见 `references/compute-analysis-chapter.md`。

## 铁律十：Word/PDF 由 Markdown 派生 —— 走 `md → HTML → LibreOffice`

同一份正文**只维护 Markdown**，`.docx` / `.pdf` 是派生件（别手改 docx，改下一轮就被覆盖）。
LibreOffice **不能直接吃 `.md`**，中间必须过一层自带 `<style>` 的 HTML：

```bash
# ① md → html（自写渲染器，见下）
# ② html → odt → docx      ← 必须两步
# ③ odt  → pdf
soffice --headless --norestore -env:UserInstallation=file://<临时profile> \
        --convert-to odt --outdir <out> <doc>.html
soffice --headless --norestore -env:UserInstallation=file://<临时profile> \
        --convert-to "docx:MS Word 2007 XML" --outdir <out> <out>/<doc>.odt
soffice --headless --norestore -env:UserInstallation=file://<临时profile> \
        --convert-to pdf --outdir <out> <out>/<doc>.odt
```

- **`-env:UserInstallation=file://<临时目录>` 必须带**：否则并发的 soffice 抢同一个 profile，第二次调用会静默失败或挂住。
- **中文字体交给「系统字体族」，不要写死 ttf 路径**：CSS 用
  `font-family:"WenQuanYi Zen Hei","Noto Sans CJK SC",sans-serif`，LibreOffice 会用系统已装的 CJK 字体。
  reportlab 那条路（`docs_pdf.py` 一类）要求**指定一个 TrueType 文件路径**，且**不吃 OTF/CFF 的 Noto CJK** ⇒
  纯 md→pdf 用 LibreOffice 更省事；只有需要精细排版控制时才回 reportlab。
- **导出器写成能独立跑的脚本**（`--out` / `--check` 只校验不出文档 / `--json` 给调用方解析），
  GUI 按钮和命令行**调同一个执行体**，不要各写一套。
- **真源是活页面时不要强行走 md**: 交互式页面（三维工艺卡/看板/看板式报告）本身就是内容真源, 正确链路是
  前端 POST 卡片数据 + `canvas` 截图 → 服务端 `python-docx` 直接出 `.docx`（服务端只排版、不复制文字, 否则必然
  「改了页面忘了改导出」）。`python-docx` 的**中文字体必须显式设 `w:eastAsia`**, 不设就是等线/宋体。
  配方（路由 / 文档结构 / 回读与转 PDF 验页数 / 坑）见 `canvas-3d-scene-page` 技能里的 page-to-docx-export 参考文件。
- 🔴 **参考件本身就是 docx / 方案册时，也直接 `python-docx` 生成器，不走 md→HTML**：30+ 张表要精确列宽、表注、整表不跨页，
  md 派生到 LO 里这几样都控不住。生成器把数字与文案集中在顶部，`build()` 依次调 ch1..chN，改一次重跑即全册更新；
  **插章要连章号和表号一起重排**（`表 5-1` → `表 6-1`、后面各章顺延、正文里的「见表 X-Y」同改），手改 docx 必漏。
  落版体检跑 `scripts/docx_layout_check.py <docx>`（soffice→pdf→bbox：越界词数、逐页首行、表注是否孤立在页首、页数）；
  数字核验再补一层：写十几行脚本把真源表（pptx 的 `has_table` 行）逐行断言在 docx 全文中出现，
  比对前先归一化（去空格/千分位 / `20万` vs `20 万`），否则会把格式差异报成内容错。

### 自写 md→HTML 渲染器的最小规则（没装 markdown 库时）
- 行内**先 `html.escape` 再替换标记**：`**x**`→`<b>`、`` `x` ``→`<code>`、`*x*`→`<i>`。**顺序反了标记会被转义掉**。
- 表格：`|` 开头成行，**第二行 `---` 分隔行要丢弃**；遇到非 `|` 行要补 `</table>`。
- 代码围栏内**只转义不解析**；文档结尾补上未闭合的 `</table>` / `</pre>`。
- `@page { size: A4; margin: 18mm 15mm }` 控页边距；中文正文 10.5pt / 行高 1.55 观感稳。

### 现成的转换器 `tools/md2pdf.py`（别每轮重写渲染器）
- 仓库里已有通用脚本：`python3 tools/md2pdf.py --in a.md --out b.pdf --title "…" --subtitle "…"`。
  自带 A4 中文文档版式（h1 20pt 深蓝 + 2.4pt 金色下划线 · h2 14pt 左金竖条 · 表头 `#1F4E79` 白字 · 正文 10.5pt / 行高 1.58 ·
  `@page margin 18mm 15mm`）、表格/引用块/代码围栏/有序无序列表，并内置抠字自检。新文档先复用它，别再手搓一遍。
- 🔴 副标题要插在**主标题之后**：`pos = body.find("</h1>")` 再插入。直接拼在 body 最前面会跑到标题上方，读起来像页眉乱码。
- 自检退出码就是闸门：中文字 <200 或 markdown 残留非 0 返回 1，可直接串在交付脚本里 `&&` 后面。

### 出稿自检（必做，别只看「文件生成了」）
从产物里把字**抠回来核**：`pdftotext <pdf> -` 看中文是否成串（不是豆腐块/空白）+ 页数；
`zipfile` 读 docx 的 `word/document.xml` 去标签后核字数与关键串；**并核 Markdown 标记残留数为 0**。
🔴 **同题的多种格式不许共用同一个文件基名**：`…_5.50.D-R1.pptx` 与 `…_5.50.D-R1.docx` 在 `soffice --convert-to pdf` 后会
落在同一个 `….pdf` 上，后转的静默覆盖先转的 —— 实测 72 页的册子被 7 页的文字版 PDF 顶掉，文件大小正常、页数才发现不对。
做法：文字版/派生件加格式后缀（`…_文字版.docx/.pdf`），导出后**逐份 `pdfinfo | grep Pages` 与该件的预期页数比对**，
不一致就是被覆盖；交付说明的清单里也要把「同名不同格式」拆成两行写清。

## 铁律十一：引用型交付件 —— 照客户原文写，不照自己的理解写

交付物是「按客户技术协议/需求文件出的工艺卡、规格对照、应答表」时，内容是**引用**，不是创作：

- 步骤/要求条目用**原文句子**（只加粗机构名），一条对一条；每条细节句尾标**条款号**（`（2.1）`/`（2.3.2）`/`（6.1.2.2）`），读者能翻到出处。
- 🔴 **原文没写的绝不补**：力控阈值、缺陷类型枚举（划痕/污点/凹坑）、性能上限、更“合理”的流程图、自拟的可选方案（换机器人本体/换轴配置/改节拍）都不要。
  这类“看起来更专业”的补充一旦被识破，整份交付件的可信度归零 —— 用户会直接退回重写（原话：“不要按你假设的机器人写，遵守原文”）。
  协议里根本没有机器人、自己却加了一张“迁移到机器人”的卡，就是这件事的典型形态。
- 协议自己标注待定的项（`型号待定` / `功率【待确认】` / `设计评审阶段确认`）**照原样保留并原位标注**，不要替他填一个合理的数。
- 视图/示意图的约定（坐标系、1:1 示意比例、颜色含义）写在图注下或导出说明里，**不要写进图题或正文当作协议结论**。
- 交付前必跑**逐字溯源 + 自拟术语扫描**，比对基准是用户贴的原文，不是自己生成脚本里的字符串；命中的删掉。

## 铁律十二：PPTX 交付件 —— 先保“可编辑”，再过“版面三道闸”，最后挂预览

用户要的是**能自己改的 pptx**，不是导出的图片。同一份内容做幻灯时（分析报告、格局分析、汇报材料）：

- **台账只一份真源**（`roster.json` 这类）+ 生成脚本（`*_figs.py` / `make_pptx.py`）；脚本里不写死任何数字，
  改数只改 json 再重跑 —— 否则同一个数在表、图、正文三处各说一套。
  🔴 **改了「生成 json 的脚本」（`data_*.py`）必须重跑它本身**：只改 .py 不重跑，json 还是旧值，
  而图从记录重算 ⇒ 同一页里正文写「9 家」、图上写 10 家。verify 脚本要从 json **重算**关键计数，
  并在 deck 全文 grep 被取代的旧值（“只有 9 家”这类句子），命中就 fail。
- **每个 page builder 必须自己 `new()` 出这一页，不能接收上一页的 `s` 往里画**：接收 `s` 的 helper 一旦被调用方
  传入上一页的 slide，几页内容叠在同一页上，`len(prs.slides)` 比声明的 TOTAL 少（实测 33 声明 → 29 产出），
  **全程不报错**，每页单看都正常，只有数页数才发现。helper 只收内容参数、内部建页；保存前断言
  `len(prs.slides._sldIdLst) == TOTAL`，并把 TOTAL 同时喂给页脚页码函数。
- **`add_shape` 自带主题 `effectRef` 阴影**：只设 `shape.shadow.inherit = False` 不够，LibreOffice/WPS 仍按
  `<p:style>` 给每张卡片、每个色块渲染脏灰投影。要连 `p:style` 一起摘（`sh._element.remove(st)`，`st` 为
  `qn("p:style")` 节点），之后 fill/line 必须显式给 —— 不再继承任何东西。
- **`vertical_anchor` 收的是 `MSO_ANCHOR` 枚举不是整数**：`tf.vertical_anchor = 2` / `cell.vertical_anchor = 2`
  直接 `ValueError: 2 is not a valid MSO_VERTICAL_ANCHOR`，写 `MSO_ANCHOR.MIDDLE`。
- **表格单元按索引打包，错一位不会报错**：把 `rec[8]` 当 `rec[9]` 用，会把“综合判断”整段塞到“技术架构”
  表头底下，JSON outline 读起来毫无异常。生成后必须**读一页渲染图**，逐列核对该列内容与表头是否同一语义。
- **一页 N 张卡横排会把下半页留空**：5 张卡挤在顶部、下面 60% 空白。改 2 列 × 3 行、左图右文的横卡铺满
  12 × 5.1 in 正文区（`cw=(12.09-gap)/2`、`ch≈1.56`、图位 `1.24×(ch-0.22)`）；末页不足 6 张时把空格做成
  图例位，不拉伸卡片。
- 🔴 **配图位放真实产品照，不许用灰框占位**: 用户看到灰框会直接问「怎么没有实际的图片？是显示问题么」——
  「留个框他自己 Change Picture」这个假设不成立。确实拿不到图的少数卡片，**必须在框内写明缺失原因**
  （如「官网未公开 / 产品整机图」两行小字），绝不静默留空、也绝不拿无关图凑。
  抓图实测顺序（30 家覆盖 14 家）：①官网 `og:image`/`twitter:image` ②从 HTML 正则抠
  `img src|data-src|srcset|_next/image`，过滤 `logo|icon|favicon|sprite|qr|banner|placeholder`，
  按 `宽≥480 · 高≥400 · 字节≥35k` 卡质量 ③官网是纯 JS 站点（HTML<3KB 或 403/526）时改抓**非 SPA 的
  新闻站/经销商页**（这些 curl 能拿到真图）。
  ⚠️ 别指望搜索引擎图片接口：Bing/Google 图片在这条网络上是 JS 渲染 + 反爬（取回 112KB HTML 里
  一条 `murl` 都没有），Wikimedia 上这些厂商的产品实拍也基本没有 —— 试一次不通就换新闻站，别反复试。
  图统一处理成卡片比例（如 900×1125），`ImageOps.contain` 等比缩放后居中放白底，**绝不拉伸**。
- 🔴 **套用客户/公司模板 = 派生，不重写**: 已有能跑的生成器时，写个小脚本读旧 `.py` 做**字符串替换**
  产出新版本（配色常量 · `header()` · `footer()` · 表格表头填充/字色 · 图片位函数），每个替换
  **打印并断言 `s.count(old) >= 1`** —— 没命中就是模板漂移，否则会静默跑出旧样式还以为套上了。
  这样页数、结构、原生图表全保留，只换视觉壳，不会因重排丢页。
- 🔴 **客户直接把 `.pptx` 模板文件给你时，做法是「保封面 + 保内容母版 + 克隆母版页」，不是按它的风格重画**:
  打开模板 → 留第 1 页(封面) 与第 2 页(标题 + 整页大表格的内容母版) → 删掉模板原有其它内容页 →
  `clone(母版)` N 次 → 逐页换标题/填表。背景图、logo、页脚版权、页边距全部原生继承，不用猜配色。
- 🔴 **克隆幻灯片必须连 rels 一起复制并保持相同 rId**，只 `deepcopy(shape._element)` 的话，形状里的
  `r:embed="rId3"` 在新页 rels 里不存在 ⇒ **logo / 背景图静默丢失**（不报错，只是图没了，肉眼一看才发现）:
  ```python
  for rId, rel in list(src.part.rels.items()):
      new.part.rels.add_relationship(rel.reltype,
          rel.target_ref if rel.is_external else rel.target_part, rId, rel.is_external)
  for shp in src.shapes:  new.shapes._spTree.append(copy.deepcopy(shp._element))
  bg = src._element.cSld.bg
  if bg is not None:      new._element.cSld.append(copy.deepcopy(bg))   # 背景图也在 cSld 里
  ```
- **克隆完三件回读判据**：① 每页 PICTURE 数 ≥ 母版（封面 6 / 内容页 1 logo）；② 每页标题命中（模板标题常是
  AUTO_SHAPE 不是占位符，按「top<1.0in 且有文字」找、别按 placeholder 取）；③ 表格底边 ≤ 页脚 y
  （7.5in 页、版权在 7.11 ⇒ 底边 ≤6.9）。行高别用 `min(0.52, …)` 兜底，那会在表格下方留半页白���；
  按 `min(0.78, 5.55/rows)` 撑满正文区。
- **模板里的 logo/页眉优先用原生文字复刻，不裁图**: 模板的 logo 常是 layout 里的位图，抠出来分辨率差
  且不可编辑；用「黄竖条色块 + `ReinBee` 15.5pt 粗体深蓝」+ 右上灰色英文口号 8pt 右对齐复刻，视觉一致且
  用户能直接改字。模板原件在 `~/zmax_data/deliverables/模板.pptx`（ReinBee 汇报模板：白底 · 深蓝 `#1F4E79` ·
  明黄 `#FFC000` · 表头深蓝白字 · 页脚 `© ReinBee All Rights Reserved.` + 页码 · 封面右上黄蓝双圆 + 左下蓝点阵）。
  套完把配色常量也收敛：我方标识别再用紫色，改模板黄系深金 `#B37F00`（白底可读且不撞蓝黄）。⚠️ 深色/装饰圆叠上去会盖住英文 —— 封面单独画品牌行，别直接复用带英文的页眉函数。
- **极坐标/雷达图别用 `bbox_inches="tight"`**：轴刻度标签画在 axes patch 外侧，会被画布边缘裁掉一半。
  这类图存图不带 tight、靠 `subplots_adjust` 留边，2×3 网格 `hspace≈0.58`，否则上排底标签撞下排标题；
  轴名用短词（场景/模型/数据/本体）。
- **像素复检要独立**：`soffice → pdftoppm -r 110` 出页图，交给独立视觉复核，问题清单枚举（溢出/重叠/行高/断词/豆腐块/表头与内容错位/同页数字自相矛盾），
  允许逐页回 `Pn: OK`、并要求像素量化；改完只复检改动页。判**渲染后的页**，不判源图。
  **30 页以上别顺序看**：把 PNG 切成三段并行派三个**只读**子代理，要求回 `页码｜位置｜缺陷｜严重度`；
  全回齐后一次性批量修 —— 同一个缺陷（一个阴影、一列宽度、一处标签偏移）通常在十几页重复出现，
  按单页报告修会重生成三次。
- **可编辑性 = 文字是 textbox、明细是 `add_table`、图是 `add_chart`**：标题正文用 `add_textbox`、明细用
  `add_table`、口径写 `notes_slide`。**数据图必须是原生图表对象，不能是 matplotlib 出的 PNG** ——
  「图里只放图形、能改的字都放文本框」这条不够：用户拿到 deck 第一件事是删行、改数、换配色，
  PNG 让他从零重画，必被退回（原话：「PPT的图表，要可以编辑。我看你的图表是图片，我无法二次编辑」）。
  `add_chart` 为每个图表内嵌一份 XLSX，右键「编辑数据」真能改；判定：
  `unzip -l out.pptx | grep -c 'embeddings/'` 等于图表数（少一个就说明那张图没带工作簿）。
  反过来，**2×2 矩阵、分档清单这类没有数据表可编辑的判断图，用形状+文本框**（能拖、能改色）比 chart 更自由。
  逐图配方（条形/柱状/折线/雷达、对数轴、逐点分色、定性分档堆叠、圆点标签不压点）见
  `references/native-charts.md`。
  中文必须同时设 `a:ea`（`run.font.name` 只管西文），否则字形回落成主题字/方块。
- **插图永远 contain + 夹页内**：给 `w` 和 `h` 会拉伸；只按 `w` 推 `h` 会让高图算出 `y+h > 页高` 被裁。
- **图的比例是版面契约**：`bbox_inches="tight"` 会把坐标轴外的 annotate/注脚扩进画布，横版 figsize 可能存成竖版，
  contain 后被压成窄条并撞上下面的表格。锁 xlim/ylim、文字留轴内、存图不带 tight，并用 `PIL` 断言实际宽高比。
- **碰撞自检要三类**：text↔text / text↔marker（散点压标签）/ text宽↔patch宽（段内标签溢出色块）；只比文字对文字会漏。
- **回读断言再交付**：逐 shape 验 `left/top/left+width/top+height` 不越页（通顶装饰条按 shape 名白名单跳过），
  并打表格底距页脚（> 约 0.2 in 余量）；表格离页脚太空就抬 `row_h`，不塞废话。
  🔴 **形状边界过 ≠ 渲染没过**：`add_table` 的 row height 是最小值，声明高度 6.06+1.20=7.26 完全落在 7.5 页内、
  形状断言全绿，渲染出来却已经压到 6.90 的页脚线上。落页面的真判据是**页图最下墨 vs 页脚线**，不是 shape 边界。
  扫页图前先掩掉两处结构假信号：左侧 0.16 in 装饰竖条（不掩则**每页**都报「左边缘大面积着墨」）、
  整条页脚带（页脚注文字本身落在页脚线下 0.2 in，不掩则每页都报「正文压到 7.19」）。
  页底只剩两三行纯数字的冗余小表别硬压行高，**换成「小标题 + 一行文字」**更稳也更像人排的版。
- 🔴 **目检只给方向，收敛靠像素量化**：视觉复核会说「文字偏上，上下留白 3:1」，但按它的建议直接改色块高度容易过头 ——
  实测把衬底块收 0.05 in，文字就被顶到块底只剩 3px。定式：用 PIL 扫页图，
  ① 按底色容差匹配衬底块的行范围 `abs(im-bg).sum(2)<10`，② 块内 `>60` 算暗像素并**排除左侧竖条装饰**
  （否则每行都被判成文字行），③ 取文字行范围算上下留白，**比值落在 0.7~1.5 且下留白 >8px 才算过**。
  实测可达 21px/21px（比 1.00）。配方代码：`references/editable-pptx-delivery.md`。
- **衬底块高度由渲染后的文字像素反推，不要按 inch 估算**：改块高或改文字框 `y` 都会让文字重排，
  改完必须重新 `soffice → pdftoppm` 再测一次；同一个块连续调三轮才平很常见，别在第一轮就宣布完成。
- 🔴 **同族表格用同一套列宽比例**：相邻两页表格首列差一寸（1.05 vs 1.38 in）就会让其中一页的长标签
  断成孤字行（「代表（本报告样」+「本）」），客户一眼就看到。首列宽度按**最长标签**定，同族页复用同一组列宽。
- **插页要连页码/章节号/文件名一起改**：`header(..., n)` 的页码、`TOTAL`、文件名里的页数都是硬编码；
  插两页后必须顺延后续页的 `n`、改章节 kick（如原「第 7 章 · 策略」→「第 8 章」）、改 `TOTAL` 与新文件名。
  插入位置按**章节逻辑**排（技术选型在策略章之前），不要图省事追加到末尾 —— 否则会出现
  「第 7 章策略 → 第 7 章技术选型 → 第 8 章策略」这种乱序，而页数断言照样通过。
  改完 `grep '^header(' ` 把所有页的章节号+页码打印一遍，回读顺序。
- **能把 pptx 挂进控制台/网页预览**（用户可能明确要求“在评估分析里直接打开”）：服务端子进程转图、
  缓存键 `(文件名, mtime, size)`、原 pptx 当附件下载、缺转换工具要**报错不出空画廊**。
  完整配方（含 PyQt 薄壳与路由）见 `references/editable-pptx-delivery.md`。

## 铁律十二·补：产品解决方案 deck 落哪 + 三道版面闸的顺序

**放置按「给谁看」定**（docs 库是七星结构，一份交付件只归一颗星）：
- 对外/客户产品方案 → `docs/1-天枢-产品边界/deliverables/<主题>_<交付版号>_<YYYYMMDD>.pptx`（+ 同名 `.pdf`）。
- 内部技术方案（讲架构/接线/模型）→ `docs/6-开阳-工程落地/`。
- 大体积成片/中间产物 → `zmax_data/deliverables/`（不进 git）；要给客户的定稿再拷一份进上面的交付目录。
- 生成脚本进 `tools/build_<…>_deck.py`，**成品不手改**：改内容改脚本重跑。

**变体下架与暂存目录清理的次序**（用户说「这份错了，删除」/「不用保存了」时）：
1. **先判唯一副本**：对要删的名字全仓 `md5sum` 扫一遍（跳过 `.git`、venv、`external`）；同名同大小仍要核 md5 —— 大小相同而 md5 不同是另一次导出，留新的那份。
   仓库里的 `_cleanup_*` / 暂存目录常存着交付件的**唯一副本**，整目录 `rm -rf` 会把三视图、作业姿态这类唯一成片一起删掉。
2. **删正式目录里的错版；没被点头的旧件不要跟着删**：挪 `zmax_data/deliverables/<批次>_未采用/`，报数量 + 体积，让他一句话定。
3. **删完扫引用**：`grep -rln <文件名>` 工具/脚本/文档 —— 硬编码文件名的生成器会把文件生回来。
4. **正式目录只放他认可的变体**：还在商量 / 未点头的那份留在数据盘，别先进交付目录。

**版面三道闸，廉价在前**：
1. **生成脚本自检**：断言 `len(prs.slides._sldIdLst) == TOTAL`（页数少一页是最常见静默错）。
2. **几何预检**（秒级，先跑）：按 CJK 全宽（汉字 1.0em / 数字 0.55 / 大写 0.62 / 其它 0.52）折算每段行数，
   与文本框 / 表行高度比 —— 覆盖「标题两行塞进 0.34 in」「表格行高被 `add_table` 当成最小值」这类溢出。
   本平台已有 `tools/check_deck_fit.py <pptx>`（溢出候选应为 0），新 deck 直接用它，别每轮重写估算器。
3. **渲染后验**：`soffice --headless --convert-to pdf` → `pdfinfo` 核页数 → `pdftotext -layout -f N -l N` 核中文成串、无豆腐块。
   要判「页图最下墨 vs 页脚线」时再上 `pdftoppm` 像素口径。

**把既有参数册升级成「解决方案」**（用户说「升级成解决方案 / 你再确认一遍准确性 / 放哪儿你决定」时）：
- 骨架就是页序：`封面（方案名+版本+四条编制依据+边界声明） → 方案总览（四张卡：构成 · 节拍 · 能力 · 口径与边界 + 一句话总述 + 读册顺序） → 外观/三视图/尺寸表/结构参数 → 节拍甘特（全轮 + 稳态放大） → 能力节点（数据流图 + 功能表） → 验收口径与边界（指标｜数值｜口径｜复核位置 四列表 + 未闭环清单）`。
- **页序重排用 sldIdLst，不要在生成器里重画**：新页 `add_slide` 到末尾，再按目标顺序重排 ——
  `lst = pr.slides._sldIdLst; ids = list(lst); [lst.remove(e) for e in ids]; [lst.append(ids[i]) for i in order]`。
  重排后回读每页首行标题核对顺序，并同步页脚页码与「第 N~M 页 = 什么」的读册说明。
- **准确性靠脚本，不靠通读**：`tools/verify_<方案>_deck.py <pptx>`，每条 =（项, 真源现算的值, PPT 里必须出现的字符串, 真源文件），打 PASS/FAIL 表并对 FAIL `sys.exit(1)`；默认路径指向新交付件，重跑就是复核。
  🔴 **每条必须是「真源重算 + 断言格式化后的值」；只断言某个子串在册里出现过，等于没验**。子串检查在「同页两个数自相矛盾」「分项加不到总数」时照样全绿（实测一本 32 项全 PASS 的册子里，节拍账摊错、甘特画错窗口、92% 与 91% 两页各说一套）。检查项写成数值/区间/占比的格式化串（`'拔 %.2f~%.2f' % (min,max)`、`'%.0f%%' % pct`），真源一变就必须改数字，改不动就说明算法没接上真源。
  🔴 **册里那句「N 项逐条回真源重算，当前 N PASS / 0 FAIL」不许手写，也不许在生成器里当常量**：每加一条检查它就过期（实测 22 → 32 → 37 → 40，四轮全对不上）。做法：构建脚本 **跑一遍 verifier、解析 `检查 N 项` 与 `结果: X PASS / Y FAIL` 后回写那一框**（跑两轮收敛），并在 verifier 末尾加**自洽闸**——册内写死的三元组 ≠ 本次实跑就 `sys.exit(1)`。自洽闸放在 summary 打印之后、不进 `results`，否则就是自己数自己的死循环。
  🔴 **每件/每段的时间账必须自下而上对平**：`Σ(动作块时长)/件 + 块间走位/件 == 节拍`。要靠第三个「移动/衔接」填充项才凑得上，就是分项算错了（实测把 2 颗补插摊到 4 件写成 1.41 s/件，真值 2.82；于是又凭空补了 2.31 s 去凑总数）。分项与总量都给 3 位小数，让相加在页面上肉眼可核。
- 旧版**归档不删**（`zmax_data/deliveries/<批次>_未采用/`），交付目录只留一套当前版。

**用户正开着这份册子看的时候重建（他说「PPT 打开，我看看」，之后又要求加页）**：
- 关旧看新：优先按**窗口标题**关掉你自己刚打开的那个只读浏览窗
  `DISPLAY=:0 wmctrl -c "<文件名> — LibreOffice Impress"` —— 不留 `.~lock` 残留、也不弹 Document Recovery；
  确认 `pgrep -c soffice.bin` 为 0 再重出。要连别的 Impress 窗一起收才用 `pkill -x soffice.bin`。🔴 **不要用 `pkill -f soffice.bin`**——`-f` 匹配整条命令行，会连正在执行这条命令的 shell 一起杀掉（实测命令返回 `exit -15`，后面的重开全没执行）；按 PID 杀也行。
- 🔴 **重出前的检测信号**：交付目录里出现 `.~lock.<文件名>#` = 这份 pptx 正被打开。覆盖后**旧窗口里按保存会把新件盖回去**
  所以要么按上一条关旧看新，要么明确告诉用户「关掉重开、别在旧窗口保存」——不要沉默地重建。
  收不了窗口（不是自己开的那个、或没有 wmctrl/视觉工具）时，**先把同版 PDF 打开**让他马上看到新版，并说清「pptx 关掉重开才是新版」；
  别让人对着旧窗口等你解释。
- 🔴 **`kill` 掉旧实例后它不一定清 lock**：`.~lock.<名>#` 还在就 `rm -f` 掉再启动，否则新实例会以只读/恢复态打开，
  用户看到的是旧内容还以为你没重建。启动后必须回读三件：`pgrep -a soffice.bin`（新 pid + 打开的是新路径）、
  `xdotool search --name Impress`（窗口真起来）、`.~lock` 的 mtime 是刚才（新实例已占住文件）。
  报告时说「旧 pid → 新 pid + 新版第几页是什么」，不要只说「已重启」。
- 覆盖一个正被 LibreOffice 打开的 pptx 后再启动，会弹 **Document Recovery** 挡住新窗口 ⇒ 点 **Discard All**（丢弃恢复，直接加载新文件）。没有视觉工具时定位按钮：`scrot -o /tmp/s.png` → `tesseract /tmp/s.png stdout -l chi_sim+eng --psm 6 tsv` 取每个词的 `left/top/width/height` → 算中心 → `xdotool mousemove X Y click 1`；点完 `wmctrl -l` 核窗口标题，确认打开的是新件而不是旧恢复副本。
- 重开用 `terminal(background=true)` 起 `soffice --impress <绝对路径>`（前台会一直挂着；不要用 nohup/setsid 包一层）。
- 告诉用户看第几页时给**页码 + 该页改了什么**（「第 15、16 页：L2 内部 65 条 + 层外 53 条」），不要只说「已重开」。

### 节点/清单类页面：名称逐字真源，生成器里禁手写标签
- 节点集按真源的**分组带成员**取（`row_bg` 的 `y .. y+h` 区间取带内节点），不要用自己猜的 y 数值区间；真源里放着的节点（如 `🌍 物理世界` 环境实体）不要按自己的判断静默剔除 —— 要么照画，要么在页面上写明剔除理由与数量。
- 名称一律 `n['name']` 逐字写入（连 emoji 一起），**生成器里不许出现手写的简称/标签**。判据：用 `search_files` 全仓搜该串，只命中你自己的生成脚本一条 ⇒ 就是自造的（实测把画布名 `⚙️ 动作执行器 (L2 收口 · 授权/闸/到位)` 写成 `⚙️ n_exec 授权·闸·到位`，用户一搜就穿）。
- 自检要两条一起断言：① 计数（总数 + 每带分布）；② **名称逐字一致** —— 真源每个名称都 `in` deck 全文，缺一个即 fail。只对计数会漏掉「数量对、名字错」。
- **输入输出块图页（用户说「描述不要那么多字，要有输入输出框图，用图标识连线关系」时的定式）**：
  三列 = 上游方块列 → 左母线 → 本节点方块 ← 右母线 → 下游方块列；方块两行 `端口 名字` + 连线 label，描述压到一行（≤70 字）。
  连线用 `add_connector(MSO_CONNECTOR.STRAIGHT)`，**python-pptx 没有箭头 API** ⇒ 往 `a:ln` 里塞
  `a:tailEnd {"type":"triangle","w":"sm","len":"sm"}`（`ln.append` 即可，无异常但没箭头就是没塞进去）。
  每侧最多 8 块，多出折成「… 另 N 条」；首行字数按比例缩字号（>18 字 ×0.86 / >24 字 ×0.74），
  **绝不截断节点名**（自检按名字逐字核）。改版式后必须同步 verifier 里靠正则在页内找的句式，否则静默 FAIL。
- 🔴 **逐节点页的页序 = 信号流主线，不是图层坐标/深度**：起点取「下游只剩反馈边的节点」（链末端），之后每步**只走主输入**，
  走到没有上游为止，最后补旁支。主输入打分：`in1` +2 · 连线文案含 动作命令/真下发/段表 +3 · 含 只喂渲染/旁路/回显/默认关 −3 ·
  同分才用画布 y/x 做 tie-break。按「离源头深度 + 坐标」排会把技能支线插到执行器前面 —— 用户会当场退回（「执行器之前应该是动作执行器，你排序搞错了」）。
  建完把前五行打出来对一遍（`01 末端 → 02 主执行 → 03 它的上游 → …`）。
- 🔴 **用户点名「某节点放到 0X/31」时，加锚点表钉位置，不改打分函数、不手改 PPT**：
  `PIN_POS = {"<nid>": 5}` 在 `chain_order()` 末尾 `_apply_pins(order)` —— 只 `pop` 该节点再 `insert(pos-1)`，
  其余节点相对顺序不变（改打分权重会把本来对的十几页一起打乱）。锚点是页序真源，换节点只改一行再重出。
  钉完必须回读：① 1..N 编号连续无缺页（正则抽 `L2 链路 (\d+)/(\d+)` 逐页 dump）；② 目标页标题等于意图的节点；
  ③ `verify_*_deck.py` 仍 0 FAIL。
  🔴 键是**画布节点 id**（`ssest` / `n_geoplan` / `ssobs`），不是中文名；节点必须在该层的节点集合里，否则锚点被**静默跳过**、
  deck 照样生成成功并自检全绿（最容易误判成已生效）。**重建前先在内存里算一遍页序**，打印 `N-3..N+3` 并断言 `order[N-1]==<id>` ——
  重建要关掉用户正开着的窗口再重开，顺序错了等于白折腾一趟。
  页数换算：L2 逐节点页首张固定在第 19 张（母版 16 + 封面/总览/验收 3）⇒ 第 k 页 = `19+k-1`；用 python-pptx 读该页
  **首行**断言 `L2 链路 k/N · <名字> · <id>` —— 别目检，也别「全文搜名字」（同一名字在总览页/母版页也会命中）。
  同一天被连续要求搬好几个节点时，**每次只加一行锚点**、算完序再重建；别去改已有锚点值或打分权重（会连带动已定稿的页）。
  🔴 **钉位必须落在两处共用的同一个排序函数里**：层首页的节点表（`layer_intro_page`）和逐节点页（`add_layers`）
  各自调一次 `chain_order` 时，只在 `add_layers` 里插钉子 ⇒ 逐节点页已对、**层首页表格仍是旧顺序**（实测「流形引擎」排在表里第 6 行）。
  做法：抽 `_ordered(lv, ids, links)`（`chain_order` + `PIN_HEAD[lv]` 前置），两个入口都调它，改完回读层首页表格首行与逐节点页第 1 位是否同一个节点。
  🔴 **他说「把这个节点放到认知层第 N 位」时，默认指册子页序，不是画布坐标**：他正看着这份 PPT，直接改 `PIN_HEAD`/`PIN_POS` 重出即可；
  动画布 JSON 会被当场退回（「没让你改画布，我说的是 ppt」）。已经动过画布就**先还原坐标并说明已还原**，别让两处都变、也别只回一句「已经改了」。
  他说「第 1 / 18 位」这类带总数的说法时，以册子里的实际页数回读为准（实测认知层 18 页，而画布同一行只有 14 个节点）——数字对不上就说明你数的是另一个对象。
- **一次要钉一串（「SK01~SK08 按顺序排 06~13」）就把整串写进锚点表一次性钉**，`_apply_pins` 按目标位升序 pop+insert 即得精确位置；
  只钉一个会把被挤走的支线插进主线（把物理约束钉到 5，技能④就落到 6、安全边界退到 7）⇒ 要么顺带把邻居也钉，要么在汇报里点名这个后果，别让他自己发现。
- **技能页横带「记忆输入 / 补偿」定式**（用户说「按顺序讲 SK01~SK08，要有记忆的输入和补偿」）：块图区压到 `A1=4.55`，
  横带 `(0.55, A1+0.10, 12.22, ~1.45)`，页脚 `FY=6.12`（与开关带同一套几何）。左半 = 记忆输入（通道 key/r/L/单拍限额/轴速/节拍 + 轴起终点 +
  条目数 real/geom + 标杆桶与命中 + 点位数），右半 = 补偿（偏差 p50/max/越界拍 → 切外归零+回中 · 物理闸削因拍数 · 偏差去向 · 到位判据 · 回填）。
  数据全部回真源现取（记忆库 corridors/champs + `skill_calls.log` 尾部聚合，GB 级日志只读尾 4MB），**建页时一律不造数**。
- 🔴 **空值要有自己的词，不能写 0、也不能省略**：本段无通道条目写「缺失，不许当 0」；本轮日志无该段写「本轮无实测记录（不填假数）」；
  标杆无该阶段桶写「0 桶」并保留。省略或填 0 会被读成「已达标/已覆盖」。
- **代表条目按语义挑，不按样本数最大挑**：按 n_poly 最大选会把「接近」选成「槽→孔」那条，读者会以为 SK01 是搬运；按阶段语义定形状（抓取系槽→槽 · 转移槽→孔 · 对位/插入/完成孔→孔）。
- **小面板塞进已有版面后，用「行带剖面」判有没有叠字/溢出**，比看图可靠：在面板矩形内逐行数暗像素（`<160` 记墨），
  连续有墨行并成一条带 ⇒ 条带数 = 文字行数，每条带高度应≈单行（多出一截就是折行叠字）；
  再断言「面板下沿与边界之间 0 墨」「面板与上方框之间 0 墨」。带数比预期多一条、或最后一条越过面板底边，
  就是文案该缩短（不是把面板加高 —— 加高会撞页脚）。缩字后重 `soffice→pdftoppm` 再测一次，别按英寸估。
- **页上要放跟画布同款的开关时**（用户说「要跟画布一样有两个开关」）：画**拨杆**（胶里+白钮，开=绿钮在右 / 关=灰钮在左），
  不画勾选框、不堆文字；状态**读真源**（如 `zmax_data/ss_live/exec_switches.json` 的 `ar_scene` / `real_auth`）并标
  状态时间 + 刷新龄；开/关**两种含义各写一句**，不能只写一边。
  🔴 新鲜度阈值必须与**消费方同口径**（服务端 1800s 就写 1800s）：写 300s 会让页上半路报「已过期/读不到」，而开关其实仍生效。
  🔴 先问清两个开关是互斥还是**可同时开** —— 默认按「独立、可同时开」写文案，别在页上/代码里自作主张加互斥。
- 汇总卡片打印「总数 N（A 2 / B 6 / …）」时断言 `sum(分解) == N`：分解加不到总数（实测写成 30 个但分项只有 28）在页面上就是自相矛盾。
- 表里放「实现文件 / PURE」这类派生列时，`^SOURCE` / `^PURE` 的正则必须带 `re.M`（不带只匹配文件首行，静默全空）；查不到就显式写 `SOURCE 未登记`，不写空。
- 🔴 **「画布上有这个节点」≠「这个节点在驱动产物」—— 能力页必须把两者分开标**。判据是**写产物的调用点**，不是节点注册表：全仓搜产物文件的 writer（如 `grep -rn 'import ar_bridge' src/` 只命中两个 impl ⇒ 只有 `n_moveit`(plan 分区) 与 `ssact`(exec 分区) 每拍写 `ar_cmd_chain.json` 给 AR 渲染虚拟臂，其余 N 个节点画布上有、也在跑，但不写该文件）。
  页面做法：给真写产物的那几张卡片加角标（如绿色 `AR`）+ 图注写明「只有 M/N 个节点每拍写 <文件>，其余不写」。不写这句，用户下一句就是「这一层实际输出画面么」——答不上就是夸大。
  另附一条现状口径：画面里跑的场景要写清是不是**方案里那一段**（实况链可能跑的是别的任务/点位，不是甘特图那段循环）。

### 母版与重建链（清了交付目录不能断重建）
- 旧交付件被「归档到未采用」后，指向它的构建脚本立刻失效 ⇒ **内容母版单独放** `zmax_data/deliveries/母版/<名>.pptx`，各构建脚本（节点页 / 甘特页 / 方案册）都从母版派生，交付目录只放成品。
- 每个构建脚本幂等：先 `reset_deck(pr, keep=<母版页数>)` 再追加，重跑不叠页；派生+重排后再跑一次 `verify_*_deck.py`（默认路径指向成品，重跑即复核）。
- 🔴 **重建链是三步、顺序不能换**: ① 层页构建器（把 层全景 / 连线页 / 功能表 重写进母版，全部从画布现算）
  → ② 方案册构建器（母版 + 封面/总览/验收 + 逐节点块）→ ③ `verify_*_deck.py` 必须 0 FAIL。
  只跑 ②③ 时, 册里的「L2 层连线 · N 条内部连线」仍是**母版里的旧数**（实测 73 而画布真源 65）, 而逐节点页与页序全对、
  自检只报这一条 ⇒ **别去改判据或逐节点页, 先重跑 ①**（母版也会被整体重写, 跑前 `cp -p` 到 `zmax_data/backups/`）。
  判据：先跑一遍旧册的 verifier 看这条 FAIL 是否**本来就红**, 再看新册 PASS 数是否回升 —— 别把陈旧计数当成自己的改动改坏了。
- **同名成品会在三处并存**（`docs/…/deliverables/`、`zmax_data/deliverables/<批次>/`、`zmax_data/backups/`）⇒ 重出后同步数据盘同名副本并
  `md5sum` 两份对拍, 只更新一处 = 用户打开的还是旧版。
  🔴 **重出前先读生成器里的输出路径常量**（`NEW_DECK` / `DIR` / `OUT`）：生成器常写到 `docs/1-天枢-产品边界/deliverables/<主题>/`，
  而用户打开的是 `zmax_data/deliverables/<日期>/` —— 只跑构建，用户那份根本没动，你会对着旧文件反复验证「没生效」（实测连验三轮才回头查常量）。
  判据：构建后 `md5sum` 两份**不相等就是分叉**，`cp -f` 同步到用户打开的那份，再 `md5sum` 相等才重开并汇报。问「打开刚才写的 PPT」时按 mtime 找最新件
  （`find ~ -name '*.pptx' -newermt '-14 days' -printf '%TY-%Tm-%Td %TH:%TM %p\n' | sort -r | head`）,
  别按文件名里的日期或目录猜。

**数字口径**：同一指标有多种算法（UPH 通道 / 闸门 / 发布）时**三档都摆出来并注明对外按最低那档报**，
只报最好看的那个是对外材料里最容易被现场复测打脸的地方；目标值 (目标) 与实测值分开标，绝不把目标写成实测。
🔴 **产能数（UPH / 节拍）由段表求和得到的只是「理论值」，必须在同一页写明这一点并给保证路径**：
- 段表口径 = 段内匀速 + 段间无缝衔接、未计加减速 ⇒ 同页给出直线段速度**峰值 / 中位**（实测 631 / 207 mm/s，允许区间 1~1000）作为可行性佐证，别只给一个漂亮的 UPH。
- 同一页写「要保证 X 需：真机连续 ≥N 件实测循环 + 检测耗时 P95 + 停留实测」。用户问「X 保证么」时，答案只能是「段表能排到，未实测」，并指出最大变数（如五点 AOI 占单件 46%、停留已贴 `dwell_max` 上限）。
- 这套「理论值 + 硬约束 + 保证所需实测」三件写全，方案册才经得起现场复测；只写 UPH 数字等于替用户向客户做了他没做过的承诺。

**外形/结构图必须来自产品自身的形态定义**：方案里画「机器人长什么样」时，先去产品自己的 3D 场景定义
（AR 页面常量、场景 JSON、仿真 env）把部件与安装几何抄出来 —— 产线本体常是**混合机型**
（左右双臂 + 顶视相机立柱 + 底盘箱体 + 轮），只按一条臂的 URDF 出图会被一眼打回。
渲染管线（STL 单位 mm/m、正交 z-buffer、相机轴向导致整图上下颠倒、标注被画布裁掉、中文豆腐块）与自检判据
见 `references/robot-outer-shape-rendering.md`。

## 铁律十三：对外 PR / 融资稿 —— 借竞品稿的骨架，只填自己的实测数

用户贴一篇竞品融资稿 + 一句「参考这个写一篇我们的」时，要的是**同款叙事节奏**和**我方基本面**，不是改写竞品。

- **骨架照竞品的叙事顺序搬**（画面化痛点开场 → 市场缺口 → 产品三件事 → 技术壁垒 → 为什么是现在 → 团队与愿景 → 收在一句金句），
  但每一个数字、每一句判断换我方的真源，绝不把竞品的数字/客户/团队顺下来。
- **三块能力要各配一句「对客户意味着什么」**，不堆名词。工业具身智能的常见三件套是：本体（能感知能受力）· 全技能智能体（一道工序一个大脑，
  换产品不用重写程序）· 多模态数据采集系统（真实产线的数据飞轮）。每块都用「以前怎么做、现在有什么不一样」讲。
- **精密操作段落用一条真实动作链串参数**：抓取 → 对位 → 插入 N mm → 力上限 N → 检测 N 项 → 良品/NG 分流，
  再落到三个真难点（准：来料会偏所以要拍-算-动-再拍；稳：力超限要退回来重新找角度，示教机器人做不到；可追溯：力曲线与检测结果留档）。
- 🔴 **参数全部标注待研发回签**（如【研发确认修订后定稿】），正文与表格逐处标；研发签完再统一去掉出对外版。
  没标就被当成对外承诺，签不回来要返工整篇。
- 🔴 **融资额 / 投资方 / 创始人姓名 / 客户名 / 专利数一律不编**：用 `【…待披露】` 占位，文末给一张「待确认清单」逐项列出。
  这几项是新闻稿最容易被追问的地方，编了就是埋雷 —— 用户对真实性零容忍。
- 交付时把「待确认清单」原样给出，并点明**哪一两项阻塞二稿**（通常是金额口径与创始人实名），不要列长选项。
- 成稿同时落 `.md` 源 + 派生 PDF，两者放同一交付目录，改完重导即可。

## 铁律十四：规格/参数页 —— 每条数字对到真源，对不上的删

用户说「保证所有参数的真实性，不确定的都删掉」时，要的是**逐条溯源**，不是通读校对。四类处置，别只分对/错：

1. **真源吻合 → 留**：质量/行程/力矩/角速度/腕偏置/法兰偏移对 URDF 与 `config/robot/zmax_robot_spec.json`（连 `totals.link_mass_sum_kg` 一起用）；台面/箱体/轮/相机立柱/FOV 对 3D 页常量；槽口/槽高/料盘尺寸对场景 XML。
2. **写错但真值可得 → 改正，连单位标签一起改**：常见形态是列头写「(mm)」而单元格填的是米（`0.3` 实为 `0.328`），或常量被四舍五入（`0.1` 实为 `0.136`）。改完把列头补成「(mm, base 系）」，否则读者按毫米读一列米值。
3. **无真源 → 删**：「作业包络 1750×1900×1452」这类既无 meta 留档、按同口径复算又算出 1250×1600×1448 的，整组删（含正文里引用它的每一页）；常量声明了但代码从未引用（只在常量表里躺着、不参与绘制的 `leg:0.045`）⇒ 由它派生的「4 条 45×45」也删。
4. **语义断言必须复算，数值一致不算数**：q 值 FK 复算出的法兰坐标与文中对得上一位，但到「1 号槽」实测差 700+ mm ⇒「对准 1 号槽 / TCP 误差 0.00」是假的，删断言、留可复算的数并标注「URDF FK 复算」。
5. 🔴 **判「无真源」前必须换第二个口径复核一遍，否则会删掉真参数**：先用**几何属性/尺寸**把真源数一遍（按 geom 的 `size` 统计槽口数），而不是按名字正则（`_槽\d+` 只匹配到一部分命名）。两种口径对不上，说明是你的取数方式太窄，不是数据不存在。
   实测：料盘「3 组 × 14 槽 + 废料盘」按名字正则只数到 13 个槽 ⇒ 被当成「无同源」删掉；按 `size=36×42` 计数是 **42 个（3×14）**，参数本来是真的。误删正确参数比留一个没核实的数代价大。
   每条删除/修正项都要落进**自检脚本的断言**（`verify_*_deck.py` 里断言该字符串必须存在 / 不得存在），下次改版重跑就能挡住复发。

收口：改完 `soffice --headless --convert-to pdf` 重出派生件（否则 PDF 还是旧的），`pdftotext` 全文检索被删数字与被删措辞残留为 0、页数未变；改版前原件备份到 `zmax_data/deliveries/_bak/`。

## 百页级技术白皮书（实测 116 → 209 页）

要 100+ 页技术 PPT 时**不要手写 pptx**，用三件套：
- 样式库 `tools/deck_lib.py`：cover/section/bullets/formula/table/timeline/layers/cards/bigstat/quote，深色工程风 16:9。
- 内容模块 `tools/deck_content{1..N}.py`：每条 dict 带 `ch="3.2 L2 感知"` 章节号；builder 按章节号排序，
  所以**补充页可以后写，自动落到正确章节**（cover 要特判 -1，section 用 num，附录按字母，结语 9.0）。
- 构建 `tools/build_tech_deck.py`：改内容只改数据，重出全册。

**排版验收用几何不用眼**：`soffice --headless --convert-to pdf` → `pdftotext -bbox` → 解析 word bbox：
1) `xMax>页宽-4` 或 `yMax>页高-3` = 出血；2) 正文 `yMax>493pt`（7.5in=540pt，页脚 500pt）= 撞页脚；
3) 两词 bbox 重叠 >35% = 压字。三项全 0 才算排好（希腊字母重音符号会有假阳性，可忽略）。

🔴 **再加一道粗密度闸**：`pdftoppm` 出页图数墨占比（像素 `<200` 算墨，先掩掉页脚带与左侧 0.16 in 装饰条）。
表格页/公式页天然落在 30%~50%，**别当成缺陷去拆**；只有 **>60%** 才是「整页糊住」，回去减行或拆页。
这条只抓糊、不抓压字——两者阈值不同，用同一个阈值会把每张表都报成问题。
中文字体写 `Microsoft YaHei`（Linux 上 Noto CJK 自动替代，Windows 直出）。

**内容纪律**：每页一个技术点；有数字必标出处文件；**负结论（未通过的消融）必须保留**——删掉它验收时一问就穿。

**密度硬规则（都是撞出来的）**：
- 表格 `n_r>12` 行时自动 `size=min(size,9.5)`、高度封 3.85 in，脚注下移到 6.55 in；否则 15 行表和脚注挤在同一 y 上（几何检查会报「压字 y=453/455」）。
- `bigstat()` 的大数字按**最长值长度**自动缩字号（≤5 字 40pt / ≤7 字 32pt / 更大 26pt）：`314 件/h` 这类带单位的 7 字值在 40pt 下会折成两行，第二行直接压在标签上（几何检查报「y=240 与 y=275 重叠」）。数字与单位分开放（值 `314`、标签写「件/h」）也可，但同一册里别两种混用。
- `section()` 分节页的项目列表 ≥6 条就会冲出页脚：字号压到 11.5pt、`space_after=3`、起始 y 4.72。
- 自绘框图（`funcmap`）行高 `bh=0.60` + `gap=0.10` 才留得下页脚注；按 0.68/0.12 算 5 行正好压到脚注。
- 改完页数要同步三处：「全册结构」那页写的页数、交付说明的页纲表、以及各章页码区间——否则第一页就自相矛盾。

- 插一整块新章（如「每个功能一页方框图」55 页）用**小数章号**（`0.55`）落在 `0.5` 与 `0.6` 之间，别给后面所有章重编号；
  排序键取 `float(章号)`，于是 `section()` 的数字渲染必须兼容小数 —— `f"{num:02d}"` 对 `0.55` 直接抛
  `ValueError: Unknown format code 'd' for object of type 'float'`，用 `is_integer()` 分支或 `f"{num:.2f}"`。
- 用户说「要图 / 图还是没加上」时，指的是**旧册里已有的那类图页版式**（逐功能框图 / 带尺寸线的三视图 / 节拍甘特），
  去旧册找同类页与它的生成逻辑复刻，不要用新自造的图种替代；补完在交付说明的图件清单里逐页登记页码。

**既有产品 deck 并进技术册（两步，别重画）**：
1. **数据先抽成 JSON**：`python-pptx` 读旧册拿每页标题/表格/图片（`sh.image.blob` + `sh.image.ext` 落成 `img/r5_pNN_<id>.png`），
   节点页的「输入 N 条 / 输出 M 条」用正则从标题解析成 `reports/*_nodes_io.json`，再一次性生成明细表 —— 手抄 55 行必错。
2. **页序按产品→技术的逻辑排，不按新旧排**：新增 `第 0 篇 整机方案`（一页看懂/物理分析/功能框图/输入输出/节点顺序/能力/节拍/外形尺寸）
   放在技术史之前，末尾加一页「从整机到技术」做承接；技术篇里出现的每个数字在第 0 篇都能指回同一条口径。
   图片用 `add_picture(width=…)` 后按可用区**等比回缩并居中**，宁可留白也不拉伸。
3. 节点「顺序说明」单独成页：一条顺序一条理由（收口点为什么在第三位、工艺序列为什么不能换、感知为什么后置），
   并注明「顺序为现场调整后固定版本」——只列清单不给理由，用户会当成排版随便排的。

### 多册合并成一本总手册（用户说「这三本合成一个」）

- **输入取内容模块，不取成品 pptx**；合并器自己重出封面/导读/结语，源册的 cover/section/quote 一律丢弃。
- 篇内排序键是 **(篇, 源册序, 原章号)** —— 两册都用 6.x 时只按章号排会交错成「原型 → 成本 → 原型能力」。
- 去重分两段：标题归一化抓同名；**同主题不同标题**（五层引擎/五层记忆/四道安全闸/力控压入/三机分工这类）
  必须在合并器里维护显式 `SKIP` 表并决定保留哪一篇的版本 —— 自动去重器抓不到，留着就是两页讲同一件事。
- 两册附录都叫 A–D 时，后并入那本加来源前缀，否则出现两个「D1｜术语表」。
- 合并后重跑三段几何体检、逐篇回读首末页标题无残留原章号、图片与方框图块数不减。配方见 `references/deck-merge.md`。
- 🔴 **封面标题与篇序由「真源册」决定，不自拟**：合册标题/主题取客户已认可的 canonical deck 封面（本项目口径：`以世界模型为核心的状态空间工程`，副题「整机 × 能力分级 × 从控制论到 H-JEPA 的技术线」）。自己起「总技术手册 / XX 产品白皮书」这类工程名，用户一句「你标题都错了，是以世界模型为核心的」就整本退回。
  篇序也服从主题，不服从拼装顺序：主题是“世界模型为核心”时，顺序为 整机(对象) → 技术来路(1948→2026) → 对标与 H-JEPA 架构(核心篇) → 状态空间工程(落成五层) → 能力分级与产品 → 实证 → 演练 → 经济交付 → 立项 → 附录；沿用“产品册在前”的顺序同样会被退。
  改标题要五处同改：封面主/副标题 · 页脚 `DECK` 常量 · 文件名与版本号 · 讲稿 docx/pdf 抬头 · 交付说明；漏一处就是文件里两个口径。
- 🔴 **交付目录 = canonical deck 所在目录，被取代的副本同一次提交里删掉**：合册成品放 `docs/1-天枢-产品边界/deliverables/1-产品方案/`（真源册旁边），`zmax_data/deliverables/<批次>/` 留同名副本；上一版文件名、临时交付目录（如自建的 `4-总技术手册/`）、旧讲稿一并删除，`README_INDEX.md` 的份数与条目同步改。两套并存时用户第一句就是「备注在哪里？是哪个 ppt」。
- 🔴 **用户问「是哪个 ppt / 备注在哪」时给三件，别只说“已打开”**：① 绝对路径；② 窗口标题栏应显示的字符串（`<文件名>.pptx — LibreOffice Impress`）；③ 备注查看方式（编辑态「视图 → 备注」；放映「幻灯片放映设置 → 演示者控制台」后 F5）。同时核他开着的是不是旧件——旧窗口标题里仍是上一版文件名，直接点明并关掉：`wmctrl -c "<旧文件名> — LibreOffice Impress"`（只关文件已被删的那个窗，不动别的）。
- 🔴 **已有 soffice 实例时再 `soffice --impress <file>` 可能不弹窗**（同 profile 被占，命令静默返回、`wmctrl` 里根本没有这个文件）：改用独立 profile 起 `soffice -env:UserInstallation=file:///tmp/lo_<tag> --impress <绝对路径>`，再 `wmctrl -l | grep -i impress` 核标题出现；`terminal(background=true)` 起，别用 nohup/setsid 包。

**合册里再插一整篇（用户后来又要加一章）**：
- **篇号必须由 `PARTS` 列表派生**（`enumerate(PARTS,1)` 进页面），不得在文案里手写「第 5 篇」—— 插一篇就会把后面全部错位，
  而几何体检全绿、图表全对，只有目录和章节号是错的。插完回读：每篇首行标题的篇号连续、无重复、无跳号。
- **每篇的起止页由构建完的实际页数现算**（构建完把 `篇名 起-止 页数` 打一张表），交付说明的页纲表**照抄这段输出**，
  不要手数。导读页写篇名 + 该篇讲什么，**不写页码**；非写不可时只在篇内写「篇内第 N 页」—— 跨篇页码是最容易过期的一类数字。
- 插篇后的三处联动：`TOTAL` 页数 · 读册说明/导读里的篇章清单 · 文件名或版本号；页脚页码必须仍从 1 连续到 `TOTAL`。
- 🔴 **新篇有自己的章号时，不能走通用的「章号首段 → 篇号」映射**：映射表里 `"5"` 早已指向别篇，新篇会被静默塞进那一篇
  （实测 27 页全落进「演练」，篇号 5 缺失、篇 7 变 40 页，而几何体检全绿）。做法：**按模块身份路由**
  （`if mod.__name__.endswith("manual_wm"): part = 5`），章号只负责篇内顺序。判据：回读打印「篇 → 起始页」表，每篇都有、无跳号。
- 🔴 **合成的封面/篇章页/结语不在内容表里**（collect 阶段就把 `cover/section/quote` 滤掉了），只在内容分发后统一写备注
  ⇒ 这 10 页备注全空。备注要写在**建页处**（`s = L.section(...)` 之后紧接着 `s.notes_slide...`）。

- **备注是页面内容的一个视图，不是另写一份稿**：由 `tools/speaker_notes.py` 按页型模板 + 重点页手写 override 生成，
  builder 里随页写入 `slide.notes_slide.notes_text_frame.text`，重跑全册自动重生 —— 不要用「按页码后处理贴备注」的脚本（一改页序就错位）。
- 规模口径：每页 **70–130 字 / 念出来 20–30 秒**；288 页实测 29,920 字（均 104 字），全册 80–95 分钟。
- **必须验 288/288 非空 + 字数 min/mean/max**，再抽 8–12 页人工读（附录、方框图、表格、公式各抽一页）；只看首页会漏掉整类页。
- 另出**可打印讲稿 docx/pdf**（页码 + 章号 + 标题 + 备注），与 PPT 备注同一份文本，不维护两份。
- 🔴 **主题变了要三层同改，只改标题等于没改**：①封面备注第一句直说主题（「今天讲一件事：以世界模型为核心的状态空间工程」）+ 为什么核心是它 + 为什么形态是它；②篇章过场写「这一篇在主题线上负责什么」；③每页结尾一句**镜头句**（`LENS[part]`，每篇 2–3 句按页序轮换）把内容扣回主题。用户的判据是「第一页 note 有没有说主题」，不是封面字对不对 —— 只换封面标题、备注还是「今天用一小时把这台机器人讲透」，当场退回（「全篇重写，主题要明确」）。
- 🔴 **备注里的篇号是索引键，重排篇序必须同步改**：`PART_TALK[part]`（篇章页过场词）与重点页 override 都按篇号取，篇序一换（如把“世界模型对标”从第 5 篇提前到第 3 篇）而表没改，篇章页会把上一套内容念出来——几何体检和字数统计全绿，只有念的人发现不对。改完抽读 3 个篇章页备注对一遍标题。
- 按页型的话术表、override 机制、中文清洗与截断坑、导出骨架 → `references/speaker-notes.md`。

### 图片页：不许拉伸，且「图缺失」必须查得出来

- 🔴 **`pic.height = <float>` 会抛错，而把「加图 + 定尺寸」整段包进 `try` 会把异常吞掉**：页面留下 `[图缺失] 路径`
  占位文字 + 一张**宽已改、高没改**的畸形图（近方图被压成 3.5×11 in 的窄条）。用户看到的就是「图还是没加上」。
  写法：`try` 只包 `add_picture` 一行，尺寸计算放在外面；所有 EMU 赋值先 `int()`（`int(box_h)`、`int(w*ratio)`）。
- 判据不是「页里有 shape_type==13」，而是**图片 cx/cy 之比 == 源图宽高比**（±2%），并且全册 `[图缺失]` 计数为 0。
  收尾跑两条：数图片页 + 逐图比比例；只数一张会被畸形图蒙过去。
- 排版：单图按可用高度回缩、双图按列宽分摊，再宽再高都只回缩并居中，宁可留白不拉伸。

### 白底线稿渲染图要转深底，不能直接贴

厂家/URDF 渲染出的图纸是白底黑线（四角均值 `[255,255,255]`），直接贴进深色册子就是一块白板或被深底吃掉。三步转：
1. 四角均值当背景色，`|px-bg|.sum(2) > 26` 判前景并紧裁（好多图有 30% 白边，不裁等于缩更小）；
2. 背景像素 alpha=0 存成透明 PNG；
3. 低饱和（灰/黑）笔画改浅色 `(226,238,255)`，彩色标注按 `0.55*px + 255*0.45` 提亮；1px 细线先做一次 3×3 膨胀再落盘。
判据：深底页图区「非背景像素占比 >5%、亮像素 >2%」，低于这个数就是又贴了看不见的线（纯 3D 线图 5% 属正常）。

### 每个功能一页方框图（用户说「我要图，每个功能的方框图」）

- 数据不手抄：从旧册节点页解析 —— 表头 shape 是 `输入接口（N 条）`，**紧邻的下一个文字 shape 才是条目体**
  （`A·标签、B·标签`）；按 `、` 切、再按 `·` 切出「上游节点 / 信号」。55 个节点一次抽到 171 入 / 162 出，手抄必错。
- 版式：左列输入 chips（两行：上游名 8.5pt / 信号 7pt；宽 3.35 in 分别截 14 / 30 字）→ 中间功能盒（名字 + 「输入 N 条 · 输出 M 条」）
  → 右列输出 chips；超过 8 条折成「…另有 N 条」。
- 🔴 **名字要三处分别截**：标题 18 字、中间盒 26 字、chip 14 字。同一串全塞进标题会顶穿副标题（几何检查报「y=106 与 y=115 重叠」）。
- 🔴 **emoji 不要进 chips**：emoji 字形框比正文高一大截，压字自检会整片报红（实际是假阳性，但排查要花时间）。
  生成前把 `\U0001F300-\U0001FAFF`、`\u2600-\u27BF`、`\uFE0F` 一起剥掉。
- 这类页的间距按 0.33~0.34 in 盒高 + 0.06 in 缝、8 个一列才算得下；盒子加高就要减条数，别硬撑。

图页最容易「看起来有、点进去是占位」。交付说明单列一表：**页 / 图 / 来源文件或生成脚本 / 一句话说明**，
