# 检测器开发状态报告（元任务矩阵）

用户问「检测做到哪了 / 元任务列一下 / 完成了哪些」时，不按时间线讲做了什么，按**元任务矩阵**讲：
每一项都有产出物与验收判据，不能验收的不算元任务。适用于视觉检测器（AOI 表面/金手指/缺陷）的进度汇报。

## 1. 固定十项（M1–M10，顺序即执行顺序）

| # | 元任务 | 产出物 | 验收判据 |
|---|---|---|---|
| M1 | 取像与几何摆正 | 相机参数 + 摆正逻辑 | 工件外接框边缘直、不贴画布边 |
| M2 | 判据图生成 | 定尺画布 + meta | 尺寸逐帧恒定、零拉伸、上下沿倾角 < 0.3° |
| M3 | 数据采集 | 按批次分组的样张集 | 每个工位/朝向/光照组合均有覆盖 |
| M4 | 数据标注 | 标注规范 + 黄金集 | 黄金集人工核过，类别/框一致率有报告 |
| M5 | 数据集切分 | 按批次分组切分 | **验证集不得与训练集同场景** |
| M6 | 模型适配训练 | 权重 + 训练日志 | 与现役**同口径对照有提升**（非仅不回退） |
| M7 | 模型调优 | 阈值/尺度/难例回灌记录 | 逐项消融，每项有同口径数字 |
| M8 | 判决与信号发布 | 话题/接口 + 真值搬运 | 无真值时记「未检」，**不得冒充 OK** |
| M9 | 产线部署 | 发布记录 + 备份 + 验收日志 | 发布→SHA 逐位核对→重启→验收全绿 |
| M10 | 自主进化 | 回灌闭环 + 进档门槛 | 门槛写死，未达标不进默认档 |

规则式检测器（阈值/几何判据，不靠模型）在 M3/M4/M5/M6 上写「**不适用**」而不是「未做」——
否则把「本来不需要」的工作显得像欠账，也让真正的欠账模糊掉。

## 2. 状态只给三态 + 分数

`✓ 完成` / `◐ 部分` / `× 未做`，每类再给「已完成 N/10」。读者第一眼要能看出两边差在哪；
不要用「基本完成 / 推进中」这类无分段词。

## 3. 已完成：真帧图像证据 + 前后实测

- 判据图、叠加图**从在役服务现抓**（`?kind=judge&grab=1` 一类），不用示意图、不用历史截图。
- 修前/修后给同一组数字（尺寸、填充度、长宽比、清晰度、残余倾角），让读者自己看出改了什么。

## 4. 未完成：给硬数据，不给判断

用**同口径交叉验证矩阵**（分布内 / 分布外 / 判据图 三路 × 新训与现役各一行）：

```
新训模型   分布内 12/12·0.977   分布外 0/12   判据图 0/12
现役模型   分布内 12/12·0.887   分布外 7/12·0.679   判据图 0/12
```

- 🔴 `mAP50=0.99x` 高得反常时先查切分：随机切「同场景微扰」数据 ⇒ 验证集全是训练集近邻，
  指标是**泄漏假象**。报告里必须点明「该指标不可用于进档判断」。
- 进档门槛写死在报告里（例：分布外 > 现役 7/12 且判据图 > 0/12），下次评审照同一张表对。

## 5. 常见误判

| 误判 | 实情 |
|---|---|
| 判据图改好了 ⇒ 检测改好了 | 检测吃的是 crop（如 960×960 方形），判据图只用于显示/落盘；修好的是「看到的东西」 |
| 模型训了 ⇒ 模型可用 | 先看分布外与判据图两路；只有分布内高、外路 0/N 的模型不能上线 |
| 权重文件在 ⇒ 可以训 | 加密权重（`.pt.enc`）且解密器只装在产线机时，开发侧无法训，单独立项 |

## 6. 落库

元任务、实测数、方案、里程碑、风险落一份 `data.json` 单一真源，生成脚本只读它，改数只改 json 再重跑。
版面与字号按本技能铁律十二（PPTX）走；成像选型章节按 `aoi-imaging-chain-selection` 写。
