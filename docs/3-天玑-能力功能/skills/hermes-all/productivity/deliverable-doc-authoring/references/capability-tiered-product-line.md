# 能力分级产品线：从技术册到「按能力卖」

## 什么时候用

已有技术白皮书/整机方案，用户说「**增加机器人能力，按能力分级规划产品，做产品解决方案，写立项任务书**」，或问「我们到底能卖哪几档」。
产出的三件套固定是：**能力分级体系（对外口径）→ 产品型号族 → 立项任务书**，配一本新 deck（不是改旧白皮书）。

## 一、分级的定义法（这一层错了后面全错）

- **用能力语言，不用算法词**：写「插进去不硬压」「来料偏了能找回」，不写「阻抗控制」「域随机化」。客户能验收的只有前者。
- **每级三条判据**，缺一条降级：`精度类`（毫米/度）+ `过程类`（力上限/重试次数/耗时）+ `结果类`（成功率/一致性/指标曲线）。
- **每级写「替客户省掉什么」**（一个人的手 / 一个熟练工的手感 / 调机的人 / 持续调参的人）—— 这列是销售话术与定价的根。
- **四态标注，四个词不混用**：`在役`（有产线实测证据）／`在研`（有通道未达指标）／`规划`（有方案未开工）／`试运行`（有闭环未稳定）。
  在研的能力**绝不许**写成「具备」，单次演示通过也不算 —— 判据是重复性与批量数据。
- **高级包含低级**：C4 的机器必然满足 C2 全部判据，反之不成立；这条决定了「升级包」的商业模型。

### 阶梯模板（照这个骨架改写，别每次重新发明）

| 级 | 能力 | 替客户省掉 | 进入判据（摘要） | 型号 |
|---|---|---|---|---|
| C1 | 定位抓放 | 一个人的手 | 抓取 ≥99%、位置 ≤2 mm、≤6 s/次 | 低配 |
| C2 | 精对位插拔 | 一个熟练工的手感 | 横向 ≤0.5 mm、姿态 ≤1°、插入力 ≤40 N | 主力 |
| C3 | 力控装配 | 装配工的试插经验 | 间隙 ≤0.05 mm 可插、深度一致性 ≤0.05 mm | 高配 |
| C4 | 柔性自适应 | 换型与调机的人 | ±3 mm/±3° 内自恢复 ≥95%、换型 ≤30 min | 柔性 |
| C5 | 自主进化 | 持续调参的人 | N≥3 轮指标单调不升、门禁留痕、人只在否决位 | 旗舰+服务 |

配一张 **能力×场景矩阵**，图例写死四档：`●=在役可签合同　◐=试运行可试点(不承诺节拍)　○=在研/规划(可做 PoC，不签指标)　—=不做`。
再配一张 **能力级 ↔ 五层引擎映射**（越往上踩的层越多），用来解释「为什么不能跳级」。

## 二、型号族：同平台，差在四个件

- 硬件差异只允许四个维度：**末端 / 力觉 / 视觉 / 软件档**。同一套引擎、同一套接口契约、同一套交付 SOP —— 这才叫可复制。
- 价格带按档位递增并**明确写「建议区间、待商务核算」**；不给单点价，不在文档里替商务定成交价。
- 每档一页：配置 / 能干什么 / 不能干什么 / 交付物。**「不能干什么」必须写**，是防扯皮的条款。
- **选型四问**（动作类型 → 间隙量级 → 来料稳定性/换型频次 → 是否要长期进化），每问答不上就落 `先做 PoC，PoC 不过不报价`。
- **主动劝退清单**（年产量过低回本超 4 年 / 间隙大且来料稳定 / 客户没有工艺标准 / 要求整线总包）—— 写进产品册，是保毛利最便宜的手段。
- 不做「万能型号」：全塞进去 BOM 涨 40%、交付周期翻 4 倍、失败时说不清是能力不足还是配置不对。

## 三、经济性：算式链必须页面上可核

```
年产能 Q = 年有效工时 H × 3600 / 单件节拍(秒)
年成本 C = 折旧(设备/年限) + 能耗 + 维护备件 + 软件服务
单件成本 = C / Q
单件节省 = 人工单件成本 − 我方单件成本
年节省 = 单件节省 × Q；静态回本 = 设备投资 / 年节省
```

- **同时给两个稼动率的数**（如 100% 与 85%，85% 时单件成本与回本一起变差）；只给最漂亮的那个，现场一问就穿。
- 五年 TCO 分四行：设备 / 五年服务（按设备价 ~5%/年）/ 备件耗材 / 合计。
- 报价拆三段：**设备段 / 软件段（按能力档定价，不按节点数）/ 服务段（进化轮次、远程支持、备件）**，外加变更单口径。三段分开，客户砍价只砍设备段。
- 与人工、与进口专机同口径对比三行：单件成本 / 换型时间 / 一次通过率 / 可追溯粒度 / 适用间隙。不比「谁更智能」。

## 四、交付与验收：证书按能力级发，不按型号发

- **四件套**：引擎 / 策略 / 接口 / 证据；缺一件不算交付（沿用交付文档技能里的四件套口径）。
- 每级一张**能力证书**：证书上写实测值与测试条件，有效期 1-2 年、到期复核；不写「行业领先」这类无法判定的词。
- **验收七步**：勘察 → 试件验证 → 配置确认 → 到场调试 → 试生产（按档位定件数）→ 能力认证 → 移交陪跑。前两步是止损点，不过就不签。
- **归责表**：现象 / 归责依据（力曲线是否超限、来料是否在标定范围内、节拍偏差是否 >5%）/ 处理。靠数据归责，不靠嘴。

## 五、立项任务书（11 章骨架，别写成宣传稿）

1 项目基本信息（编号·周期·预算·负责人·关联资产）→ 2 立项背景与必要性（市场 + 技术积累 + **四条短板照实写**）
→ 3 项目目标（总目标 + 分级目标量化表 + **非目标**）→ 4 研究内容（K1..Kn：内容/难点/交付）→ 5 技术路线（先稳后进·能力挂判据·五层收口·证据先行）
→ 6 进度（四阶段 + 里程碑表）→ 7 资源（人 / 算力 / 样机 / 试件 / 预算科目）→ 8 风险（按「会不会真发生」排序）
→ 9 组织与职责（每个角色对**一条判据**负责）→ 10 验收标准与交付物 → 11 附件（能力表 / 口径表 / 证据索引 / 产品册）。

**必须有「决策点 + 退出条件」**：每个高风险课题一个 D 点，写明「继续条件」与「终止/转向条件」，并写一句「退出不是失败，是把资源从证明不了的事挪到能卖的事上」。
没有退出机制的任务书，后面只会越拖越贵。

## 六、生成链（三件套 + 一份 docx 生成器）

- `tools/prod_content{1..3}.py`：分篇内容模块（需求边界 / 能力分级 / 产品矩阵 / 技术底座 / 实证 / 经济性 / 交付 / 立项 / 附录），每条带 `ch="3.2 F2"` 章节号。
- `tools/build_prod_deck.py`：几乎复制 `build_tech_deck.py`，只换模块元组与输出名；`_key()` 要能吃 `A/B/C/D` 附录前缀（映射到 9.x）。
- `tools/make_prod_docs.py`：`python-docx` 出解决方案文字版与立项任务书；中文必须显式设 `w:eastAsia`（不设就回落宋体/等线）。表格用 `Table Grid` 样式 + 每表一行脚注（来源/口径）。
- 复用 `deck_lib.py` 的 cover/section/bullets/table/cards/layers/timeline/bigstat/formula/quote，不新写样式库。
- 出稿后跑同一套几何闸：`soffice → pdftotext -bbox` 查出血/撞页脚/压字，三者为 0 再交付；`pdfinfo` 核页数。

## 七、坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 把在研能力写成「具备」 | 客户要求按指标验收，现场达不到 | 四态硬标注；未验的判据写「未验（在研）」 |
| 价格带写死成成交价 | 商务没法让价，或签下来亏 | 写「建议区间，待商务核算」 |
| 只给最漂亮的回本数 | 客户按 85% 稼动率一算就翻脸 | 双稼动率并列 + 算式链可核 |
| 型号族做成「万能型号」 | BOM 涨、周期长、责任说不清 | 同平台差四件，跨档用升级包 |
| 立项任务书没有退出条件 | 高风险课题拖到年底才发现做不出 | 每课题一个 D 点 + 终止/转向条件 |
| 文字版与 deck 同名 | 转 PDF 时互相覆盖，页数悄悄变成 7 页 | 文字版加 `_文字版` 后缀，逐份核页数 |
| 数字与旧册不一致 | 同一指标在产品册与技术册两套值 | 每个数字标出处（白皮书页码 / reports 文件），改动时两处同步 |

## 八、把既有方案册改写成新项目立项文档（参考件 + 方案册 → 立项）

- **骨架抄参考件，内容取方案册与实测报告**：`python-docx` 读参考件拿标题层级与表序；`python-pptx` 逐页取方案册
  的整机外形 / 三视图 / 尺寸表 / 结构参数 / 能力判据 / 型号谱系 / 三档配置（`has_table` 的行按 cell dump，比截图可靠）。
- 章节映射：背景与市场 → 目标与产品定义（**外形 / 能力 / 产品三块是正文主体**）→ 商业模式与回报 → 技术可行性
  → 算力分析 → 分工 → 计划 → 风险 → 术语与真源索引。
- 用户点名「不用写 X」时，**整章不写、正文一次都不出现**（连目录/页脚也不出现）；只在附录真源索引里保留那份文件的
  原名 —— 那是可追溯性，不是内容。
- 现场未采集的量（工位数、班次、客户接口、售价）写「待现场清点 / 待商务确认」，不代填；每条数字标口径与来源。
- 一个生成器文件：数据集中一段、`build()` 依次调各章，重跑即出 docx + 同名 PDF；成品不手改。

## 九、算力分析章（立项/产品文档里的「算力不是瓶颈，时序才是」）

- **先算需求，再谈选型**。固定五问：拍多长（控制周期）→ 每拍要算什么 → 模型多大 / 单次前向多久 → 整链实测多久
  → 秒级的那些放哪一层。
- 时间尺度表（实测口径）七行：控制拍 / 视觉定位 / 前向 / 编排 / 任务级推理 / 整链 / 力觉采样，每行写「时间尺度 +
  频率 + 单次实测」。
- 预算账必须能自己乘：`单件秒数 ÷ 拍长 = 单件拍数`；`单件拍数 × 前向耗时` = 每拍都算时的占用（给占比）；
  `整链耗时 × 单件拍数` = 同步串行的单件耗时，再与目标比出倍数 —— 这个倍数就是「为什么必须异步」的定量依据。
- 模型体积按参数算：`参数量 × 1 Byte`（INT8）给权重量级，写「常驻内存 <1 GB 量级」，不写没测过的「占用 X GB」。
- 选型表按 **AI 模组** 分档（算力 / 内存 / 相机路数 / 力控通道），**不要与整机价格档共用编号**：整机档已叫 A/B/C 时，
  算力档再叫 L2/L3/L4 会与引擎分层撞名，统一写「基线档 / 增强档 / 旗舰档」。
- 必带一张「瓶颈与处置」表：瓶颈 / 证据（哪个实测、在哪台机器上测）/ 处置。端侧没测过就写
  「未做同口径实测，列入 M1 复核判据」，不许拿工作机的数当端侧结论。
- 结论固定两句：算力够不够；真正的瓶颈是什么（通常是调用时序与内存常驻，不是 TOPS）。
- 数字来源就三类：方案册的参数/前向耗时页、逐层与整链延迟实测报告、硬件平台分档方案；三者在真源索引各占一行。
