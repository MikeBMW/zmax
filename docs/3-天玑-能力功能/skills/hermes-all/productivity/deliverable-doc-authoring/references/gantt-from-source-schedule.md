# 把节拍/排产方案出成甘特图（数据同源，条不可手填）

适用：用户要把「N UPH 节拍方案」「排产计划」「多段工序」画成甘特图并追加进 deck。
核心口径：**每根条 = 真源段表里对应动作块的区间求和**，脚本里不出现任何手写秒数。

## 1. 先把段表拉成绝对时间轴

段表（如 `sim_insert.json` 的 `plan`）通常是**顺序执行**的，逐段累加即得起止时刻：

```python
t, spans = 0.0, []
for s in plan:
    spans.append((t, t + s['t'], s))       # (起, 止, 段)
    t += s['t']
assert abs(t - sim['total_t']) < 0.05     # 累加和必须等于真源总时长, 否则段表被改过
```

这个 `assert` 是整套图的可信度来源：对不上说明你拿的段表和真源不是同一份。

## 2. 动作块怎么切（别按「连续 kind」切）

一次 AOI 五点是 `move→golden→move→side→move→side…`，**中间夹着移动段**，按连续 `kind` 切只会切出 0.8 s 的金手指导航段。
按语义块切：

| 任务块 | 切法 |
|---|---|
| 取料插入（件完成点） | 找 `kind=='insert'` 的段，块 = 前 6 段起 → 该件的 `t_ins`（= release 结束） |
| 拔出 | 找 `kind=='pull'` 的段，块 = 前 3 段起 → 后 1 段止（5 段） |
| AOI | 直接用真源的 `t_aoi0 / t_aoi1`（含点间移动），不要自己加 |
| 落盘 | `[t_aoi1, t_placed]` |

## 2·补 动作块的坐标系：一律存**绝对**时间

- 坑：动作块存成「相对窗口起点」，而时间轴切段/窗口筛选/指标统计都按绝对时间 ⇒ 三样同时错。实测稳态页把「45.87 s 的那一轮」画成了后半段的补插段，
  「右臂净作业占比」也从真值 42.18 s / 92% 变成 41.96 s / 91%（多了一个落在窗口外的 0.22 s 块）。
- 定式：
  ```python
  W0, W1 = base, base + dur                 # 一个 window 同时给 draw 与指标筛选
  bars = [(b.t0, b.t1) for b in blocks if W0 <= b.t0 < W1 and b.t1 <= W1]   # 不截不补
  occ  = sum(b.t1 - b.t0 for b in bars) / (W1 - W0)
  ```
  按节拍重复的条（如左臂每 `tact` 上一次料）要用 `k*tact + base` 生成，起点落在窗口外的条**要么不画、要么显式标「跨窗口」**，不能默默截断（截断后分母不变，占比会虚高）。
- 自检：`pdftoppm` 取色后按条左端反算时刻，与源块逐条对（排除 `l < X0` 的图例色块），差 >0.05 s 就 fail。

## 3. 段与件的关联只走绝对时间锚点

- `cycles_data[].k` 是**轮次**不是件号；`plan[].k` 只到轮数（8 轮 14 件）。按 `k` 关联「件 ↔ 段」必然错位，且 `k>轮数` 的件会静默得到零长条。
- 正确做法：以 `t_ins / t_pull / t_aoi0 / t_aoi1 / t_placed` 为锚，在段轴里取**时间最近**的那个同类段（容差 0.35 s）。
- 出图前断言：每件每行条长 > 0.05 s、末条不超过 `total_t` —— 这两条能抓住上面所有错位。

## 4. 画法（python-pptx 原生形状，可编辑）

- 空白版式 `prs.slide_layouts[6]`，按 `x = X0 + t*sc`、`sc = W/total` 换算；条最小宽给 0.04 in（否则 0.2 s 的段宽度为 0 看不见）。
- 节拍线用 `add_connector` 竖线，每 `takt_s` 一条并标秒数；件标签放图上方，NG 件用红色条 + 前缀 `NG`。
- **横排分隔线只能用 hline**（`add_connector` 两端 y 相同）；把 hline 写成 `vline(x, y, x+w)` 会生成一条 9 in 的竖线捅出页面 —— 越界预检能抓到，肉眼先看不出。
- 一页全景（全轮 + 节拍竖线 + NG 标记）+ 一页单件放大（各动作条 + 时长 + 余量），比挤在一页可读。

## 5. 追加进既有 deck 与重复生成

```python
pr = Presentation(DECK); pr.slides.add_slide(pr.slide_layouts[6])   # 追加
# 重跑前先回退上次追加的页, 否则每跑一次就多两页
while len(pr.slides._sldIdLst) > KEEP:
    sid = pr.slides._sldIdLst[-1]; pr.part.drop_rel(sid.rId); pr.slides._sldIdLst.remove(sid)
```

生成器要**幂等**：脚本自己先回退到 `KEEP` 页再追加，这样调版面参数可以反复跑。

## 6. 自检三件（缺一不可）

1. **形状越界 0**：逐 shape 断言 `left/top/left+width/top+height` 在页内。
2. **页数 + 文字**：`soffice --headless --convert-to pdf` → `pdfinfo` 核页数、`pdftotext` 核关键数字在、被删的旧口径不在。
3. **画上去了没**：`pdftoppm -f N -l N -r 60 -png` 出页图，按各条颜色做容差计数（`abs(im-rgb).max(2)<26`），五种颜色像素都 >0 才算真的渲染出来 —— 脚本零异常、形状数量对，条仍可能是因为坐标算错画在页外或宽 0。

## 7. 数据源副本随图存档

同目录存一份 `gantt_<主题>_数据源.json`：真源路径、`takt_s`、`total_t`、每件四段起止时刻、口径说明。
下次有人问「这根条哪来的」，指这份文件就够；也补上了「图出来了但无法复核」这个常见漏洞。

## 8. 等待/停留段必须画出来 —— 缺了它节拍账不成立

段表里除主动作（取/插/拔/检/放）还有**并行等待**：模块插到位后要在孔内坐一段时间才被拔去做 AOI。不画这一段，读者会以为节拍 = 动作时长之和。

- **停留口径 = 插入松开 `release@hole` → 下次夹住 `grip@hole`**（含移向孔位的空跑），与真源 `cycles_data[].dwell_s` 逐件对账应吻合（差 ≤0.05 s 属段表四舍五入）。拿 `pull` 段起点当锚会整体少算 ~1 s，对不上账。
- 停留是**参数域里的约束**（`dwell_min ~ dwell_max`）：排满时会出现首件贴下限、某件贴上限 —— 这个结论本身要写进方案（「AOI 一变慢就破上限」），比只报平均值有用。
- 画法：停留条用灰色（`#94A3B8`）与动作条区分，**不进节拍分母**；全轮页用浅蓝底纹标出稳态循环窗口并注明「节拍由右臂决定、停留与之并行」；稳态放大页把停留条裁到窗口内并标注「跨窗口」。
- 自检：停留条数 == 件数；每条时长落在 `dwell_min..dwell_max` 附近（越界必须能解释）；`pdftoppm` 后按灰色容差计数 > 0（证明真渲染出来了）。
