# 技术对标篇：世界模型横向比较与「为什么走分层」

技术白皮书/总手册里「世界模型」一章的写法。用户要的不是综述，是**能据此做工程取舍的对比**，
并且要能回答「为什么是我们这条路线」。按下面的页序与口径写，才经得起他逐页追问。

## 一、页序（一次成篇的定型骨架）

1. **先立问题，再谈技术**：第一页把需求翻译成工程语言 —— 「我下发这个动作，下一拍会怎样？
   置信度多少？能不能挂判据？」世界模型的可用性由这三问决定，不由生成得多好决定。
2. **技术基因分类**（见 §二）：四类基因，每类一句话说清「天然能不能进控制环」。
3. **发展脉络**：按年份一条线，标出每个节点**改变了什么**（不是罗列论文）。
4. **五条主线逐条剖析**（各 1–2 页）：NVIDIA / Google / OpenAI / 空间智能 / Meta-JEPA。
   每条固定三段：它解决什么问题 · 它的公开做法与量级 · 对我们可用/不可用的部分。
5. **相邻行业怎么用**（自动驾驶）：可借的三条 + 不可照搬的两条，并列成对照表。
6. **八维对比大表**（见 §三）：一页把六条路线放在同一张表里，最后一列判「能否进本工程控制环」。
7. **选型论证**：为什么是 JEPA —— 四条硬理由（可测）+ 一条软理由（不承诺）。
8. **架构页**：本工程的 H-JEPA 变体，四层时间尺度 + 三条设计约束 + 几何分支 + 与原版的差异表。
9. **产能账**：目标 UPH → 每件秒数 → 缺口倍数 → 分项预算 → 分层为何能补上缺口 → 单一大模型为何补不上 → 分层的代价。
10. **收口**：五条路线取舍表（取什么/舍什么）· 演进阶段（每段独立判据）· 出处清单。

## 二、技术基因四分法（本工程的分类口径）

按「生成什么」分，不按厂商分；同一厂商可能同时占两格（Google 的 Genie 与 Dreamer）。

| 基因 | 代表 | 预测对象 | 动作条件 | 度量一致 | 进控制环 |
|---|---|---|---|---|---|
| 生成像素 | Sora / 视频扩散 | 未来视频帧 | 无（或弱） | 不保证 | 不能 |
| 生成可交互世界 | Genie 系 | 可玩帧序列 | 有 | 弱 | 只能做训练环境 |
| 生成潜表征 | JEPA 系 | 表征 | 需外挂 | 需外挂 | 能（本工程选它） |
| 生成轨迹分布 | 自动驾驶 World Model | 轨迹/占用 | 有 | 由标定保证 | 能（但域不同） |

写这一页的作用是让读者在第一页就知道「比较的不是画质，是能不能挂判据」。

## 三、八维对比表（列怎么定）

维度：预测对象 · 输入 · 输出 · 单步延迟 · 度量一致性 · 是否吃力/几何 · 数据需求 · 能否进控制环。
**最后一列必须是可判定的布尔**（能/不能/需改造），不是「较好/一般」—— 形容词一出现，这页就变成宣传稿。
表格列宽按 `deck_lib.table()` 的可用宽分配，行数控制在 12 行内，否则脚注会撞行（见 SKILL.md 密度硬规则）。

## 四、五条主线的要点与判据句

每条的「对我们」那句必须落到具体部件，不要停在评价。

- **NVIDIA（Cosmos 系，预测/迁移/推理三位一体）**：定位是**物理 AI 的数据工厂**，公开量级为千万小时级视频。
  对我们的用法：**只做数据生成与合成，不进控制环** —— 训练数据能等，控制拍不能等。
- **Google（Genie 系 + Dreamer 系）**：Genie 走「可交互世界」（11B → 3 万小时 → 实时 720p 一代代放开），
  Dreamer 走「潜空间里想象再决策」。判据：**Dreamer 与我们的 L4 同族**（潜空间 + 回报），Genie 证明
  「可交互必须有动作条件」—— 这条恰好是我们加动作头的依据。
- **OpenAI（Sora，spacetime patches + DiT）**：证明视频里有物理直觉，但**没有动作条件、没有度量一致、延迟差 1e2~1e4**。
  这一页的核心句：把生成模型当控制模型，是把「会画」当成「会算」。
- **空间智能（World Labs，RTFM / Marble 一线）**：3D 原生表征，回答「世界长什么样」，不回答「动作后果」。
  对我们的用法：当 L5 的场景底座（建图/复现场景），不当控制器。
- **Meta / LeCun（JEPA：I-JEPA → V-JEPA → V-JEPA 2）**：表征预测 + 层级分工，V-JEPA 2 用十亿级参数、
  数十小时机器人数据做到零样本抓放。**同时必须写清它没给我们的三样：动作条件、力、几何** —— 这三样正是本工程的增量，
  也是不能直接拿开源权重的理由。

## 五、自动驾驶那一节怎么写

不要写成「自动驾驶也在用世界模型」的新闻，要写成**同架构不同约束**：

可借三条：① 闭环仿真里反复试错（世界模型当环境）；② 动作条件生成（给定轨迹预测场景演化）；
③ 安全兜底分层（模型输出永远过一层硬判据）。

不可照搬两条：① 容忍度差两个数量级（米级 vs 毫米级）；② 开放长尾 vs 封闭工位（我们的状态分布窄，
所以能自监督收敛，也所以不需要通用智能）。
结论句：**同一套分层思想，两套约束** —— 借它的结构，不借它的指标。

## 六、延迟账模板（选型的硬理由之一）

```
单拍预算 = 控制周期 T（本工程 20 ms）
规划步数 K，单步前向 t  ⇒  一次决策延迟 ≈ K·t
进控制环的必要条件：K·t ≤ 若干个控制拍，且判据能在同一拍内给出
```
把各家公开的单步时延代入，得出的是**量级结论**（差 1e2 / 1e3 / 1e4），不要写「大概几百毫秒」。
四个硬理由按可测性排序：① 单步前向进得了控制拍；② 能挂毫米级判据（表征可回归到几何量与力）；
③ 自监督，标注成本可承受（产线不可能给每帧打标）；④ 天生可分层（层间只传 latent）。
软理由只有一条，写在最后：**它不承诺通用智能，只承诺预测得准** —— 这正是产线能验收的东西。

## 七、本工程的 H-JEPA 变体（写差异，不写复述）

四层时间尺度（分钟 / 秒 / 100 ms / 20 ms），每层各答一个问题：任务可行性 / 动作序列 / 下一状态 / 本拍指令。

三条设计约束（这三条是把论文架构变成工程架构的关键，必须逐条写理由）：
1. **层间只传 latent，不传原始观测** —— 否则上层被下层频率拖死；
2. **每层自带判据**，不把判定权上交 —— 否则一处不确定全链停；
3. **每层可单独降级**（上层挂了退到下层纯闭环）—— 这是 7×24 产线的基本要求。

与原版的差异逐条列表：动作条件（我们显式喂动作）· 力通道（我们没有力就无法谈插入）·
SE(3) 几何分支（纯 latent 会「看起来对、插进去歪」）· 层级数与时标 · 上线门禁 · 评估口径。
每条写「它是怎么做的 / 我们为什么不一样」，不写「我们更好」。

## 八、UPH 论证的结构（用户最会追问的一段）

1. 目标换算：目标节拍 UPH → 每件秒数（如 1000 UPH ⇒ 3.6 s/件），与在役值并列，**明确「目标」还是「实测」**。
2. 缺口倍数：在役 11.5 s/件 ⇒ 要提 3.2 倍，写成一个数，不写「大幅提升」。
3. 分项预算表：对位 / 插拔 / 检测 / 搬运 各自 现状 → 目标（秒），合计必须等于目标节拍（自下而上对平）。
4. 分层靠什么补：并行（×1.8~2.0）· 缓存（×1.2~1.3）· 提前决策（×1.1~1.2）三者相乘 ≈ 2.4~3.1，
   **写明是乘不是加**，并说明每项的物理前提。
5. 单一大模型为何到不了：延迟不可压缩 · 容量与频率冲突 · 错误不可定位 · 无法局部升级（四条各一句）。
6. 分层的代价（不写这段会被当成只讲好话）：层间误差累积 · 契约维护成本 · 调试复杂度上升，各给缓解手段。

## 九、出处与口径纪律

- 外部工作**只述公开做法与作者自述目标**，不替它下性能结论（「实测达 X」只能写我们自己的数）。
- 收口页给出按年份的出处清单（论文/技术报告/官方博客 + 年份），每条一行，不写 URL 长串。
- 目标值与在役值**分句分页标注**；未验证的路线写「规划」，不写在役。
