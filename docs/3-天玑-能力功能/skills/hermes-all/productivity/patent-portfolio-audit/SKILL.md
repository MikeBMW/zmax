# 专利组合盘点与优先级判断

## When to Use
- 「盘点一下专利」「所有专利列出来」「这件专利是什么」「哪件最重要」「流形引擎的专利是哪件」。
- 对外报专利实力前自查（能给客户/评审看的数字必须现算）。
- 写交底书/补章节本身 → 用 `patent-disclosure-authoring`（本技能只管**看**，不管**写**）。

## 铁律
1. **一个数都不许凭印象**。件数、覆盖率、状态、缺口全从真源现算：
   `config/patents/patent_registry.json`（内容）+ `docs/0-索引/index.json`（专利↔节点链接）+
   文件系统（交底书 md/docx/pdf 齐否）+ 代码目录（落地引用）。
2. **指标不夸大，坏的先说**。件数齐、十节齐 不等于能交代理所 —— 盘点价值在于把空洞挖出来，
   而不是把 20 件排一遍就完事。
3. **结论先人话后数据**：一句定性（「这件是 X」），再上可复核的数字/路径。列清单时给完整名称不截断。

## 步骤
1. 跑盘点脚本（本技能自带，仅 stdlib，`ZMAX_ROOT` 默认 `~/zmax`）：
   ```bash
   ZMAX_ROOT=~/zmax python3 scripts/patent_inventory.py            # 逐件表 + 缺口
   ZMAX_ROOT=~/zmax python3 scripts/patent_inventory.py --dir src/lerobot/manifold   # 目录覆盖率
   ```
   脚本给：编号/星/层/状态/主关功能/节点/权项/方案步/落地引用/md/pdf，+ 缺口清单 + 节点共享度。
2. 逐件报：完整标题 + 挂载量，一件三行（编号·星·层·状态 / 名称 / 指标），不要压缩成一行挤成横表。
3. 按下面「四类空洞」核一遍，缺什么直接进回复。
4. 用户问「哪件最重要」→ 按「三条判据」给**一件**明确答案 + 次席 + 风险，不要列五个选项让他挑。
5. 用户问「某引擎/某模块的专利」→ 名义覆盖不够，必须跑 `--dir` 看文本落点覆盖率。

## 四类必报空洞（比件数重要）
1. **替代实施方式整列「待发明人确认」** —— 防规避条款全缺，代理所第一轮必问。全空就报全空，
   别因为「九、关键保护点」里有一句就当成齐了。
2. **`data_refs` 为空却有量化数字** —— 数字可以是真的（工具脚本跑出来的），但专利文本没有数据来源登记，
   交付仍然不合格（「这些数从哪来」答不出）。
3. **registry 里手写的 `embodiment` 数字会过时** —— 例如「画布节点 74 个」而库里实际 79。
   校验脚本只核生成的 `draft_text` 现算数字，**不核 registry 手写 embodiment**，件件 PASS 也拦不住。
   盘点时扫 `(画布节点|节点|功能)\s*\d+\s*个`，有就按实测改（改后重生成该件交底书 + PDF + 复核判据）。
4. **批次质量断层** —— 早期批 5 条权项/无量化/无实测，后期批 7–12 条权项/十几处实测。
   必须按批次对比报，否则会把「件数齐、十节齐」误报成「能交」。

## 判「哪件最重要」三条（同时成立，不是打分）
- **独权讲的是同类系统绕不开的矛盾**，不是某个实现手法。例：「多层架构里安全由谁保证」→
  上层只给意图、可行域逐层收窄、执行量底层收口 —— 这种独权对方整套架构绕不过。
- **权项有梯度**：独权 + 从权逐层退防，每条对应真实架构约束（合成势函数 → 稳定性条件 →
  交集空则否决 → 统一收口），不是凑数条款 —— 维权时能逐层退防。
- **落点在主干**：被多件专利共享的节点归它（脚本的共享度即可看出谁是主干）。
  **落点最广 ≠ 最重要** —— 与公开路线（开源分块/世界模型路线）重合多的件，可专利性反而最弱。

**同时必须点出的风险**：独权是纯数学载体陈述（「以某群作统一状态载体」）时，触发专利法第 25 条
「智力活动的规则和方法不授予专利权」，必须补「该表示如何产生技术效果」并绑定装置/实测。
技术价值最高 ≠ 撰写强度够，两件事分开讲，不要只夸技术价值。

## 「某引擎/某模块的专利」= 名义覆盖 vs 文本落点
节点级覆盖 和 `impl_refs` 文本落点是两回事，可能差一个数量级（实测某引擎目录 41 个源文件，
只有 3 个进了专利引用，其余仅靠别的专利在节点层顺带保护，没有自己的独立权项）。
做法：`--dir` 列出该目录每个 `.py` 被哪件引用，缺的要么补进实施例，要么明说「无独立保护」。
回答「这件专利是什么」时也要拆到代码/节点级：读了 registry 全文 + 关键实现函数 + 跑一次离线验证脚本
拿实测数，再讲「解决什么问题 / 双层怎么分工 / 四道护栏 / 实测多少」，不要只复述摘要。

## 交付口径
- 报清单末尾给绝对路径（交底书目录、渠道清单、专利地图），别只说「已生成」。
- 修了 registry/文档就提交并注明改了什么；改文件必回读。
- 两个真源副本要走同一个路径：改 `config/patents/patent_registry.json` 后必须同步到仓库里带版本的那份。
