# AR 工位场景: 渲染帧 → L2 感知 → plan → 双臂执行

## When to Use

- 要给仿真/AR 工位场景做“看得到渲染图 + 检测结果 + 执行结果”的页面。
- 要把渲染帧 (不是相机帧) 喂给 L2 检测, 再把检测定位交给 plan 驱动左右双臂。
- 要证明“模型真跑、规划真执行”, 需按真值而非“指令已下发”验收。
- 排查“链通了但 0 框/框很小”、“端口活着但服务假活”、“一臂够不到工位”这类仿真闭环故障。

把仿真 AR 场景做成一条**能看见、能核对**的闭环, 而不是"发了指令就算跑通"。典型产物: 一个 render 页面 (看得到渲染图 + 检测框 + 定位数值 + 每步执行结果), 背后是渲染站 + 感知 + 规划 + 执行四段。

## 架构 (照这个分层, 不要糊在一个脚本里)

| 段 | 位置 | 职责 |
|---|---|---|
| 渲染/真值/控制站 | `tools/ar_scene_render_server.py` (:8802) | 出 `frame.png`、给真值 `state.json`、收 `control/reset`、提供 `ik/proj/unproj` |
| 规划节点 | `tools/dual_arm_plan.py` | 纯几何: 感知位姿 → 双臂分层步骤 (观察位/对位/撤离), 带可达性闸 |
| 执行 + 页面 | `tools/ar_render_station.py` (:8805) | 抓帧→L2→2D→3D→plan→逐步执行→真值判定→复测+取证图 |
| 检测模型 | `lerobot.perception.yolo` + AR 域权重 | 每帧真推理, 不是规则/固定框 |

页面是给用户看的唯一入口: 渲染图、检测框、定位坐标、每步 want/reached mm、复测前后对比、一键跑一轮。服务化 (`systemd` + `Restart=always`), 别挂在终端里。

## 步骤

1. **先确认渲染站活着, 再谈检测**: `curl -s :8802/status.json` 看 `gold_px`(像素真值) 非 0、`calib.res_mm_med` 有值; 再隔 1~2s 取两帧比 md5 且看 truth 有没有变。**`n` 只是计数器, 涨了不代表画面在更新** (实测 n 一路涨到 8 万+ 而 `/frame.png` 十分钟 md5 完全不变)。`n=0` 或 `gold_px=0` 时后面的检测数字全无意义。
2. **标定在服务里做, 不要离线凑**: 台面单应采用九点网格现场反解 (实测残差中位 0.43mm / 0.8px), 残差落到 `status.json`, 页面显示。高度方向按工件顶面 (台面+半高) 假设, 页面标签注明"高度为假设值", 不要冒充 6D。
3. **抓帧 → 检测**: 每轮开头重抓 (不缓存), 检测走 `detect_all` + 类别/面积闸; 通道序按 `references/detect-call-contract.md` 对。
4. **2D→3D**: 像素 → 台面单应反解 → `[x,y,z]`, 同时算与场景真值的偏差 mm 并在页面显示。感知误差 >20mm 时先停下查帧源/通道, 不要拿去规划。
5. **plan**: 几何规划器输出**有序步骤**, 每步含 `side/action/target_mm/grip/tol_mm`; 不可达步在规划阶段就标 `skip+原因`, 不要留给执行阶段硬撞。
6. **act**: 每步 `IK → /control → 读真值等到位 → 残差回补`; 到位判据只用真值 (TCP mm), 不用"ctrl 已下发"。
7. **复测**: 一轮结束后重新抓帧重跑模型, 比对比前后定位 (实测应 <0.5mm) + `gold_px` 未归零, 证明"场景没被碰坏"。
8. **取证**: 落一张叠加图 (检测框 + 真值框 + 目标点 + conf/坐标文字) 到 `zmax_data/ss_live/*.jpg`, 路径写进响应, 用户要能自己看。

## 平滑执行 (回放式, 不要逐拍 P 环)

逐拍 P 环逼近 (每拍几十 mm、换段就换 v_cap、到位前 snap) 天然顿挫; 回放式 (按 `u=t/T` 采样) 天生连续。
要“像回放一样顺”且仍闭环, 分三层:

1. **轨迹由节点发出**: 五次多项式 S 曲线 (`s=10t³-15t⁴+6t⁵`, 首末速度 0),
   `T = max(1.875L/v_cap, sqrt(5.7735L/a_max))`, 输出 `pts[n]/vel[n]/T/v_peak/a_peak`。
2. **执行端按固定 dt 采样回放**, 每拍 = 轨迹点 + 小增益真值纠偏 (限几 mm) + 单拍位移上限 (`v_cap·dt·1.5`)。
3. **收尾逼近**: 轨迹走完若还差 10~50mm (PD 滞后/静差), 用 20ms 小步 (≤3mm/拍, rate 2~3°) 补到位。

公式、伪代码、度量口径: `references/smooth-trajectory-and-motion-forensics.md`。
老路径留开关 (`ZMAX_STATION_REPLAY=0`) 以便对比和回滚。

## 坑 (每条都带机制)

- **渲染线程构造必须包 try + 重试 + 写 err**。在循环外构造 `Env(render_mode="rgb_array")`, GL 未就绪时线程直接退出, 但端口还在监听、`n=0`、`err=None` ⇒ 看起来"服务正常"的假活。构造失败要写 err 并 3s 后重试。
- **sim / idle 两种模式互斥**。步进物理 (`mj_step`) 时不能再直写自由体 qpos (仿真抖动), 否则模块被打飞/穿桌; 要改位置就先切 idle、改完再回 sim。`idle` 期间画面应保持静止, 否则说明还在步进。
- **位置执行器有重力静差 (实测 8~12mm)**: 发指令后必须读真值算残差, 用 `目标+残差` 回补, 最多 3 轮, 单轮回补量夹在 ~30mm 防跑飞。`tol` 设 6~8mm 才既真实又可达。
- **IK 单初值会贴限位给出不可执行解** (`|q|=170°` 的解在 PD 下根本走不到)。解算要多初值 (当前位姿/零位/扰动向) 并对 `|q|>165°` 罚分; 规划阶段据此拒绝不可达步。
- **停机位要选在相机视野外, 不要用 home**。实测双臂 home 姿态正好压在机位与料盘之间 ⇒ `gold_px` 掉到 0, 模型无框; 抬到 z≈0.32 且靠侧边后 `gold_px` 稳定。动作前后都先看 `gold_px` 再解读检测结果。
- **双臂镜像看 `sign` 到底用没用**。`arm(side, ..., sign)` 里 sign 未被消费时左右臂运动学完全相同、都朝同一方向伸, 一臂够不到料盘 (实测腕 x 停在 -0.09, 目标解出多圈解, 执行差 150mm+)。正确镜像: 给该臂 link0 加 `quat="0 0 0 1"` (绕基座 z 转 180°); **不要逐轴取反** —— 轴取反会把 y 也翻过去 (腕跑到 y=-0.147 场外)。
- **每步都要显式下发双臂**: 只发动的一侧时另一侧会停在上一轮的位姿, 后续 IK 的初值就不对了; 两侧都用当前 `cur[side]` 填满再发。
- **夹爪几何决定能不能抓, 不能靠愿望**: 两指沿 x 并列时对 16mm 宽工件只推不夹 (实测夹紧后工件仅位移 5mm)。这种场景就把 plan 说成"双臂对位/协同", 页面写明"不做搬运", 不要拍成抓取。要真搬运得改指几何 + 重训域内权重。
- **复测"无框"先怀疑视野, 不要怀疑模型**: 先查 `gold_px`, 再看重试次数; 页面要把"重试 N 帧"显示出来, 否则一条失败看起来像模型坏了。
- **`/control` 的键是 `L`/`R`(度), 不是 `qL`/`qR`(弧度), 且未知键静默忽略**: 发 `{qL,qR}` 会照回 `ok:true` 而臂一动不动 ⇒ 每次下发后必须读 `/state.json#truth` 对比目标, 差几百 mm 就是键名/单位错了, 不要以为是没收敛。
- **`mode=idle` 只写 ctrl 不步进物理 ⇒ 臂不动**: 要动必须 `mode:"sim"` 并留收敛时间 (实测 0.4m 跨度 2.2s 后还差 114mm, 到位判据只看 truth 不看等待时长)。`idle` 的正确用途是"保持当前姿态/改自由体位置后切回 sim"。
- **`/frame.png` 会整帧冻结, 但 `status.n` 照涨**: 症状是不同姿态下取到的 PNG 字节完全相同 (md5 一致)、`gold_px` 恒定。判活: 两帧 md5 + truth 变化; 要"现在就出图"用 `/frame.png?az=&el=&dist=&tx=&ty=&tz=` 强制按机位渲染 (这条路径实测可靠)。
- **仿真臂静止 ≠ 服务死了**: `/bones.json` 的 `n` 在涨但 L/R 关节位移 `0.0000m` 就是停在停机位 (物理在跑、没有指令)。判"臂在不在动"只比关节坐标差, 别拿 `n` 或 `ts` 当运动证据。
- **模型看不到浏览器画布**: 人眼看到的 AR 页是前端 2D 画布, 服务端没有这张图; 离屏截页实测得到纯白图 (mean=255) 且矢量绘制与 MuJoCo 渲染不是同一域, 检出 0 个。正解是让模型吃 **8802 服务端渲染帧** (实测同场景 gold_module 0.89), 要跟页面同视角就把页面相机参数映射到 `/frame.png?az/el/dist/tx/ty/tz` (实测任意机位仍检出 0.80)。
- **“MuJoCo 里是一根光棍 / 动作与画布不一致”是两个独立病因**: 光棍=手写胶囊缩尺链没有 URDF 网格;
  动作不一致=链长/关节轴与 URDF 不同源 (缩尺链自定 0.06/0.18m, 真 URDF 0.328/0.4m)。
  让 MuJoCo 用真 URDF 网格生成双臂后, **必须逐轴核对 `jnt_axis` 与 URDF joint 一一对应**,
  并在基座上**不要多挂 joint** —— 多挂一个会让 6 个 hinge 名整体错位一格, 同一组关节角末端差 200mm 级,
  而 IK/PD/同步通道全部“看起来正常”。判据: 同一组角 MuJoCo 正解 TCP vs 页面正解 <1mm。
  完整做法 (URDF→MJCF 映射、kinematic override、`POST /armq` 单一指令源、取景/亮度验收):
  `references/urdf-mesh-arms-in-mujoco.md`。
- **position actuator 跟不上画布姿态就不要硬调 kp**: 真 URDF 链静差实测 j0/j1 各 15.9°、末端 57~217mm,
  kp 300→1500 也压不到 1cm。AR 叠加改用**运动学写 qpos** (步进后回写目标角 + 清 qvel),
  残差降到 ~24mm; 但这条通道只用于显示同步, 需要真接触力的任务不能这么干。

- **判“轨迹猛冲/抖动”前先量真值刷新率**: `/state.json#truth` 按渲染站 `--hz` 刷新, `--hz 8` ⇒ 125ms 一帧,
  350mm/s 就是 **44mm/帧的台阶**。用 25~30Hz 去采就会算出“1.2~1.9 m/s 峰值 / PD 过冲”这种不存在的现象
  (实测先误判成 kp=300 过冲)。规则: 先算 `v_cap × 刷新周期`, 再与观测单点位移比; 结论用位移/刷新周期, 不用位移/采样间隔。
- **给 `/control` 加指令流取证**: 暴露 `n/hz/dmax(单次最大关节变化°)/nfast(>1.2°次数)/gapmax(最长空档)` 到 `/state.json#ctl`。
  `dmax≤0.7° 且 nfast=0` = 指令连续 (看到的跳是采样/真值别名); `dmax 5~7°` = 指令在跳 (查 IK 是否带 seed/rate、循环是否连发)。
- **回放节拍不许“追帧”**: 对齐到 `k·dt` 时刻表时, 一次迭代比 dt 慢就会**连发两条指令** (实测 2.5°×2/31ms ⇒ 末端 1.3m/s)。
  规则: 落后就丢弃过期点 (`k=int((now-t0)/dt)`), 每 dt 最多下发一次。
- **关节 rate 是“度/次”, 不能拿 TCP 速度当它**: 2.5°/20ms = 125°/s, 在 0.5m 力臂上 ≈1.1m/s。
  换算: `deg_per_cmd ≈ v_tcp·dt/力臂` (350mm/s@20ms → 0.7°)。改 rate 前先用 `/ik?seed=&rate=` 实测 `rate_clipped/seed_gap_deg`。
- **控制环互抢有三个来源** (症状: 该到位的步骤停在 190mm、采样里出现 118mm/37ms):
  ① 停机位/摆场用无 seed/rate 的一发式 IK ⇒ 瞬移 + 换分支; ② 摆场重试循环与闭环同时跑 ——
  摆场函数必须 `return {"ok": True}`, 返回值丢了会让重试逻辑判失败连摆 12 次, 每次再抢一次臂;
  ③ `/api/run` 可叠加 ⇒ 两个闭环线程同时下发。规则: 闭环入口加**非阻塞单飞锁**, 摆场/复位共用同一把锁;
  另 `/reset` 是**场景瞬移** (真值一帧跳数百 mm), 默认只在进程首轮做。
- **渲染与物理解耦才提得上帧率**: 出图 (2 路 render+PNG ≈60ms) 与物理/真值同循环 ⇒ 真值被拖到 8~9Hz。
  规则: `--phys-hz`(物理/真值) 与 `--render-hz`(出图) 拆开, 没到出图时刻复用上一帧只更新真值; 出图降本 (特写每拍、全景每 3 拍)。
  实测真值 8.5→16~21Hz; 要上 50Hz 得把渲染挪到独立线程。

## 场景内容与取景 (“少东西 / 看不见 / 空白”)

- **“渲染少东西”先查真源覆盖, 不要先调机位**: 渲染几何只能来自 `fence_store` 的 box 与 `place_cells.json` 的 cell。画布上有、渲染里没有, 就是构建代码自己过滤掉了 (实测: 只取 `slots[:6]` ⇒ 只有主料盘有槽, 另 3 个盘是整块实心板)。改法是把真源条目全量建出来 (42 个槽), 不要用常数补几个看着像的。
- **真源里 `enabled=false` 的盒体也会被画**: 不过滤就变成“凭空多出来的板”; 但设备盒往往就是要看的 (相机/检测设备), 所以别按 `enabled` 硬删, 用几何组按视角开关 (下一条)。
- **结构遮挡靠 geomgroup, 不是靠调俯角/视场**: 1.6m 横梁悬在料盘上方 0.55m, 任何正俯视都被它盖死 (实测 4 个料盘被遮 95~100%, 换机位/加高相机都没用)。把设备/相机盒统一 `group="3"`, 顶视 (`elevation ≤ −70°`) 时 `MjvOption.geomgroup[3]=0`, 斜视保留。
- **透明不能当遮挡的解法**: alpha 0.45 把整幅变成磨砂玻璃 —— 料盘槽 187 灰 vs 相邻台面 185 (只差 2 个灰阶), 金手指暖色像素 998→5, 中位饱和度 15/255, 而且把设备盒之间的实体穿插暴露成“乱序”。要“看穿”只开几何组, 材质保持不透明。
- **新加机位必须现场渲染, 缓存帧会给出旧视角**: 预设机位走 `views[name]` 缓存时, 新加的 `top` 返回的是上一版斜视帧 —— HTTP 200、字节数正常, 只有和默认机位比均值/像素差才看得出 (实测差 74.5 灰阶)。规则: 预览类机位当场按 `az/el/dist/tx/ty/tz` 渲染, 验收比内容不比状态码。
- **直播页每拍直改 `<img>.src` 会显示空白**: 6fps + 单张约 200ms 加载 ⇒ 图片长期停在 loading 态 (`naturalWidth=0, complete=false`), 用户看到的就是“画面没有了”; 用离屏 Image 预载后赋同一 URL 也仍会重新下载再清空。正解: `fetch` 取 PNG → `createObjectURL` → 赋 `src` → 旧 URL `revokeObjectURL`。
- **给内嵌 JS 模板打补丁必须回读服务端返回的 HTML**: patch 吃掉 `setInterval(function(){` 的左半句会让整段脚本语法错死 (无 console 报错、画面全停); 删掉 `var FPS=6` 则 `setInterval(fn, Math.round(1000/undefined))` = `NaN` ⇒ 0ms 连发把渲染线程打满。改完 curl 服务的页面核关键标记与角标文本, 别只看源文件 diff。

## 验收口径 (用户要的是这些数字)

- 检测: conf + 框 + 面积, 与像素真值的 IoU (实测 0.95 量级)。
- 定位: 感知 3D 与场景真值的偏差 mm (实测 3mm 量级)。
- 执行: 每步 `reached_mm` 全部 ≤ tol (实测 6/6 步 6~8mm), 一轮耗时。
- 复测: 前后定位差 <0.5mm、`gold_px` 未归零。
- 页面: 浏览器打开无 console 报错, 渲染图真的加载 (960×720)。

把这些当场打印/写进页面, 不要只说"跑通了"。
